# 文档版本标注规范

> 来源：RC04文档版本维护滞后根因萃取
> 适用场景：所有包含硬编码版本号的部署/安装/配置文档

## 问题

文档中硬编码的版本号（如Ubuntu版本、软件版本、依赖版本）会随时间漂移，导致：
- 新用户按照过时文档安装遇到兼容性问题
- 文档维护者不知道哪些版本号已过时
- 无法判断文档内容是否仍然有效

## 规范

### 1. frontmatter 标注

所有部署类文档必须在 YAML frontmatter 中添加版本验证信息：

```yaml
---
title: "文档标题"
last_verified: "YYYY-MM-DD"  # 最后一次完整验证日期
versions_validated:          # 已验证的版本列表
  ubuntu: ["24.04", "26.04"]
  docker: "27.x"
  python: "3.14"
  # ... 其他关键依赖
---
```

### 2. 版本号旁标注

正文中出现的硬编码版本号旁，使用 HTML 注释标注最后验证日期：

```markdown
支持 Ubuntu 24.04 <!-- verified: 2026-07-29 --> 和 26.04 <!-- verified: 2026-07-29 -->

安装 Docker 27.x <!-- verified: 2026-07-29 --> 版本
```

### 3. 版本兼容性章节

文档末尾添加"版本兼容性"章节：

```markdown
## 版本兼容性

| 组件 | 推荐版本 | 最后验证日期 | 备注 |
|------|----------|-------------|------|
| Ubuntu | 24.04 / 26.04 | 2026-07-29 | 22.04 仍可用但非推荐 |
| Docker | 27.x | 2026-07-29 | 原生Docker或Docker Desktop均可 |
| Python | 3.14 | 2026-07-29 | 需3.14+ |
```

### 4. 版本审查流程

1. **新建文档**：创建时添加 `last_verified` 和版本标注
2. **季度审查**：每季度检查一次版本是否过时
3. **依赖升级**：依赖版本升级后，必须更新对应文档的验证日期
4. **问题反馈**：用户报告版本问题时，优先更新文档标注

## 快速检查脚本

可使用以下命令快速查找未标注版本号：

```bash
# 查找文档中裸版本号（未带verified注释）
grep -rn "2[0-9]\.[0-9]\{2\}" docs/ --include="*.md" | grep -v "verified:"
```
