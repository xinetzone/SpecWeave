# 存量业务系统智能化改造 · 项目启动文档

> **使用说明**：
> 1. 复制本模板到项目目录，重命名为 `<项目名>-kickoff.md`（如 `crm-agent-upgrade-kickoff.md`）；
> 2. 所有 `<尖括号>` 内容为需填写项，填写后删除尖括号；

## 3. 执行计划 · 5 步 SOP 甘特表

> **模式要点**：严格按 5 步顺序执行，每步有明确输入、动作、输出物，禁止跳步。

### 3.1 总体时间线（建议 4~6 周）

| 周次 | 主要阶段 | 里程碑 |
|------|---------|--------|
| 第 1 周 | Step 1 · API 梳理与分级 | 完成 API 盘点，A 级清单确认 |
| 第 2 周 | Step 2 · Gateway 快速接入 | Tool 清单生成，连通性测试 ≥ 90% |
| 第 2~3 周 | Step 3 · 权限与身份映射 | 权限矩阵完成，凭据托管配置到位 |
| 第 3~4 周 | Step 4 · Harness 跑通验证 | Local 模式 20+ 用例通过率 ≥ 90% |
| 第 5 周（可选） | Step 5 · MCP 渐进优化 | Top 高频接口 MCP 改造，灰度观察 ≥ 3 天 |
| 第 6 周 | 生产化准备 + 上线 | 12 项生产检查通过，灰度上线 |

### 3.2 各步详细执行表

#### Step 1：API 梳理与分级（第 1 周）

| 项 | 内容 |
|----|------|
| **输入** | API 文档（Swagger/Postman/Confluence）、近 90 天调用日志、业务价值评估表 |
| **核心动作** | ① 收集所有暴露接口 → ② 调用频率 × 业务价值二维打分 → ③ ABC 三级分级 → ④ 标记敏感写操作 |
| **责任人** | `<技术负责人 + 业务方对接人>` |
| **时间盒** | `<5 个工作日>` |
| **输出物** | `《A 级 API 清单 v1.0》`、`《敏感写操作管控清单 v1.0》` |
| **验收标准** | A 级接口 20~100 个，敏感接口标注覆盖率 100%，业务方签字确认 |
| **推荐工具** | Swagger Parser、Postman、API 网关流量分析；Agent 框架无关 |

#### Step 2：Gateway 快速接入（第 2 周）

| 项 | 内容 |
|----|------|
| **输入** | A 级 API 清单 + 敏感写操作标记清单 |
| **核心动作** | ① 批量导入 A 级 API 自动生成 Tool 定义 → ② 敏感写操作默认只读/二次确认 → ③ 每个 Tool 配置超时（默认 30s）+ 重试（最多 2 次指数退避）→ ④ 逐个连通性测试 |
| **责任人** | `<后端开发工程师>` |
| **时间盒** | `<5 个工作日>` |
| **输出物** | `《Agent Tool 清单 v1.0》`（含名称/描述/参数/超时/重试/权限标签）、`《连通性测试报告》` |
| **验收标准** | A 级 API 连通性测试通过率 ≥ 95%，所有 Tool 含完整描述和参数 Schema |
| **推荐工具** | `<根据实际栈填写：AgentKit Gateway 自动转换 / LangChain Tool Wrapper / Dify 自定义工具 / Coze 插件>` |

#### Step 3：权限与身份映射（第 2~3 周）

| 项 | 内容 |
|----|------|
| **输入** | 业务系统 RBAC/ABAC 权限矩阵 + Tool 清单 + 企业 IAM 用户目录 |
| **核心动作** | ① 定义 Agent 独立身份标签 → ② 业务角色 → Agent Tool 白名单映射（最小权限）→ ③ 凭据托管（AK/SK/Token 入 Secret Manager）→ ④ 跨 Agent 权限隔离 |
| **责任人** | `<安全工程师 + 后端开发>` |
| **时间盒** | `<5 个工作日>` |
| **输出物** | `《Agent-用户-Tool 三维权限映射表》`、`《凭据托管配置确认表》` |
| **验收标准** | 无明文密钥（代码/配置 grep 不到），越权测试 ≥ 10 条全部拦截，敏感写操作有二次确认 |
| **推荐工具** | `<AgentKit Identity / Keycloak / AWS IAM / HashiCorp Vault + 自定义权限中间件>` |
| **反模式红线** | ⛔ 严禁直接使用业务系统**超级管理员 Token**（对应反模式 2） |

#### Step 4：Harness 跑通验证（第 3~4 周）

| 项 | 内容 |
|----|------|
| **输入** | Tool 清单 + 权限映射表 + 典型业务场景用例清单（≥ 20 条） |
| **核心动作** | ① Harness 配置（模型/System Prompt/Tool 挂载/会话配置）→ ② Local 模式调试（Mock 依赖、单步跟踪、权限拦截验证）→ ③ 20+ 用例批量测试 → ④ 修复通过率 < 90% 的场景 |
| **责任人** | `<AI 应用工程师>` |
| **时间盒** | `<8 个工作日>` |
| **输出物** | `《典型场景 Demo 部署包》`、`《用例执行报告》`、`《失败案例根因分析》`、`《Harness 配置文件》` |
| **验收标准** | 20+ 用例整体通过率 ≥ 90%，核心场景通过率 ≥ 95%，平均延迟 `<根据场景目标设定>` |
| **推荐工具** | `<AgentKit Local 模式 / LangGraph Studio / Dify Workflow 调试 / Coze 预览模式>` |
| **反模式红线** | ⛔ 严禁跳过 Local 调试直接上 Cloud（对应反模式 3） |

#### Step 5：MCP 渐进优化（第 5 周，**可选**）

| 项 | 内容 |
|----|------|
| **输入** | 近 2 周 Tool 调用日志/Trace + Step 4 Demo 报告 |
| **核心动作** | ① 提取 Tool 调用频率排名，筛 Top 20% 高频 → ② 评估 MCP 改造收益（流式/错误码结构化/并发安全三优先）→ ③ 逐个改造 + 新旧双轨灰度 ≥ 3 天 → ④ 量化收益报告 |
| **责任人** | `<AI 应用工程师 + 后端开发>` |
| **时间盒** | `<5 个工作日（可选，人力不足可延期到二期）>` |
| **输出物** | `《MCP Server 清单》`、`《性能稳定性提升报告（改造前后对比）》`、`《灰度切换记录》` |
| **验收标准** | 改造接口 P95 延迟改善 ≥ 20% **或** 错误率下降 ≥ 30%，灰度期间无 P0 故障 |
| **推荐工具** | `<AgentKit MCP Server + Observability / 自研 MCP SDK + OpenTelemetry + Argo Rollouts>` |
| **反模式红线** | ⛔ 严禁一期就要求所有接口支持 MCP（对应反模式 1，周期会拖到 6 个月以上） |

## 5. 风险矩阵与反模式红线

### 5.1 4 条反模式红线（项目启动时团队全员签字确认）

| 编号 | 反模式 | 后果 | 预防措施 | 责任人 |
|------|--------|------|---------|--------|
| ⛔ **R1** | 一期就要求所有接口都支持 MCP 标准 | 改造周期拖到 6 个月以上，业务方失去耐心项目终止 | Step 2 先用 REST/OpenAPI 转换 1~2 天跑通 A 级；MCP 仅在 Step 5 对 Top 20% 高频接口做 | 技术负责人 |
| ⛔ **R2** | 直接把业务系统管理员密钥给 Agent 使用 | Prompt 注入后可批量删除/修改数据，造成不可逆生产事故 | 最小权限白名单 + 凭据托管 + 敏感写操作二次确认 | 安全工程师 |
| ⛔ **R3** | 跳过 Local 模式验证直接上 Cloud | 调试成本翻倍，排错周期从小时级拉长到天级 | 严格执行 Step 4，20+ 用例 Local 通过率 ≥ 90% 再上生产 | AI 应用工程师 |
| ⛔ **R4** | API 分级只看业务价值不看调用频率 | 高价值低频次接口浪费 2~3 周，一线高频接口迟迟不上线 | 严格按「频率 × 价值」二维矩阵打分，Top 20% 为 A 级 | 技术负责人 + 业务方 |

## 7. 生产化 12 项检查清单（基于 P-DEMO-TO-PROD-003）

> 生产上线前（G6 闸门）逐项检查，任一不通过**禁止上线**。

### 7.1 安全维度（2 项）

- [ ] **检查 1 · 身份与权限最小化**：Agent 独立身份标签 ✓ / Tool 白名单最小化 ✓ / 无明文密钥（grep 验证）✓ / 敏感写操作二次确认 ✓
- [ ] **检查 2 · 内容护栏配置**：输入侧拦截（敏感词/Prompt注入/越权意图）✓ / 输出侧校验（幻觉/合规）✓ / 对抗测试 ≥ 10 条全部拦截 ✓

### 7.2 可观测维度（2 项）

- [ ] **检查 3 · 全链路埋点**：Trace ID 贯穿 5 大环节（模型/Runtime/Tool/Knowledge/Memory）✓ / 抽检 ≥ 5 条链路完整 ✓
- [ ] **检查 4 · 监控告警配置**：错误率 >1% 告警 ✓ / P95 >5s/60s 告警 ✓ / 成本超预算 20% 告警 ✓ / 接收人和升级路径明确 ✓

### 7.3 权限维度（2 项）

- [ ] **检查 5 · 多租户隔离策略**：硬隔离/软隔离方案确认 ✓ / 跨租户访问测试 ≥ 10 条全部失败 ✓
- [ ] **检查 6 · 审计日志留存**：调用日志持久化 ✓ / 留存 ≥ 90 天 ✓ / 4 维查询（用户/时间/Tool/会话）✓ / 不可篡改 ✓

### 7.4 成本维度（2 项）

- [ ] **检查 7 · 资源弹性策略**：自动扩缩容阈值配置 ✓ / 空闲 15~30min 缩容到 0 ✓ / 压测 10→100 并发 P95 不超基线 2 倍 ✓
- [ ] **检查 8 · 模型路由优化**：高频简单任务→小模型/复杂任务→大模型 ✓ / 成本较全大模型基线下降 ≥ 20% 且准确率下降 <2% ✓

### 7.5 性能维度（2 项）

- [ ] **检查 9 · 响应时间 SLA**：简单场景 P95 < 5s / 复杂场景 P95 < 60s ✓ / ≥100 并发≥1000次调用达标率 ≥ 99% ✓
- [ ] **检查 10 · Tool 超时熔断**：所有 Tool 超时 ≤ 30s（特殊场景需审批）✓ / 幂等 Tool 最多 2 次重试 ✓ / 5min 错误率 >30% 自动熔断 ✓

### 9.3 术语表（启动时可根据项目补充）

| 术语 | 定义 |
|------|------|
| **A 级 API** | 近 90 天调用频率 Top 20% 且业务价值高的核心接口，本期优先接入 |
