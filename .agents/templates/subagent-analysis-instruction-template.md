# 子代理分析任务标准化指令模板

> 本模板基于 [BP-SUBAGENT-STD 模式](../../docs/retrospective/patterns/methodology-patterns/subagent-standardized-instruction.md)（L2-validated）。
> 使用时将 `[占位符]` 替换为具体内容,删除不需要的步骤,保持指令长度≤2000字。

## 模板正文（复制以下内容到子代理任务描述中）

```
请对 [分析对象类型:网页/文章/代码/文档] 进行系统性学习与深度洞察分析。

## 目标输入
[URL或文件路径或内容描述]

## 任务要求
请严格按照以下流程完成分析：

### 第一步：[内容提取/初步理解]
[具体描述这一步要做什么,产出什么]

### 第二步：[核心主题识别]
[具体描述,量化要求如"提炼3-5个核心要点"]

### 第三步：[结构分析]
[具体描述]

### 第四步：[观点与论据梳理]
[具体描述,标注论据来源类型]

### 第五步：[核心要点提炼]
提炼 [3-5] 个核心要点。确保每个要点都有原文支撑,可追溯;要点之间不重叠、不遗漏;每个要点用精炼语言概括,避免简单摘抄。

### 第六步：[可靠性评估]
评估信息来源可靠性,给出综合可靠性判断（高/中/低）并说明依据。

### 第七步：[行业趋势与市场动态洞察]
[具体描述,要求有原文依据支撑,避免过度解读]

### 第八步：[专业知识与方法论萃取]
[具体描述,要求形成可迁移的认知模型]

### 第九步：结构化输出
整合所有分析结果,形成结构化输出,包含两个清晰层次：

**学习笔记层**：
- [基本信息] [核心主题] [信息结构] [主要观点与论据] [核心要点] [关键概念与数据] [来源可靠性评估]

**洞察总结层**：
- [行业趋势] [市场动态] [专业知识/方法论] [可复用认知模型] [未来影响评估]

## 质量要求
1. 分析准确性：符合原文意图,不得曲解或添加原文未提及的信息
2. 结构清晰度：两个层次界限明确,逻辑清晰
3. 完整性：覆盖所有重要章节、观点、数据与关键信息
4. 专业性：准确理解和使用文中术语,语言规范,符合中文书面表达习惯
5. 洞察深度：超越字面内容,体现独立的思考与归纳,避免表面化复述
6. 可读性：未读过原文的读者能够通过分析报告理解文章主旨并获得有价值的洞察

## 输出格式
请以 Markdown 格式输出完整的结构化分析报告,[直接在回复中呈现 / 写入文件路径]。
```

## 使用指南

### 何时使用本模板
- 委派子代理执行微信文章分析、技术方案分析、竞品分析等复杂多步骤任务时
- 需要保证子代理产出质量一致性时
- 需要将分析步骤与验收标准（AC）关联时

### 长度控制
- 模板本体约800字,填充后应控制在2000字以内
- 超过2000字时,考虑:
  1. 拆分为2个子代理任务（如:一个做内容理解,一个做洞察分析）
  2. 提炼为"核心验收标准清单",省略详细步骤描述
  3. 关键质量要求不可省略,即使超出长度限制

### 验收标准映射
填充模板时,确保每个步骤标注对应的AC编号:
- 第一步 → AC-1（内容完整提取）
- 第二步 → AC-2（核心主题识别）
- 第五步 → AC-5（核心要点提炼）
- 第九步 → AC-10（结构化输出）

### 输出位置决策
- **对话呈现**:快速分析,不需要存档 → 指令末尾写"直接在回复中呈现"
- **文件落盘**:需要存档或后续引用 → 指令末尾写"写入 [路径]"
- 注意:根据FR-14,分析报告应写入spec目录的analysis-report.md（与Wiki教程区分）
