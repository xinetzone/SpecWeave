# 自积累机制负反馈设计模板（Self-Accumulating Mechanism Negative Feedback Template）

> **适用场景**：当设计任何包含"自学习"、"知识库"、"经验库"、"历史优化"、"自适应"、"反馈循环"等正向积累特性的系统、模式或工作流时，**必须**使用本模板确保负反馈设计完整。
> **核心原则**：任何正向积累机制，必须同时设计对应的纠错、衰减、淘汰机制——否则错误会复合增长，系统越"学习"越不可靠。
> **来源**：基于Agentrys AI芯片设计文章知识沉淀任务的对抗审查实践（2026-07-28），初版provenance-driven-trust模式中知识库规则只写了正向积累，缺失全部5项负反馈设计。

## 模板复制区

将以下模板复制到你的模式/设计文档中，然后填充内容：

```markdown
### 规则X：[自积累机制名称]

[描述正向积累的核心逻辑]

#### X.1 条目生命周期

| 阶段 | 规则 | 参数 |
|------|------|------|
| **创建/初始准入** | 新条目的初始置信度/权重 | 初始值：______（推荐0.3-0.5，禁止1.0） |
| **正向反馈** | 什么情况下置信度上升？上升多少？ | 成功时：+______（推荐0.05-0.15） |
| **负向反馈** | 什么情况下置信度下降？下降多少？ | 失败时：-______（推荐0.15-0.3，惩罚>奖励） |
| **时间衰减** | 多久不使用/验证后自动衰减？衰减公式？ | 衰减周期：______天；衰减系数：______（推荐0.7-0.9/周期） |
| **证伪/归档** | 什么条件下条目被禁用/归档？如何防止再次使用？ | 连续失败______次（推荐2-3次）；置信度低于______（推荐0.2）→归档 |
| **人工审核** | 什么场景必须人工介入？ | 风险等级≥______；置信度变化幅度≥______ |

#### X.2 置信度区间与行为映射

| 置信度区间 | 行为 | 使用限制 |
|-----------|------|---------|
| ≥ 0.8 | 自动应用，无需额外验证 | 低风险场景 |
| 0.5 - 0.8 | 可应用，但需记录并事后审计 | 中风险场景需交叉验证 |
| 0.3 - 0.5 | 建议值，必须人工确认 | 不可自动决策 |
| < 0.3 | 仅参考，不作为决策依据 | 高风险场景禁止使用 |
| < 0.2 / 归档 | 禁用，不再被检索/引用 | 永久黑名单（除非人工审核解除） |

#### X.3 防错误复合机制

- [ ] **幂等验证**：相同验证结果不重复提升置信度（防止"刷好评"）
- [ ] **独立验证**：置信度提升要求来自不同验证场景/用例，同一用例重复通过只计一次
- [ ] **近期权重**：最近N次结果权重高于历史结果（防止远古成功掩盖近期失败）
- [ ] **审计日志**：所有置信度变更记录原因、来源、时间戳，支持追溯

#### X.4 冷启动策略

- 初始默认值：______
- 前N次（推荐3-5次）应用时强制人工审核，不自动决策
- 积累______条以上验证记录后进入正常运行模式
```

## 设计原则（填充模板时必须遵守）

### 原则1：初始值保守
- ❌ 禁止：新条目初始置信度=1.0（"刚加入就完全信任"）
- ✅ 必须：初始值≤0.5，通过验证逐步提升
- **原因**：未经验证的知识应该是"可疑的"，而不是"可信的"

### 原则2：惩罚大于奖励
- ❌ 禁止：成功+0.2、失败-0.1（错误积累后难以纠正）
- ✅ 必须：失败惩罚幅度 > 成功奖励幅度（推荐2:1比例）
- **原因**：一次失败可能暴露严重问题，需要快速降低置信度；一次成功只是"没发现问题"，不应快速提升

### 原则3：时间会让知识过期
- ❌ 禁止：知识一旦验证通过永久有效
- ✅ 必须：设置时间衰减周期，长期未被重新验证的知识自动降权
- **原因**：环境会变、依赖会变、上下文会变，半年前正确的知识今天可能是错的

### 原则4：错误必须有出口
- ❌ 禁止：错误条目只是"降低权重"但仍可能被检索使用
- ✅ 必须：达到阈值后条目被禁用/归档，正常检索不可见，需人工干预才能恢复
- **原因**：已知错误的知识比没有知识更危险——它会误导决策

### 原则5：高风险不能全自动
- ❌ 禁止：高影响决策完全由自积累结果驱动
- ✅ 必须：高风险场景设置人工审核阈值，置信度不够高时必须有人拍板
- **原因**：自动化系统不应在可能造成严重后果的决策上拥有100%自主权

## 完整示例：provenance-driven-trust模式中的知识库规则

```markdown
### 规则5：知识/经验库累积（含负反馈）

系统从每次运行/验证中积累经验和知识条目，支持后续优化。每个条目带置信度分数和来源追踪。

#### 5.1 条目生命周期

| 阶段 | 规则 | 参数 |
|------|------|------|
| **创建/初始准入** | 新条目（如优化规则、问题模式）进入知识库 | 初始置信度：0.5 |
| **正向反馈** | 该知识在后续运行中被验证有效，置信度+0.1 | 每次独立验证成功：+0.1 |
| **负向反馈** | 该知识导致错误或被证伪，置信度-0.2 | 每次验证失败：-0.2（惩罚>奖励） |
| **时间衰减** | 90天未被重新验证的条目置信度自动×0.8 | 衰减周期：90天；衰减系数：0.8 |
| **证伪/归档** | 连续2次被证伪或置信度<0.2 → 归档禁用 | 连续2次失败；阈值：0.2 |
| **人工审核** | 风险等级≥High的条目应用前必须人工确认 | 高风险场景不自动应用 |

#### 5.2 置信度区间与行为映射

| 置信度区间 | 行为 | 使用限制 |
|-----------|------|---------|
| ≥ 0.8 | 自动应用 | 低风险场景 |
| 0.5 - 0.8 | 可应用，事后审计 | 中风险需交叉验证 |
| 0.3 - 0.5 | 建议值，需人工确认 | 不可自动决策 |
| < 0.3 | 仅参考 | 高风险禁用 |
| < 0.2 / 归档 | 禁用，不检索 | 人工审核方可解除 |

#### 5.3 防错误复合机制

- [x] **幂等验证**：同一用例重复验证不重复加分
- [x] **独立验证**：不同用例/场景独立计数
- [x] **近期权重**：最近3次结果权重×1.5
- [x] **审计日志**：每次变更记录原因、来源、时间戳

#### 5.4 冷启动策略

- 初始默认值：0.5
- 前3次应用强制人工审核
- 积累5条以上独立验证记录后进入正常模式
```

## 反模式清单（设计时必须避免）

| 反模式 | 为什么危险 | 正确做法 |
|--------|-----------|---------|
| "初始置信度1.0" | 未验证内容被完全信任，一个错误就能污染整个系统 | 初始0.3-0.5，逐步提升 |
| "只奖不罚" | 错误知识永远留在系统中，还会被重复使用强化 | 失败惩罚>成功奖励 |
| "一次验证永久有效" | 环境变化后旧知识变成毒药 | 时间衰减+周期性复核 |
| "降权不除名" | 低置信度条目仍可能被检索到，继续误导决策 | 达到阈值归档禁用，人工解除 |
| "全自动学习+全自动决策" | 系统在错误道路上自我强化，无人干预 | 高风险必须有人工审核闸口 |

## 快速自检问题

设计完自积累机制后，回答以下5个问题，任何一个答不上来就说明设计不完整：

1. ❓ 新进来的东西你信几分？（初始值）
2. ❓ 做对了加多少？做错了扣多少？（正负反馈）
3. ❓ 多久没用了会过期？（时间衰减）
4. ❓ 错几次就彻底拉黑？（证伪归档）
5. ❓ 多大的事儿必须人来拍板？（人工审核）
