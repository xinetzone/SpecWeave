# 统计型声明实证核验清单（声明对账）

> 配套模式：[声明对账](../../playground/pipeline-parable/retrospective/pattern-declaration-reconciliation.md)（L1，单案例待验证）。
> 核心原则：产出物中的自我声明（"合计/不超过/均为/全部/覆盖/无"）不是写作的收尾语，而是需要自证的契约。**写声明时作者并不掌握全文实际状态**，必须实证核验。

## 🚨 触发条件

以下任一成立即启用本清单：

- [ ] 产出物含统计型声明："共计 N 条/处/字"、"不超过 X"、"占比 X%"、"全覆盖"
- [ ] 产出物含合规承诺："均为短语级引用并标注页码"、"不含隐私数据"、"已脱敏"
- [ ] 产出物经多轮 SearchReplace / 分批改写 / 多人协作（作者记忆与文本已可能脱节）
- [ ] 文档包含索引/ README / 总览页（自声明高发位置）

## 🛡️ 核验步骤（5 步）

### 步骤 1：声明扫描
- [ ] 通读产出物，摘出全部自我声明句（特征词：合计、共计、不超过、均为、全部、覆盖、无断链、无遗漏）
- [ ] 每条声明编号登记（D-001 起），注明所在文件与位置

### 步骤 2：实证对账
- [ ] 字数类声明：逐条实际统计（用搜索/脚本数，不用印象估）
- [ ] 条数类声明：逐项实际枚举并计数
- [ ] 覆盖类声明：范围清单逐项映射到实际内容（如需求→章节映射）
- [ ] 否定类声明（"无断链/不含 X"）：全量扫描验证（正则/链接检查器），非抽查

### 步骤 3：缺口定性
- [ ] 声明宽于事实（声明过头）→ 标记必修
- [ ] 事实宽于声明（声明过保守）→ 记录可选修

### 步骤 4：双向修正（方向铁律）
- [ ] **优先修正内容**，使现状符合更严标准（如削减过长引用以符合红线）
- [ ] 内容无法修正时，**下调声明至与事实一致**
- [ ] 禁止反向操作：上调/放宽声明以迁就现状（把契约改成愿望）

### 步骤 5：声明回写
- [ ] 修正后的声明写入产出物，且声明本身可被独立复核（标准可度量、方法可重放）
- [ ] 声明与验证方法一并留痕（如"均为 30 字以内短语级引用并标注页码"）

## 🔴 高发反模式（本案教训）

| 反模式 | 表现 | 本案实例 |
|------|------|---------|
| 先写声明后产出 | 骨架阶段先写"引用不超 50 字"，正文未完成 | index.md 声明与实际约 100 字不符 |
| 凭印象填统计数 | 数字来自写作记忆而非实际统计 | 多轮改写后记忆与文本脱节 |
| 审查只查格式链接 | V 清单无声明对账固定项 | 最高发缺陷类别漏检 |
| 反向修正 | 放宽声明消除矛盾而非收敛事实 | 本案未发生；列为禁止项 |
