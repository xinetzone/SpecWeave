# 文档流水线模式跨领域复现检查清单（A-007）

> 配套模式：[文档自动化生成与验证流水线模式（文档流水线模式）](../../docs/retrospective/patterns/methodology-patterns/concepts/doc-automation-pipeline.md)（L1-draft，单案例：SpecWeave 智能文档系统）。
> 用途：在**第 2 个独立且跨领域**的案例中逐项复现模式 5 个核心步骤与全部检验标准，留证并通过判定线后，模式由 L1-draft 升级 L2-validated（validation_count=2）。
> 与 A-004/A-005/A-006 的区别：前序清单的第二案例仅要求"不同源、不同场景"，本模式因抽象层级为跨领域流程模式（L3-process），**强制要求第二案例跨领域**（优先非软件领域），并须实证 V 阶段修正的三个新论点（门禁分层、单一事实源、脚本护栏）。

## 🚨 启用条件（全部成立才启用）

- [ ] **独立性**：候选文档库与案例 1（SpecWeave docs/）不同组织、不同语料、不同维护者；复用案例 1 的脚本须以"换库运行"方式验证，禁止在同一语料上换个目录跑一遍冒充复现
- [ ] **跨领域性**：候选不属于"AI 协作/软件技术文档"领域；若实在只有软件领域候选，须满足"不同组织 + 不同产物类型"（如商业产品手册 vs 开源 Wiki）并在报告中降级声明
- [ ] **规模条件**：文档/记录条目 ≥100，且至少满足其一——①已感受到人工索引/引用维护负担（有断链、版本失效等历史故障可查）；②允许在执行中观察并记录"人工维护崩溃拐点"的实际规模
- [ ] **机器可验证性**：至少存在一种可机器执行的校验需求（引用有效性、版本现行性、元数据完整性、覆盖率之一），有脚本运行环境（CI、定时任务或可重复执行的本地命令）
- [ ] **门禁真实性**：存在真实的审查/验收环节（他人审查、发布审批、外审认证），门禁须至少真实拦截或试运行拦截一次，禁止"写了门禁从不执行"
- [ ] **留证许可**：基线数据、生成结果、门禁日志允许留档（涉密/隐私内容按内容敏感度预检走 playground 私域）

## 🎯 候选案例与选择评分

| # | 候选类型 | 例子 | 跨域强度 | 主要风险 |
|---|---------|------|:---:|---------|
| C1 | 企业受控文档体系（非软件域，优先） | ISO 9001 质量体系程序文件/SOP、医疗机构制度规程库、法务合同模板库 | ★★★ | 准入与数据敏感度高，多属私域 |
| C2 | 数据团队文档（相邻跨域） | 数据仓库数据目录、指标字典、血缘文档 | ★★ | 与软件域边界模糊 |
| C3 | 其他组织的软件文档库（保底） | 外部开源项目（mdBook/Sphinx 系，数百条目以上） | ★ | 不满足跨领域，仅能升"跨项目 L2"，须降级声明 |

选择评分（满分 100，≥70 立项）：独立性 20 + 跨领域 30（非软件域满分，C3 得 5）+ 可留证 20 + 规模/拐点可见 20 + 真实审查环节 10。

## 🔍 步骤 0：基线审计（任何路径必做）

- [ ] 建立 4 项基线并留证（**先于一切自动化动作测量**）：
  1. 条目/目录总数与统计口径（写清"什么算一个条目"）
  2. 失效引用数：抽样或全量扫描（死链、引用了废止版本/失效文件）
  3. 覆盖率：应有索引/README/受控清单而缺失的比例
  4. 人工全量维护一轮的实际耗时（计时，至少一轮）
- [ ] 记录历史故障证据（过去因索引/引用/版本问题发生的事故或批量返工）
- [ ] 留证：基线审计原始输出（命令输出/扫描报告），与案例 1 的 F22/F38 同等性质

## 🛡️ 复现步骤（5 步，对应模式核心步骤，逐步留证）

### 步骤 1：统一元数据契约
- [ ] 定义本领域 frontmatter/受控字段（对标 title/type/source/date，可化为文件编号、版本号、生效日期、归口部门）
- [ ] 字段集来自门禁需求反推（门禁要查什么才定什么字段），不无脑照搬 YAML 形态
- [ ] 留证：元数据规范文本 + 新旧字段映射（存量系统走路径 B 时）

### 步骤 2：模板/说明生成器
- [ ] 存在模板化批量生成需求（SOP 模板发放、目录页/受控清单生成等），以脚本生成替代人工逐份编写
- [ ] 生成器支持"模板实例化 + 自动索引"两类产出（对标本模式 Strategy B/C，但可用本领域工具实现）
- [ ] 留证：生成器入口命令、一次批量生成的输入输出清单

### 步骤 3：验证器（机器门禁前置）
- [ ] 实现至少一个本领域特有的全量校验器（如：引用文件是否现行有效、废止版本是否仍在发放清单、必填元数据是否齐全）
- [ ] 验证器对基线库实际运行并报告真实问题数（与步骤 0 基线对账，差异须解释）
- [ ] 留证：校验器命令、首次运行输出（含真实发现，不允许 0 问题的完美首跑）

### 步骤 4：索引/导航生成器与单一生产者
- [ ] 每个派生产物（索引/清单/导航）只有一个生产者；如存在既有人工维护的 Hub，执行"二选一"处置：改为从生成器派生，或显式划界并纳入契约检查
- [ ] **幂等实证**：生成器连跑两次，第二次输出 diff 为空（命令输出留证）
- [ ] 留证：生产者归属表（产物 → 唯一生产者）、两次运行的 diff 证据

### 步骤 5：两层门禁接入
- [ ] **通用机器门禁**：引用有效性 + 元数据契约 + 格式 + 覆盖率基线，接入发布/提交前环节
- [ ] **本领域专用门禁自行定义**（关键实证项）：证明分层设计成立——**禁止照抄案例 1 的 G1-G4 语义门**，须按本领域产物类型定义专用检查（如医疗域"知情同意书模板与最新法规版本一致"）
- [ ] 门禁至少真实（或试运行）拦截 1 次不合格产出，有拦截记录
- [ ] 留证：门禁配置、拦截记录、不合格返工记录

## 🧪 V 修正点专项实证（三项必须有独立证据）

| 实证项 | 证据要求 | 对标的 V 意见 |
|---|---|---|
| 门禁分层成立 | 专用门禁名称/规则为案例领域原生定义，文档中无 G1-G4 直接搬运痕迹 | V1 |
| 单一事实源成立 | 无脚本/人工双生产者分叉；重生成不产生断链；幂等 diff 空 | V5 |
| 脚本护栏成立 | 生成/验证脚本至少各有 1 条自动化测试或 dry-run 模式；记录一次脚本缺陷被护栏拦截（未发生则记录刻意注入的演练） | V4 |
| 阈值论点修正 | 记录本案例"人工维护崩溃拐点"实际规模；若显著偏离约 500，据实修正模式表述（证实/证伪皆为有效产出） | V2 |

## ✅ 复现后验收（模式检验标准逐条打勾）

- [ ] 失效引用：治理后新增失效引用 = 0（全量扫描输出留证）
- [ ] 覆盖率：向 100% 收敛的路径与批次记录完整；达成率以实测为准，禁止口径漂移
- [ ] 索引时效：单次全量生成耗时有记录（不必 <1 小时，记录本领域实际值作为模式参数修正依据）
- [ ] 门禁自动化：门禁嵌入流程且有拦截记录，不依赖人工自觉
- [ ] 单一事实源：生产者归属表完整、幂等性已实证
- [ ] 声明对账：报告中全部"0/N%/全覆盖"类声明经实证核验，对接 [声明对账清单](declaration-reconciliation-checklist.md)

## 🔴 反模式自查（5 条逐项确认未触犯）

| 反模式 | 自查问题 |
|------|---------|
| 人工维护大规模索引 | 治理后是否仍有"靠人记住要更新"的索引？ |
| 跳过验证直接发布 | 是否存在未过门禁就发布/发放的批次（紧急通道是否有补验）？ |
| 脚本与文档分离 | 生成器变更后是否有机制同步重生成全部派生文档？ |
| 多生产者无单一事实源 | 同一索引/清单是否同时能被脚本和人工改动？（对应 53a82f8c3 教训） |
| 脚本无测试护栏 | 批量脚本是否无测试、无 dry-run、无幂等复验？（对应 c6b98309d 教训） |

## 🏁 适应分级与升 L2 判定

复现中的差异按三级分类记录于复现报告：

| 级别 | 含义 | 对升 L2 的影响 |
|---|---|---|
| 参数级适应 | 阈值、字段名、文件格式、工具命令不同 | 允许，作为模式参数补充 |
| 组件级替换 | 工具替换（Sphinx→本领域文档系统等）、产物形态不同，但"契约→生成→门禁"结构不变 | 允许，作为迁移例补入模式文档 |
| 内核级修改 | 三元结构本身不成立（如门禁无法机器化、单一生产者无法建立） | 升 L2 失败：模式回 E/V 阶段修订或标注边界，维持 L1 |

**判定线（缺一不可）**：
1. 启用条件 6 项全部成立；
2. 步骤 0-5 全部留证复现；
3. V 修正点专项实证 4 项全部有证据（含真实拦截与幂等 diff）；
4. 验收 6 条与反模式自查 5 条全过；
5. 适应分级中**无内核级修改**。

未过线：模式维持 L1-draft，缺陷记入复现报告并反哺模式反模式/边界；仅 C3 保底案例通过的，模式可升"跨项目验证"但不得声称跨领域，须在 maturity_note 注明。

全过后执行：
- [ ] 模式文档 `maturity` 改为 `L2-validated`、`validation_count: 2`，成熟度说明补记案例 2 来源（组织/领域/规模）
- [ ] 将参数级/组件级适应结果回填模式文档（迁移示例表去"推演"标注、阈值参数更新）
- [ ] 案例 2 证据包归档：基线审计、元数据契约、生成/验证器证据、生产者归属表、幂等 diff、门禁拦截记录、声明对账记录
- [ ] 复现报告按内容敏感度分流：公开案例入 `docs/retrospective/reports/`，私域案例入 `playground/`；更新 methodology-patterns 索引成熟度列（向用户申请后执行）
