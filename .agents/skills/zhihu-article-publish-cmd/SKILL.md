# 知乎文章发布自动化 Skill

> 萃取自 sc-20261023-zhihu-article-publish 实战（知乎「记忆实验室」参赛文章发布全链路：Draft.js 填充 → 5 图插入 → 发布设置 → 发布 → 话题补加）。本 Skill 将「知乎编辑器 + 发布设置」的自动化契约固化为可重复执行的流程与已验证的通道选择。

## 1. Skill ID

`zhihu-article-publish-cmd`

## 2. 功能描述

提供知乎写文章编辑器的**已验证通道组合**（每个环节只给出实测可行的路径），核心能力：

1. **文本输入**：CDP `Input.insertText` + `Input.dispatchKeyEvent`(Enter) 逐段输入（Draft.js 唯一持久化通道）
2. **配图插入**：file input id 注入 → `bu.upload_file` → 上传状态文案确认 → JS 点击「插入图片」
3. **发布设置**：话题四步选择法、创作声明设置、已发布文章「更新」
4. **发布后回读验证**：话题 `a[href*="/topic/"]` 文本集合、创作声明文案、图片计数、作品链接

> **为什么通道选择是本 Skill 的核心？** 知乎编辑器是 Draft.js，程序化输入的常规手段（bu.type / execCommand / 剪贴板注入）全部不持久化或不可用，实测仅 CDP 原生输入流可靠。直接照搬通用浏览器自动化套路会反复陷入「页面有字、刷新即丢」的假成功陷阱。

## 3. 何时使用本技能

当用户提到以下任何内容时触发：

- "写文章"、"发布文章"、"知乎专栏"、"zhuanlan"、"写文章编辑器"
- "填知乎编辑器"、"插入配图"、"补图"、"插图"、"豆包截图"、"文章配图"、"话题没加上"、"补话题"
- "创作声明"、"发布设置"、"更新文章"、"已发布文章修改"
- "上传到知乎知识库"、"knowledge upload"、"Skill 备份到知乎"
- 任何「React/Draft.js 富文本编辑器自动化填充」请求（通用迁移）

> **关于触发**：即使没有说"用 skill"，只要目标是知乎写文章编辑器或已发布文章，就应该使用本技能——通用浏览器自动化在本编辑器下必然踩 Draft.js 拦截（合成事件被拒）与候选组件坐标偏移两大坑。

## 4. 方案选择决策树

```
收到「文章填充/发布」请求？
├─ 目标为知乎写文章编辑器（Draft.js）？ → 走本 Skill 第 6-9 节
│   ├─ 需输入标题/正文？ → CDP Input.insertText 通道（第 6 节）
│   ├─ 需插入配图？ → 图片插入四步法（第 7 节）
│   └─ 需发布/更新/补话题？ → 发布设置 + 回读验证（第 8-9 节）
├─ 目标为原生 textarea/input？ → 常规 type 即可，不走本 Skill
├─ 目标为已发布文章（补话题/改声明）？ → 编辑页「更新」按钮流程（第 8.3 节）
└─ 目标编辑器有官方 API？ → 优先官方 API，本 Skill 为兜底
```

> **为什么先确认编辑器类型？** Draft.js 与原生输入控件的自动化通道完全不同；对 Draft.js 用常规 type 会浪费轮次且无法定位问题（见 Gotchas 10.1）。

- **可选通道**：知乎开放平台 CLI（`zhihu` Skill，`knowledge upload` 命令）可将本 Skill 的 SKILL.md 上传到个人知识库备份（需 Access Secret 授权；仅用户明确要求时执行，固定带 `--progress`）。

> **为什么发布要确认？** 发布动作将文章公开上线，属外部不可逆操作；用户预先授权「直接发布」时可跳过确认，否则按系统确认规则执行。

## 6. 步骤 1：文本输入（CDP 原生输入通道）

```
1. 聚焦目标块：JS `Range.selectNodeContents(el) + collapse(false) + focus` 或点击块内位置
2. CDP Input.insertText 注入段落文本（逐段注入）
3. CDP Input.dispatchKeyEvent（keyDown/keyUp Enter）换行分段
4. 刷新页面验证内容持久化（段落数/字数/标题与注入源一致）
```

- 标题与正文分开注入；正文逐段注入（每段一次 insertText + 一次 Enter）。
- 换行用 Enter（`keyDown`+`keyUp`），不要用 insertText 内的 `\n`。
- 已发布文章编辑页打开时，正文已在；仅补改时用相同通道增量输入。

> **为什么逐段注入？** Draft.js 按块（block）管理内容，一次注入全文会丢失段落结构或整段内容；每段一次 insertText 后 Enter 断块，刷新后段落数与源一致（实战 25 段全部通过）。

## 7. 步骤 2：配图插入（四步法）

```
1. 打开上传面板：bu.find("图片")（工具栏图片按钮）点击
2. 注入 id：JS 给页面全部 input[type=file] 设 id（第 4 个 input 生效，即 #zhihu-up-3）
3. 上传：bu.upload_file("#zhihu-up-3", 绝对路径) → 等待「已上传 1 张图片，拖拽可调整顺序」文案出现
4. 插入：JS 遍历 button 且 textContent.trim()==='插入图片' 者 .click() → 验证图片计数 +1
```

- **光标定位**：插入前用 JS Range 定位到目标段尾（`selectNodeContents + collapse(false) + focus`）；图片插入到光标所在块之后。
- **上传状态确认**：上传后必须等到「已上传 1 张图片」文案，再点插入；未就绪时点击可能无效果且面板自动关闭。
- **面板自动关闭**：上传后面板可能自动关闭（无「插入图片」按钮）；此时重新打开面板并重复 2-4 步。
- **按钮触发**：优先 JS 点击「插入图片」button（`bu.find` 返回的 box 容器点击在图 3/图 4 生效、图 5 失效，不可依赖）。

> **为什么 JS 点击 button 而非 find 容器？** 上传面板中「插入图片」的可交互元素是 button；`bu.find` 可能返回外层 box 容器，点击容器的事件路由在部分场景不触发插入（实战图 5 两次失败，JS 点击 button 一次成功）。

## 8. 步骤 3：发布设置

### 8.1 话题添加（候选四步选择法）

```
1. 打开发布设置 → 点「添加话题」→ 搜索框输入话题关键词
2. 等待候选列表稳定（≥1.5s）
3. JS 遍历 button/元素，textContent.trim()==='目标话题' 者 .click()
4. 验证话题标签行 DOM 包含目标话题（DIV css-nut0iz 集合）
```

- 话题候选是动态列表：`bu.find` 点击候选容器、Enter 默认项、坐标点击均不可靠（坐标点击可能命中相邻候选）。
- 验证目标是**话题标签行**（已添加话题集合），不是候选菜单；标签行元素为 DIV（css-nut0iz 类），候选为 button（css-ogem9c 类）。
- 已发布文章编辑页打开发布设置后，话题标签行可能已含目标话题（发布未生效时）；确认存在后直接进入更新（第 8.3 节）。

> **为什么必须验证标签行？** 候选「看起来选中」与「真正加入标签行」是两个独立状态；只有标签行 DOM 检测确认，才代表话题已入草稿设置（实战坐标点击命中了相邻的「有趣的人工智能」话题）。

### 8.2 创作声明

- 点击创作声明下拉（默认「无声明」）→ 选择「包含 AI 辅助创作 作者对内容负责」。
- 已发布文章重新进入编辑页时，创作声明可能重置为「无声明」——必须检查并恢复（见 Gotchas 10.3）。

### 8.3 发布 / 更新

- **首次发布**：底部按钮为「发布」；点击后跳转文章页（`/p/xxx`）。
- **已发布文章修改**：底部按钮为「更新」；点击后跳转回文章页，草稿设置同步到线上版本。
- **dry-run 门**：发布/更新前执行 dry-run 预览——点击编辑器底部「预览」按钮检查渲染效果（标题/正文/配图/话题标签），或向用户展示最终状态截图并获得确认；用户已预先授权「直接发布」时，dry-run 以发布前状态回读（编辑页 DOM 检测）代替。dry-run 通过后才执行发布/更新动作。
- 发布/更新前关闭发布设置面板（Esc）与候选菜单，确保按钮可用。

## 9. 步骤 4：发布后文章页回读验证

```
1. 导航至文章页 URL（/p/xxx）
2. 话题：JS 收集 a[href*="/topic/"] 的 textContent 集合，确认包含全部目标话题
3. 创作声明：页面文案含「包含 AI 辅助创作」与编辑时间
4. 配图：确认正文配图在线（视觉或 DOM 图片计数）
5. 作品链接/标注：a[href*="project/detail"] 存在、「此项目投稿至…」文案存在
6. 存档发布截图（话题区/顶部/链接/标注）到 evidence/ 台账
```

- 验证以**文章页**为准，不以编辑页状态为准（编辑页草稿设置 ≠ 线上生效状态）。
- 截图命名按台账约定（`01-article-top.png`、`02-topics-declaration.png` 等）。

## 10. Gotchas（陷阱与反直觉行为）

### 10.1 Draft.js 输入通道（本 Skill 最大陷阱族）

- **bu.type / 合成事件不持久化**：页面显示有字、刷新即丢（Draft.js 状态树未更新）。
- **execCommand('insertText') 假成功**：DOM 可见但编辑器 state 为空 → 占位层不隐藏（叠影）+ 保存不持久。
- **剪贴板注入被拒**：clipboard 权限弹窗挂起（grantPermissions 后仍 pending），无法完成粘贴。
- **唯一可靠通道**：CDP `Input.insertText` + `Input.dispatchKeyEvent`(Enter)；验证成功标准 = 刷新后内容仍在。

### 10.2 动态候选与图片面板

- **话题候选坐标偏移**：候选位置随输入实时变化，坐标点击命中相邻项（实战命中「有趣的人工智能」）；用 JS 文本精确点击。
- **上传面板自动关闭**：上传后未及时插入，面板关闭、按钮消失；重开面板并确认「已上传」状态后重试。
- **「插入图片」按钮触发**：`bu.find` 返回 box 容器不可靠；JS 点击文本恰为「插入图片」的 button 可靠。
- **图片插入位置**：图片插入到光标所在块之后；光标定位用 JS Range 段尾。

### 10.3 已发布文章重编辑

- **发布设置重置**：已发布文章重新进入编辑页时，创作声明重置为「无声明」，需检查并恢复。
- **发布版话题缺失**：编辑页标签行含话题 ≠ 发布版文章页含话题；发布后回读文章页确认，缺失则编辑页确认后「更新」。
- **按钮变化**：已发布文章的底部按钮为「更新」（非「发布」）；「更新」才把草稿设置同步到线上。

## 12. 常见问题处理

| 问题 | 场景 | 处理方式 |
|------|------|---------|
| 文本刷新丢失 | Draft.js 合成事件/execCommand 输入 | 改用 CDP `Input.insertText` 逐段输入 |
| 「插入图片」点不动 | bu.find 返回 box 容器 | JS 遍历 button 文本恰为「插入图片」者 click |
| 上传后无插入按钮 | 面板自动关闭 | 重开面板 → 重新上传 → 确认「已上传」→ 立即 JS 点击 |
| 话题选不中 | 候选动态/坐标偏移 | JS 文本精确点击 + 标签行 DOM 验证 |
| 发布版缺话题 | 发布时话题未生效 | 编辑页确认标签行 → 点「更新」→ 文章页回读 |
| 声明变「无声明」 | 已发布文章重编辑重置 | 恢复「包含 AI 辅助创作」后更新 |
