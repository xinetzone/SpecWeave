# 七步故事法骨架校验 (Seven-Step Story Skeleton)

## 1. Skill ID

`qibu-story-cmd`

## 2. 功能描述

把「一个故事为什么会走到它的结局」拆成七个可回答的问题，并给出**可证伪的验收动作**：

| 模式 | 推荐场景 | 产出 |
|---|---|---|
| **A · 新建骨架** | 只有点子/一句话，还没有结构 | 七格表 + 删步测试结论 + 付费墙切点 |
| **B · 诊断改稿** | 已有稿，读者反馈「后面强行/高潮没劲」 | 七格回填 + 最弱一格 + 一处改法 |
| **C · 反向拆解** | 读平台热文，想学结构 | 每篇 7 行拆解表 + 平台偏好结论 |

核心动作只有四个：**填七格 → 三次删步 → 判意外极性 → 定付费墙**。

> **为什么不做「一键生成故事」？** 七步法的六份公开来源里，完整示例全是**拆已有作品**（盲人乞讨 / 八十天环游世界 / 海的女儿），
> 作者自己也说「凡套路都是三流的」。它最可靠的用法是**校验器**，不是发电机：先有冲突内核，再用它检查因果是否闭合。
> 直接拿它生成，产出会是「结构挑不出错、但没人想读」的三流文本。

## 3. 何时使用本技能

当用户提到以下任何内容时触发：
- 「七步故事法」「靶心人公式」「故事公式」「七步成文」
- 「目标—阻碍—努力—结果—意外—转弯—结局」或其中任意三步
- 「骨架」「故事结构」「因果链」「后面为什么强行」「高潮不成立」
- 「删步测试」「意外极性」「付费墙切在哪」「第几步之后收费」
- 「AI 模板六步和七步是不是一回事」

> **关于触发**：即使用户没说「用 skill」，只要请求涉及「故事结构是否成立」，就应使用本技能，
> 不要凭直觉给建议——本技能封装了每一步的**过关判据**与**失效条件**，凭直觉容易漏掉第 4/5/6 步的三个坑。

## 4. 方案选择决策

```
用户手里有什么？
├─ 只有一个点子/一句设定 ────────────────→ 模式 A（第 7 节）
├─ 有一篇写完的稿/大纲 ─────────────────→ 模式 B（第 8.1 节）
├─ 有别人写好的作品，想学结构 ───────────→ 模式 C（第 8.2 节）
└─ 问「六步模板 vs 七步」────────────────→ 直接读 references/compiled-methodology.md §6

用户明确只要「故事灵感/选题」？
└─ 不适用本技能 → 选题与情绪内核不在七步范围内
```

**写操作原则（dry-run / 预览确认）**：本技能只产出**骨架与诊断**，不代写全文、不改用户原稿。
所有改稿建议先以预览形式给出 diff（哪一格 → 现在是什么 → 改成什么），
**用户明确确认后才落盘**；未确认前一律 dry-run，只展示不写入。

> **为什么先判模式再动手？** 三种模式的输入完全不同：模式 A 的失败是「目标不可判定」，模式 B 的失败是「某一格空转」，
> 模式 C 的失败是「拿情绪轴去量结构轴」。用错模式，会得到正确但无用的答案。

## 5. 输入参数

| 参数 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| story | string | 是 | - | 点子、草稿、大纲或待拆作品；无内容时先索要 |
| mode | string | 否 | auto | `auto`/`new`/`diagnose`/`reverse` |
| target_words | int | 否 | 10000 | 目标字数；用于付费墙与低谷预算换算 |
| platform | string | 否 | 未知 | 投稿平台；只影响免费段口径，不用于预测过稿率 |
| free_words | int | 否 | 3000–4000 | 免费试读段字数；平台口径不同时由用户确认 |

## 6. 依赖与前置准备

- **必读参考**：[references/compiled-methodology.md](references/compiled-methodology.md)（运行时首选，含七格判据、删步测试、极性表、字数映射）
- **证据与边界**：[references/evidence.md](references/evidence.md)（六份公开来源、作者自评「三流」、四源第 6 步冲突）
- **可选上游**：选题/情绪内核来自用户的真实生活细节；本技能**不提供**选题
- **可选下游**：强度曲线与爽点排布属于另一套模型，本技能只给「低谷插在哪、墙切在哪」，不给爽点配方

> **为什么没有脚本？** 七步校验的判断对象是「一句话是否可判定、删掉一格故事是否还成立」，
> 这是语义判断，写死成脚本只会产出假阳性。本技能坚持「人来判、清单来防漏」。

## 7. 模式 A：新建骨架（主流程）

### 7.1 七格表（每格一句话，不许写两句）

| # | 问题 | 过关判据 | 常见写坏 |
|---|---|---|---|
| 1 目标 | 他要什么？输了失去什么？ | 能判定成败、有代价 | 「想变强」「想被爱」 |
| 2 阻碍 | 谁/什么在挡？ | 阻碍消失故事不成立 | 运气差、天灾，无加害者 |
| 3 努力 | 他**做了什么**动作？ | 删掉动作结果不会发生 | 写成心里发誓 |
| 4 结果 | 失败在哪？付出什么代价？ | 是失败，不是「虽败犹荣」 | 一次就成功 |
| 5 意外 | 什么**超出努力**的事发生了？ | 再努力一点解决不了 | 天降帮手、主角觉醒 |
| 6 转弯 | 他因此改了什么（做法/立场/目标）？ | 与第 3 格做法明显不同 | 写成「解释意外」或「情绪反应」 |
| 7 结局 | 得到/失去了什么？ | 回应第 1 格目标 | 留续集钩子 |

### 7.2 三次删步测试

| 删掉 | 通过标准 | 不通过说明 |
|---|---|---|
| 第 2 格（阻碍） | 故事**不成立** | 你没有冲突，只有愿望 |
| 第 5 格（意外） | 成立 → 删掉它是装饰；**不成立** → 回查前文有没有埋过它 | 没埋过的意外 = 作者帮忙 |
| 第 6 格（转弯） | 故事**不成立** | 第 6 格只是解释，不是转向 |

### 7.3 判意外极性，定付费墙

| 意外是 | 墙切在 | 理由 |
|---|---|---|
| 转机（好消息） | 意外揭晓的瞬间 | 读者刚看到希望，最想知道怎么用 |
| 噩耗（坏消息） | 转弯的开头，不是意外本身 | 切在噩耗处，读者正处最低点，最想关页面 |

字数换算（**本库推断，不是原文**）：`W` 取投稿门槛（短篇 8,000–12,000 字），免费段 `F` 取 3,000–4,000 字；
第 1–4 格必须在 `F` 内跑完，第 5 格落在 `F` 内或紧贴其末。超过 12,000 字，七步线性结构会被压扁。

### 7.4 可选：插低谷

七步里**没有「全文最低点」**。若第 4 格只是「第一次失败」，在第 4 与第 5 格之间插一格
「低谷：失去核心筹码 + 公开受辱」，再让意外出现。这一步属于跨模型补丁，写清「本库推断」。

### 7.5 输出契约

```
【七格】1…7 各一句
【删步】阻碍=不成立/成立；意外=装饰/依赖并说明埋点；转弯=真转向/伪转向
【极性】意外=转机/噩耗 → 墙切在 ______ 字
【最弱一格】第 N 格，因为 ______
【一处改法】把 ______ 改成 ______
```

## 8. 模式 B / C

### 8.1 模式 B：诊断已有稿

1. 回填七格（用稿子**实际怎么走**，不是本该怎么走）
2. 逐格对照第 7.1 节判据，标出**最弱一格**
3. 做三次删步测试；第 5 格「不成立」时，检查前文有没有埋点
4. 只给**一处**改法：改最弱那一格，不动其他格
5. 若用户要求改多格，先说明「因果链会整体位移」，让用户确认后再动

### 8.2 模式 C：反向拆解

1. 选 3 篇同平台同类型作品（不跨类型，否则无法比较）
2. 每篇 7 行，逐行填第 7.1 节的七格
3. 标出每篇最弱一格（通常是第 4 或第 6 格）
4. 记录付费墙落在第几格之后
5. 三篇对比，给出平台偏好（转机型 or 噩耗型第 5 格）

## 9. 与其他 Skill / 模型的边界

| 模型 | 回答 | 本技能不给 |
|---|---|---|
| 爽点三步法 / 爽点五型 | 读者为什么爽、欠什么债 | 不给选题、不给爽点配方 |
| 付费漏斗 | 钱在哪一步收 | 不估算收入、不预测过稿率 |
| AI 六步模板 | 现在该产出什么、谁来确认 | 不把它当故事结构（见 references §6） |

> **为什么边界要写死？** 这三套模型混用会互相否定：拿「信息差必不必要」否定成长型故事、
> 拿「结构完整」当质量保证、拿模板的六步当七步。边界不清，结论一定错。

## 10. 安全检查清单

- [ ] 已确认模式（A/B/C），没有一上来就生成故事
- [ ] 七格每格只有一句话，且可判定
- [ ] 三次删步测试各有明确结论
- [ ] 意外已判极性，墙位有字数依据
- [ ] 字数映射已标注「本库推断」，没有说成原文
- [ ] 没有承诺过稿率、收入或「学会就能签约」
- [ ] 没有把公开「靶心人公式」说成课程原文（来源视频号正文不可访问）
- [ ] 没有代写全文；改稿只给「改哪一格 + 怎么改」
- [ ] 改稿建议已用 dry-run 预览展示，并获得用户确认后才写入
- [ ] 强反转故事已改为倒着搭（先定结局，再回填）
- [ ] 输出包含「最弱一格」与「一处改法」

## 11. 常见错误处理

| 错误码 | 场景 | 处理方式 |
|---|---|---|
| QIBU_001 | 用户只给「写个爽文」，七格填不动 | 先要四项：题材、主角、情绪内核、目标字数；仍没有就停止 |
| QIBU_002 | 第 1 格无法判定成败 | 改写为「他赢了会怎样、输了失去什么」；改不动就说明故事没有目标 |
| QIBU_003 | 第 5 格「再努力一点能解决」 | 判定它不是意外，退回第 3 格；或把第 5 格换成外部转机/噩耗 |
| QIBU_004 | 第 6 格与第 3 格做法相同 | 判定伪转弯；要求主角换策略/立场/目标 |
| QIBU_005 | 用户要求直接写 1 万字全文 | 拒绝代写；只交付骨架与节点，正文由用户完成 |
| QIBU_006 | 用户问「七步和 AI 模板六步是不是一回事」 | 按 references §6 区分：流程 / 结构 / 校验三层 |

## 12. Gotchas（陷阱与反直觉行为）

- **七步不是七章**：它是因果检查表，不是目录。一章可以覆盖三步，一步也可以跨三章。
- **第 4 格不是低谷**：它只是第一次失败。把第 4 格当低谷，高潮会没有落差可放。
- **「意外」必须超越努力**：再努力一点就能解决的，是第 3 格的延长，不是第 5 格。
- **第 6 格有四种写法**：转弯/反转/转折，以及情绪反应/机制解释/结果改善/方向改变。本技能采用**方向改变**，
  因为它能解释「为什么第 6 格最容易被跳过」；其余三种不删不改，引用时写清用哪一种。
- **强反转不能正着填**：叙诡、身份反转、真相最后揭，按顺序搭会把底牌写在第 1–2 格。先写结局，再回填。
- **模板六步 ≠ 七步**：模板是交付流程（一句话→五句话→人物页→大纲），七步是因果结构。
  模板第 3 步里的「三幕 + 五句话 + 三次两难」是结构要求，但**也不是七步**。
- **字数映射是推断**：六份来源**没有一份**给过任何一步的字数或占比。别把它当行业标准。
