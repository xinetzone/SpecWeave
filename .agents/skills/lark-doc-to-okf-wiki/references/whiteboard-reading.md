# 画板判读：节点结构、文案抽取与三类归类

## 1. raw 节点结构

`whiteboard +export --output-type raw` 返回：

```json
{
  "ok": true,
  "data": {
    "nodes": [
      {
        "id": "a17:260",
        "type": "text_shape",
        "x": 68, "y": 2184, "width": 56, "height": 28,
        "angle": 0, "z_index": 130,
        "text": {
          "text": "真用",
          "font_size": 14,
          "font_weight": "bold",
          "rich_text": { "paragraphs": [ ... ] }
        }
      }
    ]
  }
}
```

要点：

- 只有部分节点带 `text`；连接线、容器、图片节点没有。
- 取文案用 `text.text`（已拼好的纯文本），不要自己拼 `rich_text`。
- `y` 与 `width/height` 的量纲不一致，排序可用，布局不可用。

## 2. 抽取阅读序（近似）

按 `y` 再按 `x` 排序，逐行输出"类型 + 文案"：

```bash
lark-cli whiteboard +export --whiteboard-token <token> --output-type raw \
  -q '.data.nodes | sort_by(.y, .x) | .[] | select(.text.text != null and .text.text != "") | "\(.type)\t\(.text.text)"'
```

PowerShell 落盘可用重定向；用非空行数即可得到**文本节点密度**：

```powershell
(Get-Content wb01.tsv | Where-Object {$_ -match '\S'}).Count
```

密度只用于横向比较（哪块图信息最重），不要作为质量指标。

## 3. 三类归类

| 类型 | 识别特征 | 回答的问题 | 判读要点 |
|---|---|---|---|
| 地图图 | 分阶段两列、编号、底部横条 | 一共几步、我在哪 | 阶段命名、编号与正文是否同号、底部带走句 |
| 解剖图 | 中心 + 环绕；或三列；或空间分区 | 有哪些零件、谁归谁管 | 中心是什么、外围几块、范围标签、图例 |
| 操作图 | 同构卡片；或 3 格实拍 | 点哪里、看到什么 | 每卡是否"2 动作 + 1 ✓"、兜底与加分是否分色 |

混合型：先按"这张图最主要回答哪个问题"归一类，其余元素记为附加区块。

## 4. 判读清单（每块图）

- [ ] 主标题（图内原话）
- [ ] 副标题/图例（含映射说明）
- [ ] 区块清单与各自功能标签
- [ ] 编号体系，是否与正文清单同号
- [ ] 颜色语义（主线/提示/拦截/范围外）
- [ ] 虚线用途（循环/返回/范围外）
- [ ] 范围收口句（"其他先不用管"）
- [ ] 底部结论句
- [ ] 文本节点数
- [ ] 一句问句概括：这块图回答什么问题

## 5. 常见误读

| 误读 | 后果 | 纠正 |
|---|---|---|
| 把分区当装饰 | 丢掉"调用顺序"信息 | 先读区块标题，再看箭头方向 |
| 把红色当强调色 | 漏掉"唯一例外"的设计意图 | 数一数红色出现几次：只出现一次就是例外标注 |
| 忽略灰色小字 | 漏掉"本期不做"的范围收口 | 单独抽取字号最小、颜色最浅的节点 |
| 把备注当正文 | 引用时混入作者旁白 | 区分 `font_size` 与位置：边缘小字多为旁注 |
| 用节点数当质量分 | 误判"图越复杂越好" | 密度只作对比，质量看"一问一答"是否成立 |

## 6. 交付时写什么

每块画板在知识包中至少给出四项：位置、主标题、类型、它独立回答的问题；有复用价值的再补"元素清单 + 骨架草图"。
