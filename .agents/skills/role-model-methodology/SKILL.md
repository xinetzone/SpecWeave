# 榜样人物方法论萃取与正面解读工作流 Skill

> ⚠️ **本Skill是知识沉淀工作流门面（L1索引层）**，遵循[渐进式披露三层架构](../../capabilities/ARCHITECTURE.md)：
> - L0：[.agents/ONBOARDING.md](../../ONBOARDING.md)（入口速查）
> - L1：本文件（<500行，触发词+场景决策树+七阶段流程+三框架+门禁+陷阱）
> - L2：[.agents/commands/seven-concepts.md](../../commands/seven-concepts.md)（R/I/E/F/V 子命令完整编排逻辑与 G1–G4 质量门）
>
> **术语速查**：桥接（两人之间的关联类型）；桥接强度（关联的可信度分级，★～★★★★★）；四级事实分层（A权威/B百科/C转述/D推断）；D 级（本包推断，禁止写成史实）；伪因果（把并行发生说成影响关系）；伪问题（说不清阻塞什么的情绪）；幸存者偏差（只看成功者导致的方法误读）；toctree（Sphinx 导航块，CI 门禁沿它做可达性检查）。

## 1. Skill ID
`role-model-methodology`

## 2. 功能描述

把「向榜样学习」从情绪传递变成结构传递。**本技能解决榜样学习最常见的两种失败**：

| 失败模式 | 表现 | 本技能的拦截机制 |
|---|---|---|
| **吹捧** | 只传递情绪（「他真努力」），不传递机制 | 阶段 I 反常识判据 + 框架 3 第 2 步「拆结构而非句子」 |
| **伪造因果** | 把并行发生的事说成影响，暗示「学他就能得到他的成果」 | 阶段 R 四级分层 + 第三节时间线核对 |

**核心能力**：四级事实分层采集 → 三框架诊断 → 证据桥接审查 → 可填写工作表 → 23 条交付门禁。

> **为什么核心约束是「正面 ≠ 夸大」？** 榜样学习的失败很少来自「信息不足」，更多来自**信息形态错误**——读者拿到的是一句励志标语而不是一套结构。真正有价值的正面解读是「呈现结构」：把一个人做对的事拆成可迁移的机制，让读者自己判断能不能用。夸大反而有害：读者一旦发现「他也能做到我为什么不行」，就整体放弃学习。

## 3. 何时使用本技能

当用户提到以下任何内容时触发：
- **人物调研类**：「调研 XX」「全面解读 XX」「帮我做 XX 的教程」「XX 知识包」「XX 人物 wiki」
- **关联洞察类**：「XX 和 YY 有什么关系」「他们之间有什么关联」「这几个人有什么共同点」
- **榜样学习类**：「以 XX 为榜样我该怎么学」「怎么学 XX」「XX 的方法论」「终身学习者」
- **方法萃取类**：「从 XX 身上能学到什么」「萃取 XX 的方法」「把 XX 的经验变成 skill」
- **角度指定类**：「正面解读」「从真需求角度分析」「品质技能身份」
- **人物已故**：「追忆 XX」「纪念 XX 的一生」

> **关于触发**：即使用户只说「帮我研究一下 XX」而未出现上述词，只要产出物是**人物教程/知识包/学习路径**，就应该走本技能——不要直接让模型读文章写人物教程，那会绕过伪因果拦截和伦理边界。**唯一例外**：用户只想要客观生平纪事（不涉及方法萃取与学习路径）时，按普通研究任务处理即可，不必套本技能的完整链路。

## 4. 方案选择决策树

```
用户要什么？
├─ 只做人物教程/知识包（单人） → 主干 R→I→E→V，产出 bundle
│   └─ 附带「我还该学什么」 → 主干 + 框架 2（品质技能身份）
├─ 多人 + 要看关联           → 主干 R→I→F→E→V，另建枢纽包
│   └─ 「我以他们为榜样」   → 叠加框架 1 + 框架 2 + 框架 3
├─ 只要方法论/Skill（不建包） → F→V→I，只做公理提炼
├─ 素材是已发表文章          → 先走 blog-article-to-okf-wiki 转换，再套本技能的 R/I 层
└─ 素材是扫描版书籍          → 先走 scanned-book-to-okf-wiki，再套本技能的 R/I 层
```

**与同类 Skill 的边界路由**：

| 素材形态 | 先走 | 再套本 Skill |
|---|---|---|
| 真人公开事迹（需多源交叉 + 伦理审查） | **本 Skill 全链路** | — |
| 单篇博文/公众号文章转知识包 | [blog-article-to-okf-wiki](../blog-article-to-okf-wiki/SKILL.md) | R（事实分层）+ I（反常识判据） |
| 扫描版书籍转教程 | [scanned-book-to-okf-wiki](../scanned-book-to-okf-wiki/SKILL.md) | R（主张分层）+ I |
| 源码/文档转 Wiki | [source-code-to-okf-wiki](../source-code-to-okf-wiki/SKILL.md) | 不适用（无伦理与伪因果风险） |
| 通用方法论编排（不限人物） | [seven-concepts-cmd](../seven-concepts-cmd/SKILL.md) | 本 Skill 作为领域层 |

> **为什么必须先分流再套用？** 三篇 OKF 工作流 Skill 共享「信源先行、F 编号登记、toctree 门禁」这套骨架，但本 Skill 额外承担**伦理裁决**（不消费创伤、不把他人当论据）和**伪因果拦截**。把人物素材直接丢给通用转换 Skill，产出物会是「结构完整但论证不诚实」的知识包——这类错误在门禁层面查不出来，只能靠本 Skill 的 I/V 阶段拦。

## 6. 依赖与前置准备

- **编排层依赖**：[seven-concepts-cmd](../seven-concepts-cmd/SKILL.md) 提供 R/I/E/F/V/C 子命令与 G1–G4 质量门；本 Skill 是其**领域层**，不重复实现编排逻辑
- **产出形态**：若产出物为 OKF 知识包，须先确认目标项目及其 frontmatter 规范（各项目 `.agents/rules/frontmatter.md`）
- **检索依赖**：多源交叉是硬要求，单一来源不足以支撑 A 级事实
- **操作限制**：人物在世时涉及其私生活信息默认不入库（见阶段 R 伦理约束）

> **为什么编排逻辑要复用而不重写？** 七概念方法论已封装场景决策树与质量门，重复实现会导致两套编排漂移。本 Skill 只做**领域特化**：在通用 R/I/E/F/V 之上叠加四级事实分层、伦理裁决、证据桥接三项本领域独有约束。

## 7. 阶段 R · 四级事实分层采集

**这是本技能最重要的设计。** 传统做法只分「事实/观点」两层，会导致二手来源在成文时混入事实层。

| 层级 | 定义 | 正文措辞要求 |
|---|---|---|
| **A 级** | 官方媒体、政府、学术机构、一手文献 | 直接引用 |
| **B 级** | 百科、官方工具书 | 直接引用，但需与 A 级交叉 |
| **C 级** | 深度报道、访谈转述、聚合类来源 | **必须标 C 级** |
| **D 级** | 本包推断 | **必须用「本包推断」「可推导」等措辞，禁止写成原话或史实** |

**执行规则**：

1. **每个事实编号 + 事实陈述 + 出处 + 层级**，登记在 `references/facts.md`
2. **双份登记**：同一份事实清单在两处（正文层 + 信源层），编号集合必须一致
3. **伪事实隔离**：检索中遇到无法取得一手出处的信息 → 标记 D 级待核 → **正文禁止引用**
4. **分歧并列**：史料有 N 种说法时**全部并列**，不静默择一；在正文首次出现处标注

> **为什么 D 级必须单列而不是并入「观点」？** 「观点」暗示「某个人的看法」，但本包推断是「我们的读法」，两者责任主体不同。若并入观点层，读者会误以为推断是某位受访者的原话——这正是伪因果的温床。上一轮实证：3 条无一手出处的信息（F-TX-079 / F-YB-099 / F-HG-033）在成文前被 D 级分层隔离，事后无一进入正文。

**时点核查（常被忽略）**：如果人物**已故**：

- 根 index 置顶加时点声明（生平表述以去世日为终止界）
- `stale_after` 设为较短（遗产分配、纪念活动属强时效内容）
- 新增「边界与禁区」专篇，专列**身后叙事的误读风险**

**伦理约束（不可协商）**：

| 约束 | 具体做法 |
|---|---|
| 创伤不是教材 | 重大挫折只写「事件 + 后续影响」，不做苦难美化成语录 |
| 他人不是论据 | 涉及第三人（家属、同行、争议对象）时不引用未经本人授权的私域信息 |
| 隐私不评判 | 感情生活、家庭矛盾、健康状况默认不入库；检索到也不写 |
| 幸存者偏差前置 | 若素材含创伤叙事，警告同时放 index 置顶和边界篇，不只放一处 |

## 8. 阶段 I · 洞察（三条，每条四元组）

**每条洞察必须含**：陈述 + 证据（F 编号）+ **反常识** + 行动。

**反常识项的质量判据**（这是洞察是否合格的唯一标准）：

> **问自己：这个反常识是怎么来的？**
>
> 「他很努力所以他成功」→ 反常识项是空的，来源是循环论证 ✗
> 「A 与 B 的环境差异 → 延迟差异 → 人对延迟响应衰减 → 延迟是能力杀手」→ 四步可回溯 ✓

> **为什么反常识项是唯一判据？** 洞察的其余三项（陈述、证据、行动）可以用「说得像真的」来蒙混——陈述可以写得漂亮、证据可以堆够编号、行动可以套模板。只有反常识项暴露推导链：它是循环论证还是四步回溯，一读就知道。实务中 90% 的伪洞察在这里现形。

## 9. 阶段 F · 公理提炼（框架类产出必做）

**从洞察继续追问到不可再分的基础单元**，提炼自洽公理，再自下而上重构。

**关键约束**：框架类产出**必须配可填写的表格**。

> **为什么必须配表格？**「品质技能身份」这样的三元模型极易变成「正确的废话」。加一个必填表格，它就有了判定标准——比如完成标准是「技能清单里至少一项有实际验证」，没验证就说明本框架不适用。

### 框架 1 · 真问题 · 真需求 · 真目标（诊断层）

| 层 | 定义 | 判据 |
|---|---|---|
| **真目标** | 你真正想去的地方（方向） | 能回答，但答案通常会变 |
| **真需求** | 到达目标必须具备的能力/缺口 | **能——唯一的客观判据** |
| **真问题** | 当前阻碍到达目标的具体障碍 | **能——必须具体到可观察** |

**伪问题六判据**（任一为否则是伪问题）：

1. 说不清它在阻塞什么 → **这是情绪不是问题**
2. 没有具体观测点
3. 解完之后路径上不会少一块什么
4. 很少人遇到（→ 独特情境，不能从别人方法里找答案）
5. 完全不能改变
6. 写下之后不知道下一步做什么

**关键诊断动作**：**把不可逆的东西从问题清单里划掉，剩下的才是问题。**

### 框架 2 · 品质 · 技能 · 身份（能力层）

| 层 | 定义 | 核心判据 | 可迁移性 |
|---|---|---|---|
| **品质** | 你的选择倾向 | **在无收益、无人监督时你怎么选？** | 低——无法通过听/看获得 |
| **技能** | 可重复产出的能力 | 你能在什么条件下稳定做出什么？ | 高——可以练 |
| **身份** | 你的自我叙事 | 你的行为与这个叙事一致吗？ | 最低——可被表演 |

**为什么顺序不可颠倒**（三条论证，缺一不可）：

- **只有品质没有技能 = 空谈**：品质决定你做什么，技能决定你能不能持续做
- **只有技能没有身份 = 工具**：技能告诉你「怎么做」，身份告诉你「为什么在意」
- **只有身份没有技能 = 表演**：用身份代替能力，用身份解释失败

**自检硬标准**：**技能清单里至少一项有实际验证**（作品/数据/他人反馈）。全无验证 → **本框架不适用**，先做出一件东西。

> **为什么「身份」排在最后而不是最前？** 直觉上身份最动员人，但身份是三者的**结论**而非前提：先有可验证的技能，技能反复成功后才有稳定身份叙事，身份再反过来支撑长期选择。倒序排列会导致「先立人设再找证据」，这正是励志叙事的生产机制。

### 框架 3 · 正面解读师（方法层）

**身份定义**：能在充分呈现一个人值得学的东西的同时，**不制造神话、不伪造因果、不消费他人**的专业读者。

**六个操作步骤**：

| # | 步骤 | 要点 |
|---|---|---|
| 1 | **先写「不做什么」** | **必须第一步**——否则读者把榜样当完人，然后放弃学习 |
| 2 | **把「做了什么」拆成结构** | **不接受句子，接受结构**。判据：只用句子表达 = 还没拆到结构 |
| 3 | **把「成果」拆成「条件」** | 每个成果追问「成立需要什么条件」。**省略条件就会写出「他都能做到，你也能」** |
| 4 | **把「功劳」分给结构/运气/对象** | 归因克制。参照：受访者自己怎么说（归给感恩/归给力量有限/归给时代） |
| 5 | **显式声明「不能学什么」** | **正面解读不含「不能学」就是吹捧。至少 1 条** |
| 6 | **转成本周可执行的动作** | 判据：转不成动作 = 感想，不是解读 |

**归因克制四规则**：

```
规则 1  功劳不独占     → 至少一句「这也需要 ___（条件/运气/他人）」
规则 2  不把机制归给品格 → 说「因为他有 ___ 机制」，不说「因为他品好」
规则 3  不把幸存当方法   → 「他做到了 X 所以我也要 X」须加「多少人做到了 X 却没成功」
规则 4  不把路径当普遍   → 任何具体做法须标「成立条件是 ___」
```

**三类必须拒绝的话术**：

| 类型 | 例句 | 为什么拒绝 |
|---|---|---|
| **完美化** | 「他一生无瑕」 | 抹掉真实的人 → 读者放弃学习 |
| **苦难美化** | 「他受过这么重的伤都成功了」 | 幸存者偏差；把创伤变成流量产品 |
| **单一归因** | 「他成功全靠坚持」 | 忽略结构/运气/时代；可学的东西被抹掉 |

**「苦难美化」的最隐蔽形态**：把一个人的自我对话摘出来当励志标语。**引用这类话必须带「特定处境下的自我对话」限定。**

**三个自检问题**：

```
1. 我有没有让读者觉得「我也可以」？
   → 若「是」，我可能是吹捧（真实：他可以，你不一定）
2. 我有没有省略他没做到的事？
   → 若「是」，我已在制造神话
3. 每条能转成本周的一个动作吗？
   → 若「不能」，我写的是感想
```

> **第 1 问最反直觉**：正面解读的目标不是让读者觉得自己也行，**而是让读者看清结构**。替代「我也可以」的是「我看清了」。

## 10. 关联洞察专用：证据桥接审查

当任务要求「洞察多人之间的关联」时，**关联本身需要被审查**，不能只写。

### 桥接强度评级标准

| 级别 | 含义 | 判据 |
|---|---|---|
| ★★★★★ | 有直接可核查证据 | 人物原话、时间线、或文献支撑 |
| ★★★ | 结构同一性明确但无直接证据 | 结构可对照，两人无接触 |
| ★★☆ | 仅为假设 | 有合理推测但**无任何证据**——必须显式标为弱假设 |
| ★ | 仅时代/领域背景 | 客观共存，无因果含义 |

### 六类桥接（可作为检查清单）

| 桥接类型 | 审查要点 |
|---|---|
| **师承** | 是否有直接证据（同门、师徒、共事） |
| **独立同向** | 是否有时间重叠？**时间重叠才能谈影响** |
| **交叉影响** | 方向是什么？**互相确认 ≠ 单向影响** |
| **伪因果识别** | **做时间线核对**——这是最关键的一步 |
| **同时代背景** | 确认无时间重叠（这本身是「无关联」的信息） |
| **精神影响** | **必须标为弱假设**，除非有一手证据 |

### 伪因果的识别（核心动作）

**做一张时间线表，把双方的关键事件按时间排开**。若 A 的行为早于 B 的存在，则「B 影响 A」不成立。

**正确表述模板**：

```
❌ 「X 影响 Y 开始做 Z」
✅ 「X 与 Y 在各自的路径上独立走向了同一方向，并在此后互相确认」
```

### 三类伪关联（明确反对）

| 类型 | 表现 | 为什么错 |
|---|---|---|
| **伪造因果** | 「A 影响 B 做成了 C」 | 时间线不支持；暗示「学 A 就能得到 C」 |
| **强行拉平** | 「他们都努力/善良/坚持」 | 不可拆解、不可检验、不可迁移 |
| **时代产物当个人品质** | 「A 有献身精神所以能坚持」 | 忽略结构条件；真实是「困难条件 → 需要结构能力 → 他有」 |

> **为什么枢纽包必须做自我审查？** 关联洞察包的产出物是「我对两人关系的推理」，不是「已核实的史实」。审查它的正确姿态是「检查我的推理是否诚实」，而不是「检查产出是否完整」——后者更容易被跳过。上一轮实证：枢纽包唯一可能构成伪因果的推断（陶行知的隐性在场）被主动降级为 ★★☆ 弱假设并写明「无证据表明」。

## 11. 阶段 E · 成文（信源先行）

**顺序**：`references/` → `concepts/` → `examples/` → 各级 `index.md`

**骨架判定（是否设 `examples/`）**：

```
问两遍：① 作品主体是「概念」还是「操作流程」？
        ② 操作是否可被独立复现（照着做能得到同样结果）？
任一为否 → 不设 examples，使用动作写进 concepts
```

**「不做什么」也要记录**：不设 examples、不引入某类信息，都要在 `log.md` 里写明理由——否则后来者会以为是遗漏。

## 12. 阶段 V · 对抗审查（四视角）

| 视角 | 攻击什么 |
|---|---|
| **魔鬼代言人** | 结论有没有可能是错的？数据来源可靠吗？有没有因果搞反？作者有没有利益冲突？ |
| **新人** | 读懂概念了吗？知道第一步做什么吗？有没有 Hello World 级示例？ |
| **老板** | 投入产出比？可复制性？最坏情况？什么时候能看到效果？ |
| **未来** | 这是过渡形态吗？环境变化后结论还成立吗？5 年后回看会不会变笑话？ |

**通过标准**：每视角 ≥1 条**具体**攻击点（非客套话），**至少采纳 2 条修正**。

**⚠️ 必须自我审查（最容易被跳过）**：

> **V 阶段要攻击推断层自身，不只核查事实层。**
>
> 具体做法：主动把自己**唯一可能构成伪因果的推断**降级为弱假设，并写明「无证据表明…」。

**「未达标项」也要显式承认**：深度要求与实际执行轮次不符、某阶段未使用等，写入交付报告——隐瞒未达标比未达标本身更有害。

## 13. 阶段 C · 交付门禁清单

```
□ 场景已识别，链路已选定，裁剪理由已记录
□ 骨架已判定（设/不设 examples），理由已写明
□ 事实四级分层完成，D 级有显式措辞
□ 伪事实已隔离并禁止正文引用
□ 事实双份登记，编号集合一致
□ 史料分歧并列保留（不静默择一）
□ 伦理四条约束已遵守（创伤/他人/隐私/幸存者偏差）
□ 关联洞察：桥接强度评级完成，弱假设已标注
□ 关联洞察：时间线核对完成，伪因果已识别
□ 每条洞察有 F 编号 + 反常识 + 可回溯推导链
□ 框架类产出配可填写表格
□ V 阶段四视角，≥5 条具体意见，≥2 条被采纳
□ V 阶段攻击了推断层自身
□ 正面解读含「不能学」≥1 条
□ 幸存者偏差警告已前置到 index（若涉及创伤人物）
□ 编码/乱码脚本复验（U+FFFD 全文扫描）
□ ★ 每个包的根 index.md 都有 toctree ← 最高频失误
□ 三级索引计数对账（frontmatter/计数行/节标题/分组表/toctree 五面）
□ 构建工具的 toctree 检查通过
□ 「不做什么」已记录
□ 未达标项已显式承认
□ ★ 最小验证树复验（Sphinx -W；全站太慢时只建新内容，30 秒定位）
□ ★ 正文相对链接全部指向存在的文件（门禁不查这一项）
```

> **为什么最后两条打★？** 前 21 条门禁都通过，仍可能留下 7 处断链——上一轮实证：toctree 门禁全绿后，最小验证树又摘出 7 处链接缺陷（含一处文件编号错误 `05-` 写成 `04-`）。**门禁查结构，不查正文相对链接是否指向存在的文件**。两者必须都做，缺一不可。

## 14. 安全检查清单（逐项确认）

- [ ] 场景已识别，链路与深度已选定，裁剪理由已记录
- [ ] 已做 `dry_run` 预检或向用户展示落盘计划并获得确认
- [ ] **写入范围已确认**：目标路径在授权目录内，未越界写入子模块/vendor
- [ ] 伦理四条已逐条检查（创伤不是教材 / 他人不是论据 / 隐私不评判 / 幸存者偏差前置）
- [ ] 伪事实已隔离，无一条进入正文
- [ ] D 级推断在正文有显式措辞，未被写成史实
- [ ] 桥接强度评级完成，★★☆ 及以下已标为弱假设
- [ ] 时间线核对完成，伪因果已识别并改写
- [ ] 正面解读含「不能学」≥1 条
- [ ] 编码已复验（无 U+FFFD 替换字符）
- [ ] toctree 门禁已跑
- [ ] **最小验证树已复验正文相对链接**（门禁不查此项）
- [ ] 未达标项已显式写入交付报告，无隐瞒
- [ ] 索引与登记表已同步（frontmatter / 计数 / 分组表 / toctree 五面一致）

> **为什么伦理检查要逐条列而不是写一句「注意伦理」？** 伦理违规在产出物里不留技术痕迹——门禁全绿、格式完美，但内容消费了他人创伤。这类错误只能靠清单强制逐项过一遍。上一轮实证：胡歌包检索到大量感情类信息与家庭隐私细节，全部剔除；「用思想填满」这类容易被摘成励志标语的话，强制降级为「特定处境下的自我对话」。

## 15. Gotchas（陷阱与反直觉行为）

> **为什么需要 Gotchas 章节？** 错误处理记录「已知错误及修复」，Gotchas 记录**不产生明确错误但导致结果不符合预期**的隐性陷阱——这类坑不会报错，只会悄悄产出错误内容。

| # | 陷阱 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | **根 index 漏 toctree** | 文件静默留在导航外，无任何警告 | 每个包的根 index 都要有 toctree |
| 2 | **只做两层事实分层** | 二手来源混入事实层，成文后再改等于承认分层是摆设 | 用四级（加 D 级推断） |
| 3 | **先成文后标注推断** | 同上 | **分层必须在成文之前** |
| 4 | **框架不带表格** | 变成「正确的废话」 | 每个框架配必填表格 |
| 5 | **V 只核查事实不审推断** | 自己的推理可能构成伪因果而不自知 | 主动把自己唯一可能伪因果的推断降级 |
| 6 | **把并列的人写成同一类** | 学错对象 | 先做「可拆解层级」分层 |
| 7 | **规模当目标** | 照着规模规划必然失败（规模是持续性的副产品） | 目标写「频率×时长」，不写总量 |
| 8 | **摘句当原则** | 省略处境，易被误读 | 引自我对话的话必须带处境限定 |
| 9 | **幸存者偏差未前置** | 读者读完已被励志叙事带走 | 警告同时放 index 置顶和边界篇 |
| 10 | **把「不做什么」留到最后写** | 读者已形成完人印象，再补禁忌显得像补充说明 | 正面解读第 1 步就写 |
| 11 | **用「我也可以」检验正面性** | 方向反了——正面解读的目标是「我看清了」 | 问「每条能转成本周动作吗」 |
| 12 | **人物已故仍用进行时写生平** | 事实错误 + 读者不适 | 根 index 置顶时点声明，短 `stale_after` |
| 13 | **Sphinx 缺分词器** | 中文站搜索不可用且不报错 | 确认 `jieba` 在依赖里；词干器引用指向真实全局名 |
| 14 | **grid 直接放 card** | `design.grid` 警告，构建 `-W` 失败 | card 必须包在 `grid-item-card` 内 |
| 15 | **toctree 路径带目录前缀** | `toc.not_readable` | toctree 路径相对**当前文档**，不带自身目录名 |
| 16 | **被索引的文档里再放 toctree** | 重复收录 / `toc.not_readable` | 只有「目录型 index」放 toctree |
| 17 | **文件编号靠手写** | `xref_missing`（`05-` 写成 `04-`） | 编号写完立即用解析器验一次，**不要靠眼睛** |
| 18 | **正文相对链接跨目录层级算错** | `xref_missing` | 从 `concepts/x.md` 指向兄弟包根是 `../../<pkg>/index.md`（**两层**）；从 `<pkg>/index.md` 出发才是 `../<pkg>/index.md`（一层） |
| 19 | **全站构建太慢** | 干等十几分钟还不知道是不是自己的问题 | **构造最小验证树**：只复制新内容 + 最小 `conf.py`（须含用到的扩展），30 秒定位 |
| 20 | **伦理检查靠自觉** | 门禁全绿但内容消费了他人创伤 | 逐条过第 14 节清单，伦理项不可跳过 |
| 21 | **人名近音/错字未复核** | 正文出现错名，读者直接判定不可信 | 关键人名与机构名在成文后统一对照信源复核一次 |

## 18. 真实案例参考

**2026-10-03 三人榜样知识包**（陶行知 / 游本昌 / 胡歌）——本 Skill 的实战样本。

产出：4 个 OKF 知识包（61 文档、254 条四级分层事实、10 张可填写工作表、3 个自研框架），落地于 `projects/awesome-okf-xs/doc/bundles/sheke/personal-growth/`；复盘报告落地于 `projects/daoapps.github.io/doc/fupan/`。

**从该案例学到的最重要四件事**：

1. **四级分层救场**：三级（事实/观点/待核）不够，必须单列「本包推断」层并在正文显式措辞——否则二手来源与推断会混入事实层
2. **关联洞察必须自我审查**：关联包是「检查我的推理是否诚实」而非「检查产出是否可信」，后者更容易被跳过
3. **三道门禁全绿 ≠ 链接都对**：门禁查 toctree 结构，**不查正文相对链接是否指向存在的文件**。本次门禁全绿后，最小验证树又摘出 7 处链接缺陷（含一处编号错误）
4. **人物已故改变教程定位**：时点声明前置 + `stale_after` 缩短 + 专列「身后叙事误读风险」，比事后补免责声明有效
