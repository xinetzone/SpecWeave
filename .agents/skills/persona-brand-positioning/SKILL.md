# 人格化品牌定位诊断 Skill

> 当用户带着一个有人格温度的品牌名来问"怎么优化小程序信息/品牌定位"时，用这个方法。

## 何时使用

触发词：
- "优化小程序信息/简介/名称"
- "品牌定位诊断"
- "自闭环品牌/变现闭环/学习闭环"
- "人格化IP怎么落地"
- 用户给了一个有哲学深度或人格感的品牌名（不是品类词堆砌）

**不适用：**
- 纯工具类产品命名（如"XX计算器"）——直接按搜索关键词命名即可
- 用户明确说"我想改名字"——那是命名任务，不是定位诊断
- 已经有成熟品牌只需要微调简介——直接写文案即可

## 核心原则

### 原则一：先画层级图，再诊断

**最大的错误是在错误的层级上分析。**

开始诊断前，必须先画出品牌层级树：

```
品牌名（如：道德大师兄）
├── 子模块A（如：结伴）
│   ├── 子频道A1（如：知足）
│   ├── 子频道A2（如：恒与）
│   └── ...
├── 子模块B（如：学习实验室）
└── 子模块C（如：复盘）
```

**为什么：** 人格化品牌名通常是一个容器，下面挂着多个子模块。如果把某个子模块当成品类招牌加在名字后面，就把品牌缩小了。

**操作：** 问用户三个问题：
1. 这个品牌名下面有哪些子模块/产品线？
2. 当前主推哪个？
3. 未来还会加什么？

### 原则二：先理解命名哲学，再补桥

**不要替用户改名字。**

人格化品牌名通常有三层含义：
- **哲学层**：名字背后的思想依据（如"道德即得到"——德者得也）
- **美学层**：调性锚点（如"大道至简""见素抱朴"）
- **人格层**：角色定位（如"大师兄"=先走一步回头拉你的人）

**操作：** 问用户"你为什么取这个名字？"，听完三层含义后：
- 名称本身不动
- 问题不在名字，在名字和品类之间缺一座桥
- 桥 = 简介第一句说清楚这是什么生态

### 原则三：补桥不改名

人格化IP名不需要品类后缀。搜索权重靠三层：

| 层 | 做法 |
|---|---|
| 名称 | 保留人格化原名，不加品类后缀（后缀会限制未来扩展） |
| 简介 | 三层结构：现在开放什么 / 生态是什么 / 怎么进来 |
| 页面内容 | 各子模块落地页自然嵌入搜索关键词 |

**简介模板：**
```
[人格化称呼]领路，[生态定位]。

现在开放「[主推子模块]」：[一句话价值主张]。
[子模块核心功能1]，[核心功能2]，[核心功能3]。
[差异化立场，如：反XX、反XX]。

后续开放：[未来子模块1]、[未来子模块2]。
[行动召唤，如：微信端向XX申请邀请]。
```

### 原则四：三环闭环按顺序建

自闭环品牌 = 三个环咬合，不是三个独立产品：

```
结伴闭环（人）──→ 学习闭环（学）──→ 变现闭环（钱）
     ↑                                    │
     └────────────────────────────────────┘
```

**顺序不能反：**
1. **先有人（结伴闭环）**：社群/关系/归属感——这是流量入口
2. **再留人（学习闭环）**：成长/进步/可见的改变——这是留存理由
3. **后养人（变现闭环）**：工具/深度内容/增值服务——这是收入来源

> **为什么？** 顺序反了不是"慢一点"，而是直接变成割韭菜。三个环一起上时，用户只看到一个急于收费的陌生品牌，社区还没建立就先收到付费邀请，信任一次性归零。按人→学→钱排序，收费发生前用户已经拿到过两次真实价值（被看见、有进步），付费是关系的延续而不是入口。

**变现红线：**
- 不卖课（和"反割韭菜"矛盾）
- 不卖会员（和社区气质矛盾）
- 不做情感付费（和反杀猪盘矛盾）
- **只卖工具**：工具付费是最干净的——你给我工具，我给你钱，没有焦虑绑架

## 执行步骤

> **为什么？** 每一步都设了"检查"闸门，是因为本方法最常见的失效不是判断错，而是跳步——没画层级图就开始改名，没理解命名哲学就开始写简介。闸门的作用是把跳步变成显式停顿。

### 步骤1：采集事实
- 读品牌相关的所有现有资产（网站、文档、已有产品）
- 用搜索工具（如知乎CLI）搜竞品命名和用户痛点
- 列出：品牌名、子模块清单、主推产品、现有简介、服务类目

### 步骤2：画层级图
- 画出品牌→子模块→子频道的完整树
- 标注当前主推哪个、未来规划什么
- **检查：有没有把某个子模块误当成品类招牌？**

### 步骤3：理解命名哲学
- 问用户：你为什么取这个名字？
- 提炼三层：哲学层、美学层、人格层
- **检查：有没有建议用户改名？如果有，停下来——先理解再补桥**

### 步骤4：补桥设计
- 名称：保留原名
- 简介：按三层模板写
- 类目：选和主推子模块匹配的主类目
- 视觉：人格化形象要接住名字的人格层（如"大师兄"是现代年轻人，不是古装道士）

### 步骤5：三环闭环设计
- 结伴闭环：现在有什么？缺什么沉淀？
- 学习闭环：现在有什么工具？缺什么路径？
- 变现闭环：第一个付费产品选什么？（选最轻的、内容已有的）
- **检查：三个环是不是按人→学→钱顺序？有没有三个一起上？**

### 步骤6：对抗审查
四个视角攻击方案：
- 魔鬼代言人：这个闭环是不是伪命题？完全自闭环可能吗？
- 新人：看完知道第一步做什么吗？
- 老板：投入产出比如何？第一个付费产品能赚多少？
- 未来：一年后这个品牌会变成什么样？

## 预览确认与幂等

本 Skill 只产出诊断建议与文案草稿，**不替用户改动线上配置**。执行前必须先出预览：

1. **预检**：列出将被改动的项（名称/简介/类目/视觉），逐项标注"改什么、为什么改"
2. **预览**：把新简介全文以代码块原样给出，不做截断，让用户自己判断长度与调性
3. **确认**：等用户明确认可后再输出可执行的操作清单；用户提出修改则回到步骤4 重出预览
4. **重复检查**：若同一品牌已诊断过，先比对既有结论——品牌名与主推子模块未变时直接复用既有层级图，不重复重画；已给出过的简介草稿不重复生成

> **为什么？** 品牌名和简介是用户与平台审核之间已经建立共识的资产，未经确认就改动会造成两个后果：一是用户失去对自己品牌的最终控制权，二是平台侧改名需要重新审核、可能丢掉已积累的搜索权重。预览确认把"建议"和"已改动"之间的边界固定住。

## 安全检查清单

执行前逐项确认：

- [ ] 品牌名未被改动（人格化原名保留）
- [ ] 层级图已画出且用户认可层级归属
- [ ] 命名哲学三层已从用户处采集（未凭空推断）
- [ ] 新简介未含品类后缀
- [ ] 三环顺序为人→学→钱，未三环齐上
- [ ] 变现方案未涉及课/会员/情感付费
- [ ] 预览稿已给出并等用户确认
- [ ] 未替用户执行任何线上改名/改类目操作
- [ ] 建议项已标注"改什么、为什么改"

> **为什么？** 清单逐条对应本方法最容易踩的六个反模式与两类越权操作。清单的价值在于它是可核对的——每一条都能对照用户实际给出的答案，而不是靠"我应该已经懂了"。

## 5. Gotchas：隐性陷阱

以下是真实踩过且**没有报错码**的隐性陷阱：

| # | 陷阱 | 表现 | 正确做法 |
|---|---|---|---|
| 1 | 子模块名自带品类感 | 用户说"我的品牌叫'大师兄''，主要做结伴"，你直接建议"结伴大师兄" | 判断子模块名是不是会缩小品牌的未来扩展空间；若会，改用简介桥接而非名称后缀 |
| 2 | 把"三个环"读成三个产品 | 输出一份同时含社交、学习、付费的完整产品方案 | 顺序执行，一个环稳了再动下一个；变现环必须最后 |
| 3 | 用"我觉得"代替用户意图 | 凭想象补出命名哲学三层 | 三层含义必须问出来，问不出来就标"未确认"，不要替用户编 |
| 4 | 简介写成功能清单 | 简介堆砌"提供结伴、学习、变现服务" | 简介是生态说明，不是功能罗列；具体功能留给页面内容承载搜索 |
| 5 | 视觉与名字年代错位 | 名字是"大师兄"（现代），视觉画成白胡子老道 | 视觉接人格层的当代性，不要接古风想象 |
| 6 | 首轮就推翻用户命名 | 第一轮就给改名方案，用户失去方向 | 首轮只做诊断与补桥；改名建议必须等用户主动问 |

> **为什么？** 这六条陷阱的共同点是"看起来都完成了任务"——每一份输出读起来都像一份合格的诊断。正因如此只能靠显式清单与预览闸门拦住，而不是靠结果自检。

## 反模式

| # | 反模式 | 表现 | 后果 |
|---|---|---|---|
| 1 | 层级误判 | 把子模块当成品类后缀加在品牌名后面 | 品牌被缩小，未来扩展受限 |
| 2 | 替用户改名 | 建议把人格化名改成搜索关键词堆砌的名字 | 丢掉品牌的哲学厚度和人格温度 |
| 3 | 三个环一起建 | 结伴、学习、变现同时开工 | 三个环都建不好，顺序反了就是割韭菜 |
| 4 | 卖课变现 | 第一个付费产品是课程/训练营 | 和"反割韭菜"立场直接矛盾，信任崩塌 |
| 5 | 名称加品类后缀 | "道德大师兄·结伴" | 未来加学习实验室时后缀就不对了 |
| 6 | 视觉不接人格 | "大师兄"画成白胡子老道 | 名字是现代的，视觉是古代的，调性分裂 |

## 检验标准

做完后检查：
- [ ] 层级图画出来了，品牌→子模块→子频道关系清晰
- [ ] 没有建议用户改名字
- [ ] 简介是三层结构（现在开放/生态/怎么进来）
- [ ] 三个环按人→学→钱顺序排列
- [ ] 第一个付费产品是工具，不是课程
- [ ] 视觉方向接住了人格层（现代/亲切/认真，不是古装/修仙）
