# 两个模式的完整定义

> 本文件是 [SKILL.md](../SKILL.md) 的 L2 参考，仅在需要判断边界或写检验标准时加载。两个模式均为 **L1 单案例待验证**。

## P-1 零侵入留痕

**适用于**：用户禁止改动既有文件仍需落盘；落点有索引/登记规范；延续轮次的极简指令。

**不适用于**：用户已允许改索引；产出物本身就是索引；落点无版本控制且无索引规范；多人协同与合规留痕场景。

**六步**：判定内容级别与落点 → 只新建不改写 → 枚举规范动作 → 写成待补文本（含决定人与时限）→ 机械自查并核对既有文件零写入 → 交付末尾只留一个待决项。

**反模式**

| # | 反模式 |
|---|---|
| 1 | 为遵守约束顺手改了索引 |
| 2 | 只说「未改动文件」而不记索引债 |
| 3 | 待补文本写成跨目录 markdown 链接 |
| 4 | 落在本就需强制登记的既有分类目录里 |
| 5 | 留债不写过期条件，长期腐化 |

**检验标准**：既有文件 mtime 与内容未变；包内 README 含四段；新文件通过结构不变式；用户能一句话回答补不补；交付末尾只有一条待决项。

**跨领域迁移（未实测）**：数据库迁移只加新表时，把应建的索引/外键写成待执行 DDL 清单随包交付；锁文件冻结时，把应更新的版本约束写成下一次解冻窗口的单一待决项。

## P-2 假绿双判

**适用于**：解读任何校验器、linter、测试收集器、链接检查的输出；目标可能落在排除表或 ignore 作用域外；告警路径可能相对另一目录。

**不适用于**：审计 CI 工作流的 `continue-on-error` 抑制项；修真实断链；归因既有门禁红项。

**六步**：取门禁基线（对象数/作用域/退出码）→ 识别漏检型假绿（0 对象 PASS 判未执行并换调用方式复跑）→ 识别误报型告警（回原文核对路径上下文）→ 分别处置（漏检改调用方式、误报改被测文本）→ 复跑并留改前/改后两组输出 → 把判据抽象出来，具体脚本名降级为示例。

**反模式**

| # | 反模式 |
|---|---|
| 1 | 把 PASS 当作已检查 |
| 2 | 把所有 WARN 一律当误报 |
| 3 | 把真断链也当误报 |
| 4 | 只改被测文本、不换调用方式 |
| 5 | 把具体脚本名写进模式，随 bug 修复一起过时 |

**检验标准**：存在改前/改后两组可比输出；基线含扫描对象数；每条 WARN 写明相对哪个目录；两类改动未混为一谈；复跑后告警归零且无新增忽略项。

**跨领域迁移（未实测）**：测试收集器收集 0 用例仍返回 0 时先读 collected 数；linter 因 ignore 规则跳过目标目录时改为显式文件列表复跑。

## 两者如何串起来

P-1 管「怎么交付与留债」，P-2 管「怎么验证交付」。P-1 的第 5 步直接调用 P-2 的判据；只做 P-1 不跑 P-2，会拿到一个「0 对象 PASS」的假绿并误以为交付已验证。
