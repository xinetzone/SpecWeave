(zero-intrusion-overview)=
# 零侵入交付留痕

> 一句话：把交付放进全新目录，并把「按规范本应做的登记动作」写成包内待补文本，让债务可见、可回答、可过期。

> **为什么？** 「不改既有文件」并没有消除登记义务，只是让它不可见。静默省略债务会让索引缓慢腐化且无人能回答「到底欠了什么」；写出来的债务则变成一条可以用「补 / 不补」回答的是非题。同理，校验器的 PASS 只说明它没报错，不说明目标进入过扫描范围——所以交付验证必须自带一层输出判读。

(zero-intrusion-id)=
## 1. Skill ID / Name（技能唯一标识）

`zero-intrusion-handoff`。名称与目录名一致。承载两个 L1 模式：**零侵入留痕**（交付与留债）与 **假绿双判**（输出判读），二者同属「约束下可审计交付」这一条链路，故不拆分。

(zero-intrusion-description)=
## 2. Description（功能描述）

解决一类问题：用户禁止触碰存量文件，但任务仍需要产生持久产物。技能同时管住三件事——落点、债务、验证。

### 方案决策树

```text
需要落盘？
├─ 用户允许改既有文件？ → 按既有规范直接更新索引，不用本技能
├─ 用户禁止改动，且产出物本身就是索引？ → 约束与任务冲突，先澄清，不执行
├─ 用户禁止改动，且落点有索引/登记规范？ → 走完整六步（含待补文本）
└─ 用户禁止改动，且落点无索引规范？ → 走步骤 1/2/5/6，不留债
```

**默认推荐**：完整六步。宁可多写一段待补文本，也不要让债务隐身。

### 适用边界

| 用 | 不用 |
|---|---|
| 私域/公开交付物的新建落盘 | 用户已授权改索引 |
| 延续轮次的极简指令（上一轮承诺过零侵入） | 审计 CI 抑制项（交 `ci-gate-effectiveness-audit`） |
| 门禁输出的 PASS/WARN 判读 | 修真实断链（交 `link-check-cmd`） |
| 报告导出后的结构自查 | 产出物是索引或导航本身 |

(zero-intrusion-io)=
## 3. I/O Parameters（输入输出参数）

**输入**

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|---|---|---|---|---|
| `target_dir` | string | 是 | — | 全新目录路径，不得落在需强制登记的既有分类目录内部 |
| `index_target` | string | 否 | 无 | 按规范本应更新的既有索引文件，只读取其规范、不写入 |
| `deliverables` | list | 是 | — | 待新建的文件清单，每个文件单一职责 |
| `constraint` | enum | 否 | `no-existing-write` | `no-existing-write` / `read-only-existing` |
| `verify` | boolean | 否 | `true` | 是否执行结构不变式与假绿双判 |

**输出**

| 产物 | 格式 | 说明 |
|---|---|---|
| 新目录与交付文件 | 文件集合 | 每个文件单一职责、可独立验证 |
| 包内 README | Markdown | 含「按规范应做 / 未改动 / 待补原文 / 决定人与时限」四段 |
| 机械自查记录 | 文本 | 行尾、frontmatter、围栏、表格列数、相对链接、扫描对象数 |
| 唯一待决项 | 文本 | 交付末尾一条，含当前状态与决定人 |

(zero-intrusion-flow)=
## 4. 执行流程（六步）

1. **预检与落点判定**：先做内容敏感度预检，再选全新目录；确认目标目录不存在，存在则先读现状、不覆盖。
2. **dry-run 提案**：列出「将新建的路径」与「不会触碰的既有文件」，确认后再写盘。
3. **只新建不改写**：写入全部交付文件；对既有文件只读不改。
4. **枚举并留债**：查出按规范应做的登记/索引/提交动作，逐项写成待补文本，注明目标文件、决定人、时限；待补文本不带跨目录链接语法。
5. **机械自查 + 假绿双判**：跑结构不变式；先记录扫描对象数，0 对象即判未执行并换逐文件复跑；每条 WARN 回原文核对作用域，区分漏检型假绿与误报型告警。
6. **交付收口**：末尾只留一条「唯一待决项 + 当前状态」，并如实标注未执行项。

> **为什么步骤 4 要求待补文本不带跨目录链接语法？** 那段文本的目标是另一个目录，用当前包的根目录去解析必然报错；这个噪声会长期留在门禁输出里，下一任维护者要么忽略整道门，要么浪费时间排查不存在的断链。

> **为什么步骤 5 先看对象数再看结论？** 排除表、ignore 规则、作用域过滤都会让校验器在「什么都没检查」的情况下返回 0。此时绿色是漏检，不是通过；换调用方式才有意义，改被测文本只会掩盖问题。

(zero-intrusion-safety)=
## 5. 安全检查清单

- [ ] **dry-run**：写盘前已列出将新建的路径与不触碰的既有文件。
- [ ] **幂等**：目标目录已存在时不覆盖，先读现状转更新提案。
- [ ] **零写入验证**：既有索引、README、配置的 mtime 与内容均未变化。
- [ ] **结构不变式**：行尾纯 LF、frontmatter 闭合、围栏成对、表格列数一致、相对链接可达。
- [ ] **门禁基线**：记录扫描对象数；0 对象 PASS 已判为未执行并复跑。
- [ ] **WARN 核对**：每条告警回原文核对路径上下文，未一律当误报。
- [ ] **债务过期条件**：待补项写清由谁、在何时之前决定。
- [ ] **不可撤销操作警告**：提交、推送、登记、删除既有文件一旦执行难以回滚，本技能默认**不执行**，需用户另行明确授权。

(zero-intrusion-errors)=
## 6. Error Handling（错误处理）

| 症状 | 判据 | 处置 |
|---|---|---|
| 校验器输出 PASS 但 `0 个文件` | 扫描对象数为 0 | 判「未执行」，换逐文件参数或显式清单复跑，不改被测文本 |
| WARN 提示路径不可达 | 回原文核对路径相对哪个根目录 | 上下文错位改纯文本；真断链修文本，不得一律当误报 |
| 目标目录已存在 | 目录枚举命中 | 先读现状，停止覆盖，转更新提案 |
| 写日志报 `File has not been read yet` | 目标文件已存在 | 先读再追加，不覆盖既有内容（append-only） |
| 既有文件出现内容变化 | mtime 或字节比对不一致 | 停止交付，列出变化清单，回滚须用户确认 |
| 索引债长期未决 | 待补项超过约定时限 | 交付前先清旧债，再开新包 |

(zero-intrusion-deps)=
## 7. Dependencies（依赖项）

- Python 3.10+（用于字节级结构不变式自查）。
- 项目内 `.agents/scripts/check-line-form.py`，**必须使用 `--file` 逐文件模式**（`--path` 会排除目标区，产生 0 对象假绿）。
- 项目内 `.agents/scripts/check-links.py`（可选，导出后验证相对链接）。
- 无第三方 Python 包；不依赖浏览器、网络或外部服务。

(zero-intrusion-deploy)=
## 8. Deployment（部署要求）

- 目录位于主权区 `.agents/skills/zero-intrusion-handoff/`，随仓库纳入版本控制；不修改 `vendor/` 内任何文件。
- 无需安装或注册：技能被触发时读取本文件即可。
- 长文档按需加载：[两个模式的完整定义](references/patterns.md)；评测用例见 [evals/evals.json](evals/evals.json)。
- 默认不提交、不推送、不做四处登记；这些动作需要用户另行明确要求。

(zero-intrusion-gotchas)=
## 9. Gotchas

1. 约束只禁止「移动/重命名/修改」，不禁止新建；但新建在既有分类目录内会制造「该登记却没登记」的模糊态，应另起顶层主题目录。
2. 把待补文本写成可粘贴的 markdown 表格行最直观，也最容易触发跨目录路径告警——用反引号纯文本更稳。
3. 门禁 WARN 必须人工回原文核对：编号唯一不保证指向正确，一律当误报会放过真断链。
4. 延续轮次能否零澄清，取决于上一轮是否只留了一个待决项；留一堆开放问题等于把澄清成本推给下一轮。
5. 两个模式均为 L1 单案例待验证；跨领域用法是原则迁移，未经实测，不要写成「已验证」。
