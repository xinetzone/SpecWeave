# 信源分层与取证通道选型速查

按主张类型选层，按页面形态选通道。两张表交叉使用。

## 1. 主张类型 → 信源层级

| 主张类型 | 首选层 | 最低门槛 | 判定要点 |
|---|---|---|---|
| 产品能力 | L1 官方产品页/文档功能页 | 1 个 L1 | 注意能力与条款分属不同页 |
| 价格 / 额度 / 套餐 | L1 官方定价或计费专页 | 1 个 L1 专页 | 必须记录口径名（原价/首购价/限时价） |
| 发布事件 / 上线状态 | L3 独立媒体 | ≥2 家非同源 L3，或 1 家 L3 + 1 家 L2 | 状态词逐字对齐（邀测 ≠ 公测 ≠ 上线） |
| 时间节点 | L3 独立媒体 | ≥2 家日期/时间戳一致 | 记录具体时刻而非仅日期 |
| 生态集成 / 数据打通 | L1/L2 官方集成页 + L3 | L3 可单独支撑，但须标注无官方源 | 跨平台数据调用类主张官方源稀缺 |
| 数字指标 / 营销承诺 | — | 不可外部核验 | 标为作者自述，不进待证清单 |

## 2. 页面形态 → 取证通道

| 页面形态 | 首选通道 | 兜底 | 实测要点 |
|---|---|---|---|
| 官方官网 / 文档 / 市场页 | `web_fetch` | 浏览器通道 | SPA 站直取会返回前端配置 JSON，正文取自 SEO 兜底区块（title/description/H1+首段） |
| 财经 / 行业媒体报道 | `web_search` 的 content 快照 | 浏览器通道 query(text) | 快照已是正文、无导航噪音；正文被折叠时再走浏览器 |
| 框架渲染站（Next.js RSC 等） | `web_fetch` + 定位 RSC 载荷 | 浏览器通道 | 表格类内容在 `self.__next_f.push` 载荷里，需按行核对列对齐 |
| 短链 / 旧地址 | 先 HEAD 或直取看重定向 | 搜索快照 | 记录规范地址，短链仅作来源标注 |
| 数据在第三方 App 内 | `mcode-tools` connector | 无 | 不用网页检索冒充 App 数据 |

## 3. 提取锚点速查

| 站点类型 | 正文定位锚点 |
|---|---|
| 新京报等门户 | `div#contentStr`（时间戳在 `span.timer`，署名在 `span.reporter`） |
| Next.js 文档站 | `self.__next_f.push` 载荷中的 `children` 字段 |
| 阿里云产品动态 | 搜索快照 content 已是「产品介绍 / 适用客户 / 发布功能 / 付费方式」四段结构 |
| 通用 SPA | `<section id="seo-home">` 兜底区块 |

## 4. 同源转载识别信号

同时命中两项以上即判同源，按 1 个信源计：

1. 正文句式高度雷同（逐句比对可达八成以上）
2. 发布集中在同一日、同一时段（数小时内）
3. 结构完全一致（同样的段落顺序与举例）
4. 存在同一通稿的独家细节（如同一「大麦电子票根册」例子、同一「70 元航班延误险」例子）

**反例**：同一事件的不同媒体各自采写，可能共享事实但不共享举例——这类是独立信源。

## 5. 落盘纪律

| 文件 | 允许写 | 禁止写 |
|---|---|---|
| `verify-<平台>.md` | 标题、时间戳、署名、版权声明、正文、图片链接 | 任何评价、结论、自己的话、总结段 |
| `verify-ledger.md` | 主张摘句、来源文件、层级、四态结论、差异说明、裁决理由 | 未标来源的判断、省略「无法证实」的行 |
| `article.md` | 成稿原文（只读） | 任何清洗或改写 |
