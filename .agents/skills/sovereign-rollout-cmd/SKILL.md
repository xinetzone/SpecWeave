# Sovereign-Rollout 主权区治理资产落盘命令 Skill

> ⚠️ **本Skill是命令入口门面（L1索引层）**，遵循[渐进式披露三层架构](../../capabilities/ARCHITECTURE.md)：
> - L0：[.agents/ONBOARDING.md](../../ONBOARDING.md)（入口速查）
> - L1：本文件（触发词+四阶段流程+安全清单）
> - L2：执行报告与复盘实例见 `playground/pipeline-parable/retrospective/execution-report-a103-path-naming-preflight.md`（A-103 实战案例，私域）

## 1. Skill ID
`sovereign-rollout-cmd`

## 2. 功能描述

主权区（`.agents/`、`docs/` 等直接纳入版本控制的治理资产区）变更高影响、难回滚，本Skill将「先提案后批准」治理门固化为四阶段闭环：

| 阶段 | 名称 | 关键动作 | 写入？ |
|------|------|---------|--------|
| S0 | 提案草案 | 背景/落盘位置/草案全文/关联资产/待批准事项五节 | ❌ 零写入 |
| S1 | 批准门 | 用户逐项确认待批准事项，批准语与清单一一对应 | ❌ 零写入 |
| S2 | 落盘执行 | 主资产落盘 + 元数据副本（`.meta/toml/`）+ 成熟度/索引登记 | ✅ |
| S3 | 执行报告 | export-report 流程导出报告 + 第一时间 `check-links.py` + 关联报告对账回写 | ✅ |

> **为什么用本Skill而非直接落盘？** 主权区资产一旦落盘即成为他人复用的事实来源，半成品或未经批准的资产会污染整个工作区；本Skill把「批准前零写入」「路径逐层推算」「导出即验证」三条纪律变成不可跳过的步骤。

## 3. 何时使用本技能

当任务满足以下任一条件时触发：
- 新增/修改 `.agents/templates/`、`.agents/skills/`、`.agents/rules/`、`.agents/commands/` 下的资产
- 新增/修改根 `docs/` 下的对外文档、模式库、复盘报告
- 涉及 `.meta/toml/` 元数据副本的创建或更新
- 用户提到"提案"、"批准落盘"、"主权区变更"、"治理资产落盘"、"先提案后批准"

> **不适用**：私域目录（`playground/`）内的产出物按内容敏感度预检直接执行，无需提案门；平凡修复（错别字、单点链接修复）可豁免。

## 4. 核心步骤

### S0 提案草案（零写入）
按五节结构输出草案，**禁止任何文件写入**：
1. **背景**：触发来源（复盘行动项编号/用户需求），为何入主权区
2. **落盘位置**：精确路径 + 参照的现有同类资产（先查现有实例再定格式）
3. **草案全文**：目标资产的完整内容（frontmatter 齐全）
4. **关联资产**：需同步创建的元数据副本、需更新的索引/登记表
5. **待批准事项清单**：逐条列出，S1 批准须逐项对应

### S1 批准门
- 等待用户明确批准；批准语应与第五节清单一一对应
- 未获批准前，任何理由不得进入 S2
- 批准范围外的扩展（如新增第四个落盘项）须回到 S0 补充提案

### S2 落盘执行
- 按批准清单逐项执行，一项一核验
- 元数据副本（`.meta/toml/`）与主资产同构，字段沿用同类资产现有格式
- 成熟度登记：新模式/新模板默认 L1（单案例待验证），升 L2 条件写入登记处
- **路径纪律**：所有相对链接从「文件实际所在目录」逐层推算，禁止从草案/记忆直写

### S3 执行报告 + 验证
- 按 export-report-cmd 流程导出执行报告（时间线/明细/偏差/验证/溯源/后续跟踪六要素）
- **导出后第一时间运行** `python .agents/scripts/check-links.py --path <归档目录>`（归档位置改变相对路径层级深度）
- 检查关联报告是否需要声明对账回写（文件名/体积引用是否仍与磁盘一致）
- 偏差（如路径错层）记入执行报告「偏差与处置」节，作为反模式证据

## 5. 质量门

- **G1**：S0 阶段零写入（提案前磁盘状态与任务开始时一致）
- **G2**：S2 逐项对应批准清单，无范围外变更
- **G3**：S3 链接检查通过（0 断链）后才算闭环
- **G4**：后续跟踪项（如升 L2 条件）登记到执行报告末节，有唯一权威来源

## 6. Gotchas（陷阱与反直觉行为）

- **批准不等于可以顺手改进**：S2 只做清单内事项，想加项先回 S0。"反正都要批准"是主权区膨胀的开端。
- **相对路径错层是本流程最高频偏差**：同一会话出现两次同类错层的实战中，一次靠主动推算拦截、一次靠 check-links 拦截——两者互补，缺一不可。
- **check-links 必须在导出第一时间跑**：归档越深层级深度变化越大，收尾时补跑会把断链带到已交付状态。
- **L1 登记不是终点**：升 L2 需要第 2 独立案例复用并回填 reuse_count，条件必须显式写入登记处，否则永远停在 L1。
- **私域产出物不要套用本流程**：`playground/` 内容直接执行，套提案门是过度工程。

## 7. 执行日志（CMD-LOG）

按 [CMD-LOG规范](../../rules/cmd-log-specification.md) 输出结构化日志：
- `cmd=sovereign-rollout`，session 前缀 `sc-YYYYMMDD-<topic>`
- 核心事件：`PROPOSAL_DRAFTED`、`APPROVAL_GRANTED`、`ITEM_EXECUTED`、`LINK_CHECK_PASSED`、`LINK_CHECK_FAILED`、`ROLLOUT_COMPLETED`
- S0/S1 阶段因零写入，日志是唯一过程证据，不得省略
