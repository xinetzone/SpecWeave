# Windows 误删影响面定性

误删之后的第一次答复常常是错的：`rm` 不打印成功删除，目录 mtime 会被服务刷新，空目录看起来像被清空，回收站为空被当作"没删"。本技能把"到底删了什么"拆成四类可交叉印证的证据，输出**已确认删除 / 已确认完好 / 未验证**三段结论。

## 1. 输入、输出与边界

输入：事故命令原文或等价描述、受影响根路径、事故时间窗（用户给出，或由工具输出时间戳推定）、当前可用权限。

输出：三段式结论、每条结论的证据定位、可恢复性判定、根因与删除前断言。

本技能只做定性取证，不做以下事情：

- 不做数据恢复、不重建目录、不清理事故遗留物——清理也是写操作，需单独授权。
- 不重跑破坏性命令，包括"复现一下看会不会再删"。
- 不把"日志里没有报错"当成"没有删除"。
- 不越过安全拦截去访问被拦截的系统路径；拦截即写"未验证"并请求授权。

> **为什么？** 事故后的第一反应通常是"再跑一次看看到底删了什么"，但破坏性命令的成功删除不打印、失败才打印：重跑既扩大影响面，也不产生新证据。

## 2. 冻结现场

1. 停止一切针对受影响卷的写入与删除，包括清理自己刚创建的探针产物。
2. 确认超时转后台的命令已经终止（查看任务列表并显式停止）；停止后仍在写盘的路径要重新取证。
3. 记录观察起点时刻，后续所有 mtime 判断以它为零点。
4. 先只读、后判断；任何写操作先说明目标与影响面。

> **为什么？** 误删命令常因超时被转入后台，停止时可能已遍历进深层目录。没确认进程真的终止就取证，会把"仍在发生的删除"记成"已停止后的状态"。

## 3. 四步取证

### 3.1 根级清单差异

先找事故前快照，再取现状清单：

- 快照可能就在同一条失败命令的前置输出里（`ls`/`find` 先执行、`rm` 后执行，命令失败不代表前置输出丢失）。检索 transcript 与工具输出后再断言"没有基线"。
- 确实没有快照时，明确记"无基线"，不要用"目录看起来正常"替代。

比对三列：名称、类型与权限位、mtime。差异分三类：

| 差异 | 含义 | 后续动作 |
|---|---|---|
| 事故前有、现在没有 | 候选删除对象 | 进 3.4 判可恢复性 |
| 事故前有、现在仍有 | 根级未被整体删除 | 仍需 3.2 判子树 |
| mtime 变化但条目仍在 | 可能被写入，也可能被删了子项 | 进 3.3 判别 |

### 3.2 权限与报错证据

`Permission denied` 行是这一层最直接的证据：`rm` 成功不打印、失败才打印，所以报错行同时证明"这条路径一个字节都没删成"。

```bash
icacls "C:\Program Files\Lenovo"
```

形如 `BUILTIN\Users:(I)(RX)` 表示只有读取与执行权限，无写/删权限。再用三条独立事实交叉印证：

- 父目录 mtime 与事故前快照一致（移除子项会刷新父目录 mtime）。
- 被报 `Permission denied` 的样本文件仍在原处。
- 该路径下存在安装期空目录——只读路径上 `rm` 连内容都删不掉。

> **为什么不能只用 ACL？** ACL 描述的是"该账户"的权限：进程若以管理员提权运行，`Administrators:(F)` 生效，RX 结论就失效。结论必须建立在"报错行 + 父目录 mtime + 样本文件"的交叉印证上，ACL 只作解释。

### 3.3 服务写入判别

目录 mtime 变化有两个来源：移除子项，或运行中的服务在写。判别顺序：

1. 取一组"事故后 mtime 更新"的目录。
2. 隔数十秒再取一次同一组目录。
3. mtime 在观察窗口内继续推进 → 归因服务写入，不归因删除。
4. 需要点名服务时用 `tasklist` 或服务管理器交叉确认。

空目录不是删除证据：

```bash
find "<根>" -type d -empty | wc -l
```

只读路径下的空目录不可能是 `rm` 的产物。本案 103 个空目录全部是安装期的 `__pycache__`、`tap-snapshots` 一类空壳。

> **为什么？** 目录 mtime 表示"该目录的条目被改动过"，不表示"内容是否还在"；日志、缓存、下载都会刷新它。把它当删除证据，会得出"整个厂商目录都被删了"的错误结论。

### 3.4 回收站与可恢复性

`rm` 走 POSIX 删除，不进回收站；因此"回收站为空"证明的是**不可恢复**，不是"没有删除"。

```bash
whoami /user
ls -la '/c/$Recycle.Bin'
ls -A '/c/$Recycle.Bin/<当前用户SID>' | wc -l
```

- 先取当前用户 SID，只统计该 SID 子目录。
- 逐条列出条目名与时间，只有落在事故时间窗内的才相关。
- 回收站目录自身 mtime 与 `desktop.ini` 由资源管理器重写，不构成"有删除/无删除"的证据。

结论口径只写一句：`本用户 SID 下无事故时间窗内条目 → 本次删除没有回收站恢复路径`。其他 SID 的条目与本事故无关，不并入结论。

## 4. 根因与删除前置断言

常见根因是变量退化：`sed`/`cygpath` 表达式报错后输出为空，`"/c/${root#C:/}"` 塌成 `/c`，末尾 `rm -rf "$var"` 直接作用在盘根。

把变量送进 `rm -rf` 之前，必须通过两道真实阻断的断言：

```bash
case "$target" in ""|"/"|"/c"|"/c/"|"C:/"|"C:\\") echo "REFUSE: bad target [$target]"; exit 9;; esac
[ -f "$target/.keep" ] || { echo "REFUSE: marker missing"; exit 9; }
printf 'target=[%s] depth=%s\n' "$target" "$(awk -F/ '{print NF-1}' <<<"$target")"
```

第三行只打印给人看；前两行必须真的 `exit`。

> **为什么是这两条？** 空值与盘根覆盖了命令替换、`sed` 失败后最常见的退化结果；标记文件断言把"路径看起来对"升级成"路径指向我刚准备的临时目录"——盘根上永远不会存在你刚放进去的标记文件。

## 5. 安全拦截处置

安全分类器拦截"删除盘根条目"时：

1. 不换工具绕行（`rmdir`、PowerShell `Remove-Item`、原生 API 都算绕行）。
2. 说明拦截原因与影响面。
3. 给出等价的手动命令：删目录联接只删本体，用 `rmdir C:\jdang`，不带 `/s`。
4. 给一行只读校验：`python -c "import os; print(os.path.lexists(r'C:\jdang'))"`，期望 `False`。

用户口头授权不解除分类器拦截；把命令交给用户执行，比让智能体找一条能通过的路径更安全。

> **为什么？** 拦截发生在"已授权"之后，说明系统判定该操作的风险高于当前任务的必要范围。此时换工具等于用工具选择规避风险控制，一旦判断失误就再没有第二道防线。

## 6. 报告口径

三段并列，禁止合并成"影响很小"：

| 段 | 可写内容 | 典型证据 |
|---|---|---|
| 已确认删除 | 名称、类型、恢复路径有无 | 根级清单差异 + 该卷可写 |
| 已确认完好 | 名称与范围 | 报错行 + 父目录 mtime + 样本文件仍在 |
| 未验证 | 对象、缺失的证据、需要的授权 | 分类器拦截、权限不足、无基线 |

不可恢复的对象单列一行。自己创建的遗留物（如盘根的悬空联接）应写"仍在、未清理、待授权"，不默认已完成。

## 7. Gotchas（陷阱与反直觉行为）

1. `rm -rf` 成功删除不打印，失败才输出；"没有报错"与"没有删除"无关。
2. `test -e` 对悬空链接/联接返回假；存在性判定用 `os.path.lexists`，并同时报 `lexists` 与 `exists`。
3. Git Bash 的 `ls -la` 把目录联接显示成 `lrwxrwxrwx`，与符号链接同形；需要类型时用 `os.path.isjunction`（Python ≥3.12），且先于 `islink` 判定。
4. 目录 mtime 变化不等于删除：必须在同一观察窗口内二次取样，看它是否持续推进。
5. 只读路径下的空目录不是删除产物——`rm` 连内容都删不掉，更不会清空它。
6. 回收站目录自身 mtime 与 `desktop.ini` 会被重写，不能当作清空或写入证据。
7. `rm` 不进回收站，所以"回收站空"证明不可恢复，不证明未删除。
8. 父目录 mtime 未变只能证明"该目录下没有条目被移除"，不能外推到其他卷或其他根。
9. 取证探针本身是写操作：在系统卷根建链接会在盘根留下遗留物；探针一律放 `%TEMP%`，且不要在上面可能被遍历的目录里留链接。
10. 超时转后台的删除命令可能仍在运行；先确认进程终止，再开始取证。

## 8. 安全检查清单（逐项确认）

- [ ] 已冻结现场，并确认后台删除进程已终止
- [ ] 已检索既有快照，或已明确记为"无基线"
- [ ] 已按名称/类型/mtime 三列完成根级差异比对
- [ ] 已用报错行 + 父目录 mtime + 样本文件交叉印证不可删路径
- [ ] 已二次取样确认 mtime 变化来自服务写入，未当作删除
- [ ] 已区分空目录假阳性与真实删除产物
- [ ] 已用 `whoami /user` 确定当前 SID，只统计该 SID 的回收站条目
- [ ] 结论已分为已确认删除 / 已确认完好 / 未验证三段
- [ ] 已给出根因与删除前置断言，未重跑破坏性命令
- [ ] 未绕过安全拦截、未清理遗留物、未做数据恢复
- [ ] 未把"回收站为空"写成"没有删除"

## 9. 依赖与错误处理

- 只读依赖：Git Bash（`ls`、`find`）、`icacls`、`whoami`、Python 3.10+（`isjunction` 需 ≥3.12）。
- 无脚本、无网络、无安装包；四步都是可直接复制执行的只读命令。
- 取证命令零命中不等于事件未发生：先确认路径拼写与 shell 引号（`$Recycle.Bin` 在双引号内会被展开）。
- 取证被分类器拦截时，记录对象与拦截原因，写入"未验证"段并请求显式授权，不改用其他工具继续访问。
- 同一组只读命令重复执行应得到相同结论；结论变化说明有新的写入源，回到 3.3 重新判别。
