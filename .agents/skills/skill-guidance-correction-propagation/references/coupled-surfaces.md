# 耦合面判定与命令

本文件说明如何把“同一条技术口径”在所有直接耦合面上找齐、判定是否同步，以及哪些邻近问题应移交其他技能。

## 1. 什么叫直接耦合

一个面与纠正事实**直接耦合**，当且仅当满足至少一条：

1. 它定义了该事实的真值（权威章节、规范段、错误码定义）。
2. 它复述该事实作为操作指令（正文步骤、检查清单、命令示例）。
3. 它把该事实编码成可执行输入（测试夹具、样本常量、模板）。
4. 它断言该事实的行为后果（错误码、报错数、退出码）。
5. 它对外承诺该事实已被处理（what it does、limitations、最终汇报）。

不满足以上条件的相似文本，属于**邻近内容**：只报告，不默认修改。

## 2. 权威面、派生面与状态

| 类别 | 例子 | 修改顺序 | 判定标准 |
|---|---|---|---|
| 权威面 | 引用章节的定义段、错误码表、版本边界 | 最先 | 新断言在此处完整、可复现 |
| 派生指令 | `SKILL.md` 的步骤、清单、命令 | 其次 | 不再要求旧行为，指针指向权威面 |
| 可执行输入 | 夹具构造器、样本目录、模板 | 再次 | 能被真实解析器/构建器接受 |
| 行为契约 | 单元测试、集成测试、断言 | 再次 | 非法形态有精确错误码与计数 |
| 对外承诺 | what it does、limitations、汇报 | 最后 | 与脚本真实能力逐条一致 |

三种状态必须分开命名：

- **目标态**：新规则要求且能通过真实验证的形态，可作为健康基线。
- **迁移中状态**：部分迁移、尚不完整但合理，测试可以保留，名称必须标明。
- **缺陷态**：已知会被后端或门禁拒绝的形态，必须由测试断言报错。

把缺陷态写成健康基线，是本次来源案例中最贵的错误：测试通过，生产构建失败。

## 3. 发现命令

### 3.1 全文枚举

```bash
TARGET="<skill-or-doc-dir>"
rg -n --hidden -S "<旧断言原句>|<核心名词>|<精简说法>" "$TARGET"
```

至少准备三组搜索词：

- 原句中的完整短语。
- 原句的核心名词（例如 `classifier`、`license-files`、`minimum-version`）。
- 旧结论被改写后的口语说法。

搜索时排除缓存，但不要排除 `scripts/` 与测试目录：

```bash
rg -n -S "<keyword>" "$TARGET" -g '!**/__pycache__/**' -g '!*.pyc'
```

### 3.2 文件盘点

```bash
find "$TARGET" -type f -not -path '*/__pycache__/*' -printf '%P\n' | sort
```

盘点用于发现没有命中的文件，例如只含错误码常量、或只用注释描述旧规则的测试。

### 3.3 逐面核对

| 面 | 额外命令 | 要读什么 |
|---|---|---|
| 正文 | `rg -n "references/" "$TARGET/SKILL.md"` | 正文指向哪些引用章节 |
| 引用章节 | `rg -n "^#{1,4} " "$TARGET/references"` | 标题本身是否旧口径 |
| 夹具 | `rg -n "def .*fixture\|def .*pyproject\|SAMPLE\|TEMPLATE" "$TARGET/scripts"` | 健康基线是否合法 |
| 测试断言 | `rg -n "assert|assertIn|assertEqual|exit" "$TARGET/scripts/test_*.py"` | 断言的是错误码还是仅非零 |
| 脚本检测 | `rg -n "ERROR\|WARN\|CONFLICT\|COEXISTENCE" "$TARGET/scripts/*.py"` | 文档中的错误码是否真实存在 |
| 能力说明 | `rg -n "What it does\|What it does not do\|limitations" "$TARGET/references"` | 已覆盖与未覆盖是否同步 |

## 4. 语义一致，不是字符串一致

同一条事实可能以五种形式出现，字符串不同但语义必须一致：

1. 散文：`SPDX 字符串与任何 License :: classifier 互斥。`
2. 表格：旧 classifier 与 SPDX 的映射表，标明“仅用于读取旧 manifest”。
3. 代码：`if license_is_spdx and has_license_classifier: error(...)`。
4. 测试：构造 SPDX + 匹配 classifier，断言新错误码。
5. 汇报：说明“已迁移仓库 0 错误，旧组合会报错”。

判定同步时逐项问：

- 散文是否还暗示“可以并存”或“保持对齐”？
- 表格是否仍被呈现为目标态？
- 代码是否只检查“不一致”而放行“一致但非法”？
- 测试是否只覆盖旧缺陷，未覆盖新非法形态？
- 汇报是否把“文档已改”说成“检测已补”？

## 5. 覆盖守恒

删除或改写夹具前执行三步：

1. 记录原测试覆盖的分支与错误码。
2. 为新确认的非法形态补测试，断言精确错误码、报错数与退出码。
3. 再删除或改写旧测试，复跑并比较测试总数与分支覆盖。

若原测试是某分支唯一覆盖，允许保留它，但必须改名为“迁移中状态”或“legacy”，避免下一个人把它当目标态。

## 6. 门禁与归因

| 检查 | 命令 | 通过标准 |
|---|---|---|
| Skill 格式 | `python quick_validate.py "$TARGET"` | `Skill is valid!`，退出 0 |
| 链接 | `python check-links.py --path "$TARGET" --check-frontmatter-paths` | `broken_local=0`、`broken_frontmatter=0`，退出 0 |
| 单元测试 | `python "$TARGET/scripts/test_<name>.py"` | 全部 OK，退出 0 |
| 真实样本 | 审计器或构建器对真实目录运行 | 错误数、警告数、退出码与预期一致 |
| 正样本 | 含已知缺陷的临时夹具 | 指定错误码出现，退出码为 1 |

每条命令单独执行并立即取 `$?`。以下写法会掩盖状态：

```bash
# 错误：返回 head 的状态
python test_x.py | head -5

# 正确
set -o pipefail
python test_x.py | head -5
```

归因表：

| 判定 | 证据 | 报告写法 |
|---|---|---|
| 本次引入 | 改动前无、改动后有 | 已修复并复跑 |
| 既有债务 | 改动前已有，改动后原样 | 单列，未修，附原文 |
| 环境伪失败 | 缺依赖、网络、文件锁 | 标注环境原因，不写通过 |
| 未验证 | 未执行、样本缺失 | 写明原因 |

## 7. 移交边界

| 情况 | 移交 |
|---|---|
| 需要全仓枚举许可证、版本、路径等声明 | `declared-consistency-fix` |
| 只读核验产物与源文档 | `artifact-consistency-audit` |
| 需要读取会话记录确认历史授权与失败 | `chat-session-evidence-audit` |
| 需要为随包脚本设计多类正负夹具、识别假失败 | `skill-bundled-script-validation` |
| 目录级门禁需要系统拆分既有与本次 | `gate-baseline-delta-triage` |
| 新建、更新、重命名 Skill 的完整流程 | `skill-creator` |
