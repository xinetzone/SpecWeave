# Skill Guidance Correction Propagation

本技能回答一个问题：当一条技术口径被证明写错后，怎样把它一次传播到所有直接耦合面，并且不在门禁与汇报里制造第二层错误。

## 1. Why：改一行不是纠错

同一条事实通常同时存在于正文、被引用章节、测试夹具和检测逻辑里。只改用户指到的那一句，会产生四种后果：

| 只改正文的后果 | 实际表现 |
|---|---|
| 引用章节继续教旧规则 | 读者点开正文里的链接，得到相反结论 |
| 健康夹具继续表达非法状态 | 测试全绿，真实构建仍失败 |
| 检测逻辑继续放行缺陷 | 文档声称已覆盖，实际没有错误码 |
| 门禁失败被误判为本次回归 | 要么回滚正确改动，要么顺手改坏无关字段 |

来源会话的实证：`license-scope-unification` 的同一处纠错经过了三轮才收敛——第一轮改正文与引用章节，第二轮改测试夹具，第三轮补检测逻辑。第一轮后 `quick_validate.py` 退出 1，但原因是被改文件**原本就有**顶层 `source` 字段，不是本次引入的回归；把它算到本次改动头上会导致无关修改。

> **为什么只改用户指到的那一句不够？** 同一条事实会在引用章节里被再次定义、在测试夹具里被编码成输入、在检测逻辑里被实现成条件。只改一处，其余三处仍在教旧规则，下一次读者或构建会从旧的那侧得到相反结论。

> **为什么引用文件的标题也要改？** 读者通过标题判断这一节讲的是目标态还是历史兼容；标题保留旧口径时，即使正文改了，链接预览与目录仍会把人引向旧结论。

## 2. 适用边界

使用本技能：

- 已有一条可复现证据表明 Skill 或文档中的规则、命令、版本边界、错误对照写错。
- 用户只指出一处，但同一事实可能被引用章节、夹具或测试断言复用。
- 测试数据把已知非法组合当作健康基线。
- 门禁失败，需要判断是本次引入还是既有债务。
- 文档声称某项检查存在，但脚本实际不检测。

不使用本技能：

| 任务 | 交给 |
|---|---|
| 许可证、版本号、路径等产物声明的全仓一致性修复 | `declared-consistency-fix` |
| 只读核验产物与源文档是否一致 | `artifact-consistency-audit` |
| 读取来源会话、核实推荐依据 | `chat-session-evidence-audit` |
| 随包脚本的深度正负夹具与假失败识别 | `skill-bundled-script-validation` |
| 新建或重命名 Skill 的完整流程 | `skill-creator` |
| 仅需把目录级门禁失败拆成既有与本次 | `gate-baseline-delta-triage` |

## 3. 铁律

1. **一条事实，全部耦合面。** 未完成枚举，不得说“已修正”。
2. **权威面优先。** 先改定义真值的引用章节或规范段，再改正文指针，最后改派生面。
3. **夹具必须表达合法目标态。** 把互斥选项写在一起的“健康基线”不是基线，是缺陷的固化。
4. **删旧覆盖前先补新覆盖。** 删除某个夹具或测试的唯一分支前，先为新确认的非法形态补断言。
5. **检测逻辑是独立授权。** 文档与夹具改完不等于脚本能发现缺陷；脚本行为变更先报告再动手。
6. **门禁失败必须归因。** 先取改动前基线，区分既有债务与本次回归；无关字段不顺手修。
7. **不静默扩大范围。** 相邻的同类问题列入报告，等待授权，不混入本次改动。
8. **只认原始退出码。** 管道、`tee`、复合命令会替换退出码；不用“看到输出”代替断言。

## 4. 工作流

### 0. 冻结纠正事实

先写一张四行卡片，再动任何文件：

```text
旧断言：
新断言：
证据：<命令输出、精确报错、版本边界、提交或文档>
影响范围：<哪个 Skill、哪个包、哪些生态>
```

证据不足时先做只读预检（取改动前基线、复现精确报错），不传播猜测。若新断言依赖后端版本，记录“首个支持的版本”，不要只记录当前环境版本。

### 1. 机械枚举耦合面

用绝对路径扫描旧断言及其同义词，逐条读取命中，不能只看文件名或标题：

```bash
TARGET="<skill-or-doc-dir>"
rg -n --hidden -S "<旧断言关键词>|<同义词1>|<同义词2>" "$TARGET"
find "$TARGET" -type f -not -path '*/__pycache__/*' -printf '%P\n'
```

搜索词至少覆盖三类：旧结论原句、旧结论的核心名词、旧结论的精简说法。同一条规则常被改写成表格、注释、测试名或错误消息，字符串不同但语义相同。

> **为什么用三组同义词而不是只搜原句？** 派生面很少逐字复述原句：引用标题会换说法，夹具用常量表达，测试用错误码断言。只搜原句会漏掉这些语义相同、字符串不同的耦合面。

### 2. 建立耦合面分类表

| 面 | 位置 | 角色 | 动作 | 理由 |
|---|---|---|---|---|
| 正文 | `SKILL.md` | 操作指令 | 修改 / 仅报告 | 是否直接依赖该事实 |
| 引用章节 | `references/*.md` | 权威解释 | 修改 / 仅报告 | 正文是否指向它 |
| 夹具 | `scripts/test_*.py` 的构造器 | 输入样本 | 修改 / 新增 | 是否把旧假设当健康态 |
| 测试断言 | 测试方法 | 行为契约 | 修改 / 新增 | 删除后是否丢覆盖 |
| 脚本检测 | 解析器、检查分支 | 执行能力 | 仅报告 / 另行授权 | 是否属于行为变更 |
| 能力说明 | 引用章节的 what it does / limitations | 对外承诺 | 修改 | 必须与实际行为一致 |

分类时区分三种状态：**目标态**（新规则要求的样子）、**迁移中状态**（合理但未完成，必须命名）、**缺陷态**（必须报错）。不要把迁移中状态写成健康基线。

### 3. 按依赖顺序修补

1. 权威引用章节或规范段。
2. 正文中的操作指令与指针。
3. 测试夹具：健康基线改成合法目标态。
4. 测试断言：同步旧断言，补非法形态覆盖。
5. 脚本检测：仅在获得授权后修改。
6. 能力与限制说明：逐条对齐脚本真实行为。

每次只改该事实及其直接后果。保留仍然有效的规则，不做顺手重构。

### 4. 覆盖守恒

- 原夹具把非法组合当基线：改成合法组合，并另加一条非法组合用例，断言精确错误码。
- 原测试是某分支的唯一覆盖：先补替代测试，再删除或改写旧测试。
- 旧测试名带 `mismatch` 不代表它测的是互斥；读断言，不读名字。
- 迁移中状态可以保留测试，但测试名与注释必须标明它是过渡态。

### 5. 复跑门禁并取原始退出码

```bash
python "<repo>/.agents/skills/skill-creator/scripts/quick_validate.py" "$TARGET"
echo "VALIDATE_EXIT=$?"

python "<repo>/.agents/scripts/check-links.py" \
  --path "$TARGET" --check-frontmatter-paths
echo "LINK_EXIT=$?"

python "$TARGET/scripts/test_<name>.py"
echo "TEST_EXIT=$?"
```

有随包脚本时，再跑两类真实样本：

- 干净产物：断言错误数、警告数与退出码。
- 含已知缺陷的正样本：断言错误码、报错数与退出码，不能只看到消息就算通过。

需要构建或渲染时，把产物放到临时目录，避免在用户仓库留下 `build/`、`dist/` 或缓存。

### 6. 把既有失败与本次回归分开

对每个失败项记录改动前与改动后：

| 判定 | 条件 | 动作 |
|---|---|---|
| 本次引入 | 改动前不存在，改动后出现 | 修复并复跑 |
| 既有债务 | 改动前已存在，改动后原样存在 | 报告中单列，不顺手修 |
| 环境伪失败 | 缺依赖、网络超时、锁目录 | 标注环境原因，不冒充通过 |
| 未验证 | 未执行或样本缺失 | 明写“未验证”及原因 |

典型误判：`quick_validate.py` 报 `Unexpected key(s) in SKILL.md frontmatter: source`，而被改文件在本次改动前就已带顶层 `source`。这属于既有契约冲突，不是本次回归；把字段移到 `metadata.source` 是单独的修改授权。需要更细的目录级归因时，调用 `gate-baseline-delta-triage`。

### 7. 按面汇报

报告必须包含：

| 项 | 必须写 |
|---|---|
| 纠正事实 | 旧断言、新断言、证据 |
| 改动面 | 每个文件的路径、行号、改了什么 |
| 未改面 | 发现但未授权或不属于本次的耦合面 |
| 门禁 | 每条命令的原始退出码与关键计数 |
| 归因 | 本次引入、既有债务、环境伪失败、未验证 |
| 覆盖 | 删除或改写的夹具是否有替代测试 |

只要还有直接耦合面在教旧规则，就不能写“已修正”。

## 5. 耦合面矩阵

| 面 | 发现方式 | 判定已同步 | 常见漏点 |
|---|---|---|---|
| 正文 | 搜索旧断言与同义词 | 操作指令不再要求旧行为 | 只改一句，段落其余句子仍默认旧规则 |
| 引用章节 | 正文中的相对链接与章节标题 | 标题、引言、表格用途、结论四处一致 | 标题本身仍是旧口径，表格仍暗示旧结论 |
| 夹具 | 搜测试构造器与样本常量 | 健康基线能被真实后端解析 | 非法组合被当成 pass 基线 |
| 测试断言 | 搜错误码、计数、退出码 | 非法形态有精确断言，不只是“失败” | 只断言退出非零，不断言错误码 |
| 脚本检测 | 读解析器与检查分支 | 新错误码真实产出且可定位行号 | 文档声称已检测，代码无分支 |
| 能力说明 | 读 what it does / limitations | 已覆盖项与未覆盖项都更新 | 只加能力，不写限制 |
| 面向用户摘要 | 最终回复、索引、变更说明 | 不夸大为“已全覆盖” | 把“文档已改”说成“检测已补” |

详细判定规则与命令见 [references/coupled-surfaces.md](references/coupled-surfaces.md)。

## 6. 失败模式对照

| 失败模式 | 症状 | 处置 |
|---|---|---|
| 只改正文 | 引用章节给出相反结论 | 先改权威面，再改指针 |
| 夹具固化旧假设 | 测试绿、构建红 | 健康夹具改成合法目标态 |
| 删除唯一覆盖 | 测试数下降但无人注意 | 先补非法形态测试 |
| 文档先于代码 | 声称有检测，实际放行 | 能力说明写“未覆盖”或补齐代码 |
| 既有失败算本次 | 回滚正确改动或改坏无关字段 | 取改动前基线再归因 |
| 管道吞退出码 | 门禁假绿 | 单独执行并 `echo $?` |
| 只看错误外层 | 多包异常难定位 | 解开 `ExceptionGroup` / `Failed to parse ... (1 sub-exception)` |

来源会话中出现过的精确报错：

```text
Setting "project.license" to an SPDX license expression is not compatible with 'License ::' classifiers
Failed to parse pyproject.toml (1 sub-exception)
Unexpected key(s) in SKILL.md frontmatter: source. Allowed properties are: allowed-tools, compatibility, description, license, metadata, name
```

## 7. 写后卫生

- 回读每个改动文件，确认 frontmatter 可解析、正文非空、引用文件存在。
- 文本 UTF-8 无 BOM；清理 `__pycache__` 与 `*.pyc`。
- 新增或修改 Python 时不写 `from __future__ import annotations`。
- 不创建 `README.md`、`CHANGELOG.md` 等非任务要求的人类文档。
- 未获授权不提交、不推送；共享工作树中只暂存明确路径。

## 8. Gotchas

1. 用户说“那一处”通常只授权那一处；先列出直接耦合面并说明，再决定是否扩大。
2. 引用文件的**标题**也可能是旧口径；改正文不改标题，链接仍会误导。
3. 把表格“降级为审计参考”必须写清用途；只删最后一行结论不够。
4. “审计不报错”不等于夹具健康；要用真实解析器或真实构建验证。
5. 测试名可能与实际断言不一致；以断言和错误码为准。
6. 用户级 `quick_validate.py` 只允许六个顶层键；仓库原生字段会被拒，不要把契约差异当成本次回归。
7. 链接门在用户级目录必须用绝对 `--path`；相对路径会按当前工作目录解析。
8. 删除一个夹具分支前，确认没有其他测试覆盖同一分支。
9. 脚本行为变更单独确认；文档先写“未覆盖”比假装已覆盖安全。
10. 迁移中状态必须命名；否则下一个人会把它当健康基线继续复制。

## 9. 安全检查清单（逐项确认）

- [ ] 已写下旧断言、新断言、证据与影响范围。
- [ ] 已用旧断言原句与同义词扫描全部耦合面，并逐条读取命中。
- [ ] 已列出改动面、仅报告面与未授权面。
- [ ] 已确认权威引用面先于正文指针修改。
- [ ] 已确认健康夹具表达合法目标态，非法形态另有测试。
- [ ] 已确认删除或改写的测试没有净丢失分支覆盖。
- [ ] 已确认脚本检测能力与能力说明一致，行为变更已获授权。
- [ ] 已检查格式、链接、测试、真实样本均取到原始退出码。
- [ ] 已区分既有失败与本次回归，未顺手修无关字段。
- [ ] 已明确报告区分已改、未改、未验证，没有夸大为“已全覆盖”。
- [ ] 已确认无残留 `__pycache__`、`*.pyc` 缓存与 BOM。
- [ ] 已确认未提交、未推送，未写入授权范围外的文件。
