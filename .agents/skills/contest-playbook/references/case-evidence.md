> ⚠️ **证据性质声明**：
> - 两个样本的**规则部分**均为**平台单源**（官方细则 PDF 无公开直链、第三方转载极少），且**均未包含已获奖结果样本**——因此所有机制判定都是**规则结构推断**，未经结果验证。

| 《学术星轨 ScholarMatrix》 | 六十多个工具面板，按科研节奏串成八个阶段；作品页与项目链接双发 |

### 值得单独记住的一句

参赛者《坠入黑洞》自述：「**AI 可以快速输出代码，但视觉参数、交互手感、边界 bug，必须由我作为创作者持续反馈、精细校准。**」

> 这是"AI 辅助开发"在竞赛语境下的**真实分工**——AI 给骨架，人给判断。对应到评审维度里的"AI 工具的实际使用情况"，真正拉分的不是"用了 AI"，而是"**你做了什么只有人能做的判断**"。

### 社区参赛作品（🟡 参赛者自述，2026-10 前后发布）

| 作品 | 可提取的经验 |

| 电控掌中工具箱 · PID 调参实验室 | 4 种真实被控对象；拖滑块实时画阶跃响应 + 自动算超调量/调节时间/稳态误差；**两个专门的反直觉演示**（抗积分饱和开关、噪声滑块看微分项放大噪声）；一键 ITAE 自动整定 |
| 看板开发看板 | 痛点四问（进度散在对话 / 无法验证"已完成" / 卡住无人知 / 换窗口失忆）；三层设计（看板 + CLI + Skill）；**稳定 JSON + 乐观锁 + 语义化退出码**（0 成功 / 2 参数错 / 3 版本冲突 / 4 找不到）——让 Agent 能程序化处理 |
| 第一现场 SceneOne | 多格式日志解析（GHA/Nginx/syslog/JSON/logfmt/Java/Python 堆栈）→ 定位第一现场 → 四级启发式判定疑似级联 → 124 条中文错误知识库给修复建议 → 一键生成可贴 Issue 的报告。**两个设计取舍**：不调大模型（纯本地规则，结果可复现）+ 零网络请求（日志不出浏览器，生产日志也敢贴） |
| 真实时薪计算器 | 八问画像 → 四路线打分只推荐一条 + 明确告诉哪条千万别碰；12 周计划前 4 周只做验证；报价底线计算器；**竞业协议等合规红线自查**；数据只存本地，单文件点开就用 |

> **共性观察**：五个作品的**共同结构**不是"功能多"，而是——
> ① 有一个**可演示的核心交互**；② 有一个**可举证的过程**（脱敏案例 / 对话截图 / 源码 / 规则引擎）；③ 至少一个**刻意的取舍**（不调模型、零网络、脱敏、语义化退出码、单文件）。
>
> 这与判定 A（有效作品=排除项清单）、判定 B（过程举证是硬要求）一致。

## 三、样本 C · 跨赛事情报（🟠 非官方口径，仅作参照）

### 审核与合规情报

| 主题 | 情报 |
|---|---|
| **AI 应用审核雷区** | ① 自动引入第三方通用 SDK 且不补齐隐私清单与权限说明文案；② 无意识生成区分测试/审核环境的分支代码（命中规避审核条款）；③ 存在动态加载、热更新、远程配置逻辑（命中禁止动态执行代码条款）；④ 缺少差异化独有功能 → 判定"无独立价值"；⑤ 资源文件哈希值重复；⑥ 元数据文案高度模板化 |
| **检测层级** | 代码指纹 > 界面布局 > 产品功能 > 商店文案，**四层联动**；两处及以上高度重合即加重风控标记 |
| **AIGC 检测** | 多赛事已启用 AIGC 检测工具；双查重下 **AIGC 率 ≥25% 认定为抄袭**；查重看控制流图/语义指纹/图表数据分布，**换字洗稿无效** |
| **AI 声明表** | 多赛事要求强制提交《AI 创作作品使用说明》/《AIGC 使用情况声明表》；**未提交视为无效投稿**；要素：工具名+版本 / 参与环节 / 人工修改与审核过程 / 占比区间（>50% 属高风险）；海外同类赛事有 AI Declaration Form，未披露者直接取消资格 |
| **同质化阈值** | 有赛事明示"自动检测作品相似度，**超过 80% 视为重复作品**，评审阶段发现的重复作品直接判定无效" |

### 赛程形态情报

| 形态 | 实例特征 |
|---|---|
| **双阶段预审** | 报名/组队截止 → **作品预审（作品规划材料评审）** → 通过者进入正式开发 → 正式提交 → 初评 → 终评。作品规划书是**资格初审唯一依据**；"报名截止后无特殊原因不得更换成员"、"报名信息截止前可修改，截止后锁定"、"未锁定队伍的报名自动失效" |
| **组队截止早于报名截止** | 反直觉顺序，必须单独登记 |
| **每日提交次数限制** | 有赛事"每队每天限提交 1 次，取最新版本评分" |
| **答辩型** | 初筛 → 公布晋级 → 总决赛现场路演答辩 |

### 传播情报

| 主题 | 情报 |
|---|---|
| 图文最佳区间 | 6—8 张；用户多在**第 4—6 张**决定是否收藏；角色分工：1 门面 / 2—3 钩子 / 4—6 干货 / 7—8 收尾 / 末张互动 |
| 算法权重 | 评论 > 收藏 > 点赞 |
| 冷启动 | 发布后 1 小时内找 5 个好友做有效评论 |

### 部署情报（实战踩坑）

| 主题 | 情报 |
|---|---|
| 本地能跑提交后跑不起来 | 六个必查：真实 start 命令 / bind `0.0.0.0` + 读 `PORT` / Vite 只暴露 `VITE_` 前缀且构建期烘焙（缺值静默失败）/ 干净环境装依赖 / 容器文件系统一次性（SQLite 相对路径下次重部署即消失）/ 密钥 grep |
| 硬编码问题 | Hardcoded localhost URL / API key 硬编码 / SQLite in production / CORS（localhost 下正常是因为 CORS 没生效） |
| 提交包卫生 | 不含真 `.env` / `id_rsa` / service-account JSON / 真实数据库备份；用 `.env.example` 占位；不带 `node_modules`；README 必答 7 问；团队项目须列全部成员 |
