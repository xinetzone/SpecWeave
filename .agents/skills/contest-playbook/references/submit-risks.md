# 提交与合规风险清单

> **本文件是执行层**：SKILL.md 步骤 5—7 的细则展开。所有条目都标注了来源强度：
> 🟢 **实测/平台明示**（规则原文或前端代码）｜🟡 **社区实战单源**（参赛者自述，未经官方确认）｜🔴 **跨赛事通用**（多场赛事一致，但非本样本官方口径）

## 一、提交技术风险 12 项

> **核心判断**：绝大多数 AI 生成作品的失败不是"被驳回"，而是"**本地能跑，提交后跑不起来**"。这 12 项按部署链路的实际顺序排列。

| # | 检查项 | 具体做法 | 来源 |
|---|---|---|---|
| **T1** | **干净环境从零复现** | 在**全新目录/全新容器**里按 README 从零跑一遍；记录每一条复现命令。AI 生成的 Python 常 import 了没进 `requirements.txt` 的包 | 🔴 |
| **T2** | **start/build 脚本存在且平台可猜** | 平台只认 `start`/`build` 等约定脚本；只有 `dev` 脚本的平台起不来 | 🔴 |
| **T3** | **监听 `0.0.0.0` + 端口来自环境变量** | bind `127.0.0.1` 时**日志完全正常但外网不可达**，是最隐蔽的失败 | 🔴 |
| **T4** | **构建期变量的前缀与静默失败** | Vite 只暴露 `VITE_` 前缀且**构建期烘焙**；缺值时页面显示 `undefined` 且**任何地方都不报错** | 🔴 |
| **T5** | **依赖清单完整** | `requirements.txt` / `package.json` 与实际 import 对齐；在干净环境安装验证 | 🔴 |
| **T6** | **持久化路径** | 容器文件系统是**一次性**的——SQLite 相对路径在下次重部署即消失；需用平台持久卷或外部存储 | 🔴 |
| **T7** | **密钥不进包** | 提交包绝不能含真实 `.env` / `id_rsa` / service-account JSON / 数据库备份；用 `.env.example` 占位；构建后轮换密钥 | 🔴 |
| **T8** | **硬编码地址全局搜索** | 全局搜 `localhost` / `127.0.0.1` / 绝对路径 / 硬编码 URL。AI 常生成 `localhost` 链接，**外网访问必然失败** | 🔴 |
| **T9** | **CORS** | 前后端分离时跨域配置；"一切在 localhost 下正常"往往是因为 CORS 没生效才没暴露 | 🔴 |
| **T10** | **包体裁剪** | 去掉 `node_modules` / `.git` / 缓存 / 大文件；确认包在限制内 | 🔴 |
| **T11** | **前端校验全量预演** | 逐个字段实测：字符数/字节数预算、格式白名单、必填星号、违规词归一化、草稿缓存会丢哪些字段 | 🟢 |
| **T12** | **不可逆状态快照** | 提交后能否改？能否撤回？能否重排？形态选项提交后是否锁定？核验日是哪天？ | 🟢 |

### T11 的实测细节（来自样本 B 的前端代码，最易被忽略）

| 项 | 实测值 | 陷阱 |
|---|---|---|
| 截图压缩 | 最长边 1600px、初始质量 0.82，共 6 档降质 | 压缩参数是**平台设定**，不可控 |
| 截图上传 | **逐张串行上传**，失败**最多尝试 3 次（首次 + 2 次重试）**，**任一张失败即中止投稿** | 提交前务必本地先确认每张都能正常打开 |
| base64 预算 | 单张 ≤ 520×1024、总量 ≤ 1900×1024 | ⚠️ **口径是「字符数」不是字节数**——常量名带 KB 字样但代码按 `.length` 累加 |
| 违规词扫描 | 5 个字段：作品宣言 / 作品名称 / 作者昵称 / 作品介绍 / 作品体验链接 | ⚠️ **作品形态与社媒链接不在扫描范围内**；匹配会做归一化（全角→半角、繁→简、去标点空格 emoji）以抓「赌*博」式拆词 |
| 草稿缓存 | **不含联系方式字段**；视频只存本地路径引用 | 刷新页面后需重填/重选 |

### 平台规则 vs 安全实践的冲突（必须仲裁）

**冲突**：某平台部署文档明确指示「若提示注入环境变量秘钥 → 告诉 Agent：**秘钥写入文件直接构建**，代码不会上传到仓库」。这与通用安全实践（T7：密钥不入包）**直接冲突**——把密钥打进构建产物等于公开。

**仲裁规则**：
1. 采用「**最小权限测试密钥** + **构建后立即轮换** + **作品介绍中只声明用途不贴值**」；
2. 在方案里把这条记为「平台规则与安全实践冲突，已按最小暴露方案处理」；
3. 若平台明文要求写入文件且无法轮换，则**该作品不得承载真实数据**，只能用测试数据。

### 部署链路的平台特例（样本 A 实证）

- **代部署暂不支持独立数据库托管** → 把数据库文件改成 JSON 数据文件；
- **preview 链接仅作者登录可访问**，审核通过后才有不带 preview 的正式公网链接 → ⚠️ **不要把"预览可访问"当作"已通过审核"**；
- **有应用数量上限**（样本 A 为 10 个）→ 提交前清理占位项目；
- **某个指定分类是否存在不可判定**（前端渲染问题）→ 走 SKILL.md 步骤 5 的"向平台确认"分支。

## 二、合规三层自查

### L-A 产出物形态层

从规则原文**逐条抄**排除项，不归纳。对每条判定标注：

| 判定载体 | 判定强度 | 后果 |
|---|---|---|
| 功能 / 展示文案 / 作品形态 / 主题相关性 | 硬阻断 | 不算有效作品 |

**样本 A 的排除项原文**（并列全避）：简单套壳、批量生成、重复搬运、无实质功能、与科学/科研主题无关。

**样本 B 的排除项原文**：仅提交创意说明或静态设计稿。

> ⚠️ **不要归纳成"要有创意"**——那会丢掉全部可执行性。要抄原文。

### L-A′ 工具/技术绑定层

| 判定载体 | 判定强度 | 后果 |
|---|---|---|
| 创作工具 / 技术栈 / 赛道选择 | **一票否决** | 取消全部评奖资格 |

**样本 A 的绑定条款**：「全程使用对应赛道指定工具完成科学/科研主题作品」（资格条件）+「每件作品仅可使用**一个**赛道指定工具完成，并**仅可报名一个**专属赛道」（一票否决）。

**样本 B 的绑定条款**：作品形态仅「网页应用 / 小程序应用」两项，且**第 04 项提交后不可改**。

**检查动作**：

| # | 查什么 | 怎么查 |
|---|---|---|
| 1 | 是否强制指定工具/技术栈 | 规则原文找「全程使用」「须使用 X 完成」 |
| 2 | 是否限制只能选一个 | 找「仅可」「只能」「一票否决」字样 |
| 3 | 该选项是否有**获取阻塞**（内测申请、等待延迟、可能失败） | 找「申请」「XX 小时后生效」「权限」 |
| 4 | 该选项的**体验链接获取路径**是否明确 | 找「发布为网站」「上传源码至 X」 |
| 5 | 选错的补救成本 | 有没有第二赛道/形态可退 |

> ⚠️ **这一层必须在选题之前查**。若某选项的获取有阻塞（内测 24h 且可能失败）而规则又不允许同时准备两个选项，那么**该选项的失败没有退路**——此时应先确认能否拿到资格，再投入任何不可逆成本。

### L-B 生产过程层

| 判定载体 | 判定强度 | 后果 |
|---|---|---|
| 创作过程记录 / 对话记录 / AI 声明表 / 过程截图 | 硬阻断（若规则要求） | 无效投稿 / 取消资格 |

**「AI 使用声明四要素」模板**（跨赛事通用项，多场比赛通用）：

```
1. 使用的工具名与版本：
2. AI 参与了哪些环节：（如：需求梳理 / 代码生成 / 素材生成 / 文案初稿）
3. 人工做了哪些修改与审核动作：（逐条列，例：逐行审查逻辑、补充边界处理、
   手工校核全部数值、撰写全部解释性文字、最终测试由本人执行）
4. 占比估算区间：（精确到 5% 区间；若 >50% 属高风险）
```

> **未提交声明表 = 无效投稿、不予评审**（多个赛事的明文规则）。这一项比"作品做得好不好"更容易致命，因为它**不需要审核者主观判断**——形式上就卡死。
>
> 另一个高频致命点：**纯 AI 直接生成、无实质性人工干预** → 不予入围或直接淘汰。

**AIGC 检测已成常规**：多个赛事已全面启用 AIGC 检测工具，双查重机制下**AIGC 率 ≥25% 即认定为抄袭**。对策不是"洗稿"（查重不看表面字面，看控制流图/语义指纹/图表数据分布），而是**真的有人工实质参与并留下证据**。

### L-C 同质化层

| 判定载体 | 判定强度 | 后果 |
|---|---|---|
| 代码 / 界面 / 文案 / 资源文件 | 概率性（相似度阈值） | 相似度驳回 / 取消资格 |

**实际判定尺度**（比想象的严）：

| 维度 | 判定依据 | 错误做法 | 正确做法 |
|---|---|---|---|
| **代码** | 控制流图 / AST 语法树 / 语义指纹 | 改变量名、删注释（只降低文本相似度，无效） | 改**产品逻辑与结构**，重写差异功能 |
| **界面** | 页面布局、功能入口、交互逻辑 | 只换配色/图标 | 改架构与信息层级，改变用户进入核心功能的路径 |
| **文案** | 标题/描述/关键词的固定句式 | 同义词替换 | 重新组织表达，写真实场景与真实数字 |
| **资源** | 图片/图标/占位图的**哈希值重复** | 重新压缩图片（哈希仍近同） | 换用自制或明确授权素材 |
| **元数据** | 应用名、简介、截图、版权信息、联系方式 | 换名 | 全部重做并填真实信息 |

**检测是多维联动的**：代码 + 界面 + 文案三重维度同时筛查，**两处及以上高度重合即加重风控标记**。

> **只换图标/截图/应用名是最无效的表层修改**——底层代码骨架没变，机器扫描几秒即可识别模板复用，且会**提升账号后续提审的风控敏感度**。

### 账号状态层（易漏、后果严重）

| 检查 | 后果 |
|---|---|
| 注册手机号是否为虚拟号 | 样本 A：直接取消全部评奖资格 |
| 活动期账号是否有违规记录 | 样本 A：取消全部评奖资格 |
| 投稿账号与领奖账号是否一致 | 样本 B：积分发到**投稿账号**——A 账号投稿、B 账号收则收不到 |
| 获奖公示期前是否删帖 | 样本 A：取消全部评奖资格（即便不获奖也要保留） |

## 三、传播打法分档

**前置动作（不可跳过）**：查该比赛取消资格条款里有没有「刷赞 / 作弊 / 不正当手段」字样。
- **有** → 该分项期望收益按 ≤0 处理，只做自然互动，禁止互赞群/互赞帖/刷赞脚本；
- **无** → 按下面的口径分支。

### 分支 A：站外独立计分

> ⚠️ **别把传播分的作用只说一半**。在 B 样本中，社媒分在**档位之间**不改变奖励内容（参与奖区内同档均为 500 积分），但它**决定你能否进入某一档**——若原本落在门槛之外，传播分正是翻过门槛的唯一杠杆。**只说"对奖项无影响"是危险的一半真话**，会让处在门槛边缘的参赛者直接放弃这 30 分。

```
① 标签逐字核对（缺一可能整项归零，不只是少分）
② 冷启动：发布后 1 小时内完成有效互动（算法权重 评论 > 收藏 > 点赞）
③ 按计分口径反推选图：
   若计「点赞 + 收藏」之和 → 收藏权重更高且用户多在第 4—6 张决定是否收藏
                        → 把最能说明核心玩法的一张放在中段，而非习惯性放首图
   若只计点赞 → 钩子图前置
④ 零互动不补发（若规则不限次数则可择机补发，零互动帖在核验窗内不产生收益）
⑤ 核验日之前不发新内容（核验后补发来不及累积）
```

### 分支 B：站内弱参考

只做自然互动。**不做任何刷赞动作**——这在样本 A 里是取消资格情形，而互动表现本身只是"参考项"，不是主要依据。

### 分支 C：无

不排期。把精力全部投到作品本体与材料。

### 材料展示通用建议（站外图文）

- 图数：**6—8 张**为佳区间；
- 分工：第 1 张门面 / 2—3 钩子 / 4—6 干货 / 7—8 收尾 / 最后 1 张互动；
- 正文结构：**开头三行决定是否留下**——不要自我介绍和背景铺垫，直接给最有反差或结论性的那句；
- 链接位置：正文中段偏前，让读者在读完第一段后就能点；
- 若规则要求配图含"过程截图"，**过程截图与作品展示图要分开占位**，不要一张图兼顾两种用途。

## 四、参赛后处置（易漏但影响长期）

| 事项 | 处置 |
|---|---|
| 未获奖能否公开/商用 | 查规则；样本 B 明文"不得擅自转发至其他平台、不得用于出版、商业盈利或二次创作"，且**作品是否留存作品墙官方未给** |
| 获奖后奖励的时效 | 样本 B：积分有效期 3 个月，未用的 15 日内返还抵扣 |
| 公示期前删帖 | 不删——即便不获奖 |
| 账号后续状态 | 活动期结束后恢复常态，但保留过程记录（下次参赛直接复用） |
