# 参赛作战手册（Contest Playbook）

> **定位**：把一个比赛的活动规则，逆向成一份可执行的参赛方案。
>
> ⚠️ **三条硬边界（不可越）**：
> 1. **本 skill 输出的机制判定全部来自规则文本结构推断，未经获奖结果验证**——两个样本都没有一个已获奖作品可用于验证。凡涉及"获奖概率、名次、评审口味"一律**不可输出**。
> 2. **不承诺名次、不承诺获奖、不预测对手**——评审机制官方几乎从不披露。
> 3. **规则原文与推断必须分离标注**——凡本包未逐字读到的东西，一律标「未读到 / 缺口」，不得以推测填充。

---

## 1. 这个 skill 解决什么问题

比赛规则的**结构**跨比赛高度稳定，而**具体条款**每次都变。本 skill 沉淀的是前者：

```
比赛规则（每次不同）  →  取证 →  结构化编号事实  →  抽取通用判定  →  套入你的资产  →  参赛方案
   ↓ 每场都变                    ↓ 每次重做            ↓ 这层稳定        ↓ 每次不同
```

**输入**：一个比赛的活动页/规则文本 + 参赛者的真实资产与可投入时间。
**输出**：一份可执行的参赛方案（选题、形态、材料、倒排、风险清单）。

---

## 2. 执行流程（7 步）

```
步骤 0  判型：先分类，再排期          ← 跳过这步，倒排表整表失效
步骤 1  取证：采集阶梯 + 不可得模式  ← 正常路径在最主流的页面上会失败
步骤 2  结构化：编号事实 + 缺口登记  ← 判定与事实分离的基础
步骤 3  抽判定：跨比赛通用机制      ← 只有 3 条经得起双样本检验
步骤 4  对位：你的资产 → 评分维度    ← 不是打分，是找材料
步骤 5  选形态：决策树 + 不可选分支
步骤 6  排期：双轨倒排 + 阻塞决策点
步骤 7  合规：三层自查（形态/过程/同质化）
```

每步的详细执行规范见 `references/` 对应文件，按需读取。

---

### 步骤 0 · 判型（不可跳过）

**先判赛道形态，再排期**——不同形态的时序结构完全不同：

| 形态 | 特征 | 排期要点 |
|---|---|---|
| **单阶段投稿型** | 开发 → 材料 → 提交 → 评审 | 单轴倒排；提交即定生死（若审核在窗口后） |
| **双阶段预审型** | 报名/组队 → **作品预审** → 才有开发资格 → 正式赛 | **双轨**：资格轨 + 作品轨；预审不过 = 没有开发资格 |
| **路演答辩型** | 提交 → 初筛 → 晋级 → 现场路演 | 答辩材料是**独立交付物**，不能临场准备；答辩稿要单独排期与试讲 |
| **内测资格型** | 报名 → 申请内测/审核 → **等待延迟** → 才可用 | 延迟天数进倒排；不可逆投入须在资格确认后 |
| **命题型** | 主办方给定题目清单 | 选题变成"逐题对位"而非"自由选题" |

> **判型信号**：规则里出现「作品规划书作为资格初审唯一依据」「预审通过才能进入开发」「报名截止后锁定信息」→ 双阶段预审型；出现「XX 小时后生效」「申请内测权限」→ 内测资格型；出现「初筛/晋级/总决赛/现场路演」→ 路演答辩型。
>
> **形态可叠加**：命题型 + 内测资格型很常见（如"用指定内测工具做指定题目"）。判型后按**最早收紧的那条轨**排期。

> **为什么判型必须排在取证之前？** 形态决定了倒排表的**轴数**（单轴还是双轨）、决定哪些时点是硬边界、决定缓冲留几天。形态判错，倒排表不是"某几格填错"，而是**整张表的结构错了**——双阶段赛事按单轴排会漏掉资格轨的全部时点，单阶段赛事按双轨排会凭空造出一批不存在的约束。所以判型不依赖规则细节，只依赖时序信号，可以先于深读完成。

### 步骤 1 · 取证：采集阶梯

**正常路径（SPA 直读、明文规则页）往往不可用**——两个真实样本的规则都不在明文 HTML 里。逐级下探，命中即停：

| 级 | 手段 | 命中标志 |
|---|---|---|
| L1 | 静态 HTML 直读 | 规则在 `<div>`/`<table>` 里 |
| L2 | 平台 API / 开放平台 CLI | 有开放平台且返回正文 |
| L3 | SPA 引导数据逆向 | 静态 HTML 只含 `window.__PUBLISH_BOOTSTRAP__` 之类引导数据 → 取 artifact 清单 → 下载静态托管目录 → 从页面 JS 的**字符串字面量**里取正文 |
| L4 | 渲染后 DOM | 用 browser 工具取渲染后 HTML |
| L5 | 官方 PDF / 附件 / 细则弹层 | 活动页有「下载规则」链接 |
| L6 | 截图 + OCR / 评论区补充 / 官方问答 | 规则只在海报图里 |
| L7 | **规则不可得** | 以上全空 |

> **L3 的实战细节**：正文常在 JS 的函数返回值里（例：`function ruleHTML(){ return "..." }`）。用 HTML 标签剥离只能拿到几十行噪声——必须从状态树 JSON 的文本节点里取。

**L7「规则不可得模式」**（不可省略，实战中很常见）——不猜规则，只做三件事：

1. 列出**无法确认的必答项**清单：作品形态、资格条件、材料、截止时间、资格取消情形、评审维度；
2. 每项给**保守默认动作**（宁可多做不可漏做）；
3. 标注「**在规则确认前不做不可逆投入**」——不发社媒帖、不买域名、不公开作品、不报名不可退的赛道。

### 步骤 2 · 结构化：编号事实 + 缺口登记

**这是本 skill 最可复用的一层，比任何具体章节都值钱。**

| 族 | 含义 | 是否原文 | 纪律 |
|---|---|:---:|---|
| **F-xxx** | 事实——规则原文或页面代码里直接读到的 | ✅ | 逐字转录，挂信源定位 |
| **G-xx** | 缺口——**官方未给出**的信息 | ❌ | 官方没说 ≠ 我没查到，两者不可混同 |
| **M-xx** | 采集元数据 | ⚪ | 采集链路、体量、动作记录 |
| **C-xx** | 核验结论 | 混合 | ✅已核 / ⚠️推导或不自洽 / ❌冲突 |
| **I-xx** | 机制推断 | ❌ | 必须显式标注「推断」，不得伪装成官方口径 |
| **E-xx** | 勘误 | — | 对自己或原文的更正，留痕 |

**六条纪律**：

1. **事实行不写因果词**（因为/导致/所以）——条件—后果条款除外，且须声明豁免；
2. **缺口单独成族**——官方没说的信息单列，不与事实混排；
3. **口径分层标注**（平台口径 / 页面结构 / 平台展示值 / 转录 / 独立核验）；
4. **单源标记**——若全部规则只有一个信源，整包标 `flagged`；
5. **勘误留痕**——发现原文错误或自身错误都登记，不静默改；
6. **复核触发条件写「载体变更」而非日历到期**——规则可由主办方随时调整。

---

### 步骤 3 · 抽取通用机制判定（只有 3 条经得起双样本检验）

> ⚠️ **不要把某一场比赛的结构当成通用**。以下是经过双样本交叉、并经对抗审查后保留的判定。其余看似通用的东西，先判它是不是某一侧的特例。

**判定 A · 有效作品是「排除项清单」，不是「做完就有效」**

规则几乎从不正面定义有效作品，而是**列举排除项**（如"简单套壳、批量生成、重复搬运、无实质功能、与主题无关"）。这些项是**并列全避**，不是打分。

→ 产出物：逐条抄下排除项 + 一张「可交互动作声明」（写出那个"用户不做就不发生"的动作，录屏证明）。

**判定 B · 材料有生产依赖链，顺序不可换**

先有作品 → 才有链接 → 才有截图 → 才有介绍文章 → 才有传播。先做介绍文章再开发，必然返工。

→ 产出物：材料依赖链 + 生产顺序表。

**判定 C · 审核裁量不可知，且审核时点决定一切**

规则常写"以审核结果为准""审核通过才算有效投稿"，但**不公布审核标准与时长**。关键分叉：

- **审核在窗口内** → 可迭代（提交后可能退回改），缓冲按 ≥2 天留；
- **审核在窗口后**（活动结束后才审）→ **提交即定生死**，必须把自检推到极限，且**提交后无反馈机会**。

→ 产出物：先判审核在窗口内还是窗口后，再决定缓冲与自检强度。

**已被对抗审查否掉的 3 条**（不要写进方案）：

| 曾经的"通用判定" | 为什么否 |
|---|---|
| 「传播分可独立获取」 | 在 B 样本成立，在 A 样本**为负收益**——A 的规则把"刷赞"列为取消资格情形，传播只是"参考项"。**必须分支判定，见步骤 3-bis。** |
| 「评分维度有门槛型/连续型之分」 | 无官方口径。A 样本连权重都没有；B 样本的该判断被自己的知识包标为"不可单独引用的推断"。**改为：逐维度找可举证材料，权重未知时全部等权对位。** |
| 「选题四象限（知识密度 × 交互性）」 | 直接由 B 样本的形态定义措辞生成，且一半是对特定资产的定制判断。**改为分支：命题型走逐题对位，自选型走资产盘点。** |

### 步骤 3-bis · 传播/互动：先分支，再决定做不做

**先查该比赛的"取消资格情形"里有没有「刷赞 / 作弊 / 不正当手段」字样。有，则该分项的期望收益按 ≤0 处理。**

| 分支 | 判定信号 | 动作 |
|---|---|---|
| **站外独立计分** | 有明确分值、核验日、话题标签义务 | 按计分口径反推打法：核对标签逐字无误 → 发布后 1 小时内做冷启动互动 → **按计分口径反推选图**（若计"点赞+收藏"之和，把最能触发收藏的一张放在中段而非首图）→ 零互动不补发（若规则不限次数则可择机补发） |
| **站内弱参考** | 只写"参考互动表现"，无分值、无核验日 | **只做自然互动**。禁止互赞群、互赞帖、刷赞脚本——这是取消资格情形 |
| **无** | 完全不提 | 不排期 |

### 步骤 4 · 对位：你的资产 → 评审维度

**不是给维度打分，是给每个维度找"可举证材料 + 自查动作"。**

权重未知时的策略：**同时满足所有维度，不押注任何一项**——权重未知时均衡策略的期望收益高于集中押注。

```
| 评审维度 | 分值(若有) | 我的可举证材料 | 自查动作 | 事实 |
```

**权重已知 vs 未知的两种做法**：

| 情况 | 做法 |
|---|---|
| **有明确权重**（如技术 30 / 设计 40 / 价值 30） | 逐维度算**分值占比**，投入时间按占比分配；再叠加两项检查——① 是否有维度是**门槛型**（不达标即整项归零，如"能否正常运行"）；② 是否有维度是**一票否决**（不满足直接取消资格）。**加权投入不等于忽略低分维度**：占比最低的维度若同时是门槛，照样能让你出局 |
| **权重未知** | **全部维度等权对位**——每个维度至少准备一件可举证材料，不押注任何一项。无权重信息时，均衡策略的期望收益高于集中押注 |

**两种情况都要先问的两个问题**（比权重本身更重要）：
1. 哪些维度是**归零型**的（不做就没有分）？
2. 哪些是**资格型**的（不满足会被取消资格）？

> ⚠️ **不要从"分值高"推出"最该投入"**。高权重维度往往是**连续可微**的（多花时间边际收益递减），而低权重维度若同时是门槛型，**投入产出比可能更高**。先归零型，后加权型。

**资产盘点必须现场做**，不能背模板。盘点三个东西：
- 已有内容/代码资产（体积、条数、可用度）
- 已有工程资产（流水线、部署、构建脚本）
- 已有对外资产（站点、账号、社媒受众）

> ⚠️ **对外文案里的绝对数字会漂移**——库会增删、作品会变。凡提交给评审的材料一律用量级表述，不写精确数字。

### 步骤 5 · 形态决策树

```
作品形态是封闭选项（仅 N 种）？
├─ 是 → 哪个选项提交后不可改？        ← 不可改的那个 = 整个方案的不可逆点
│        先查它对体验链接获取路径的影响
│        ↓
│   ├─ 选项数 = 2 且都有明确获取路径 → 按"资产匹配度 × 路径确定性"选
│   └─ 有选项的标识存在性不可判定 → 走"向平台确认"分支（见下）
└─ 否 → 形态自选，但仍要问：作品能否被"未登录陌生人"打开？
```

**「形态标识不可判定」分支**（实战常见）：当规则要求发布到某个分类/类型，但该分类在页面上是 JS 渲染、无法确认存在时——

1. 输出**向平台确认的具体问题句**（可直接发问的完整句子，含活动名、你的作品、具体问点）；
2. 保守动作：按活动页当前说明处理，**不要仅凭公告推断适用**；
3. 在方案里标「待核」。

**不推荐形态的判据**（当主路径存在不确定性时）：若某形态的体验链接只能绕道第三方、且第三方约束未知——它的收益不抵它的不确定性。

### 步骤 6 · 排期：双轨倒排 + 阻塞决策点

**双时间轴**：

| 轴 | 内容 |
|---|---|
| **资格轨** | 报名 / 组队 / 预审 / 内测申请 / 资格审核 |
| **作品轨** | 开发 / 材料 / 提交 / 评审 / 答辩 |

**三张必填时点表**：
1. 报名轨关键时点表
2. 作品轨关键时点表
3. **两轨交汇约束表**——专门记反直觉顺序（如"组队截止早于报名截止"、"预审通过才可开发"、"报名后信息锁定"）

**外部依赖阻塞管理**（在选题之前执行）：

| 构件 | 内容 |
|---|---|
| **依赖登记表** | 每条外部依赖记：获取方式 / 是否可复核 / 延迟时长 / 失败模式 / 失败后果 / 兜底方案 |
| **阻塞决策点** | 如"申请后 T+24h 仍不可用 → 触发赛道切换决策" |
| **不可逆红线** | 切换前不得投入不可逆成本：公开发布、买域名、发社媒帖、报名不可退的赛道 |
| **一票否决前置检查** | 任何"只能选一个"的条款（赛道/工具/形态/账号）**必须在动手前确认**，否则整个方案是废的 |

> **真实案例**：某比赛的专属赛道需填问卷申请内测、24 小时后生效、且规则规定"一件作品仅可使用一个赛道指定工具、仅可报名一个赛道"——这意味着**如果内测权限拿不到，没有退路**，因为不能同时准备两条赛道。依赖必须排在选题上游。

**倒排表的纪律**：
- 每个时点必须有**理由 + 依据编号**；
- 不可逆动作（提交、撤回截止、形态锁定、核验日）单独列表；
- 审核在窗口后时，把**全部自检压到截止前最后一天之前**，不安排任何变更动作在截止当天。

> **为什么依赖必须排在选题上游？** 外部依赖是**资格**问题而不是**作品**问题。"只能选一个赛道"这类条款一旦触发，无法靠作品质量补救——它决定的是你有没有资格参赛。把依赖放到选题之后，等于先做完作品再发现赛道不能报；而把依赖前置，是让"换赛道"这个决策在成本最低的时刻发生。真实案例里 24 小时的内测审批延迟，如果发生在选题之后，整份方案直接作废。

---

### 步骤 7 · 合规自查：三层结构

**按判定载体分层，不是静态勾选清单。**

| 层 | 查什么 | 典型后果 |
|---|---|---|
| **L-A 产出物形态层** | 规则原文逐条抄下的排除项 | 不算有效作品 |
| **L-A′ 工具/技术绑定层** | 是否强制指定工具、是否要求"全程使用"、是否限制只能选一个赛道/工具 | 资格取消（样本 A 是一票否决式条款） |
| **L-B 生产过程层** | 人工实质性干预证明 / AI 使用声明表 / 过程记录 | 无效投稿 / 取消资格 |
| **L-C 同质化层** | 模板化、批量、搬运、资源复用 | 相似度驳回 / 取消资格 |

**L-A′ 单独成层的原因**：工具绑定是**资格**而非**评分**——它决定你有没有资格参赛，与作品做得多好无关。而且这类条款常是**一票否决式**的（A 样本：「每件作品仅可使用一个赛道指定工具完成，并仅可报名一个专属赛道」），踩中就没有第二选择。

⚠️ **L-A′ 必须在选题之前查**——因为它可能直接否掉某些选项，而选项被否掉后再改选题就晚了。

**每条自查项必须带三列**：`判定载体（功能/文案/截图/对话记录/链接/账号状态/发帖行为）` + `判定强度（硬阻断/软参考/概率）` + `后果（不算有效/取消资格/扣分）`。

**L-B 的「AI 使用声明四要素」**（当下最通用的一项，多个赛事通用）：

1. 使用的工具名与版本；
2. AI 参与了哪些环节；
3. **人工做了哪些修改与审核动作**；
4. 占比估算区间。

**L-C 同质化的实际判定尺度**（换字洗稿无效，判的是结构特征）：
- 代码：控制流图 / AST 语法树 / 语义指纹，不是文本相似度；
- 资源：图片/图标/占位图的**哈希值重复**——AI 生成的配套素材来自同一素材库，成千上万开发者复用同一套；
- 文案：标题/描述/关键词的固定句式；
- 检测：**代码 + 界面 + 文案三重维度**，两处及以上高度重合即加重标记。

**账号状态类**（易漏且后果严重）：虚拟手机号注册、活动期违规记录、账号主体与领奖主体不一致。

## 3. 输出物规格

一份参赛方案应包含（按此顺序）：

1. **判型结论** + 时点表（双轨）
2. **资产盘点**（实测值 + 量级表述建议）
3. **选题/对位表**（命题型或自选型，按分支）
4. **形态决策** + 理由 + 不可逆点标注
5. **材料清单**（按比赛形态分表）+ 依赖顺序图
6. **合规三层自查表**
7. **倒排表** + 不可逆动作清单
8. **阻塞决策点与兜底**
9. **待核清单**（规则不可确认项 + 保守默认动作）

---

## 4. 不可省略的三个「不要」

| 不要 | 原因 |
|---|---|
| **不要输出获奖概率、名次、评审口味** | 评审机制与分数分布几乎从不披露；两个样本的知识包都明确拒绝给这个 |
| **不要把推断写成规则** | 官方未给的评分口径、权重、判定标准，一律标「未给出」并登记为缺口 |
| **不要在规则未确认前做不可逆投入** | 规则不可得是常态，不是例外 |

## 5. 预检门（先出方案清单，确认后才执行）

本 skill 产出的是**方案**，不是直接提交作品。但方案的产出过程会连带产生外部副作用——写文件、建目录、发请求、发社媒帖。为避免"方案还没定稿，副作用已经发生"，全流程按**预检 → 确认 → 执行**三段推进：

| 阶段 | 动作 | 门禁 |
|---|---|---|
| **预检（dry-run）** | 只采集与判定，产出规则编号事实 + 缺口清单 + 判型结论 + 阻塞决策点 | 规则未确认前，**不写任何方案文件、不做任何对外动作** |
| **确认** | 向用户展示：判型结论、F/G 编号事实与缺口、依赖登记表、不可逆红线清单 | 用户确认后，才进入执行段 |
| **执行** | 产出正式参赛方案（按第 3 节 9 项规格） | 执行前再检查一次不可逆红线是否已解除 |

**预检阶段的硬约束**：

1. **只读**——本阶段只允许读取规则文本与既有材料，不允许创建/修改任何交付文件，不允许发出对外请求或发布动作；
2. **产出可审阅的中间物**——把判型结论与缺口清单先摆出来，让用户在写方案之前就能否掉错误方向；
3. **确认点写明范围**——确认时明确列出「本次授权产出的方案文件清单」，未列入的产物不生成；
4. **缺确认即停**——用户未确认时，停在预检段并报告"待确认"，不按默认假设继续往下做。

> **为什么？** 预检门解决的是"方向错误的返工成本"。方案写作本身可逆（改文字），但"按错误赛道做完再发现不能报"不可逆。把判型与缺口暴露放在方案写作之前，是把最贵的错误挪到最便宜的时刻。

## 6. 幂等与收尾验证

本 skill 会被反复调用（换比赛、换阶段、补材料），因此必须保证重复执行不会产生互相矛盾的产物。

**重复执行的判定**：

| 情形 | 判定 | 动作 |
|---|---|---|
| 目标方案文件**已存在** | 非首次执行 | 不新建同名文件；在既有文件上按编号增量更新，并保留既有编号不动 |
| 同一场比赛的 F/G 编号**已登记** | 同一事实 | 复用原编号，不新起编号；内容有变化则走勘误留痕（登记 E-xx），不静默改写 |
| 判型结论与既有方案**冲突** | 规则已变更或上次判错 | 停下并报告冲突，由用户裁决，不静默择一 |

**收尾验证**（每次执行完必须执行，逐项确认）：

- **方案文件已生成**：确认目标路径下文件存在，且章节编号连续、无重复小节；
- **编号引用可达**：方案中引用的 F/G/M/C/I/E 编号在事实底账中逐条可查，无悬空引用；
- **缺口已登记**：规则不可确认项全部落在 G 族，无"静默按推测填充"；
- **资源引用存在**：`references/` 中被方案引用的文件真实存在；
- **链接无断链**：方案内相对链接可解析；
- **无运行残留**：临时文件、缓存目录已清理，未残留半成品。

> **为什么？** 同一场比赛的参赛方案会被多轮修改，而规则本身也可能中途调整。若每次执行都重写整份文件，先前的勘误与人工批注会被无声覆盖；若编号体系漂移，同一条规则在不同版本里对不上号，评审材料的可信度会崩。所以"复用编号 + 增量更新 + 逐项收尾验证"不是洁癖，是让多轮执行能累积而不是互相抵消。

## 7. Gotchas（陷阱与反直觉行为）

1. **判型不是读完全部规则才能做**——形态只依赖时序信号（预审/生效延迟/晋级/锁定），出现信号即可判型；先判型再深读，比读完再判型更省力也更准。
2. **规则页能打开 ≠ 规则能读到**——两个真实样本的规则都不在明文 HTML 里。静态直读拿到的空壳页面会让整条采集阶梯误判为"已采集"。
3. **L3 逆向的坑在"剥标签"**——用 HTML 标签剥离只能拿到几十行噪声，正文在 JS 的字符串字面量或状态树文本节点里，必须从那里取。
4. **"官方没说"≠"我没查到"**——缺口单独成族（G 族），不与事实混排。这两者的区别决定了"缺信息"和"缺规则"两种完全不同的处理动作。
5. **传播分不一定加分**——一个样本把刷赞列为取消资格情形，另一个才把它作为独立计分项。默认按"站内弱参考"处理最安全；要按独立计分打，先确认该场的取消资格条款里没有刷赞/作弊字样。
6. **高权重维度未必最该投入**——高权重项往往边际收益递减，低权重项若是门槛型则不达标即归零。先归零型，后加权型。
7. **审核在窗口外 = 提交即定生死**——"审核通过才算有效投稿"且未公布时长时，必须按最坏情况处理：全部自检压到截止前最后一天之前，不在截止当天安排任何变更。
8. **同质化判的是结构特征不是文本相似度**——换字洗稿无效；代码看控制流与语义指纹，资源看哈希重复，文案看固定句式。
9. **对外材料里的绝对数字会漂移**——库会增删、作品会变，一律用量级表述。
10. **AI 声明表的四要素缺一不可**——工具与版本、参与环节、人工改动与审核动作、占比估算区间；缺项即可能被判无效投稿。
11. **形态标识不可判定时的正确动作是"问平台"**——输出可直接发问的完整问句 + 保守默认动作 + 标「待核」，不要仅凭公告推断适用。

## 8. 安全检查清单（逐项确认）

产出方案前逐项确认：

- [ ] 已完成判型，并写明判型依据的原文位置；已按最早收紧的那条轨排期
- [ ] 已确认规则原文与推断分离，推断处均标注「推断」，缺口均登记为 G 族

- [ ] 已确认传播/互动分项按分支处理，且该场取消资格条款中无刷赞/作弊字样
- [ ] 已确认合规自查覆盖 L-A / L-A′ / L-B / L-C 四层，且 L-A′ 已在选题前查过
