# 六组件详解：做法、反模式、迁移

> 本文件是 `howto-course-writing/SKILL.md` §3 的展开。每个组件给出：判据、做法、≥3 条反模式、跨领域迁移。
> 示例已做泛化处理，不绑定具体产品与课程。

## 1. 收获前置（Opening with Deliverables）

**判据**：读者读完第一屏，能说出"学完我会拿到哪三样东西"。

**做法**

1. 拆成 4 个动词组：认知（弄清楚）、安装（装上）、跑通（做成）、配置（接上）。
2. 每条改写成可观察结果：`了解 X` → `能说出 X 与 Y 的区别`；`掌握 X` → `能拿到 X 并填进 Y`。
3. 三例递进：权威案例（行业已发生）→ 可复现案例（同工具、真机、低成本）→ 同类案例（读者身份的愿望）。
4. 展示上限后补一句范围收束："本期只做其中一小块"。
5. 结尾作业只检查已承诺的收获项。

**反模式**

| 反模式 | 表现 | 后果 | 改法 |
|---|---|---|---|
| 原理开场 | 第一节讲"什么是大模型/行业趋势" | 读者在不知收益前被要求投入 | 原理后移到概念章 |
| 收获不可验收 | "了解/熟悉/掌握/体验" | 课后无法自查 | 换成"能说出/能拿到/能停在" |
| 只有成功案例 | 全是熟练者的成果 | 读者归因于天赋或设备 | 补一例"和你一样的人刚跑通" |
| 展示上限不收束 | 罗列 90 个技能、20 个定时任务就进入正文 | 读者预期被拉到"要学全部" | 紧跟"本期只取一小块" |

**迁移**：开源 README 的 Features 段按"能做什么/需要什么/怎么验证"重写；B 端上手文档把功能列表换成"上线后第一个工作日你会看到什么"。

## 2. 一步一验收（One Step, One Check）

**判据**：任意一步做完，读者能用一个外部现象判断"继续还是返工"。

**做法**

1. 操作章开头声明："共 N 步，每步有一个看得见的结果。"
2. 每步压到 2 条动作，动词 + 对象（装客户端、填两个参数）。
3. 每步一条 `✓`：写页面跳转、弹窗文案、字段一致，禁止写"应该成功了"。
4. 多链路分别自检：说话链路 / 动手链路 / 通知链路各一条测试。
5. 标出人工接管点，并给一句可复述的"继续"口令。

**反模式**

| 反模式 | 表现 | 后果 | 改法 |
|---|---|---|---|
| 模糊验收 | "如果一切正常，你应该能看到主界面" | 分不清正常与异常 | 写具体控件与文案 |
| 只写操作不写结果 | "点击设置，填入 Key，保存" | 保存失败也以为成功 | 每条动作后补"你会看到" |
| 验收集中到文末 | 前五步无检查 | 错在第 2 步，第 5 步才发现 | 每步就地验收 |
| 隐藏人工环节 | 不提验证码、实名、付款确认 | 读者把被拦当成装错 | 提前写"这一步必须你本人做" |

**迁移**：运维 SOP 每条命令附"预期输出特征"；CI 修复手册写"本地复现 → 单点解除 → 观察转绿"三个可截图状态；数据迁移 runbook 每步写行数/字段一致性断言。

## 3. 一喻到底（One Metaphor System）

**判据**：全篇只有一套比喻家族，且能画出"生活名—功能名—代码名"三列表。

**做法**

1. 先定最上位对仗：X 像 A，Y 像 B，差别落在一个可感知动作上。
2. 给零件配器官名（身体 / 家居 / 办公），优先选有肌肉记忆的。
3. 建三列对照表，逐行核对；对不上就换比喻，不要硬凑。
4. 图例显式声明映射（"小标签对应哪个零件"）。
5. 用比喻做范围收口（"其他房间先不用管"）。

**反模式**

| 反模式 | 表现 | 后果 | 改法 |
|---|---|---|---|
| 比喻换得太勤 | 第一段像公司，第三段像工厂 | 读者每段重建模型 | 全篇一个隐喻家族 |
| 只装饰不承载 | 开头一句"就像助理"，后文不用 | 比喻不承担结构 | 后文复用同一批名词 |
| 三层名词不对齐 | 文中"记忆"、图上"知识库"、代码 `store` | 读者接不起三段知识 | 三列表逐行核对 |
| 过度延伸 | 户型图讲到水电改造 | 比喻比被解释对象更复杂 | 只保留"房间在哪、干什么" |
| 用比喻替代定义 | 通篇只有"助手小队" | 读者无法与他人沟通 | 首次出现给一次正式定义 |

**迁移**：数据库入门用"仓库—货架—拣货单"；网络协议用"邮局—信封—挂号信"；财务课用"水池—进水口—出水口—水位线"。三列同表，中途不换。

## 4. 三图配置（Three Diagram Types）

**判据**：每块图能用一个问句概括它回答的问题，且三类不混用。

| 类型 | 回答 | 关键元素 |
|---|---|---|
| 地图图 | 一共几步、我在哪 | 分阶段两列 + 编号 + 底部带走句 |
| 解剖图 | 有哪些零件、谁归谁管 | 中心/三列/空间隐喻三选一 + 范围标签 |
| 操作图 | 这一屏点哪里、看到什么 | 同构卡片（2 动作 + 1 ✓）或三格实拍 |

**反模式**：一图多问；写完正文再配图；编号与正文不同号；颜色语义不固定；不标"本期不做"；卡片文字过密。

**迁移**：产品架构图用三列（客户端/服务端/第三方）+ 右下角一个成本或延迟数字；课程大纲用地图图；故障复盘用解剖图并把失败节点涂红。

## 5. 行动块（Action Block）

**判据**：读者不需要组织语言，复制就能执行。

**五槽结构**

| 槽位 | 作用 | 例 |
|---|---|---|
| 情境/输入 | 指定该看什么 | "请阅读项目的 README 与目录结构" |
| 输出受众 | 约束语言难度 | "用不懂代码的人也能听懂的话" |
| 任务清单 | 拆成 2-3 个可回答问题 | 编号问题 1/2/3 |
| 预期用途 | 让答案服务下一步动作 | "如果以后想改某个习惯，通常改哪里" |
| 安全句 | 限定权限 | "先只讲解，不要修改任何文件" |

**三类安全句**（缺一不可的场景各不相同）：只读（挡 AI 改文件）、由我确认（挡代付/代签）、不含凭据（挡自己泄露 Key）。

**反模式**：把提示词写成散文；一次给多个目标；缺安全句；示例含真实凭据；只给任务不给验收。

**迁移**：给 AI 派活写成"读哪个文件 + 按什么结构输出 + 不要改原文"；研发工单复用四要素（目标/约束/验收位置/交付物）；客服话术写成"情境 + 可复制回复 + 禁用词"。

## 6. 边界前置（Boundaries First）

**判据**：读者遇到"做不到"时，第一反应是"换个做法"，不是"我太笨"。

**做法**

1. 列出所有读者可能做不到的条件（设备/账号/网络/权限/预算），逐条写限制 + 原因 + 降级路径。
2. 人机红线表：不可逆 / 涉资金 / 涉身份 / 涉凭据，一律写明由人做并给理由。
3. 数字三件套：上限、有效期、以什么为准。
4. FAQ 按来源分三张表：通用使用 / 本产品特有资源 / 卡住了怎么求助。
5. 用真实反馈回归覆盖度：评论区、工单里的卡点逐条对到文档条目。

**反模式**

| 反模式 | 表现 | 后果 | 改法 |
|---|---|---|---|
| 限制放文末 | 全篇讲成功，末尾一段常见问题 | 读者在第二章就退出 | 写在首次出现该操作的段落旁 |
| 只说不支持 | "iOS 用户请略过本节" | 读者直接离开 | 限制 + 原因 + 降级路径捆绑 |
| 用"有问题请联系"兜底 | FAQ 最后一行是联系方式 | 读者仍需自己描述问题 | 给可复制的求助提示词 |
| 承诺式表述 | "保证一次成功" | 一次失败失去全部信任 | 改"大多数情况下""以账单为准" |

**迁移**：开源 README 把 Requirements 改成"支持/不支持/不支持时怎么办"三行；SaaS 计费每个价格旁标额度、周期、超出行为；内部系统公告先写"哪些岗位暂时用不了、替代流程是什么"。

## 组合关系

六个组件是一条流水线，不是六张清单：

```text
收获前置（承诺） → 一步一验收（交付） → 一喻到底（理解） → 三图配置（骨架）
                → 行动块（执行） → 边界前置（兜住放弃）
```

承诺与验收必须闭环：结尾作业检查的，只能是开头承诺过的。其余组件都服务于这两端。
