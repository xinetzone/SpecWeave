# 投影面清单：增量拓展要改哪些索引

> 配套 [SKILL.md](../SKILL.md) §5 第 1 步与 §6。动笔前逐项标「需改 / 无需改」，无空项才算完成。

## 一、九个投影面

| # | 投影面 | 判定问题 | 何时需改 |
|---|---|---|---|
| 1 | 最近一级目录 `{toctree}` | 新文档的文件名在条目集合里吗？ | **总是需改**（新增内容文档时） |
| 2 | 同目录 `index.md` 导航表 | 表格行数与目录实际内容文档数一致吗？ | 目录有导航表时 |
| 3 | 同目录 `index.md` 阅读顺序 / 使用边界 | 新增文档改变了阅读路径或符号口径吗？ | 有顺序说明、边界声明时 |
| 4 | 上级分组 / 域索引的「文件数」 | 该束登记的 `.md` 数还准确吗？ | 分组索引带文件数列时 |
| 5 | 上位概念文档互链 | 新文档是某个概念的下沉实现吗？ | 存在概念—算例对应关系时 |
| 6 | bundle 根 `index.md` 的 description / 工具数表格 / 阅读地图 | 根索引里的数量与步骤提到新文档了吗？ | 根索引有投影字段时 |
| 7 | 域索引 / 分组索引的束数 | **本次是否新增或迁移了整个 bundle？** | 仅在新建 / 迁移 bundle 时 |
| 8 | 总索引 `total_bundles` / 计数行 / 节标题 / 分组表 / toctree | 同上，五面是否都要动？ | 仅在新建 / 迁移 bundle 时 |
| 9 | 仓库 README badge / 首页规模数字 | 规模数字是否因新增 bundle 变化？ | 仅在新建 / 迁移 bundle 时 |

> **为什么把 7/8/9 单列并标「仅在新建 bundle 时」？** 最常见的误操作不是漏改，而是多改：在既有 bundle 内加一篇文档，文件数从 17 变 18，但 bundle 总数、域束数、分组束数都不变。此时去动共享总索引，会直接制造计数漂移，还可能覆盖并行会话刚写入的内容。

## 二、接线完成判据（缺一即视为未入库）

1. 新内容文档出现在最近一级 `{toctree}` 的条目集合中；
2. 导航门输出「所有内容文档均可达」且精确退出码 0；
3. 目录 `index.md` 表格行数 = 目录实际内容文档数；
4. 上级索引中本束「文件数」= 本束实际 `.md` 数；
5. 未新增 bundle 时，`total_bundles`、域束数、分组束数保持不动；
6. 所有相对链接无断链，frontmatter 路径字段有效；
7. 根索引的 description / 数量表格 / 阅读地图与实际一致。

## 三、真实案例：04 补篇的接线闭环

来源：[里程碑复盘报告](../../../../docs/retrospective/reports/knowledge-content/retrospective-okf-bundle-atomic-extension-20261106.md) F-23~F-27。

一份内容完整、frontmatter 齐备、上位互链已加的进阶算例文档落盘后，仍不是「入库」，因为面 1 未登记。实际收口动作覆盖了 7 个面：

| 面 | 实际改动 |
|---|---|
| 1 | `examples/index.md` toctree 新增 `04-judgement-as-parameter` |
| 2 | 导航表从「三篇」改「四篇」并新增一行 |
| 3 | 阅读顺序补「差异化何时改写方向」；使用边界补符号非实测与三条参数化路径互不代入 |
| 4 | `industry/index.md` 本束文件数 `17 → 18` |
| 5 | `concepts/02` 与 `concepts/03` 各补一条互链；`examples/03` 补续篇提示 |
| 6 | 根 `index.md` 工具数表格 `3 → 4`、阅读地图第 5 步补新文档 |
| 7/8/9 | **刻意不动**：bundle 数不变，且共享索引正被并行会话占用 |

收口后导航门退出码 0，计数门输出「9 域 / 64 组 / 718 束」退出码 0，编码门 12963 文件退出码 0。

> **为什么面 7/8/9「刻意不动」也算完成？** 判据是「每个面都有明确判定」，不是「每个面都改」。把「无需改」写清楚，才能避免下一个会话看到未动的共享索引时误以为漏接线又去改一遍。

## 四、编号歧义的处理

当同一知识包内既有 `concepts/03` 又有 `examples/03` 时，文档正文里的「03 篇」会产生混引。收口动作之一是在新文档首段加**编号约定**：明确「03 进阶算例」与「concepts/03 第一性原理篇」各自指代，并把含混表述替换为带路径前缀的写法。

> **为什么编号歧义要算接线问题？** 它不产生断链，机械门抓不到，但会让读者把不同参数化路径的数值互相代入。这类错误只能靠投影清单里「使用边界」这一面在人工侧拦住。
