# 古典底本节日祝福视频生成 Skill

以古典文献为底本，为**特定对象**生成「有文化分量、情感分寸精确」的节日祝福短视频：三张 AI 关键帧 → 10 秒竖版视频 → 随片文案 + 考据弹药。

## 1. 何时触发

- 用户要求为具体的人制作节日祝福视频/动图（中秋、春节、元宵、端午、生日等）
- 关键词：「祝福视频」「节日贺卡视频」「给 TA 做个视频」「用老子/庄子/诗词做底本」
- 用户指定了古典文献底本（道德经、庄子、诗经、宋词等）或共同文化线索（同乡、同校、共同读过的书）

不适用于：群发商业贺卡、无特定收信人的通用节日海报（直接单图生成即可，无需本流程）。

> **为什么必须锁定"特定对象"？** 本Skill的全部价值在情感分寸——没有收信人就没有关系阶段，分寸矩阵失效，流程退化为普通视频生成。

## 2. 启动前必收的四个参数

信息不全时先用一次 AskUserQuestion 问清，不要凭猜测定调：

| 参数 | 说明 | 示例 |
|---|---|---|
| `occasion` 节日 | 决定节日天体/意象 | 中秋=满月+露+桂；春节=梅+雪+灯；元宵=灯+月；端午=艾+水 |
| `relation_stage` 关系阶段 | 决定情感重量（见 §3 分寸矩阵） | 初识未谋面 / 互有好感 / 恋人 / 长辈 / 挚友 |
| `shared_clue` 共同线索 | 文案与结尾地标的桥接点 | 同乡（县城+历史名人）、同校、共同爱好 |
| `source_text` 底本偏好 | 文献来源；用户未指定时按节日与调性推荐 | 帛书老子、庄子、诗经、宋词 |

私域任务（给具体个人的情感祝福）一律落 `playground/<occasion>-greeting/`，不入 `docs/`、不入 `.trae/specs/`。

## 3. 方法论链路：轻量 F→V→I（七概念）

不必走全链路，按序完成三步，每步有硬门禁：

1. **F 第一性原理——立意**：先回答「这段关系此刻送祝福的本质约束是什么？」（如极早期关系 = 高用心 + 零压力），由约束反推美学基调（克制的"淡"往往比重词更有力）。
2. **V 对抗审查——证伪**，至少过三关：
   - **分寸关**：对照 §3.1 矩阵，逐句检查有无越阶词、有无索取回应的压力（"等你回复""一定要"）。
   - **考据关**：引文必须核实原字原篇；出土文献（帛书/楚简/汉简）与通行本异文要查清，文案可用通行读法，但在"考据弹药"中向用户交代原字。
   - **画面关**：AI 视频生成汉字必然崩坏——画面中**禁止出现任何可辨文字**，帛书/卷轴只呈现墨迹肌理；文案随片另发。
3. **I 洞察落地——成片方案**：文案 + 三幕分镜（§5）+ 生成指令（§6）。

> **为什么画面禁止出现汉字？** AI 生成模型对汉字的结构先验极弱，必糊成乱码，乱码画面比没有文字更伤质感；文字是信息层，应走消息通道随片另发，两者分离后各得其所。

### 3.1 情感分寸矩阵（硬约束）

| 关系阶段 | 措辞重量 | 允许 | 禁忌 |
|---|---|---|---|
| 初识未谋面 | 最轻 | 节候问候、文献转译、共同线索、留白钩子 | 表白、"想念/喜欢"、邀约见面、索取回应、感叹号堆砌 |
| 互有好感 | 轻+ | 以上 + 含蓄"期待" | 直白表白、逼问态度 |
| 恋人 | 重 | 思念、专属称呼、未来约定 | 掉书袋压过真情 |
| 长辈 | 敬 | 安康、顺遂、康健 | 情爱意象、网络流行语 |
| 挚友 | 松弛 | 调侃、共同回忆 | 过度端着文言 |

通用原则：**祝福的重量 ≤ 关系的实际深度**。宁可轻一寸，不可重一两。

> **为什么宁可轻一寸？** 越阶施压是不可逆的社交损伤（对方会感到被冒犯或被迫回应），而分量不足只是遗憾，可留待下个节日补足——两种错误的代价不对称。

## 4. 底本选择与本地资料优先

在 SpecWeave 工作区优先检索本地资料库再引经据典：

- 帛书老子及历代注本：`playground/books/帛书版道德经资料/`
- 庄子资料：`playground/books/庄子资料/`
- 最高可信度知识包（只读）：`projects/awesome-okf-xs/doc/bundles/`

选句标准：① 意象与节日物候同构（如中秋配"甘露"/"水"/"月"）；② 句子脱离哲学语境仍是美好祝愿；③ 避开被用滥的段子句。优先选可"生活化转译"的句子——引文后必须用一句白话讲明白，禁止裸掉书袋。

## 5. 三幕分镜模板（参数化）

10 秒一镜到底，三张关键帧即时间轴，意象随节日替换：

| 幕 | 时长 | 功能 | 画面骨架 | 中秋实例 |
|---|---|---|---|---|
| 起 | 0–3s | 底本登场 | 夜色器物特写：卷/册/笺徐徐展开，只见抽象墨迹肌理，暖灯+窗格 | 月下花窗，素帛展开，铜灯摇曳 |
| 承 | 3–6.5s | 生灵接引 | 一只贯穿全片的小生灵（蝶/鸟/萤/花瓣）触及水/光，节日天体在水中倒影荡开涟漪 | 白蝶翼尖点水，水中满月涟漪，秋荻薄雾 |
| 合 | 6.5–10s | 共同线索收束 | 镜头随生灵升高，共同地标的古风剪影 + 节日天体悬天，生灵飞向天体 | 北宋密檐塔剪影，蝶入满月，草露微光 |

贯穿主体全片**只能有一只**（一只蝶/一叶/一瓣），多主体是 AI 视频崩坏的首要原因。地选取 `shared_clue` 中真实存在的古建筑，形制须与朝代吻合（不确定时只描述"密檐古塔/古建飞檐剪影"等泛型，不写具体塔名进 prompt）。

## 6. 生成执行（工具参数已实测）

**步骤 A：三张关键帧并行生成（GenerateImage，一次调用发三个请求）**

- 尺寸：竖版 `1440x2560`（9:16 自定义像素，符合工具像素区间）
- 风格锚点每张必带：`中式工笔写实电影感、暖灰纸感色调、暖金光+靛青夜、低对比度、无纯黑、无人物`（视觉纪律：用户反感纯黑/高对比深色）
- 负向约束每张必带：`绝不能出现任何文字、汉字、字符、牌匾字、印章、水印或 logo`
- 文件名：`kf1-<起>.jpg`、`kf2-<承>.jpg`、`kf3-<合>.jpg`

**步骤 A′：预览确认门（dry-run 等价物，必做）**

三张关键帧生成后**先交用户目检确认**（无乱码文字 / 主体唯一 / 风格锚点达标），确认通过再进入步骤 B；未通过只重生成关键帧，不消耗视频生成。文案稿同理——先出稿确认，再决定随片发送的版本。

**步骤 B：图生视频（GenerateVideo，单次）**

- 参数：`duration=10`、`ratio="9:16"`、`resolution="720p"`
- `image_paths` 按起→承→合顺序传入三张帧，prompt 中明确写「严格以三张参考图作为时间轴关键帧，按顺序自然演变，不要跳切」，并逐镜复述画面与时长
- 运镜词：`匀速舒缓连贯、无人物、无硬切、一镜到底`
- 输出：`<occasion>-blessing.mp4`

**步骤 C：物理量验收（必做，防止失实交付）**

```powershell
Get-ChildItem "playground/<occasion>-greeting" | Select Name, @{N='SizeMB';E={[math]::Round($_.Length/1MB,2)}}
```

确认 3 图 + 1 mp4 均存在且 mp4 体积合理（10s 720p 通常数 MB 级；为 0 或异常小即失败需重生成）。交付前人工目检关键帧：无乱码文字、主体唯一、地标形制无硬伤。

> **为什么必须核对物理大小而非只看文件存在？** 本执行环境中"存在性检查"会被假象骗过（生成失败也可能落一个 0 字节/极小文件），体积与目检是独立于流程的物理量验收，能拦截"流程走完但成片不可用"的失实交付。

## 7. 随片文案结构（随消息另发，不烧进视频）

四段式，总长 120–180 字：

1. **一句轻问候**（"中秋安康。"）
2. **引文 + 白话转译**（"老子讲……——好的相逢像……"）
3. **共同线索桥接**（同乡/同校 + 文献中相邻的一句轻典故）
4. **轻祝愿 + 留白**（不邀约、不索要回应；钩子藏在祝愿里）

另出一版 50 字内短版供用户二选一。文末附**考据弹药**小节（不给收信人，给用户备用）：出土本与通行本异文、引文出处篇名、地标朝代形制；并可给一句"对方回应后如何自然接话"的后续建议。

## 8. 交付清单（安全检查清单）

- [ ] 四个参数已确认（`occasion` / `relation_stage` / `shared_clue` / `source_text`），无猜测定调
- [ ] 文案逐句过 §3.1 分寸矩阵（无越阶词、无回应索取）
- [ ] 引文已核实原字原篇，异文在"考据弹药"中交代
- [ ] 关键帧与视频 prompt 均含禁字约束与唯一主体约束
- [ ] 步骤 C 物理量验收通过（3 图 + 1 mp4 体积正常），关键帧已目检
- [ ] 产出落 `playground/<occasion>-greeting/`（私域，不入库）
- [ ] 交付物：成片链接、主推文案 + 短版文案、考据弹药、后续接话建议

## 9. 反模式（G2/G3 教训固化）

- ❌ 让 AI 在画面上写"中秋快乐"等汉字 → 必糊成乱码；文字一律随消息发
- ❌ 多只蝴蝶/多人物群像 → 主体崩坏；全片一只生灵
- ❌ 引文不核实版本，帛书用字凭印象 → 考据翻车比没有引文更糟
- ❌ 关系刚认识就写"千里共婵娟"式重句 → 越阶施压
- ❌ 只凭 `Test-Path` 判完成 → 必须核对文件物理大小并目检
- ❌ prompt 写具体塔名/建筑名 → AI 会臆造形制；用泛型描述，靠共同线索在文案中点名

## 10. Gotchas（隐性陷阱）

- **关键帧分三次调用生成 → 风格漂移**：三张帧必须**同一次调用**并行发出，风格锚点才共享同一上下文；分次调用会各自漂移，成片画面跳变。
- **`playground/` 不入库 → 跨机器/跨会话产物不可达**：本地路径只是过程证据，交付必须附对话内可访问的成片链接，否则用户换机后拿不到视频。
- **三种"成功"假象**：工具返回成功 ≠ 成片可用；文件存在 ≠ 内容完整（可能是 0 字节/极小文件）；流程走完 ≠ 交付达标——只有体积核对 + 目检属物理量验收。
- **`paths` 与模板路径分离**：本 Skill 无脚本依赖，`paths` 仅指向自身目录；资料库路径（`playground/books/` 等）属运行期数据源，随环境变化，不写入 frontmatter。
