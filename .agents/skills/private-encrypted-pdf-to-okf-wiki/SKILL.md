# Private-Encrypted-PDF-to-OKF-Wiki 加密私域 PDF 转知识包

> ⚠️ **本Skill是工作流门面（L1索引层）**，遵循[渐进式披露三层架构](../../capabilities/ARCHITECTURE.md)：
> - L0：[.agents/ONBOARDING.md](../../ONBOARDING.md)（入口速查）
> - L1：本文件（触发词 + 七工序 + 质量门 + 安全清单）
> - L2：[里程碑复盘报告](../../../docs/retrospective/reports/knowledge-content/retrospective-private-encrypted-pdf-okf-wiki-20261026.md)（本次萃取来源：20 文件交付的实测台账、4 条洞察、4 条模式与对抗审查记录）

## 1. Skill ID
`private-encrypted-pdf-to-okf-wiki`（对外名称：**加密私域 PDF 转 OKF 知识包工作流**）

## 2. 功能描述

把用户提供的加密私域材料转化为可审计的 OKF v0.2 知识包，七工序：

| 工序 | 名称 | 关键动作 |
|------|------|---------|
| S0 | 凭据隔离 | 密码只存在于进程内存；判定内容敏感度并锁定产出目录 |
| S1 | 解密与文本层判定 | 解密后抽查文本层质量，**据此决定本技能或姊妹技能** |
| S2 | 结构决策 | 写 `route` / `ocr_layer_policy` 字段；少页材料按概念维度而非物理页拆分 |
| S3 | 主张分层 | 五类：可核验事实 / 讲师经验值 / 不可核验绝对化 / 待核验 / 法律红线 |
| S4 | 原创改写与数学反解 | 重构论证链；把营销数字还原为其隐含假设（本技能的核心增值点） |
| S5 | 口径先行计数与声明契约化 | **先跑脚本再写数字**；口径、排除项、指标名三者写清 |
| S6 | V 审查与机械对账 | 四视角对抗审查 + 逐条回验声明与实测一致 |

### 与姊妹技能的分工

| 源材料形态 | 走哪个技能 | 判定依据 |
|---|---|---|
| 加密 PDF，文本层干净无 OCR 噪声 | **本技能** | 解密后可直读文本层，`ocr_layer_policy: text-layer-trusted` |
| 加密 PDF，内嵌文本层错字密集 | 转 `scanned-book-to-okf-wiki` | 文本层不可信，须图像为准 + OCR 仅定位 |
| 无密码的扫描版（纯图像 / 噪声 OCR） | 转 `scanned-book-to-okf-wiki` | 不存在凭据处置环节 |
| 公开网页 / 公众号文章 | 转 `blog-article-to-okf-wiki` | 不存在文件解密与文本层判定 |

> **为什么先判文本层再选技能？** 加密与否决定的是"怎么拿到文本"，文本层可信与否决定的是"拿到的东西能不能用"。把两件事混为一谈，常见后果是：因为文件加密就默认走 OCR 重路线（浪费时间且引入识别错误），或因为文件能解密就默认文本层可信（把噪声 OCR 当原文，事实污染进入知识包）。两个判定必须分开做。

## 3. 何时使用本技能

满足以下**全部**条件时使用：

- 源材料为加密 PDF，访问需用户提供的密码或口令
- 材料性质为课程讲义、内部培训、付费报告、内部会议纪要等私域内容
- 目标产出为知识包 / Wiki / 教程 / 结构化学习材料，而非全文存档

> **不适用**：需要逐字转录存档（须用户显式确认并说明理由）；公开无版权风险材料（直接走常规流程）；纯图像扫描版（走姊妹技能）。

## 4. 核心步骤

### S0 凭据隔离与敏感度预判

1. 按 [content-sensitivity-precheck](../../rules/content-sensitivity-precheck.md) 判定：含访问密码的培训材料**默认私域**——产出入 `playground/` 或用户指定目录，跳过 `.trae/specs/`
2. 密码只用于当次解密调用。落盘前检查四个泄漏载体：脚本文件、命令行历史、报告正文、日志输出
3. 源 PDF 不复制进产出目录

> **为什么凭据要单独作为一个工序？** 凭据泄漏不会让任务失败——它让任务"成功"地留下一个永久后门。含密码的脚本一旦落盘并进入版本控制，密码就与交付物同寿命。把凭据处置列为 S0 的第一步，是因为它是唯一一类"出错时没有任何即时反馈"的风险。

### S1 解密与文本层可信度判定

1. 用 `pypdf` 解密（`reader.decrypt(pwd)` 返回非 0 表示成功），逐页 `extract_text()`
2. 抽样判定文本层：连续中文是否成词、有无系统性错字、有无串行/缺字
3. 可信 → 本技能继续，写入 `ocr_layer_policy: text-layer-trusted`
4. 不可信 → 停止本技能，移交 `scanned-book-to-okf-wiki`（不可在本技能内"降格处理"）

### S2 结构决策

1. `index.md` frontmatter 写入 `route: chaptered-summary`、`route_decided_at`（禁止事后补记）
2. 少页材料（如 4 页讲义）**按概念维度组织**，不按物理页组织：一页一个文件会得到 4 个空壳文档
3. 标准分层：`concepts/`（核心概念，含 `index.md`）、`examples/`（可填写表格、自测题）、`references/`（源规格与外部锚点）、`audit/`（主张审计与对账台账）、根级 `facts.md` / `insights.md` / `patterns.md` / `log.md`

> **为什么少页材料不能按页拆分？** 拆分单元的选择决定了文档的语义密度。4 页讲义里通常有 6–8 个独立概念、跨页交织，按页拆会把一个完整论证切成互不承接的片段，读者必须自己重组。按概念拆则每个文件自洽。

### S3 主张分层

对每条内容标注类型，五类互斥：

| 类型 | 处理方式 |
|------|---------|
| 【事实】 | 可外部核验，标注信源 |
| 【经验值】 | 讲师个人经验，标注"经验值，非普适规律" |
| 【主张】 | 观点或预测，标注"讲师主张" |
| 【待核验】 | 有具体数字但无法定位来源，单列清单 |
| 【红线】 | 触碰法律边界，标注条款依据而非删除 |

### S4 原创改写与数学反解

1. 重构"论点→论据→结论"，禁止金句摘抄集；通过"换个说法"测试（无连续 ≥30 字原文复现）
2. **数学反解**：对材料中的营销数字，解出其隐含假设。示例：若材料称"达到 X 倍月支出即可自由"，反解出所需年化收益 `r = 12 / X`，再给出 `X ∈ {100, 150, 200, 300}` 四档对照与回撤压力测试

> **为什么数学反解是本技能的核心增值点？** 私域培训材料的说服力来自"具体数字"，而数字的可信度取决于未言明的假设。反解不改变原意，只把隐含条件显式化——读者因此获得判断力而非结论。这是"学习材料"与"宣传材料摘录"的分界线。

### S5 口径先行计数与声明契约化

1. **先用固化脚本取证**：`python .agents/scripts/audit-wiki-count-declarations.py --wiki <交付目录> --source-pdf <源PDF>`（口令走环境变量 `WIKI_SOURCE_PASSWORD`），对真实文件跑出数字，再回填声明
2. 声明中每个计数必须同时给出：**指标名 + 阈值 + 归一化规则 + 排除项**
3. 不同指标分开表述：`引号内引用最长 N 字` 与 `全文最长公共子串 M 字` 是两个数，不可合并为"最长 N 字"
4. 三段式契约：可度量标准 + 溯源方式 + 使用边界

> **为什么计数必须脚本先行？** 计数类声明是口径函数，不是客观量。同一批产物，"逐字比对且 ≥8 字"得一种结果，"归一化去标点后 ≥8 字"得另一种，差异可达 27%。写作时数的对象是记忆中的引用，不是文件里的引用——先写声明再找证据，等于让结论去挑选事实。

### S6 V 审查与机械对账

1. 四视角对抗审查：魔鬼代言人 / 新人 / 老板 / 未来
2. 逐条回验：声明中的每个数字在脚本输出中有对应行
3. 全文最长公共子串必须 < 30 字（版权红线）
4. 对产出目录跑 `python .agents/scripts/check-links.py --path <交付目录>`
5. 中间产物（文本抽取文件、临时解密产物）用后删除；取证脚本为仓库固化资产，不删除
6. 幂等重入：同一交付目录已有内容时，先枚举既有文件与编号台账，按编号比对后跳过已存在项或增量追加新编号，不整包覆写

## 5. 质量门

- **G1**：`route` 与 `ocr_layer_policy` 在写正文前已落 frontmatter，且决策时间戳可审计
- **G2**：概念文档为论证链重构，非金句汇编；每个概念文件可独立阅读
- **G3**：全文无连续 ≥30 字原文复现；直接引用 ≤30 字并标物理页码
- **G4**：声明中的每个数字均可由附录命令复现；指标名、阈值、归一化规则、排除项四要素齐全

## 6. Gotchas（陷阱与反直觉行为）

1. **凭据泄漏的四个载体**：脚本文件硬编码密码、命令历史、报告正文引用"密码是 xxx"、错误日志回显。四者中只有第一个会被代码审查发现，其余三个靠流程堵。
2. **按物理页拆分少页材料**：4 页讲义拆成 4 个文件，每个文件只有 1/4 个论证，读者无法独立理解任一篇。
3. **计数口径未定义**：写入"共 11 条引用"而不写归一化规则，下次复验得 14 条，声明与实测同时"正确"却无法对齐。
4. **指标混用**："最长 23 字"可能指公共子串，"最长 22 字"是引号内引用——两个都真，合并成一句话就都假。
5. **重复编号**：`facts.md` 的"待核验清单"复述已有编号，导致表格行 50 行而唯一编号 45 个。机械计数必须同时报 `rows` 与 `unique`。
6. **免责声明替代边界标注**：给高危主张加一句"仅供参考"不构成处置；必须按法律性质分类并标注每类的边界依据。
7. **中间产物未清理**：解密后的纯文本抽取文件落在 `.temp/` 但忘记删除，等于把私域原文副本永久留在工作区。
8. **按记忆计算相对路径**：以"文件应该在 bundle 根"的心智模型写 `../`，实际文件在子目录，同类错误会在正文链接与 frontmatter 路径字段各出现一次。写完立即跑链接检查，不留给收尾。

## 7. 安全检查清单

- [ ] 密码未出现在任何落盘文件中（脚本 / 报告 / 日志 / 命令历史）
- [ ] 源 PDF 未被复制进产出目录
- [ ] 产出目录符合私域分流（`playground/` 或用户指定），未创建 `.trae/specs/` 规划文件
- [ ] 中间产物已删除（文本抽取文件、临时解密产物）
- [ ] 全文最长公共子串 < 30 字，且已由脚本实测而非目测
- [ ] 每个计数声明都能追溯到一次具体脚本输出，含指标名与归一化规则
- [ ] 法律红线类主张已标注条款依据，且产出含"不构成专业建议"边界声明
- [ ] `check-links.py --path <交付目录>` 通过，0 断链
- [ ] 幂等重入已验证：重复执行不会覆写既有编号或重复追加（编号台账比对后跳过或增量）
