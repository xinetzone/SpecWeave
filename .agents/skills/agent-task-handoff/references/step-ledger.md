# 三段任务卡与步数台账

> 用于图形界面多步任务（手机 App、浏览器自动化、桌面 Agent）：把成本当作任务设计的因变量。

## 一、步数估算口径

| 动作 | 计步 |
|---|---|
| 一次搜索 / 一次输入关键词 | 1 步 |
| 一次筛选 / 一次排序 | 1 步 |
| 进入一次详情页 | 1 步 |
| 一次表单填写 | 1 步 |
| 一次返回 / 翻页 | 1 步 |

估算目的不是精确预测，而是**识别哪一段占步数最多**。

## 二、三段任务卡

| 段 | 目标 | 完成标志 | 典型步数占比 | 失败后的动作 |
|---|---|---|---|---|
| 侦察 | 摸清候选范围与筛选条件 | 候选清单（名称/关键属性/价格） | 高 | 只重跑本段，不改停点 |
| 选定 | 在候选中确定目标 | 一个明确目标 + 依据 | 低 | 收紧条件后重跑侦察 |
| 决策 | 执行不可逆或有副作用的动作 | 到达停点或人工确认 | 低但代价高 | 停下，交回人工 |

分段的价值：把探索成本与不可逆成本分开，任一段失败只重跑该段。

## 三、步数台账模板

| 日期 | 任务类型 | 段 | 步数 | 重试次数 | 费用 | 验收结果 | 备注 |
|---|---|---|---|---|---|---|---|
|  |  | 侦察/选定/决策 |  |  |  | 通过/不通过 | 贵在哪一段 |

规则：

- 无账单时用步数作代理指标（费用 ≈ 步数 × 单步成本），并在备注注明「代理口径」。
- 失败重试的累计费用必须合并记录，不能只记成功那一次。
- 第二次执行同类任务时与基线比较；步数下降但验收项减少，不算优化成功。

## 四、停点前移对照

| 当前停点 | 可前移到 | 代价变化 |
|---|---|---|
| 结算页确认前 | 商品详情页 | 少 1–2 步，且完全避开下单链路 |
| 商品详情页 | 搜索结果列表页 | 少 N 步，但需要列表页已含验收字段 |
| 全文读取后总结 | 摘要/目录页判断相关性 | 少 N 步，适合大批量筛选 |

前移的前提是：**停点位置仍能满足全部回报项**。回报项不够时，先加字段再前移，不要用「少看一页」换「验收变松」。
