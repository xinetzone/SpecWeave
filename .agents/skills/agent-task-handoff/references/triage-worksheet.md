# 分链排障工作表

> 复制本表填写，一次故障一份。目标是先归链，再在链内查，最后做交叉回归。

## 一、前置：两条最小指令

| 链路 | 要求 | 本次选用 | 观察结果 |
|---|---|---|---|
| 理解链 | 只触发理解，不产生外部动作 | 如「介绍一下你自己」「复述这条要求」 | 通过 / 不通过 |
| 执行链 | 只触发执行，不依赖复杂推理 | 如「打开固定页面」「写一个固定文件」 | 通过 / 不通过 + 外部状态证据 |

若两类指令找不到（执行结果就是下一次理解的唯一输入），本工作表不适用，改用逐部件替换法。

## 二、分支判定

| 观察组合 | 分支 | 归属 |
|---|---|---|
| 理解通过 / 执行未改变外部状态 | 只理解不执行 | 执行链 |
| 理解不通过 / 外部有异常动作 | 只执行不理解 | 理解链或意图解析 |
| 两者都不通过 | 两条都不通 | 共同前置（凭据/网络/运行时） |
| 执行开始后中途停住 | 执行中途停 | 权限、确认闸门、单步失败 |

## 三、分支固定检查项

| 分支 | 检查项 1 | 检查项 2 | 检查项 3 |
|---|---|---|---|
| 只理解不执行 | 执行侧模型/执行器是否配置 | 输入模态是否被支持 | 执行所需权限是否被关闭 |
| 只执行不理解 | 意图路由是否指向错误技能 | 上下文/记忆是否污染 | 提示词或工具描述是否过期 |
| 两条都不通 | 凭据与配额 | 网络与端点 | 运行时版本与依赖 |
| 执行中途停 | 是否等待人工确认 | 单步超时/重试上限 | 中途错误是否被静默吞掉 |

## 四、单点改动记录

| 项 | 内容 |
|---|---|
| 本次改动 | 只写一项：<配置/文件/开关> |
| 改动依据 | 对应上表哪一分支的哪一个检查项 |
| 复测指令 | 与判定时相同的那条最小指令 |
| 复测结果 | 通过 / 不通过 |

同时改三项会导致「恢复了也不知道哪项起作用」，下次同类故障仍要重新试错。

## 五、交叉回归

| 链路 | 修复前 | 修复后 | 结论 |
|---|---|---|---|
| 原故障链 |  |  | 已修复 / 未修复 |
| 另一条链 | 通过 |  | 未回归 / 已回归（需回退） |

只复跑故障那条链，是最常见的遗漏——修执行链时改了模型配置，往往会把理解链弄坏。

## 六、结论模板

```text
本次坏在：<理解链 / 执行链 / 共同前置 / 中途闸门>
判定依据：理解链 <通过/不通过>；执行链 <通过/不通过 + 外部状态>
改动一项：<改了什么>
交叉回归：另一条链 <仍通/已回归>
后续动作：<回到 P3 改任务书 / 换底座 / 无需变更>
```
