# 任务书模板与三类任务示例

> 复制下方模板直接填写；三类示例用于校准「条件该写到多细」与「停点该设在哪」。

## 一、空白模板

```text
【做什么】在 <环境/设备/账号/站点> 上，对 <对象> 达成 <可观察结果>。
【条件】<预算 ≤ N 元>；<规格 = 枚举值>；<时间 ≤ 今天 18:00>；<数量 = N>。
        条件冲突时优先级：<预算 > 规格 > 时间>。
【停点】停在 <页面/动作> 之前；到达停点后不再深入。
【回报】①<名称> ②<关键属性> ③<价格/数量> ④<其他验收项>。
【红线】不要 <加购/下单/发送/删除/改配置/代填凭据>；
        遇到 <验证码/实名人脸/密钥输入> 请停下并告知我。
```

## 二、填写要点

| 字段 | 判定方法 | 不合格写法 |
|---|---|---|
| 做什么 | 能回答「在哪个环境、对哪个对象、结果如何观察」 | 「整理一下资料」 |
| 条件 | 每条都能被机械判真/假；有冲突时给优先级 | 「便宜点」「性价比高」「尽快」 |
| 停点 | 是位置或动作边界，且早于不可逆动作 | 「下单后停一下」 |
| 回报 | 3–5 项字段，验收方无需回放过程 | 「告诉我过程」 |
| 红线 | 否定式列举 + 越界上报动作 | 「注意安全」 |

## 三、示例 A：采购类（有不可逆动作）

```text
【做什么】在某电商站为办公室采购 1 件键盘托，适配桌面深度 ≤ 60cm。
【条件】单价 ≤ 200 元；宽度 ≤ 60cm；颜色不限；今天 18:00 前完成比价。
【停点】停在商品详情页，不进入结算页。
【回报】前 3 个候选项的名称、宽度、价格、店铺。
【红线】不要加购、不要下单、不要填写任何收货或支付信息；遇到验证码或实名人脸请停下并告知。
```

对照检查：四条条件全为数字/枚举；停点早于「加购/下单」；回报项可在不动手时验收。

## 四、示例 B：信息收集类（只读，可放开步数）

```text
【做什么】在公开网页上收集 3 家同类工具的定价页信息，整理为表格。
【条件】每家 1 个官方定价页；只取公开可见信息；时间 ≤ 今天 20:00。
【停点】停在各家定价页阅读完成，不登录、不注册、不提交任何表单。
【回报】①工具名 ②最低付费档价格 ③计费单位 ④是否有免费额度。
【红线】不要注册账号、不要填写邮箱、不要绕过登录或付费墙。
```

差异：只读任务可放开步数，但停点从「不进入结算」变成「不登录、不提交」。

## 五、示例 C：内容处理类（可回退，停点即交付边界）

```text
【做什么】把 12 份会议纪要合并为 1 份带日期索引的 Markdown，写入 <工作目录>/notes/。
【条件】保留原文小标题；每份不超过 400 字摘要；按日期升序；不改写原意。
【停点】停在初稿完成、文件已写入，等人工定稿后再改。
【回报】①文件路径 ②收录条数 ③缺失或重复的日期 ④待确认的 3 条歧义。
【红线】不要删除原文件、不要覆盖同名文件、不要自动发布或推送。
```

差异：可回退任务的重点是「不覆盖、不删除」，停点即交付边界。

## 六、发出前的四问自查

1. 第三人读完能说出「它会在哪停」吗？
2. 每条条件都能判真假吗？
3. 停点早于所有不可逆动作吗？
4. 回报项足以验收吗？

任一为否，回到对应字段重写，不要靠「它应该懂我」补足。
