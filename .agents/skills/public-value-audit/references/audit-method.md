# 公开值取值域审计 · 方法细则

> 本文是 `public-value-audit` Skill 的方法层（L2），SKILL.md 是入口层（L1）。
> 讲「怎么填清单、怎么选收口手法」；证据链见 [verified-case.md](verified-case.md)。

## 1. 三张清单的填写范式

### 清单 A：公开面清单

逐个数据出口登记。对每个出口问三句：**谁不是所有者也能看到？能看到哪几列？值有多敏感？**

| 出口类型 | 判定「他人可见」的方法 | 常见漏判 |
|---|---|---|
| 表列 | `information_schema.column_privileges` 里有 `anon` / `authenticated` | 只看客户端有没有读，忘了服务端授权 |
| RPC | `pg_proc.proacl` 里有终端角色 | 只看函数体校验，忘了函数**返回值** |
| 对象存储路径 | 路径的**第 2 段**是不是归属标识 | 只看文件名，不看目录段 |
| 公开 API 响应体 | 序列化时是否带出标识字段 | 只看入参，不看响应 |
| 日志 / 埋点 | 是否落到公开可读位置 | 只看应用日志，忘了前端上报 |
| Webhook / 分享链接 | 接收方是谁 | 只看自己能不能看 |

### 清单 A 的取数方法（新人必读：清单 A 不能只靠读客户端代码）

清单 A 的表列与 RPC 两行**必须从活库授权面取**，不能只看客户端 `.select()`。
下面是三条可直接粘贴的 SQL（执行位置：WorkBuddy 云端数据库 MCP `db_exec_sql`（`mode=read`）或 `psql` 直连）：

```sql
-- ① 对外角色的列级/表级授权面（清单 A 的「表列」行）
SELECT table_name, column_name, grantee
FROM information_schema.column_privileges
WHERE table_schema='public' AND grantee IN ('anon','authenticated')
ORDER BY table_name, column_name;

-- ② 对外 RPC 的 EXECUTE 名单 + 是否 SECURITY DEFINER（清单 A 的「RPC」行）
SELECT p.proname, pg_get_function_identity_arguments(p.oid) AS args,
       p.prosecdef, p.proacl::text
FROM pg_proc p JOIN pg_namespace n ON n.oid=p.pronamespace
WHERE n.nspname='public' ORDER BY p.proname;

-- ③ 行级隔离（决定某表算不算「他人可见」，决定 WARN 能否降级为豁免）
SELECT tablename, policyname, cmd, roles, qual, with_check
FROM pg_policies WHERE schemaname='public' ORDER BY tablename, policyname;
```

> ①与③**缺一不可**：①只答「能看哪些列」，③只答「能看哪些行」。
> 两层独立机制叠加才构成「他人可见」的完整判定——本项目的 `registrations` 表
> 是表级授权（①里能看到 `owner_id`/`contact`），靠 ③ 的 `owner_id = auth.uid()` 才限到本人行。

⚠️ **所有权者 ≠ 全体**：`users/<uid>/x` 这类路径里装的是**调用者自己**的 uid，
且该行只有本人可见 → **不是泄露面**。判定要落到「行级隔离」上，不是列名上。

### 清单 B：标识列清单

登记所有承载或内嵌用户标识的列/字段/路径段。默认词典（脚本内 `DEFAULT_IDENTIFIERS`）：

```
owner_id creator_id created_by author_id user_id uid owner_uid
openid unionid phone phone_number mobile email account
login_name real_name id_card token
```

补充约定：
- 路径的**归属段**（第 2 段 / `<uid>` 段）也算标识，即便它不在任何一列的列名里；
- 别名要一并登记（`creator`、`operator`、`assignee`、`from_user`…）；
- 「只展示后 4 位」这类**已截断**的值不算标识，但「哈希后的 uid」若可反查也要登记。

### 清单 C：值域构造方清单

对清单 A 里的每个值，追到**谁拼出来的**：

| 构造方 | 值域 | 判定 |
|---|---|---|
| 服务端常量/表达式 | 有限、可枚举 | ✅ 收口良好 |
| 服务端从**非入参**的表列读出 | 有限（该表的取值域） | ⚠️ 取决于该表是否对外可读 |
| 客户端传入的入参 | **由调用方任意决定** | 🔴 必须收口 |
| 脚本传入的入参 | 同上 | 🔴 必须收口（脚本也可能是攻击面） |

🔴 判定口诀：**「这个值，调用方能换成任意别的吗？」能 → 值域不封闭。**

## 2. 收口手法库

按「值域封闭性」从强到弱：

| 手法 | 值域 | 适用 | 代价 |
|---|---|---|---|
| **服务端拼装**（目标路径由服务端常量拼出，调用方不传参） | 有限且可写正则 | 应用级资产（主图、图标、模板） | 需要服务端有写入通道 |
| **值置空 + 走另一条渲染路径** | 空 | 该值本可有可无 | 可能牺牲产品需求 |
| **列级授权收回** | 该列不可见 | 该列对用户无价值 | 客户端要改字段列表 |
| **行级隔离到本人** | 同行不可见 | 本人私有数据 | 需 RLS 策略 + 逐条确认 |
| **值脱敏（截断/哈希）** | 有限但不可反查 | 需要展示但无需精确 | 失去可操作性 |
| ⛔ **什么都不做，只靠「客户端不读」** | 无限 | —— | **不是收口** |

### 「服务端拼装」的两种落地

- **路径型**：`v_path := 'shared/_application/activities/' || p_slug || '.png'`
  —— 调用方只传 slug（受形状约束），路径前缀由服务端决定。
- **映射型**：公开列存稳定别名（`dawn-trek.png`），真实路径由服务端查表后签发。
  代价是客户端需要多一次交互；适合路径本身敏感的场景。

## 3. 判定决策树

```
这个公开值里含标识吗？
├─ 不含 → 结束（记一句「已核对」即可）
└─ 含
   ├─ 该值所在的对象只有所有者可见（行级隔离到本人）？
   │  └─ 是 → 不是泄露面；登记为「已豁免 + 理由」
   └─ 否 → 泄露面
      ├─ 值域由服务端封闭？ → 是：核对授权面即可
      └─ 值域由调用方入参决定？
         ├─ 该入参承载标识？（名字像标识 / 路径型且无形状约束）
         │  └─ 是 → 收口三件套：
         │     ① 服务端拼装（优先）
         │     ② 列级授权（标识列移出对外清单）
         │     ③ 客户端白名单逐列对齐 + 双向断言
         │     ④ 读授权面对齐（收口可能制造新风险，见下）
         └─ 否（入参被形状约束，如 slug）→ 不承载标识
            ├─ 该入参是否可枚举？ → 是：记为中危，可枚举性另行处置
            └─ 否 → 记录并继续
```

### 收口制造的**新**风险（第四件：读授权面对齐）

把资产从「按用户分目录」迁到「应用级命名空间」后，存储侧的读授权会从
「行级受限」变成「namespace-wide 可读」。若拼接进路径的片段（如 slug）可枚举，
则**未发布对象的存储对象也可能被直接读到——表级 RLS 在这一层被绕过**。

⇒ 收口三件套之外必须加第四件：**公开路径列的取值域，其存储侧读授权必须与表侧 RLS 同粒度**。
命名空间内的全部对象都算公开时，未发布对象应走独立前缀并各自授权。

## 4. 收口后的必做项

1. **对账**：`column_privileges`（对外角色的列清单）与 `pg_proc.proacl`（函数的 EXECUTE 名单）逐项复核；
2. **函数体一致性**：磁盘真相源与云端函数体逐字节一致（`md5(prosrc)` 口径；
   注意 `prosrc` 含尾换行，比对时磁盘侧要补）；
3. **返回值审计**：凡 `RETURNS SETOF <表>` 的函数，确认返回的是**调用者自己的行**，
   否则改为只返回标量；
4. **回归断言**：把结论写成不变量并挂 CI（见 SKILL.md §9）；
5. **回归对抗**：重新跑扫描器，确认原高危项消失且无新增。

## 5. 与相邻方法的边界

| 方法 | 解决什么 | 与本方法的关系 |
|---|---|---|
| RLS 策略审计 | 「谁能看哪些行」 | 本方法假设 RLS 已就位，把行级隔离当作**已知前提**来标注豁免 |
| 依赖漏洞扫描 | 已知 CVE | 本方法不看第三方实现 |
| 最小权限原则 | 授权面尽量小 | 本方法是它的**具体化**：列级授权 + 值域封闭 |
| 脱敏规范 | 展示层如何遮蔽 | 脱敏是本方法的**弱手段**（值仍存在、仍可被反查） |
