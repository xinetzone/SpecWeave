# 技术文档模板契约（tech-guide-template）

> 配套 [docx-template-report SKILL.md](../SKILL.md)，定义 `templates/tech-guide-template.docx` 的
> 数据上下文契约、适用场景、边界与反模式。
>
> 模板萃取来源：`XMNN_SDK_使用指南v1.1.0.docx`（芯劢微 XMNPU 工具链使用指南）。

## 1. 模板定位

从真实技术文档（SDK 使用指南）萃取的通用结构模板，覆盖技术手册的高频骨架：

| 结构块 | Word 样式 | 说明 |
|--------|-----------|------|
| 封面 | Table Grid（3×1） | 公司名 / 文档标题 / 版本元信息 |
| 更新记录 | Table Grid（5 列） | 版本/修改人/修改日期/修改说明/核定人，行循环 |
| 章节 | Heading 1 | `{% for ch in chapters %}` 循环 |
| 小节 | Heading 2 | `{% for sec in ch.sections %}` 循环 |
| 正文段落 | Normal | 逐段循环 |
| 代码块 | Normal + Consolas + 浅灰底纹 | `sec.code` 逐行循环 |
| 表格（4 种列数） | Table Grid | 2/3/4/5 列，按 `tbl.cols` 条件切换 |

预置 4 种表格列数，对应技术文档常见场景：

| 列数 | 典型用途 | 原文档出现频率 |
|------|---------|--------------|
| 2 列 | 说明表（目录/API 功能/参数解释） | 约 10 个 |
| 3 列 | 属性表（结构体成员/命令格式） | 约 9 个 |
| 4 列 | 参数表（编译参数/推理参数） | 4 个（最高频核心） |
| 5 列 | 命令参数表（命令行选项详细说明） | 1 个 |

## 2. 数据上下文契约

```python
context = {
    "company":   "公司名",
    "doc_title": "文档标题",
    "doc_meta":  "版本信息 / 日期",
    "revisions": [
        {"version": "1.0.0", "author": "张三", "date": "2025-07-02",
         "desc": "初始版本", "approver": "李四"},
    ],
    "chapters": [
        {
            "title": "章标题",
            "intro": ["章引言段落", "..."],          # 可选，可为空列表
            "sections": [
                {
                    "title": "节标题",
                    "paragraphs": ["正文段落", "..."],
                    "code": ["代码行1", "代码行2"],     # 可选，可为空列表
                    "tables": [                         # 可选，表格列表；每表带 cols 字段
                        {
                            "cols": 4,                   # 必须，2/3/4/5 之一
                            "headers": ["参数名", "类型", "可选项", "说明"],  # 长度需 == cols
                            "rows": [["name", "str", "", "说明"], ...],     # 每行长度需 == cols
                        },
                    ],
                },
            ],
        },
    ],
}
```

> 命名约定：键名英文小写下划线，与 `template-guide.md` 一致。
>
> **表格约束**：`headers` 长度和 `rows` 中每一行的长度都必须等于 `cols`，否则索引越界渲染为空。
> `cols` 只能是 2/3/4/5 中的一个，其他值不会渲染任何表格（静默跳过）。

## 3. 适用场景

- 技术使用指南、SDK 手册、工具链文档、API 参考手册
- 需要封面 + 更新记录 + 多级章节 + 代码示例 + 参数表的标准技术文档
- 批量生成多份结构一致、仅内容不同的技术手册
- 表格列数在 2–5 之间的技术文档（覆盖 SDK 文档 95% 以上的表格场景）

## 4. 边界与扩展（对抗审查结论）

以下能力不在本模板覆盖范围内，需在 Word 中手工调整：

| 需求 | 处置方式 |
|------|---------|
| 1 列或 6 列及以上的表格 | 在 Word 中复制最近列数的表格后增删列，同步调整 `headers[n]` / `r[n]` 索引 |
| 自动目录（TOC） | 交给 Word 域字段，本 Skill 不处理 |
| 修订追踪 | Word 完成，python-docx 不支持 |
| 富文本混排（加粗/变色） | 用 `{{r richtext}}` + `RichText`（见 template-guide.md） |
| 跨列合并单元格 | Word 手工操作，docxtpl 不支持动态合并 |

**设计取舍**：docxtpl 的表格列数在模板中物理固定，无法在渲染期动态增删列。
模板预置 2/3/4/5 四种列数，通过 `tbl.cols` 条件切换，覆盖技术文档的绝大多数表格场景。
不支持的列数（1 列、≥6 列）在真实 SDK 文档中出现频率极低（< 5%），手工调整成本可接受。

## 5. 反模式

| 反模式 | 后果 | 对策 |
|--------|------|------|
| `cols` 与 `headers`/`rows` 长度不一致 | 索引越界，渲染为空值或报错 | 确保 cols == len(headers) == len(rows[i]) |
| `cols` 不是 2/3/4/5 | 表格静默不渲染，无报错提示 | 校验 cols 取值范围 |
| 用字典行 `{{ r.key }}` 代替列表行 `{{ r[0] }}` | 与模板索引方式不兼容，渲染失败 | 行数据统一用列表（数组），按索引访问 |
| 代码块与正文混用同一样式 | 代码失去等宽与底纹区分 | 代码走 `sec.code`，等宽 Consolas + 灰底 |
| 遗漏 `intro`/`code`/`tables` 字段 | Jinja2 未定义变量报错 | context 中三字段要么给值要么给空列表 |

## 7. 验证记录

- 渲染引擎：docxtpl 0.20.2 + python-docx 1.2.0，py314 环境
- 验证方式：`tech-guide-render-example.py` 用样例数据渲染，8 项断言（封面/更新记录×2/2列表/3列表/4列表/5列表/代码块）全部 PASS
- 条件表格机制：`{% if tbl.cols == N %}` + 物理表格块 + `{% endif %}`，docxtpl 支持段落级控制流包裹表格元素
- 列表索引 `headers[0]`、`r[0]` 语法经 docxtpl 渲染验证支持
