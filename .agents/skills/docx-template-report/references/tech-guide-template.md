# 技术文档模板契约（tech-guide-template）

> 配套 [docx-template-report SKILL.md](../SKILL.md)，定义 `templates/tech-guide-template.docx` 的
> 数据上下文契约、适用场景、设计规范、边界与反模式。
>
> 模板萃取来源：一份真实 AI SDK 使用指南文档（已脱敏处理），v2 美化版参考企业级技术文档设计规范重构。

## 1. 模板定位

从真实技术文档（SDK 使用指南）萃取的通用结构模板，覆盖技术手册的高频骨架。
**v2 美化版** 采用科技蓝配色体系，参照企业级技术文档视觉标准重构。

| 结构块 | 样式特征 | 说明 |
|--------|---------|------|
| 封面-品牌栏 | 左公司名（灰） + 右版本号（深蓝粗）+ 深蓝分隔线 | 顶部品牌识别区，版本号居右醒目展示 |
| 封面-大标题 | 24pt 微软雅黑 深蓝 居中 | 文档主标题 |
| 封面-信息表 | 2 列，浅蓝标签 + 浅灰值，灰边框 | 文件状态/版本/日期/作者 |
| 更新记录 | 深蓝表头白字 + 5 列行循环 | 版本/作者/日期/说明/审批人 |
| 一级标题 | 18pt 深蓝 + 中下蓝分隔线 | `{% for ch in chapters %}` 循环 |
| 二级标题 | 14pt 中蓝粗体 | `{% for sec in ch.sections %}` 循环 |
| 正文段落 | 10.5pt 微软雅黑 深灰 1.5 倍行高 | 逐段循环 |
| 代码块 | Consolas 9.5pt + 浅灰底纹 + 左缩进 | `sec.code` 逐行循环 |
| 表格（4 种列数） | 深蓝表头白字 + 灰网格边框 | 2/3/4/5 列，按 `tbl.cols` 条件切换 |

预置 4 种表格列数，对应技术文档常见场景：

| 列数 | 典型用途 | 原文档出现频率 |
|------|---------|--------------|
| 2 列 | 说明表（目录/API 功能/参数解释） | 约 10 个 |
| 3 列 | 属性表（结构体成员/命令格式） | 约 9 个 |
| 4 列 | 参数表（编译参数/推理参数） | 4 个（最高频核心） |
| 5 列 | 命令参数表（命令行选项详细说明） | 1 个 |

## 2. 设计规范（v2 美化版）

### 2.1 配色体系

| 角色 | 色值 | 用途 |
|------|------|------|
| 主色（深蓝） | `#1F4E79` | 一级标题、表头背景、分隔线 |
| 辅色（中蓝） | `#2E75B6` | 二级标题、二级分隔线 |
| 浅蓝 | `#D6E4F0` | 封面信息表标签列、斑马纹（备用） |
| 浅灰 | `#F2F2F2` | 代码块背景、封面信息表值列 |
| 边框灰 | `#BFBFBF` | 表格边框 |
| 正文灰 | `#333333` | 正文文本 |
| 辅助灰 | `#808080` | 辅助文字、jinja 标签 |

### 2.2 字体规范

| 元素 | 字体 | 字号 | 字重 |
|------|------|------|------|
| 一级标题 | 微软雅黑 | 16pt | Bold |
| 二级标题 | 微软雅黑 | 13pt | Bold |
| 正文 | 微软雅黑 | 11pt | Regular |
| 表格表头 | 微软雅黑 | 11pt | Bold |
| 表格内容 | 微软雅黑 | 11pt | Regular |
| 代码块 | Consolas | 10pt | Regular |
| 封面标题 | 微软雅黑 | 24pt | Bold |

### 2.3 页面布局

- 页边距：上下 2.54cm，左右 3.17cm（标准 A4）
- 行高：正文 1.5 倍，代码 1.2 倍
- 表格内边距：上下 2pt，左右 4pt

## 3. 数据上下文契约

```python
context = {
    "company":     "公司名",                    # 封面右上角
    "doc_title":   "文档标题",                  # 封面大标题
    "doc_meta":    "版本 v1.1.0  2025-08-01",  # 封面左上角品牌栏
    "doc_status":  "正式发布",                  # 封面信息表
    "doc_version": "1.1.0",                     # 封面信息表
    "doc_date":    "2025-08-01",                # 封面信息表
    "doc_author":  "张三",                      # 封面信息表
    "revisions": [
        {"version": "1.0.0", "author": "张三", "date": "2025-07-02",
         "desc": "初始版本", "approver": "李四"},
    ],
    "chapters": [
        {
            "title": "章标题",
            "intro": ["章引言段落", "..."],          # 可选，可为空列表
            "sections": [
                {
                    "title": "节标题",
                    "paragraphs": ["正文段落", "..."],
                    "code": ["代码行1", "代码行2"],     # 可选，可为空列表
                    "tables": [                         # 可选，表格列表；每表带 cols 字段
                        {
                            "cols": 4,                   # 必须，2/3/4/5 之一
                            "headers": ["参数名", "类型", "可选项", "说明"],  # 长度需 == cols
                            "rows": [["name", "str", "", "说明"], ...],     # 每行长度需 == cols
                        },
                    ],
                },
            ],
        },
    ],
}
```

> 命名约定：键名英文小写下划线，与 `template-guide.md` 一致。
>
> **表格约束**：`headers` 长度和 `rows` 中每一行的长度都必须等于 `cols`，否则索引越界渲染为空。
> `cols` 只能是 2/3/4/5 中的一个，其他值不会渲染任何表格（静默跳过）。

## 4. 适用场景

- 技术使用指南、SDK 手册、工具链文档、API 参考手册
- 需要封面 + 更新记录 + 多级章节 + 代码示例 + 参数表的标准技术文档
- 批量生成多份结构一致、仅内容不同的技术手册
- 表格列数在 2–5 之间的技术文档（覆盖 SDK 文档 95% 以上的表格场景）
- 对文档视觉质量有要求、希望输出专业企业级外观的场景

## 5. 边界与扩展（对抗审查结论）

以下能力不在本模板覆盖范围内，需在 Word 中手工调整：

| 需求 | 处置方式 |
|------|---------|
| 1 列或 6 列及以上的表格 | 在 Word 中复制最近列数的表格后增删列，同步调整 `headers[n]` / `r[n]` 索引 |
| 自动目录（TOC） | 交给 Word 域字段，本 Skill 不处理 |
| 修订追踪 | Word 完成，python-docx 不支持 |
| 富文本混排（加粗/变色） | 用 `{{r richtext}}` + `RichText`（见 template-guide.md） |
| 跨列合并单元格 | Word 手工操作，docxtpl 不支持动态合并 |
| 自定义品牌色 | 修改模板构建脚本中的 COLOR_* 常量后重新生成 |
| 斑马纹（交替行底色） | docxtpl 行循环为单物理行，无法逐行交替底色；如需斑马纹需后处理或改用固定行数表格 |

**设计取舍**：docxtpl 的表格列数在模板中物理固定，无法在渲染期动态增删列。
模板预置 2/3/4/5 四种列数，通过 `tbl.cols` 条件切换，覆盖技术文档的绝大多数表格场景。
不支持的列数（1 列、≥6 列）在真实 SDK 文档中出现频率极低（< 5%），手工调整成本可接受。

## 6. 反模式

| 反模式 | 后果 | 对策 |
|--------|------|------|
| `cols` 与 `headers`/`rows` 长度不一致 | 索引越界，渲染为空值或报错 | 确保 cols == len(headers) == len(rows[i]) |
| `cols` 不是 2/3/4/5 | 表格静默不渲染，无报错提示 | 校验 cols 取值范围 |
| 用字典行 `{{ r.key }}` 代替列表行 `{{ r[0] }}` | 与模板索引方式不兼容，渲染失败 | 行数据统一用列表（数组），按索引访问 |
| 代码块与正文混用同一样式 | 代码失去等宽与底纹区分 | 代码走 `sec.code`，Consolas + 浅灰底 |
| 遗漏 `intro`/`code`/`tables` 字段 | Jinja2 未定义变量报错 | context 中三字段要么给值要么给空列表 |
| 直接修改 .docx 模板后忘记更新契约文档 | 数据字段与模板变量不同步 | 模板变更必须同步更新本契约文档 |
