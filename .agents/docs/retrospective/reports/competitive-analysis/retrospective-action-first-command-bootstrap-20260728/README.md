## 三、核心洞察（I阶段·V阶段修正后）

### 洞察1：范式入库后存在"体验-信任-工具化-规范化"连续深化链

- **现象**：用户在看到action-first范式即时演示效果后，连续产生5个递进需求：从"看看效果"到"配置默认设置"到"注册为正式指令"到"多形态产出"最后到"元复盘"，需求链自我强化而非一次性完成
- **根因**：输出格式范式具备即时可验证性——用户能直接在当前对话中体验到输出结构差异，产生即时反馈，降低信任建立门槛。（注：用户也可能本来就有完整规划只是分步表达，因果机制待更多案例验证）
- **影响**：知识沉淀不是一次性入库即完成的终点，而是"初版入库→使用验证→迭代深化→二次沉淀"的螺旋上升过程。初版模式入库只是起点而非终点
- **建议**：新模式入库后默认设置"使用验证期"——直到模式在≥2个不同场景下被成功使用且无重大修正需求，方可标记为稳定；验证期内收集使用反馈，触发二次沉淀迭代

### 洞察2：格式类范式天然具备"自举效应"，文档自身必须符合范式要求

- **现象**：创建action-first命令文档时，撰写过程本身严格遵循action-first范式；Mermaid决策图本身就是范式决策逻辑的可视化；整个对话的回复结构也是范式的 live demo
- **根因**：输出格式类/沟通规范类范式天然具有自指性——范式规定了"应该如何输出"，而范式文档本身就是一个输出物，因此必须遵循自身规则。自指性存在连续谱：格式类最强，架构类中等（文档结构可映射架构分层），算法类最弱
- **影响**：自举效应降低了模式传播成本——范式文档本身就是最佳使用示例，新智能体只需阅读文档就能同时理解"该怎么做"和"做出来是什么样"。但风险在于：如果范式本身有缺陷，自举过程会放大缺陷导致自我一致但对外错误
- **建议**：对于自指性强的范式（格式/沟通/风格类），将"范式文档必须自举符合自身规则"作为强制质量检查项。V阶段增加专门审查："文档是否自洽地演示了它描述的规则？"

### 洞察3：元编排层自动补全用户遗漏的质量门概念

- **现象**：用户发出"复盘+洞察+萃取+导出+原子提交"指令时，列出的概念链是R→I→E→X→C，跳过了V（对抗审查）和A（原子化）。七概念元编排层自动识别知识沉淀场景需要V作为必要质量门，补全了V阶段
- **根因**：用户是方法论使用者而非方法论设计者，调用时倾向于列出他们直观理解的必要步骤，可能遗漏横切质量门（V）或认为某些步骤是隐含的。七概念作为元编排指令的核心价值之一是流程完整性保障
- **影响**：如果严格按用户给出的概念链执行跳过V，产出的模式缺乏对抗审查，质量门形同虚设。元编排层的价值正在于用户不需要记住完整7概念组合和质量门位置，只需给出意图关键词，系统自动补全正确链路
- **建议**：在seven-concepts指令中增强"缺失概念自动补全"机制：识别用户列出的概念子集，根据场景决策树自动补全必需的质量门概念。用户明确说"快速版/跳过审查"时允许跳过V，但必须提示"已跳过对抗审查，产出质量可能存在盲区"

## 四、萃取模式（E阶段）

### 模式：格式类范式自举验证模式（Format Paradigm Bootstrapping Verification）

| 要素 | 内容 |
|------|------|
| **模式ID** | format-paradigm-bootstrapping |
| **触发场景** | 创建/入库输出格式类、沟通规范类、写作风格类范式/模式/规范文档时；模式本身规定了"应该如何输出/写作/沟通"，且文档本身就是该模式的产出物 |
| **自指性强度判断** | 用一个简单自检问题判断："写完这个文档后，如果有人说'按你写的规则，你这文档本身就不合格'，这句话是否成立？"成立→强自指性，必须自举验证；不成立→弱自指性，可选验证 |
| **核心步骤** | ①识别范式类型：判断自指性强度（格式类>架构类>算法类）②强制自举撰写：撰写过程严格遵循范式自身规则 ③逐条自洽检查：文档完成后对照范式规则逐条检查文档是否违反自身规则 ④反模式自证：检查"反模式禁止"章节是否列举了文档自身正在犯的错误 ⑤破规场景演示：如果包含破规场景，文档中应至少有一个破规场景的实际演示 |
| **反模式** | ❌ 范式文档自己违反范式规则（如"结论前置"范式开头写三段铺垫才给结论）<br/>❌ 反模式章节列举的错误正是文档自身正在犯的<br/>❌ 为了自举牺牲文档完整性（强制简洁导致必要说明缺失）<br/>❌ 对弱自指性范式强行自举（过度工程） |
| **迁移验证** | ✅ 编码规范文档：代码示例必须符合规范本身<br/>✅ API设计指南：API示例必须遵循指南原则<br/>✅ 写作风格指南：指南文档本身必须是风格典范<br/>✅ 提交信息规范：规范文档的提交记录必须遵循自身格式<br/>✅ 检查清单模板：模板自身必须通过清单所有检查项<br/>✅ Mermaid安全编码规则：规则文档中的Mermaid示例必须遵循六规则 |
| **ROI说明** | 一次性自举验证成本远高于普通文档撰写，但对于高复用范式（如action-first被所有输出默认遵循），成本远低于多次使用中因范式缺陷导致的问题。低复用/一次性文档可放宽要求 |
| **成熟度** | L1（单案例验证，从action-first范式入库过程中提炼） |

> **入库决策**：本模式为L1成熟度（仅1个案例验证），暂不正式入库到patterns目录，先在本报告中记录。待有≥2个不同场景验证案例后升级为L2并正式入库。
