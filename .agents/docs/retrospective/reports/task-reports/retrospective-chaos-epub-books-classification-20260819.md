## I：核心洞察（G2门检查）

### 洞察1：多轮递进分类策略优于单次穷尽规则
- **陈述**：分类任务采用"高置信度先行，低置信度遗留后用更丰富特征回捞"的递进策略时，两轮即可将分类率从 68.6% 提升到 81.8%；规则库是迭代收敛的产物，而非一次性设计完备的产物。
- **证据**：F-004（首轮两轮匹配）、F-006（68.6%）、F-007（遗留667本）、F-012（回捞280本）、F-013（81.8%）
- **反常识**：挑战"把规则一次写全就能分好"的默认假设——第一轮强关键词覆盖了 68.6%，剩余 667 本恰恰需要第二轮用更高维特征（正则模式+作者库+高频词）才能再分 42%，一次性设计全部规则属于过度工程。
- **行动**：对分类/分拣类任务采用"先强后弱"分层策略：第一轮只做高置信度精确匹配，统计遗留项；第二轮针对遗留项做特征放大（N-gram 高频词分析、正则模式、领域词典）后再回捞，避免在低置信区间反复调参。

### 洞察2：书名清洗与分类匹配需要解耦
- **陈述**：EPUB 文件名普遍携带格式噪声（书名号、`[精品]`标签、版次后缀），若不先统一清洗，会同时导致关键词误判与漏判；将 `clean_title` 作为独立前置步骤，是二次分类 280 本成功的关键。
- **证据**：F-010（两级匹配结构）、F-011（清洗内容清单）、F-012（280本）、F-013（81.8%）
- **反常识**：挑战"直接拿原始文件名做关键词匹配即可"的默认假设——格式噪声本身就是干扰特征，先剥离噪声再匹配，等价于降低了特征空间的维度，匹配准确率与召回率同步提升。
- **行动**：任何文本分类/匹配任务，先把"清洗"与"匹配"拆成两个独立管道；清洗规则（去标签、去冗余后缀）单独维护、单独验证，禁止在匹配逻辑里内联做清洗。

### 洞察3：精确关键词与正则模式必须分层管理并收窄边界
- **陈述**：把正则通配符混入精确关键词列表、或使用过度宽泛的短词/正则，是分类误判与语法错误的两大根因；精确关键词（高置信）与正则模式（中置信）分离、单字符匹配禁止、两栖关键词去重、正则加排除词，是保证准确率的四条纪律。
- **证据**：F-020（正则语法错误）、F-021（单字符误匹配）、F-022（两栖冲突）、F-023（过宽正则误匹配）、F-024（通配符混入强关键词）
- **反常识**：挑战"匹配规则越宽泛覆盖越全越好"的默认假设——宽泛规则带来的误判成本远高于漏判成本，在无人工复核的批量场景下，宁可漏判留在"其他"，也不可错分污染目标类别。
- **行动**：匹配规则设计遵循"窄规则优先"：精确关键词与正则分离为两个独立规则表并标注置信度；单字符/双字符短词一律进正则且加词边界；发现两栖关键词必须先消歧再入规则；正则必须附排除词列表。

## E：模式萃取（G3门检查）

### 模式：先强后弱两级匹配分类模式

**模式名称**：先强后弱两级匹配分类模式

**触发场景**：
- 大量文本/文件需要按类别分拣，且无法一次性准确全部分完
- 分类对象携带格式噪声（标签、后缀、书名号等）
- 允许存在一个"未分类/其他"的暂存区，容忍部分难例遗留
- 追求高准确率（宁可漏判，不可错判）而非高召回

**核心步骤**：
1. **全量枚举基线**：先导出完整文件名/文本清单，记录总数作为守恒校验的基线
2. **清洗与匹配解耦**：编写独立的 `clean` 函数统一剥离格式噪声（扩展名、标签、冗余后缀），匹配逻辑只消费清洗后的文本
3. **第一轮强关键词精确匹配**：只放高置信度的精确关键词（含领域词典、作者库），匹配成功的立即归入目标类别，同时记录匹配命中的关键词与类型
4. **统计遗留项**：将未命中的全部留在"其他"，列出清单，计算分类率
5. **高频词分析发现遗漏**：对遗留项做 N-gram（bigram/trigram）高频词统计，识别未被规则覆盖的分类信号（体裁词、模式短语）
6. **第二轮丰富特征回捞**：据高频词分析结果补充正则模式、作者库、短语规则，对遗留项二次匹配（返回匹配类型 strong/regex/none 便于审计）
7. **执行与守恒校验**：先 dry-run 预览移动结果，执行后统计各目录计数，总和必须等于基线总数
8. **抽查验证准确率**：对每个类别（尤其高占比类别）随机抽样核对无跨域误判
9. **边界收窄**：两栖关键词去重、正则加排除词、短词匹配加词边界、精确关键词与正则分表管理

**反模式**：
1. ❌ **反模式1：一次想写全规则**：试图在第一轮就穷尽所有可能的关键词与正则，导致规则库庞大且互相冲突，边际收益递减（对应 F-006 首轮仅 68.6% 后仍需第二轮）
2. ❌ **反模式2：正则通配符混入精确关键词列表**：在高置信关键词列表里混入 `打造.*团队` 这类通配符，既引发语法歧义又破坏"精确匹配"的置信度假设（对应 F-024）
3. ❌ **反模式3：过宽的单字符/短词匹配**：用单字符（如 `C`）做匹配导致大规模误分类，短词必须进正则并加词边界（对应 F-021）
4. ❌ **反模式4：两栖关键词不去歧**：同一关键词命中多个类别时不消歧，导致同一本书被两个规则争抢、错分（对应 F-022）
5. ❌ **反模式5：过宽正则无排除词**：`思维.*模型` 这类宽正则误吸跨域内容，正则必须附排除词列表（对应 F-023）
6. ❌ **反模式6：执行后不做守恒校验**：移动文件后不统计各目录总和与基线对照，可能出现静默丢失或重复却无感知

**检验标准**：
- 分类率第一轮 ≥ 60%，第二轮 ≥ 80%
- 执行后各目录计数总和 = 基线总数（文件守恒）
- 随机抽样 ≥ 30 本核对无跨域误判
- dry-run 预览结果与实际执行结果一致
- 每个匹配结果可追溯到命中的关键词与匹配类型（strong/regex/none）

**迁移示例**：
```python
# 通用两级匹配分类骨架（伪代码）
def classify(text):
    t = clean(text)                      # 步骤2：清洗解耦
    for kw, cat in STRONG_KW.items():    # 步骤3：精确关键词
        if kw in t:
            return cat, kw, 'strong'
    for cat, pattern in REGEX_RULES:     # 步骤6：正则模式
        if pattern.search(t):
            return cat, pattern.pattern, 'regex'
    return '其他', None, 'none'          # 步骤4：遗留

# 非 EPUB 场景迁移：只需替换 clean() 的噪声词典与 STRONG_KW/REGEX_RULES
# 可复用于：邮件自动分箱、客服工单分类、评论情感分类、日志告警分类、电商商品归类
```
