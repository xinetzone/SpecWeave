# 一站式操作指南模式（One-Stop Operation Guide）

## 模式类型
方法论模式（document-architecture）

## 成熟度
L2 已验证（在 Mermaid 图表操作指南中完整验证一次）

## 适用场景
当某个高频任务/工具/流程的知识分散在多个位置（模板目录、规则文档、脚本代码、排错指南、开发规范），导致使用者需要多文件跳转才能获得完整信息时。

典型信号：
- 同一主题的规则、模板、工具用法分散在 3 个以上位置
- 新成员/新智能体经常问"这个怎么用"
- 规范存在但执行率低（规范落地"最后一公里"断裂）
- 用户反馈"知道有规范但找不到"

## 问题背景
规范落地不仅需要规则本身正确，还需要**降低规则获取成本**。当知识分散在多个文件中时，即使每个文件都正确，使用者也可能因为查找成本高而放弃查阅，导致"规范存在但未执行"的治理失效。

这是一种**结构性摩擦力**——不是规范写得不好，而是到达规范的路径太长。

## 核心思想
> 为高频任务创建一个一站式入口文档，将规则、模板、工具用法、排错流程和检查清单整合到单一文件中，将知识获取路径从"多文件跳转"压缩为"单文件直达"。

入口文档不是替代详细文档，而是作为**路线图和导航枢纽**——提供快速开始步骤、核心规则摘要、常用命令、排错决策树和检查清单，同时链接到详细参考文档供深入查阅。

## 文档结构六要素

一份合格的一站式操作指南应包含以下六个核心部分：

### 1. 快速开始（3步以内）

用最少的步骤让用户完成第一次成功操作。包含：
- 一句话说明文档用途
- 流程图/步骤图展示整体流程
- 可直接复制的起步代码/模板
- 预期结果说明

### 2. 核心规则（最常违反的 Top N）

不是完整规则列表（那放在详细文档里），而是最常被违反的 5-8 条规则，每条规则包含：
- 一句话总结
- 错误/正确示例对照
- 记忆口诀（如有）

### 3. 工具用法（常用命令）

该任务涉及的自动化工具的核心命令：
- 最常用的 3-5 个命令及参数说明
- 检查/修复/预览等不同模式的用法
- CI 集成方式

### 4. 排错流程（决策树）

遇到问题时的排查顺序，最好用 Mermaid 流程图展示：
- 按出现频率从高到低排列检查项
- 每个分支给出具体修复动作
- 形成闭环（修复→重新检查→仍有问题→下一项）

### 5. 检查清单（完成前必过）

提交/完成前的对照检查清单：
- 10项以内，可快速勾选
- 每项对应一条规则或工具检查
- 最后一项是运行自动化检查

### 6. 参考索引（链接不重复）

链接到更详细的参考文档：
- 不重复详细文档的内容
- 按用途分类（模板、详细规则、陷阱表、工具源码、CI脚本）

## 反模式

| 反模式 | 问题 | 正确做法 |
|--------|------|---------|
| 入口文档成为详细文档的完整副本 | 内容重复，维护时容易不一致 | 只放摘要+链接，详细内容保留在原文档 |
| 缺少快速开始章节，直接进入详细规则 | 新用户不知道从何开始 | 3步快速开始必须放在最前面 |
| 没有排错流程 | 遇到问题时用户仍需到处搜索 | 用Mermaid决策树展示排查路径 |
| 只描述"应该怎么做"，不给示例 | 用户无法判断自己写的是否正确 | 每个规则配正反例 |
| 检查清单太长（超过15项） | 用户跳过不看 | 控制在10项以内，覆盖最高频问题 |

## 成功案例

| 文档 | 整合前分布 | 整合后效果 |
|------|----------|---------|
| [mermaid-guide.md](../../../../../../docs/knowledge/best-practices/mermaid-guide.md) | 模板(8文件)、规则模式(2文件)、检查脚本(1文件)、CI脚本(2文件)、开发规范(1文件)共14个文件 | 单文件含快速开始+六规则+10项检测能力表+6步排查图+提交前清单，7个参考链接 |

## 失败案例与边界强化（V2）

### 失败案例

| 案例 | 失败表现 | 根因 | 教训 |
|------|---------|------|------|
| 根目录 docs/ 双入口治理失效（本项目真实事件） | 文档同时存在 `.agents/docs/`（唯一有效容器）与根目录 `docs/`（后被判定废弃）两个入口，入口不唯一导致引用混乱，最终需要全仓级别的路径迁移与引用修复 | 违反"入口唯一"原则：入口文档与容器文档未做分离，历史入口废弃时未同步清理引用 | 一站式入口必须与 entry-container-separation 配合；入口废弃必须同步迁移引用，否则入口本身就是新的摩擦源 |
| 规范存在但执行率低（Mermaid 治理复盘·洞察3，本模式诞生诱因） | Mermaid 规则分散在 14 个文件中，使用者因查找成本高而放弃查阅，违规持续发生 | 结构性摩擦力：不是规范错误，而是到达规范的路径太长 | 高频任务的规则必须压缩获取路径（单文件直达），否则规范形同虚设 |

### 反目标用户/反目标场景

| 反目标用户/场景 | 不适用原因 | 适配策略 |
|----------------|-----------|---------|
| 低频任务（数月一次的操作） | 整合与维护成本高于偶尔查找的成本 | 不适用：保留分散文档+良好索引即可 |
| 知识尚未稳定的演进中规范 | 入口文档会频繁过时，维护负担重 | 中度：等规范稳定后再建入口，过渡期用临时索引 |
| 知识本身单一简单的任务（一个规则、一个命令） | 六要素结构是过度设计 | 轻度：一个 README 段落即可，无需独立文件 |
| 已有强导航体系（导航表+看板+Skill 门面）覆盖的任务 | 入口文档会成为重复入口，制造双入口风险 | 中度：先做入口唯一性审计，避免叠加 |
| 超大知识域（整本手册级别的内容） | 单文件入口装不下，会退化为目录页 | 不适用：用分层导航（目录页+子指南）替代 |

### 早期预警信号

| 预警信号 | 含义 | 应对 |
|---------|------|------|
| 入口文档行数逼近详细文档 | 正在退化为副本，双份维护风险 | 删减为摘要+链接 |
| 出现同一主题的第二个入口文档 | 入口唯一性被破坏 | 立即合并或明确分工 |
| 用户/Agent 仍频繁问"这个怎么用" | 快速开始或排错章节失效 | 按真实提问补全快速开始路径 |
| 入口文档内链接断链率高 | 引用的详细文档被移动/重命名 | 修复链接并将入口纳入链接检查范围 |
| 检查清单项长期被跳过或清单膨胀超 15 项 | 清单与实际风险脱节 | 精简回 10 项以内 |

### 适用前提

- 任务高频且知识确实分散在 ≥3 个位置（适用场景四信号至少命中一个）
- 存在稳定的详细文档作为链接目标（入口只做摘要+路由，不承载全部内容）
- 有维护机制保证入口与详细文档同步（收尾检查或 CI 链接检查覆盖入口文档）
- 入口唯一：同一主题没有其他竞争性入口

## 与其他模式的关系

- **entry-container-separation**：本模式是入口-容器分离原则的正向应用——入口文档精简且导航性强，详细内容留在容器文档中
- **three-layer-rule-enforcement**：一站式入口降低了第一道防线（源头预防）的摩擦力
- **mermaid-safe-coding-rules**：六规则是操作指南中"核心规则"章节的内容来源
- **safe-starter 模板**：是操作指南中"快速开始"章节的可复制素材
