# 工程方法论文章七技法·实战填空模板

## 使用说明

- **适用**：系统性工程方法论长文（3000字以上）
- **标记约定**：`【必填】` = 长文必须填写；`【选填】` = 短文可选；`【...】` = 填空位置，填写时删除方括号和提示文字
- **填写顺序**：建议先填技法2（破题）定调，再填技法3（分层）搭骨架，然后逐章填充其他技法（**顺序仅供参考，按个人写作习惯调整即可**）

## 各技法填空详细指引

### 技法2：反直觉破题（文章开头，150-300字）

**填写位置**：文章开头，摘要/前言部分，在任何详细内容之前

**填空公式**（三句话）：
```
第一句：点出读者的常见做法/惯性认知
第二句：指出这个做法为什么不够/有问题/会踩坑
第三句：给出本文要讲的正确认知/本文价值
```

**填空指引**：

| 位置 | 内容类型 | 长度建议 | 好例子 | 坏例子 |
|------|---------|---------|--------|--------|
| 第一句 | 读者常见做法/行业惯性 | 20-40字 | "很多团队做Agent上线前，跑几十条case觉得效果不错就发了" | "本文讨论Agent评测问题"（无认知靶心） |
| 第二句 | 为什么不够/会踩什么坑 | 40-80字 | "但同一Prompt跑通一次不代表每次都能跑通，结果看起来对可能过程已经出错——这类假阳性问题在生产环境迟早暴露" | "这是不对的/有问题的"（只否定不说为什么） |
| 第三句 | 本文给出什么/读者能得到什么 | 40-80字 | "本文系统讲清楚Agent评测从'跑几条case'到工程质量闭环的完整方法论，覆盖指标、数据、评分、根因、资产沉淀五大模块" | "下文将详细介绍"（空泛无价值） |

**可选增强**：如果不想直接否定读者，用[正言若反写作法](../creative-design/zhengyan-ruofan-writing.md)的"不是不X，是X需要..."句式。

---

### 技法1：划重点先行（每章开头，15-30字）

**填写位置**：每个二级/三级标题（`##`/`###`）下面，正文之前，独立成段

**填空公式**：
```
【用肯定句直接说结论】：【必要时用10字以内补充适用范围/前提】
```

**填写指引**：

| 要素 | 要求 | 好例子 | 坏例子 |
|------|------|--------|--------|
| 句式 | 肯定句，不用疑问句/铺垫句 | "P0指标是上线门禁，不达标绝对不能发布" | "接下来我们讨论一下P0指标" |
| 信息密度 | 读完这一句就知道本章核心 | "LLM Judge不能裸跑，必须校准到与人工一致率85%以上再自动化" | "Judge很重要" |
| 位置 | 标题下第一行，正文之前 | 直接跟在`### 某某章节`标题下面 | 写了几段正文才给结论 |

**提示**：写完一章后，问自己"如果读者只看这一句，能知道这章讲什么吗？"——如果不能，重写这一句。

---

### 技法3：分层分级贯穿（全文骨架，开头给出）

**填写位置**：破题之后，正文第一章之前，给出全文结构总览

**填空公式**：
```
本文从【维度】出发，分为【X】层/【X】级/【X】类：

| 层级/等级/分类 | 用途/适用场景 | 判断标准 |
|---------------|-------------|---------|
| 【最高优先级/第一层】 | 【做什么用】 | 【怎么判断属于这一层】 |
| 【中间优先级/第二层】 | 【做什么用】 | 【怎么判断属于这一层】 |
| 【最低优先级/第三层】 | 【做什么用】 | 【怎么判断属于这一层】 |

这套分层将贯穿全文，后续章节不再引入新的分类体系。
```

**填写指引**：

- 分层维度选择：从你的主题里找最核心的一个区分维度（优先级/责任方/执行顺序/风险等级/抽象层次）
- 层数：2-4层最佳，超过5层读者记不住
- 全文统一：选定一套分层后，所有章节都用这套分类，不要这章分三层那章分四层
- 命名一致：同一层级在全文用同一个名字，不要一会说"P0"一会说"高优先级"

---

### 技法4：原则+落地锚点结合（每个核心观点后）

**填写位置**：讲完一个核心原则/观点之后，紧接着给出落地锚点，不要隔几节再说

**落地锚点四件套**（每个核心观点至少选1-2个填写）：

| 锚点类型 | 填空模板 | 什么时候必须填 |
|---------|---------|---------------|
| **具体数值** | "【指标名】达到【参考数值】再【动作】，典型值是【X】（来自【来源/经验】）" | 涉及阈值/比例/数量时必填 |
| **数据结构** | "【记录/配置/输出】至少要包含：【字段1】、【字段2】、【字段3】" | 涉及要记录/存储/传递的数据时必填 |
| **判定逻辑** | "当【条件A】或【条件B】时，走【路径X】；否则走【路径Y】" | 涉及判断/路由/分支逻辑时必填 |
| **起步路径** | "从零开始先做【具体第一步，不超过20字】，再【第二步】，不要一开始就【反模式】" | 章节开头讲"怎么做"时必填 |

**关键位置要求**：锚点必须在讲完原则后**立即**给出，不要统一放到文末"最佳实践"章节。

---

### 技法5：反模式提醒穿插（正文对应位置）

**填写位置**：在讲正确做法的**同一段落或下一段**，紧跟正确做法之后，不要集中到文末"避坑指南"

**填空公式**（两种句式）：
```
句式A（直接提醒）：⚠️ 不要【具体错误做法】—— 这会导致【具体后果】，正确做法是【一句话回顾正确做法】。
句式B（正言若反）：不是说【错误做法】完全没用，而是【适用边界】，在【本文场景】下应该【正确做法】。
```

**填写指引**：

| 要素 | 要求 | 好例子 | 坏例子 |
|------|------|--------|--------|
| 具体性 | 错误做法要具体可识别 | "不要只写'请从1到5打分'不给评分标准" | "不要犯错误" |
| 后果 | 说清为什么错，不是只说"不对" | "会导致Judge评分一致性差，版本对比结果不可信" | "这样不好" |
| 位置 | 在正确做法之后0-3段内 | 讲完"怎么写Judge Prompt"立刻接反模式 | 讲完隔了十节在文末才说 |
| 数量 | 长文至少5处，均匀分布 | 每章1-2个 | 全文只在文末列1个 |

---

### 技法6：单案例贯穿（全文至少3章复用）

**填写位置**：在讲不同模块/方法的章节中，回到同一个案例说明应用

**案例选择填空**：
```
贯穿案例名称：【给案例起个好记的名字，如"已发货退款案"】
案例场景：【2-3句话描述具体场景，要有细节，不要抽象】
案例覆盖章节：
- 在【第X章讲XX】时：案例中【发生了什么问题/方法如何应用】
- 在【第Y章讲YY】时：案例中【发生了什么问题/方法如何应用】
- 在【第Z章讲ZZ】时：案例中【发生了什么问题/方法如何应用】
```

**案例选择标准**（填写前自检）：
- [ ] 足够具体：有具体场景、具体角色、具体问题，不是"比如一个客服场景"
- [ ] 覆盖多模块：这个案例能在至少3个不同章节中被复用
- [ ] 读者能共情：是目标读者日常会遇到的问题，不是极端特例
- [ ] 有完整链路：案例有起因→经过→结果，不是断片

---

### 技法7：闭环收尾（文章结尾，200-400字）

**填写位置**：文章最后一部分（最后一章/结语）

**填空公式**（四句话结构）：
```
第一句：回到开头提出的问题，确认本文给出了答案
第二句：总结全文核心路径/核心框架（一句话，呼应开头破题）
第三句：指出终点不是"做完一次"而是"建立持续机制/沉淀可复用资产"
第四句：承认落地难点，给读者现实预期和起步建议
```

**填写指引**：

| 位置 | 内容类型 | 好结尾示例要素 |
|------|---------|---------------|
| 回应开头 | 让读者感觉"圆回来了" | "回到开头的问题：'跑几条case就上线为什么不行？'——现在你知道答案了：..." |
| 一句话总结 | 全文核心压缩成一句话 | "评测体系的本质，是把不稳定的智能行为持续收敛为可发布的工程质量" |
| 升维到机制/资产 | 不要停在"按这个做就行" | "评测的终点不是一份报告，而是六大质量资产库越积越厚，让迭代脱离个人经验和临时救火" |
| 现实预期 | 不画大饼，承认难点 | "落地最难的不是技术，是跨团队协作中能否长期稳定产出可执行行动项——建议从Golden Set的50条核心case起步" |

## 模板填写完成后的自检

写完后，用这个清单快速验证七技法是否都用对了：

| # | 检验项 | 自检方法 | ✅/❌ |
|---|--------|---------|------|
| 1 | 反直觉破题 | 给一个没读过本文的人看开头300字，TA会想继续读下去吗？ | |
| 2 | 划重点先行 | 随机翻3章，遮住正文只读章首第一句话，能说出这章核心结论吗？ | |
| 3 | 分层贯穿 | 全文是否能说出"本文分X层/级/类，分别是..."？ | |
| 4 | 落地锚点 | 随机抽3个核心观点，后面是否紧跟了具体的数值/结构/逻辑/起步建议？ | |
| 5 | 反模式穿插 | 全文是否有≥5个"不要XXX"穿插在正文中，不是集中在文末？ | |
| 6 | 贯穿案例 | 同一个具体案例是否在≥3个章节中被提到和复用？ | |
| 7 | 闭环收尾 | 结尾是否回到了开头的问题？是否指向持续机制而非单次完成？ | |
