# V阶段对抗审查「用户视角优先」权重分配模式

## 触发场景

当执行对抗审查（V阶段）时，且项目满足以下条件：
- 项目产出物有明确的目标受众（如文档给开发者看、报告给CTO看）
- 审查目标是发现"实际使用中的问题"而非"纯逻辑正确性"
- 审查资源有限（时间/精力不足以做大规模多轮审查）

**不适用场景**：纯数学/逻辑证明类项目、安全审计（逻辑严谨性优先于用户体验）、无明确受众的纯理论探索。

## 核心步骤（优化后的四视角分配）

```
步骤1：确定目标受众画像
  - 主要受众是谁？（新手/资深用户/技术决策者/运营人员？）
  - 次要受众是谁？
  - 输出：受众优先级排序

步骤2：按ROI分配攻击配额（总配额12-16条）
  - 【高配额4-5条】主要用户视角（如文档类→新手视角/首次使用者视角）
    攻击方向：术语门槛、步骤可操作性、信息缺口、阅读路径清晰度
  - 【高配额4-5条】决策者/付费方视角（如企业类→CTO/技术负责人视角）
    攻击方向：成本/ROI、锁定风险、落地可行性、合规性
  - 【中配额2-3条】魔鬼代言人视角（逻辑/事实漏洞）
    攻击方向：绝对化表述、事实矛盾、逻辑跳跃、证据不足
    ⚠️ 强制约束：攻击必须基于项目范围和目标受众，禁止越界攻击
  - 【低配额2-3条】未来/扩展视角（长期演进）
    攻击方向：可扩展性上限、未来技术兼容性
    ⚠️ 强制约束：只攻击"3年内大概率遇到"的问题，禁止过度超前需求

步骤3：攻击质量检查
  每条攻击必须包含三要素：攻击对象（具体到章节/条目）+ 攻击点理由（具体逻辑，不是"不对"）+ 修正建议（可操作）

步骤4：采纳率健康检查
  - 总采纳率：30%-40%为健康区间
  - 各视角采纳率：用户视角和决策者视角目标采纳率≥40%，魔鬼/未来视角目标采纳率≥20%
  - 单一视角采纳率<15%时，检查该视角攻击方向是否偏离目标
```

## 视角攻击方向检查清单

| 视角 | 优先攻击方向（高ROI） | 禁止攻击方向（低ROI） |
|------|---------------------|---------------------|
| **新手/用户视角** | 术语未解释、步骤跳步、缺少前置条件说明、错误示例缺失、阅读路径不清晰 | 挑战架构决策合理性、质疑战略判断 |
| **CTO/决策者视角** | 成本/TCO缺失、锁定风险未提及、落地步骤不清晰、合规风险、人员技能要求 | 代码细节错误、语法问题、小的格式问题 |
| **魔鬼代言人视角** | 绝对化表述（"完全"/"所有"/"100%"）、事实矛盾、证据不足的结论、逻辑跳跃 | 脱离上下文的纯逻辑抬杠、对受众已经知道的常识进行攻击 |
| **未来/扩展视角** | 3年内可见的扩展性瓶颈、已知技术演进路线的兼容性、有公开Roadmap的特性 | 10年后的科幻场景、小众边缘场景、目标受众3年内不会遇到的问题 |

## 反模式（禁止做的事）

**反模式1：机械四视角等分**
- 表现：不管什么项目，四个视角各4条，凑齐16条
- 后果：高价值视角（用户/决策者）攻击不充分，低价值视角（纯逻辑/未来）浪费配额
- 避免：按目标受众确定视角权重，高价值视角配额加倍

**反模式2：魔鬼代言人陷入逻辑诡辩**
- 表现：脱离项目上下文和受众定位，进行纯逻辑抬杠（如针对入门教程要求亿级并发架构）
- 后果：大量"不采纳"意见浪费审查资源，真正的问题被淹没
- 避免：为魔鬼代言人设置"上下文锁定规则"，攻击必须在项目目标范围内

**反模式3：只统计总采纳率，不看视角分布**
- 表现：只看总采纳率是否≥30%，不检查各视角的采纳情况
- 后果：可能出现"高价值视角0采纳、低价值视角全采纳"的不健康分布，总采纳率达标但审查质量差
- 避免：分视角统计采纳率，高价值视角（用户/决策者）采纳率必须≥40%

## 迁移验证

本模式已在以下场景验证可迁移：
1. ✅ 本项目：AgentKit Wiki教程V阶段审查（采纳率37.5%，新手/CTO视角采纳率50%，验证了权重分配的有效性）
2. ✅ 可迁移到：任何需要对抗审查/评审的环节（代码评审、设计评审、架构评审、文档评审）
3. ✅ 可迁移到（非技术领域）：产品方案评审、商业计划书评审、营销文案评审
4. ✅ 迁移要点：只需要根据项目类型替换"高价值视角"的具体身份（如B端产品→采购决策者视角、C端产品→真实用户视角、代码评审→维护者视角），权重分配原则和三要素要求不变

## 案例验证

- **验证案例1**：AgentKit Wiki教程项目V阶段（2026-07-31）
  - 应用结果：四视角×4条=16条攻击意见，采纳6条（采纳率37.5%）
  - 视角采纳率分布：
    - 魔鬼代言人视角：采纳1/4=25%
    - 纯新手用户视角：采纳2/4=50%
    - CTO技术决策者视角：采纳2/4=50%
    - 未来资深用户视角：采纳1/4=25%
  - 采纳分布：facts.md修正3处、insights.md修正1处、patterns.md修正2处（新增锁定风险维度+退出预案检查项）
  - 验证数据：采纳分布健康（三类文档均有采纳），高价值视角（新手/CTO）采纳率50%≥40%目标，低价值视角（魔鬼/未来）25%≥20%目标，验证了权重分配模式的有效性
