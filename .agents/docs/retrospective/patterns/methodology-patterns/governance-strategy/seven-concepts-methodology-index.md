# 七概念方法论体系索引

## 方法论体系概述

很多人学一套新方法论，第一步都是先记住概念名字——R（复盘）、I（洞察）、E（萃取）、C（原子提交）、A（原子化）、F（第一性原理）、V（对抗审查）。这是必要的起点，但如果停在这里就以为掌握了，你会发现遇到实际任务时仍然不知道什么时候该启动哪几个概念、质量门在哪里、按什么顺序执行不会乱。七概念真正解决的问题不是"给你七个概念名字"，而是把AI智能体协作中**经验复用率低、质量不可控、知识沉淀碎片化**这三个老问题，变成一套有质量门拦截、有场景化链路、可验证可复现的执行闭环——它来自SpecWeave项目18天1258次提交的实战复盘，不是从概念推导出来的纸上框架。

**一句话结论**：七概念不是七个孤立概念清单，而是以质量门（G1-G4）为串联枢纽，根据五种场景自动选择概念组合链路的元编排引擎。

**核心分层框架**：七概念按"感知→认知→验证→执行→沉淀"分为五层能力：

| 层级 | 包含概念 | 核心作用 |
|------|---------|---------|
| 感知层 | R（复盘） | 还原事实、采集数据，不带因果推断 |
| 认知层 | I（洞察）、F（第一性原理） | 根因分析、本质思考 |
| 验证层 | V（对抗审查） | 多视角证伪、暴露盲区 |
| 执行层 | A（原子化）、C（原子提交） | 拆分任务、单一职责交付 |
| 沉淀层 | E（萃取） | 提炼可复用模式、入库管理 |

不是每次任务都需要走完七层——五种场景有五种标准链路组合（见决策树文档）：里程碑复盘用R→I→E→C，问题解决用I→F→V→C，重构优化用I→F→A→C，知识沉淀用R→I→E，创新突破用F→V→I→C。

⚠️ **常见反模式**：不要每次都强行走完七个概念（R→I→E→C→A→F→V全链路）——轻量任务（如写个小脚本、改个文档）只需要C（原子提交）就够了，强行全链路是过度工程。

**从零起步路径**：不要一开始就学全链路，先练单一概念——从C（原子提交）或A（原子化）开始，做5次以上形成肌肉记忆，再逐步加入R和I，最后再用F和V。

七概念的终点不是"又学会了一套方法论"，而是沉淀下来的可复用模式库越积越厚，让后续项目脱离"靠个人经验、临时救火"的状态，进入可预测、可审计、可演进的治理轨道。落地最难的不是理解概念，而是在日常工作中坚持不跳过质量门——建议新手从原子提交（C）的三查暂存法开始实践。

## 快速入门指南

### 新手阅读路径
1. **第1步（15分钟）**：先读「复盘报告」了解这套方法论从何而来、解决什么实际问题
2. **第2步（20分钟）**：读「定位模型」建立七概念的整体认知框架，记住五个层级和七概念缩写
3. **第3步（10分钟）**：对照「决策树」判断你当前任务属于哪种场景，应该启动哪几个概念
4. **第4步（按需）**：根据场景找到「核心工作流」中的对应流程，按步骤执行
5. **第5步（执行中）**：参考「交互规范」确保概念间输入输出格式正确
6. **第6步（交付前）**：用「质量标准」检查清单逐项验收
7. **第7步（进阶）**：阅读「对抗性审查」了解方法论的已知局限，避免教条使用

### 使用建议
- 从简单场景开始：先练单一概念（原子提交C或原子化A），再练双概念组合
- 每次执行后用质量标准自检，逐步形成肌肉记忆
- 遇到问题回溯定位模型，检查是否违反了层级依赖关系
