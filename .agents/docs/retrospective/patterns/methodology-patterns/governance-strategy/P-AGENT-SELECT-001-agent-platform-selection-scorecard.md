## 🎯 9 维度评分标准（权重合计 100%）

> **评分规则**：每维度 1-5 分，依据评分标准客观给出，避免主观"感觉好"。每个分数必须有事实证据（官方文档、PoC 实测、第三方评测），不得仅凭 PPT 打分。

### 维度 1：治理能力（权重 20%，**最高权重**）

> **为什么权重最高**：治理外环（身份/网关/观测/评测）是 Demo 能跑 vs 能在生产跑的分界线。编排能力决定"能不能做"，治理能力决定"能不能稳定做"。

| 分数 | 判定标准 |
|------|---------|
| **1 分** | 治理模块基本缺失，仅提供最基础的模型编排/调用能力，无独立鉴权、无观测、无评测体系 |
| **2 分** | 仅有简单的 API Key 鉴权，日志仅含模型请求/响应，无链路追踪、无评测工具 |
| **3 分** | 有独立鉴权模块（Identity）+ 网关层（Gateway），但 Observability 仅有基础日志、Evaluation 完全缺失或需自建 |
| **4 分** | Identity + Gateway + 基础 Observability（链路追踪+指标）三者齐全；评测能力依赖第三方或需自行集成 |
| **5 分** | Identity + Gateway + Observability + Evaluation **四大治理模块完整闭环**：统一鉴权（含用户/Agent/工具三元身份）、工具接入网关（含超时/熔断/重试）、全链路 Trace（模型/Runtime/Tool/记忆/知识全环节）、评测闭环（离线+在线+发布闸门绑定） |

### 维度 2：开发者体验（权重 14%）

| 分数 | 判定标准 |
|------|---------|
| **1 分** | 仅 1 种语言 SDK，无 CLI 工具，文档不全，社区活跃度低 |
| **2 分** | 1-2 种主流语言 SDK，基础 CLI（仅部署功能），有官方文档但示例少 |
| **3 分** | 支持 2 种语言 SDK，基础 CLI 工具链，官方文档完整，有社区论坛/Issue 响应 |
| **4 分** | 支持 ≥3 种主流语言 SDK，CLI 工具链完整（init/config/build/deploy/launch），兼容主流开源生态（如 LangChain/LiteLLM），有丰富示例 |
| **5 分** | ≥3 种语言官方 SDK + 完整 CLI 工具链（含本地调试/热重载），兼容主流开源框架与标准（ADK/MCP/A2A 等），活跃社区（GitHub Star 万级+周级更新），企业级 SLA 文档支持 |

### 维度 3：部署灵活性（权重 13%）

| 分数 | 判定标准 |
|------|---------|
| **1 分** | 仅支持单一云托管模式，无法本地部署、无混合部署选项 |
| **2 分** | 支持云托管 + 本地调试，但无法混合部署，扩缩容需手动配置 |
| **3 分** | 支持 Local/Cloud 两种模式，有基础自动扩缩容能力，多租户隔离为软隔离 |
| **4 分** | Local/Hybrid/Cloud 三种部署模式齐全，支持 Serverless 弹性（秒级扩缩容），多租户可配置软/硬隔离 |
| **5 分** | Local/Hybrid/Cloud 三模式齐全，Serverless 秒级弹性 + 预热实例冷启动优化，多租户硬隔离（独立 Runtime 实例/独立存储），支持私有云/混合云/边缘部署 |

### 维度 4：企业级安全（权重 13%）

| 分数 | 判定标准 |
|------|---------|
| **1 分** | 无独立鉴权体系，密钥明文配置，无输入/输出内容安全检测 |
| **2 分** | 有基础 AK/SK 管理，单点权限控制，无内容安全检测 |
| **3 分** | 有统一身份管理，凭据托管（Secret Manager），基础敏感词过滤，但无细粒度 ABAC/RBAC、无审计日志 |
| **4 分** | 统一身份治理 + 凭据托管 + 内容护栏（输入拦截+输出合规）+ 审计日志，支持 IdP 集成（SSO/OIDC） |
| **5 分** | Identity 三元鉴权（用户/Agent/工具）+ KMS 凭据托管（无明文密钥）+ 双端内容护栏（输入 Prompt 注入检测+输出合规校验）+ 完整审计日志（≥90天留存，支持多维度查询，不可篡改）+ 细粒度 ABAC 权限模型 + 企业 IdP 深度集成 + 合规认证（等保/SOC2/ISO27001） |

### 维度 5：生态兼容性（权重 11%）

| 分数 | 判定标准 |
|------|---------|
| **1 分** | 私有协议锁定，无标准协议支持，无法接入第三方工具/模型 |
| **2 分** | 支持 MCP 或 A2A 其一，基础 REST API 接入，仅支持自家模型 |
| **3 分** | MCP + A2A 双协议支持其一，REST/OpenAPI 接入能力，支持主流大模型接入 |
| **4 分** | MCP + A2A 双协议兼容，主流框架兼容（LangChain/LlamaIndex/LiteLLM 等），OpenAPI 一键转换接入工具，支持多模型路由 |
| **5 分** | MCP 2.0 + A2A 双标准深度兼容，可接入任意模型/框架/向量库/工具，OpenAPI/GraphQL/gRPC 多协议自动转换，自定义扩展点丰富，提供开放 Plugin 生态市场 |

### 维度 6：可观测与评测（权重 9%）

| 分数 | 判定标准 |
|------|---------|
| **1 分** | 仅有模型调用日志，无 Trace、无指标、无评测能力 |
| **2 分** | 有基础日志和简单指标（调用次数/Token 消耗），无链路追踪、无评测 |
| **3 分** | 有基础链路追踪（Trace ID 贯穿）和核心指标，评测需自建或依赖第三方 |
| **4 分** | 全环节 Trace 串联（Runtime/Gateway/Tool/Memory/Knowledge），Metrics/Logging/Tracing 三支柱齐全，离线评测数据集管理+在线 A/B 实验 |
| **5 分** | 三维信号齐全 + 成本分析（分模型/Agent/Tool 成本拆分）+ 用户满意度采集（NLP+星评双通道）+ 评测体系闭环（离线评测→在线监控→发布闸门→自动回滚），且评测结果与 CI/CD 发布流程深度绑定 |

### 维度 7：成本可控性（权重 7%）

| 分数 | 判定标准 |
|------|---------|
| **1 分** | 无弹性策略，固定资源包计费，无任何成本优化工具，费用不可预测 |
| **2 分** | 有基础手动扩缩容，单一计费模式，无成本优化建议工具 |
| **3 分** | 自动扩缩容，有基础成本看板，按量计费+资源包双模式 |
| **4 分** | Serverless 按需伸缩 + 智能模型路由（小模型处理简单任务）+ 多模式计费 + 成本超预算告警 |
| **5 分** | Serverless 秒级伸缩（空闲缩容到 0）+ 智能模型路由（成本对比全大模型下降 ≥30%）+ 缓存策略（相似请求复用结果）+ 免费额度 + 多档计费（按量/包年包月/预留实例）+ 成本优化建议引擎（自动识别浪费资源） |

### 维度 8：可扩展性上限（权重 6%）

| 分数 | 判定标准 |
|------|---------|
| **1 分** | 单 Agent 上限，无多 Agent 协作，无记忆/知识库扩展能力，无自定义扩展点 |
| **2 分** | 支持简单多 Agent 串行调用，记忆/知识库有明确规模上限且无法扩容 |
| **3 分** | 支持多 Agent 协作（主从模式），记忆/知识库可扩展但有软上限，支持基础自定义 Tool |
| **4 分** | A2A 多 Agent 编排（主从/并行/流水线）+ 分层记忆（会话/长期/知识库）+ Harness 动态热切换 + 自定义扩展点（插件/Hook） |
| **5 分** | 大规模多 Agent 编排（企业级组织架构模拟）+ 分层记忆（无限扩展 + 向量检索）+ 知识库无限分片扩展 + Harness 会话内热切换模型/工具/Skills + 开放插件体系 + 支持亿级会话规模（官方有明确规模指标） |

### 维度 9：供应商锁定风险（权重 7%，**V 阶段对抗审查新增维度**）

> **为什么必须评估锁定风险**：选型阶段忽略锁定风险，3 年后想迁移时退出成本是选型成本的 5-10 倍。开源 SDK + 云托管 + 私有协议的三重嵌套是最危险的锁定组合。

| 分数 | 判定标准 | 锁定等级 |
|------|---------|---------|
| **1 分** | 全栈私有协议，SDK 不兼容任何开源标准，数据导出困难（无标准导出格式），迁移需全部重写 | 🔴 极高锁定 |
| **2 分** | 核心能力（编排协议/工具定义）为私有标准，仅模型层可替换，业务代码严重依赖供应商专有 API | 🟠 高锁定 |
| **3 分** | 兼容部分开源标准（如 OpenAI API 格式），但 Harness 编排、工具协议、记忆格式为私有，迁移需重写核心逻辑 | 🟡 中锁定 |
| **4 分** | 高度兼容主流开源框架/标准（如兼容 LangChain/LangGraph ADK、MCP/A2A 协议），核心业务代码可低成本迁移，但云原生能力（Serverless/评测等）迁移有成本 | 🟢 低锁定 |
| **5 分** | 完全开源（核心 SDK 开源且协议宽松 Apache2/MIT）、全协议标准化（MCP/A2A/OpenAPI）、数据标准格式导出一键迁移、无供应商专有 API 绑定，可无缝切换到任何其他平台或自建 | 🟢 极低锁定 |

### 加权得分计算公式

```
平台 X 总分 = Σ(维度得分 × 权重)
           = 治理×0.20 + 开发体验×0.14 + 部署×0.13 + 安全×0.13
           + 生态×0.11 + 观测评测×0.09 + 成本×0.07 + 扩展×0.06 + 锁定×0.07
```

**示例计算**（以 AgentKit 为例，v2.0 九维度）：
- 治理 5×0.20 = 1.00
- 开发体验 4×0.14 = 0.56
- 部署灵活性 5×0.13 = 0.65
- 企业安全 4×0.13 = 0.52
- 生态兼容 5×0.11 = 0.55
- 观测评测 4×0.09 = 0.36
- 成本可控 3×0.07 = 0.21
- 扩展性 4×0.06 = 0.24
- 锁定风险 3×0.07 = 0.21（VeADK 兼容 Google ADK 是加分，但云托管模式绑定火山引擎生态）
- **合计 = 4.30 / 5.00**

## ✅ 决策建议矩阵

| 加权总分区间 | 决策建议 | 后续动作 |
|-------------|---------|---------|
| **4.5 - 5.0** | ⭐ **强烈推荐** | 可直接进入商务谈判与 PoC 试点，预计成功率 ≥90% |
| **4.0 - 4.4** | ✅ **推荐** | 进入 PoC 验证，重点确认 3 分维度在实际场景是否达标 |
| **3.5 - 3.9** | ⚠️ **有条件推荐** | 可作为备选方案，PoC 重点评估短板维度是否可通过自建/集成补齐（补齐成本需量化） |
| **3.0 - 3.4** | 🟡 **谨慎评估** | 不建议作为主选方案，若选需明确补齐短板的具体方案和成本（预期补齐成本 ≥30% 总投入则放弃） |
| **< 3.0** | ❌ **不推荐** | 存在明显短板，不建议进入 PoC，继续寻找其他候选 |

## ⚠️ 反模式清单（避免这些坑）

1. **❌ 只看编排能力不看治理**：编排维度满分但治理缺失的平台，Demo 到生产必翻车。治理权重（20%）必须是最高的，不可随意调低。
2. **❌ 仅凭 PPT 和报价决策**：选型前**必须做 PoC**（建议覆盖 3 个核心业务场景、≥50 条测试用例），不做 PoC 就决策 = 赌博。
3. **❌ 权重倒置**：把"开发者体验"权重调到最高、"治理能力"权重最低，是典型 Demo 思维，生产环境日均调用破千后治理债务集中爆发。
4. **❌ 忽略锁定风险（不打维度 9）**：这是最常见的 CTO 决策盲点。第一年选型觉得无所谓，第三年想迁移发现所有业务代码依赖私有 API，迁移成本是重新选型的 5 倍以上。
5. **❌ 团队技术栈与平台语言不匹配**：团队全是 Java 却选了仅支持 Python 的平台，招聘和培训成本远超平台本身成本。
6. **❌ 用单一平台对比分数差异 <0.3 就直接决策**：总分差距在 0.3 分以内（满分 5 分）属于误差范围，需要用业务场景 PoC 实测二次验证。

## 📋 PoC 验证必做清单（进入 PoC 阶段使用）

| 序号 | 验证项 | 验证方法 | 通过标准 |
|------|--------|---------|---------|
| 1 | 存量 REST API 接入速度 | 选 10 个核心业务 API 实测接入 | 10 个 API 2 天内全部接入且联调通过 |
| 2 | Identity 与现有 IAM 集成 | 对接企业 SSO/OIDC | 3 天内完成单点登录集成，权限映射正确 |
| 3 | 典型场景成功率 | 跑 50 条核心业务测试用例 | 通过率 ≥90%，核心场景 ≥95% |
| 4 | P95 延迟压测 | 100 并发持续 10 分钟 | 简单场景 P95 <5s，复杂场景 P95 <60s |
| 5 | 可观测链路完整度 | 抽检 10 条调用 Trace | 10/10 都能看到全链路（模型+网关+Tool+知识） |
| 6 | 故障注入测试 | 模拟 Tool 超时/5xx/429 | 超时重试、熔断降级均按配置生效，不雪崩 |
