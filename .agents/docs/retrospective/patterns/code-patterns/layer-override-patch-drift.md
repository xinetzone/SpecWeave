# 分层覆盖补丁的版本漂移（layer override patch drift）

## 模式概述

在存在继承/叠加/多阶段结构的系统（Docker 多层镜像、类继承、配置分层覆盖、变体继承基础层）中，通过在下层之上"覆盖"一个临时补丁来让改动立即生效，会形成"每层一个补丁"的隐性版本分歧——一旦中间层被重建/拉平，行为即回退到旧状态。正确做法是将改动合并入源头（被覆盖基座），而非长期依赖覆盖补丁。

## 核心机制：覆盖补丁"立即可用"的错觉（洞察 I-3）

覆盖（override）补丁有一个最危险的属性：**"立即可用"且往往"当前零漂移"**，极易让人误以为它等价于源头修改。

- **立即可用**：`COPY` 覆盖、子类 override、配置覆盖都是在不改动基座的前提下直接生效，响应速度快。
- **当前零漂移**：本例中 COPY 覆盖的 helper 与源头 sha256 一致（F20），验证全过，强化了"等价"错觉。
- **实则隐患**：任何中间层（该基座）重建时，下游覆盖被拉平/重建，行为静默回退到旧版本——这就是"每层一个补丁"的版本分歧。漂移不发生在当前，而发生在"下一次上层重建"，具有延迟性。

**反常识**：覆盖补丁的危险不在"应用时"（那时它一切正常），而在"依赖链重排时"（那时它静默消失）。凡是分层结构，必须区分"临时补丁"与"源头修复"，并为所有临时补丁标注生命周期与清理点。

## 触发场景

采用分层/继承/叠加结构，且需要让某个跨层共享的组件快速生效。特征信号：

- Docker 多变体继承基础层，某变体通过 `COPY` 覆盖共享文件（helper/脚本/配置）
- 类继承中，子类 override 父类方法以"修补"父类缺陷
- 配置分层覆盖（基础配置 + 环境覆盖），临时覆盖项
- 改源头需等待全链重建才能生效，而当前追求"立即生效"

## 核心步骤

1. **识别分层结构中的"基座"与"覆盖层"**：明确哪个是源头（被覆盖的共享组件），哪个是下游覆盖补丁
2. **覆盖补丁必须标记生命周期**：在覆盖处标注"此为临时补丁，全链重建后移除"以及清理触发点（如"next full rebuild"）
3. **源头同步修正**：覆盖的同时，将改动合并进入源头共享文件，保证下一次重建时移除补丁后行为不丢失（单一职责）
4. **全链重建时收敛**：待一次完整重建完成、验证源头已含改动后，删除覆盖补丁，消除双重维护
5. **验证层加固**：最终以"无覆盖补丁"的干净态验证，而非套用补丁态——确认移除补丁后行为仍正确

## 反模式

- **长期依赖覆盖补丁"立即生效"**：把 COPY 覆盖/override 当作永久修复，忽略中间层重建后的回退风险
- **覆盖补丁无生命周期标注**：不写"全链重建后移除"，清理点丢失，补丁永远残留，源头与覆盖层版本持续分叉
- **只改源头不做生效验证**：反过来，改源头共享文件后未做 `COPY`/重建使下游生效，导致"改了但没用"
- **以补丁态验证替代干净态验证**：验证始终在套用补丁的状态下进行，掩盖移除补丁后的潜在失效

## 正反例对比

| 维度 | ❌ 反模式 | ✅ 正模式 |
|------|---------|---------|
| 生效方式 | COPY 覆盖共享 helper / 子类 override 长期保留 | 临时补丁标注生命周期，全链重建后移除并合并源头 |
| 更新来源 | 依赖链各层各自持有不同版本 helper | 单一源头共享 helper，无双重维护 |
| 生命周期 | 无清理点，补丁永久残留 | 明确"next full rebuild 后移除"清理触发点 |
| 验证对象 | 始终以补丁态验证 | 最终以"无覆盖补丁"的干净态验证 |
| 漂移时点 | 中间层重建时静默回退（延迟暴露） | 源头单一，重建后行为稳定 |

## 检查清单

- [ ] 已识别分层结构中的源头与被覆盖层
- [ ] 每个覆盖补丁已标注临时性 + 清理触发点
- [ ] 补丁改动已同步合并入源头共享文件（单一职责）
- [ ] 已安排全链重建后移除覆盖补丁并验证干净态

## 实际案例

**torch-dev 镜像 helper 版本漂移**（2026-08-20）：torch-dev 变体通过显式 `COPY install-helpers.sh` 覆盖基础层文件，使 `--extra-index-url` 生效。当前 sha256 一致无漂移，但修改源头 `shared/lib/install-helpers.sh` 才是正解；COPY 补丁使依赖链各层持有不同版本 helper。Dockerfile 已标注注释 "Remove after next full rebuild"，下次全链重建时需移除 COPY 补丁，将 `--extra-index-url` 支持合并入源头 helper。
