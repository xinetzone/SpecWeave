# 上下文压缩技术

上下文压缩技术针对长上下文场景，在不损失关键信息的前提下减少传给模型的token数量，同时提升模型对关键信息的注意力集中度。这类技术是处理长文档、RAG系统和长对话的核心手段。

## 技术清单

### 1. 摘要压缩（Summarization Compression）

**原理说明**：将对话历史、长文档或工具返回结果通过LLM或专用摘要模型压缩为简洁摘要，用摘要替代原始长文本传入上下文。摘要不是简单截断，而是保留关键事实、决策结论和待办事项的结构化浓缩。常见实现包括滚动摘要（每超过阈值即摘要旧内容）和层级摘要（先分块摘要再合并摘要）。Microsoft Semantic Kernel内置的`ChatHistorySummarizationReducer`即采用此方法。

**本质路径映射**：压缩

**适用场景**：长对话系统；客服机器人；Agent任务执行；文档问答系统；多工具调用场景。

**实施难度**：中。需要一个摘要模型（可使用小模型），设计摘要格式模板，并处理摘要幻觉问题。

**预期效果范围**：上下文token减少50-80%，质量影响5-15%（取决于摘要质量）。

**优点**：
- 压缩比高，可处理任意长度的历史
- 保留语义信息而非单纯截断
- 结构化摘要可提升关键信息召回率

**缺点**：
- 摘要本身消耗token（摘要模型调用成本）
- 可能遗漏数字、时间、否定条件等细节
- 存在摘要幻觉风险（虚构信息）
- 异步摘要可能增加延迟

**注意事项**：
- 关键业务字段（金额、日期、审批结论）应结构化存储，不依赖摘要
- 摘要格式模板化，明确要求保留哪些类型的信息
- 定期评估摘要质量，设置摘要触发的token阈值
- 原始数据应持久化存储，摘要仅用于上下文传递

### 2. RAG检索增强优化（RAG Retrieval Optimization）

**原理说明**：传统RAG常因召回过多文档块导致上下文膨胀。优化手段包括：精准分块（语义分块而非固定长度分块）、重排序（Reranker对召回结果二次排序，只保留Top-N相关块）、相关度过滤（设置相似度阈值，过滤低相关度内容）。核心思想是"少而精"——3个高相关度的文档块效果往往优于20个低相关度块，后者还会引入"分心问题"（Lost in the Middle）降低回答质量。CORE-RAG等研究表明，精准压缩可将输入减少到全上下文的6%，同时提升EM分数1.5-6.9点。

**本质路径映射**：减少

**适用场景**：知识库问答系统；企业知识库；文档问答；客服知识库；需要外部知识的所有场景。

**实施难度**：中-高。需要选择合适的分块策略、嵌入模型、重排序模型，并调优相关度阈值。

**预期效果范围**：检索上下文token减少60-90%，回答质量提升5-15%（减少噪声干扰）。

**优点**：
- 减少token的同时往往提升回答质量
- 缓解"中间迷失"问题
- 可解释性强，能追溯来源

**缺点**：
- 增加检索和重排序的计算开销
- 阈值调优需要大量测试
- 分块策略对效果影响大，需反复迭代
- 可能遗漏跨块的关联信息

**注意事项**：
- 语义分块优于固定长度分块，保持段落完整性
- 重排序模型（如bge-reranker、Cohere Rerank）是高ROI投入
- 混合检索（稠密+稀疏）提升召回率
- 动态调整Top-N数量，根据问题复杂度决定检索块数

### 3. 滑动窗口（Sliding Window）

**原理说明**：只保留最近的N轮对话或固定token窗口大小的上下文，更早的内容直接截断丢弃。进阶方案包括：动态窗口（根据问题复杂度调整窗口大小）、重要性加权（给包含关键信息的轮次更高的保留权重，不单纯按时间截断）。滑动窗口是最简单的上下文管理策略，token开销可预测，但可能丢失早期关键约束。Microsoft Semantic Kernel将Truncation作为基础压缩策略。

**本质路径映射**：减少

**适用场景**：普通聊天机器人；轻量客服；成本敏感场景；短对话为主的应用；简单任务助手。

**实施难度**：低。按消息条数或token数截断即可实现。

**预期效果范围**：上下文token控制在预算内（如4K/8K），简单任务质量影响<5%，复杂任务可能丢失关键信息。

**优点**：
- 实现极其简单，零额外计算开销
- token消耗可预测，便于成本控制
- 延迟低，不增加额外处理步骤

**缺点**：
- 粗暴截断可能丢失早期关键约束
- 不适合需要长期记忆的复杂任务
- "关键信息在早期被截断"是常见故障模式
- 无法处理跨多轮的指代消解

**注意事项**：
- 系统消息（system prompt）永远保留，不可截断
- 保留用户明确陈述的偏好、约束、目标
- 结合重要性判断，而非单纯按时间截断
- 设置合理的窗口大小，不宜过小

### 4. 记忆筛选与遗忘机制（Memory Filtering）

**原理说明**：模拟人类记忆机制，从对话中提取实体、关键事实和用户偏好存储在结构化记忆中，而非保留完整对话原文。记忆系统通常分为：工作记忆（当前上下文）、短期记忆（最近对话摘要）、长期记忆（结构化实体/事实库）。遗忘机制主动删除低价值信息（如寒暄、确认、重复内容），保留高价值信息（如用户偏好、关键决策、待办事项）。检索时按需从长期记忆中取回相关信息，而非全量传入。

**本质路径映射**：减少 + 压缩

**适用场景**：个人助理；长期陪伴型对话；复杂Agent系统；需要记住用户偏好的应用。

**实施难度**：高。需要设计记忆 schema、实体提取逻辑、记忆检索策略和遗忘机制。

**预期效果范围**：长期对话token减少70-90%，关键信息保留率>90%。

**优点**：
- 支持无限长对话，token增长可控
- 结构化记忆便于推理和利用
- 模拟人类记忆，用户体验自然
- 可跨会话保留用户偏好

**缺点**：
- 实现复杂度高，需要完整的记忆系统架构
- 实体提取可能出错或遗漏
- 记忆检索增加复杂度和延迟
- 遗忘策略设计困难，容易忘"不该忘的"

**注意事项**：
- 关键事实（如用户过敏信息、账户信息）永不遗忘
- 记忆提取需按需进行，不把全部记忆塞入上下文
- 用户可查看和编辑记忆，增加透明度
- 区分会话级记忆和用户级长期记忆

### 5. 语义压缩（Semantic Compression / LLMLingua）

**原理说明**：token级语义压缩技术，以LLMLingua系列为代表，利用小语言模型计算每个token的信息熵，移除信息量低的token（如停用词、冗余修饰、重复表达），同时保留语义完整性。与摘要不同，LLMLingua不重新生成文本，而是在原始文本上做"token级减法"，可实现2-20倍压缩率。压缩后的文本虽然不符合人类语法，但LLM仍能理解，这是因为LLM对噪声和语法错误有很强的鲁棒性。

**本质路径映射**：压缩

**适用场景**：长文档输入；RAG系统的文档块压缩；提示词token预算紧张时；需要保留原文细节的场景。

**实施难度**：中。可直接使用开源的LLMLingua库，需要调优压缩率参数。

**预期效果范围**：token减少30-80%（可配置压缩率），质量影响3-10%（取决于压缩率）。

**优点**：
- 压缩比灵活可调（2x-20x）
- 不重新生成文本，幻觉风险低于摘要
- 保留原文细节（数字、专有名词等）
- 压缩速度快，可使用小模型

**缺点**：
- 压缩后文本人类不可读，不适合需要展示给用户的场景
- 过高压缩率会导致信息丢失
- 需要额外的压缩模型推理开销
- 对中文的支持效果略逊于英文

**注意事项**：
- 压缩率不宜超过5x，否则质量下降明显
- 问题/指令部分不要压缩，只压缩上下文文档部分
- 压缩后进行质量验证，设置回退机制
- 保留原始文本备查，压缩仅用于传入LLM

### 6. 关键信息提取（Key Information Extraction）

**原理说明**：使用NER（命名实体识别）、三元组提取（主谓宾结构）、关键词提取等技术，从上下文中结构化提取关键信息，以结构化格式（如JSON、键值对、知识图谱三元组）替代原始文本传入上下文。与记忆筛选不同，关键信息提取通常针对单次文档或单轮对话进行信息抽取，而非维护长期记忆。xRAG等极端方案甚至将文档压缩为单个token表示，实现极端压缩率。

**本质路径映射**：压缩

**适用场景**：合同/法规问答；信息抽取任务；结构化数据查询；需要精确事实的场景。

**实施难度**：高。需要训练或调优信息抽取模型，设计抽取schema，并验证抽取准确率。

**预期效果范围**：token减少80-95%，关键事实准确率>85%（取决于抽取质量）。

**优点**：
- 压缩率极高，接近信息论极限
- 结构化信息便于推理和校验
- 减少无关内容干扰
- 可直接与数据库/知识图谱集成

**缺点**：
- 抽取错误会导致信息永久丢失
- 隐含信息、语用信息难以抽取
- schema设计需要领域知识
- 实现和维护成本高

**注意事项**：
- 关键抽取字段应有人工校验机制
- 抽取schema不宜过大，聚焦核心实体和关系
- 保留原始文档引用，支持溯源验证
- 结合RAG，抽取信息作为索引而非完整替代

### 7. 查询感知压缩（Query-Aware Compression）

**原理说明**：通用压缩不考虑具体查询问题，可能压缩掉对当前问题重要的信息。查询感知压缩（如LooComp、Provence）根据当前用户问题动态判断哪些句子/token与问题相关，只保留相关部分，丢弃无关内容。核心机制是"留一法"（Leave-One-Out）：计算移除某句话后对回答问题的信息量影响，影响大的句子保留，影响小的句子丢弃。LooComp等研究显示该方法可在高压缩比下保持回答性能。

**本质路径映射**：减少 + 压缩

**适用场景**：长文档QA；RAG系统的精细化压缩；合同/法规问答；需要高精度的问答场景。

**实施难度**：高。需要训练查询感知的压缩模型，或使用LLM进行相关性判断。

**预期效果范围**：token减少70-90%，回答质量损失<5%（优于通用压缩）。

**优点**：
- 压缩精准，只保留对当前问题有用的信息
- 在高压缩比下仍能保持回答质量
- 减少无关信息干扰，提升准确率
- 自适应不同问题的信息需求

**缺点**：
- 需要针对每个问题进行相关性计算，增加延迟
- 模型训练/调优成本高
- 对隐含相关的信息（需要推理才能关联）可能漏判
- 难以处理需要综合全文的开放性问题

**注意事项**：
- 对事实型问题效果最好，对创意/开放性问题效果有限
- 设置自适应阈值，问题简单时压缩率高，复杂时降低压缩率
- 结合通用压缩作为兜底
- 保留句子粒度而非token粒度，便于可读性和调试

## G2质量门：核心洞察四元组

**现象**：上下文压缩技术呈现"两极分化"——简单粗暴的截断/滑动窗口应用最广但效果有限，而学术上最先进的查询感知压缩、极端压缩（如xRAG单token压缩）实际生产落地率不足10%。大多数团队停留在"截断+简单摘要"阶段，未能充分利用语义压缩和检索优化的组合潜力。

**根因**：上下文压缩的本质矛盾是"压缩比"与"信息保真度"的权衡。简单策略虽粗糙但可预测、易调试；先进压缩方法虽然压缩比高，但增加了系统复杂度、引入额外计算开销、存在"压缩错误难以排查"的问题。另一个根因是缺乏标准化的压缩质量评估指标——团队难以量化"压缩后丢失了什么信息"，导致不敢激进压缩。

**影响**：上下文管理是长对话、RAG、Agent系统的核心瓶颈。无效的上下文策略导致两个极端：要么token成本失控（全量传入），要么出现"AI健忘症"（过度压缩丢失关键信息）。上下文压缩不是单一技术问题，而是需要分层设计：工作记忆用滑动窗口、短期记忆用摘要、长期记忆用结构化存储、检索结果用RAG优化+语义压缩，多层策略组合才能达到最优效果。

**建议**：采用分层上下文架构而非单一压缩策略：（1）系统提示词和最近N轮完整保留（工作记忆）；（2）更早对话用结构化摘要（短期记忆）；（3）关键实体和用户偏好存入结构化记忆库（长期记忆）；（4）RAG检索必须加重排序+相似度阈值；（5）长文档块可用LLMLingua做适度压缩（3x以内）。建立压缩质量监控，对比"全上下文基线"与"压缩后"的回答差异，持续调优压缩参数。压缩策略必须有回退机制——当检测到低置信度时，自动扩大上下文窗口而非盲目压缩。
