# 03 API峰谷定价与竞品对比

> ⚠️ 本章价格为2026年8月17日生效的最新定价。API定价可能调整，请以[官方定价页面](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)实时显示为准。

## 3.1 峰谷定价机制

DeepSeek首次在国产大模型中引入类似"峰谷电价"的分时计价机制：

| 时段 | 时间（北京时间） | 时长 | 价格倍数 |
|------|----------------|------|---------|
| **高峰时段** | 每日 9:00-12:00、14:00-18:00 | 7小时 | 2倍（基准价） |
| **空闲时段** | 其余时间（含夜间、周末、法定节假日） | 17小时 | 1倍（高峰的50%） |

**计费单位**：元/百万tokens。

## 3.4 上下文缓存机制（省钱核心）

### 什么是缓存命中？

当多个API请求共享相同的前缀文本时（例如相同的system prompt、相同的RAG上下文），DeepSeek会自动缓存这部分KV Cache，后续请求直接读取缓存而非重新计算。

### 缓存命中有多便宜？

以V4-Pro为例：
- 缓存命中输入：**0.15-0.30元/百万tokens**
- 缓存未命中输入：**4.5-9.0元/百万tokens**
- 缓存命中比未命中**便宜97-98%**

### 实际影响

对于RAG应用、多轮对话、Agent任务等具有大量重复前缀的场景，缓存命中率可达50-90%，实际账单远低于"输入未命中+输出"的表面价格。

> **关于"缓存命中涨幅1100%"的真相**：V4-Pro缓存命中从0.025元涨到0.30元，涨幅看似惊人，但绝对值仍然极低（0.30元/百万tokens）。对大多数应用来说，输出token才是成本大头。

## 3.7 成本优化策略

### 策略1：错峰调度（最直接）

将非实时批处理任务（数据清洗、离线推理、批量摘要、报表生成）调度到空闲时段（18:00-次日9:00及周末），成本直接减半。

### 策略2：提升缓存命中率

- 保持system prompt稳定，不要频繁变动
- 将RAG检索结果放在system prompt或消息前缀位置
- 对用户群共享相同的前缀上下文
- 避免在system prompt中插入动态内容（如时间戳、请求ID）

### 策略3：合理选模型

- 简单对话、分类、抽取 → V4-Flash非思考模式
- 代码生成、数学推理 → V4-Flash思考模式或V4-Pro
- 复杂Agent任务、长链推理 → V4-Pro Think Max

### 策略4：控制输出长度

- 设置合理的`max_tokens`
- 明确要求"简洁回答"
- 需要结构化输出时指定JSON Schema，减少冗余

### 策略5：监控用量

- 在platform.deepseek.com的Usage页面定期查看用量
- 设置用量告警
- 分析token消耗分布，识别异常消耗

## 3.9 价格趋势观察

- 峰谷定价是行业趋势信号：从"价格战烧钱"到"精细化运营"
- 缓存定价的精细化表明推理成本优化成为焦点
- 即便涨价，国产大模型性价比仍显著高于海外旗舰
- 预计更多厂商会跟进分时定价机制
