## 3. 新手入门：5步构建第一个应用（答案之书案例）

这是秒悟应用搭建的**通用迭代流程**，任何应用都可以按这个顺序来：

| 步骤 | 做什么 | 答案之书示例 | 为什么这么做 |
|------|--------|-------------|-------------|
| **Step 1：输入需求** | 用自然语言描述你要做什么 | "做一个答案之书的H5应用，用户输入问题，点击提交后翻动，随机生成启示" | 先跑通最小可用版本（MVP） |
| **Step 2：优化设计** | UI不好看时，加设计参考图或指定风格 | "参考图片的视觉效果"，推荐使用"秒悟UI设计专家"Skill | MVP跑通后再美化 |
| **Step 3：接入AI** | 调用大模型实现智能逻辑 | "点击按钮时调用qwen 3.6 plus，根据问题生成30字以内有趣答案"，也可用Qwen Image生图 | 先有界面，再加智能 |
| **Step 4：优化体验** | 处理加载状态等交互细节 | AI生成时显示三行循环文案："正在翻阅千问答案之书→每一次翻阅都是与智慧的对话→从困惑到清晰只差一个千问" | 功能可用后优化体验 |
| **Step 5：加数据库** | 需要持久化数据时再加 | 记录昵称和提问时间，显示"你是第X个使用该书的人" | 最后一步再加数据，避免一开始卡壳 |

**✅ 新手遵循原则**：每完成一步，测试没问题了再进下一步，不要一开始就想做完美。

## 8. 避坑指南

| 坑点 | 现象 | 怎么避免 |
|------|------|---------|
| **注册窗口期过期** | 点了链接但1小时内没注册，再进要重新点 | 推广时提醒用户"点进来1小时内完成注册" |
| **Plan mode浪费积分** | 简单需求开了Plan mode，积分消耗快效果不一定好 | 记住：需求明确直接做，只在复杂/模糊需求用Plan mode |
| **一开始就加数据库** | 想做复杂应用，一开始就设计数据库，结果卡壳放弃 | 遵循5步法：最后一步再加数据库 |
| **UI太丑就放弃** | 第一版生成不好看就觉得工具不行 | 用Skill、加设计参考图，Design mode能迭代得很好看 |
| **不知道用Skill** | 自己随意编写提示词，效果不好 | 先看看有哪些现成Skill，优先用Skill（推荐"秒悟UI设计专家"） |
