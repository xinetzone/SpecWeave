## 一、魔鬼代言人视角（逻辑漏洞攻击）

### D-01 🔴 严重：三大本质路径"穷尽所有可能"的表述过于绝对
- **文件位置**：01-principles/01-first-principles.md（原第五章开头+结尾）
- **问题描述**：原文声称"所有token优化技术最终可归约为三条本质路径""这三条路径穷尽了token优化的所有可能性——任何新的优化技术都可以被分解到这三个维度上"。这一表述过于绝对：推测解码（Speculative Decoding）通过小模型猜token+大模型验证改变计算顺序而非减少/复用/压缩token；连续批处理（Continuous Batching）通过调度优化提升GPU利用率而非直接操作token；这些技术严格来说不属于Reduce/Reuse/Compress中的任何一类，或属于"复用"的延伸但边界模糊。
- **修正建议**：将"穷尽所有可能"改为"实用分类框架，覆盖绝大多数工程实践"，明确说明系统层调度优化可视为第四类或归入复用大类。
- **修正状态**：✅ **已采纳修正**
- **修正说明**：第五章开头和结尾均已修改，明确说明这是实用分类框架而非数学完备集，补充了系统层调度优化的说明。

### D-02 🟡 中等：现代注意力技术对O(n²)复杂度的影响未说明
- **文件位置**：01-principles/01-first-principles.md（第三章）
- **问题描述**：文档中O(n²d)复杂度作为核心公理，但没有说明Flash Attention、Sliding Window Attention、GQA/MQA等现代技术已改变实际计算特征。虽然从第一性原理角度O(n²)仍然是理论基线，但工程实践中n增长带来的实际延迟增长并非严格4倍关系。
- **修正建议**：在第三章开头补充"重要前提说明"，区分理论复杂度与实际工程表现，说明现代优化技术的影响。
- **修正状态**：✅ **已采纳修正**
- **修正说明**：新增3.0节"重要前提说明：标准注意力vs现代优化"，用表格列出Flash Attention、SWA、GQA、PagedAttention对复杂度的影响，并给出结论。

### D-03 🟡 中等：实施路线图收益数据过于乐观且无前提条件
- **文件位置**：02-methods/00-methods-overview.md（实施路线图章节）
- **问题描述**：阶段1预期"成本降低50-70%，吞吐量提升5-10倍"没有说明适用场景和前提条件：①吞吐量提升5-10倍仅适用于自托管场景从Transformers Pipeline迁移到vLLM；②API用户无法获得吞吐量提升；③低流量、短提示、单轮问答场景成本降低可能只有20-30%；④5-10倍吞吐是理想情况，实际取决于batch size、序列长度分布等因素。
- **修正建议**：补充收益前提条件，区分API用户和自托管用户，说明适用场景。
- **修正状态**：✅ **已采纳修正**
- **修正说明**：阶段1预期收益已补充前提说明，区分场景给出合理预期。

## 四、学术研究者视角（技术准确性攻击）

### A-01 🔴 严重：O(n²)复杂度表述未区分计算复杂度和IO复杂度
- **文件位置**：01-principles/00-facts.md（事实10-14）、01-principles/01-first-principles.md（第三章）
- **问题描述**：文档中"O(n²d)"表述过于笼统。Flash Attention的核心贡献正是发现Transformer推理的瓶颈不是计算而是HBM内存访问——Flash Attention的计算复杂度仍然是O(n²d)，但IO复杂度从O(n²)降到O(n)，这是它实际加速的原因。Sliding Window Attention（Mistral采用）将注意力限制在窗口w内，计算复杂度变为O(nwd)，是真正降低了计算复杂度。文档将这些混为一谈不够准确。此外，GQA/MQA减少KV头数但不改变QK^T矩阵维度，也不改变注意力计算复杂度——它减少的是KV缓存内存和带宽，这点也需要澄清。
- **修正建议**：同D-02，在第三章开头补充详细说明，区分计算复杂度、IO复杂度、内存复杂度，准确说明各技术的影响。
- **修正状态**：✅ **已采纳修正**（与D-02合并修正）
- **修正说明**：新增3.0节表格中准确区分了各技术对计算复杂度、IO复杂度、内存利用率的影响。

### A-02 🟡 中等：关键学术论文引用缺失，事实清单来源质量参差不齐
- **文件位置**：01-principles/00-facts.md
- **问题描述**：事实清单的来源大量是CSDN博客、微信公众号文章、商业网站，缺少原始论文引用。关键技术如BPE(1994/2016)、Flash Attention(2022)、PagedAttention(2023, SOSP)、Speculative Decoding(2023)、LLMLingua(2023)、GPTQ/AWQ量化等都没有引用原始论文。
- **修正建议**：为关键事实补充原始论文引用，博客来源作为辅助说明。
- **修正状态**：🟡 记录在案（后续版本补充论文引用）

### A-03 🟡 中等：输出/输入价格比"3-8倍"范围过宽，掩盖厂商差异
- **文件位置**：01-principles/00-facts.md（事实27）、01-first-principles.md（T4）
- **问题描述**："主流厂商输出token单价为输入token的3-8倍"这个范围太宽，实际上不同厂商差异极大：OpenAI是6倍($5→$30)，Anthropic是5倍($5→$25)，DeepSeek V4-Flash是2倍(1元→2元)，Qwen3.5-Flash是10倍(0.2元→2元)。用一个宽范围平均会掩盖重要的决策信息——不同厂商定价策略不同，优化侧重点也应不同。
- **修正建议**：保留"3-8倍"作为经验范围，但补充说明不同厂商差异大，并列举典型厂商的实际比率。
- **修正状态**：🟡 记录在案（后续版本补充）

### A-04 🟡 中等：技术分类边界存在混淆
- **文件位置**：02-methods/00-methods-overview.md（技术分类总表）
- **问题描述**：将"量化"归入"压缩"路径、"推测解码"归入"复用"路径存在边界争议：量化是模型层面降低数值精度，不是"用更少token传递信息"，而是降低每个token的计算成本；推测解码是计算顺序优化（用小模型猜测+大模型验证），不是"复用已计算结果"。分类框架本身可以实用化，但应该说明分类的模糊地带，避免读者以为这是严格的学术分类。
- **修正建议**：在分类总表前补充说明分类的实用主义性质，指出边界模糊的案例。
- **修正状态**：🟡 记录在案（已在第五章说明，分类表可补充脚注）
