# 创作过程记录：从资料收集到内容撰写

> 本文件记录《Agent评测方法论》Wiki教程的完整创作过程，涵盖**资料收集、框架搭建、内容撰写**三个阶段（审核修订阶段在V对抗审查完成后补充）。记录的目的是复盘创作方法论，沉淀可复用模式。

---

## 阶段一：资料收集（R阶段）

### 目标
围绕"Agent评测体系化建设方法论"收集权威、可追溯的一手资料，为后续分析提供事实基础。

### 决策依据
- **内容敏感度预检**：判定为公开内容（基于公开论文/官方文档/企业博客），采用标准工作流，产出物位于知识库目录。
- **信源选择**：优先学术论文（arXiv）、官方文档、企业技术博客；覆盖 2022-2026 年，兼顾经典与最新。
- **信源广度**：收集 25 个权威来源（F-061），覆盖评测框架、指标、流程、案例、挑战、数据集六大主题。

### 挑战与解决
- **挑战**：Agent评测领域信息分散，框架众多且更新快。
- **解决**：按"框架→指标→流程→案例→挑战→数据集"六类主题分类收集，逐类核实出处并编号（F-001~F-063），确保每一条事实可追溯到原始来源。

### 产出
- [R阶段事实清单](fact-list.md)：63 条客观事实，通过 G1 质量门（事实无因果词、可追溯、数据完整）。

## 阶段二：框架搭建（F阶段 + I阶段）

### 目标
从本质出发界定问题、提炼公理、重构框架，并产出驱动内容深度的核心洞察。

### 思考过程
- **问题界定**：Agent评测的表面问题是"怎么打分、怎么跑benchmark"，本质问题是"如何可信地判断Agent是否真正满足用户与业务的价值观需求"。这个界定颠覆了"跑个分"的直觉。
- **要素识别**：将评测体系拆解到不可再分的最小单元（评测目标、测试用例、评分标准、执行器、分析器、迭代回路），确认这是任何评测体系的共通骨架。
- **公理提炼**：从六个基础单元自下而上提炼 6 条不证自明的公理（价值锚定/单一事实源/能力可测/闭环驱动/成本约束/多源互证）。
- **假设剥离**：列出并逐条质疑行业 10+ 个默认假设（如"评测分数越高=产品越好"），多数被推翻。

### 决策依据：为什么选六大模块？
从公理 A1-A6 自下而上重构，天然推导出 wiki 的六大模块：
1. 方法论概述 ← 公理 A1/A2（价值与事实锚定）
2. 核心框架对比 ← 公理 A3（"行为测量"载体选择）
3. 关键指标 ← 公理 A2/A5/A6（度量与取舍）
4. 八阶段实施 ← 公理 A4/A5（流程与成本）
5. 行业案例 ← 公理 A1（价值锚定实证）
6. FAQ ← 公理 A2/A6（避坑与落地）

这不是拍脑袋定的模块，而是从第一性原理推导出的必然结构。

### 决策依据：为什么是四维指标体系？
基于事实清单中 IETF 的四层安全框架（F-015）、能力/效率指标（F-012/F-014）、人本/商业指标（F-020/F-021），归纳为四个正交维度：能力（能不能做对）、效率（成本速度）、安全（会不会闯祸）、人本与商业（是否创造价值）。四维覆盖"从能力到价值"的完整链路。

### 挑战与解决
- **挑战**：如何避免"正确的废话"（如"评测很重要"这类无信息量的洞察）？
- **解决**：通过 I 阶段的四元组硬约束（陈述+证据+反常识+行动），强制每条洞察有反常识点和可执行的行动建议，通过 G2 质量门。

### 产出
- [F/I阶段分析](first-principles-and-insights.md)：6 条公理、10+ 假设挑战、3 条核心洞察（含完整四元组），通过 G2 质量门。

## 阶段三：内容撰写（E阶段，本阶段记录）

### 目标
将前两阶段的产出转化为结构清晰、内容详实、可操作的 Wiki 教程正文。

### 思考过程：如何平衡深度与可读性？
这是内容撰写阶段最大的挑战。专业内容（如 IETF 55 项安全指标、pass@k 公式）容易写得艰深，而教程面向的读者背景差异大。

**解决方案**：采用"三层表达"策略——
1. **通俗层**：每个专业术语首次出现时附一句"通俗解释"（如"评测指标=考试分数"）。
2. **结构层**：用表格、Mermaid 图、决策树降低理解成本，信息密度高且易扫读。
3. **深度层**：保留公式、参考阈值、事实编号引用，满足专业读者追根究底。

### 思考过程：如何组织复杂信息？
**解决方案**：
- **模块化**：按 README 规划的六大模块组织，每个模块一个目录，模块内再按主题拆分文件（如模块3按四维拆成5个文件）。
- **四维指标拆分**：模块3 因需覆盖 50+ 指标，拆分为"总览 + 能力 + 效率 + 安全 + 人本与商业"5 个文件，避免单文件过大、便于按需查阅。
- **一致化**：统一 frontmatter 格式、章节小结、延伸阅读与表格风格，保持整套教程的一致性。

### 思考过程：遇到哪些表达困难？如何解决？
- **困难1：指标数量多且易混淆**。
  - **解决**：每个指标采用统一的"定义/测量方法/参考阈值"三段式，并配汇总表，让读者快速对照。
- **困难2：框架对比维度多**。
  - **解决**：先提炼"目标/载体/判定/产出"四条主线，据此设计 8 个对比维度，避免维度零散。
- **困难3：抽象公理难以落地**。
  - **解决**：在概述模块中明确标注每条公理对应哪个模块、支撑哪个误区剖析，让公理"看得到、用得上"。

### 挑战与解决
- **挑战**：如何确保内容有据可依、不编造？
- **解决**：每个关键论点都回引事实编号（F-xxx），并在"延伸阅读"指向事实清单与 F/I 分析，形成可追溯的证据链。

### 产出
- 模块1：方法论概述（[01-methodology-overview.md](../01-overview/01-methodology-overview.md)）
- 模块2：核心框架对比（[02-core-frameworks.md](../02-frameworks/02-core-frameworks.md)）
- 模块3：关键指标体系（[03-metrics-overview.md](../03-metrics/03-metrics-overview.md) 等 5 个文件）

### 模块4-6撰写的补充思考
- **模块4（实施步骤）**：核心挑战是把"八阶段流程"写成"可照做的操作手册"而非概念罗列。解决：每阶段统一用"输入/输出/工具/验收标准/常见坑"五段结构，并补充 0-8 周落地清单，让读者获得"立即能上手"的路径。
- **模块5（行业案例）**：核心挑战是"案例真实可信不编造"。解决：所有案例严格基于事实清单（F-030~F-037），每个案例统一用"背景/做法/成果/经验教训/可复用要点"五要素，并做跨案例对比提炼共性规律，避免"案例罗列"。
- **模块6（FAQ）**：核心挑战是"FAQ有真实价值而非凑数"。解决：22 条 FAQ 严格分"选型/实施/踩坑"三类，每条给出可操作的对策并回引事实编号，确保"问得到痛点、答得出解法"。

### 产出（模块4-6）
- 模块4：八阶段实施步骤（[04-implementation-overview.md](../04-implementation/04-implementation-overview.md)）
- 模块5：8个行业案例（[05-cases-overview.md](../05-cases/05-cases-overview.md)）

## 阶段四：审核修订（V对抗审查）

### 目标
对全部内容进行四视角对抗审查，暴露逻辑漏洞、可读性问题、落地风险与时效性问题，并采纳有价值的意见进行实质性修订。

### 思考过程
- **四视角设计**：采用魔鬼代言人（逻辑攻击）、新人（可读性攻击）、老板（ROI攻击）、未来（时效性攻击）四视角，确保从多个利益相关方立场审视内容。
- **审查产出**：共 17 条意见（魔鬼代言人5 + 新人4 + 老板4 + 未来4），按 P0-P3 分级。

### 决策依据：如何取舍冲突意见？
- **分级原则**：P0 严重必修、P1 重要采纳、P2 一般部分采纳、P3 轻微记录。
- **采纳范围**：采纳 5 条 P1 意见（幸存者偏差、LLM-Judge矛盾澄清、缺最小示例、投入产出不清、中小团队适用性），进行实质性修订。
- **取舍理由**：优先采纳魔鬼代言人与老板视角（直接关系到"读者是否被误导"与"是否可落地"），未来视角的 P2/P3 意见记录为迭代 TODO，避免内容膨胀偏离主线。

### 挑战与解决
- **挑战1：不同视角意见冲突**（魔鬼代言人说"全是成功案例是幸存者偏差"，未来视角说"应讨论评测被滥用"）。
  - **解决**：都以"内容偏正面"为准判定，优先采纳影响"读者判断"与"落地可行性"的意见。
- **挑战2：修订范围控制**。17条意见全采纳会导致内容膨胀。
  - **解决**：严格遵循分级原则，只对 5 条 P1 做实质性修订，其余记录为 TODO。
- **挑战3：避免表演式审查**。每条修订都记录"修订前/修订后/位置"三要素，确保可追溯、可验证。

### 产出
- [V阶段对抗审查记录](adversarial-review.md)：17 条意见 + 5 条采纳修订对比，通过 V 门。
