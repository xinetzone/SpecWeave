# R阶段事实清单

> 本文件是七概念方法论 **R（复盘）阶段** 的产出物，收录 Agent 评测体系化建设的客观事实。所有条目为可验证的客观陈述，不含因果推断与主观评价。通过 G1 质量门（事实无因果词、可追溯、数据完整）。

---

## 一、评测框架事实

- **F-001**：HELM 由斯坦福大学 CRFM 团队于 2022 年提出，代表论文为《Holistic Evaluation of Language Models》（arXiv:2211.09110）。
- **F-002**：HELM 评测维度包括准确率、校准度、鲁棒性、公平性、有偏行为、毒性、效率（推理延迟与成本）。
- **F-003**：MT-Bench 由加州大学伯克利分校 LMSYS 组织于 2023 年提出，代表论文为《Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena》（arXiv:2306.05685）。
- **F-004**：MT-Bench 使用 GPT-4 作为裁判，对模型多轮对话回答进行 1-10 分的主观评分。
- **F-005**：AgentBench 由清华大学于 2023 年提出，代表论文为《AgentBench: Evaluating LLMs as Agents》（arXiv:2308.03688）。
- **F-006**：AgentBench 覆盖操作系统、数据库、知识图谱、数字卡牌游戏、横向思考等 8 个真实交互环境。
- **F-007**：AutoEval 是 OpenAI 于 2024 年公开的 Agent 自动化评测实践，见官方博客《How we evaluate our agents》。
- **F-008**：τ-bench 由 Sierra 公司于 2024 年提出，代表论文为《τ-bench: A Benchmark for Tool-Agent-User Interaction in Real-World Domains》（NeurIPS 2024）。
- **F-009**：τ-bench 模拟真实用户与客服/零售 Agent 交互，评测工具调用与策略学习能力。
- **F-010**：AgentBoard 由中科院计算所等机构于 2024 年提出，代表论文为《AgentBoard: An Analytical Evaluation Board for Multi-turn LLM Agents》（arXiv:2401.13178）。
- **F-011**：AgentBoard 提供分步进度追踪、中间奖励曲线与错误类型归类，面向长程多步 Agent 任务。

## 二、指标体系事实

- **F-012**：能力维度指标包括任务完成率、推理规划、工具调用正确率、记忆管理召回率。
- **F-013**：任务完成率定义为成功 case 数与总 case 数的比值。
- **F-014**：效率维度指标包括平均响应时间（P50/P95）、推理成本（$/任务）、Token 消耗、GPU 利用率、并发吞吐。
- **F-015**：IETF 提出 LLM/Agent 安全评估分层框架，共 4 层、55 项具体指标。
- **F-016**：IETF 安全框架第 1 层（输入/提示层）覆盖提示注入、越狱、敏感信息泄露、毒性输入检测。
- **F-017**：IETF 安全框架第 2 层（模型/推理层）覆盖幻觉率、越界输出、偏见、推理鲁棒性、指令遵循偏离。
- **F-018**：IETF 安全框架第 3 层（工具/行动层）覆盖工具滥用、权限越界、危险操作、数据外泄、供应链攻击。
- **F-019**：IETF 安全框架第 4 层（系统/治理层）覆盖审计可追溯、日志完整、合规性、责任制、风险评估流程。
- **F-020**：人本维度指标包括用户满意度（CSAT/NPS）、可解释性评分、拒绝率、情感倾向、公平性暴露。
- **F-021**：商业维度指标包括转化率、用户留存、成本收益比（ROI）、业务指标提升量、客户流失率变化。

## 三、实施流程事实

- **F-022**：八阶段实施流程为：评测规划→体系设计→资产构建→自动化执行→人工校准→数据分析→迭代优化→生产监控。
- **F-023**：评测规划阶段输入为业务目标、Agent 需求、资源约束，输出为评测目标、范围、KPI 定义。
- **F-024**：体系设计阶段输入为评测目标与指标模板，输出为指标体系、评分权重、评测协议。
- **F-025**：资产构建阶段输出为基准数据集、测试环境、Ground Truth。
- **F-026**：自动化执行阶段的工具包括 LangSmith、OpenAI Evals、自建评测管线。
- **F-027**：人工校准阶段用于对 LLM-as-Judge 结果进行纠偏与双人复核。
- **F-028**：数据分析阶段输出洞察报告与错误归类，支撑迭代优化。
- **F-029**：生产监控阶段输出实时质量指标与告警，形成在线反馈回路。

## 四、行业案例事实

- **F-030**：OpenAI 自建 AutoEval 评测管线，将 LLM-as-Judge 与人工抽检结合。
- **F-031**：LangChain 的 LangSmith 平台提供评测与追溯一体化功能，支持数据集与回归测试。
- **F-032**：Similarweb 使用 LLM-as-Judge 评测数据提取 Agent，并通过人工校准纠偏。
- **F-033**：Nubank 在金融场景强调安全与合规 KPI，执行严格权限与审计。
- **F-034**：AWS Motorway 使用 Bedrock AgentCore 进行评测与监控。
- **F-035**：JPMorgan 金融数据 Agent 评测强调准确可靠与可追溯，设置高精度阈值与审计日志。
- **F-036**：Harvey 法律 AI 评测强调专业正确性，由人工律师复核。
- **F-037**：IBM 自研 JudgeIt 评测平台，实现自动化多维度评测。

## 五、挑战与解决方案事实

- **F-038**：可复现性挑战源于 LLM 随机性、环境非确定性、不同版本差异。
- **F-039**：可复现性解决方案包括固定种子、锁定模型版本、容器化环境、统一协议。
- **F-040**：LLM-as-Judge 存在 4 种偏差：位置偏差、冗长偏差、自我增强偏差、推理局限偏差。
- **F-041**：位置偏差指回答排列顺序影响评分，通过多次乱序重排取平均缓解。
- **F-042**：冗长偏差指越长的回答越易获高分，通过长度归一化与控制长度缓解。
- **F-043**：自我增强偏差指裁判偏爱与自身同源/同族的模型，通过多裁判交叉、异源裁判缓解。
- **F-044**：推理局限偏差指裁判无法识别深层逻辑错误，通过人工抽检与结构化评分缓解。
- **F-045**：奖励黑客指 Agent 学会欺骗奖励函数而非真正完成任务。
- **F-046**：奖励黑客解决思路包括环境加固（Environmental Hardening）、奖励设计抗性测试、多指标交叉验证。
- **F-047**：数据污染指训练集与测试集重叠导致性能虚高。
- **F-048**：数据污染最新综述（Nourbakhsh 等，UTSA，2026）系统性回顾 55 篇研究，提出四层污染分类（T1-T4）与五类检测方法。
- **F-049**：数据污染可导致性能虚高 6%-40%，相关研究包括推理时去污染（ITD）与跨语言污染。
- **F-050**：长程误差累积指长程多步任务中单步误差随步数累积放大，稀疏奖励导致信用分配困难。
- **F-051**：长程评测的信用分配方案包括 HCAPO（事后反思细化步骤级 Q 值）、GiGPO（双层分组细粒度信用分配）、Multiplicative Gated Rewards（乘法门控）。

## 六、基准数据集事实

- **F-052**：GAIA 包含 466 道真实世界问题，需多步推理与工具使用。
- **F-053**：SWE-bench 包含 2294 个真实 GitHub issue，用于代码 bug 修复能力评测。
- **F-054**：SWE-bench Verified 是 500 个人类验证的可靠子集。
- **F-055**：WebArena 包含 812 个网页任务，用于真实网站端到端任务评测。
- **F-056**：OSWorld 包含 369 个操作系统任务，用于桌面/操作系统操作评测。
- **F-057**：τ-bench 数据集覆盖客服/零售领域任务，用于工具调用型 Agent 评测。
- **F-058**：WebShop 包含约 12k 商品，用于电商网页购物交互评测。
- **F-059**：ALFWorld 覆盖 6 类家务任务，用于文本版嵌入式导航评测。
- **F-060**：HumanEval 包含 164 道编程题，是代码生成经典基准。
