# 模块6：常见问题解答

> **方法论视角**：本模块以问答形式覆盖评测选型、实施与踩坑三类高频问题。若需完整的术语解释与权威参考来源（学术论文、官方文档、开源项目），请参阅 [工程手册 · 第10章 术语表与参考资源](../../agent-evaluation-wiki/10-resources.md)。

> 本模块汇总 Agent 评测落地中的常见问题，按**选型、实施、踩坑**三类组织，共 22 条 FAQ（基础事实见附录事实清单）。

## 一、选型类（8条）

**Q1. 应该用哪个开源评测框架？**
A：先定评测对象与阶段（见模块2决策树）——模型底子用 HELM，对话质量用 MT-Bench，Agent泛化用 AgentBench，垂直领域用 τ-bench，长程诊断用 AgentBoard，生产落地参考 AutoEval 思路。多数团队会组合使用。

**Q2. 自建评测管线还是用现成平台？**
A：小团队起步推荐现成平台（LangSmith、OpenAI Evals）快速跑通；规模化后自建沉淀能力（如 IBM JudgeIt）。判断标准是评测资产是否成为核心竞争壁垒。

**Q3. 评测指标应该选多少个？**
A：遵循北极星原则——1-2 个核心北极星指标 + 分层辅助指标，避免指标爆炸。具体参考模块3。

**Q4. 需要覆盖多少测试用例？**
A：无绝对数量，但需覆盖目标能力的各子维度，且 Ground Truth 经人工核验。用例过少（<20）无统计意义。

**Q5. 评测环境要和线上完全一致吗？**
A：能力维度可离线简化，但关键业务场景需接近真实环境（呼应用户价值锚定）。强监管场景建议真实级环境。

**Q6. 应该多久评测一次？**
A：开发期每次变更回归；发布前完整评测；生产期持续监控。频率取决于迭代速度与业务风险。

**Q7. 安全指标需要全部覆盖吗？**
A：强监管领域（金融/法律/医疗）按 IETF 完整 55 项实施；一般场景选关键代表指标（模块3.6 的 20 项）。

**Q8. 需要成立专门的评测团队吗？**
A：规模化后建议专人负责（规划者/执行者/分析者/校准者多角色）。小团队可先由工程师兼任，但需明确职责。

## 二、实施类（8条）

**Q9. 评测结果不可复现怎么办？**
A：固定随机种子、锁定模型版本、容器化环境、统一评测协议（F-039）。逐项排查环境差异。

**Q10. LLM-as-Judge 评分不准怎么办？**
A：识别并缓解 4 种偏差（F-040）：乱序重排缓位置、长度归一缓冗长、多裁判交叉缓自我增强、人工抽检缓推理局限。

**Q11. 如何确定 Ground Truth？**
A：由领域专家标注，双人复核（呼应 F-027 人工校准）。避免由单一标注者主观决定。

**Q12. 长程任务评测失败无法定位怎么办？**
A：采用分步进度追踪（AgentBoard 思路，F-011）与细粒度信用分配（HCAPO/GiGPO，F-051），定位失败步骤而非只看最终成败。

**Q13. 评测成本太高怎么办？**
A：分层评测——小样本快筛 + 大样本精测；优化 Token 效率（模块3.5）；对 LLM 裁判按比例抽检而非全量。

**Q14. 如何把评测接入 CI/CD？**
A：设定每次模型/Agent 变更的自动回归评测（F-026），用脚本触发、结果门禁（达标才放行）。

**Q15. 人工校准应该抽检多少比例？**
A：建议固定比例（如10%-20%）随机抽检，并记录校准偏差率作为体系健康度指标；偏差率高时提高抽检比例。

**Q16. 评测报告应该包含哪些内容？**
A：执行摘要、四维指标结果、错误归类、趋势对比、改进建议。避免只给一个综合分数。

## 三、踩坑类（6条）

**Q17. 为什么评测分数虚高？**
A：很可能是数据污染（F-049）——测试集与训练集重叠，虚高可达 6%-40%。需定期审查评测数据是否被污染。

**Q18. Agent 学会"作弊式应试"怎么办？**
A：这是奖励黑客（F-045）。对策：环境加固、奖励设计抗性测试、多指标交叉验证（F-046）。

**Q19. 为什么评测结论很快过时？**
A：评测漂移（F-047）——数据、模型、环境随时间变化。需定期审查更新评测资产，建立持续闭环。

**Q20. 指标涨了但业务没涨怎么办？**
A：指标可能测偏了（测到的不是真正有用的能力）。检查指标是否锚定业务价值，建立功能→性能→业务三层因果链路。

**Q21. 评测团队只信自动化指标怎么办？**
A：这是"过度自动化"反模式。需理解自动化无法覆盖主观维度（用户体验、创造性），结合人工评估。

**Q22. 团队没有评测经验从哪开始？**
A：从模块1的成熟度自评开始，走模块4的0-8周落地清单，先垂直跑通最小闭环，再逐步扩展。
