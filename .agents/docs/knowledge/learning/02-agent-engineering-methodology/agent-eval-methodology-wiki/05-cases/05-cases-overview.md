# 模块5：8个行业案例分析

> **方法论视角**：本模块按"背景/做法/成果/经验教训/可复用要点"五要素解析 8 个企业案例。若需按场景视角（Coding Agent/RAG Agent/多工具/多Agent 协作）阅读评测实践与反模式，请参阅 [工程手册 · 第7章 行业实践案例](../../agent-evaluation-wiki/07-industry-practices.md)。

> 本模块通过 8 个真实企业案例，展示 Agent 评测方法论在不同领域、不同场景的落地形态（基础事实见 F-030~F-037）。每个案例按"背景/做法/成果/经验教训/可复用要点"五要素解析，帮助读者从中提炼适用于自身场景的做法。

## 5.1 OpenAI：AutoEval 自动化评测管线

- **背景**：OpenAI 需要大规模评测其产品级 Agent，平衡自动化效率与人工准确性。
- **做法**：自建 AutoEval 评测管线，将 LLM-as-Judge 与人工抽检结合（F-030）。
- **成果**：形成可落地、可复现的产品级评测范式（F-007）。
- **经验教训**：自动化与人工校准互补，不能偏废。
- **可复用要点**：评测管线工程化——自动化跑量 + 人工兜底校准。

## 5.2 LangChain：LangSmith 评测与追溯一体化

- **背景**：LangChain 需要为其 Agent 框架使用者提供评测能力。
- **做法**：LangSmith 平台提供评测与追溯（Tracing）一体化功能，支持数据集与回归测试（F-031）。
- **成果**：评测与可观测性打通，用户可追踪每次执行的完整轨迹。
- **经验教训**：评测与追溯结合，让"测到什么"与"为什么"可对照。
- **可复用要点**：评测数据与执行轨迹关联，便于归因分析。

## 5.3 Similarweb：数据提取 Agent 的人工校准

- **背景**：Similarweb 用 Agent 做数据提取，需保证数据质量。
- **做法**：使用 LLM-as-Judge 评测数据提取 Agent，并通过人工校准纠偏（F-032）。
- **成果**：兼顾自动化效率与数据准确性。
- **经验教训**：内容提取类任务，LLM裁判需人工校准，避免质量偏差。
- **可复用要点**：数据型 Agent 评测 = LLM自动评分 + 人工抽检校准。

## 5.4 Nubank：金融场景的安全与合规

- **背景**：Nubank 是金融科技公司，Agent 涉及资金与敏感数据。
- **做法**：在金融场景强调安全与合规 KPI，执行严格权限与审计（F-033）。
- **成果**：守住金融底线，满足强监管要求。
- **经验教训**：金融场景安全指标是"一票否决"底线，而非加分项。
- **可复用要点**：强监管领域按完整安全框架（如IETF四层）评测。

## 5.5 AWS：Motorway 的 Bedrock AgentCore 监控

- **背景**：AWS 需要为云上 Agent 提供评测与监控能力。
- **做法**：使用 Bedrock AgentCore 进行评测与监控（F-034）。
- **成果**：云原生环境下的评测与生产监控一体化。
- **经验教训**：评测要与生产监控打通，形成在线闭环。
- **可复用要点**：生产监控是评测闭环的终点（呼应八阶段第⑧阶段）。

## 5.6 JPMorgan：金融数据 Agent 的准确性与可追溯

- **背景**：JPMorgan 金融数据 Agent 处理高价值数据，容错率极低。
- **做法**：评测强调准确可靠与可追溯，设置高精度阈值与审计日志（F-035）。
- **成果**：满足金融级准确性与审计要求。
- **经验教训**：高价值场景需高精度阈值 + 完整审计追溯。
- **可复用要点**：金融数据评测 = 高准确率阈值 + 全链路可追溯。

## 5.7 Harvey：法律 AI 的专业正确性复核

- **背景**：Harvey 面向法律行业，输出需专业正确。
- **做法**：评测强调专业正确性，由人工律师复核（F-036）。
- **成果**：守住法律专业性与合规底线。
- **经验教训**：专业领域（法律/医疗）需领域专家人工把关，不能只靠自动化。
- **可复用要点**：专业领域评测 = 自动化初筛 + 领域专家复核。

## 5.8 IBM：JudgeIt 自动化多维度评测平台

- **背景**：IBM 需要规模化评测各类 Agent。
- **做法**：自研 JudgeIt 评测平台，实现自动化多维度评测（F-037）。
- **成果**：企业级评测基础设施，支持多场景复用。
- **经验教训**：规模化评测需自建平台沉淀能力。
- **可复用要点**：评测平台化，沉淀可复用的评测资产。

## 5.9 案例对比与启示

| 企业 | 领域 | 核心做法 | 可复用要点 |
|---|---|---|---|
| OpenAI | 通用产品 | AutoEval 自动化管线+人工抽检 | 自动+人工互补 |
| LangChain | 框架平台 | 评测+追溯一体化 | 评测与轨迹关联 |
| Similarweb | 数据提取 | LLM裁判+人工校准 | 数据型Agent人工校准 |
| Nubank | 金融科技 | 安全合规KPI+严格审计 | 安全一票否决 |
| AWS | 云平台 | AgentCore评测+监控 | 评测与监控打通 |
| JPMorgan | 金融数据 | 高精度阈值+审计日志 | 准确+可追溯 |
| Harvey | 法律 | 专业正确性+律师复核 | 专家人工把关 |
| IBM | 企业平台 | JudgeIt多维评测平台 | 评测平台化 |

**跨案例启示**：
1. **自动与人工互补**是普遍范式（OpenAI/Similarweb/Harvey）。
2. **强监管领域**（金融/法律）安全与专业正确性优先（Nubank/JPMorgan/Harvey）。
3. **评测与监控/追溯打通**是闭环关键（LangChain/AWS）。
