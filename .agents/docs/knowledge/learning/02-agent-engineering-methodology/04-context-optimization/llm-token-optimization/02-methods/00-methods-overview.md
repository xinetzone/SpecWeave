# LLM Token优化技术方法总览

本目录系统梳理大语言模型（LLM）token节省的五大类优化方案，总计35种具体技术，覆盖从提示词工程到推理引擎的完整优化栈。

## F阶段三大本质路径

所有token优化技术最终可归约为三条本质路径：

| 路径 | 核心思想 | 典型技术 |
|------|---------|---------|
| **减少（Reduce）** | 直接减少需要处理的token数量 | 精简提示词、截断、小模型路由、结构化输出 |
| **复用（Reuse）** | 复用已计算的结果，避免重复计算 | KV缓存、前缀缓存、PagedAttention、语义缓存、推测解码、多LoRA服务 |
| **压缩（Compress）** | 在保留信息的前提下用更少token表示 | 摘要、LLMLingua语义压缩、量化、蒸馏、实体提取、状态机 |

## 实施成本前置说明

> ⚠️ **重要前提**：以下时间估算基于**具备LLM应用开发经验的工程师**（有vLLM/LangChain使用经验、熟悉Transformer基本概念）。若团队为初级后端开发、无LLM相关经验，所有时间估算应乘以2-3倍，且建议优先选择P0级Checklist中无需架构改动的项（max_tokens、提示词精简、重试限制、监控告警）。

| 阶段 | 所需技能 | 人力投入估算（有经验） | 人力投入估算（初级） | 额外基础设施成本 |
|------|---------|---------------------|-------------------|----------------|
| 阶段1 | 提示词工程、基础推理引擎部署 | 1-2人×1-2周 | 1-2人×2-4周 | 无（API用户）/ 需GPU服务器（自托管） |
| 阶段2 | RAG基础、结构化输出、模型量化 | 1-2人×2-4周 | 2人×4-8周 | 向量数据库（语义缓存/RAG）、可观测工具费用 |
| 阶段3 | 模型路由、语义缓存、LoRA微调 | 2-3人×1-3月 | 不建议初级团队独立完成 | 标注数据成本（LoRA需1k-10k条）、向量数据库 |
| 阶段4 | 知识蒸馏、状态机、多LoRA服务 | 专职ML团队×持续 | 不建议 | 训练集群、ML工程团队人力成本（最高） |

**隐性成本提示**：
- A/B测试基础设施和流量分割需要开发工作
- 可观测工具（Helicone/Langfuse）有服务费用或自托管运维成本
- 语义缓存需要额外维护向量数据库和缓存失效策略
- 微调/蒸馏需要持续的数据收集、标注、模型迭代成本
- 任何优化都需要质量监控和回退机制，这部分投入常被低估

## 实施路线图（推荐顺序）

### 阶段1：快速见效（1-2周，有经验团队）
1. **提示词审计与精简**：所有现有提示词去除冗余、组织为"静态前缀+动态后缀"结构
2. **升级推理引擎**：从Transformers Pipeline迁移到vLLM，启用PagedAttention和连续批处理（自托管场景）
3. **启用前缀缓存**：开启API端Prompt Caching，组织提示词顺序最大化缓存命中
4. **基础对话截断**：实现系统消息保留+最近N轮截断的基础策略
5. **基础防护**：设置max_tokens、重试限制、成本监控（见P0 Checklist）

**预期收益（前提）**：适用于有一定流量、系统提示词较长、多轮对话场景，成本降低40-60%，吞吐量提升2-5倍（自托管）。若为低流量、短提示、单轮问答场景，收益可能只有20-30%。

### 阶段2：质量优化（2-4周）
1. **结构化输出**：所有API集成场景强制JSON/结构化格式输出
2. **RAG优化**：添加Reranker重排序、语义分块、相似度阈值过滤
3. **摘要缓冲记忆**：对话系统实现ConversationSummaryBufferMemory（摘要+近期原文）
4. **模型量化**：部署模型使用AWQ 4-bit量化
5. **消息优先级标记**：对系统/开发者/用户/工具消息分类标记优先级

**预期收益**：在阶段1基础上再降本20-40%，对话质量明显提升。

### 阶段3：高级优化（1-3月）
1. **小模型路由**：建立分类器将简单请求分流到小模型
2. **推测解码**：启用vLLM speculative decoding降低延迟
3. **语义缓存**：对高重复率场景（客服、FAQ）部署语义缓存
4. **实体提取与状态跟踪**：任务型对话提取关键实体存入结构化记忆
5. **LoRA微调**：对核心任务使用LoRA微调，缩短提示词同时提升效果

**预期收益**：在阶段2基础上再降本30-50%，端到端成本降低80-90%。

### 阶段4：极致优化（持续迭代）
1. **知识蒸馏**：超高并发场景蒸馏专用小模型
2. **状态机工作流**：流程化任务用状态机替代自由对话
3. **动态上下文窗口**：根据任务复杂度自适应调整上下文
4. **异步后台压缩**：压缩操作移出用户关键路径
5. **多LoRA服务**：多任务场景使用Multi-LoRA Serving提升GPU利用率

**预期收益**：特定场景再降本30-50%，支撑百万级用户规模。

## 关键原则

1. **分层组合而非单一技术**：没有银弹，五大类技术应组合使用，在不同层面同时优化
2. **质量优先于成本**：所有优化必须以质量监控为前提，建立"全上下文基线"对比质量
3. **ROI驱动优先级**：按"实施难度低+收益大"的顺序实施，不要一开始就做最复杂的
4. **可观测性是前提**：建立token成本、质量指标、缓存命中率、GPU利用率的监控看板
5. **回退机制不可少**：所有压缩/优化策略必须有阈值触发的回退机制，质量下降时自动扩大上下文/升级模型
