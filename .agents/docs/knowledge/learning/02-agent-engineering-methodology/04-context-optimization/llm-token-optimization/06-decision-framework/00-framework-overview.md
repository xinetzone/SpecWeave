## 从零开始 vs 已有系统优化：两种入口路径

### 路径A：从零开始搭建新系统
```
阶段0（第1天）：通读决策框架
  └─→ 识别你的场景（01-decision-tree.md）
  └─→ 理解反模式避免踩坑（04-anti-patterns.md）

阶段1（第1周）：基础设施层
  └─→ 升级到vLLM等现代推理引擎（启用PagedAttention+连续批处理）
  └─→ 接入可观测性网关（Helicone/Langfuse/Portkey）
  └─→ 按Checklist P0项配置基础防护

阶段2（第2周）：快速见效优化
  └─→ 提示词审计与精简（组织为静态前缀+动态后缀结构）
  └─→ 启用前缀缓存（Prompt Caching）
  └─→ 结构化输出约束
  └─→ 按场景选择第一优先级技术

阶段3（第3-4周）：质量优化
  └─→ 根据场景添加RAG/摘要记忆/模型路由
  └─→ 完成P1 Checklist项
  └─→ 建立A/B测试流程

阶段4（持续迭代）：高级优化
  └─→ 按ROI逐步实施P2项
  └─→ 沉淀适合自己业务的模式
```

### 路径B：已有系统优化（快速降本）
```
Day 1：可观测性审计
  └─→ 接入成本监控网关，识别Top 5花费项
  └─→ 检查P0 Checklist，立即修复明显问题（如无max_tokens限制）

Day 2-3：缓存优化（最大单个杠杆）
  └─→ 重构prompt结构为"静态前缀+动态后缀"
  └─→ 启用Prompt Caching，验证缓存命中率>50%
  └─→ 检查是否使用vLLM，如未用立即升级

Day 4-5：快速裁剪
  └─→ 精简系统提示词（目标减少30-50%长度，行为不变）
  └─→ 严格设置所有接口的max_tokens
  └─→ 添加结构化输出约束（JSON Schema）

Day 6-7：模型路由
  └─→ 建立三级模型分类：简单→Haiku/mini，中等→Sonnet/GPT-4o，复杂→Opus/GPT-5
  └─→ 限制重试次数（最多2-3次），添加熔断机制

Week 2+：持续优化
  └─→ 根据场景添加RAG/语义缓存/上下文压缩
  └─→ 建立质量监控和A/B测试流程
```

## 核心决策原则（来自案例萃取）

1. **可观测性先行**：所有成功案例第一步都是建立成本可见性——回答不了"钱花在哪里"就无法优化。
2. **缓存是最大单个杠杆**：正确结构化prompt（静态前缀+动态后缀）即可获90%折扣，几乎适用于所有场景。
3. **模型路由是标准配置**：60%+任务可用轻量模型完成且质量无感知差异，成本差10-60倍。
4. **输出Token优先优化**：输出Token成本是输入的3-8倍，控制输出长度的ROI远高于精简输入。
5. **渐进式优化而非大跃进**：先易后难（提示词→缓存→RAG→微调），每步验证收益再继续。
6. **质量是硬约束**：所有优化必须以质量监控为前提，建立"全上下文基线"对比质量。
7. **ROI驱动优先级**：按"实施难度低+收益大"的顺序实施，不要一开始就做最复杂的。
