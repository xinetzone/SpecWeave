# P-T-004: 输入精简模式

## 触发场景
- 向AI提问时习惯用客套话、长句子、大量铺垫
- 需要贴大段日志/配置/代码给AI看
- 提问模糊，需要AI反复确认需求
- 感觉AI"理解慢"、需要多轮才能get到点

## 核心步骤

1. **指令去客套**
   - 去掉"你好"、"麻烦帮我"、"谢谢"、"请仔细分析一下"等冗余词
   - 直接说需求和目标，不用礼貌性铺垫
   - ❌ 不好："你好，我想请你帮我看看这个Python代码可能有什么问题，麻烦你仔细分析一下，谢谢你了"
   - ✅ 好："检查#file:auth.py的性能问题，直接给修改建议"

2. **先全称后简称**
   - 第一次提概念用全称，之后用简称/代词
   - 例如：第一次说"Transformer注意力机制"，后面说"它"、"该机制"即可

3. **大内容文件化**
   - 大段日志、报错、配置、长代码（>50行）先保存到文件
   - 用`#文件名`引用，不要直接粘贴到输入框
   - AI读取文件和粘贴效果一样，但更省输入Token且可复用

4. **精准引用**
   - 需要AI看哪个函数/哪段代码，明确`#文件名`甚至行号
   - 不要说"看看整个项目"、"检查一下哪里有问题"
   - 给AI明确的范围，避免它自己遍历整个代码库

5. **结构化表达**
   - 用列表、Markdown格式分点
   - 减少自然语言连接词（"然后"、"其实"、"我觉得"等）
   - 需求/问题/期望分开说，结构清晰

6. **添加全局精简回答规则（一次性配置）**
   在全局规则中添加：
   ```markdown
   # Token节省规范
   - 默认极简回答：先给结论，再给必要解释，避免冗余修饰
   - 除非明确要求"详细解释"，否则不做背景铺垫
   - 列表优先，能用关键词不用完整句子
   - 代码修改直接给diff，不重复贴完整文件
   ```

## 反模式
❌ 提问用一大段客套话+背景铺垫，最后才说需求  
❌ 把1000行报错日志直接粘贴到输入框  
❌ "帮我看看这个项目有什么问题"（不指定具体范围）  
❌ 一次说多个不相关需求，让AI自己拆分  

## 预期收益
输入Token减少**20-40%**，AI理解需求更准确，减少歧义返工和反复确认。

## 额外收益
输入精简不仅省Token，还能让AI更快抓住重点，减少"理解偏差"导致的错误返工——返工的Token成本往往是原始问题的好几倍。

## 验证记录
- 论坛帖子1271推荐：一句话指令+简称+结构化格式可显著节省输入Token
- 符合Prompt工程中"清晰、具体、简洁"的基本原则
