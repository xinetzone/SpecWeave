# P-T-002: 对话清理模式

## 触发场景
- 一个对话已经超过15-20轮
- 对话中包含大量报错日志、工具调用、中间试错过程
- 发现AI开始"遗忘"之前的规则或重复犯错
- 解决完一个独立子任务（bug修复、功能模块写完）后

## 核心步骤

1. **识别断点**
   - 一个独立子任务完成即为断点：bug修复了、功能模块写完了、问题解答完了
   - 发现对话开始"绕圈子"、AI重复相同错误时也是断点

2. **保存成果**
   - 重要代码已经写入文件，不要依赖对话记忆
   - 关键结论、决策记录到项目文档或注释中
   - 需要复用的方案保存到对应文件，不要指望"下次还在这个对话里"

3. **新开对话**
   - 直接新开对话处理下一个任务
   - 不要舍不得"之前的上下文"——其中90%是无效内容

4. **必要时精准注入上下文**
   - 如果需要延续之前的结论，在新对话中简洁说明："继续之前的XX功能，参考#file:xxx.py中的实现"
   - 只引用必要的文件，不要把整个历史复述一遍

## 反模式
❌ 一个对话用一整天，从项目初始化聊到部署  
❌ 对话已经50+轮还硬扛，期待AI"记住"所有上下文  
❌ 把对话当记事本，所有结论都存在聊天历史里  
❌ 明明方向错了还继续聊，指望AI"自己悟出来"  

## 预期收益
动态上下文Token消耗减少**40-70%**，AI遵守规则准确率回升，减少返工和无效循环。

## 原理解释
- 上下文过长时，有效信息被稀释，AI"注意力"被无效内容占据
- 历史对话中的报错日志、工具返回值、试错过程都是无效Token，但每次请求都重新发送
- 这是ROI最高的单项优化——零成本，只改使用习惯

## 验证记录
- 社区论坛帖子1102列为排名第一的节省技巧
- 用户反馈"解决一个重开一个"是单项效果最明显的方法
- 符合"上下文只留必要"的Token优化基本原则
