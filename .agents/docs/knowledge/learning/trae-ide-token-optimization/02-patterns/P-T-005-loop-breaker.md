# P-T-005: 循环熔断模式

## 触发场景
- Agent模式下AI反复运行测试、反复读取同一个文件、反复修改相同代码
- AI陷入"试错→报错→修改→再试错"的死循环
- 添加自定义模型时需要安全护栏
- 无人值守跑任务担心超支

## 核心步骤

1. **人工熔断机制**
   - 发现AI连续3次做类似操作还没进展时，手动点击停止
   - 不要让它继续"试"——试错是最贵的Token消耗
   - 停止后给出明确反馈，指出错误方向，不要让它继续猜

2. **配置轮次上限（一次性配置）**
   - 添加自定义模型时，在高级配置中设置合理的「工具调用轮次」上限
   - 建议设置10-20轮，防止无限循环
   - 配置「单次响应最大Token数」，防止单次输出过长

3. **前置规划减少试错**
   - 复杂任务先让AI出方案（plan），你确认后再让它执行
   - 先写SDD（软件设计文档）明确需求、架构、接口，再开始编码
   - 需求不清时先问清楚，不要让AI"边做边猜"

4. **及时纠偏**
   - 发现方向错了立即打断，给出明确反馈
   - 不要等AI"自己发现错了"——它可能要试十几次才发现
   - 每完成一个小步骤就检查，不要等全部做完再回头改

5. **监控用量**
   - 定期在Trae后台查看Token消耗，发现异常增长及时排查
   - 关注大请求（≥$0.20）占比，超过20%说明存在很多无效循环
   - 新配置/新规则上线后第一天密切关注用量变化

## 反模式
❌ 开着Agent不管，让AI自己"试"半小时，结果消耗大量Token还是错的  
❌ 不设工具调用轮次上限，遇到bug死循环到额度耗尽  
❌ 不提前说清需求，让AI"自己看着办"，反复返工  
❌ 发现AI在错误方向上越走越远还不打断，期待它"自己修正"  

## 预期收益
避免**90%以上**的极端超支情况，大请求（≥$0.20）占比从18%降到5%以内，防止单次任务消耗正常10倍以上Token。

## 数据支撑
根据用户实测（帖子11921）：
- 18.4%的大请求消耗了51.9%的Token
- 大请求主要来自Agent无限循环和超长上下文
- 熔断机制可以消除大部分这类极端消耗

## 配置示例（自定义模型高级设置）
| 参数 | 建议值 | 说明 |
|-----|-------|------|
| 工具调用轮次上限 | 10-20轮 | 超过后自动停止，需要人工确认 |
| 单次响应最大Token | 2000-4000 | 防止幻觉输出过长内容 |
| 上下文窗口大小 | 根据模型实际能力设置，不要盲目开到最大 |
