# P-T-001: 静态减负模式

## 触发场景
- 配置Trae IDE环境后感觉响应变慢、Token消耗快
- 新接手项目发现AGENTS.md/规则文件很长（>200行）
- 添加多个MCP/Skills后单次请求成本明显上升

## 核心步骤

1. **规则精简**
   - AGENTS.md控制在200行以内
   - 删除过期、重复、过于琐碎的规范
   - 保留真正必须遵守的硬约束，删掉"最好"、"建议"类软约束

2. **拆分规则**
   - 将大规则文件按功能拆分成多个小文件（代码风格、Git规范、输出规范分开）
   - 设置为「智能生效」或「手动触发」
   - 不要全部设为「始终生效」

3. **MCP最小化**
   - 只开启当前任务需要的MCP服务器
   - 用完即关，不要为"以防万一"开着一堆
   - 不用时关闭Browser Use、数据库连接等重型MCP

4. **Skills按需启用**
   - 不常用的Skill不要启用
   - 第三方Skill按需安装，不要"全量安装"
   - 自己写Skill时description保持简短，触发词精准

5. **关闭不必要自动导入**
   - 不需要CLAUDE.md就关闭自动导入开关
   - 在「设置」→「规则」中管理导入选项

## 反模式
❌ AGENTS.md写500+行，把所有想到的"最佳实践"都堆进去  
❌ 所有规则文件都设为"始终生效"  
❌ 开启十几个MCP服务器，哪怕当前只写Python  
❌ 安装几十个第三方Skill，大部分从来不用  

## 预期收益
静态Token消耗减少**30-60%**，AI响应速度提升，遵守规则准确率提高。

## 反模式危害
- 静态成本占每次请求30-60%，且持续累积
- 规则越多AI越容易"注意力分散"，遵守关键规则的概率反而下降
- MCP工具定义每个都占用Token，积少成多
