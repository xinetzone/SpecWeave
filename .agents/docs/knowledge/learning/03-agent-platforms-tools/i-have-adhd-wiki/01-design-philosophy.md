# 二、设计理念

## 2.1 ADHD认知科学基础

i-have-adhd 的设计出发点**不是简单的"让AI说短点"**，而是基于对注意力工作模式的认知科学研究，系统性地适配特定类型的大脑认知特点。

传统的"简洁回复"往往只做到了文字量减少，但缺乏结构化的行动引导——对执行功能存在挑战的用户而言，一段没有明确下一步、没有状态重述、没有时间预期的简短文字，与冗长的客套话同样难以执行。

本项目的核心设计哲学是：**降低从"理解"到"执行"的认知摩擦**。所有10条输出规则都不是美学偏好，而是针对五条可验证的认知事实所做出的工程化应对。

> **立场声明**：本项目采用 "No ADHD diagnosis needed" 立场——这些输出优化对所有追求效率的用户都有价值，不要求使用者自我认同或确诊任何医学状况。认知科学原理在此作为设计输入，而非诊断依据。

## 2.2 五大核心认知事实

以下五条认知事实直接驱动了i-have-adhd的全部设计规则，源文件第23-31行原文如下：

```markdown
## What ADHD changes about reading

Five facts drive every rule below:

1. Working memory is small. Anything not on screen is forgotten. Do not ask the reader to "keep in mind X."
2. Knowing the answer is not doing the answer. The friction between "got it" and "done it" is where work dies.
3. Starting is the hardest step. The first action must be obvious, small, and doable now.
4. Time estimates feel uniform. "A bit of work" and "a few hours" register the same. Vague estimates fail.
5. Dopamine is scarce. Visible progress matters. Buried wins do not register.
```

### 2.2.1 工作记忆容量有限

**通俗解释**：人的工作记忆（Working Memory）就像电脑的RAM而非硬盘——容量有限，且掉电（注意力转移）即丢失。当用户阅读完一条AI回复，切换到编辑器开始操作时，回复中没有直接显示在当前屏幕上的信息（"请记住我们在第三步"、"前提是X已配置好"等）会快速从工作记忆中消退。要求用户"在脑海中记住X"本质上是在要求用户承担本应由界面/文档承担的状态保持责任。

**对应设计决策**：
- 每轮对话**重述当前状态**（第5条规则）：明确告知"第3步（共5步）已完成"
- 永远不要出现"请记住X"、"keep in mind"这类表述
- 多步骤任务使用编号列表，每个步骤都是自包含的，不依赖前文隐含上下文
- 关键上下文（文件路径、行号、命令）必须在需要它的步骤中重复出现，而不是只在开头提一次

### 2.2.2 知行鸿沟（知道≠做到）

**通俗解释**：认知心理学中的"知行鸿沟"（Knowledge-Action Gap）描述了一个普遍现象：理解了一个解决方案，并不等于能够执行这个解决方案。从"哦，我懂了"到手指放在键盘上开始敲代码之间，存在大量微小的决策摩擦——"我先开哪个文件来着？"、"具体改哪一行？"、"命令参数是什么？"——这些摩擦每一个都很小，但累积起来足以让工作停滞，用户转而刷手机或切到其他任务。

**对应设计决策**：
- **行动优先**（第1条规则）：回复第一行必须是可以直接执行的动作，而非上下文铺垫或思考过程
- 首行即可执行：命令、文件路径、代码片段直接放在最前面，解释性文字放在后面（如果有必要）
- 消除执行前的微小决策：不要让用户思考"第一步是什么"，直接告诉他
- 每个步骤只包含一个有界动作（第2条规则），避免一个步骤里出现多个"and then"

### 2.2.3 启动是最难的一步

**通俗解释**：任务启动（Task Initiation）是执行功能的核心组成部分。面对一个模糊的大任务（"重构认证模块"），大脑会感知到高门槛而触发拖延——不是因为懒，而是因为大脑无法清晰看到"第一步"是什么，从而进入回避状态。相反，如果第一步是一个极其微小、明确、可以在两分钟内完成的动作（"运行npm install jsonwebtoken"），启动门槛会大幅降低，而一旦开始，继续执行的惯性通常会自然产生。

**对应设计决策**：
- 首步必须**明显、微小、可立即执行**（第1、3条规则）
- 多步骤任务结尾必须给出一个明确的"两分钟内可完成的下一步"（第3条规则），哪怕只是"打开文件"这种小事
- 禁止开放性结尾（"有问题随时问我"），必须给出具体的可执行动作
- 列表项控制在5个以内（第9条规则）：5个有优先级的行动项，好过10个未排序的行动项——选择本身也是一种启动摩擦

### 2.2.4 时间感知模糊化

**通俗解释**：在缺乏具体时间锚点的情况下，大脑对任务耗时的感知会严重失真。"一点工作"（a bit of work）、"很快"、"需要点时间"这类模糊表述，在用户大脑中无法建立明确的预期——可能是5分钟，也可能是5小时，这种不确定性本身就是焦虑和拖延的来源。用户无法决定"现在开始做还是吃完饭再做"，因为他不知道这件事会占用多久。

**对应设计决策**：
- 使用**分钟/小时等具体时间单位**给出估计（第6条规则）
- 给出条件化估计（"如果测试已覆盖约15分钟，否则需要一下午"），而非单点估计
- 避免"一点"、"一些"、"很快"这类无单位的模糊量词
- 时间估计要面向执行者（在Agent环境中面向执行工具的调用者）

### 2.2.5 多巴胺稀缺

**通俗解释**：多巴胺是驱动动机和奖励感知的关键神经递质。当完成工作后看不到明确的成果反馈时，大脑无法获得完成任务的奖励感，动机会快速消退。"我改了半天到底有没有用？"——这种疑问会快速消耗本来就稀缺的动力资源。相反，明确展示"什么现在可以工作了"、"你已经完成了什么"，能够提供即时的正反馈，维持继续推进的动力。

**对应设计决策**：
- **成果可见**（第7条规则）：明确展示已完成的工作，用具体可验证的方式表述
- 不要把成果埋在冗长的总结段落里
- 好的成果描述应该是可立即验证的（"现在可以用魔法链接登录了，试试：npm run dev，打开/login"）
- 坏的成果描述是模糊的（"我对认证流程做了一些修改"）
- 完成每一步都要有明确的状态反馈，而非沉默推进

## 2.3 认知原理→设计规则映射表

五大认知事实系统性地映射到10条具体的输出规则上，形成完整的设计约束体系。本节先给出总览映射表，具体每条规则的详解、正反示例和边界情况见下一章「核心规则」。

| 认知事实 | 核心问题 | 直接映射的规则 |
|---------|---------|---------------|
| **工作记忆容量有限** | 屏幕外信息易丢失 | 规则2（多步骤编号）、规则5（每轮重述状态）、规则9（列表限5项） |
| **知行鸿沟** | 理解≠执行，摩擦导致停滞 | 规则1（首行是行动）、规则2（单步单动作）、规则4（抑制旁枝） |
| **启动门槛高** | 任务启动触发拖延 | 规则1（首步明显微小）、规则3（结尾给明确下一步）、规则10（无前缀无客套） |
| **时间感知模糊** | 模糊估计无法建立预期 | 规则6（具体时间单位）、规则8（错误平实陈述） |
| **多巴胺稀缺** | 缺乏即时反馈导致放弃 | 规则7（成果可见）、规则5（状态反馈）、规则3（小步闭环） |

**设计约束的整体逻辑**：
- 从回复开头（规则1、10）→ 中间结构（规则2、4、9）→ 每轮状态（规则5）→ 结尾闭环（规则3）→ 细节表达（规则6、7、8），覆盖了AI回复的全链路
- 每条规则都有明确的认知科学依据，而非主观风格偏好
- 规则之间存在协同效应：例如"首行行动+编号步骤+结尾下一步+状态重述"共同作用，系统性地降低启动和执行摩擦

## 2.4 理论溯源

i-have-adhd 的认知原理框架参考了成人ADHD领域的临床实践著作：

**参考书籍**：《The Adult ADHD Tool Kit: Using CBT to Facilitate Coping Inside and Out》
- 作者：J. Russell Ramsay & Anthony L. Rostain
- 领域：成人ADHD认知行为疗法（CBT）临床实践指南

**重要区分**：
需要特别强调的是，i-have-adhd **不是**在给AI编程助手加入临床治疗建议，也不是在做人类日常组织工具（如待办清单App、时间管理方法）的移植。它做的是一件更具体的事情：

> 将认知科学中关于注意力、工作记忆、执行功能的实证发现，**适配到LLM文本响应这一特定交互媒介**上。

传统的ADHD应对策略（如番茄工作法、外部化记忆、时间块划分）面向的是人类自我管理场景，而i-have-adhd面向的是"人类-AI对话"这一特定场景：
- 不是让用户自己写待办清单，而是AI直接输出结构化为可执行步骤的回复
- 不是让用户自己估算时间，而是AI在回复中给出具体时间估计
- 不是让用户自己记录进度，而是AI每轮自动重述状态
- 不是让用户自己寻找下一步，而是AI在结尾直接给出

这是一个媒介适配（Medium Adaptation）过程，而非简单的技巧搬运。

## 2.5 关键洞察：为什么"简洁"不等于"ADHD友好"

一个常见的误解是："只要回复简短就是对ADHD友好的"。这是一个危险的认知误区。

**反例说明**：
> "认证模块有问题，你去修一下。"

这句话非常简洁（只有12个字），但它：
1. ❌ 没有给出第一步做什么（启动门槛高）
2. ❌ 没有给出具体文件/行号（知行鸿沟大）
3. ❌ 没有时间估计（预期模糊）
4. ❌ 没有说清楚"修好"是什么样（成果不可见）
5. ❌ 没有下一步指引（闭环缺失）

对于存在执行功能挑战的用户而言，这样一句"简洁"的话，和一段500字的客套话一样难以执行——甚至更糟，因为它看起来像是给了答案，但实际没有给任何执行路径。

**真正的ADHD友好设计的判断标准**：

一个回复是否ADHD友好，**不是看它有多短**，而是看它能否通过以下测试：

> **首尾测试**：如果用户只读回复的第一行和最后一行，他是否知道：
> 1. 现在立刻该做什么？
> 2. 刚才已经完成了什么？

这是源文件第140行明确给出的发送前自检标准（pre-send check）：
> Then verify: if the reader reads only the first line and the last line, do they know (a) what to do next, and (b) what just happened?

这一洞察解释了为什么i-have-adhd的规则看起来有些"反直觉"——它不是在追求文字量最小化，而是在追求**执行摩擦最小化**。有时候为了降低执行摩擦，反而需要多写几行字（比如重述状态、给出时间估计、明确展示已完成工作）——这些文字不是冗余，是认知脚手架。
