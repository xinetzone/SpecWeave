# 十一、行动优先输出范式深度解析

> **【SpecWeave 方法论补充】** 本章基于七概念知识沉淀方法论，从 i-have-adhd 实践中提炼出可跨场景复用的 Agent 输出设计哲学框架——"行动优先 vs 解释优先"双范式决策体系。这是对 i-have-adhd 四条核心规则的元层面抽象，适用于所有 AI 交互场景。

---

## 11.1 两种输出范式：行动优先 vs 解释优先

i-have-adhd 的四条核心规则本质上服务于一个更宏观的设计决策：何时采用**行动优先**范式，何时采用**解释优先**范式。这不是非黑即白的二元选择，而是一个需要根据场景动态切换的连续谱。

### 11.1.1 11维度对比矩阵

| 维度 | 行动优先范式 | 解释优先范式 |
|------|------------|------------|
| **核心目标** | 降低从"理解"到"执行"的摩擦 | 降低从"未知"到"理解"的摩擦 |
| **首屏内容** | 答案/命令/结论直接呈现 | 背景/上下文/问题分析逐步展开 |
| **信息密度** | 高信噪比，剔除所有非必要信息 | 渐进式披露，铺垫必要认知基础 |
| **结构特征** | 编号步骤、单步单动作、明确收尾 | 逻辑递进、因果链、概念定义 |
| **用户状态假设** | 用户已理解问题，需要执行方案 | 用户不理解问题，需要认知框架 |
| **认知负荷** | 低（直接执行，无需额外决策） | 中（需要跟随思路，建立心理模型） |
| **Token效率** | 高（直奔主题，减少冗余） | 中（必要的铺垫解释不可省略） |
| **适用风险等级** | 低-中风险操作 | 中-高风险、首次接触、概念教学 |
| **时间压力适配** | 高压力、紧急场景 | 低压力、学习场景 |
| **新手友好度** | 低（假设用户能看懂命令） | 高（提供必要上下文） |
| **专家效率** | 高（无需忍受冗余铺垫） | 低（需要等待结论出现） |

### 11.1.2 两种范式的黄金结构（混合范式）

大多数场景下最优解不是纯行动优先或纯解释优先，而是采用混合范式——"结论前置+分层展开+用户可控"的三层黄金结构：

```
【首屏核心区】（30秒内可读完）
├─ 核心结论/答案/命令（第一行）
├─ 关键进度/状态（如需要）
└─ 立即要做的1-3个行动项

【中间详细区】（用户按需阅读）
├─ 详细操作步骤（编号，单一步骤）
├─ 关键注意事项/风险提示
└─ 预期结果/验证方法

【可选补充区】（用户深入时阅读）
├─ 原理解释/设计思路
├─ 备选方案/trade-off分析
├─ 延伸阅读/参考资料
└─ 💡 额外建议（现在做/以后做分类）
```

这一结构同时满足了高效用户的"快速获取答案"需求和学习型用户的"理解为什么"需求，将信息消费的控制权完全交还给用户。

## 11.2 认知负荷管理五条核心原则

行动优先范式的认知科学基础是认知负荷理论（Cognitive Load Theory）。i-have-adhd 的设计实践提炼出五条可复用的认知负荷管理原则：

### 原则1：初始位置资源最充足
- **原理**：工作记忆在信息接收初始阶段认知资源最充足，注意力最集中
- **设计应对**：最重要的信息（答案/命令/结论）放在第一行
- **反模式**：三段铺垫后才给出答案，初始注意力已被客套话消耗

### 原则2：外部认知卸载优于内部记忆
- **原理**：工作记忆容量有限（3-5个信息块），要求用户"记住X"本质上是在让用户承担认知负担
- **设计应对**：每轮重述进度、关键上下文在需要处重复出现、状态外部化
- **反模式**："还记得我们在第三步讨论的方案吗？"——用户不记得

### 原则3：单步认知原子化
- **原理**：每个决策点都消耗认知资源，一个步骤中包含多个"and then"会显著增加执行摩擦
- **设计应对**：编号步骤、单步单动作、每步只包含一个有界操作
- **反模式**："打开文件，修改配置，重启服务，然后测试"——这是4个动作却被塞进1个步骤

### 原则4：执行意向封装
- **原理**："如果X，那么做Y"的执行意向（Implementation Intentions）比模糊意图更易执行
- **设计应对**：具体的时间估计、明确的文件路径:行号、可复制粘贴的命令
- **反模式**："修改一下配置文件"——改哪个文件？用什么编辑器？改成什么？

### 原则5：认知信噪比最大化
- **原理**：无关信息会消耗注意力资源，干扰核心信息加工
- **设计应对**：压制客套话、抑制离题建议、去掉无信息含量的填充词
- **反模式**："好的，很高兴能帮到你！这个问题很有意思，让我想想……"——这些文字对执行毫无帮助

## 11.3 Agent输出设计决策框架

基于上述原则，i-have-adhd 项目隐含了一套可复用的输出设计决策框架，可通过"三问法"快速判断当前场景应采用何种范式。

### 11.3.1 范式决策三问

**第一问：任务的核心目标是什么？——执行还是理解？**
- **执行导向任务**（修复bug、执行命令、修改代码、配置环境）→ 行动优先
- **理解导向任务**（学习概念、分析问题、方案讨论、架构设计）→ 解释优先
- **混合任务**（在理解基础上执行）→ 混合范式：结论前置，解释分层

**第二问：操作风险等级如何？——低/中/高？**
- **低风险操作**（查询、读取、本地测试、非生产环境修改）→ 行动优先，直接给出答案
- **中风险操作**（修改配置、安装依赖、测试环境数据修改）→ 行动优先+简短风险提示
- **高风险操作**（删除数据、生产环境修改、发布上线、不可逆操作）→ 解释优先+风险说明+确认环节

**第三问：用户-任务熟悉度如何？——新手还是专家？新任务还是常规任务？**
- **专家用户+常规任务** → 极致行动优先，零客套，纯答案
- **新手用户+新任务** → 解释优先，先讲背景和原理，再给出步骤
- **中间状态** → 混合范式：行动优先，答案前置，但解释部分更详细，标注"💡 新手提示"

### 11.3.2 场景-范式映射矩阵

| 场景类型 | 推荐范式 | 具体要求 |
|---------|---------|---------|
| Bug修复/调试 | 行动优先 | 首行给出修复方案/命令，后跟根因分析（可选阅读） |
| 代码修改/功能开发 | 行动优先 | 首行列出要修改的文件和核心改动，后跟步骤和解释 |
| 命令行操作 | 行动优先 | 直接给出命令，必要时1句话说明作用 |
| 架构设计/方案讨论 | 解释优先 | 先分析问题和约束，再推导方案，最后给出结论 |
| 代码审查/问题分析 | 混合 | 首行给出"是否通过"结论和关键问题列表，后跟详细分析 |
| 复盘/根因分析 | 解释优先 | 先还原事实，再分析根因，最后给出行动项 |
| 知识讲解/教学 | 解释优先 | 从已知到未知，循序渐进，例子先行，结论后出 |
| 情感支持/困惑解答 | 解释优先 | 先共情回应，再分析问题，最后给出建议 |
| 生产环境操作 | 解释优先+确认 | 先讲风险和回滚方案，确认后再执行 |
| 多轮连续高频交互 | 行动优先 | 减少重述和客套，聚焦当前动作，进度重述极简 |
| 对话中断后恢复 | 混合 | 先完整重述上下文（解释式回顾），再给出下一步行动 |

### 11.3.3 范式切换信号识别

Agent需要在对话过程中动态识别范式切换信号：

**切换到行动优先的信号**：
- 用户说"直接告诉我怎么做""别解释了，给命令""赶紧修复"
- 用户连续快速回复，只问执行相关的问题
- 用户重复执行类似操作（显示出熟练度）
- 任务有明确的时间压力（"快""紧急""线上等着"）

**切换到解释优先的信号**：
- 用户说"为什么""解释一下原理""我没太理解"
- 用户开始问背景性、原理性问题
- 用户是第一次接触该任务，问了很多基础问题
- 操作涉及高风险，用户主动询问后果和回滚方案
- 用户说"我们来讨论一下""先想想方案"

## 11.4 V2补充：四类易被忽略的关键边界场景

第二轮对抗审查（V2）发现，在"技术专家用户"默认假设下，4个关键边界场景容易被遗漏。

### 11.4.1 非技术用户场景

**盲区表现**：首屏直接给代码/命令会让产品经理、设计师、业务用户产生畏难；量化时间估计对不熟悉技术操作的用户不准确；"单步单动作"对非技术用户可能显得居高临下。

**适配策略**：
- 首屏除核心结论外，增加1-2句"这是什么/为什么需要"的极简上下文
- 时间估计改为"这是一个简单操作，完成后告诉我结果"而非量化分钟数
- 适当合并相关步骤并增加"为什么做这一步"的微型说明
- **关键判断信号**：用户提问包含"什么是""为什么""帮我理解""你觉得"等探索性词汇时，即使涉及技术内容，也默认切换到解释优先

### 11.4.2 多轮长对话场景（>10轮）

**盲区表现**：固定格式进度重述在超过10轮的长对话中产生"进度疲劳"；进度块被用户忽略反而增加认知负担；进度重述可能占总Token的30-40%；长对话的分支、回退、转向打破线性结构假设。

**适配策略（梯度降级）**：
- 5轮以内：完整进度重述
- 5-15轮：极简进度提示（如"【阶段3/5：执行修复】"）
- 15轮以上：仅在用户询问进度或对话中断恢复时才重述
- 长对话中允许非线性的探索性回复

### 11.4.3 创意写作/头脑风暴场景

**盲区表现**：结论前置在创意发散阶段有害——过早给出结论锚定思维，抑制创意探索；"单步单动作"与创意流非线性冲突；"压制离题"在创意场景中危险——大量创意突破来自意外离题联想。

**适配策略（探索优先范式）**：
- 首屏呈现思考方向/待探索问题列表而非结论
- 中间呈现多个并行思路而非编号步骤
- 离题不主动压制但标记"💡 这是一个岔路思路"
- 最后才在可选补充区给出收敛建议

### 11.4.4 高风险决策场景

**盲区表现**：行动优先肌肉记忆可能导致在完成风险评估前就输出行动指令；编号步骤暗示虚假确定性——高风险场景正确答案可能是"现在不要做任何操作"；时间估计制造虚假紧迫感；7±2步骤限制可能过度简化复杂决策。

**高风险信号清单**：
1. 涉及"删除/清空/重置/force"等不可逆操作关键词
2. 涉及生产环境/真实资金/法律后果
3. 用户描述模糊但操作影响范围大
4. 操作需要管理员/root权限且影响多人

**高风险场景输出模板**：⚠️风险提示→回滚方案→确认请求→（用户确认后才给出操作步骤）

## 11.5 行动优先范式的8个破规场景

默认采用行动优先范式时，遇到以下场景必须主动切换范式：

| # | 破规场景 | 切换到 | 识别信号 |
|---|---------|--------|---------|
| 1 | 用户情绪崩溃/线上事故 | 共情优先→行动 | 用户情绪激动、描述事故 |
| 2 | 高风险操作 | 解释优先+确认 | 出现不可逆关键词 |
| 3 | 首次接触/新手用户 | 解释优先 | 用户问大量基础问题 |
| 4 | 用户明确要求解释 | 解释优先 | "为什么""解释一下" |
| 5 | 非技术用户 | 解释优先（带上下文） | 探索性词汇、非技术背景 |
| 6 | 创意写作/头脑风暴 | 探索优先 | 发散性、开放性问题 |
| 7 | 长对话中后期（>15轮） | 梯度降级 | 多轮交互历史 |
| 8 | 发现严重风险即使离题 | 风险优先 | 发现危险操作 |

## 11.6 对SpecWeave智能体设计的启示

1. **默认范式**：混合范式（结论前置+分层展开）作为SpecWeave智能体的默认输出范式
2. **规则弹性**：所有输出规范采用"默认推荐+弹性提示"模式，避免"必须/禁止"等强刚性表述
3. **文化适配**：中文语境保留"好的""收到"等具有确认功能的简短回应
4. **Token成本意识**：进度重述类规则显式标注Token消耗，短平快交互默认简化
5. **用户画像适配**：范式判断增加"探索性词汇"信号检测，超越"技术专家"默认假设
6. **高风险拦截**：建立高风险信号清单和严格拦截模板
