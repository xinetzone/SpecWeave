# monetize · 运营与演进路线图

> **本文件是什么**：容器级的**运营节奏、知识回流规则与演进条件**。主题级的执行节奏（每日打卡 / 每周核对 / 月度复盘）在各主题 `tracker.md` 内，本文件不重复。
> **规则性质**：文中带「建议值」的参数可随实践修订；修订时在文末「修订记录」登记。

## 一、分层治理模型

| 层 | 承载 | 节奏 |
|---|---|---|
| 容器层（本文件） | 主题注册、扩增 / 归档决策、知识回流、形态演进 | 月度巡检 + 事件触发 |
| 主题层（各工作台 `tracker.md`） | 每日 / 每周 / 每月的执行与记录 | 按各主题自定节奏 |
| 知识层（信源 / 知识库，只读） | 事实编号、规则快照、复核线 | 事件触发（回流流程，见 §三） |

## 二、运营节奏（容器级，尽量轻）

| 节奏 | 动作 | 判据 |
|---|---|---|
| 每月末 | **容器巡检**：核对主题注册表状态；抽查活跃主题台账是否有更新（防"僵尸工作台"）；检查下月关键锚点（报名窗 / 活动窗） | 巡检记录（可记入主题 `records.md` 或执行笔记） |
| 复核线前 1 个月 | **复核预警**：对 `stale_after` 到期主题发起复核（如 2026-11-30 预警 2026-12-31 复核线） | 各主题复核锚点逐项过 |
| 事件驱动 | 命中 §三 / §四 任一触发器即响应 | 见对应章节 |

## 三、知识回流规则（执行 → 知识层）

执行中发现的规则变化按**影响面**分流；工作台**禁止直接改写知识层**（知识层在子模块内，只读外链）：

| 发现类型 | 示例 | 通道 |
|---|---|---|
| 口径微变 | 页面措辞微调、数值小幅变化 | 记入主题 `records.md` / 执行笔记 + 当期页面快照留痕；等待复核线统一处理 |
| 规则重大变动 | 门槛 / 奖池 / 时间窗结构变化（历史先例 [F-067](../awesome-okf-xs/doc/bundles/sheke/industry/zhihu-monetization/references/article-source.md) 载字数门槛演变） | 主题工作台记录 → **发起知识层复核提案**：新增事实编号 + 勘误登记 + 核验记录更新（走 awesome-okf-xs 子模块流程，入口见[区域资产索引](../AGENTS.md)） |
| 官方细则发布 | 如 AI 协作认定细则 | 立即触发对应主题复核锚点（已登记于主题 `tracker.md`「复核锚点」）+ 同上回流 |

**回流时限（建议值）**：重大变动发现后 7 天内发起提案；官方细则发布立即响应。
**回流收益**：工作台只链接不复制——知识层更新后工作台自动指向最新版本，无需逐处修改（这正是单一事实来源的设计收益）。

## 四、主题扩增与归档触发器

**扩增（新开主题工作台）——三条件同时满足（建议值）**：

1. **信源底座可得**：定义层（公开文档 / 报告）与知识层（知识库）齐备或可采集；
2. **运营余量**：活跃主题数 ≤ 2；且既有主题已完成冷启动（进入持续期或稳定执行 ≥ 4 周）；
3. **独立性成立**：新主题规则体系独立（否则并入既有主题，不新开台）。

**归档（主题停运）——命中任一（建议值）**：

1. 主题自身退出条件触发（如 zhihu 主路径：连续 8 周收益趋近于零）；
2. 长期中断：≥ 30 天无台账更新且无中断记录。

**归档动作**：注册表状态改「已归档」→ 主题台账顶部加归档说明（日期 / 原因）→ 文件保留不删（历史留痕）。

## 五、形态演进（普通目录 → 独立成仓）

**现状**：主仓库直接跟踪的普通目录（非 git 子模块）。

**升级条件（任一满足即启动评估，建议值）**：

1. 主题数 ≥ 3，或容器文件规模显著增长；
2. 真实数据需要版本化 / 多设备同步（应迁独立**私有**仓——公开仓不适合承载个人数据）；
3. 需要对外分发工作台模板（协作 / 复用需求）。

**升级路径**（按 [projects/AGENTS.md](../AGENTS.md)「新增子项目」流程）：提案（用户批准）→ 独立仓库初始化与迁移 → `git submodule add` → 区域路由 / 索引 / 边界声明同步更新 → 更新本文件「现状」与容器登记。

**反向约束**：保持简单优先——仅 1 个主题且稳定运行时维持普通目录，不为升级而升级；子模块不默认回退为普通目录（如确需，另立提案）。

## 六、维护清单（变化时必须同步的位置）

| 变化事件 | 同步位置 |
|---|---|
| 新增主题 | 容器 [README.md](README.md) 主题注册表 + 容器 [AGENTS.md](AGENTS.md) 主题路由表（**两处必须一致**） |
| 主题入口变化 | [projects/AGENTS.md](../AGENTS.md)（路由表 + 优先级树 + 资产索引）+ [projects/README.md](../README.md) + 容器内引用 |
| 容器级新增文件 | 容器 [AGENTS.md](AGENTS.md) 文件地图 |
| 复核线变更 | 受影响主题入口 + 本文件 §二 |
| 主题归档 | 注册表状态 + 主题台账归档说明 |

**红线**：同一枚举在多处的**不一致即缺陷**（先例：区域路由表与优先级树曾因未同步被 V 门审查记为 V-06）。
