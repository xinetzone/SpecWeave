# monetize · 变现执行工作区容器 · 智能体入口

> 本文件是 `projects/monetize/` 的智能体入口：先读本文件定位主题与纪律红线，再进入对应主题工作台并读取其 `AGENTS.md`（嵌套优先——以离工作目录最近的 AGENTS.md 为准）。

## 一、定位

- `projects/monetize/` 是个人变现的**执行工作区容器**，每个主题一个工作台子目录；
- **主仓库直接跟踪的普通目录（非 git 子模块）**，归属 projects 区域（区域路由见 [../../AGENTS.md](../../AGENTS.md)、目录总览见 [../../README.md](../../README.md)）；
- 容器**只承载执行状态与记录**，定义与知识留在信源——见各主题工作台的链接矩阵。

## 二、主题路由表

| 主题 | 工作台入口 | 状态 | 说明 |
|---|---|---|---|
| zhihu-monetization | [zhihu-monetization/AGENTS.md](zhihu-monetization/AGENTS.md) | 已就绪 | 知乎变现执行工作台（参考实现）：定义层 = docs 路径报告；知识层 = OKF bundle |

> 新增主题：按 [README.md](README.md)「三、新增主题步骤」执行，并同时更新本表与 README 主题注册表。

## 三、纪律红线（全容器适用）

1. **单一事实来源**：定义 / 知识 / 执行三层互不复制，跨层引用只链接回源；
2. **数字溯源**：平台口径数字必须挂事实编号（F 编号或等价物）并链接出处，零无源数字；
3. **数据隔离**：真实执行数据一律写各主题工作台的 `local/`（已 gitignore），**禁入库**；仅模板与机制入库；
4. **时效复核**：遵守各主题的 `rule_snapshot` 与 `stale_after` 复核线；引用规则前回源复核当期版本；
5. **防画饼**：池规模 ≠ 个人收益；个人实得以到账记录为唯一事实源。
6. **知识回流**：发现规则重大变动 / 官方细则发布 → 按 [roadmap.md](roadmap.md) §三 分流处理（工作台禁止直接改写知识层，回流走子模块流程）。
