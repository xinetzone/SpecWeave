### 洞察 1：Draft.js 类编辑器拒绝合成事件，CDP 原生输入是唯一持久化通道

- **陈述**：React/Draft.js 富文本编辑器对自动化输入存在分层拦截——合成事件（bu.type、合成 beforeinput）与剪贴板注入均被丢弃或重置，CDP 原生输入流（`Input.insertText`）是内容持久化的唯一可行通道。
- **证据**：F-005（bu.type 刷新丢失）、F-006（execCommand 刷新丢失）、F-007（剪贴板被拒）、F-008（CDP 输入持久化）、F-009/F-010（正文与标题全量成功）。
- **反常识**：浏览器自动化的常规手段（type/execCommand/剪贴板）在 Draft.js 下全部失效，看似「更低层」的 CDP 原生输入反而最可靠——因为 React 合成事件系统会拦截非可信（isTrusted=false）事件，而 CDP 注入的是原生输入流，被 React 当作真实用户输入。
- **行动**：将 CDP 输入通道固化为 Skill（`zhihu-article-publish-cmd`）核心路径；遇到任何 React 内容可编辑组件（Draft.js/Slate/ProseMirror）时优先尝试 CDP `Input.insertText`，验证标准统一为「刷新后内容仍在」。

### 洞察 2：动态候选下拉组件（话题选择）需「输入→等待稳定→JS 精确点击→验证」四步，坐标/视觉定位易命中相邻项

- **陈述**：话题候选列表随输入实时变化，`bu.find` 容器点击、Enter 默认项、`click_xy` 坐标点击均不可靠——坐标点击在候选项相邻时会命中非目标项；JS 按文本精确匹配候选元素并 `.click()` 才可靠。
- **证据**：F-025（三种常规方式均未选中）、F-026（坐标点击后新增「有趣的人工智能」话题）、F-027/F-037（编辑页标签行检测含目标话题）、F-040（更新后文章页三项话题）。
- **反常识**：视觉定位（find/坐标）在动态候选列表上比 DOM 文本精确选择更容易出错——候选项位置随输入逐帧变化，坐标偏移一两个候选即命中相邻项；「看起来选中了」与「真正加入标签行」是两个独立状态，必须用 DOM 结构验证。
- **行动**：候选类交互统一「输入 → 等待候选稳定 → JS 按文本精确 click → 目标区 DOM 验证」四步；话题/标签类组件验证目标是标签行容器（DIV 集合），而非候选菜单。

### 洞察 3：已发布文章再次编辑时发布设置会重置，发布后必须回读文章页验证而非信任编辑页

- **陈述**：编辑页显示的话题标签行与创作声明状态，不等于发布版文章页的生效状态；已发布文章重新进入编辑页时创作声明重置为「无声明」，发布版话题缺失需「更新」动作同步。
- **证据**：F-031（发布版话题区仅两项）、F-036（重编辑时声明为「无声明」）、F-037（编辑页标签行三项齐全）、F-039/F-040（更新后文章页三项话题 + 声明恢复）。
- **反常识**：编辑页草稿设置与线上发布版存在状态分离——「发布/更新」按钮才是草稿设置同步到线上版本的提交点；发布动作本身未完整携带话题标签（F-031 发布版缺项），仅重新编辑 + 更新才补齐。
- **行动**：发布/更新后强制「文章页回读验证」步骤（话题 `a[href*="/topic/"]` 文本集合、创作声明文案、图片计数、作品链接），并将该步骤纳入 Skill 验收清单；发布时在确认界面点按后不立即收工，先回读文章页。

### 模式 1：Draft.js 编辑器 CDP 输入通道（L1）

- **名称**：CDP 原生输入通道
- **触发场景**：
  - 适用于：React 内容可编辑组件（Draft.js/Slate/ProseMirror）的文本/标题输入；任何「程序化输入刷新后丢失」的富文本场景；合成事件与剪贴板被拒时的编辑器填充。
  - 不适用于：原生 `<textarea>/<input>`（常规 type 即可）；已提供官方 API 的编辑器（优先官方通道）。
- **核心步骤**（4 步）：
  1. 聚焦目标块（JS Range + focus，或点击块内位置）。
  2. CDP `Input.insertText` 注入段落文本（逐段注入，不要一次注入全文）。
  3. CDP `Input.dispatchKeyEvent`（keyDown/keyUp Enter）换行分段。
  4. 刷新页面验证内容持久化（唯一成功标准）。
- **反模式**：
  - ❌ 用 `bu.type` 输入长文本（Draft.js 下刷新丢失）。
  - ❌ 用 `execCommand('insertText')` 后只看页面可见性（状态树未更新，保存不持久）。
  - ❌ 剪贴板写入 + Ctrl+V（clipboard 权限弹窗挂起，无法完成）。
  - ❌ 一次注入全文（Draft.js 按块管理，长文本一次注入会丢块/丢段落结构）。
- **检验标准**：刷新后正文段落数、字数、标题与注入源一致。
- **迁移示例**：Notion/飞书文档类 React 编辑器、代码编辑器（CodeMirror 为 React 包装层）遇到相同「输入不持久」症状时，先试 CDP 原生输入。

### 模式 2：动态候选下拉四步选择法（L1）

- **名称**：候选四步选择法
- **触发场景**：
  - 适用于：搜索式话题/标签/关联项选择组件（输入后出候选列表）；候选位置随输入实时变化的下拉；`bu.find` 容器点击与 Enter 均未生效的选择类组件。
  - 不适用于：静态固定选项的下拉（find 点击正常）；原生 `<select>`（常规 select 处理）。
- **核心步骤**（4 步）：
  1. 输入关键词后等待候选列表稳定（等待 ≥1.5s 或出现「已上传/已搜索」状态文案）。
  2. JS 遍历 DOM 查找文本恰为目标值的元素（`textContent.trim() === 目标`）。
  3. 对该元素调用 `.click()`（若为容器，取其中可交互子元素或直接 click）。
  4. 验证目标区变化（标签行 DOM 检测 / 值区文本更新），未变化则重开面板重试。
- **反模式**：
  - ❌ 用坐标点击候选（候选项相邻时命中非目标项）。
  - ❌ 用 Enter 选择默认项（默认项可能不是目标项）。
  - ❌ 点击候选容器 box 而非内部可交互元素。
  - ❌ 点击后不验证目标区（「看起来选中」≠「真正加入」）。
- **检验标准**：目标区（话题标签行/已选项文本）DOM 检测包含目标值。
- **迁移示例**：电商商品分类选择、CMS 标签管理、工单系统的关联项选择组件。
