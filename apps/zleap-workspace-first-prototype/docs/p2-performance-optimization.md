# P2 阶段性能优化方案：模型适配层延迟治理

> 基于 `stress_model_latency.py` 并发 50 高并发压测结论，制定 P2 阶段模型适配层性能优化方案。
> 前置：P1 已完成 ModelProvider 接口 + 延迟量测体系（53 用例通过）
> 日期：2026-08-03 | 状态：规划中

## 1. 压测基线（并发 50，200ms 基准）

| 抖动(ms) | mean | p50 | p95 | p99 | p99-p50 | stdev |
|:---:|:---:|:---:|:---:|:---:|:---:|:---:|
| 0 | 200.4 | 200.4 | 201.1 | 201.3 | 0.9 | 0.3 |
| 50 | 198.9 | 198.1 | 247.1 | 249.4 | 51.3 | 29.3 |
| 100 | 199.2 | 197.0 | 289.1 | 295.8 | 98.8 | 56.7 |
| 200 | 202.9 | 200.6 | 378.6 | 395.4 | 194.8 | 115.0 |

**关键洞察**：
1. **p99 显著偏离 p50**：抖动 200ms 时 p99(395ms) 比 p50(200ms) 高 ~195ms，接近 2 倍。**均值无法反映真实尾部延迟**。
2. **并发 50 不放大延迟**：与单线程基线相比，p50 几乎不变（sleep 主导，线程开销 <1ms），说明线程化不是瓶颈。
3. **抖动主导延迟波动**：stdev 随抖动线性增长（0.3→115ms），网络波动是延迟分布宽度的决定因素。

## 2. 优化目标

P2 阶段目标：**在真实网络波动下，将 p99 延迟控制在预算内，同时保证并发吞吐不劣化**。

| 指标 | 当前基线 | P2 目标 |
|------|---------|---------|
| p99 延迟 | 抖动相关（200~395ms） | ≤ 预算 p99（如 300ms） |
| 并发吞吐 | 50 并发稳定 | ≥ 50 并发稳定 |
| 超时率 | 未设超时 | <1% |

## 3. 优化方案（按优先级）

### 3.1 延迟预算管理（高优先级）

**依据**：压测证明"以 p99 而非均值作为延迟预算依据"。

做法：
- 为每个模型设定 **p99 延迟预算**（SLO），如 strong-model 预算 300ms
- 路由决策时参考预算，超预算模型自动降级
- 预算分配：框架层（路由判定 <5ms）+ 模型层（推理延迟预算）

### 3.2 超时与重试（高优先级）

**依据**：抖动导致尾部请求超时，需显式控制。

做法：
- `RemoteProvider` 增加 `timeout` 硬超时（现有 `timeout` 参数落地为强制超时）
- 指数退避重试（`retry` + `backoff`），仅对幂等请求重试
- 超时样本计入 p99 统计，暴露真实尾部延迟

### 3.3 连接池与并发（中优先级）

**依据**：并发 50 无瓶颈，但真实 HTTP 连接需复用。

做法：
- 连接池复用（`requests.Session` / `httpx.Client`），避免每次 TLS 握手
- 并发上限控制（`max_concurrency`），防止打爆上游
- 批量请求批量路由，减少框架层调用

### 3.4 缓存与降级（中优先级）

**依据**：重复任务可复用，减少模型调用。

做法：
- 结果缓存（按 prompt 哈希 + 模型），命中则跳过模型调用
- 降级链：强模型超时 → 降级到便宜模型 → 兜底默认结果
- 熔断（`circuit_breaker`）：连续超时后暂缓调用该模型

### 3.5 抖动平滑（低优先级）

**依据**：抖动是延迟宽度的决定因素。

做法：
- 请求级抖动容忍：设置 `jitter_buffer`（如 ±50ms），吸收小幅波动
- 优先级调度：高优先级任务优先分配空闲连接

## 4. 落地任务分解

| 任务 | 内容 | 验收标准 |
|------|------|---------|
| T1 延迟预算 | ModelProvider 增加 p99 预算属性 + 路由参考 | 超预算模型可降级 |
| T2 超时重试 | 实现 timeout 硬超时 + 指数退避 | 超时请求不卡死，重试收敛 |
| T3 连接池 | 集成 httpx/requests Session 复用 | 并发 50 下连接数受限、吞吐稳定 |
| T4 缓存降级 | 结果缓存 + 降级链 + 熔断 | 重复任务命中缓存，降级可达 |
| T5 压测回归 | 扩展 stress_model_latency.py 覆盖上述路径 | p99 达标、无回归 |

## 5. 风险与应对

| 风险 | 应对 |
|------|------|
| 超时设置过严导致大量失败 | 以压测 p99 为基线，预留 20% 余量 |
| 重试放大上游压力 | 指数退避 + 熔断，限制重试次数 |
| 缓存命中率低 | 先评估任务重复度，再决定缓存规模 |
| 优化引入复杂度 | 保持 ModelProvider 接口不变，优化为内部实现 |

## 6. 与 P1 的衔接

- P1 已交付：ModelProvider 接口、延迟量测、抖动模拟
- P2 将：在接口内部实现延迟治理（预算/超时/缓存/熔断），不改变对外接口
- 验收：以 p99 为延迟预算，接入真实模型后达标
