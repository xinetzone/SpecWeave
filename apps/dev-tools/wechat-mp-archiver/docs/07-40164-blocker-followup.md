# 40164 阻塞排查记录（2026-09-29 第二轮）

> 触发：用户添加 IP 白名单后重跑探针，**仍报同一 `40164`**。
> 本记录为第二轮排查，含一次**自我纠错**（首轮误判为 IPv6 问题）。

## 1. 现象（稳定复现）

连续 3 次调用均返回同一结果，出口 IP 不变：

```text
{"errcode":40164,"errmsg":"invalid ip <EGRESS_IPV4> ipv6 ::ffff:<EGRESS_IPV4>, not in whitelist"}
```

时间线：首轮报错 18:55 → 用户加白名单 → 19:04 复查仍 `40164`（已过约 9 分钟）。

## 2. 首轮误判与纠正（重要教训）

**首轮错误结论**：把 `ipv6 ::ffff:<EGRESS_IPV4>` 读成"平台拿到的是 IPv6 连接、需在 IPv6 白名单栏另填"。

**实测推翻**：

| 检验 | 结果 | 含义 |
|---|---|---|
| `api.weixin.qq.com` AAAA 记录 | **不存在**（`getaddrinfo` 报 10044） | 微信**不提供 IPv6 接入** |
| `curl -6` 连微信 | `000`（失败） | IPv6 路径根本不通 |
| 连接微信时的本地源地址 | `<LAN_IPV4>`（内网） | IPv4 单栈出网 + NAT |
| NAT 后出口 IP | `<EGRESS_IPV4>` | 与报错一致 |

**结论**：`::ffff:` 是微信对 IPv4 源地址的**回显格式**，不是"必须加 IPv6"。微信域名无 AAAA，调用**只能走 IPv4**。
**教训**：`::ffff:` 前缀是 IPv4-mapped IPv6 的展示写法；看到它不要推断链路走 IPv6，须先查目标域名有无 AAAA。

## 3. 微信校验顺序（实测推导）

用两个受控实验定位校验次序：

| 实验 | appid | secret | 返回 | 推断 |
|---|---|---|---|---|
| A | 你的真实 AppID | 故意写错 | `40164` | 被 IP 白名单拦在 secret 校验**之前** |
| B | 不存在的 AppID | 故意写错 | `40013 invalid appid` | appid 存在性检查**早于** IP 白名单 |

**推定校验顺序**：`appid 存在性` → **`IP 白名单`** → `secret 校验`

**两个直接推论**：

1. 你的 AppID **确实存在**（否则 A 会返回 40013 而非 40164）；
2. **在白名单生效前，无法通过接口验证 AppSecret 是否写对** —— 报错必然停在 40164。首轮曾据"40164 而非 40125"推断"secret 正确"，**该推断不成立**：secret 错也会返回 40164，因为根本没走到验签那步。

## 4. 已排除项

| 假设 | 检验 | 结论 |
|---|---|---|
| 代理干扰出口 IP | 绕代理 vs 走代理，两者报错 IP 均 `<EGRESS_IPV4>` | 排除 |
| `.env` 被外部环境变量覆盖 | `Settings()` 实测 appid/biz 与 `.env` 一致；环境内 `MP_ARCHIVER_*` 计数 = 0 | 排除 |
| 出口 IP 漂移 | 连续多次 + 19:04 复查，均为 `<EGRESS_IPV4>` | 排除 |
| IPv6 白名单缺失 | 微信无 AAAA，IPv6 不可达 | 排除（不适用） |

## 5. 剩余可能原因（按概率排序）

### 5.1 白名单未生效 / 未保存 ⭐ 最可能

社区反馈生效需 **5–10 分钟**，个别更长。19:04 复查距添加仅约 9 分钟，**尚未超出生效窗口**。
→ **先等待至 19:15 后重试**，不要立即重复添加。

### 5.2 白名单加在了错误的位置或账号 ⭐ 高概率

**最容易错的一条**：该 AppID 属于**公众号**，白名单必须加在
**公众号后台 →「设置与开发」→「基本配置」→「IP 白名单」**。

常见误加位置（**均不生效**）：

- 公众号后台 →「设置与开发」→「公众号设置」→「功能设置」下的 IP 白名单
- **开放平台** / 小程序后台的白名单（属于不同 AppID 体系）
- 服务市场「测试公众号」后台

### 5.3 IP 输入形式问题

- 每行一个 IP，**不支持 CIDR 网段**（如 `183.156.6.0/24` 无效）
- 检查有无多余空格、全角字符、把 `<EGRESS_IPV4>` 误写为其他数字

### 5.4 网络结构问题（若上述均无效）

出口 `<EGRESS_IPV4>` 为**运营商级 NAT（CGNAT）**
（同网段已见 `183.156.6.0/24` 被多地 ISP 复用）。
若微信侧看到的源地址与探针自测不一致，则白名单**在原理上无法锁定**该出口 —— 需改用有固定公网 IP 的服务器/云主机代理出站。

## 6. 建议处置顺序

```text
① 等待至 19:15+ 后原样重试（排除生效延迟）
        ↓ 仍失败
② 核对白名单位置：必须是【公众号后台 → 设置与开发 → 基本配置 → IP 白名单】
   核对内容：<EGRESS_IPV4>（单独一行、无空格、无 CIDR）
        ↓ 仍失败
③ 截图该页面（可打码 AppID 尾部），我比对是否在正确入口
        ↓ 仍失败
④ 判断是否 CGNAT 导致与微信视角不一致 → 改用固定公网 IP 出站
```

## 8. 环境事实补充

- 本机网络：IPv4 单栈出网，本地 `<LAN_IPV4>` → NAT `<EGRESS_IPV4>`；**同时具备可用的 IPv6 出网能力**（`<IPV6_PREFIX>...`，经独立测试可达），但微信不支持 IPv6，故 IPv6 与此问题无关。
- 系统代理 `http_proxy=127.0.0.1:<PROXY_PORT>` 存在；本地服务探测须 `--noproxy '*'`（见 `06-credential-probe-2026-09-29.md` §4.2）。
