若为账号级权限缺失，应普遍返回 48001；实际仅 `freepublish/*` 一条被拒。

## 3. 定性依据（官方社区口径）

微信开放社区技术与运营团队答复：

> 自 **2025 年 7 月**起，**个人主体账号、企业主体未认证账号及不支持认证的账号**将被**回收发布能力相关接口**的调用权限。

- `48001` 与第三方平台权限集无关（权限集问题是 `61007`）；
- 社区对同类问题的标准处置答案是：**「目前发布能力相关接口需要公众号/服务号完成微信认证后才可调用」**；
- 即：`freepublish/batchget`（已发布图文列表）属于**发布能力相关接口**，需要**微信认证**。

## 4. 结论

当前 `.env` 中的 `wx4c620ec6cd51a2d6` 该号**未满足发布能力接口的认证门槛**（个人主体 / 未认证 / 不支持认证三者之一）。

**这是账号主体资质问题，不是配置问题** —— 继续调参、重加白名单、改 AppSecret 都不会改变结果。

**重要**：R1 被 `48001` 阻断，**不代表归档能力整体失效**。`material/*`、`draft/*` 可用这一点说明该号仍有可用的接口面，只是不包含"已发布图文列表"。

## 5. R1 与 R2 的正确定位（避免误解）

| | R2 采集服务 | R1 官方接口 |

| 路径 | `127.0.0.1:5000` 私有部署 | `api.weixin.qq.com` 直连 |
| 能力 | **历史全量文章列表**（主路径） | **仅"发布成功"的图文**（交叉补全） |
| 依赖 | 专用订阅号扫码登录态（约 4 天） | AppID/AppSecret + IP 白名单 + **认证门槛** |

**R1 在架构上从不是主力** —— 官方文档明确其只覆盖"已发布图文"（含"发表不通知"），**不含传统群发历史**。历史全量只能靠 R2。

∴ **推进归档的正确动作是启动 R2 采集服务，而不是继续攻 R1。**
