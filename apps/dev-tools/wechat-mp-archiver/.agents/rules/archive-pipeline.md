# 归档管线硬约束

本文件是 `apps/dev-tools/wechat-mp-archiver` 的**唯一规则主题**，承载归档管线不可协商的工程硬约束。
人类可读说明见 [../../docs/03-operations.md](../../docs/03-operations.md) 与 [../../docs/05-compliance.md](../../docs/05-compliance.md)；
**文档与代码冲突时以代码为准**。

## §1 保守限速不可下调（默认值即推荐值）

- 默认 `MP_ARCHIVER_REQUEST_DELAY_MIN/MAX = 2.0/5.0` 秒（均匀采样，天然带抖动），`MP_ARCHIVER_MAX_RETRIES = 5`，退避 `min(60, 2·2ⁿ)` 秒 + 抖动，单请求超时 30 秒。
- **保守方向来自平台事实**（方案文档 3.2 节失效模式已实证高频请求触发验证码/临时封禁）；**2–5 秒/篇的具体区间是本项目据此取的工程判断**，非平台公布阈值——不得表述为平台规定。
- 下调限速属于用户自担风险行为，不得作为默认值变更；新增网络请求路径必须复用 `http_client.py` 的限速与退避能力，禁止裸 `requests`/`httpx` 直连。
- 频率自律：每日增量至多一次、全量每周至多一次；一旦出现验证码或封禁信号立即停止。

## §2 采集服务只绑回环，禁止暴露公网

- 采集服务仅监听 `127.0.0.1:5000`；`deploy/docker-compose.yml` 不得出现 `0.0.0.0` 绑定或公网端口映射。
- 管线只经回环地址取列表；正文与媒体下载直连 `mp.weixin.qq.com`，**剥离采集服务 Token**。

## §3 凭证治理

- 所有凭证只存本地 `.env`（已在 `.gitignore`），**不入库、不进日志**；日志输出必须经 `logging_utils.py` 脱敏。
- 仅使用**管理员本人扫码**授权的登录态；不共享账号、不转售凭证。
- 互动票据（`appmsg_token`/`pass_ticket`）默认关闭，失效记 `skipped_no_credential`（非 failed），不影响正文归档。

## §4 幂等与断点续跑

- 状态以 SQLite 五表（`articles`/`media`/`comments`/`metrics`/`sync_state`）为准，**每篇成功/失败即时落库**。
- 半成目录在重跑时**整体清空重建**，不产生重复文件；进程随时终止（含 `kill -9`）后重跑安全。
- 普通重跑只采 `pending`；**仅 `--include-failed` 才重试失败篇**。
- `sync` 增量模式遇整页全已知即停；`run --full` 才翻到历史尾页并执行下架对账——**未显式加 `--full` 绝不执行全量长任务**。

## §5 故障作用域分流与熔断矩阵

| 故障 | 作用域 | 行为 |
|---|---|---|
| 403/429（账号或 IP 级风控） | 账号级 | 请求级退避用尽后置 failed（原因 `risk_abort:`），**立即熔断**，本批后续零请求 |
| 验证码/环境异常页 | 账号级 | 显式判为风控，置 failed 并立即熔断，**不产生空壳归档** |
| 超时/连接错误、文章页 5xx | 传输级 | 单篇退避重试→failed 隔离；**连续 2 篇**（`MP_ARCHIVER_TRANSPORT_ABORT_THRESHOLD`）才熔断，成功/业务失败篇重置计数 |
| 单篇 404 / 解析异常 | 单篇级 | 不重试，置 failed，批次继续，末尾给成功/跳过/失败分类计数 |
| 媒体链接失效 | 资源级 | 登记 media 表与 `metadata.json` 例外表（保留远程引用），文章仍 downloaded |
| 采集服务凭证过期 401/403 | 会话级 | 不落归档重试，凭证状态写库 `expired` 并立即终止 |

- 退避日志**只记主机名、不记链接参数**。
- **5xx 按传输故障分类**（非业务失败），避免网关故障放大为逐篇业务失败。

## §6 风控判定必须结构感知

- 风控页判定基于**页面结构**（正文容器 `#js_content` 缺失或为空），**禁止全文子串匹配**。
- 禁止以「正文中包含验证/风控相关词」作为判定依据——历史缺陷：全文子串匹配对正文恰好包含相关词的正常文章产生误报。
- 误判可通过 `--include-failed` 复核重试。

## §7 退出码契约（CLI 对外接口，不得随意变更）

| 码 | 含义 |
|---|---|
| `0` | 成功（含仅有媒体告警） |
| `1` | 存在失败文章或参数错误（`export-rag` 存在失败导出亦为 1） |
| `2` | 登录态失效需重新扫码 |
| `3` | 账号未找到（`sync-official` 路径亦表示 biz 未配置；`report` 账号未找到同码） |
| `4` | 环境/风控异常（采集服务不可达、端点发现失败、R2 列表 biz 不可得，或正文阶段触发熔断） |

## §8 官方接口边界

- 官方接口**仅用于自己管理的认证服务号**；个人/未认证主体返回 48001 时**自动降级为退出码 0**。
- 日配额守护 `MP_ARCHIVER_OFFICIAL_DAILY_CALL_CAP = 90`（经验日限约 100，预留余量），按 UTC 日滚动；配额耗尽 UTC 0 点恢复。
- 不得利用官方接口突破平台权限边界。

## §9 派生产物纪律

- `export-rag` 与 `report` 为**纯派生离线命令**：不触网、幂等、**临时文件 + 原子覆盖**，不得出现半成品产物。
- `export-rag` 仅导出 `downloaded` 文章；`report` 统计口径（前四项基于有发布时间的全部文章、音视频占比基于 downloaded、时间按北京时间 UTC+8 聚合）必须在报表页首声明，并附对账 SQL。

## §10 合规条款工程化落地

合规声明六条（个人学习与存档限定 / 不绕付费与权限 / 尊重版权 / 频率自律 / 凭证与数据安全 / **24 小时删除义务**）为发布硬约束，见 [../../docs/05-compliance.md](../../docs/05-compliance.md)。任何功能不得以绕过付费阅读、会员、赞赏等访问控制为目标；采集服务不得暴露公网；收到权利人主张时 24 小时内删除对应本地归档（含派生产物）。

## 新增规则纪律

本应用**单一职责原则**：新增规则只能新增文件，不得把上述主题拆散或复制到父级层；新增前先明确「现有文件为何覆盖不了、新文件标题能否被一句话概括、父级是否已有同名规则」，并同步 [../../AGENTS.md](../../AGENTS.md) 的「上下文路由表」与「P0 约束速览」。
