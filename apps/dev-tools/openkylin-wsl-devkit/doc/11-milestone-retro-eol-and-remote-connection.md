# 里程碑复盘：EOL/CRLF 治理与远程连接收口（npu-toolchain 阶段收尾）

> **本篇职责**：复盘 2026-11-03 至 2026-11-04 这一阶段的三条主线——WSL 路线收尾与空间回收、远程 Podman 架构与工具链固化、EOL/CRLF 与远程连接治理；并**郑重记录一次「结论被实测证伪」**的完整过程，从中萃取可迁移的验证方法。
> **本篇不负责**：技术规格与决策依据见[入口索引](09-npu-toolchain-windows-host.md)及其 7 个分篇；验收判定见[验收与实测](09-5-acceptance-and-evidence.md)；风险与待确认项见[风险与待办](09-6-risks-todos-changelog.md)；上一阶段（换后端）的复盘见[10 号报告](10-milestone-retro-remote-podman.md)。

## 0. 结论摘要

- **路线层**：v1.x 的 WSL 本地后端被两条**不可协商的系统边界**判死——`wsl --import` 只接受本地固定盘（S: 为 DriveType=4 网络盘），D: 首次导入又被 `vmcompute`/`wslservice`（SYSTEM）的独占文件锁阻塞。收尾清理回收 **25.19 GB**（D: 8.82 GB → 34.01 GB），D:\WSL 结构收敛为 `libs` 与 `podman-machine-wsl` 两项。
- **架构层**：现行架构固化为「Windows 经 SSH 使用 10.16.11.3 的 rootless Podman 5.6.2 + overlay + 本地 XFS」，容器 `npu-toolchain` 满足 `--userns=keep-id`、`--cgroupns=host`、`label=disable`、非特权和零端口发布；容器内 LLVM **22.1.8** 门禁成立，`libtvm.so` 按 LLVM 22 重编（854 目标 rc=0），`import tvm` **0.19.0**、`import xmnn` **1.0.1.dev120**，`verify.sh` **13 PASS / 1 N/A / 0 FAIL**。
- **治理层**：`.gitattributes` 补齐 4 类文件的 LF 规则（2 条提交），12 个工作区副本（本轮 8 个 + 此前 4 个）CR 全部降为 0；LLVM 23 混装构件以「**可逆隔离**」而非直接删除处置（268 MB / 48 文件），回归通过并获批后才删除，XFS 可用 **+280,948,736 B**。
- **认知层（本轮最重要）**：原假设「CRLF 导致 `sshd` 解析失败」**被实测证伪**——OpenSSH 10.2p1 对纯行尾 `\r` 宽容（人造 CRLF 版 `sshd -t` 仍 rc=0，`sshd -T` 生效配置与 LF 版差异 0 行）。这批 LF 化因此必须改写为「**规则合规与跨平台一致性修复**」，不是故障修复。同期 `docker-cache`（带 shebang）的 CRLF 问题则是真故障（内核报 `bad interpreter: /bin/bash^M`）。
- **体积层**：镜像 14 GB 中 **13 GB（93%）是不可拆分的 `openkylin:3.0` 单层**（tarball 导入），应用层仅约 1.06 GB；卷 `npu-build` 7.0 GB 不计入镜像；运行时合计约 21.7 GB。

**核心洞察**

1. **没有控制组的验证不算验证**：`sshd -t` 全绿之所以误导，是因为没有「错误输入」这一组；注入 `BogusOption` 得到 rc=255 之后，rc=0 才具备区分力。
2. **规则合规 ≠ 故障修复**：把「观察到 CRLF」直接写成「因此解析失败」，让一个推断获得了事实外观。推断与实测必须分栏表述。
3. **工作区是索引的派生态**：修复只能从索引重放（`rm` + `git checkout --`），手工转码改的是派生态而非权威源。
4. **交付风险按层分布**：存储层同 inode 全绿，只证明「文件相同」，不证明「被目标程序正确加载」；运行层才是消费者所在。
5. **归档式导入锁死优化边界**：13 GB 单层无法按包拆分，体积治理只能作用于应用层、卷与可写层。
6. **可逆隔离是删除的正确前态**：`mv` 成本近乎为零，却把「删除前的判断」变成「删除后可验证的事实」。

**最值得复用的一条**：**先造一个必须失败的对照组，再去相信绿灯**——本次用一条非法指令（rc=255）就把「4 份配置全部通过」从结论降级为线索，避免了一次错误结论进入文档。

## 3. 第一性原理（F）：本阶段的六条根本约束

**F1 存储语义与操作系统边界决定路线。** 本阶段所有「路线被否定」的事件都不在工具链能力范围内：S: 的网络盘属性（DriveType=4）、`vmcompute`/`wslservice` 的 SYSTEM 独占锁、overlay 对 d_type/xattr/hardlink/flock 的要求——三者都在 OS/FS 语义层。工具链再完整也无法把网络盘变成固定盘，也无法让非管理员会话释放系统服务句柄。**推论**：环境类任务的第一步必须是「边界探测」，而不是「方案设计」。

**F2 索引是权威，工作区是派生态。** Git 索引中的 blob 是换行形态的唯一权威；工作区形态由检出时 `core.autocrlf` / `core.eol` / `.gitattributes` 三者共同决定。因此「修工作区」只有一条合法路径——从索引重放。手工转码会把派生态改成与索引不一致的手工态，并在下一次检出时被覆盖；更糟的是，它抹掉了「索引本来就是对的」这一关键事实。

**F3 检查的证据力来自「能被错误输入击穿」。** 一个检查器返回 rc=0，可能意味着「输入正确」，也可能意味着「检查器不检查这一项」。只有当我们能构造一个**必须失败**的输入并观察到失败时，rc=0 才从「无消息」升级为「证据」。

**F4 解析器宽容度决定缺陷可观测性，并因此决定治理的性质。** 同一份 CRLF 文件，交给 OpenSSH 配置解析器时被宽容，交给内核 `execve` 的 shebang 解析时立即崩溃。所以「CRLF 治理」不能作为一个整体命题：对 `sshd_config` 它是**合规修复**，对带 shebang 的脚本它是**故障修复**。

**F5 归档式导入让镜像失去层粒度。** `openkylin:3.0` 以 tarball 导入后成为单层 13 GB，无法按包拆分或选择性清理。体积优化的可行域因此被压缩到：应用层（1.06 GB）、卷（7.0 GB）、可写层（0.68 GB）、宿主悬空对象。

**F6 不可逆动作只能是「可逆隔离 → 回归 → 批准 → 删除」的终点。** 删除没有回滚；`mv` 有。把判断前移到「隔离后仍可观测」的阶段，是唯一能让删除决策具备事后验证性的形态。

## 4. 中心事件：结论被实测证伪

本节按委托要求单独立章。它不是一次普通纠错，而是**一个错误结论曾经进入文档注释与报告**、随后被实验推翻的过程。

### 4.1 原假设如何形成

推理链只有三步，每一步单独看都成立，合起来却产生了伪因果：

1. **观察 A**：Windows 工作区中若干 `Containerfile*` 与 `sshd_config` 含 `\r`（CRLF），与 `.gitattributes` 要求的 LF 不符。
2. **观察 B**：`.gitattributes` 已声明这些文件必须为 LF，且提交历史显示它们是按规则应修的对象。
3. **推断 C（未经实验）**：于是推断「CRLF 会让 `sshd` 报 `Bad configuration option` / `missing argument`」，并据此把这些文件定性为「故障源」。

推断 C 随后被写进 `.gitattributes` 第 128–130 行的注释，也进入了本轮早期的口头结论。**一旦进入注释，推断就获得了事实的外观**——后来的读者（包括智能体）会把注释当作已验证的知识继承下来。这是本次事件最值得警惕的部分。

### 4.2 实验设计（含控制组）

实验分三层，关键在第二层的对照：

| 层 | 做法 | 目的 |
|---|---|---|
| 存储层 | 宿主与容器内对同一文件取 `st_dev`、inode、size、CR 数、sha256 | 排除「容器看到的是另一份文件」 |
| 解析层（正向） | 对 4 份真实 `sshd_config` 用 OpenSSH 10.2p1 执行 `sshd -t` | 观察现状是否报错 |
| 解析层（**控制组**） | 故意插入一条非法指令 `BogusOption` 后再执行 `sshd -t` | 证明「检查器会说话」——否则 rc=0 不可解释 |
| 解析层（反事实） | 把一份 LF 配置人为转成 CRLF（871 B / 38 CR），再执行 `sshd -t` 与 `sshd -T` | 直接检验「CRLF 是否致错」这一因果 |
| 运行层 | 核查是否有常驻 `sshd` 进程加载这些文件；核查 `Containerfile*` 是否有打开句柄 | 判断这批文件是否真的被消费 |

### 4.3 实验结果

- 4 份真实配置：`sshd -t` **全部 rc=0**（与假设相反，现状并未报错）。
- 控制组：插入 `BogusOption` → **rc=255**。说明检查器有效，前面的 rc=0 不是「检查器哑火」。
- 反事实：人造 CRLF 版（871 B / 38 CR）→ `sshd -t` **仍 rc=0**；`sshd -T` 输出的生效配置与 LF 版**逐行相同，差异 0 行**。
- 运行层：仅 `verify-*` 临时容器在 `-t`/`-T` 测试模式下加载过这些文件，**没有任何常驻服务使用它们**。

### 4.4 修正后的表述（本报告采用的正式结论）

> **修正结论**：OpenSSH 10.2p1 对纯行尾 `\r` 宽容，因此**这批 LF 化不是故障修复，而是「规则合规 + 跨平台一致性」修复**；其价值在于让检出形态与 `.gitattributes` 声明一致、消除跨平台噪声，而不在于消除某个已发生的解析失败。

同时必须保留一个**边界说明**，否则修正结论会被过度泛化：

> **对照事实**：`.agents/scripts/docker-cache` 带 `#!/bin/bash` shebang，若为 CRLF，内核在 `execve` 阶段解析 shebang 会报 `bad interpreter: /bin/bash^M`。该类文件的 CRLF 问题是**真故障**。

也就是说，「同一治理动作」对两类文件的性质不同，必须分开表述、分开验收。

### 4.5 方法论教训

1. **没有控制组的验证不算验证。** 若只跑 4 份配置的 `sshd -t` 就宣布「修复生效」，我们会把一个从未存在的故障写进结论。控制组（`BogusOption` → rc=255）只花一条命令，却决定了整个结论的可信度。
2. **推断与实测必须分开表述。** 「观察到 CRLF」是实测；「CRLF 导致解析失败」是推断。两者在文档中必须使用不同的句式（「实测为…」/「推测可能…」），否则推断会被下游继承为事实。
3. **修复后的绿灯不等于修复前的红灯。** 修完再验证只能证明「现在没问题」，不能证明「之前有问题」。要证明因果关系，必须做**反事实**（把好文件改坏、看是否复现）。
4. **不同文件类型不可共享同一因果。** 配置解析器与内核 shebang 解析器的宽容度不同；「行尾治理」必须按「谁解析这个文件」分类，而不是按「文件是否违反规则」分类。

### 4.6 由证伪直接产生的待办

`.gitattributes` 第 128–130 行的注释仍写着「a CRLF `sshd_config` yields stray \r in option values ("Bad configuration option" / "missing argument")」。**规则正确，注释里的因果错误**。建议只改注释、不动规则（改注释属文档修正，规则变更无需连带），列入 §11 未解事项第 9 项，等待批准后执行。

## 6. 洞察（I）：六个四元组

**I1 没有控制组的验证不算验证。**
- 现象：4 份 `sshd_config` 的 `sshd -t` 全部 rc=0，曾被当作「修复生效」的证据。
- 机理：检查器对无效输入不报错时，rc=0 只证明「检查器没说话」，不证明「输入正确」；注入 `BogusOption` 得 rc=255，才让「检查器会说话」变成可观测事实，rc=0 由此获得区分力。
- 迁移条件：任何「某配置/某结构是否被正确接受」的验收，尤其当被检查对象是新写的、检查器是第三方程序时。
- 反例：连通性探测（`ping`、端口探活）——rc=0 本身就是目标，不存在「检查器宽容」问题，控制组无意义。

**I2 规则合规与故障修复必须分栏，推断与实测必须分句。**
- 现象：「CRLF 导致 sshd 解析失败」先成为注释、后成为结论，最终被反事实实验推翻。
- 机理：观察到 A（含 `\r`）与 B（规则要求 LF）之后，补了一个未验证的因果 C；因果一旦写入注释/报告，就被下游当作已验证知识继承。
- 迁移条件：任何「治理动作收益」的陈述；任何从「违反规范」直接跳到「导致故障」的推理。
- 反例：`.agents/scripts/docker-cache`（shebang + CRLF）确实是故障修复，因为内核 `execve` 对 `\r` 零宽容——此处因果成立且可复现。

**I3 工作区是索引的派生态，修复必须回到权威源。**
- 现象：逐文件 `rm` + `checkout` 后，字节减少量恰等于 CR 数，`git status` 无 `M`。
- 机理：索引 blob 早已是 LF；工作区形态是检出规则的产物。手工转码只改派生态，还会制造「索引与工作区不同」的假差异。
- 迁移条件：跨平台换行、可执行位、symlink 检出、smudge/clean filter 类漂移。
- 反例：若索引本身存的是 CRLF（历史遗留 blob 或二进制式文本），`checkout` 无法修复，必须重写 blob 并重新提交。

**I4 交付风险按层分布，单层绿灯不足以验收。**
- 现象：存储层证据（同 `st_dev=2049`、同 inode、sha256 一致）当时已全绿，但真正的消费者是 `sshd` 进程，而非文件本身。
- 机理：「文件相同」与「文件被目标程序正确加载」是两个独立命题；容器化交付天然把两者拆到不同层。
- 迁移条件：容器内配置文件、共享库、入口脚本的交付验收。
- 反例：纯只读且无运行期消费者的静态资产（归档、数据快照），存储层一致即足够，运行层无对象可验。

**I5 归档式导入让镜像失去层粒度，优化边界随之锁死。**
- 现象：14 GB 镜像中 13 GB（93%）来自 `openkylin:3.0` 单层。
- 机理：tarball 导入把整镜像压成一层，无法按包/按目录裁剪；只有应用层（1.06 GB）具备可操作性。
- 迁移条件：所有以 tarball/OCI 归档离线导入的基镜像。
- 反例：多阶段构建产出的镜像保留层边界，可按层裁剪（如丢弃构建期工具层）。

**I6 可逆隔离是删除的正确前态。**
- 现象：LLVM 23 三件套先 `mv` 至隔离目录（268 MB / 48 文件），回归通过并经批准后才删除，XFS 回收 280,948,736 B。
- 机理：删除不可回滚，`mv` 成本近似为零却保留回滚窗口，把「删除前的一次性判断」变成「删除后可验证的事实」。
- 迁移条件：疑似污染、重复、陈旧、来源不明资产的处置。
- 反例：已确认零引用且可由一条命令再生的缓存（如 pip/conda 下载缓存），直接删即可，隔离只增加步骤。

## 7. 萃取（E）：可复用手法、一次性结论与反模式

### 7.1 可复用的检查手法（11 项）

| # | 手法 | 命令 / 操作 | 证明什么 | 备注 |
|---|---|---|---|---|
| E-1 | 盘型与容量探测 | `Get-Volume` / `DriveType` / 可用字节 | 某路线在存储语义上是否可行 | 立项 15 分钟内可完成，成本极低 |
| E-2 | 三重存储层取证 | 双侧取 `st_dev`、inode、size、CR 数、sha256 | 容器与宿主看到的是**同一份文件** | `st_dev=2049` 是 overlay 的指示值 |
| E-3 | 控制组注入非法项 | 插入 `BogusOption` → 期望 rc=255 | 检查器具备区分力（「会说话」） | 任何第三方校验器的前置校准 |
| E-4 | 规则生效取证 | `git ls-files --eol` + `git check-attr text eol` | 规则确实命中（`i/lf w/lf attr/text eol=lf`） | 三者需同时为 LF 才算闭环 |
| E-5 | 从索引重放 | `rm` + `git checkout -- <显式路径>` | 修复的是权威源派生态，非手工转码 | 禁用通配符，逐文件显式路径 |
| E-6 | 字节差断言 | 修复前后字节数 − 减少量 = CR 数 | 修复未夹带其他改动 | 比「看着是 LF」强得多 |
| E-7 | 索引未改动断言 | `git status` 无 `M` | 索引原本即 LF，修复不产生新差异 | 与 E-4 联用可完全闭环 |
| E-8 | 删除前引用普查 | `grep` 于脚本、`profile.d`、文档、`readelf` 的 RUNPATH | 待删对象是否仍被引用 | rpath 是最隐蔽的引用 |
| E-9 | 可逆隔离流程 | `mv` → 回归 → 批准 → `rm` | 处置动作可回滚、可事后验证 | 隔离窗口应覆盖一次真实用例 |
| E-10 | 指令普查（弱证据） | 统计 `FROM` 数、未知指令数、末行是否截断 | 容器文件无明显结构性缺陷 | **不等于语法验证**，措辞必须区分 |
| E-11 | 体积归因 | 单层占比 / 卷外计 / 悬空对象 / 可写层 | 优化对象定位（哪一部分才可动） | 可写层与卷不计入镜像体积 |

**必须强调 E-10 的定性**：在没有 `--parse`/`--dry` 的情况下，指令普查只是**弱证据**。把它写成「Containerfile 语法校验通过」是本阶段最容易再犯的表述错误。

### 7.3 反模式（6 条）

1. **把 rc=0 当作「检查有效」**——缺少控制组，绿灯不可解释。
2. **把「违反规则」直接写成「故障原因」**——推断越级成事实，并被注释固化。
3. **手工转码修工作区**——改派生态，制造假差异，下次检出复现。
4. **把「悬空镜像」等同于「可回收空间」**——祖先层引用使其可能为零收益。
5. **对可疑资产直接 `rm`**——失去回滚窗口；应先 `mv` 隔离。
6. **用镜像标称体积推导磁盘占用**——`storage/overlay` 实测值可显著大于标称。
