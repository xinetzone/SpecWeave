# 内容敏感度预检规范

## 概述

内容敏感度预检是启动协议步骤 2.3 的详细规范，用于在任务执行前判定分析对象/产出物的内容敏感度级别，选择正确的工作流模式与存储位置，防止私域/敏感内容进入公共规划区域。**核心原则**：就高不就低——不确定时默认按私域处理，或向用户确认。

## 内容级别定义

### 公开内容（Public）

| 特征 | 说明 |
|------|------|
| 访问控制 | 无访问控制，任何人无需特殊权限即可访问 |
| 典型场景 | 公开发布的网页、开源代码仓库、官方文档、公开新闻/文章、公开 API 文档、技术博客 |
| 工作流模式 | **标准模式**：生成完整规划文档（spec/tasks 等） |
| 规划目录 | 公共规划区域（如 `.trae/specs/<theme-subdir>/`） |
| 最终产出物 | 面向公众的文档目录（如 `docs/` 下对应分类目录） |
| 可提交 Git | 是 |

### 私域内容（Private）

| 特征 | 说明 |
|------|------|
| 访问控制 | 需要特殊权限、邀请码、token、登录态才能访问 |
| 典型场景 | 内部会议记录/录音、带 code/token 的私域分享链接、个人笔记、商业培训材料、含隐私/商业秘密的内容、未公开文档、实验性内容 |
| 工作流模式 | **私域直接执行**：跳过公共规划区域，在目标目录直接执行 |
| 产出物目录 | `playground/` 下对应用户目录，或用户明确指定的目录 |
| 可提交 Git | 默认不提交（遵循 `.gitignore` 规则） |

## 判定信号清单

满足以下任一信号即判定为**私域内容**：

### URL 特征
- URL 路径含 `share?code=`、`?token=`、`?key=`、`?invite=`、`?pwd=` 等访问控制参数
- URL 含 `internal.`、`corp.`、`intranet.`、`private.`、`admin.` 等内部域名前缀
- 域名为企业内部应用（飞书/企微/钉钉内部链接、企业 CRM/ERP/OA、企业知识库）
- 需登录态才能访问的页面（未登录时跳转登录页）

### 用户信号
- 用户明确标注"私域"、"内部"、"保密"、"个人"、"不要外传"等关键词
- 用户指定目标目录为 `playground/` 或其他非公共目录
- 源文件位于临时目录、`playground/`、个人目录等非公共区域

### 内容主题信号
- 内部会议记录/纪要/录音转写；商业培训材料/课程笔记/付费内容
- 含个人身份信息（PII）的文档；商业秘密/财务数据/客户信息
- 未公开的产品规划/战略文档；个人笔记/随笔/实验性内容

### 不确定场景处理
- 信号不明确时 → 默认按私域处理
- 用户请求与个人判断冲突时 → 向用户确认："这个内容属于私域/内部内容吗？我将直接在 playground 目录下处理"
- 内容同时包含公开和私域部分 → 整体按私域处理，公开部分后续单独提取

## 工作流分流决策树

```
收到任务
  ├─ 步骤 2.0：任务类型预检（外部方法论资产）
  ├─ 步骤 2.3：内容敏感度预检 ◀── 本规范
  │   ├─ 命中私域信号？
  │   │   ├─ 是 ──► 私域工作流（跳过公共规划区域；直接在目标目录执行；产出物存 playground/）
  │   │   └─ 否 ──► 公开工作流（标准模式；公共区域规划；产出物到公共文档目录）
  │   └─ 不确定？ → 默认私域 或 询问用户
  └─ 后续步骤（规范读取 → 自检 → 执行）
```

## 私域工作流执行规范

1. **确定目标目录**：优先用用户指定目录；未指定时在 `playground/` 下创建语义化目录（如 `playground/reports/<topic>-<date>/`）
2. **跳过规划**：不生成公共规划区域下的规划文档
3. **直接执行**：根据任务类型选择合适的 Skill 和工具直接执行
4. **产出物管理**：所有产出物直接存放在目标目录（报告、笔记、截图等）
5. **元数据规范**：产出物 frontmatter 标注 `type: "private"` 或 `type: "playground"`
6. **不提交公共索引**：不将私域内容加入公共索引和导航表
7. **清理**：任务完成后不在公共规划区域留下任何规划文档

## 扫描版版权材料任务附加条款（route 决策前置）

源材料为**扫描版（无文本层）且受版权保护**的材料时，除执行私域工作流外，必须增加 route 决策前置工序：

1. **R 阶段第一步显式二选一**：逐字转录 / 深度摘要。默认摘要路线——逐字转录物本身即高侵权风险衍生物；深度摘要 + 原创改写在合规性与信息保真度上同时占优。
2. **决策写入 frontmatter**：摘要路线记 `route: chaptered-summary`；转录路线记 `route: verbatim-transcription` 并附选择理由、经用户确认（默认不批准）。
3. **禁止隐式执行**：不记录 route 决策即开始处理，视为流程违规。

**反模式**：默认先 OCR 逐字转录；摘要写成书摘集；部分章节转录、部分章节摘要导致引用红线声明无法全覆盖。

## 私域内容转公开流程

1. 提取通用部分（去除私域细节、个人信息、商业秘密）
2. 抽象为可复用模式/方法论
3. 存入公开的模式/知识目录，更新公共索引
4. 在原私域文档中添加"已沉淀公开模式：[链接]"引用

## 典型案例

| 案例 | 信号 | 判定与处理 |
|---|---|---|
| 私域分享页（本规范来源） | URL 含 `share?code=`，商业培训会议录音 | 私域：直接在 `playground/reports/` 下执行，不创建公共规划目录 |
| 公开技术博客分析 | 公开发布，无访问控制 | 公开：标准模式，最终报告到公共文档目录 |
| 企业内部文档分析 | 企业内部应用链接，需登录 | 私域：直接在 `playground/` 下执行 |
