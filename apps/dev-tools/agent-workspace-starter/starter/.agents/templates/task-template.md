# 任务模板

> **标准化模式集成**：本模板已应用以下模式——spec-driven-development（Spec 驱动开发，非平凡任务先写 spec 再执行）、three-tier-governance（三层治理闭环，验收包含自动化验证）、context-recovery-protocol（上下文恢复协议，保障任务上下文完整性）。

## 任务描述

```
任务名称: {任务名称}
任务类型: {feature/bugfix/refactor/test/docs/analysis/research}
优先级: {high/medium/low}
负责人: {角色 ID}
组ID: {group-id，同组任务将合并执行；单独执行填"N/A"}
Spec状态: {已完成/待编写/不适用（简单任务<3文件变更）}
预探索状态: {已完成/待执行/不适用（小型任务<5个分析对象）}
```

### 任务分组规则（group-id 说明）

同组任务（相同 group-id）将在同一次子代理调用中合并执行，以减少重复探索成本、提升输出一致性、降低上下文切换开销。

**合并判断标准（三项全部满足）**：①输入源重叠度 > 60%；②输出可自然融合；③合并后输出量 < 上下文窗口 60%。

**命名规范**：使用小写英文 + 连字符格式 `{主题}-{编号}`；单独执行的任务填 `N/A`。

### Pre-flight 预探索阶段（中大规模任务必须）

**目的**：减少子代理重复探索成本，提升并行执行效率。**执行方式**：主控代理一次性完成所有分析对象的结构概览，将结果作为共享上下文注入所有子代理。**输出物**：preflight-exploration.md。

| 任务规模 | 是否触发预探索 |
|---------|--------------|
| 小型（<5 个分析对象） | 不适用，跳过 |
| 中型（5-10 个分析对象） | 推荐 |
| 大型（>10 个分析对象） | 必须 |
