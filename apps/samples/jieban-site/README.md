# 结伴站点（jieban-site）

> 「结伴」品牌网站的**内容层**——Sphinx + MyST 静态站。
> 一期只搭骨架：构建链跑通 + 首页 + 社群公约两页；四频道详情与缘起页留占位。

## 定位

本应用是三层分离架构中的一层，依据见
`playground/reports/jieban-brand-20260918/结伴-技术选型建议-Sphinx与JupyterLite.md`：

| 层 | 载体 | 现状 |
|---|---|---|
| 信任层 `/` | 单文件 HTML 落地页（手工六屏） | 已有，不在本目录 |
| **内容层 `/guide/`** | **Sphinx + MyST** | **本应用** |
| 实验层 `/lite/` | JupyterLite + Voici | 三期，未启动 |

本应用**不是**品牌首屏。首屏是手工打磨的单页落地页（30 秒决策场景），
Sphinx 负责的是「内容会增长、需要多人协作、需要检索」的那部分。

```

│   ├── origin.md        缘起：四个群，一间客厅（含联邦制 Mermaid 图）
│   ├── covenant.md      社群公约：六条底线 + 举报处置 + 引文版本说明
│   ├── channels/        四个频道详情（入口 + 知足/恒与/知和/愈多）

├── tests/               契约测试

```

## 构建

```bash
pip install -r requirements.txt

# 构建（-W：警告即失败）
python -m sphinx -b html src build/html -W --keep-going

# 本地预览
python -m http.server -d build/html 8000
```

验证环境：`D:\Users\xinzo\anaconda3\envs\py314\python.exe`（Python 3.14.3 + Sphinx 9.1.0），
实测输出「构建成功」，零警告。

契约测试：

```bash
pytest apps/samples/jieban-site/tests
```

> 注：根 `pytest.ini` 的 `testpaths` 锁定 `.agents/scripts/tests`，本目录测试需显式指定路径运行。

## 构建期守卫：版本身份证

`conf.py` 在 `config-inited` 阶段检查两条正向不变量——**引文出现在哪，版本标识就必须跟到哪**：

1. 页面出现末章短引文「己愈多」→ 必须同时出现「帛书乙本」
2. 页面出现「知和曰明」→ 必须同时出现「帛书甲本」

不满足则构建直接失败。这是把品牌统筹报告 4.3 的「截断引用冒充帛书面貌」陷阱
变成机器可拦截的约束——引文合规不靠人记得，靠构建卡住。

「禁止笼统称帛书本」这条纪律以文字条款写在 `covenant.md`，**不**纳入自动检查：
公约页本身要引用这条规则，机械匹配必然误伤。

## 内容纪律

- **「结伴」二字不见于今本与帛书本《老子》原文**——站点不宣称其典出《道德经》。
  主名不背经典，slogan 与频道名承经义。
- 末章短引文一律用「既以予人矣，己愈多」（帛书乙本独见面貌）；甲本此句损掩。
- 「恒与善人」的帛书铁证是「恒」字（今本避汉文帝刘恒讳作「常」）。
- 「知和曰明」仅见帛书甲本，今本作「知常曰明」。
- 正式印刷前引文须再对勘高明《帛书老子校注》或文物出版社整理本。

## 相对原始文案的降敏处理

站点为**公开页**，故对品牌统筹报告 5.5 的四频道卡片文案做了四处降敏，均为调性红线（6.3）要求：

| 原表述 | 站点表述 | 理由 |
|---|---|---|
| 没有猎杀式**相亲** | 没有猎杀式**速配** | 红线禁用「相亲」 |
| 分享真案例、真工具、**真收入** | 真案例、真工具、**拒绝割韭菜** | 避免收益暗示（风险 #2 广告合规），且与落地页入群选择器文案一致 |
| 想学用 AI，多一份本事**和收入** | 想学用 AI，多一份**本事** | 同上：站内不做任何收益承诺 |
| 出自**帛书本**《老子》 | 帛书《老子》**第七十九章** | 落具体的章，不笼统称帛书本 |

「知和」频道页额外声明**与民政部门无任何关联**（风险 #3 官方机构误认的缓解措施）。

四个频道的**内部群昵称不上站点**，站点只用频道名（知足 / 恒与 / 知和 / 愈多），
由测试 `test_internal_group_nicknames_not_on_site` 守护。逐一对应的理由：

| 内部群昵称 | 是否上站点 | 理由 |
|---|:---:|---|
| 感恩小队 | 否 | 「感恩」易引发成功学／灵修污名联想（风险 #4） |
| 民政局小分队 | 否 | 官方机构误认（风险 #3） |
| 玩转 AI 变现 | 否 | 含红线禁用词「变现」（调性红线 #2） |
| 脱单公助会 | 仅首页品牌故事出现一次 | 缘起叙事的核心事实；「脱单」不在禁用词表内，且不进标题与导航 |

缘起页因此采取「**描述而不贴标签**」的写法：讲清四个群的来历与状态，
同时明说「我们没有给它们改名——它们在微信里仍叫原来的名字」，
既保住叙事真实性，又不把内部旧称搬上公开页。

## 主题说明（与选型报告的偏离）

选型报告第五章写的是「furo 主题定制为纸感」，但构建环境**未安装 furo**。
本应用改用 `sphinx_book_theme`——同为阅读优先主题，且对暖灰纸感的定制成本更低。
纸感 token 取自 `playground/reports/jieban-brand-20260918/jieban-style-tile.html`
（`--paper / --card / --ink / --line / --cinnabar / --dai` + 四频道色）。

深色模式：CSS 已隐藏主题切换按钮并将 `[data-theme="dark"]` 的语义色回落到浅色 token——
本项目明确不要深色模式，不使用 `default_mode` 选项（该选项 sphinx-book-theme 不支持）。

Mermaid：缘起页的联邦制结构图由 `sphinxcontrib-mermaid` 渲染，**前端从 jsDelivr CDN
加载 `mermaid.esm.min.mjs`**（版本已在 `conf.py` 里固定为 11.4.1）。这意味着：

- 图表需要浏览器能访问 CDN 才会显示；离线打开 `build/html` 时该位置只显示图表源码。
- 若后续要离线可用，需把 mermaid 换成本地静态文件——属于二期决定，一期保持 CDN。

## 一期范围

已做：构建链、纸感主题、首页、缘起页、社群公约、四个频道详情页（含频道入口页），共 7 个页面。

待补：**真实故事采集**（品牌统筹报告行动项 #3）——向各群收集 1–2 件真实互助小事，
用来替换首页故事里的示例性细节（做饭 / 跑步 / 换工作）。这是内容工作，不影响构建。

一期唯一要验证的假设仍是报告 6.4 的那条：
**品牌调性能否让陌生新人心动并愿意入群。**

频道页的固定结构：**引文与版本出处 → 这间屋子在做什么 → 你会遇到什么 → 谁适合来 →
频道边界 → 怎么加入**。「边界」一节是各页差异最大的部分，也是风险缓解措施的落点：

| 频道 | 页面上的边界条款 | 对应风险 |
|---|---|---|
| 知足 | 用「记录」不用「修行」；拒绝集会式教化 | #4 成功学/灵修污名联想 |
| 恒与 | 禁止一切收费导流；「愈多」不得向其推销；违者永踢并公示 | #1 杀猪盘联想（致命） |
| 知和 | 明示与民政部门无任何关联、不代办业务；经验非专业意见 | #3 官方机构误认 |
| 愈多 | 不得向「恒与」成员推销；不做收益承诺；投资/代币/境外平台即红线 | #1 + #2 广告合规 |

一期站内**不设任何表单**，加入途径写明为「微信端向管理员申请邀请」——
与选型报告「一期无后端」的结论一致，也满足「不收集个人信息」的隐私默认要求。
