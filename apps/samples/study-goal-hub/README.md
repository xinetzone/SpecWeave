# 学习目标管理台 · Study Goal Hub

> 管理**有终点、有总量**的学习目标（背完 2000 个单词、读完 440 页的书、刷完 30 节课），不是「每天喝水」那种无限期习惯打卡。

单文件 `index.html` 实现全部功能：**无外部库、无网络请求、资源全内联、断网可用**。双击即可打开，数据存 `localStorage`。

## 一、定位与边界

| 项 | 说明 |
|---|---|
| 位置 | `apps/samples/study-goal-hub/`（`apps/` 主仓库内置，可直接修改） |
| 形态 | 零构建单文件 HTML：内联 CSS + 内联 SVG 图标 + 内联 JS，favicon 与 Web App Manifest 均以 data URI 内联 |
| 适用 | 有截止日、有总量、可量化推进的学习/备考/读书目标 |
| 不适用 | 无限期习惯养成（无终点则「剩余量 ÷ 剩余天数」不成立） |
| 数据 | `localStorage['study-goal-hub.v3']`，只在本机浏览器，不联网、不上传 |

## 二、快速开始

```bash
# 直接打开
start apps/samples/study-goal-hub/index.html     # Windows
open  apps/samples/study-goal-hub/index.html     # macOS

# 或起个本地服务（便于手机同局域网访问）
python -m http.server 8000
```

首次打开会预置 3 个带「示例」标签的目标和若干记录，可一键「清空示例」。

| Tab | 内容 |

## 四、关键算法（诚实优先，不编数字）

### 1. 今日建议量

```
今日建议量 = ceil(剩余量 ÷ 剩余天数)      剩余天数含当天；逾期时剩余天数按 1 计
```

打卡时预填该值，允许修改。建议量按「当日剩余量 ÷ 当日剩余天数」逐日重算，所以补记会自动摊平后面的节奏。

### 2. 连续打卡天数（每周自动使用 1 个休息日）

- 从今天往回逐日扫描；**今天还没结束，今天没打卡不算中断**。
- 遇到空缺日时，检查该日所在周（**周一起算**）的休息日配额：本周尚未用过则抵扣并继续，**同一周第二次空缺才真正中断**。
- 配额按周重置，跨周重新开始。
- 补记按**真实日期**参与计算，因此补上昨天的卡会立刻修复连续天数。

### 3. 预计完成日

```
近 7 天平均速度 = 近 7 天总量 ÷ 7
预计完成日 = 今天 + ceil(剩余量 ÷ 平均速度)
```

**样本不足时显示「暂无推算」**：近 7 天内有记录的天数 < 2，或近 7 天总量为 0，一律不推算。与截止日比较后显示「比截止早 N 天 / 晚 N 天 / 正好卡线」。

### 4. 昨日漏打卡的两张卡

| 卡片 | 触发条件 | 文案基调 |
|---|---|---|
| 🟡 琥珀卡 · 休息日 | 昨天所在周内（周一至昨天）这是**第一次**漏 | 已自动用掉本周的 1 个休息日，连续 N 天未中断 |
| 🔴 红卡 · 滚入今日 | 该周已漏过 ≥ 2 次，休息日已用完 | 连续天数已中断，昨天该做的量已滚入今日 |

> **已知边界**：若今天是周二，则本周只过了 1 天，「第二次漏」在逻辑上不可能发生，此时所有漏打卡都正确显示为黄卡。这是规则本身的必然结果，而非缺陷。

### 5. 逾期出口

截止日早于今天且未完成时，卡片显示逾期天数，并同时提供两个出口：**立即打卡**（推一把）与**调整计划**（打开编辑弹窗并聚焦截止日——把计划改成能做到的样子，同样是正经出口）。

## 五、预置示例状态覆盖

| 目标 | 覆盖状态 |
|---|---|
| 背完 2000 个考研核心词 | 昨天漏打卡 → 休息日抵扣（黄卡）；含 1 条带「补」标的补记记录 |
| 读完《人类简史》440 页 | 连续多日漏打 → 红卡滚入今日；含补记 |
| 刷完 Python 入门课 30 节 | 已逾期数天；近 7 天样本不足 → 预计完成日显示「暂无推算」 |

三个目标均填写了「最容易拦住我的障碍」与「如果它出现，我就……」的对策，卡片上直接展示。

> 示例数据按**当天日期动态生成**（以「昨天所在周的周一」为锚点），因此无论星期几打开，休息日黄卡状态都成立。

## 六、其他行为

- **备份横幅**：累计打卡记录 ≥ 20 条后，页面顶部出现温和提示，可直接导出；导出或手动收起后不再出现。
- **跨天自动刷新**：从后台切回时若检测到已跨天，自动重算所有「今日」数据。
- **即时保存**：新建目标表单草稿、周报四栏均为输入即存。
- **响应式**：手机底部四 Tab + 单列；平板顶部横向导航 + 双列；电脑左侧固定边栏 + 多栏网格。
- **视觉**：冷白底、紫色渐变主色、绿色成功、红色逾期、琥珀色休息日；目标达成触发彩带动效；图标全部为内联 SVG，不使用 emoji。

## 七、数据模型与迁移

```jsonc
{
  "schemaVersion": 3,
  "goals":  [{ id, name, unit, total, deadline, color, obstacle, plan, createdAt, sample, doneAt }],
  "logs":   [{ id, goalId, date, amount, minutes|null, note, backfill, createdAt }],
  "weeklyNotes": { "<周一日期>": { keep, problem, tryNext, plan } },
  "settings": { bannerDismissed, lastExport },
  "draft":   { goal: { ...新建目标表单草稿 } }
}
```

导入时的迁移链（见 `migrate()`）：

| 来源 | 字段映射 |
|---|---|
| v1（无 `schemaVersion`） | `title→name`、`target→total`、`dueDate→deadline`、`blocker→obstacle`、`ifThen→plan`、`records→logs`、`gid→goalId`、`day→date`、`value→amount` |
| v2 | 补全 `weeklyNotes`、`settings` |
| v3 | 当前版本 |

旧键 `study-goal-hub.v2` / `.v1` / `study-goal-hub` / `goal-hub` / `goalHub` 中的数据可通过「我的 → 旧版本迁移」一次性收进来。
