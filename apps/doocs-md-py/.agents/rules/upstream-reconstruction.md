# 上游复刻与契约审计纪律

> **适用范围**：任何涉及「与上游 `doocs/md` 对齐程度」的改动 —— 新增或修改模块、登记行为差异、裁决契约口径、定义渲染或 API 验收。
> **权威事实源**：[../../docs/architecture.md](../../docs/architecture.md)（模块级映射总表）、[../../docs/contract-differences.md](../../docs/contract-differences.md)（差异台账）、上游参照树磁盘源码。
> **文档与代码冲突时以代码为准**：文档（含本文与 spec）与上游磁盘源码不一致时，一律以磁盘源码逐行对拍为准。

## §1 上游基线唯一化

- 上游项目：`doocs/md`；基线版本 **v2.1.0**；commit **`1bdad48d20048bddc8d32afb1b75a6475169f163`**（2026-10-12）。
- 参照树（**只读**）：`d:/AI/.chaos/libs/md`。该目录位于 `.chaos/` 下，**不得修改、不得提交**；本应用对该树的依赖仅为「对拍证据源」。
- 基线变更（上游升级 / 重新锁定 commit）属于**口径级变更**，必须：
  1. 更新 [../../docs/architecture.md](../../docs/architecture.md) 首部基线声明与本文 §1；
  2. 全量重跑黄金样例与契约测试，逐条复核 [../../docs/contract-differences.md](../../docs/contract-differences.md) 存量条目是否仍然成立；
  3. 在 [../CHANGELOG.md](../CHANGELOG.md) 记录基线迁移条目。

**禁止**：在不更新基线声明的前提下，直接按「记忆中的上游行为」或「上游最新 main」改代码。任何未绑定到上述 commit 的上游断言一律视为**未取证事实**，不得作为裁决依据。

## §2 锚点注释强制

- 每个复刻模块的 docstring 或首部注释必须标注上游锚点，格式固定为：

  ```
  # upstream: <上游相对路径>:<行号>
  ```

  上游相对路径相对上游 monorepo 根（如 `packages/core/src/renderer/renderer-impl.ts:88`）。
- **关键魔数**（阈值、限宽、超时、配额、颜色、字号、正则、白名单）必须集中为命名常量，并在常量处注释来源行号 —— **不得把魔数散落在逻辑分支中**。
- 本仓**新增**（无上游对应）的模块用 `# upstream: —（本仓新增）` 显式声明，并在差异台账登记对应 `CD-` 编号（见 §4）。
- 锚点漂移风险：上游行号随版本演进会失效。基线锁定（§1）即为锚点有效性前提；行号可疑时**重新对拍**而非猜测。

## §3 复刻口径三分类

每个模块/函数在 [../../docs/architecture.md](../../docs/architecture.md) 中必须归类为以下三者之一，归类即契约：

| 口径 | 含义 | 附加要求 |
|------|------|---------|
| **逐字复刻** | 与上游逐行等价，行为与边界条件一致 | 锚点精确到函数；差异台账无需登记，但测试须覆盖边界 |
| **等价实现** | 因运行时/生态差异换实现（如 marked→markdown-it-py、DOMPurify→nh3、D1→SQLite、R2→S3），**对外行为等价** | 必须登记 `CD-` 编号并说明「等价性论证 + 已知残余差异」 |
| **规格新增或裁剪** | 本仓主动增加或去除的能力 | 必须登记 `CD-` 编号 + 说明动机与影响面 |

判定顺序：**先问"对外可观测行为是否一致"，再问"实现是否同构"**。实现不同但行为一致 = 等价实现；行为不同 = 规格变更，无论实现是否同构。

## §4 行为差异台账流程

- 台账位置：[../../docs/contract-differences.md](../../docs/contract-differences.md)。编号规则：
  - `D-<n>`：**结构性 / 平台级**差异（如 D1→SQLite 方言、R2→S3 对象存储、前端托管方式）；
  - `CD-<n>`：**契约细节级**差异（如净化后端、代码高亮包裹、CSS `calc()` 缺陷复刻）。
- 每条登记至少包含：**差异主题 / 上游锚点 / 本仓锚点 / 裁决结论 / 影响面（是否对外可观测）**。
- **禁止静默偏离**：任何非逐字等价的实现，未登记即为缺陷。新增差异的五步流程：
  1. 对拍上游磁盘源码，确认差异**真实存在**（排除误读）；
  2. 判定差异是否对外可观测（不可观测的记入 §2 注释即可；可观测的必须登记）；
  3. 取下一个未被占用的 `D-`/`CD-` 编号，写全五个字段；
  4. 配套补一条**回归测试**覆盖该差异的裁决口径（正向断言"本仓行为"）；
  5. 同步 [../../docs/architecture.md](../../docs/architecture.md) 对应行的「复刻口径」列与本文 §3 归类。
- **禁止**复用已占用编号，**禁止**在台账中写"待定/TODO"结论 —— 台账只承载已裁决事实。

## §5 验收口径

- 上游锚点审计依据分两级，二者都必须可机械复核：
  - **AC-U2（可审计的上游对应关系）**：从任一 Python 模块可定位到上游文件与行号；由 §2 锚点注释 + architecture.md 映射表承载。
  - **AC-U3（差异有据可查）**：任一非逐字等价处均有台账条目与锚点；由 §4 承载。
- **渲染验收口径 = 归一化 DOM 等价**（NG6）：marked 与 markdown-it-py 的 token 模型存在固有差异，**禁止承诺 HTML 字节一致**，也**禁止**把"字节比对"写进任何验收标准。对拍由 [../../src/doocs_md_py/render/domcompare.py](../../src/doocs_md_py/render/domcompare.py) 与黄金样例集承载。
- 契约测试（端点/字段/常量）以 [../../docs/contract-mapping.md](../../docs/contract-mapping.md) 为对拍表；测试里出现的上游常量必须能在该表找到出处。

## §6 非目标冻结（NG1–NG6）

以下能力**明确不复刻**，任何人不得以"上游有"为由新增（新增需走 NG 解冻流程，见下）：

| 编号 | 冻结内容 |
|------|---------|
| NG1 | VS Code 扩展 / uTools 插件 / 浏览器扩展等宿主端形态 |
| NG2 | 浏览器运行时能力（PDF 打印、截图、剪贴板内联、浏览器内直传、用户 JS 沙箱等） |
| NG3 | 云服务运营特性（多租户、计费、平台化运维） |
| NG4 | 平台运维等价（Cloudflare Workers 运行时语义、边缘部署拓扑） |
| NG5 | 服务端 AI 代理（服务端代调大模型） |
| NG6 | 字节级渲染一致（验收口径见 §5，改为归一化 DOM 等价） |

**平台差异处置**：上游绑定平台（Workers / R2 / D1 / DOMPurify / marked / 宿主浏览器）的能力，在本仓一律按「等价实现」或「规格裁剪」处理，**登记对应 `D-`/`CD-` 编号**，不得因平台缺失而静默降级。

**NG 解冻流程**：提出者须在差异台账新增条目，写明**动机 / 与现有 NG 的冲突点 / 替代方案 / 影响面 / 回归方案**，经用户明确批准后方可实施；未经批准的解冻等同违规。

## §7 反模式（出现即打回）

| # | 反模式 | 后果 |
|---|--------|------|
| A1 | 按「记忆中的上游行为」改代码，未对拍磁盘源码 | 引入无法审计的伪契约 |
| A2 | 模块无 `# upstream:` 锚点，或魔数散落无来源注释 | AC-U2 审计断链 |
| A3 | 换实现但对外行为有差异却未登记 `D-`/`CD-` | 静默偏离，AC-U3 失效 |
| A4 | 在验收标准里写「HTML/响应体字节一致」 | 违反 NG6，必然长期红 |
| A5 | 复用已占用编号或留下"待定"结论 | 台账失去裁决价值 |
| A6 | 修改 `d:/AI/.chaos/libs/md` 参照树 | 污染证据源，不可逆 |

## 变更纪律

- 本文档只增不删；口径变更须先更新 [../../docs/architecture.md](../../docs/architecture.md) 与 [../../docs/contract-differences.md](../../docs/contract-differences.md)，再回写本文，最后记 [../CHANGELOG.md](../CHANGELOG.md)。
- 与父级冲突时：本文件优先（嵌套优先原则），但不得违反 SpecWeave 根契约的强制条款。
