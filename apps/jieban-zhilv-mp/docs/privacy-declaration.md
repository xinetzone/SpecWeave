# 小程序用户隐私保护指引

> **申报草稿，尚不可直接提交，非线上生效版本。**
> 2026-10-28 按当前仓库代码核对了处理路径；开发者主体与真实联系方式、数据保存与删除安排、
> 手机号等字段的必要性、云服务处理关系及用户同意流程仍待确认。
> 本轮未登录后台、未保存平台声明、未重新提审；本地测试通过不代表平台审核通过。

材料确认后，在「管理 → 版本管理 → 提交代码审核 → 信息填写页面」对应待审版本填写隐私指引
（既有流程称“入口2”，实际入口及字段以后台为准）。逐项核对待审包、平台扫描结果和下列业务处理路径，
不能只按隐私 API 扫描结果填写，也不能用现网版本的声明代替待审版本核验。

## 一、引导语

本指引是本小程序开发者为处理你的个人信息而制定的说明草稿。
开发者主体名称待确认，正式提交前须与小程序后台登记主体一致。

## 二、开发者处理的信息

以下内容描述当前代码实际处理的信息，不代表这些字段的必要性或授权流程已通过核验。

- 开发者收集你选中的照片或视频信息，用于为报名记录添加配图。当前仅支持图片，可从相册或相机选择；先本地预览，报名成功后才上传至云存储并关联该报名。
- 开发者收集你手工填写的手机号，保存在报名记录中，并在“我的报名”中供你查看。当前表单将手机号设为必填；必填的必要性及是否存在后续联系用途仍待确认，不能据此宣称已有短信通知或主办方联系功能。
- 开发者处理云服务返回的用户标识和登录来源，用于识别登录状态、关联本人活动与报名记录；会话资料会缓存在本机。
- 开发者处理云服务返回的可选展示名和头像地址，随会话资料缓存在本机；展示名还会随报名保存为报名人名称。仅在云服务返回相应值时处理，不能仅凭字段名认定它们就是微信真实昵称、头像；头像地址缓存的必要性仍待确认。
- 开发者处理你选择的活动、报名人数、选填备注及报名状态、创建时间，用于保存和展示本人报名记录、计算活动已报名人数。备注可能包含你主动填写的个人信息，不因它是自由文本而排除在处理范围之外。
- 开发者处理你主动填写并发布的活动内容，用于展示活动、接受报名及管理本人发布的活动；已发布活动的内容会公开展示。

### 信息类型与处理路径对照

| 处理的信息 | 实际路径 | 代码依据 |
|---|---|---|
| 选中的照片或视频信息（当前仅图片） | `wx.chooseMedia` → 本地预览 → 报名后上传 → 绑定记录 | [选择和上传](../pages/signup/signup.js)、[绑定接口](../utils/api.js) |
| 手填手机号 | 表单输入 → `onInputContact` → `api.signup` → `submit_signup.p_contact` → `registrations.contact` | [报名表单](../pages/signup/signup.wxml)、[报名逻辑](../pages/signup/signup.js)、[API](../utils/api.js)、[数据库](../scripts/db/schema.sql) |
| 用户标识、登录来源与可选展示名、头像地址 | `signInWithWechat` → `cacheUser` → `wx.setStorageSync`；展示名另经 `ownerName` 写入报名 | [会话缓存](../utils/auth.js)、[报名逻辑](../pages/signup/signup.js)、[API](../utils/api.js) |
| 活动关联、报名人数、备注、状态和时间 | 表单及服务端生成字段 → 报名记录；有效报名人数参与聚合 | [报名表单](../pages/signup/signup.wxml)、[数据库](../scripts/db/schema.sql) |
| 主动发布的活动内容及归属 | 发布表单 → 活动 RPC；已发布内容可公开读取，归属由服务端确定 | [发布页面](../pages/publish/publish.js)、[数据库](../scripts/db/schema.sql) |

`wx.login` 获取登录 code 并交给云服务建立会话；当前业务代码没有通过 `wx.getPhoneNumber`
取得手机号，但手工输入和入库同样属于收集。SDK 返回资料一旦在小程序中缓存、使用，也属于应用处理，
不能写成“仅由云服务处理”。

隐私 API 扫描只覆盖部分入口，上表还依据表单、SDK 返回值、本地缓存和数据库写入核对。
平台若要求选择“手机号”“昵称、头像”等类别，应按待审包实际处理的数据及当前表单定义匹配；
可选云资料的来源和类别尚待核实，不能把本地字段名当作平台类别核验结果。
项目根目录的 `.<applicationId>.privacy.json` 是云服务侧的声明面，与平台隐私指引分别维护，不能互相替代。

## 三、开发者对信息的存储

当前代码将会话资料缓存在本机，将活动与报名记录写入云数据库，将报名配图上传到云存储。

保存期限待确认：需分别确定会话资料、活动、报名记录、配图的保存期限或明确的期限确定方式、起算条件，
以及到期删除、备份处理和用户申请删除的执行方式。旧草稿中“活动结束后 180 天清理”没有已核实的履行证据，
不能作为现行承诺提交；本轮未验证云端是否另有清理流程。

取消报名只把记录状态改为 `cancelled`，不删除数据库记录或云端配图。
删除小程序也不能代替云端删除；本轮未验证它对本地授权记录和 SDK 缓存的具体影响。

## 四、信息的使用规则

1. 正式指引应逐项写明经确认的具体用途，不以“改善体验”等空泛措辞代替。
2. 手机号必填、头像地址缓存，以及备注中可能涉及的健康等敏感信息，需在提审前核实必要性和相应告知、同意安排；未确认前不得把本草稿当作完整合规结论。
3. 使用目的或范围变化时，应先更新告知内容，并按适用要求取得用户同意，再开始新的处理。

现有静态测试只验证授权函数存在及媒体调用前的代码顺序，不证明用户作出了同意。
`utils/privacy.js` 的 `onNeedPrivacyAuthorization` 回调直接执行 `resolve({ event: 'agree' })`，
需要复核是否缺少真实的用户确认；还需核验登录、手填信息提交、首次选图、拒绝及撤回授权的行为。
本轮未修改授权逻辑，也未完成真机验证。

## 五、信息对外提供

当前应用使用 WorkBuddy 云服务完成登录、数据库和图片存储。服务提供方主体、处理的信息范围、
委托处理或其他提供关系、存储地点及相关隐私说明仍待开发者核实，不能笼统填写“没有第三方处理”。

仓内权限规则将报名明细读取限制为本人；这不代表云服务提供方或运维侧的全部访问情况已核实。
已发布活动的内容可公开读取，与私有报名明细不同，不能承诺“所有信息均不公开”。
正式指引需说明上述区别，并提醒发布者不要把本人或他人的联系方式等私密信息填入公开活动内容。

## 六、用户权益

你可在“我的报名”中查看及取消本人有效报名；取消不等于删除个人信息。
涉及照片等权限，可在微信小程序右上角“…” → “设置”中查看当前可管理的授权项，具体项以微信版本为准；
撤回权限不自动删除已上传的信息。

查阅、复制、更正、删除等申请的接收渠道、身份核验方式、处理流程及答复安排尚待开发者确认。
正式提交前须验证该渠道能够接收申请，并确认数据库、对象存储及备份各自的处理方式；
不能以删除小程序或取消报名代替这些权利的处理。

## 七、联系方式

开发者联系邮箱：待填写真实、可接收并处理隐私申请的邮箱。
原示例邮箱已移除，不能用占位邮箱提交。主体、联系方式、保存安排及上述待确认项补齐后，
才可将经确认的内容填写到待审版本，并保存、重新提审及记录审核结果。
