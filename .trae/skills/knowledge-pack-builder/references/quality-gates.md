# 质量门判定细则与实战踩坑

> 本文件是 SKILL.md 的展开参考，只在需要核对门标准细节或处置踩坑时加载。质量门顺序（G1→G2→G3→V→G4）不可颠倒；一门不过不得推进，修复后回当前门重检。

## 1. 各门判定清单

### G1（R 阶段事实门）

- 事实总数 ≥20；每条有唯一编号并集中登记于 index 事实表。
- 全文事实层无因果词：因为、所以、导致、从而、使得、推动了、促使、助力（作因果用时）。
- 数字/日期/版本号/URL 完整：不写"近期/很多/大幅"，写"2026-09-18""57.3%（沙利文白皮书媒体转引）"。
- 每条事实至少 1 个信源键；单点信源、三级信源显式标注。
- 矛盾数据并列保留（不同页面日期、两份报告不同数字），并注明各自取数位置。
- 引用本地包只用锚点表，不复制对方事实原文。
- 规模数字带口径四件套：统计对象、时点、发布方、原始/转引层级。

常见挂门原因：把"导致"写进事实表；动态页面数据写成点值；转引数据不标转引；把媒体定性句放进事实表（应独立编号并标"媒体定性评价"）。

### G2（I 阶段洞察门）

- 洞察 ≥3 条，每条四元组齐全：陈述、证据（编号）、反常识、行动。
- 维度独立：逐条检查是否有两条在解释同一件事（供应链/治理/技术/AI/市场这类不同轴）。
- "反常识"必须真有冲突：写出"直觉认为 X，证据显示 Y"；没有冲突的只是摘要不是洞察。
- "行动"必须可执行：清单/问题集/核查动作，不写"值得重视"。
- 证据闭环：洞察引用的每个编号都能在 G1 事实表中找到。

### G3（E 阶段模式门）

- 模式名 4—8 个汉字（或等效短语），名实相符。
- 双边界：适用于 + 不适用于都要写。
- 步骤 3—7 步，按执行顺序编号，每步是动作不是观点。
- 反模式 ≥3，最好含一个"按知名度/总量决策"型认知反模式。
- 检验标准可客观判定（第三人能复核），不写"效果良好"。
- 跨域迁移 ≥1 个具体领域。
- 成熟度标注：L1-draft（单案例首成型）→ L1（≥2 独立案例）→ L2（多案例且有独立验证记录）；写明升级条件。
- 默认只在包内成型；独立入 `docs/retrospective/patterns/` 需用户明确要求，入库时模式文件与知识包双向加链。

### V 门（对抗审查）

- 四视角缺一不可：魔鬼代言人、新人、老板、未来。
- 意见总数 ≥5，每条是具体攻击点（指向具体数字/结论/缺口），不写空泛问题。
- 裁定三态：采纳 / 部分采纳（写明采纳与不采纳部分）/ 不采纳（必须给理由）。
- 回归确认逐条关闭，引用具体文件与章节；禁止"已修改"式空确认。
- 典型攻击库（每个包至少自查）：官方口径数字无复测、跨对象统计口径对比、多源日期压成单一、术语墙无入口、社区版/商业版 SLA 混同、新版本窗口与协议更替的过期风险、信源结构偏官方、非发起方贡献占比无数据却下中立性结论。

### G4（原子化与工程门）

- 文件单一职责：index 是登记与摘要，概念页是问题域展开，references 是台账与审查记录。
- 包内文件数 8—14 为宜；概念页按读者问题命名（00-overview、05-selection-guide 等），文件名 kebab-case 纯英文。
- 链接相对路径且实测有效；无 `file:///`、无 `.temp/` 引用。
- toctree 双登记：包内隐藏 toctree 列全子页；上层索引追加一行。
- frontmatter 仅 index.md 需要，YAML 合法；表格行列变更整表替换。
- 文件名检查与链接检查两条脚本均通过。

## 2. 路径层数速查（断链高发点）

| 引用位置 → 目标 | 相对路径写法 |
|---|---|
| `<bundle>/index.md` → `docs/retrospective/...` | `../../../retrospective/...` |
| `<bundle>/concepts/0x.md` → `docs/retrospective/...` | `../../../../retrospective/...` |
| `<bundle>/index.md` → 包内概念页 | `concepts/0x-*.md` |
| `<bundle>/concepts/0x.md` → 包内另一概念页 | `0y-*.md` |
| `<bundle>/references/x.md` → 兄弟知识包 | `../../<sibling-bundle>/...` |
| `<bundle>/concepts/0x.md` → 包内 references | `../references/...` |
| `<bundle>/references/x.md` → 包内概念页 | `../concepts/...` |

规则：先数自己在 `docs/` 下第几层（域 bundle 的 index 在第 3 层，子页在第 4 层），再数目标层数；落盘后一律跑 check-links.py 实证，不要心算提交。

## 3. 本仓环境事实（2026-09 实测）

- Windows 环境，PowerShell 7；`python` 不在被裁剪的 PATH 中，直接调用会报"术语无法识别"。可用解释器全路径：`C:\Users\XMICUser\AppData\Local\Programs\Python\Python314\python.exe`。
- `check-filename-convention.py` 不带参数会全仓扫描（含 projects/vendor submodule），耗时极长（实测数分钟未完）；对新包检查务必加 `--directory docs/knowledge/<域>/<bundle>`。
- `check-links.py` 用 `--path <目录>` 限定范围，输出断链的行号与解析后的绝对路径，按图索骥即可。
- 检查器两个容易误伤模板的规则：① 行内反引号代码中的 `[文字](路径)` 仍会被提取为链接（只有围栏代码块被跳过），模板里的示例链接一律写"文字 → `路径`"纯文本形式；② `**<占位符>**` 会命中 BOLD_AUTOLINK_RE 被当作 autolink 报断链，加粗项不要包尖括号，写成 `**角色一（示例）**`。
- Sphinx 配置 `suppress_warnings = ["myst.xref_missing"]`，但 toctree 未登记的页面不会进入侧边栏导航；包内子页必须在 index 隐藏 toctree 中列出。

## 5. CMD-LOG 事件序列（场景 4 标准集）

必需事件：`S0 CMD_START` → `S2 CHAIN_SELECTED`（ctx 含 chain 与 depth）→ `G1 GATE_PASSED`（ctx 含事实编号范围）→ `G2 GATE_PASSED` → `G3 GATE_PASSED`（ctx 含模式名）→ `V GATE_PASSED`（ctx 含 adopted/partial 计数）→ `S99 CHAIN_COMPLETED`（ctx 含 gates 数组与 deliverable 路径）。

失败事件用 `GATE_FAILED` + 修复后重发 `GATE_PASSED`，不允许抹掉失败记录。

## 6. C 阶段提交边界

- 默认只提案不执行；提案信息为中文 Conventional Commits，scope 用 knowledge，例如：
  `docs(knowledge): 新增 <主题>知识包——<一句话价值>（七概念R-I-E-V-C）`
- 一次提交只含：新包全部文件 + 上层 toctree 的一行登记。模式独立入库、目录合并、索引刷新属于不同职责，另起提交。
- 用户明确说"提交"后再执行；任何情况下不主动 push。
