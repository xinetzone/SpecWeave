# 洞察（I 阶段）

> 每条洞察含四元组：陈述 / 证据 / 反常识 / 下次行动。证据编号对应 `facts.md`。

## I-1 框架竞争的焦点已从“模型接入”转向“长任务运行时”

- **陈述**：MAF 1.0 把“能调模型”视为基线，Build 2026 的增量几乎全部投在长任务运行时：Harness 的待办、压缩、文件记忆、审批、可观测性，以及 Foundry 的缩容保留与 Durable 的持久执行。
- **证据**：F-036、F-038、F-087、F-092、F-099。
- **反常识**：这些能力不是“高级可选”，而是**默认开启**；默认值越强，默认攻击面与默认副作用越大（文件写盘、Web 搜索、审批规则）。
- **下次行动**：新项目接入 Harness 时，先做一张“默认开关审计表”，逐项确认是否符合威胁模型，再谈功能。

## I-2 安全正在分成“数据流控制”与“执行隔离”两层，但两层尚未打通

- **陈述**：FIDES 用标签在工具调用前确定性拦截数据外流；CodeAct 用 micro-VM 隔离代码执行。两者解决不同问题，且当前组合存在明确缺口：CodeAct 内生成的宿主工具调用绕过 FIDES。
- **证据**：F-062、F-064、F-065、F-104。
- **反常识**：**沙箱越强，不代表数据越安全**。沙箱限制“代码能碰什么”，FIDES 限制“数据能流向哪”；CodeAct 路径目前让后者失效。
- **下次行动**：把需要 FIDES 的工具保留为直接代理工具；在采用 CodeAct 的流程里单独做数据流评审，而不是复用水印式“已隔离”结论。

## I-3 多代理的可靠性来自“显式拓扑 + 可恢复状态”，而不是更聪明的代理

- **陈述**：Handoff 把路由决策交给代理、把拓扑与护栏留给开发者；检查点与 Durable 把执行状态外置。三者共同把“代理的自主性”约束在可恢复的边界内。
- **证据**：F-078、F-079、F-109、F-092。
- **反常识**：代理越自主，越需要外部的状态机与幂等设计；否则一次崩溃就会让“自主”变成“重复扣款”。
- **下次行动**：先画拓扑与状态转移，再写代理指令；外部副作用一律加幂等键。

## I-4 文档与公告的“口径差”是框架快速演进的必然产物

- **陈述**：Build 2026 博文与 2026-10 文档在压缩条件、Go 支持、Copilot SDK 时间线上存在差异；这些差异多不是错误，而是“公告先行、文档后补”。
- **证据**：F-037、F-005、F-108、F-120。
- **反常识**：**读最新文档不等于读对**；公告解释“为什么”，文档解释“怎么配”，两者缺一不可。
- **下次行动**：任何“默认行为”声明都以文档的能力矩阵为准；公告只用于理解动机与路线。
