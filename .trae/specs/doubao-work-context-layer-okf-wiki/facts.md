## 核心论点（F-021~F-035）

| 编号 | 事实 | 核验 |
|------|------|------|
| F-021 | 📝 "有Context的Agent才有壁垒可言" | 📝 核心论点 |
| F-022 | 📝 每天产生的想法/判断/需求都有痕迹（老板群里提想法、开会讨论需求），这些Context基本都在飞书的群聊/会议/文档/审批流里 | 📝 |
| F-023 | 📝 飞书是Agent的Context Layer | 📝 核心比喻 |
| F-024 | 📝 Codex/Claude Code等Agent过去解决的核心问题是个人效率，个人效率提升不等于组织效率提升 | 📝 |
| F-025 | 📝 Coding只是整个工作流程中的一个环节；Agent作为个人效率工具只提升局部效率，融入团队工作流才提升组织效率 | 📝 |
| F-026 | 📝 Claude Tag看起来轻但重要，表面把Claude放进Slack，背后逻辑是Agent可成为企业基础设施 | 📝 |
| F-027 | 📝 豆包工作主线是做企业级Agent；个人Agent提升个人效率，企业Agent改变组织协作方式 | 📝 |
| F-028 | 📝 使用AI最大成本之一变成不断给它补充Context | 📝 |
| F-029 | 📝 "没有充分的上下文，Agent在干活时就只能瞎猜" | 📝 |
| F-030 | 📝 同样写招聘JD，有无上下文交付质量天差地别 | 📝 |
| F-031 | 📝 各Agent基础能力（PPT/数据分析/文档/浏览器操作）已做得很好，接下来真正重要的竞争是Context的竞争 | 📝 |
| F-032 | 📝 Coding场景Context相对简单（大部分在代码仓库/GitHub/本地文件），但白领工作场景Context不规整，在飞书群聊/知识库/会议/文档里 | 📝 |
| F-033 | 📝 办公Agent本质不是个人工具，而是服务组织的Agent，需理解企业知识/流程/协作关系 | 📝 |
| F-034 | 📝 这就是字节合并豆包和飞书的原因 | 📝 |
| F-035 | 📝 "豆包工作的后劲，才刚刚开始" | 📝 金句 |
