# 微信公众号全量内容采集与存档管线 - Product Requirement Document

## Overview

- **Summary**: 建设一套可复跑的微信公众号内容采集与存档系统，覆盖「自有公众号」与「他人公众号」双轨：以**私有部署的开源采集引擎 wechat-article-exporter 为凭证与列表内核**，自研 **Python 薄管线**完成全量历史回溯、富媒体本地化、多格式存档、增量监控、RAG 知识库导出与基础数据分析；并以 wechatDownload 作为富媒体/评论采集的桌面端兜底与交叉验证手段。
- **Purpose**: 解决微信生态封闭导致的四个痛点：①官方不提供历史群发文章的完整导出能力（自有号亦如此）；②优质内容随删文/封号失联，需要本地离线存档；③存量内容无法进入个人 AI 知识库（RAG）进行检索问答；④文章与互动数据分散，无法做选题与发布节奏分析。
- **Target Users**: 用户本人（个人学习、内容存档、个人 RAG 与数据分析）。他人号采集验证样例：播客类公众号「意识食谱」（@XELA赛拉，示例文章 `https://mp.weixin.qq.com/s/o8akvA6Rba2BkKvQPWymlQ`）。

## Goals

- 给出 2026 年现状下四条技术路线（官方开放 API / 开源后台接口代理 / 桌面端密钥捕获 / 商业与托管服务）的完整对比、风险反证与明确选型。
- 对指定公众号（以「意识食谱」为验证样例）完成**全量历史图文**采集：标题、作者、发布时间、原文链接、原始 HTML、正文 Markdown、图片本地化。
- 完成**富媒体**采集：文章内嵌语音（mpvoice，播客号核心资产）可下载；图片无水印本地化；腾讯视频 embed 可解析记录；视频号卡片明确标记为不可得。
- **条件性**采集评论与互动数据（评论、阅读数、点赞、在看）：凭证可用时入库，凭证缺失时优雅降级、主流程不中断。
- 支持**全量回溯 + 持续增量**：幂等、断点续传、二次运行只处理新增。
- 产出三类消费物：本地离线存档（Markdown/HTML）、RAG 语料（JSONL）、分析报表（CSV/HTML）。
- 凭证通过环境变量/`.env` 管理，全程不入库不入 Git；默认保守限速，内置合规使用声明。

## Non-Goals (Out of Scope)

- 不破解付费文章、限时文章、「仅订阅者可见」内容；不恢复已被作者删除的文章；不下载视频号原生视频（封闭体系，无公开直链）。
- 不做大规模、多账号分布式商业爬取，不对外提供 SaaS 或公开分发存档内容。
- 不做公众号运营操作（发文、删文、回复留言、菜单管理）。
- 不开发移动端 App 或自研 GUI（复用 exporter 的 Web 界面 + Python CLI）。
- 不集成本轮选定的 seedream（文生图）、seedance（文生视频）插件——与采集任务无直接关联；若未来需要对存档内容做图文/视频二创，另立规格。
- 不集成 user-research-toolkit（面向用户调研）与 personal-workbench（个人工作台页面）插件——本任务交付物是独立采集工具，经评估两者均不适用。
- 不修改任何第三方开源项目源码；私有部署的开源组件以容器方式引用。

## Background & Context

### 一、第一性原理：微信内容体系的技术边界（2026-09 核实）

1. **公众号唯一标识 `__biz`**：每篇永久链接（`mp.weixin.qq.com/s/<sn>` 或带 `__biz/mid/idx/sn/chksm` 参数的长链）中可解析出公众号 `__biz`，它是全部采集路线的寻址基础。
2. **文章正文页公开可读**：无付费墙时，`/s/<sn>` 页面 HTML 含标题、作者、正文、图片 CDN（mmbiz.qpic.cn）、发布时间戳；**不含**阅读数/点赞/评论，这些由独立动态接口（`getappmsgext`、`appmsg_comment`）凭客户端票据返回。
3. **历史消息接口票据短命**：`mp/profile_ext?action=getmsg` 翻页接口依赖 `key`（数小时过期）、`pass_ticket`、`appmsg_token`，且校验微信客户端环境；票据必须通过微信客户端/公众号后台实时获取，无法一劳永逸。
4. **公众号后台存在「全局搜文」内部接口**：任意公众号（含免费注册的个人订阅号）扫码登录 mp.weixin.qq.com 后台后，可调用 `searchbiz`（全局搜索任意公众号）与 `appmsg` 列表接口（分页拉取目标号全部群发文章的标题/链接/时间/摘要）。这是当前最稳的他人号文章列表来源——本质是借用官方后台接口，而非逆向客户端。
5. **官方开放 API 对自有号同样不完整**（关键反直觉事实）：
   - `cgi-bin/freepublish/batchget` 仅能获取「发表但**不通知**」的内容；正常**群发通知**的历史文章官方明确不支持列表获取（微信开发者社区 2025-07/2025-10 官方答复）。
   - 自 2025 年 7 月起，个人主体账号、未认证企业账号被回收发布能力类接口权限（报错 48001）；接口日限 100 次 × 每次 20 条。
   - 官方社区对「个人号注销前如何下载历史发布资料」的答复是「平台没有提供该能力」。
   - 数据统计接口（datacube）只返回聚合指标，不返回文章列表与正文，且需认证账号。
   - 结论：**自有号的历史群发文与他人号一样，需要借助后台接口路线；开放 API 仅对认证账号起到补充作用。**

### 三、选型结论（待审批门确认）

- **主路线 = R2 私有部署 wechat-article-exporter 作为采集引擎 + 自研 Python 薄管线（本项目主体）**。理由：最难的环节（扫码登录态、后台接口翻页、风控退避、HTML 保真、代理池、订阅）由成熟开源项目承担且提供开放 API；自研层只做目标号配置、断点续采、富媒体落盘、Markdown 清洗、SQLite 元数据、RAG 导出、分析报表与调度，与用户的 Python 技术栈和 RAG 诉求直接衔接。
- **兜底 = R3 wechatDownload 4.4**：用于 mpvoice 音频、评论的交叉验证与 exporter 失效时的人工应急；不嵌入、不分发。
- **R1 官方 API 作为条件性补充源**：若自有号为认证主体，Python 管线预留 adapter，接入 `freepublish/batchget` 补齐「发布不通知」内容；个人号/未认证号路径关闭并文档化。
- **R4 不纳入本期建设**：增量需求由 exporter 订阅机制满足；仅在方案文档中留「未来若需免运维 webhook 可评估 Wechat2RSS 自部署授权版」的演进注记。

## Functional Requirements

- **FR-1 目标号配置管理**：以配置文件/环境变量管理目标公众号清单（名称、`__biz`/fakeid、别名、是否自有号）；预置验证样例「意识食谱」。
- **FR-2 全量历史列表采集**：经 exporter API 分页拉取目标号全部群发文章元数据（标题、链接、作者、发布时间、idx、摘要、原创标记、合集归属），入 SQLite；已删除文章自动识别记录。
- **FR-3 正文存档**：逐篇下载原始 HTML（保真备份）并转换 Markdown；图片全部本地化、目录可离线打开；文件名跨平台安全（去非法字符、长度控制）。
- **FR-4 富媒体采集**：mmbiz 图片下载并改写本地引用；mpvoice 语音下载（重点验证播客内容）；腾讯视频 embed 解析记录 vid/占位；视频号卡片与外链音频（如小宇宙）记录为「外部链接」而非伪造本地文件。
- **FR-5 互动数据条件采集**：配置手机端 credentials 时拉取评论/回复、阅读数、点赞、在看、转发并入独立表；无凭证时标记 `skipped_no_credential`，不影响其他数据。
- **FR-6 增量与幂等**：以文章唯一键（`__biz+mid+idx` 或 sn）去重；维护采集水位；二次运行只下载新增/更新；中断后可续跑；重复运行零重复文件。
- **FR-7 RAG 语料导出**：生成 JSONL，每条含 title/author/publish_time/url/原创标记/纯文本正文；清洗模板噪声（文末推广、二维码图注、重复声明）为可选项并保留原文对照。
- **FR-8 分析报表**：输出 CSV 明细 + 单文件 HTML 报表，至少含发文量时间序列、星期/时段分布、原创占比、合集分布、含音频/视频文章占比。
- **FR-9 凭证与配置安全**：exporter 地址/认证、微信 cookies/token、可选 AppID/Secret 全部经 `.env`/环境变量注入；提供 `.env.example`；日志与报错脱敏。
- **FR-10 可观测与韧性**：结构化日志、每篇文章采集状态（pending/downloaded/failed/skipped）、失败原因记录；单篇失败隔离不阻断批次；遇验证码/风控自动指数退避并保存现场。

## Non-Functional Requirements

- **NFR-1 运行环境**：Windows 11 优先，Python 3.11+；exporter 经 Docker Compose 本地或 NAS 部署（最终部署位置为开放问题）。
- **NFR-2 合规与克制**：默认保守限速（请求间隔、单轮文章数可配置，默认值显著低于经验风控阈值）；面向单账号个人量级；合规声明随项目分发。
- **NFR-3 可维护性**：平台接口差异隔离在 adapter 层（exporter API / 官方 API / 兜底导入）；核心解析逻辑为纯函数并配套本地 HTML fixture 单测，覆盖率遵循仓库 ≥80% 要求。
- **NFR-4 可移植存储**：存档根目录可配置；目录结构 `archive/<公众号别名>/<YYYY>/<YYYY-MM-DD_标题>/`；元数据库与语料、媒体分离；不依赖绝对路径。
- **NFR-5 安全**：`.gitignore` 覆盖 `.env`、`data/`、`archive/`；任何输出（日志、报表、Git）不得出现 token/cookie/key 明文。
- **NFR-6 文档**：含架构说明、部署步骤、凭证获取图文步骤（含失效后重新获取）、合规声明、故障排查（风控/验证/票据过期）。

## Constraints

- **Technical**:
  - 微信接口为非官方借用性质，参数与风控策略随时可能变化；凭证（后台 session、手机端 credentials）具有时效性，系统必须把「重新获取凭证」作为常规运维路径设计。
  - 评论/阅读数据依赖微信客户端环境票据，无法保证任何账号任何时刻可取；只能条件性、尽力而为。
  - exporter 私有部署需要 Docker；使用其开放 API/订阅能力前需核实其当前版本的 API 形态与开源协议（实现阶段以仓库实际 LICENSE 与文档为准，遵守署名等义务）。
  - 构建规范遵循仓库 AGENTS.md：代码落位 `apps/` 区域（实现时先读 `apps/AGENTS.md` 路由确认目录与构建后端要求）；新增脚本前查 `.agents/scripts/lib/` 避免重复实现。
- **Business/合规**:
  - 仅限采集**公开发布**的图文，用于个人学习、存档与个人 RAG；禁止商用、公开再分发、大规模采集、绕过付费/访问控制。
  - 采集行为对目标站保持克制频率，尊重版权方；工具随附「学习交流、自行删除」声明（同类开源工具通行做法）。
- **Dependencies**:
  - 开源：wechat-article-exporter（容器私有部署，不修改源码）；外部 GUI：wechatDownload（人工兜底）。
  - Python 生态（实现时锁定版本）：httpx（HTTP）、beautifulsoup4/lxml（解析）、markdownify 或 html2text（HTML→MD）、pydantic（配置）、pandas + jinja2（报表）、tenacity（重试）、pytest（测试）。
  - 前置账号：一个用于扫码登录后台的个人订阅号（免费注册）；建议使用非主力微信号作为采集号隔离风险。

## Assumptions

- 用户可在实现阶段提供可扫码的微信与一个个人订阅号（已有或新注册）；评论/阅读数据所需的手机端抓包凭证为可选项。
- 「意识食谱」为中小体量个人播客号，全量历史在数百篇量级，单轮保守限速下可在数小时内完成回溯；实际体量以采集结果为准。
- 目标号文章均为公开发布、无付费墙；示例文章可正常访问（2026-09-24 已实测可打开）。
- 存档内容仅在本地/个人 NAS 使用，不进入任何公网可访问服务。
- 用户自有公众号的类型（个人/企业、认证状态）尚未提供；R1 补充源按「条件性能力」设计，不阻塞主路线。

## Acceptance Criteria

### AC-1: 路线对比事实完整可核验
- **Type**: `rule`
- **Given**: 方案对比章节/文档
- **When**: 审查其信源与时效
- **Then**: 覆盖 R1–R4 四条路线 × 全量完整性/富媒体/互动数据/增量/成本/风险六个维度，每条关键事实附来源 URL 与 2026-09 核实日期，信源至少包含微信官方文档、开源仓库、第三方实测三类
- **Pass Condition**: 矩阵与信源清单存在，抽样 3 条事实可回源验证
- **Evidence**: 方案文档（本 spec 的背景章为草案，实现任务固化为正式文档）

### AC-2: 选型经用户在审批门确认
- **Type**: `rule`
- **Given**: spec.md 中的推荐主路线（R2 自研薄管线 + R3 兜底 + R1 条件补充）与备选
- **When**: Approve 阶段
- **Then**: 用户明确批准推荐路线，或在审批意见中改选；未经确认不进入实现
- **Pass Condition**: 审批记录中存在用户对路线的明确选择
- **Evidence**: Approve 阶段审批记录

### AC-3: 私有部署采集引擎可运行
- **Type**: `rule`
- **Given**: Docker Compose 部署的 exporter
- **When**: 使用采集专用订阅号扫码登录并搜索「意识食谱」
- **Then**: 能定位目标公众号并返回文章列表；Python 侧通过其开放 API（或等效接口）完成一次连通性自检
- **Pass Condition**: 自检脚本返回目标号 biz 与首页文章列表（≥1 条）
- **Evidence**: 自检命令输出截图/日志

### AC-4: 全量文章列表完整落库
- **Type**: `rule`
- **Given**: 目标号全量采集任务执行完毕
- **When**: 核对 SQLite 元数据与微信客户端内该号历史消息页
- **Then**: 最早一条记录到达该号可公开加载的最早群发文章；列表条目含 title/url/publish_time/idx/作者/原创标记；无重复键
- **Pass Condition**: 末页（最早）文章与微信端一致；唯一键无重复；缺失/已删条目有状态记录
- **Evidence**: 数据库查询结果 + 微信端最早文章对照

### AC-5: 正文与图片离线保真
- **Type**: `rule`
