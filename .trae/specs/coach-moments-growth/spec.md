# 商业教练朋友圈AI增长系统（apps/coach-moments-growth）Spec

## 问题、用户与目标

### 问题

商业教练（企业创始人/个体创业者/高管的成长陪跑者）拥有专业能力，却在私域成交环节失速：

1. **内容无体系**：朋友圈凭感觉发，缺选题框架与文案模板，专业度、感染力、引流属性三者不可兼得；
2. **转化无路径**：内容曝光与万元私教成交之间没有显式漏斗，互动、导流、咨询、成交各环节职责不清；
3. **效果不可见**：无数据追踪，"发了没效果"无法归因，内容模型无法迭代；
4. **合规有风险**：用户见证无授权、营销用语触碰广告法与平台规范，埋下封号/投诉隐患。

结果是"高频输出、低效成交"——内容努力与万元私教成交目标之间缺少一套**可复用、可迭代、可合规**的系统。

### 用户

- **主要用户**：商业教练本人（1 人团队为主，无专职运营），每日投入朋友圈运营 ≤30 分钟；
- **次要用户**：其助理/外包运营者（据本系统执行日常发布与数据记录）；
- **AI 智能体**：作为内容生产引擎，按本系统的选题框架与提示词资产生成朋友圈文案。

### 目标

1. 建立**精准个人 IP 定位**：细分赛道 + 差异化价值主张 + 专业可信人设，并完成三类目标客群（企业创始人 / 个体创业者 / 高管）的痛点、需求、付费能力画像；
2. 建立**AI 朋友圈内容生成体系**：选题框架 + 文案模板 + 素材库 + 可直接调用的提示词资产，覆盖案例拆解、干货输出、用户见证、价值预告、成交场景五大品类；
3. 建立**从曝光到万元私教成交的转化漏斗**：每日 2-3 条固定黄金时段发布节奏 + 互动引导机制 + 私域导流流程 + 成交话术库 + 客户分层运营策略；
4. 建立**数据追踪与月度迭代机制**：监控曝光量、互动率、引流转化率、私域咨询量、成交率，每月迭代 AI 内容模型与转化路径，服务"连续 3 个月每月 ≥2 单万元私教"的运营目标；
5. 建立**合规保障机制**：平台规范自查清单、禁用词表、用户见证授权流程与授权书模板，确保商业推广合法合规；
6. 在 `apps/` 恰当位置落地为一个**独立应用**，并登记 apps 区域路由。

### 非目标

- 不代运营、不代发布、不接管用户微信账号（所有发布由用户本人执行）；
- 不承诺成交结果（万元私教成交为目标与假设，非保证）；
- 不采集/存储任何客户隐私数据（PII）、微信会话内容或成交金额明细；
- 不做付费投流/广告投放方案（仅自然流量 + 私域）；
- 不新增第三方付费工具依赖；不修改 `docs/`、`projects/`、`vendor/` 任何文件。

## 信源与内容敏感度（预检结论）

- **敏感度判定**：内容主题涉及"私域运营/商业成交策略"，命中 `content-sensitivity-precheck` 的私域信号（商业培训材料/商业秘密）。默认应走私域工作流（产出入 `playground/`）。
- **用户裁定**：用户明确选择**标准 Spec Mode**（`/spec`），并指定**产出物落 `apps/` 恰当位置**。按"用户明确指定优先"执行；本 Spec 记录该偏离决策以便审计。
- **落点**：规划区 `.trae/specs/coach-moments-growth/`；交付物 `apps/coach-moments-growth/`（主仓库直接跟踪的普通目录，非子模块）。
- **合规纪律（写入交付物）**：用户见证类内容须取得本人书面授权；一切效果数字标注为"目标/假设"，不写成承诺；禁用极限词与虚假宣传表述。

## 设计原理（七概念 F 阶段：假设剥离 → 公理 → 方案）

### 假设剥离

| # | 隐含假设 | 裁定 |
|---|---|---|
| A1 | "发得多就能成交" | **否定**：数量≠信任。高净值客户为"专业判断力"付费，非为"活跃度"付费；需内容分层与信任递进。 |
| A2 | "朋友圈是广告位，直接讲产品" | **否定**：硬广触发屏蔽与合规风险。朋友圈是"信任场"，成交场景占比应受控（≤1 条/日且需前置铺垫）。 |
| A3 | "AI 生成的内容可以直接发" | **否定**：AI 文本有事实幻觉与合规风险；须经"AI 生成→人工事实校验→合规自查→发布"闭环。 |
| A4 | "客群是同一类人" | **否定**：企业创始人/个体创业者/高管的痛点、决策链、付费能力差异显著，须分层运营。 |
| A5 | "效果靠感觉判断" | **否定**：无指标则无法迭代；须定义可记录、可计算的最小指标集。 |

### 要素识别

1. **定位层**：细分赛道 + 差异化价值主张 + 人设 + 客群画像；
2. **内容层**：选题框架 + 五大品类文案模板 + 素材库 + AI 提示词；
3. **转化层**：漏斗阶段定义 + 发布节奏 + 互动机制 + 私域导流 + 成交话术 + 客户分层；
4. **度量层**：指标定义 + 追踪表 + 月度迭代 SOP；
5. **合规层**：规范清单 + 禁用词 + 授权流程与授权书。

### 公理

- **P1 信任先行**：高客单成交源于"专业信任"，内容首要目标是建立信任而非直接推销；
- **P2 单一入口**：所有内容最终指向唯一低门槛行动（如"评论/私信关键词领取"），避免多入口分散；
- **P3 分层匹配**：内容与话术必须与客户分层（认知/意向/高意向）匹配，差异化触达；
- **P4 人机边界**：AI 负责生成与批量化，人负责事实校验、合规判定与最终发布；
- **P5 度量驱动**：任何内容策略调整必须绑定可观测指标与其基线，禁止"感觉式"改版。

## 功能性需求

### FR1 定位打造（docs/01-positioning.md）

- 明确个人 IP 定位：**细分赛道**（服务谁）、**差异化价值主张**（一句话，含"结果 + 时限 + 对象"）、**人设关键词**（3-5 个，专业可信导向）；
- 三类目标客群画像：**企业创始人 / 个体创业者 / 高管**，每类含：典型处境、核心痛点（≥3）、显性需求与隐性需求、决策链、付费能力区间（标注为估计区间，非承诺）、触达话术要点；
- 输出"专业可信人设"的证明体系：资质/案例/方法论/内容一致性四要素。

### FR2 AI 内容系统（docs/02-content-system.md + prompts/ + templates/copy-templates.md）

- **选题框架**：≥5 个选题母题（如：认知颠覆、案例实证、方法工具、避坑清单、成长叙事），每个母题下给出发文切入角度 ≥2；
- **五大核心品类**（案例拆解 / 干货输出 / 用户见证 / 价值预告 / 成交场景）：说明各品类的目标、使用频率、与其他品类的配合关系（内容配比建议）；
- **文案模板**：五大品类每类 ≥2 个可套用模板，含变量占位（如 `{{痛点}}`、`{{结果}}`、`{{案例}}`）、结构说明（钩子→冲突→证据→行动）；
- **素材库结构**：定义素材字段（客户案例、数据、金句、方法论、见证素材等）与登记方式；
- **AI 提示词资产**：`prompts/00-system.md`（人设/语气/合规约束/输出格式）+ `prompts/01-five-categories.md`（分品类提示词），要求可复用、含占位变量、显式写入合规约束；
- **生成流程闭环**：AI 生成 → 人工事实校验 → 合规自查 → 发布，写明四步职责。

### FR3 转化路径设计（docs/03-conversion-funnel.md）

- **漏斗阶段定义**：曝光 →（互动）→ 私域/加微 → 私域咨询 → 万元私教成交，逐阶段给出目标动作与转化信号；
- **发布节奏**：每日 2-3 条，明确三个黄金时段（如早 7:30-8:30 / 午 12:00-13:00 / 晚 20:00-22:00，含依据）与两条固定档（干货/日常）结构；
- **互动引导机制**：评论钩子、点赞/聊天策略、私信关键词引导话术；
- **私域导流流程**：从朋友圈到私聊/社群的路径与话术（含合规化的"加微"引导）；
- **成交转化话术**：咨询开场、需求诊断、方案呈现、报价、异议处理、成交临门一问的结构化话术；
- **客户分层运营**：≥3 层（如：认知期 / 意向期 / 高意向期），每层定义触达频率、内容匹配、成交动作与升级信号。

### FR4 效果验证与迭代（docs/04-tracking.md + templates/tracking-sheet.md）

- **指标定义**：曝光量、互动率、引流转化率、私域咨询量、成交率——每项含口径（分子/分母）与记录方式；
- **追踪表模板**：逐条朋友圈的日期/品类/时段/曝光/互动/引流/备注 的记录表；
- **月度迭代 SOP**：数据回收 → 归因（哪类内容/时段/话术有效）→ 调整 AI 内容模型与转化路径 → 记录变更；
- **目标与机制**：设定"连续 3 个月每月 ≥2 单万元私教"的运营目标，配套里程碑与复盘节奏（目标标注为假设，非承诺）。

### FR5 合规保障（docs/05-compliance.md + templates/testimonial-authorization.md）

- **平台规范自查清单**：发布前固定门（内容真实性、无极限词、无诱导分享、无违规导流）；
- **禁用词/敏感表述表**：广告法极限词与平台违规词清单，附替换建议；
- **用户见证授权流程**：获取授权的步骤 + **授权书模板**（字段：见证人、内容用途、范围、期限、撤回方式）；
- **合规留痕**：见证授权与内容发布的留痕要求。

### FR6 apps 应用骨架与路由登记

- 创建 `apps/coach-moments-growth/` 应用目录（README + docs/ + prompts/ + templates/）；
- `README.md` 含：定位与防画饼声明、目录地图、每日用法（≤30 分钟流程）、合规红线、时效声明；
- 在 `apps/AGENTS.md`「应用路由表」与「边界声明」各新增一行；在 `apps/README.md` 新增对应条目；既有行零改动（纯新增）。

- **Then**: 发布前自查清单、禁用词/敏感表述表（含替换建议）、用户见证授权流程、授权书模板（含见证人/用途/范围/期限/撤回）齐备；合规留痕要求明确
- **Pass Condition**: 四要素 + 授权书 5 字段齐全
- **Evidence**: 清点记录

### AC-7: 事实与合规纪律

- **Type**: `rule`
- **Given**: 全部交付文档完稿
- **When**: 检索数字与承诺性表述
- **Then**: 所有效果数字/付费能力均标"估计/假设/目标"，无成交承诺；无客户 PII、无真实成交金额明细入库；无 `file:///`、无本机绝对路径
- **Pass Condition**: 承诺性/无源数字 0 处
- **Evidence**: 关键词检索记录

### AC-8: apps 路由登记

- **Type**: `rule`
- **Given**: 应用目录与索引更新完成
- **When**: 核对 `apps/AGENTS.md` 与 `apps/README.md`
- **Then**: 两处各新增条目且注明应用定位；`git diff` 仅含新增行（既有行零改动）
- **Pass Condition**: 两处新增存在且 diff 无既有行改动
- **Evidence**: `git diff` 输出

### AC-9: 执行者可用性（rubric）

- **Type**: `rubric`
- **Dimension**: 新手教练从零到首条内容的可执行效率
- **Scale**: 1-5
- **Anchors**: 1 = 需通读全部文档仍无明确起点；3 = 能照模板产出但需反复跳转；5 = README 引导下 1 天内按提示词+模板产出首条合规内容
- **Pass Threshold**: >= 4
- **Evidence**: V 阶段新人视角审查记录 + README 结构说明

### AC-10: AI 内容样例质量（rubric）

- **Type**: `rubric`
- **Dimension**: 生成内容的专业度 / 感染力 / 引流属性
- **Scale**: 1-5
- **Anchors**: 1 = 空泛套话、无专业信息、无行动引导；3 = 结构完整但空洞或引流弱；5 = 专业可信、有情绪张力、含明确低门槛行动钩子
- **Pass Threshold**: >= 4
- **Evidence**: 依提示词与模板生成的 5 品类各 1 条样例内容 + 自评理由

### AC-11: V 门审查质量（rubric）

- **Type**: `rubric`
- **Dimension**: 对抗审查实质性与修复闭环
- **Scale**: 1-5
- **Anchors**: 1 = 客套式审查无具体发现；3 = 有发现但 <5 条或未修复；5 = ≥5 条具体发现、≥2 条采纳修正且有修复证据
- **Pass Threshold**: >= 4
- **Evidence**: `review.md` 审查记录 + 修正 diff

### AC-12: 原子提交

- **Type**: `rule`
- **Given**: 审查通过
- **When**: 执行提交并核对
- **Then**: 提交单一职责、Conventional Commits 中文、`docs/`/`projects/`/`vendor/` 零 diff、未 push
- **Pass Condition**: `git log` / `git status` 核对通过
- **Evidence**: 提交哈希与验证输出
