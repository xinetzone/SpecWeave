# E 阶段：模式萃取与去重裁决

> 两个候选模式，逐条给出「新建 L1 / 并入既有 / 不入库」裁决。
> G3 门：新建模式含「触发场景（适用/不适用）/ 核心步骤（通用动作表述）/ 反模式 / 迁移验证（含成本边界信号）」四要素。

## 候选 C1：跨期指标口径对齐先行

- **来源洞察**：I-3
- **裁决**：**新建 L1** → `cross-period-metric-scope-alignment`
- **去重比对**：既有 `community-metric-triple-check`（社区指标三查法：查口径→查时点→查独立性）针对「引用外部社区/厂商指标」；`synthetic-stats-source-of-truth` 针对「合成统计的唯一事实源」；`automated-stats-three-defense-lines` 针对「自动统计数据入库的三道防线」。C1 的处理对象是**本方两次观测之间的口径漂移**，与上述三者的适用面不重叠（那是外部信源与本仓自动统计的各自防线，C1 是跨期对比的前置步骤），故判新建。

### 四要素

| 要素 | 内容 |
|---|---|
| 触发场景（适用） | 对同一对象做第二次及以后的全面复盘、度量对比、增长汇报，且两次观测之间存在结构治理动作（目录迁移、资产归并、分类重构） |
| 触发场景（不适用） | 单次快照统计；两次观测间无结构变更；只关心绝对存量而不做差值陈述 |
| 核心步骤 | ① 列出两次统计各自的计数边界（目录范围、排除规则、采集时点）→ ② 逐指标标注「口径一致 / 口径变更 / 不可比」→ ③ 对「口径变更」指标只报存量与边界，不报方向性增减 → ④ 「不可比」指标改为以同一脚本重跑基线后再纳入对比 |
| 反模式 | 直接相减上期报告的数字；把结构治理造成的计数变化写成「增长/萎缩」；沿用上期排除规则而不核对本期目录结构 |
| 迁移验证 | 案例：本仓知识库计数 836→500（口径 `docs/knowledge` 替代 `.agents/docs/knowledge`）、Skill 门面 18→172（期间发生技能目录统一）。成本边界信号：单次对齐 4 个指标约需 30 分钟以内的命令复核；若需重跑基线脚本，成本升一个量级 |

## 候选 C2：身份别名归并计量

- **来源洞察**：I-4、F-012、F-013
- **裁决**：**并入既有** → `community-metric-triple-check`（追加「身份别名归并」条，差异 3 条，设硬上限 ≤3）
- **去重比对**：该候选与「口径-时点-独立性」三查法同属「指标可信度」治理族；归并身份属于其中「口径」维度的子问题，故不另立新模式，按既有模式追加条目并入。

### 追加内容（≤3 条）

1. 计量贡献者集中度前，先执行身份别名排查（同人不同 `user.name`/`user.email`），未排查则不得据「单身份占比」下结论。
2. 报告须并列「身份数」与「归并后人数」两个口径，并标注归并证据（邮箱/署名一致性）。
3. 无归并证据时，把集中度表述降级为「前 N 位身份合计占比」，避免使用「单人」（自然人）措辞。
