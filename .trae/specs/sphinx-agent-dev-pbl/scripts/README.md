# scripts/ — 审计脚本

本目录存放方案自身的**质量保障脚本**，用于在每次修改后复核"多文档一致性"。

## audit_consistency.py — 一致性审计

```bash
python scripts/audit_consistency.py --root .
```

**退出码**：`0` = 通过；`1` = 有失败项（可直接接入 CI）。

### 它查什么（4 项，按可靠性从低到高）

| # | 检查项 | 性质 | 说明 |
|---|---|---|---|
| 1 | 相对链接可达性 | 完备性（最弱） | 检查所有 `[text](path)` 是否指向存在的文件。**注意：链接可达 ≠ 内容正确** |
| 2 | 幽灵文件 | 完备性 | 被反引号引用的文件名是否真实存在（排除"学生待创建文件"白名单） |
| 3 | **派生数字** | **一致性（高发区）** | 文档声称的行数 / 截图张数 vs 实测值 |
| 4 | **可复制命令** | **一致性（高发区）** | 同一条命令多处出现是否写法一致；错误写法（会跑不起来的）单独报错 |

### 为什么重点在后两项

来自 R8 完整性审计（session `sc-20260929-pbl-audit`）的结论：

> **多文档套装的缺陷高发区不是"文件缺失"，而是"文档对自身的描述"失效。**
>
> 文件是**一次性创建**的，所以"完备性"几乎总是达标；
> 而文档是**增量修改**的，每次只改一处，另一处的旧说法就成了定时炸弹。

**三个高频漂移点**：派生数字、目录树、可复制的命令。

### 已知的"正确噪声"

以下几类会被扫描到但**不应被视为缺陷**，脚本已内置排除：

| 类别 | 例子 | 处理方式 |
|---|---|---|
| 学生待创建的文件 | `api-draft.md`、`docs.yml` | `PLANNED_ARTIFACTS` 白名单 |
| 演示环境脚本 | `shells.py`、`make_shots.py` | `EXTERNAL_SCRIPTS` 白名单 |
| 无路径的裸文件名 | 文中泛指"`conf.py` 这类配置文件" | `BARE_NAMES` 白名单 |
| 审计报告自身的引用 | `insight.md` / `review.md` 为批判而引用错误命令 | `AUDIT_FILES` 排除 |
| 警示语境 | "**不要写成** `sphinx-build -b html . _build/html`" | `WARNING_MARKERS` 识别 |
| 等价写法未统一 | `python -m sphinx ...` vs `sphinx-build ...`（都正确） | 报告为 `⚠` 提示，**不判失败** |

### 维护提示

- 新增"学生待创建文件"时，把它加进脚本顶部的 `PLANNED_ARTIFACTS`
- 脚本自身也需随方案演进而更新——**它是方案的一部分，不是一次性工具**
- ⚠️ **白名单会腐烂**：`PLANNED_ARTIFACTS` 是"暂时不存在"的豁免清单。
  一旦某文件**真的被创建**，必须**立刻从白名单移出**，否则它就变成了
  "永不兑现的免死金牌"。**R9 已对 `calculator-draft.md` 执行过这次移出。**

### R9 增补：存在性检查（第三道线）

R8 建了两道线：**相对链接可达性** + **幽灵文件（反引号引用）**。
R9 暴露出**第三类盲区**：**"一致的虚空引用"**。

> 三份文档可以**完全一致地**说"发草稿样例给学生"，
> 交叉比对**全绿通过**——而实物文件根本不存在。

因此本脚本现在的语义是：

| 线 | 查什么 | 本轮实例 |
|---|---|---|
| 一致性 | 同一事实在两处说法是否一致 | R8 的 6 处漂移 |
| **存在性** | 被引用的路径/文件**在磁盘上真的存在吗** | R9 的 5 处虚空引用 |

**判别口诀**：完备性（文件齐不齐）会被"**一致的承诺**"绕过——
所以审计不能止于"两处说法是否一致"，必须追到**实物**。
