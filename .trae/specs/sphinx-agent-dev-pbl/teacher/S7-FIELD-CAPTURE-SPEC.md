# S7-1 / S7-2 / S7-3 现场采集规格（Field Capture Spec）

> **本文件替代"补 3 张能力留白图"这一行动项。**
>
> 这三张图**不该被合成**——它们承担的是"证据义务"（证明某次教学真实发生过），
> 而合成图无法履行证据义务，只会污染证据链。详见
> [`../handbook/shots/README.md`](../handbook/shots/README.md) §五「按设计留白」与
> [`../insight.md`](../insight.md) I-10。
>
> 因此本文件的交付物不是图片，而是**一份让开课教师拿到手就知道拍什么、
> 什么算合格、什么时候能拍的行动规格**。

---

## 一、为什么是"规格"而不是"图"

| 直觉做法 | 后果 | 本方案的做法 |
|---|---|---|
| 合成 3 张图补满 37/37 | 往教学材料植入"这门课已开过、已有学生作品"的**虚假证据**；教师可能因此不再收集真实作品 | **留白 + 本规格** |
| 只写"需教师自填" | 教师不知道做到什么样算对 | 每项给出**可判定的合格标准** |
| 等教师自己想到 | 规格丢失，三人做三个样 | 本文件把规格**固化下来** |

> 🎯 **可迁移的判据**（来自 I-10 公理 2）：
> **一个画面若承担"证据义务"，它就不能被合成。**
> 只有"操作演示"性质的画面（终端输出、代码、界面）才可以合成。
> 三门任务中 31 张图属操作演示 → 已合成；这 3 张属证据 → 只能实拍。

## 三、逐项采集规格

### S7-1 · 路演现场演示画面

| 项 | 内容 |
|---|---|
| **画面内容** | 学生小组正在演示可运行智能体的现场画面 |
| **拍摄时机** | Task7 路演环节，任意一组演示过程中 |
| **拍摄要点** | ① 屏幕可辨（能看出是文档站或终端）② 人物可辨（不必正脸，背影亦可）③ 横向构图 |
| **隐私处理** | 若拍到其他学生正脸，须征得同意或虚化；拍到屏幕上的 API Key 须打码 |
| **分辨率** | 1920×1080 或更高（当前示意稿为 1440×900，保持一致即可） |
| **格式** | PNG |
| **存放** | `handbook/shots/S7-1-路演现场.png`（同名覆盖后续引用无需改动） |

**合格判据（拍完怎么判断合格）**：
- ✅ 能让人**不读文字就看出**"有人在演示一个网页/程序"
- ❌ 只有空桌子、看不清屏幕、或看起来像摆拍 → 不合格

**引用位置**：[`../handbook/task-7-showcase.md`](../handbook/task-7-showcase.md) 第 16 行留白块 → 替换为该图

---

### S7-2 · 答辩场景 / 教师记录表

| 项 | 内容 |
|---|---|
| **画面内容** | 答辩现场，或**当场填写完毕**的答辩记录表 |
| **拍摄时机** | Task7 答辩环节进行中 |
| **使用工具** | [`SCORING-SHEET.md`](SCORING-SHEET.md) **第六节「Task7 现场答辩记录表」**（已含 3 个评分维度与 0/1/2 分档） |
| **拍摄要点** | 若留存现场照，**不得拍到其他学生的答卷内容**（隐私红线） |
| **⚠️ 特别注意** | **记录表必须当场填写**——预置"填好的表"会诱导学生以为有标准答案可背 |

**合格判据**：
- ✅ 每组**至少抽 1 个函数**做"输入输出 / 实现逻辑 / 设计取舍"三问
- ✅ 该函数由教师**随机指定**（不让学生自选——自选会挑最容易讲的）
- ✅ 学生答不出"设计取舍"时，扣**"展示路演"分**而非"可运行智能体"分（代码能跑是两回事）

**引用位置**：[`../handbook/task-7-showcase.md`](../handbook/task-7-showcase.md) 第 98 行留白块

### S7-3 · 反思报告文档

| 项 | 内容 |
|---|---|
| **画面内容** | **学生本人**产出的反思报告文档 |
| **拍摄时机** | Task7 提交后，征得该学生同意 |
| **格式** | 学生交的是 Markdown 或文档文件；若需转成 PNG 用于手册，须**保留原始排版**，不得美化改写 |
| **⚠️ 特别注意** | **不得由教师代笔或润色**。预置一张"范文"会让所有人都写成同一个样子——而反思的价值恰恰在于它是**你自己的** |

**合格判据**（对照 [`SCORING-SHEET.md`](SCORING-SHEET.md) **§3.5「反思报告」**，5 档，通过阈值 ≥4；评估点定义见 [`../review.md`](../review.md) **CP-U3**）：

| 分档 | 特征 |
|---|---|
| **5 分** | 写出"我原以为 X，实现后发现 Y"——暴露了**自己的理解盲点** |
| **4 分** | 描述了具体过程，且有 **Git 提交历史**能对上 |
| **3 分** | 描述了过程但缺深度 / **或**内容完整但整个项目只有一次大提交 |
| **2 分** | 大量套话（"我学到了很多""团队合作很重要"） |
| **1 分** | 套话且无过程证据 |

> 📌 **权威源是 `SCORING-SHEET.md` §3.5**（教师打分用）；`review.md` CP-U3 是评估点定义，
> 两者锚点一致（`1=套话; 3=描述过程; 5=真实盲点洞察`）。上表 5 档与 §3.5 逐档对齐。
> ⚠️ **单次大提交**（无论内容多完整）→ 该项最高 3 分（防 AI 代写的关键判据）。

> 💡 **优先选 5 分或 4 分的作品入册**——它们才示范了"反思报告可以写成什么样"。
> 若全班最高只有 3 分，**如实放 3 分作品**并加注说明，不要抬高。

**引用位置**：[`../handbook/task-7-showcase.md`](../handbook/task-7-showcase.md) 第 153 行留白块

## 四、统一验收清单

采集完成后，逐项打勾：

- [ ] **S7-1** 现场照已拍，能不加说明看出"有人在演示"，人物隐私已处理
- [ ] **S7-2** 记录表为**当场填写**，现场照未拍到其他学生答卷
- [ ] **S7-3** 反思报告为**学生本人**产出，未经教师润色，且标注了对应分档
- [ ] 三张图均为 **PNG**、分辨率 ≥1440×900
- [ ] 三张图**均非合成**——画面取自真实发生的教学现场
- [ ] 已按 `handbook/task-7-showcase.md` 中的留白块位置替换图片引用
- [ ] 已删除 [`../handbook/shots/README.md`](../handbook/shots/README.md) §五表格中对应的 3 行留白记录
- [ ] 已同步更新 `shots/README.md` 的完成度口径（从"31/31 + 6 留白"改为实际值）

> ⚠️ **最后两项容易漏**：图片替换了但清单没更新，会让下一个使用者看着
> "还有 6 个留白"却找不到它们——**账实不符比缺失更糟**。

---

## 五、若始终无法采集

留白**永远是合法状态**。手册在无图情况下仍然可用（详见
[`../handbook/shots/README.md`](../handbook/shots/README.md) §七）。

**不要**因为"缺 3 张图"就觉得方案不完整。按 I-10 的口径：

> **完成度 = 31/31 可预填位点已填 + 6 位点按设计留白**
>
> 把 37 个位点全部填满，不是更完整，而是更差。

若某校决定放弃采集，正确动作是：**保留留白块不动**，并在本节下方记录决定（谁、何时、为何）。
