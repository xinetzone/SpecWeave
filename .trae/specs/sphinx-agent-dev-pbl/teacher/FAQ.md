# 课堂高频问题与应对（FAQ）

> **配套**：[`TEACHER-GUIDE.md`](TEACHER-GUIDE.md) 第五节
> **用法**：课前通读一遍；课上被问到时直接查。
>
> 分三类：**学生质疑**（B 类）｜**技术故障**（T 类）｜**教学组织**（P 类）。

---

## 一、学生质疑类（B）

### B-1 「AI 时代为什么还要手写文档？」

**这是最需要答好的一问**，因为它直接质疑 Task2 的核心纪律。

**答法**（三层，按学生水平取用）：

1. **类比层**（对所有人）：
   > "计算器普及了，但小学还是要求你会笔算。不是因为计算器不好，而是因为**笔算过程本身在训练你的数感**。写文档也一样——AI 能帮你写，但'想清楚要写什么'这个过程，替代不了。"

2. **机制层**（对追问的学生）：
   > "能力建构期用工具提效，会抑制能力形成。你现在让 AI 写文档，得到的是'一份文档'；你自己写，得到的是'写文档的能力'。前者能用一次，后者能用一辈子。"

3. **证据层**（对质疑强烈的学生）：
   > "这门课 Task6 会真的让你用 AI 写文档。但你得先有能力判断它写得对不对——不然你连'它写错了'都不知道。"

**不要说**："因为老师要求" / "考试要考"——这会把纪律降格为规则。

> 📎 完整依据：[`../insight.md`](../insight.md) I-3（含边界条件：写作基础扎实的高年级可放宽）

---

### B-2 「我用 AI 写代码，为什么还要理解原理？」

**答**：
> "Task7 我会随机指一个函数，让你口头解释它。你能解释，就说明你懂；解释不了，代码是谁写的就不重要了——因为项目结束后你什么都带不走。"

> 💡 **顺势提醒**：这不是威胁，是保护。真正的问题是"如果 AI 能做完一切，你的价值在哪"。
> 答案就是：**能判断 AI 做得对不对**。而这需要理解原理。

---

### B-3 「为什么非要部署到网上，本地能打开不就行了吗？」

**答**：
> "本地能打开，只有你能看到。部署之后，你能把它发给家人、放到求职材料里。**这是你的作品，不是一次作业。**"

> 💡 这一条对学生动力影响很大（DQ-2 的核心判据就是"资产归属"）。
> 可顺势说："这个网址课程结束后还是你的。"

---

### B-4 「我的文档站很丑，要不要换个主题？」

**答**：
> "Task0 的丑是故意的（用了内置主题，少一个依赖就少一个失败点）。Task1 开始你可以自己换 furo，那是你的选择。"

> ⚠️ 若学生在 Task0 就纠结主题 → 这是跑题信号，直接打断。

---

### B-5 「能不能不做 Task6？我觉得没用。」

**答**：
> "Task6 的核心部分（审校 + 差异分析）是必做的，而且**不花 Token**。只有'自己调 API 生成草稿'那一步是选做加分。"

> 💡 大多数学生的抵触来自"要花钱/要配额"的误解。解释零成本后抵触通常消失。

---

### B-6 「小组里只有我在干活。」

**现场处理**：
1. 不当众评判，先了解情况
2. 请该学生展示自己的 Git 提交记录（`git log --oneline`）
3. 用提交历史作为客观依据与全组沟通

**答**：
> "我们看的是过程证据。谁提交了什么、什么时候提交的，Git 都记着。这部分会体现在'参与度'和'协作'的分数里。"

> 📎 评分依据：[`SCORING-SHEET.md`](SCORING-SHEET.md) 第二节

## 二、技术故障类（T）

### T-1 学生卡在 `python: command not found`

**原因**：Python 没装，或装了没勾 Add to PATH。

**处理**：

```bash
# 依次试这几个命令，看哪个能用
python --version
python3 --version
py --version
```

- 有一个能用 → 让学生后续都用那个命令
- 全不能用 → 用预置环境（`warmup-docs` 的自愈脚本），或重装 Python 并勾选 Add to PATH

> 🚨 **预防优于现场救火**：开课前按 [`SETUP-CHECKLIST.md`](SETUP-CHECKLIST.md) 第 1.1 节查过，就不会在课上遇到。

---

### T-2 `(.venv)` 不出现（虚拟环境激活失败）

**诊断**：

```bash
# Windows
.venv\Scripts\activate

# 然后看提示符前是否有 (.venv)
# 再自查这是谁
where python
```

**判据**：`where python` 第一行**必须**是 `.venv\Scripts\python.exe`。

- 若是系统 Python 路径 → 激活没成功，重试
- `activate` 报"无法加载文件，因为在此系统上禁止运行脚本" → PowerShell 执行策略问题：

```powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

> 💡 这个报错在 Windows 上很常见。**提前知道答案就不会卡 10 分钟。**

---

### T-3 `did not find executable`（退出码 103）

**原因**：**跨机器复制了 `.venv/`**（最常见），或 `.venv` 被移动过。

**处理**：删掉 `.venv`，在**当前机器**上重建。

```bash
rm -rf .venv          # Windows: rmdir /s .venv
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

> 🚨 这是**验证过的 P0 坑**：`pyvenv.cfg` 硬编码创建时的绝对路径，跨机器必然失败。
> 详见 [`../warmup-docs/TEACHER-SETUP.md`](../warmup-docs/TEACHER-SETUP.md) 第六节。
> **预防**：分发时不要带 `.venv/`。

---

### T-4 `import agent` 报 `OpenAIError: api_key must be set`

**这可能有两种情况**：

| 情况 | 判据 | 处理 |
|---|---|---|
| **学生自己写的代码**有模块级 `client = OpenAI(...)` | 看代码顶部 | 这是**知识盲点**，引导改延迟初始化 |
| **模板被改坏了** | 用的是 `templates/agent.py` | 重新复制模板 |

**教学价值**（第一种情况）：**不要直接给答案**，而是引导：

> "你把这个 `client = OpenAI(...)` 放在文件顶部，那 Python 什么时候执行它？"
> "能不能让它'用到的时候才创建'？"

> 📎 这正是 [`../insight.md`](../insight.md) T-1 记录的 P0 问题——
> **"设计意图被实现方式反向破坏"**。学生自己踩到，收获最大。

---

### T-5 `make html` 报一堆 warning，`-W` 下直接失败

**处理顺序**：

1. **先读最后一行**——Sphinx 的报错关键信息几乎都在最后
2. 最常见的是 `toctree contains reference to nonexisting document`
   → 检查 `index.md` 里 toctree 列的文件是否真的存在
3. `document isn't included in any toctree`（warning）
   → 把新页面加进 toctree

> 💡 **`-W` 失败是设计意图，不是麻烦**：它保证文档与代码不漂移。
> 可以告诉学生："这些警告在普通构建里会溜过去，但 CI 把它当错误拦住了——这就是工程规范。"

---

### T-6 模型不调用工具，直接瞎编时间

**原因**：`build_tools()` 里的 `description` 写得不够明确。

**处理**：

```python
# ❌ 不好
{"name": "get_time", "description": "获取时间"}

# ✅ 好
{"name": "get_time",
 "description": "获取当前的系统日期和时间。"
                "当用户询问'现在几点''今天几号'等需要实时时间的问题时，"
                "必须调用此工具，不要凭记忆回答。"}
```

> 🎯 **这是本任务最好的教学时刻**：
> 让学生亲身体会到"**我写的文档直接决定了模型的行为**"——
> 这就是"文档工程"和"AI 应用"的交汇点。

---

### T-7 `calculator` 对恶意输入会执行吗？

**答**：用 `ast` 就不会。可用真实数据演示：

```
输入：__import__('os').system('echo HACKED')
eval 版    → 真的会执行系统命令 ⚠️
ast 版     → 计算失败: 只支持简单的四则运算 ✅
```

> 🎯 **课堂冲击力很强的一个演示**。建议当场投屏。
> 注意：演示前**务必确认用的是 ast 版本**，别真的执行了。

---

### T-8 构建成功但页面是旧的

**原因**：浏览器缓存。

**处理**：`Ctrl+F5` 强制刷新。

---

### T-9 中文显示成方框

**原因**：字体缺失（极少见）。

**处理**：换机器测试；或确认 `conf.py` 中 `language = 'zh_CN'`。

---

### T-10 GitHub Actions 跑失败，但本地构建是好的

**排查顺序**：

| 现象 | 原因 | 处理 |
|---|---|---|
| `actions/upload-pages-artifact` 报错 | Pages Source 没设成 GitHub Actions | Settings → Pages → Source 选 **GitHub Actions** |
| 权限报错 | `permissions` 缺 `pages: write` | 补上 `pages: write` + `id-token: write` |
| 找不到依赖 | 忘了 `pip install -r requirements.txt` | 检查 `docs.yml` 步骤顺序 |
| 本地无警告，CI 有 | Python/包版本不同 | 在 `docs.yml` 里固定 Python 版本 |

> 📎 `docs.yml` 范本：[`../handbook/task-3-ci.md`](../handbook/task-3-ci.md)

---

### T-11 机房访问不了 GitHub

**处理**：走 DQ-2 档②（内网 Git）或档③（RTD）。

- 内网 Git：替换 `upload-pages-artifact` / `deploy-pages` 两个 action，其余步骤完全一致
- **连内网 Git 都没有**：本地构建 + 拷贝到共享盘，此时 TR-3.1 相应下调

> 📎 详见 [`SETUP-CHECKLIST.md`](SETUP-CHECKLIST.md) 第四节。

---

### T-12 学生说不清怎么用 Git

**处理**：只教四个命令，别讲原理。

```bash
git add .                          # 把改动放进"待提交"
git commit -m "说明你做了什么"      # 提交
git push                           # 推到远程
git status                         # 看现在什么状态
```

> 💡 提交信息给句式模板：
> `docs: 补充使用指南`
> `feat(agent): 实现最小循环`
> `fix(tools): calculator 改用 ast 安全求值`
>
> 不要求严格遵循规范，但要**说明"做了什么"**，不能写 "update"。

## 三、教学组织类（P）

### P-1 学生在 Task1 集体卡住，我该怎么办？

**不要逐个救**——你会在前 20 分钟被一个人占满。

**做法**：
1. 投屏 [`../handbook/task-1-env.md`](../handbook/task-1-env.md) 的「常见报错」小节
2. 让学生自己对照排查
3. 宣布："自己排查 10 分钟仍不行，再来找我，**带着完整报错**"
4. 你只处理"报错表里没有的"问题

> 💡 **"带着完整报错来"**这句话能过滤掉一大半求助——很多学生自己读一遍报错就解决了。

---

### P-2 学生问「这个 conf.py 是干嘛的？」（在 Task0）

**答**：
> "下课再说，现在别管它。你今天的任务只有一个：改 `index.md`，看它变成网页。"

> 🚨 **任何配置讨论都是跑题**。Task0 的唯一 KPI 是正反馈。
> 如果你开始解释 conf.py，说明你正在破坏这个任务的设计。

---

### P-3 我发现学生用 AI 写了 Task2 的文档

**不要当众指责。**

**识别信号**：
- 文字风格与课堂口语表达不一致
- 出现学生不可能知道的术语
- Git 提交时间集中在同一分钟

**处理**：
1. 私下沟通，要求重做
2. 说明理由（用 B-1 的答法，但语气是"为你考虑"而非"你违规了"）
3. 若已提交 Git → 让他补一次真实的手写版本

> 💡 **重点是能力养成，不是抓作弊。** 学生可能只是不知道这条纪律的意义，
> 也可能只是想省时间。两种情况的处理都一样：让他重做一遍。

---

### P-4 小组进度差距很大，怎么收尾？

**做法**：
- 允许落后组用 `templates/agent.py` **全量模板**（不影响评分）
- 优先保证 Task7 能展示——**展示比完成重要**
- 把差距转化为教学资源：让快的组给慢的组讲一个函数

> 🔑 **降范围，不降标准**：少做一个工具可以，讲不清已做的那个不行。

---

### P-5 Task7 路演时间不够怎么办？

**方案**：
- 严格限时 5 分钟/组，超时打断
- 答辩环节改为抽查（每组抽 1 个函数）而非全覆盖
- 大班（>15 人）直接改为：抽查答辩 + 同伴互评交叉验证

> 📎 详见 [`../insight.md`](../insight.md) I-4 边界条件（大班需改为抽查）。

---

### P-6 有学生想用 LangGraph / CrewAI 等框架

**答**：
> "想探索非常好，但请**先把最小循环做完**。做完之后你可以用框架重写一版，对比一下——你会发现框架帮你省掉的那部分，正是我们这个项目要你理解的部分。"

> 📎 spec.md Non-Goals 明确限制框架深度（仅作概念扫盲），避免认知过载。

---

### P-7 学生说「我全都会了，能不能跳过 Task2」

**答**：
> "如果你全都会了，Task2 对你就是最快的任务——因为你已经在脑子里写完 `api-draft.md` 了。但你还是得**写下来**，因为 Task6 要用它做差异分析。"

> 💡 不要开特例。Task2 是纪律，开了特例纪律就失效了。

---

### P-8 想给课程加个"拓展任务"

**方向**（不破坏主干的加法）：
- 让智能体多做 1 个工具（如查天气、查汇率）→ 强化 Task5 的 docstring 质量体感
- 让文档站加一个 Mermaid 流程图 → 强化 Task2 的 MyST 使用
- 写一篇"给学弟学妹的建议" → 强化 Task7 的反思深度

> ⚠️ **不要加**：讲框架源码、讲多智能体编排、讲生产部署。
> 这些会挤占核心任务的时间，且偏离 G1–G3 目标。

## 五、需要向上反馈的问题

如果遇到以下情况，**不是你的教学问题**，而是方案需要调整——请记录并反馈：

| 现象 | 可能说明 |
|---|---|
| 学生 > 30% 卡在 `base_url`/模型名配置而非 Agent Loop | DQ-1 的可证伪信号被触发，需把"配置与代码分离"前置到 Task1 |
| 机房 GitHub 能访问但登录态无法保持 | DQ-2 的可证伪信号被触发，应翻转默认档位 |
| 档 A 的预置草稿在两届学生中产出的差异分析高度重复（相似度 >70%） | DQ-3 的可证伪信号，说明预置草稿未触发个体化认知 |
| 档 B 完成率 > 90% 且网络稳定 | 说明 Token 约束被高估，可把档 B 提升为默认必做 |

> 📎 各决策的完整可证伪信号与回滚条件：见 [`../decisions.md`](../decisions.md) 各节末尾。
