## 一、这门课的性质（决定你怎么教）

### 它不是编程课

学生最终要交付的是**一个作品 + 一份能讲清作品的文档 + 一次能解释代码的答辩**。代码只是载体。

**判断你是否教偏了的标准**：如果你在课上花大量时间讲 Python 语法、讲 `openai` SDK 的参数细节，方向就偏了。学生应该由 `handbook/` 自己看懂这些。

### 它有三条不能破的纪律

这三条来自 V 对抗审查（详见 [`../insight.md`](../insight.md)），**破了就会让教学效果归零**：

| 纪律 | 破了会怎样 | 落地位置 |
|---|---|---|
| **文档先行** | 文档沦为事后粉饰，学生学不到"用文档检验理解" | Task2 必须在 Task4/Task5 之前 |
| **先手写、后 AI** | 能力建构期用 AI 提效会抑制表达能力发育 | Task2 禁止 AI；Task6 才引入 |
| **多次小提交** | 单次大提交 → 无法验证过程真实性 → AI 代写无法识别 | 全程；TR-7.2 要求 ≥5 次 |

> 🚨 **纪律 2 是最容易被违反的一条**——学生（和部分教师）会本能地想"AI 时代何必手写"。
> 唯一的例外：已有扎实写作基础的高年级/大学生可放宽。详见 [`../insight.md`](../insight.md) I-3 边界条件。

### 它的 KPI 是"正反馈"，不是"知识量"

Task0 的存在意义就是**在学生会卡住之前，先让他们成功一次**。
如果你在 Task0 讲了配置、讲了原理，就已经违背了它的设计目的。

## 二、课时编排（8 个任务怎么排进课表）

### 总时长：约 10–14 课时 + 30 分钟

| 任务 | 时长 | 难度 | 建议排课 | 关键交付物 |
|---|---|---|---|---|
| **Task0** 热身 | 30 min | ★☆☆☆☆ | 单独一节课的前半段 | 一个能打开的网页 |
| **Task1** 环境 | 1–2 课时 | ★★★☆☆ | **第一节课 + 课后** | 能构建的空文档站 |
| **Task2** 文档先行 | 2 课时 | ★★★☆☆ | 2 节课（手写，节奏要慢） | 文档站有内容 + `api-draft.md` |
| **Task3** CI 部署 | 1–2 课时 | ★★★☆☆ | 2 节课（首次配置最耗时） | 一个可分享的网址 |
| **Task4** 智能体循环 | 2–3 课时 | ★★★★☆ | 3 节课（**核心难点**） | 能对话的程序 |
| **Task5** 工具 + autodoc | 2 课时 | ★★★★☆ | 2 节课 | 会调工具的智能体 + API 文档页 |
| **Task6** 元文档闭环 | 1–2 课时 | ★★★★☆ | 2 节课（含讨论环节） | 差异分析 `diff-notes.md` |
| **Task7** 展示反思 | 1 课时 | ★★★☆☆ | 1 节课（路演可能超时） | 验收材料 |

### 三种排课方案（按你的课时条件选）

#### 方案 A：标准版（12 课时，4 周 × 每周 3 课时）

```
第 1 周：Task0(0.5) + Task1(1.5) + Task2(1)
第 2 周：Task2(1) + Task3(2)
第 3 周：Task4(3)
第 4 周：Task5(2) + Task6(2) + Task7(1)
```

> ⚠️ **第 3 周是学生流失风险最高的时间点**——Task4（Agent Loop）是全项目最难的一步。
> 建议：① 用 `templates/agent.py` 的 `ask_simple()` 给保底路径；② 课中做一次集体走查。

#### 方案 B：紧凑版（8 课时，适合课时紧张或社团活动）

```
课 1：Task0 + Task1（环境部分让教师预置好，学生只验证）
课 2：Task2（压缩为写 api-draft.md + index.md）
课 3：Task3（用 RTD 托管替代，跳过 CI YAML 编写）
课 4-5：Task4 + Task5（合并，用 templates 模板）
课 6：Task6 档 A（教师预置草稿，课上做差异分析）
课 7：Task7 路演 + 反思
课 8：缓冲（补交/重做）
```

> 📌 方案 B 用了 **DQ-2 的③托管替代** 与 **DQ-3 的档 A**——两者都是官方设计内的合法降级，不是偷工减料。

#### 方案 C：项目周/营地集训（连续 4–5 天）

```
Day 1 上午：Task0 + Task1
Day 1 下午：Task2
Day 2 上午：Task3
Day 2 下午 – Day 3：Task4 + Task5
Day 4：Task6 + 文档收尾
Day 5：Task7 路演 + 答辩 + 反思
```

> ⚠️ 集训模式最容易牺牲的是 **Task2 的"手写"纪律**（赶进度就会想上 AI）。
> 建议 Day 1 下午**断开 AI 工具访问**，物理保障这条纪律。

### 分层教学：同一节课怎么照顾不同水平

| 学生水平 | 识别信号 | 差异化处理 |
|---|---|---|
| **跟得上** | Task1/Task2 独立完成，很少问环境问题 | 引导走 **Task6 档 B**（全自动），鼓励在 Task5 多做 1 个工具 |
| **勉强跟** | Task1 卡住但能自己排查出来 | 给 `templates/agent.py`，**用脚手架但要求讲清原理**（不影响评分） |
| **明显吃力** | Task1 卡死 1 小时以上、无法读报错 | ① 跳过 Task3（用本地构建替代部署）；② Task5 只做 `get_time()` 一个工具；③ Task6 走档 C |

> 🔑 **关键原则：降级不减要求，只减范围。**
> 允许少做一个工具，但不允许讲不清已做的那个。Task7 的现场答辩是最后一道防线。

## 三、每个任务怎么教（教学要点与坑）

### Task0 · 热身（30 分钟）

**唯一目标**：让学生说出"原来写文档就是写文字，不是搞环境"。

| 要做 | 不要做 |
|---|---|
| 发下去 `warmup-docs/` 脚手架，让学生改 `index.md` | ❌ 讲 `conf.py` 是什么 |
| 演示**一条**构建命令 | ❌ 讲 venv / pip |
| 让学生截图自己的成果页 | ❌ 提 Git |

> 🚨 **最容易犯的错**：学生问"这个 conf.py 是干嘛的？"——地回答"下课再说，现在别管"。
> 任何配置讨论都是跑题。此任务唯一 KPI 是**正反馈**。

**收尾必做**：让每人展示一下自己的页面。这个"被看到"的动作是正反馈的关键一环。

---

### Task1 · 环境搭建（1–2 课时）

**这是全项目最容易卡住的一步**，请预留缓冲时间。

| 教学要点 | 说明 |
|---|---|
| **先讲"为什么用 venv"** | 一句话：让每个项目的依赖互不干扰。别展开。 |
| **强调 `(.venv)` 提示符** | 学生最常犯的错是"以为激活了其实没有"。让学生跑 `where python` 自查。 |
| **用非交互式初始化命令** | `sphinx-quickstart` 的交互提问会让新人卡死。手册已给一键命令，直接发。 |
| **`.gitignore` 必须此刻建** | 晚建一次就可能已经把 `.env` 提交了（AC-5 直接失败） |

> 💡 **课堂技巧**：把手册 Task1 的「常见报错」小节投屏，让学生自己对照。**不要逐个帮学生排错**——那样你会在前 20 分钟被一个人占满。

---

### Task2 · 文档先行（2 课时）⚠️ 纪律最严

| 教学要点 | 说明 |
|---|---|
| **开场必须讲清"为什么先写文档"** | 用一句话：*"先写文档，是为了让你发现哪些地方你其实没想清楚。"* 这是本任务的全部意义。 |
| **物理断网/断 AI** | 集训模式建议直接断 AI 工具访问。常规模式至少口头强调 + 巡视。 |
| **`api-draft.md` 要写得"不确定"** | 鼓励学生把"我还不确定的地方"写成 checkbox 列表——这些是 Task6 和 Task7 的素材。 |
| **术语表不是凑数** | `glossary.md` ≥7 条（TR-2.2）。跨学科背景学生靠它读懂全文。 |

> 🚨 **最大的风险**：学生悄悄用 AI 写文档。识别方法有三：
> ① 文字风格与课堂口语表达不一致；② 出现学生不可能知道的术语；③ Git 提交时间集中在同一分钟。
> 发现后**不要当众指责**，私下要求重做即可——重点是能力养成，不是抓作弊。

---

### Task3 · CI 部署（1–2 课时）

**按你的机房条件选档**（详见 [`../decisions.md`](../decisions.md) DQ-2）。

| 档 | 适用 | 教师要准备 |
|---|---|---|
| ① **GitHub Pages（默认）** | 机房可访问 github.com | 确认学生能注册/登录个人账号 |
| ② **内网 Git** | 机房无外网 | 内网 Gitea/GitLab 或 bare repo + runner |
| ③ **RTD 托管替代** | 学生不想管 CI 细节 | 无；但学生**失去了写 `docs.yml` 的机会** |

| 教学要点 | 说明 |
|---|---|
| **`-W` 必须保留** | 三档都不豁免 `sphinx-build -W`。这是"文档与代码不漂移"的硬约束。 |
| **强调"文档即代码"** | 让学生理解：改文档 → push → 网站自动更新。这是本任务的核心认知。 |
| **验收看 URL 能打开** | TR-3.1 要求 URL 返回 200。让学生把网址发给同学验证。 |

> 💡 **离线机房的说话方式**：「我们用内网 Git 服务，原理和 GitHub 一模一样」——不要让学生觉得"我们用的是阉割版"。

---

### Task4 · 智能体最小循环（2–3 课时）⚠️ 最难

**全项目流失风险最高的一步。**

| 教学要点 | 说明 |
|---|---|
| **先跑通 `ask_simple()`** | 模板已预填。让学生确认"我能和 AI 说上话"再往下做。 |
| **用 `templates/agent.py`** | 样板代码已写好，学生只填 5 个函数。**用了模板不影响评分**。 |
| **讲清 Agent Loop 的"为什么"** | 去掉工具调用那两步，它就只是聊天机器人——不能获取实时信息。 |
| **`max_turns` 一定要讲** | 没有它可能死循环。这是学生踩坑后才会记住的点。 |
| **延迟初始化是设计亮点** | 让学生在没配 `.env` 时 `import agent`——不报错。这本身就是一课。 |

> 🎯 **本任务的核心考点只有一个**：学生能说清"消息 → 模型 → 工具调用 → 观察 → 再问模型"这个循环。
> `main()`、`get_client()`、`ask_simple()` 都是样板，学生不该在这里耗时间。

---

### Task5 · 工具调用 + autodoc（2 课时）

| 教学要点 | 说明 |
|---|---|
| **docstring 是"给模型看的文档"** | 这是文档工程与 AI 的交叉点：写得清不清楚，直接决定模型会不会调用。 |
| **`eval()` 禁用要讲案例** | 现场演示 `__import__('os').system(...)` 被 `ast` 拦截 vs 被 `eval` 执行。冲击力很强。 |
| **autodoc 的"神奇感"要放大** | 让学生看到：函数签名和 docstring **自动**出现在文档站上。 |

> 💡 **可当场演示的真实数据**（来自实际验证）：
> `calculator("123 * 456")` → `56088`；恶意输入 → `计算失败: 只支持简单的四则运算`。

---

### Task6 · 元文档闭环（1–2 课时）⭐ 最有想法

**按档位上课**（见本文第〇节）。三档的教学目标完全相同。

**要让学生体会到的核心认知**：

> **「AI 看不到我代码背后的设计意图。」**

| 档 | 课堂怎么组织 |
|---|---|
| **档 A（必做·零 Token）** | 打印 [`task6-tier-a/calculator-draft.md`](task6-tier-a/calculator-draft.md) 发给学生 → 学生对照自己的 `agent.py` 独立找差异 → **小组讨论"为什么 AI 会这么理解"** → 最后用 [`task6-tier-a/ANSWER-KEY.md`](task6-tier-a/ANSWER-KEY.md) 收口 |
| **档 B（选做·加分）** | 学生自己调 API 生成草稿 → 审校 → 差异分析 |
| **档 C（降级）** | 用自己 Task2 的 `api-draft.md` 对比最终代码 |

> 📄 **档 A 的三份教师材料**（都在 [`task6-tier-a/`](task6-tier-a/) 目录）：
> - `calculator-draft.md` —— **要发的**样例草稿。内含 3 处典型误解 + 2 处加分差异，已按"看起来很像 AI 写的"来构造。
> - `ANSWER-KEY.md` —— **教师专用，不得发给学生**。列出全部 5 处差异及判分对接。
> - `README.md` —— 分发纪律与 30 分钟课堂节奏（★ 第 3 步"为什么 AI 会这么理解"是全课重点）。
>
> 🚨 **切勿把学生手册当答案发**：`handbook/task-6-meta-doc.md` 里**刻意不写**"会在哪几处出错"，
> 就是为了保住"自己发现"这个过程。答案只在这里和 `ANSWER-KEY.md`。
>
> 详见 [`task6-tier-a/README.md`](task6-tier-a/README.md)。

> 🚨 **必须讲清诚实性红线**：用档 A/C 的学生**必须在 `diff-notes.md` 开头如实标注草稿来源**。
> 谎报为"我调 AI 生成的" → **本项判 0**。
> 讲法建议：*"降级完全正当，伪装才不正当。用老师给的样例拿满分，和调 API 拿满分，是一样多的分。"*
>
> 这条红线的作用就是**让降级没有动机伪装成满配**。

**课堂讨论的引导问题**（档 A 尤其重要）：
1. AI 猜错了哪个函数的用途？它凭什么这么猜？
2. 你的代码里哪一行"写得很清楚"但 AI 还是不懂？
3. 如果让你重新写 docstring，你会加哪句话？

### Task7 · 展示与反思（1 课时）

| 环节 | 时长 | 关键动作 |
|---|---|---|
| 路演 | 5–8 min/组 | 演示智能体 + 展示文档站 URL |
| **现场答辩** | 3–5 min/组 | 随机指一个函数，学生口头解释输入/输出/逻辑/为何这么设计 |
| 反思报告 | 课后 | 提交书面反思 |

> 🚨 **现场答辩是防 AI 代写的最后一道防线**（V 攻击 A-6 判定为 P0）。
> **随机抽函数，不要让学生自己选**——自己选就失去了验证意义。
> 大班（>15 人）可改为抽查 + 同伴互评交叉验证（见 [`../insight.md`](../insight.md) I-4 边界条件）。

**问什么**（照 [`SCORING-SHEET.md`](SCORING-SHEET.md) 附录的记录表填）：

1. 这个函数接收什么、返回什么？
2. 为什么要这样设计？换个写法行不行？
3. 如果输入是空的/异常的，会发生什么？

## 四、评分怎么给（5 分钟上手）

**完整评分表见 [`SCORING-SHEET.md`](SCORING-SHEET.md)**，可直接打印。总分为：

```
总分 = 过程性评价 40% + 终结性评价 60%
```

| 部分 | 维度 | 权重 | 怎么给 |
|---|---|---|---|
| **过程性 40%** | 参与度 | 15% | 课堂观察 |
| | 协作 | 15% | 小组互评 + 你的观察 |
| | 探究精神 | 10% | 是否主动查文档、试错 |
| **终结性 60%** | 可运行智能体 | 20% | CP-R2（TR-4.1/5.1） |
| | 文档站质量 | 20% | CP-U1（TR-2.3/5.2） |
| | **跨学科融合** | **10%** | CP-U2（TR-6.1）**档 C 折半** |
| | 展示路演 | 5% | TR-7.4 |
| | 反思报告 | 5% | CP-U3（TR-7.1） |

### 三个最容易给错分的地方

| 陷阱 | 正确做法 |
|---|---|
| **把"代码能跑"给高分** | 代码能跑**只是** TR-4.1/5.1。文档质量占 20%，融合深度占 10%。只跑通代码最多拿 40%。 |
| **觉得档 A/C 是"没做"** | 档 A 是**正式必做**，档 A 拿满分完全合理。折半只针对档 C 的 10% 那一项。 |
| **忽略过程证据** | ≥5 次原子提交（TR-7.2）。单次大提交即使内容完美也要扣——这是防 AI 代写的关键。 |

> ⚠️ **最重要的一条**：**不要因为学生没调 API 就在"跨学科融合"上扣分**。
> 这一项考的是"三视角是否咬合"，档 A 的教师预置草稿完全能达到 5 分。
> 详见 [`../review.md`](../review.md) 第五节。

## 五、常见问题速查

| 问题 | 应对 |
