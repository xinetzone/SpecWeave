## 五、档 C 折半版（配额耗尽 / 无外网时使用）

> **仅第 3.3 节（跨学科融合）折半，其余全部不变。**

| 部分 | 标准版 | **档 C · 方式 A** | **档 C · 方式 B（推荐）** |
|---|---|---|---|
| 过程性评价 | 40 | 40 | 40 |
| 可运行智能体 | 20 | 20 | **24** |
| 文档站质量 | 20 | 20 | **21** |
| **跨学科融合** | **10** | **5** | **5** |
| 展示路演 | 5 | 5 | 5 |
| 反思报告 | 5 | 5 | 5 |
| **总计** | **100** | **95** | **100** |

> ✅ **方式 B 的算术**：40 + 24 + 21 + 5 + 5 + 5 = **100**（整数，无需小数）
> ——把标准版中"跨学科融合"的 10 分，改为"该项 5 分 + 3.1 加 4 分 + 3.2 加 1 分"。
>
> 📐 **为什么不是平均分**：10 分要拆给两个 20 分项，若均分则是各 +2.5（非整数）。
> 这里按 **"难度权重"** 而非"平均"来分——3.1（可运行智能体）是 Task4/Task5 的硬骨头，且是 AC-1 的唯一证据，
> 故多分 4 分；3.2（文档站质量）本就以 rubric 五档计分、颗粒度天然偏粗，分 1 分即可。

**两种方式怎么选**：

| 方式 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 总分计 95** | 各项按表打，最后总分 ×100/95 折算百分制 | 规则最直白 | 需向学生解释"为何我们满分是 95"；折算后可能出现小数 |
| **B. 重分配至 100（推荐）** | 3.1 满分改 24、3.2 满分改 21，跨学科改为 5，总分仍 100 | **学生完全感知不到差异**；无需折算 | 需在评分表上改两个数字 |

> 💡 **为什么推荐方式 B**：档 C 是官方设计的合法降级路径（见 [`../decisions.md`](../decisions.md) DQ-3），
> 学生不应因为"机房断网"而在心理上感到被惩罚。方式 B 让总分保持 100，
> **学生只看到"跨学科融合这一项是 5 分"，而不会看到"我们被扣了 5 分"**。
>
> 🚨 **无论用哪种方式，全班必须统一**——混用会导致成绩不可比。

> 📌 **重要提醒**：**不要因为学生走了档 C 就在其他项扣分。**
> 档 C 下 AC-6 **完整可达**（用 Task2 的 `api-draft.md` 顶替 AI 草稿做差异分析）。

## 七、附录：Git 提交历史检查表

> **用途**：Task7 前对每组执行一次，填入封面的证据格。

```bash
# 1. 提交次数（TR-7.2 要求 ≥5）
git rev-list --count HEAD

# 2. 提交信息一览（看是否"单一职责"）
git log --oneline

# 3. 提交日期分布（看是否集中在最后一晚）
git log --pretty=format:"%ad %s" --date=short
```

| 检查项 | 判据 | 是 | 否 |
|---|---|---|---|
| 提交次数 ≥5 | TR-7.2 | ☐ | ☐ |
| 提交信息说明"做了什么"（非"update"/"修改"） | 质量 | ☐ | ☐ |
| 提交分散在 ≥3 个不同日期 | 真实性 | ☐ | ☐ |
| 无"一次性提交全部"的巨型提交 | 真实性 | ☐ | ☐ |
| 包含至少一条 `fix` 类提交（说明真的调过错） | 真实性 | ☐ | ☐ |

> 💡 **最后一条（有 `fix` 提交）是很好的真实性信号**：
> 一路顺利、从没修过 bug 的项目，很可能不是真做的。
> 反之，一个诚实的 `fix(tools): calculator 改用 ast 安全求值` 恰恰是深度学习的证明。
