# 截图位清单（Screenshot Slots Manifest）

> 本文件列出学生手册中全部截图位，供教师**批量填充真实截图**使用。
>
> **用法**：
> 1. 按本表拍摄/截取对应画面，命名后放入本目录（`handbook/shots/`）
> 2. 打开对应手册文件，把该截图位的引用块替换为 Markdown 图片语法：
>    ```
>    ![画面说明](shots/S1-1-venv激活.png)
>    ```
> 3. 若某截图位不需要，直接删除引用块即可，不影响手册可读性

## 二、拍摄建议

### 通用要求
- **分辨率**：建议 1920×1080 或更高，放大后仍清晰
- **格式**：PNG（截图类内容比 JPG 清晰）
- **隐私脱敏**：涉及 API Key、用户名、邮箱的画面必须打码
- **窗口整洁**：关闭无关标签页、通知弹窗、聊天窗口

### 各类画面的要点

| 类型 | 要点 |
|---|---|
| **终端截图** | 确保提示符、命令、输出都在画面内；重要输出可用红框标注 |
| **编辑器截图** | 左侧文件树 + 编辑区同时可见，便于学生对照 |
| **浏览器截图** | 保留地址栏（能看出是 `file://` 还是 `https://`） |
| **对比类截图** | 如 S5-4，用左右分栏或箭头标出差异处 |

### 特别说明

- **S1-1（venv 激活）**：这是学生最容易困惑的一步，务必让 `(.venv)` 提示符清晰可辨
- **S3-6 / S5-3**：这两个是学生"成就感来源"的关键画面，建议截取完整美观的状态
- **S6-3（差异分析）**：这是 Task6 的核心产出，建议用真实的学生案例（脱敏后）。**画面须包含 `diff-notes.md` 开头的"草稿来源声明"**——该声明是 TR-6.3 的验证对象
- **S4-1（密钥配置）**：`.env` 内容必须打码或用占位符示意
- **S7-5（设计对照）**：建议用左右分栏呈现 `api-draft.md` 的原始设想与最终代码，让"认知变化"一眼可见

## 三、文件夹约定

```
handbook/
├── README.md                    ← 手册目录
├── task-0-warmup.md
├── task-1-env.md
├── ...
├── task-7-showcase.md
└── shots/
    ├── README.md                ← 本文件
    ├── S0-1-文件夹结构.png       ← 教师填充的截图
    ├── S1-1-venv激活.png
    └── ...
```

**注意**：当前 `shots/` 目录只有本说明文件，所有截图位在手册中以引用块形式呈现。教师填充后，手册中的引用块应替换为图片链接。

> 💡 **条件性截图位**（S3-7 / S6-1 / S6-2）即使永远不填也不影响手册完整性。
> 建议教师先在**课程跑完一轮**后，用真实产生的画面回填高优先级项（尤其 S6-3 / S7-5）——
> 学生真实案例的说服力，远高于教师自制的演示截图。

## 四、无截图时的替代方案

如果时间紧张无法准备截图，手册**仍然可用**。因为：
- 每个步骤都有**完整的文字说明 + 可复制的命令**
- 每个任务都有**常见报错表**，比截图更能解决实际卡点
- 截图位是"体验优化"，不是"功能必需"

此时建议直接删除手册中的截图引用块，保持文档整洁。
