## 三、教师如何替换为真实截图

1. 按第二节表格的「文件名」列拍摄真实画面，**同名覆盖**本目录下的 PNG
2. 手册中的图片引用**已经写好**（如 `![venv 激活成功](shots/S1-1-venv激活.png)`），
   覆盖文件后无需改动任何 Markdown
3. 删除本文件第二节的「内容来源」列，或把整张表换成你的实际截图记录
4. **建议在课程跑完一轮后再做**——学生真实案例（尤其 S6-3 / S7-5）说服力远高于教师自制演示

## 四、拍摄建议（替换时参考）

### 通用要求
- **分辨率**：1920×1080 或更高，与现有示意稿保持一致（当前均为 1440×900）
- **格式**：PNG（截图类内容比 JPG 清晰）
- **隐私脱敏**：涉及 API Key、用户名、邮箱的画面必须打码
- **窗口整洁**：关闭无关标签页、通知弹窗、聊天窗口

### 各类画面的要点

| 类型 | 要点 |
|---|---|
| **终端截图** | 确保提示符、命令、输出都在画面内；重要输出可用红框标注 |
| **编辑器截图** | 左侧文件树 + 编辑区同时可见，便于学生对照 |
| **浏览器截图** | 保留地址栏（能看出是 `file://` 还是 `https://`） |
| **对比类截图** | 如 S5-4，用左右分栏或箭头标出差异处 |

### 关键画面提醒

- **S1-1（venv 激活）**：学生最容易困惑的一步，务必让 `(.venv)` 提示符清晰可辨。
  **强烈建议**连 `where python` 的输出一起截图——这是判断激活是否成功最可靠的方法
- **S3-6 / S5-3**：学生「成就感来源」的关键画面，建议截取完整美观的状态
- **S6-3（差异分析）**：Task6 核心产出，建议用真实学生案例（脱敏后）。
  **画面须包含 `diff-notes.md` 开头的「草稿来源声明」**——该声明是 TR-6.3 的验证对象
- **S4-1（密钥配置）**：`.env` 内容必须打码或用占位符示意
- **S7-5（设计对照）**：建议左右分栏呈现 `api-draft.md` 原本设想与最终代码，
  让「认知变化」一眼可见

## 七、无截图时的替代方案

即使一张图都没有，手册**仍然可用**。因为：
- 每个步骤都有**完整的文字说明 + 可复制的命令**
- 每个任务都有**常见报错表**，比截图更能解决实际卡点
- 截图位是「体验优化」，不是「功能必需」

**特别地**：当前所有示意图都由 HTML 合成，若某张图与你的实际环境差异过大（如
依赖版本号），**直接删掉手册中该处的图片引用即可**——不会破坏文档结构。
