## 一、你要做出的东西

一句话：**一个能完成任务、还能自动生成并发布自己使用文档的 AI 智能体。**

最终你会交付两样东西：
1. **一个能跑起来的智能体**（`agent.py`，能回答你的问题，会调用工具）
2. **一个公开可访问的文档站**（用 Sphinx 搭建，把自己讲清楚）

以及三份"过程证据"：反思报告、Git 提交历史、现场答辩。

## 三、开始之前：你需要会什么

如果你的 Python 还没到"能写函数、能读报错"的程度，先补这两块：

- **Python 基础**：函数、类、模块、import、异常处理（try/except）

其余的（Sphinx、Agent、工具调用）本手册会带你做。

## 四、贯穿全程的三条纪律

### 纪律 1：文档先行，不是事后补
本项目把文档定位为**理解的检验**，不是理解的记录。
你要在写代码**之前**先写出"我打算提供哪些函数、怎么调用"（Task2 的 `api-draft.md`）。
实现时如果发现和草稿对不上——**恭喜，你找到了自己的理解盲点**，记下来，这是反思报告的素材。

### 纪律 2：先手写，后用 AI
Task2 必须**完全手写**，禁止让 AI 帮你写文档。
原因：能力建构期用 AI 提效，会抑制你自己的表达能力发育。
Task6 才引入 AI 协作，而且你必须分析"AI 写错了什么"。

### 纪律 3：多次小提交，不要憋大招
Git 提交历史是评估你的重要证据。
要求 ≥5 次原子提交（每次只做一件事），**单次大提交会被扣分**。
这不是形式主义——它是你"过程真实参与"的证明。

## 六、遇到问题怎么办（通用招数）

1. **先读报错最后一行**。Python 和 Sphinx 的报错，关键信息几乎都在最后一行。
2. **抄下完整报错**，去搜索引擎搜（把路径换成通用的）。90% 的问题别人踩过。
3. **对照本任务的"常见报错"小节**，那里列了高频坑。
4. **检查你所在的目录**。一半的怪问题是因为在错误的文件夹里执行命令。用 `pwd`（Mac/Linux）或 `cd`（Windows）确认。
5. 还是不行 → 带着**完整报错 + 你执行的命令 + 你的目录位置**去问老师。这三样齐全，问题基本秒解。
