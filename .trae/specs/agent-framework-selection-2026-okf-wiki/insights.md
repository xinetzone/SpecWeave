# 洞察 — 2026 AI Agent 框架选型

## I-1 竞争轴已从“能力清单”转向“运行时范式 + 迁移成本”

- **陈述**：五个框架都能接 MCP、都能做多 Agent，真正的差异是状态放在哪里、失败后如何恢复、控制流由谁决定。
- **证据**：F-009~F-013（五种范式）、F-018~F-020（checkpoint/resume）、F-033~F-036（会话状态与图工作流）、F-041~F-043（capability 组合）、F-048~F-051（事件驱动 step）、F-058（MCP 普及降低工具迁移成本）。
- **反常识**：工具生态不再是护城河；当 MCP 把工具连接标准化后，锁定点转移到“状态与运行历史”，也就是迁移时最贵的那部分。
- **下次行动**：选型评审第一页不列功能勾选表，先写清“失败代价、状态归属、审计粒度”三项。

## I-2 “双框架”不是妥协，而是原型层与记录系统层的分工

- **陈述**：CrewAI/Pydantic AI 负责快速学习问题，LangGraph/MAF 负责不能失败的工作负载；这是分层，不是二选一。
- **证据**：F-029（CrewAI 原型后迁移）、F-055（资深团队模式）、F-065~F-067（双框架建议与迁移成本）。
- **反常识**：强行用一个框架覆盖两段，会把原型的低约束带进生产，或把生产的重约束压进原型，二者都更贵。
- **下次行动**：在任何 Agent 项目启动时标注 `demo` 或 `system of record`，并据此选框架；迁移预算单列。

## I-3 二手对比文的最大风险是“版本时间线”，不是“观点分歧”

- **陈述**：观点可以被读者辨别，日期与版本却会被当作事实直接引用；本次核验的主要产出是一处年份错误与两处过度表述。
- **证据**：F-072（LlamaIndex 1.0 实际为 2025-06，原文写 2026-06）、F-074（A2A “native at 1.0” 实为 coming soon）、F-075（Replit 未在官方客户页）、F-061/F-080（价格区间无单一出处）。
- **反常识**：越是结构清晰、表格漂亮的对比文，越容易让未核验的日期混入决策依据。
- **下次行动**：所有“某年某月发布/稳定/GA”必须回 GitHub release、PyPI 上传时间或官方公告三选一；找不到就标“仅博文单源”。

## I-4 成本讨论应从“框架许可”切换到“token 模式”

- **陈述**：框架免费，真正增长的是多步推理与多 Agent 重发上下文带来的 token 支出。
- **证据**：F-059~F-064。
- **反常识**：省框架许可费没有意义；限制每步推理、启用 prompt caching、用结构化状态压上下文，才是成本杠杆。
- **下次行动**：选型 PoC 同时记录每次任务的 token/步骤数，把成本指标与延迟、成功率放在同一张表。
