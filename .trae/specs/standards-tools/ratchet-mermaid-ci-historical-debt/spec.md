# Mermaid 历史债务基线与 CI 增量门禁 — 产品需求文档

## Overview

- **Summary**：为 Mermaid 全仓扫描建立可审计的历史违规基线，使 CI 阻断新增或恶化的问题，同时保留严格全量检查能力。
- **Purpose**：VS Code 兼容规则于 2026-07-20 接入全仓检查后，现存历史图表被一次性报告为约 5.1k 条错误、涉及约 687 个 Markdown 文件，阻断 CI。绝大多数是历史 `<br/>` 用法；全量机械改写会造成大范围文档差异并损失图表排版。
- **Target Users**：维护 SpecWeave 文档、Mermaid 检查器及 CI 门禁的贡献者。

## Goals

- 保留当前 Mermaid 规则及严格扫描能力，不把历史错误误报为新增问题。
- 让 CI 对新增违规及同一指纹违规数量增加继续失败。
- 支持在修复历史问题后显式缩减基线，形成可验证的渐进治理。
- 统一换行规则与诊断：VS Code 兼容模式下换行压为单行，不再建议以 `<br/>` 替代 `\n`。

## Non-Goals

- 一次性重写数百篇历史文档或自动删除全部 `<br/>`。
- 放宽 Mermaid 的 VS Code 兼容规则或关闭全仓扫描。
- 自动清理历史违规、静默更新基线或把新增文件纳入豁免。

## Background & Context

- 2026-07-20 的提交 `4e345b316` 将 VS Code 兼容检查接入扫描，但未迁移历史图表。
- 2026-09-30 的只读扫描涉及约 687 个问题文件；分类约为：`<br/>` 3,939 条、嵌套 direction 119 条、空行 72 条、反斜杠换行 44 条、带圈数字 206 条，其他规则约 735 条。检查输出中还存在一条汇总错误行，具体基线总数须由新工具在可复现扫描中重新计算。
- `common.py` 的换行检查/修复测试仍期待 `\n → <br/>`，与当前 VS Code 单行策略不一致。
- 当前未跟踪的 `docs/topics/travel/` 文档单独扫描为 0 错误；不得将未跟踪或工作区修改内容写入初始历史基线。

## Functional Requirements

- **FR-1**：检查器 SHALL 支持严格全量模式和基线比较模式；严格模式继续对任何违规返回非零退出码。
- **FR-2**：基线 SHALL 由稳定指纹表示，至少包含仓库相对路径、规则标识、规范化违规源码指纹及出现次数，不以行号作为唯一身份。
- **FR-3**：基线初始化 SHALL 只采集指定 Git 基线提交中的已跟踪 Markdown 内容，不采集未跟踪文件或工作区改动。
- **FR-4**：基线比较 SHALL 将超过基线的新增指纹或出现次数增加报告为错误；已知历史项保持可见但不阻断；已修复项 SHALL 可通过显式操作从基线移除。
- **FR-5**：更新基线 SHALL 是显式操作，默认只允许缩减已登记债务；新增豁免不得由普通 CI 或扫描命令静默写入。
- **FR-6**：CI 的 Mermaid 门禁 SHALL 使用基线比较模式，并分别汇总已知历史项、新增项及已消除项。
- **FR-7**：`\n` 换行违规的诊断和修复 SHALL 与 VS Code 单行策略一致，建议以空格压平，而不是引入随后会被拒绝的 `<br/>`。

## Non-Functional Requirements

- **NFR-1**：同一提交、同一规则下，跨平台生成的基线和摘要必须确定且可重复。
- **NFR-2**：基线比较不得隐藏违规文件、规则类别或新增错误的位置。
- **NFR-3**：CI 不得修改基线或其他工作区文件。

## Constraints

- **Technical**：复用 `.agents/scripts/lib/checks/mermaid.py`、`repo-check.py` 与现有 CI 接线；新增脚本前检查 `.agents/scripts/lib/README.md`，避免重复实现。
- **Policy**：规则 8 保持有效；全量严格扫描仍可供本地审计使用。
- **Scope**：不批量改写未涉及此次门禁的历史 Markdown 文件。
- **Dependencies**：基线必须进入 Git 跟踪并接受常规代码审查；正式基线扫描结果须由实现后的工具复现并记录。

## Assumptions

- 采用历史基线渐进收敛，是在保留严格策略的前提下恢复 CI 可用性的默认方案。
- 当前待提交旅行文档通过严格单目录检查，不属于历史基线豁免范围。
- 早先全量 CI 与本次隔离扫描报告的数量存在差异；基线实现须以同一工具、同一提交的可复现结果为准，不硬编码扫描摘要数字。

## Acceptance Criteria

### AC-1: 历史基线可复现且不吸收工作区内容
- **Type**: `rule`
- **Given** 一个已提交基线提交，以及包含未跟踪或已修改 Markdown 文件的工作区
- **When** 生成初始 Mermaid 历史基线
- **Then** 基线只反映指定提交中的已跟踪文件，不包含未跟踪或工作区版本中的发现
- **Pass Condition**：连续两次对同一提交生成的基线字节级确定；未跟踪文件的违规不会出现在基线中
- **Evidence**：基线生成器测试及同一提交的重复生成校验

### AC-2: 新增或恶化违规被阻断
- **Type**: `rule`
- **Given** 已登记的路径、规则与源码指纹基线及其出现次数
- **When** 基线比较模式发现新指纹或同一指纹数量高于基线
- **Then** 检查以非零退出，并输出文件、行号、规则和超出数量
- **Pass Condition**：新增文件违规、既有文件新增违规及重复次数增加均阻断；仅行号漂移不产生新增发现
- **Evidence**：检查器回归测试及 CLI 退出码断言

### AC-3: 历史债务不再阻断 CI，严格扫描语义不变
- **Type**: `rule`
- **Given** 全仓发现与已登记基线完全相同或更少
- **When** 分别运行基线比较模式和严格全量模式
- **Then** 基线模式通过并报告历史发现；严格模式仍对任何存量错误返回非零
- **Pass Condition**：CI 接线使用基线模式；默认严格模式仍保留原阻断行为
- **Evidence**：命令级测试、`repo-check.py` 集成测试及 CI 调用点检查

### AC-4: 基线只能显式、单调缩减
- **Type**: `rule`
- **Given** 一份已版本控制的 Mermaid 基线
- **When** 执行普通 CI 检查或显式清理已修复项
- **Then** CI 不写文件；清理操作只移除已不存在的基线发现，不能静默增加豁免
- **Pass Condition**：工作区只读检查无差异；缩减前后基线差异可审查；尝试隐式增加基线项被拒绝
- **Evidence**：文件系统写入断言和基线更新命令测试

### AC-5: 换行检查与修复符合单行策略
- **Type**: `rule`
- **Given** Mermaid 文本含 `\n` 且目标规则采用 VS Code 单行兼容策略
- **When** 执行诊断或自动修复
- **Then** 诊断建议压平为空格，修复结果不产生 `<br/>`
- **Pass Condition**：公共函数、各图表修复器及端到端 CLI 测试对该策略一致
- **Evidence**：更新后的单元测试和 Mermaid 检查器回归测试

## Open Questions

- 无；本草案采用历史基线加严格新增违规门禁，实施细节由任务计划约束并在批准后完成。
