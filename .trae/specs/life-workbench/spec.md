# 一页生活（life-workbench）- 产品需求文档

> 七概念场景：新功能开发，采用 C → V 链路；通过 Spec Mode 固化范围、验收标准、实施证据与独立审查。应用成品为一个完全自包含的 `index.html`，不依赖网络、框架、字体、图标库或外部资源。

## Overview

- **Summary**：为泛生活人群提供一个本地优先的生活工作台，把财务、习惯、体重健身、日程、待买事项与书影音收藏整合在一页内，数据只保存在当前浏览器。
- **Purpose**：减少生活记录分散在多个 App、表格与备忘录中的切换成本；让用户能在一个克制、清晰、可持续使用的界面里记录、回顾和备份个人生活数据。
- **Target Users**：希望用一个轻量页面管理日常生活的普通个人用户；不要求技术背景。

## Goals

- G1：一屏提供今日概览与七个生活域的快速入口，桌面与手机均可稳定使用。
- G2：所有业务数据输入后立即写入 `localStorage`，刷新或关闭页面后可恢复。
- G3：财务模块覆盖收支、预算、月度对比、分类筛选、消费结构与 Excel 兼容导出。
- G4：习惯与健身模块既支持快速日常打卡，也支持 30 天与 7 日趋势回顾。
- G5：日程、待买与书影音模块覆盖从收集、执行到统计回顾的完整闭环。
- G6：提供 JSON 全量备份、无人工条数上限的导入、20 条新增提醒、存储失败与数据损坏恢复。
- G7：以不模板化的编辑台式布局呈现，视觉克制、高级、有生活感。

## Non-Goals

- 不做账号、多用户、云同步、服务端、数据库或跨设备自动同步。
- 不调用天气、行情、图书、影视、封面或任何第三方 API。
- 不引入 React/Vue、图表库、Excel 库、图标库、Web Font、CDN 或构建链。
- 不提供医疗诊断、投资建议或精确运动处方；BMI、热量缺口等仅作个人记录参考。
- 不做系统通知、后台任务、PWA 安装或浏览器扩展。
- 不承诺突破浏览器 `localStorage` 容量；容量不足时必须明确告知并提供内存数据紧急导出。

## Background & Context

- 用户明确要求在 `apps/` 下交付纯单文件 HTML，全部 CSS、JavaScript、图标与视觉资源内联。
- 应用属于长期可用的独立工作台而非展示型页面，正式目录采用根级 `apps/life-workbench/`；开发先在工作区 `.temp/life-workbench/` 完成，再迁移。
- 数据全部留在浏览器本地。唯一文件可直接双击使用，也可通过任意静态 HTTP 服务打开。
- “今日生活指数”定义为由当前月预算余量、今日习惯完成、今日健身记录、日程完成度等可观测本地数据计算出的生活节奏指标；无数据时显示引导，不伪造结论。

## Functional Requirements

### FR-1：应用壳与今日生活指数

- 提供固定品牌区、日期问候、全局快捷新增、模块导航、今日重点摘要与总览指标。
- 今日生活指数至少展示：生活节奏综合分、预算健康、习惯完成、日程完成；计算规则在界面可解释。
- 无数据、新用户与演示数据被清空后均有明确空状态。

### FR-2：记账理财

- 收支记录字段：日期、类型（收入/支出）、金额、分类、备注；支持新增、删除。
- 支持月预算设置、当月支出/收入/结余、预算使用进度、上月与本月对比。
- 支持按月份、类型、分类筛选；消费结构按支出分类展示金额、占比与可视化。
- 导出当前筛选结果为 Excel 可直接打开的 UTF-8 CSV 文件，中文与金额不得乱码。

### FR-3：习惯健康

- 用户可新增、删除习惯；习惯类型为勾选、计数、数值三种。
- 勾选型支持当天开/关；计数型支持增减与直接输入；数值型支持输入数值与单位。
- 每个习惯展示最近 30 天热力图；颜色强度按完成度或数值相对目标计算。
- 支持目标值与单位；当天打卡改变后立即保存并更新总览。

### FR-4：减脂健身

- 个人设置：身高、起始体重、目标体重；日志字段：日期、体重、体脂率、摄入热量、消耗热量。
- 展示最新 BMI、目标进度、累计变化、当天/近期热量缺口。
- 体重趋势使用内联 SVG 绘制原始值与 7 日移动均线；不足 7 天时用已有数据计算。
- 提供周一至周日可自定义训练计划，支持内容编辑与当天完成勾选。

### FR-5：日程统筹

- 日程字段：标题、日期、时间、类型、备注、完成状态；支持新增、完成切换、删除。
- 默认突出今天与未来日程，逾期未完成项明确标记；支持按日期查看。

### FR-6：待买清单

- 条目字段：名称、数量、预估单价、优先级、分类、已购买状态；支持新增、勾选、删除。
- 展示未买数量与预估总额；已购买条目可折叠或筛除。

### FR-7：书影音收藏

- 收藏字段：类型（书/电影/剧集/音乐/播客/其他）、标题、创作者、状态（想看/在看/已完成/搁置）、完成日期、1-5 星、短评。
- 提供封面墙与列表两种视图；封面由本地 CSS 色块、类型标识与标题生成，不请求远程图片。
- 支持状态与类型筛选；年度统计至少包含完成数量、类型分布、平均星级、月度完成趋势。

### FR-8：即时持久化与数据模型

- 任何表单字段修改、勾选、计数、排序或设置改变后自动保存；自由文本输入允许短防抖，但页面离开前必须同步冲刷。
- 使用带 `schemaVersion` 的统一 JSON 状态；记录均含稳定唯一 ID 与创建/更新时间。
- 首次打开载入少量演示数据；提供“仅清空演示数据”和“清空全部数据”两个不同操作，后者二次确认。

### FR-9：备份、导入与恢复

- 全量 JSON 导出包含 schema 版本、导出时间与全部业务数据；导出成功后重置“新增后未备份”计数。
- JSON 导入不设人工条数上限；支持“合并”和“替换”两种模式；导入前完成结构校验并显示记录数摘要，用户确认后写入。
- 每新增累计 20 条业务记录显示持久备份提醒；提醒不会阻断录入，完成 JSON 导出后消失。
- 每次成功保存前保留最近一次可解析安全快照。主数据解析失败时明确显示损坏提示，允许从安全快照恢复、下载原始损坏内容或重置。
- `localStorage` 配额、隐私模式或权限导致保存失败时显示明确错误，不得伪装成功；保留内存状态并提供紧急 JSON 下载。

## Non-Functional Requirements

- **NFR-1（单文件）**：应用运行所需 HTML、CSS、JavaScript、SVG 图标和演示数据全部位于一个 `index.html`；源码中不存在外部运行时资源引用。
- **NFR-2（离线）**：断网情况下除浏览器下载文件外全部功能可用；无网络请求。
- **NFR-3（兼容）**：支持当前主流 Chromium、Firefox、Safari；宽度 360px 的手机与 1280px 以上桌面均无横向溢出，关键操作可触达。
- **NFR-4（可访问性）**：使用语义化表单、可见焦点、键盘可操作按钮、足够对比度、`aria-label` 或可见标签；尊重 `prefers-reduced-motion`。
- **NFR-5（性能）**：常规 1,000 条记录下首屏与模块切换保持流畅；列表渲染不执行网络或同步重计算型外部任务。
- **NFR-6（安全）**：用户文本通过 DOM `textContent` 或等价安全方式渲染，禁止把用户输入直接拼入 `innerHTML`；导入数据经过字段与类型校验。
- **NFR-7（视觉）**：采用纸张、编辑台、分栏或时间轴等混合构图，避免整页等尺寸圆角卡片阵列；色彩为暖灰、墨绿与少量琥珀强调，层级清楚但不过度装饰。
- **NFR-8（仓库）**：正式应用目录包含自包含 `index.html` 与说明性 `README.md`；同步 `apps/AGENTS.md` 和 `apps/README.md` 索引，无临时文件残留。

## Constraints

- **Technical**：纯原生 HTML/CSS/JavaScript；仅使用浏览器标准 API（DOM、localStorage、Blob、FileReader、SVG）。
- **Data**：数据存于当前浏览器 origin 的 `localStorage`；用户需通过 JSON 备份跨浏览器或跨设备迁移。
- **Resources**：不得引用外部图片、字体、样式、脚本或图标。
- **Repository**：先在 `.temp/life-workbench/` 开发验证，完成后迁移至 `apps/life-workbench/` 并登记路由。

## Assumptions

- 用户在现代浏览器中运行，允许使用 `localStorage` 与文件下载/上传。
- “Excel 导出”以 Excel 可直接打开且中文正确的 UTF-8 CSV 为验收形态，不引入第三方 XLSX 库。
- “不限条数导入”指应用不设置业务数量上限；实际可导入规模受设备内存和浏览器存储配额约束，超限必须明确提示。
- 7 日均线按最近 7 条按日期排序的体重数据滚动计算；少于 7 条时按已有数据计算。
- 生活指数是本地记录的透明聚合指标，不代表医疗或财务专业结论。

## Acceptance Criteria

### AC-1：单文件与零外部依赖
- **Type**：`rule`
- **Given**：正式交付目录中的 `index.html`
- **When**：静态扫描资源引用并在断网环境打开
- **Then**：CSS、JS、SVG 与演示数据全部内联；无 CDN、远程图片、外部字体、模块包或网络请求；页面可完整交互
- **Pass Condition**：依赖扫描无外链，离线浏览器冒烟通过
- **Evidence**：静态扫描结果 + 浏览器冒烟记录

### AC-2：即时保存与刷新恢复
- **Type**：`rule`
- **Given**：用户在任一模块新增或编辑数据
- **When**：立即刷新页面或关闭后重新打开
- **Then**：最后一次有效输入被恢复；自由文本防抖中的内容在 `pagehide` 前完成保存
- **Pass Condition**：七个模块各完成至少一次新增/修改/刷新对拍
- **Evidence**：浏览器自动化冒烟 + localStorage 状态检查

### AC-3：财务闭环
- **Type**：`rule`
- **Given**：包含两个月、多分类、收入和支出的构造数据及月预算
- **When**：切换月份/类型/分类筛选并导出
- **Then**：汇总、月度对比、预算进度和消费结构与手算一致；导出文件可被 Excel 打开且中文无乱码
- **Pass Condition**：计算断言与下载冒烟通过
- **Evidence**：脚本断言 + 浏览器下载记录

### AC-4：三类习惯与 30 天热力图
- **Type**：`rule`
- **Given**：勾选、计数、数值三种习惯
- **When**：分别打卡、修改目标、删除其中一项
- **Then**：当天值与总览同步更新；每项展示连续 30 天格；删除后记录不再出现
- **Pass Condition**：三类型交互与 30 格数量断言通过
- **Evidence**：浏览器 DOM 与 localStorage 检查

### AC-5：健身指标与计划
- **Type**：`rule`
- **Given**：身高、目标、至少 8 条跨日体重/体脂/热量日志及周计划
- **When**：查看趋势并完成当天计划
- **Then**：BMI、目标进度、热量缺口、7 日均线计算正确；SVG 趋势可见；周计划内容和完成态刷新后保留
- **Pass Condition**：公式与持久化断言通过
- **Evidence**：脚本断言 + 浏览器冒烟

### AC-6：日程、待买与书影音闭环
- **Type**：`rule`
- **Given**：每个模块至少 3 条不同状态数据
- **When**：新增、筛选、完成/购买、切换收藏视图并查看年度统计
- **Then**：状态变化、筛选结果、合计、封面墙/列表与年度统计正确且刷新后保留
- **Pass Condition**：各模块主路径与空状态均通过
- **Evidence**：浏览器冒烟记录

### AC-7：备份提醒、导入与恢复
- **Type**：`rule`
- **Given**：连续新增 20 条记录、一个合法大批量 JSON、一个畸形 JSON、一个被破坏的主存储值
- **When**：触发提醒、导出、合并/替换导入、重新加载损坏数据
- **Then**：第 20 条出现提醒；导出后提醒重置；合法数据无人工条数限制地导入；畸形数据零写入；损坏数据可从安全快照恢复或下载原始内容
- **Pass Condition**：所有分支均有明确可观察结果且无静默数据丢失
- **Evidence**：浏览器自动化 + localStorage 注入测试

### AC-8：存储失败显性化
- **Type**：`rule`
- **Given**：模拟 `localStorage.setItem` 抛出异常
- **When**：用户继续录入
- **Then**：界面出现持久错误提示，说明数据仅保留在内存并提供紧急 JSON 导出；不得显示保存成功
- **Pass Condition**：异常分支可重复触发且导出数据包含最新内存状态
- **Evidence**：注入测试与下载内容检查

### AC-9：响应式与可访问性
- **Type**：`rule`
- **Given**：360×800 与 1440×900 两种视口以及键盘操作
- **When**：访问所有模块、打开表单和执行主要操作
- **Then**：无横向溢出、遮挡或不可触达控件；Tab 焦点可见；按钮与输入有可理解名称
- **Pass Condition**：双视口冒烟与基础可访问性检查通过
- **Evidence**：浏览器 DOM/布局检查

### AC-10：视觉与信息设计质量
- **Type**：`rubric`
- **Dimension**：克制、高级、生活感与非模板化布局的综合契合度
- **Scale**：1-5
- **Anchors**：1 = 通用管理后台与重复卡片堆叠；3 = 配色舒适但信息架构普通；5 = 编辑台式层次鲜明、数据密度与留白平衡、细节有生活温度且操作直观
- **Pass Threshold**：>= 4
- **Evidence**：独立审查对源码结构、关键页面与双视口交互的评估

## Open Questions

- 无阻塞问题。Excel 导出、生活指数和不限条数导入的边界已在 Assumptions 中明确。
