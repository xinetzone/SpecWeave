# 秒悟赏金 IDEA·026「Skill 导航台」 - Product Requirements Document

## Overview

- **Summary**：响应秒悟（Meoo）应用赏金广场赏金 **IDEA · 026**「帮新手快速找到最合适的 Skill，并直接体验结果」，交付一个零依赖单页 **「Skill 导航台」**：新手用一句话描述痛点或点选痛点卡片，页面在 3 秒内推荐 1–2 个最合适的 Meoo Skill，讲清「它能具体解决你什么实际问题、适合谁、什么时候不该用它」，并提供页内**示意演示**（用示例数据现场跑一遍「输入 → 它做什么 → 你会拿到什么」），让新手在安装前先看到结果形态；末段给出前往 Meoo 技能市场的入口。交付物以静态模式**已部署到 Meoo CDN：<https://yzv5eq2kp2uc.meoo.run>**（项目「Skill 导航台」，URL ID `yzv5eq2kp2uc`；2026-10-18 首版发布 v2 active，同日按用户实测反馈完成「出口按钮直达该技能」缺陷修复后重新发布 **v5 active**，见 Task 8）。
- **Purpose**：赏金发起人（`aliyun1367352920`，设计师）指出的问题域是——**Skill 列表太长，新手不知道每个 Skill 能具体解决什么实际问题，缺乏直观的体验和引导，导致无从下手**。平台侧技能市场（`meoo.com/skills`）是「平铺目录」形态，按分类罗列 + 累计使用量，新用户缺少「从我的问题反推该用哪个」的入口。本页补的正是这一段：**把「目录」翻译成「问题 → 技能 → 结果」三跳路径**。
- **Target Users**：第一次注册使用 Meoo、对平台能力不了解的新用户；不知道该从哪个 Skill 入手的产品/内容/运营初学者；需要先看结果再决定是否投入的谨慎型用户。

## Goals

- 让新用户**不必读完整个技能市场**即可收敛到 1–2 个候选 Skill：入口只需一次点选或一句话。
- 让推荐**可解释**：每张推荐卡必须说明「为什么是它」，而不是只给结论。
- 让用户在**安装前就看到结果形态**：页内示意演示覆盖全部被推荐条目，不允许出现「点了没反应」的空演示。
- 数据全部取自 Meoo 平台**真实可见**的 Skill 条目（名称 / 作者 / 累计使用量 / 简介），不改写、不排名背书、不虚构使用量。
- 交付物**零依赖、零构建、零成本、可断网运行**：单页静态资源，不调用任何大模型 API，不消耗平台额度。

## Non-Goals

- 不调用大模型做「智能推荐」：推荐由策展映射 + 关键词打分实现，理由可审计（详见 Assumptions 与 `raw/design-f.md`）。
- 不运行任何真实 Skill：页内演示为**示意**（示例输入 + 由该 Skill 公开简介拆解出的处理步骤 + 示意产出），不冒充真实执行结果。
- 不抓取 Skill 详情页正文，不逆向平台 SPA 私有接口，不绕过任何登录/鉴权。
- 不展示全部 Skill（赏金痛点正是「列表太长」）；本页是**策展子集**，未收录条目不承诺覆盖。
- 不对任何 Skill 或创作者作评测、背书、排序、收益承诺。
- 不修改 `projects/`、`vendor/` 内任何文件；不动 `.agents/` 主权区规范资产。

## Functional Requirements

- **FR-1（入口）**：页面首屏提供两种等价入口——①**痛点卡点选**（≥12 张，分「我想做点什么」与「我卡在哪一步」两组）；②**自由输入**（一句话描述问题）。两者产生同一份查询向量，进入同一推荐流程。
- **FR-2（推荐）**：输出 **1–2 个** Skill 卡片。每张卡必须含：技能名、作者、累计使用量（来自市场页则为数字，来自事件页则为「事件页未提供」）、**「它能帮你解决什么」**（忠实于该条目自身简介的一句话）、**「适合谁 / 什么时候不该用它」**、**匹配理由**（显示命中的痛点关键词与打分依据）、**数据来源标注**。
- **FR-3（匹配可解释）**：推荐由本地打分实现——痛点 → 标签集合 → 对每个 Skill 的标签集合求加权命中分；并列时以累计使用量（缺失按 0）与策展权重决胜。**页面须展示命中依据**，不得只给结论。
- **FR-4（互动演示）**：每张推荐卡提供「先看看结果」按钮，展开页内演示面板，含三段：①**你大概会这样输入**（示例输入文案）②**它会怎么做**（3 步，由该 Skill 公开简介拆解）③**你会拿到什么**（产出物清单 + 一张示意产物卡）。面板内**必须**有显著标识：`示意演示 · 非该 Skill 的真实运行结果`。
- **FR-5（兜底）**：无匹配或用户点「都不对」时，给出兜底路径——列出该组痛点对应的全部候选，并提供「去 Meoo 技能市场自己找」直达链接（`https://meoo.com/skills`）。
- **FR-6（收录范围）**：数据集收录 ≥30 条真实 Skill 条目，**每条都必须带完整演示数据**（不得出现空演示）；覆盖面须覆盖全部痛点卡（每张痛点卡的候选数 ≥2）。
- **FR-7（页脚声明）**：页脚标注 ①数据快照日期与两个来源页 URL；②免责声明「演示为示意，非真实运行；本页不评测、不背书任何 Skill 或创作者；**页面顺序只表示与用户描述匹配的程度，不代表质量/口碑/收益排名**」；③「源码自身零网络请求 + 托管方注入的外部引用」的如实说明；④本页用途说明（秒悟应用赏金广场 IDEA·026 交付物）。
- **FR-8（直达技能，2026-10-18 缺陷修复追加）**：每张推荐卡与演示面板的出口按钮，在能确定该条目详情页地址时必须**直达该技能详情页**（`https://meoo.com/skills/<数字ID>`）；确实无法确定时回退到技能市场首页，且**回退状态必须在按钮文案上可识别**（「打开这个技能」/「去市场里搜它」二态），不得用同一文案掩盖两种行为。
- **FR-9（别名披露，2026-10-18 追加）**：同一技能在两个来源页显示名不同时（平台侧口径差），卡片必须显式披露其在技能市场页显示名（形如「打开后会看到它在技能市场页里的名字是「X」」），避免用户点进去看到不同名字而以为走错。

## Non-Functional Requirements

- **NFR-1（零依赖）**：纯 HTML/CSS/JS，无框架、无包管理器、无构建步骤、无外部 CDN 资源（字体/图标/图片一律内联或本地）；断网可用。
- **NFR-2（四文件分离）**：`site/index.html`（结构）+ `site/assets/app.css`（样式）+ `site/assets/data.js`（数据层，全局 `window.SKILL_DATA`）+ `site/assets/app.js`（逻辑层）。数据层与视图层分离，便于后续刷新数据。
- **NFR-3（部署协议）**：项目根 `mise.toml` 满足 Meoo 静态协议——`[tasks.dev]` 监听 `0.0.0.0:3015`、`[meoo.deploy] mode = "static"`、`output = "site"`、不得声明 `port` 或 `tasks.start`；`site/index.html` 存在。
- **NFR-4（可访问性与响应式）**：语义化标签（`button`/`section`/`aria-*`）；键盘可达（Tab 顺序、Enter/Space 触发）；≥900px 双列、<900px 单列；对比度满足 WCAG AA。
- **NFR-5（诚实标注）**：任何非平台官方口径的内容（「适合谁」「什么时候不该用它」「它会怎么做」「你会拿到什么」）必须在 UI 上可识别为本页整理/示意，不得表述为 Skill 官方承诺。
- **NFR-6（无外部请求）**：页面运行时**零网络请求**（不含 `fetch`/`XMLHttpRequest`/外链图片）；不采集用户输入，不做埋点，不上传任何数据。
- **NFR-7（响应时间）**：点选痛点 → 结果呈现 ≤ 300ms（本地计算，无异步等待）。

## Acceptance Criteria

- **AC-1（rule）**：`apps/samples/skill-navigator/site/` 下恰有 4 个文件（`index.html`、`assets/app.css`、`assets/data.js`、`assets/app.js`）；运行时零外部网络请求（正则核查 `http://`/`https://` 仅出现在**数据层的来源标注文本**与**CTA 链接**中，且 CTA 仅在用户点击时跳转）。
- **AC-2（rule）**：`data.js` 中 Skill 条目数 ≥30；**每条**均含非空 `name`/`author`/`solve`/`fit`/`notFor`/`tags`(≥2)/`source`/`demo{input,steps[3],deliverables[≥2]}`；`tags` 全集覆盖全部痛点卡的标签引用（零悬空标签）。
- **AC-3（rule）**：痛点卡 ≥12 张，分两组；每张痛点卡的候选 Skill 数 ≥2（机械可数）。
- **AC-4（rule）**：推荐函数在给定任一痛点卡时返回 1–2 条结果且非空；返回结果必须含「匹配理由」文本（命中标签名 + 分值），不得为空串。
- **AC-5（rule）**：项目根 `mise.toml` 通过 `validate-mise-protocol.cjs` 校验；`mise run dev` 起服后 `http://127.0.0.1:3015/` 返回 200 且含页面标题文本。
- **AC-6（rule）**：`meoo deploy` 成功，产出公网静态链接；`meoo releases list` 可见本次发布记录。
- **AC-7（rubric，阈值 ≥4）**：新手可用性——①首屏 5 秒内能判断「该点哪个」；②推荐卡读完即知道「这技能干什么、给谁、我该不该用」；③演示面板看完能说出「我会拿到什么」；④无术语墙（不使用 Skill/Agent/Prompt 等词作为面向用户的标题）。
- **AC-8（rubric，阈值 ≥4）**：事实忠实度——①每条 `solve` 与来源条目简介语义一致、无新增事实；②使用量数字与来源页一致；③无来源条目不虚构使用量；④演示三段均可追溯到该条目的公开简介。
- **AC-9（rule，2026-10-18 追加）**：`data.js` 中所有 `url` 字段（若存在）必须匹配 `^https://meoo\.com/skills/\d+$`；带 `url` 的条目占全部条目 **≥75%**；且**抽样 ≥6 条**实测其落地页确实渲染出对应技能（技能名 + 贡献者一致）。禁止以 HTTP 状态码作为可达性证据——实测伪 ID 亦返回 200 + 同一 SPA 外壳。
- **AC-10（rule，2026-10-18 追加）**：存在市场页别名（`marketName`）的条目，卡片上必须出现别名披露文案；`marketName` 与 `name` 相同的条目不得渲染该文案。

## Constraints

- **Technical**：Windows 环境；Meoo 静态 CDN 发布；`output` 相对路径；纯 HTML 不得引入框架/包管理器；`mise` 已装（2026.7.14）。
- **Business**：接单已提交（F-018），交付说明已在平台公开可见，其中承诺的交付内容与本 spec 的 FR-1~FR-7 一一对应，不得缩减。
- **Dependencies**：`.agents/skills/meoo-cli/references/mise-import.md`、`static-deploy.md`；`.agents/skills/meoo-cli/scripts/validate-mise-protocol.cjs`；同族先例 spec 与其 `raw/source-page.md`。
- **边界**：`projects/awesome-okf-xs/` 为 git submodule，本轮只读引用其工作树内既有文件，不写入、不 commit。

## Assumptions

- **A1（推荐不依赖大模型）**：赏金原文用词为「智能推荐」，本方案实现为「策展标签映射 + 加权打分」。理由（假设剥离记录见 `raw/design-f.md`）：①受众痛点域是有限集合，策展映射的准确率不低于通用模型猜测，且**理由可解释、可审计**；②静态部署不引入 API Key 与额度消耗；③零网络请求 → 断网可用、无延迟。若后续要求接入大模型，数据层已独立，可直接复用。
- **A2（演示为示意而非真实执行）**：静态页无法执行 Skill。以「示例输入 + 简介拆解步骤 + 示意产出物」满足「先看到结果」的目标，并以显著标识避免误导。若平台后续提供 Skill 试跑接口，本页可替换为真实调用。
- **A3（数据来源合并）**：合并 S1（事件页 25 条）与 S2（市场页条目）为一份策展集，同主题不同署名的条目各自登记、不判同一性。
- **A4（落位）**：`apps/samples/skill-navigator/`；如用户要求改址，回到 Specify 重新对齐。
- **A5（平台口径时效）**：技能市场条目与使用量为快照数据，页脚标注快照日期；后续以 `meoo.com/skills` 最新为准。
