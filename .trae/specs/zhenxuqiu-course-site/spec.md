# spec：需求澄清方法论工作台（公开站）

> ⚠️ 本 spec 是**公开区**文件（`.trae/specs/` 受版本控制）。
> 它**不得**包含任何私域标识、学员称呼、讲师真名、联系方式、
> 私域台账编号、平台取证细节或课堂逐字内容。
> 私域工作文档（含实测数据、审查记录、语料样本）另存于私域目录。

## 1. 目标

建设一个**公开**网站，把一套「需求澄清」方法论做成**可填写、可带走、可离线使用**的工作台。

方法论内核来自一门线上课程。我们**只公开方法论层**：

- **要公开**：概念的定义与相互关系、追问链的结构、练习表字段与自检维度、教练（陪练）侧的行为约束
- **不公开**：课堂逐字内容、课堂环节的真实题目与验收方式、讲师与学员的身份信息、
  课程方的品牌标识与标识物、付费课程的课程结构映射

## 2. 范围

### 2.1 站点能力

| 能力 | 说明 |
|---|---|
| 概念阅读 | 7 个方法论页面（含首页分流页与关于页）+ 术语表 |
| 互动练习 | 4 张练习表（三问 / 优势 / 校准 / 落地）+ 落地动作诊断器（由前两表派生） |
| 小玩法 | 《只够问三句》：六张牌里挑三张、给它们排顺序，逐句看落点与前提。不评分、不排行 |
| 数据自主 | 练习数据默认只存在读者本机浏览器，不上传；可导出 JSON / Markdown / 打印成 PDF |
| 云端回看 | 读者可登录并主动把练习记录存到「我的空间」（按账号隔离，仅本人可见）；**默认不存**，不存即本机 |
| 离线可用 | 页面无外部资源依赖；导出件可离线使用 |

### 2.2 明确不做

- 无评论、无支付、不设课程导流入口
- **不做默认上传**：不点「保存到我的空间」就不上传任何内容
- 不发布任何未公开环节的内容
- 不使用课程方的品牌标识作本站框架命名，不使用其图片素材
- 不做逐字稿还原
- **玩法不做判定**：不评分、不排行、不判输赢、不公布「先问哪句」——判定由读者自己做

## 3. 技术方案

| 项 | 选择 |
|---|---|
| 运行时 | Python 3.14（`requires-python = ">=3.14,<3.16"`） |
| Web 框架 | Starlette（仅 1.x API） |
| 模板 | Jinja2 |
| Markdown | markdown-it-py |
| frontmatter | 零依赖 YAML 子集解析（不引入 PyYAML） |
| 前端 | 原生 JS，无框架、无 CDN、无第三方脚本 |
| 测试 | pytest + httpx（ASGITransport） |
| 渲染 | 双模：请求时渲染 **或** 预渲染静态产物 |
| 依赖 | 运行时 3 个；锁文件入仓；CI 跑多 Python 版本矩阵 |

**双模的理由**：静态预渲染便于托管到静态托管服务并获得可缓存与可离线能力；
请求时渲染便于后续扩展交互。两者共用同一份内容与同一套模板，不产生两套事实。

## 4. 内容规范

### 4.1 来源声明（四档）

每条内容必须在 frontmatter 声明 `derivation`：

| 取值 | 含义 |
|---|---|
| `official` | 官方公开物料中的逐字内容 |
| `inferred-from-official` | 由官方物料推理性改写 |
| `private-derived` | 内部材料派生（须绑定内部来源指纹） |
| `original` | 本站原创 |

另标 `claim` 等级（`fact` / `course-claim` / `curated`），
使「课堂主张」不会被误读为公开规范。

### 4.2 内容原子化

单页 500–5000 字符；超出则拆分 + 交叉引用，不硬删内容。

### 4.3 术语规范

- 自造术语首次出现必须紧跟一句大白话（≤40 字）
- 术语表页收录全部自造术语，每条给：定义 + 生活化比喻 + 在本方法中的作用
- 契约测试校验：页内出现的自造术语必须在术语表中有条目

### 4.4 诚实性规范（站上必须常驻）

- 本站与该课程方**无隶属关系、未获授权**，为独立整理
- 本站表格 **≠** 课堂原表
- 明确列出**尚未公开**的环节，不暗示已掌握全部内容
- 练习数据只在本机，不上传；换设备或清缓存会丢，请导出

## 5. 质量门

| 门 | 检查 | 位置 |
|---|---|---|
| G1 | **内容白名单白读**：站内逐字片段必须能在「官方公开物料白名单」中原样回查；内部人名实体做集合差分 + 同音模糊匹配 | 私域侧，发布前 |

**白名单的完整性要求**：官方物料有**三个**信源——公众号推文（原文）、
课程大纲长图、课程海报。后两者是**图片**，必须先 OCR 物化成文本才能进白名单；
只覆盖推文时，官方大纲里的表述会被差分判据当成「内部独有」而误报，
反过来也会让闸门对图片里的内容**完全失明**。

**允许集的纯净性要求**：白名单与蒸馏层合起来是差分判据的**允许集**。
允许集里一旦混入含真实人名的内部原话，那段话就会被差分**豁免**——
原样抄进公开面也不会报警。所以允许集里**不得出现任何中文人名**，
这一条是 G1 的硬门，不是可选的加强项。
| G2 | **结构闸门**：无表单提交、无外部资源引用、frontmatter 契约字段齐全、来源标注自洽 | 公开仓 CI |
| G3 | **契约测试**：同一事实跨页唯一、派生内容有来源指纹、方法版本一致、术语覆盖 | 公开仓 CI |
| G4 | **路由与双模渲染冒烟**：全部页面可达、两种渲染模式均能产出 | 公开仓 CI |

**闸门分工的理由**：G1 需要访问内部语料，只能在内部侧执行；
把敏感实体清单放进公开仓等于发放一份可验证的名单（短中文串的散列可被字典还原），
因此公开仓只承担**与内部信息无关的结构性断言**。

## 6. 发布

- 两段式：内部 staging 逐页人工审 → 一次性 promote 到公开仓（公开仓历史只出现终稿）
- 单一发布入口脚本，执行顺序固定：G1 → G2 → G3 → 生成产物 → 部署
- 提供**急停开关**（触发后整站下线并显示撤回声明页）与撤回声明页
- 指定下线责任人与时限
