# 需求澄清方法论工作台（公开站）· 独立审查

> 审查方法：V 阶段对抗审查（场景 5 创新突破链路，F → V → I → C，**V 门不可裁剪**）。
> 审查范围：内容边界（私域泄漏 / 去品牌化 / 洗白通道）、工程正确性（静默失效 / 双模漂移）、闸门有效性。
> 审查结论：**P0 = 0（全部修复）**，P1 = 8（全部修复），P2 = 5（全部修复），遗留缺口 3 项（见 §六）。
> 共 24 项审查项；其中 R19–R24 来自**第二轮闸门有效性专项审查**（见 §四）。

> ⚠️ 本文件是**公开区**文件（`.trae/specs/` 受版本控制）。
> 它**不得**包含任何私域标识、学员称呼、讲师真名、联系方式、私域台账编号或课堂逐字内容。
> 实测数据、审查记录、语料样本另存于私域目录。

## 一、内容边界审查（本项目最高风险项）

- [x] R1: 站内无课程方品牌标识
  - **Type**: `rule`
  - **Covers**: 验收项「站内文本无课程方品牌标识」
  - **Evidence**: 闸门 2 的 `BRAND_TOKENS` 对全仓扫描；实测 0 命中。
    该断言放在公开仓是安全的——品牌名本身是公开信息，出现在本站才是违规。

- [x] R2: 无逐字转录衍生物
  - **Type**: `rule`
  - **Covers**: spec §2.2「不做逐字稿还原」
  - **Evidence**: 内容层的 `route` 字段只允许 `chaptered-summary`；
    `verbatim-transcription` **不在**批准集内，出现在内容页即构建失败。
    路线决策写进 frontmatter 而非文档——文档会漂移，代码不会。

- [x] R3: 措辞档位与实际来源一致（**防洗白通道**）
  - **Type**: `rule`
  - **Covers**: spec §4.1 四档来源声明
  - **Evidence**: 三张 `private-derived` 表原先写「依据公开说明推导」——
    这是用官方说法给私域内容背书。现改为「由独立整理而成」，
    并由契约测试 `test_source_wording_matches_tier` 锁住：
    措辞与档位不一致即构建失败。

- [x] R4: 「课堂原表」声明在每处表格呈现
  - **Type**: `rule`
  - **Covers**: spec §4.4 诚实性规范
  - **Evidence**: 四张表 + 练习台页 + llms.txt 均含「表格 ≠ 课堂原表」。
    读者会把任何表格当成课程原表——这不是免责声明能解决的。

- [x] R5: 站内无 DayN 课程结构映射
  - **Type**: `rule`
  - **Covers**: 验收项「无 DayN 课程结构映射」
  - **Evidence**: 站内无「DayN / 第 N 天」式结构词；
    概念页按**主题**组织（三问 / 优势 / 成长三角 / 落地 / 陪练），不按课程日程。

- [x] R6: 私域原始材料未进入任何公开面
  - **Type**: `rule`
  - **Covers**: spec §5 闸门 G1
  - **Evidence**: 闸门 1 三层判定（逐字回查 ≥12 字 / 人名实体集合差分 / 同音模糊匹配）
    对**两个公开面**执行：站点仓与 spec 目录。
    禁止集只取私域**原始材料**（ASR + 台账），允许集 = 官方物料 + 私域蒸馏层——
    差分是必需的，否则「真问题」「真目标」这类共有表述会被全判成泄漏。

## 二、工程正确性审查

- [x] R7: 无静默失效（**渲染不报错 ≠ 渲染对了**）
  - **Type**: `rule`
  - **Covers**: spec §7 验收标准
  - **Evidence**: 开发期实测三个静默 bug——base 模板抢占 content 块、
    模板引用模型里不存在的属性、侧栏目录指向不存在的锚点。
    Jinja 对未知属性返回 Undefined，渲染照常成功。
    现已全部改为可复跑的断言（路由可达 / 产物里该有的东西在不在）。

- [x] R8: 动态站与静态站不漂移
  - **Type**: `rule`
  - **Covers**: spec §3 双模
  - **Evidence**: 两者共用同一个 `Renderer`（结构性保证），
    并由 `test_dual_mode.py` **逐页逐字节**比对——不是抽查。
    漂移只在部署之后显形，那时改内容已经晚了。

- [x] R9: 练习器四项阻断性缺陷已修复
  - **Type**: `rule`
  - **Covers**: spec §2.1 互动练习
  - **Evidence**: ① slug 当练习 id 传（定义找不到 ⇒ 静默退出）；
    ② 打印镜像选择器不匹配（打印出空表）；
    ③ 诊断器期望跨表 state 而存储是单页扁平（诊断永远「还差几项」）；
    ④ JS 覆盖 content 层正文（来源标记被丢弃）。
    四项均已修复并逐项做过「注入 → 变红 → 恢复 → 变绿」回退验证。

- [x] R10: 练习数据不出本机
  - **Type**: `rule`
  - **Covers**: spec §2.1 数据自主
  - **Evidence**: 默认只存 sessionStorage；持久化须读者主动开启，
    取消开启时删除旧副本（否则读者以为「记住进度」已关、数据却还在盘上）。
    JS 测试断言无 fetch / XHR / sendBeacon / WebSocket。

- [x] R11: 页面无外部资源依赖（离线可读）
  - **Type**: `rule`
  - **Covers**: spec §2.1 离线可用
  - **Evidence**: 闸门 2 拦「会被浏览器自动加载的站外引用」
    （img/src、link/href、CSS url()、JS URL 字面量、Markdown 图片），
    不拦点击才导航的 `<a href>`；双模测试另对静态产物断言无站外资源。

## 三、闸门有效性审查（闸门本身也会写错）

- [x] R12: 每道闸门都有正样本与负样本
  - **Type**: `rule`
  - **Covers**: spec §5 闸门分工
  - **Evidence**: 闸门 2 的每条规则都有「该报警的报警」与「不该误报的放行」两组用例。
    只写「扫一遍没报错」的测试等于没写——它无法区分「闸门在工作」与「闸门根本没跑」。

- [x] R13: 闸门 1 的误报已压到 0
  - **Type**: `rule`
  - **Covers**: spec §5 G1
  - **Evidence**: 早期版本按「私域有 ⇒ 泄漏」判定，实测误报 30+ 条，
    包含「真问题能举出最近两周」这类方法论本身。
    改为允许集差分后降至 0；归一化只保留中文与数字
    （保留拉丁字母会让代码标识符两边都出现 ⇒ 再误报 30+ 条）。

- [x] R14: 闸门覆盖**所有**公开面
  - **Type**: `rule`
  - **Covers**: spec §5 G1
  - **Evidence**: 本轮实测发现闸门 1 只扫站点仓，漏掉 spec 目录——
    而 spec 目录受父仓版本控制，同样是公开面。
    实际漏过一次：spec 的 tasks.md 里写了三个真实学员昵称（站点仓是干净的）。
    现改为双面扫描，并已注入验证「变红 → 恢复 → 变绿」。

- [x] R15: 闸门 2 的「外链」口径按「是否自动加载」判定
  - **Type**: `rule`
  - **Covers**: spec §5 G2
  - **Evidence**: 早先版本用「文件里出现 http 字样」一刀切，
    README 里的本地地址被判成泄漏。
    闸门一旦误报，人就会开始整体忽略它——那时闸门就真的没了。

## 四、第二轮闸门有效性审查（本轮新发现，见下节）

- [x] R19: 允许集不得混入敏感实体（**信任边界不可被静默破坏**）
  - **Type**: `rule`
  - **Covers**: spec §5 G1 的差分判据
  - **Evidence**: 逐字回查做的是「私域 n-gram 减允许集 n-gram」。
    只要某段私域原话**也出现在允许集里**，它就被差分豁免，不再算「私域独有」。
    ⇒ 允许集一旦混进含真实称呼的私域原话，**那段话可以原样抄进公开面，
    闸门却一声不响**。
    实测不是理论风险：含真实称呼的两段私域原话确实被豁免了。
    处置：① 清洗蒸馏层，把真实称呼替换为角色表述；② 加**允许集纯净性硬门**，
    允许集里出现任何中文人名即报错，并报出是哪个文件带进来的。

- [x] R20: 拉丁字母人名对闸门不可见（**归一化把盲区一起带进来了**）
  - **Type**: `rule`
  - **Covers**: spec §5 G1 的实体层
  - **Evidence**: 归一化只保留中文与数字（为了不让代码标识符造成误报），
    后果是**拉丁人名既进不了逐字回查，加进词条也会被归一化静默跳过**。
    实测案例当事人的拉丁写法在私域蒸馏层出现约 20 次，闸门一次都没报过。
    处置：新增一条**绕开归一化**、按词边界匹配的独立通道。

- [x] R21: 敏感实体清单必须**机械可复现**，且逐条有语料实证
  - **Type**: `rule`
  - **Covers**: spec §5 G1 实体层
  - **Evidence**: 上一版清单是手挑的 3 个词条，其中 1 个在私域包里 **0 命中**
    （凭空虚项，却占着一个「已覆盖」的名额），而转写体里的真实称呼
    **一个都没进清单**。手挑清单同时犯了「虚项」与「漏项」两个错，
    而两者都会让人误以为「检测已覆盖到位」——**这比没有闸门更危险**。
    处置：① 改为「机械推导 + 人工裁决」，推导器与漂移比对在私域侧；
    ② 加不变式「清单里每个词条都必须在语料里实证存在」；
    ③ 与常用词同形的改收**带称呼形态**（单字名尤其重要——单字是「智慧 / 欣赏 /
    宁静」的子串，公开面各能命中几十次）。

- [x] R22: 同音层的误报排除词不能是**单字**
  - **Type**: `rule`
  - **Covers**: spec §5 G1 第三层
  - **Evidence**: 旧方案用「点/分/时」这类单字做窗口排除，
    结果公开面一句「提到了道九的观点」里，「观点」的「点」把命中整个干掉
    ⇒ 必过夹具实测**六个变体一个都没拦住**（漏检 100%）。
    改为「变体 + **紧邻**的称呼后缀」：语料里的真实形态 100% 是「某老师 / 某哥」，
    而常见假阳性（知道就是、观点）都不带紧邻称呼。

- [x] R23: 官方物料白名单要覆盖**全部**官方信源（含图片）
  - **Type**: `rule`
  - **Covers**: spec §5 G1 白名单
  - **Evidence**: 白名单此前只覆盖公众号推文，而大纲长图与课程海报是**图片**，
    差分判据对图片内容无效。已 OCR 物化两份图片并纳入允许集。
    海报的 OCR 还解开了一个悬案：一个方法论核心术语在两场转写里 **0 命中**，
    其官方出处就在海报上——**不是转写漏了，是它本来就不出自转写**。

- [x] R24: 闸门自身的有效性要有**自测**，不能只靠「现在恰好是干净的」
  - **Type**: `rule`
  - **Covers**: spec §5 G1
  - **Evidence**: 新增的允许集纯净性检查若遍历写错或正则写错，会**永远绿**。
    所以必过夹具里加了一条「注入污染后纯净性检查必须报红」的自测；
    另加一条反向测试：常用词**不得**被误报——
    误报一次的闸门，开发者就会开始整体忽略它，那时闸门就真的没了。

## 五、发布链路审查

- [x] R16: 闸门顺序不可裁剪
  - **Type**: `rule`
  - **Covers**: spec §6 发布
  - **Evidence**: 单一入口 `release.py`，顺序写死在脚本里：
    G1 → G2 → G3 → 构建 staging → 人工审 → promote。
    顺序错了闸门就白设：先上线再跑闸门，闸门只能事后补救。

- [x] R17: 下线是可验证的状态，不是口头约定
  - **Type**: `rule`
  - **Covers**: spec §6 急停开关
  - **Evidence**: `_disabled` 标记随产物上线，页面据此显示下线声明；
    `withdraw` / `disable` 两个动作分别对应「撤回」与「急停」。

- [x] R18: 下线责任人与时限已写入契约
  - **Type**: `rule`
  - **Covers**: spec §6
  - **Evidence**: `AGENTS.md` 的发布纪律节写明责任人与 T+0 / T+1 时限。
    「收到异议就下线」若没有责任人与时限，三个月后就变成「有人提过但没人管」。

## 六、遗留缺口（不影响当前发布，但不得当成已完成）

| 缺口 | 影响 | 补齐方式 |
|------|------|---------|
| G1 在独立仓库 CI 里显式跳过 | 差分判据需要私域语料，单独检出仓库时拿不到 | 本地发布链路跑 G1；CI 里打印跳过原因，不假装通过 |
| 私域案例页仍含案例当事人的拉丁写法 | 约 20 处；这些页面不发布，但若整段引用进公开面，需先替换 | 闸门已能拦「公开面出现该写法」；蒸馏层替换需改文件名与站内链接，留作后续项 |
| 常用词判据语料依赖 | 基线能筛掉同形候选，但基线里没出现的常用词需人工判定 | 人工判定结果登记在私域排除表；新增词条时重跑漂移比对 |
