## 6. 方法论结论（G3 可迁移教训）

1. **"上溯一手"在能拿到全量时必须上溯到全量**：R 阶段已按信源先行原则从博文上溯到原仓，但受工具输出截断只抽样了 5 章；用户指认本地克隆后，全书机械核对把"高可信"升级为"可复现审计"。教训：转化工作区若存在完整克隆，全量结构统计（条目数求和/计数闭合）应在 R 阶段默认执行，而非等评审后补。
2. **核验发现"差异"时必须区分"原书错"与"我读得不全"**：F-078 是验证轴错配——法规核验代理用权威源证明了"正确条款是什么"，但"原书写了什么"必须回到原书**全文**才能判定；截断预览 + 权威核验的组合会产生"原书错误"的假阳性。定谳原书错误前，原文全文是必要证据。
3. **诚实更正是可信度资产**：把己方误归从 5 处"原书勘误"中摘出、五处留痕改判，不降低反而提高 bundle 的可信度——verification.md 的账本同时包含"原书的 3 处问题"和"本包的 1 处自我更正"。
4. **机器可数的总量声明优先于转述计数**：615 条的最强证据不是任何文章或 README 文字，而是 33 个文件中 `### N.` 标记求和=615；对结构规整的开源文本，总量类事实应尽量建立独立机器统计。
5. **审计通道与读者事实源分开声明**：本地克隆路径是工作区工件（读者未必有），bundle 正文只把它登记为"审计通道"，读者侧可回溯事实仍指向 GitHub 原仓与公开权威源——防止把私有环境路径误当公共信源。
