## 核心论点（全部为【观点】——作者方法论主张）

| 编号 | 分类 | 事实内容 |
|------|------|---------|
| F-003 | 【观点】 | 核心论点：赚不到钱的人问题几乎不在能力上，而在顺序上——把赚钱的顺序从一开始就搞反了 |
| F-004 | 【观点】 | 作者描述的典型错误路径：想赚钱第一步闷头做产品，花三个月做出来挂到网上等，没人搭理；"不是产品不好，是压根没人需要" |
| F-005 | 【观点】 | 正确顺序主张：真正赚到钱的人第一步是"找买家"而非"做产品"；错误顺序"做→卖→等反馈"，正确顺序"卖→验证→再做" |
| F-006 | 【陈述】 | 作者引述：查理·芒格引用数学家雅各比的话——"反过来想，永远反过来想。" |
| F-007 | 【观点】 | 需求发现论：需求不需要发明只需要发现；能想到的需求几乎都已被验证过；真正稀缺的不是"发现新需求"，而是"发现一个已经被验证、但还没被满足好的需求" |
| F-008 | 【陈述】 | 作者援引："哈佛商学院的高级讲师 Lou Shipley"专门研究该问题，指出创始人应专注于在投入时间和资源构建产品之前先把它卖出去；典型"先做后卖"顺序往往导致失败（头衔为博文口径，核验见 F-031） |
| F-009 | 【观点】 | 作者自述的看项目方法：第一眼不看产品漂亮与否，看三问——谁需要它？为什么现在需要？已经有人为它付过钱了吗？ |

## 一周验证法（博文方案，F-018~F-026）

| 编号 | 分类 | 事实内容 |
|------|------|---------|
| F-018 | 【陈述】 | 方案承诺：一周可执行；不需要特殊技能、不需要投钱、不需要粉丝 |
| F-019 | 【陈述】 | 第 1 天：在小红书、闲鱼、抖音搜"模板、教程、指南、避坑、清单"；重点看三五千粉丝但橱窗已售几千单的小账号；把能做的方向至少记三个 |
| F-020 | 【陈述】 | 第 2 天：选一个方向发"测试内容"（"大部分人不知道的XX技巧"/"关于XX我踩过的三个坑"），发小红书/朋友圈/知乎；不看点赞，只看有没有人来问"这个怎么做/还有吗"，没有就换方向 |
| F-021 | 【陈述】 | 第 3 天：做"最小产品"——一个三五页的 PDF，写清问题是什么、怎么解决、踩过什么坑；用 WPS 或飞书文档排版导出 PDF；两小时以内完成 |
| F-022 | 【陈述】 | 第 4 天：挂出去标价（9 块 9、19 块 9 都行），不要免费（"免费的东西没人认真看，你也不会认真做"）；挂闲鱼、小红书、朋友圈，写清是什么、解决什么问题、适合谁 |
| F-023 | 【陈述】 | 第 5 天：写三篇"搜索型内容"——用户本来就会搜的问题（例："应届生简历最容易犯的三个错""夜景怎么拍才不糊"）；内容不会爆但每天有人搜，搜到的人顺手买产品 |
| F-024 | 【陈述】 | 第 6 天：看数据做判断——有没有人买、有没有人问、有没有人问"能不能再详细一点"；没人买就调方向或调标题描述；"真实反馈比空想一百遍都管用" |
| F-025 | 【陈述】 | 第 7 天：迭代或换方向——有人买就优化（更新案例、改标题、加问答）；没人买就换方向从第 1 天重来；"试错的成本比你想象的低得多" |
| F-026 | 【观点】 | 方案中的判断信条集合：小账号能卖动说明"需求是真的、门槛是不高的"；不需要追热点拍段子，老老实实回答问题旁边放产品；大多数人的失败"不是败在能力上，是败在顺序上" |
