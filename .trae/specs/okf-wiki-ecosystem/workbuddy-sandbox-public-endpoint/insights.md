# I 阶段：核心洞察

## 洞察 1：可验证的是“公网 HTTPS 能力”，不是博文化名的完整内部链路

- **陈述**：WorkBuddy/CloudStudio 相关环境能够承载公网可访问的 HTTPS 页面，但博文给出的 `CLB → sandbox-proxy` 只能视为二手实现描述。
- **证据**：腾讯云 WMA 官方文档确认 Runtime 具备“端口转发”能力（F-031）；三个 `*.agentos-app.net` 实时 URL 均返回 HTTPS 200（F-034）；响应头统一显示 `Server: CloudStudio Gateway`（F-035）；公开检索未找到 `sh1.agentos-app.net`、`sandbox-proxy` 的官方说明（F-037/F-038）。
- **反常识**：能打开页面并不自动证明文章描述的每个网络组件都准确；边缘响应头比架构叙述更适合作为事实锚点。
- **行动**：bundle 正文将“能力事实”“可观测网关”“博文推测的内部链路”三层分开写，提示词中不硬编码域名后缀。

## 洞察 2：这是操作提示，不是可直接入 examples/ 的可复现实验

- **陈述**：文章提供了有价值的使用方向，但不满足 OKF 博文转化模式对 `examples/` 的两问判据。
- **证据**：博文只有 `:3000`、泛化的 Node/Python/Java/静态服务器描述和通用 `nohup` 命令（F-006/F-011/F-015/F-016），缺少产品版本、可运行服务代码、端口发现路径、请求输出和回收时长；域名后缀还在 2026-09-15 转载稿中变为 `app.workbuddy.host`（F-036）。
- **反常识**：技术主题不等于可演练教程；把粗提示包装成 example 会制造“照做必通”的虚假确定性。
- **行动**：不设 `examples/`，将内容组织为机制、场景、生命周期三篇概念文档，并把操作建议限定为“以实际沙箱面板为准”。

## 洞察 3：“免费服务器”的真正决策边界是工作负载生命周期

- **陈述**：该能力最适合短生命周期 Demo、静态页和临时联调，不应因“公网 HTTPS 可用”而替代生产运行时。
- **证据**：博文自身也提示沙箱活着服务才活着、不要放机密和长期数据、7×24 应使用云服务器或容器（F-018~F-020）；官方 WMA 则是另一种企业托管形态，具备 7×24、自动休眠/恢复、数据持久化、跨节点恢复等能力（F-030/F-031/F-039）。
- **反常识**：临时端点“回收即失效”既是安全便利，也是不可用于生产的原因；同一特性在 Demo 和生产场景中的价值方向相反。
- **行动**：用场景矩阵明确“可用/谨慎/不适用”，将保活命令标注为延缓会话退出的通用技巧而非 SLA 保障。
