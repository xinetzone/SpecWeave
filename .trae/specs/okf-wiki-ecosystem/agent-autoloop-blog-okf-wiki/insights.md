## 二、5 项洞察（四元组：陈述 / 证据 / 反常识 / 行动）

### 洞察 1：内核的价值不在「能做什么」，而在「被禁止做什么」

- **陈述**：Autoloop 的确定性来自一组显式禁令（不联网、不读系统时钟、不用随机数、不写死产品名、只做四件事），而非功能清单。
- **证据**：F-011、F-012、F-015、F-016、F-058。
- **反常识**：中台类项目常以「支持多少能力」为卖点；这里的核心设计动作是做减法，并用自动化测试把禁令固化（F-016）。确定性不是测出来的，是被约束出来的——「给它同一个事件、同一套规则、同一个初始状态，结果都一样」是约束的推论，不是调优的结果。
- **行动**：设计编排层时先写「禁止清单」并加守护测试；任何需要联网、时钟、随机或具体产品名的能力一律外移到插件。

### 洞察 2：把「等待人」建模成持久化状态而非运行中的进程，长流程才可能零成本

- **陈述**：挂起零消耗的本质是把「等待审批」从进程状态迁移为日志/数据库中的可恢复状态，Agent 进程直接退出。
- **证据**：F-021、F-024、F-025、F-057。
- **反常识**：直觉上「让 Agent 保持在线、每隔几分钟问一次回复」最省事，但那意味着轮询常驻与 Token 常驻。借用审批/订单长流程的「存档—读档」模型后，等待三天与等待三分钟成本几乎相同。成本不是被优化掉的，是被状态建模消掉的；官方口径还保留「只有很轻的中台在后台等着」这一残余成本（F-057），比博文的「一分钱不花」更精确。
- **行动**：任何超过分钟级的人工介入点，都按「退出 + 存档 + 事件唤醒」设计，而不是「保持会话 + 轮询」。

### 洞察 3：事件溯源与指令数据分离，是同一条原则的两个投影

- **陈述**：两者共同点是把「不可信/不可变的东西」与「决策逻辑」隔离：前者隔离时间（状态由只追加日志推算，不改历史），后者隔离内容（外部文字降级为资料，不进指令）。
- **证据**：F-025、F-026、F-029、F-030、F-057、F-058。
- **反常识**：它们常被当作两个不相干特性（一个防丢数据、一个防注入）。实际上都是「决策只依赖本机可信规则 + 只追加事实」这一条约束的推论；也正因决策面收得足够窄，内核才能不写死产品名、不联网。官方把事件里携带 `cwd`/`agent`/`access` 字段直接拒收（F-057），是这条原则落到输入校验层的具体形态。
- **行动**：把「什么能进入决策」做成单一入口校验，而不是在每个功能点分别防注入；外部文本一律以文件路径传递，提示词里只留校验过的类型、编号与链接。

### 洞察 4：TTL 式跳数熔断是「Agent 互唤」这类无中心循环的必要兜底

- **陈述**：跳数熔断把每次「Agent 叫醒下一个 Agent」记为不可清零的一层，超过 8 层只记录、不再派活并发卡片（F-031、F-057）。
- **证据**：F-031、F-032、F-057。
- **反常识**：常见做法是「限制单轮次数」或「检测重复内容」；前者被跨会话绕过，后者需要语义判断且可能误杀。借用网络包 TTL 后，用纯结构计数并让层数经过人工提问与定时复查仍不清零、Agent 自身改不了，才防得住 A→B→A 的分布式循环。作者此前把 Codex 审 Claude 代码限制在 3 轮（F-032），是同一问题在两 Agent 场景下的局部版本。
- **行动**：多 Agent 互唤系统里把「跳数」作为随事件传递的元数据，禁止执行方修改，并把超限处理设计为「只记录 + 通知人」而非静默丢弃。

### 洞察 5：博文与官方 README 的「口径差」，本身是这类教程最该教的内容

- **陈述**：同一作者、相隔两天的两个文本，在性能数字、可靠性边界、平台支持、Agent 支持范围与合规提示上存在系统性差异。
- **证据**：F-013/F-061（1600 行 → 约 1650 行、1.5ms → p99 1.82ms）、F-026/F-057（「断电也不丢」→「整机断电没有单独测过」）、F-035/F-054/F-055（「装好就能直接用」→ 官方标注「还没有逐个跑过」）、F-045（Windows 待定）、F-064（订阅额度与 API Key 合规）、F-068（`deliver-review` 未在 README 列出）。
- **反常识**：读者通常把「作者自己写的官方 README」当作博文的等价复述。实际上 README 补上了测试环境、p99 口径、未测边界、未验证的接入命令与用量合规提示——这些恰恰是博文最有传播力、也最需要打折的部分。
- **行动**：从二手内容转知识库时，把「官方一手文档」设为必查项而非可选项；差异不是噪音，是可信度分级的主要信号。该判据可迁移到一切「二手内容 → 可信知识库」转化任务（G3 可迁移性验证）。
