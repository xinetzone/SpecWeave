# I 阶段洞察（F 阶段第一性原理 → I 阶段洞察）

> 每条洞察必须四元组齐全，且**观察**部分只引用 F 编号事实、**机制**为推断并显式标注「洞察/推断」、**可迁移条件**与**反例边界**共同构成 G3「模式可迁移」门的判据。
> 作者本人的因果分析（F-058）属**待检验的作者洞察**，不因写在博文里就升级为事实。

## 洞察 1：验收定义是长程 Agent 任务的控制面，而非文档副产品

- **观察**：作者不先让模型写代码，而先要「交给任何一个 Agent 都能照着做完」的文档（F-045）；两份文档把验证拆成模拟器 S1–S11、真机 R1–R7、任务 T0.1–T9.2、交付定义 9 项（F-077/F-078）；验收记录显示 S4/S7/S8/S9 四项是「通过（修复后）」，并登记 9 个自修问题（F-079）。
- **机制（洞察/推断）**：把「什么叫做完」外化为可观察的通过条件后，Agent 获得了**终止判据与自检信号**；没有验收定义时，模型只能以「代码写完了」为终止条件，边界 bug 就不会进入反馈回路。博文「别跟它聊需求，跟它定验收」（F-059）是这一机制的口语表达。
- **可迁移条件**：① 任务可拆出可观察的输入/输出或状态变化；② 存在不被本次改动破坏的回归基线（本例为 Mac 186 个测试，F-053/F-079）；③ 能区分「可自动验」与「必须人/真机验」并允许后者显式留白。
- **反例/边界**：需求本身尚未定型、探索性研究、以审美/主观偏好为交付目标的任务，强行写死 S/R 只会把不确定性伪装成确定；本例的 R3–R6 至今「待真机」（F-080），说明验收定义**不等于**验收完成。

## 洞察 2：「6 小时」的隐藏前提是产品形态已确定，不是模型能力的独立证据

- **观察**：作者自己把顺利归因于「Kimi 强模型加持」**加上**「我们的产品形态是确定的」（F-058）；官方 README 显示 Mac/Windows 已跑通、iOS 复用 `WeChatBridgeCore`（F-065/F-067）；提示词①明确「iOS 要复用它，不要另写一套」（F-046）；档期按 1 人全职估 18 个工作日（F-050/F-078）。
- **机制（洞察/推断）**：可复用核心 + 已验证的产品语义，把搜索空间从「设计产品」压缩到「移植与验收」，Agent 的长程执行才稳定。6 小时（F-039/F-055）是**净运行时长口径**，18 工作日是**含真机验收与缓冲的全职档期口径**，二者不是同一工作量的分子分母。
- **可迁移条件**：存在可复用核心、明确的不做清单（官方 §12 共 14 项，F-077）、以及人可审阅的规格文档。
- **反例/边界**：从零定义新产品、无回归基线、需求需与用户反复澄清时，同一套提示词不会复现 6 小时；官方验收记录日期跨 10-23 与 10-24（F-079/F-080），也说明「一个下午加一个晚上」是叙事化表达（F-055），不是可审计的工时数据。

## 洞察 3：二手产品文的「完成态」必须以仓库一手件收窄

- **观察**：博文称 iOS「开发完成」「正在提审、还没上架」（F-009/F-010）与「灵动岛小入口」（F-019）；官方 README 同期仍写「iOS 版正在开发中」且路线图 `[ ] iOS 版`（F-065/F-066），dev-spec §12 明列「灵动岛」不在 v1（F-077），验收记录 R3–R6「待真机」（F-080）。
- **机制（洞察/推断）**：营销/发布文案描述**作者期望的状态**，仓库文档描述**当前可验证的状态**；后者通常滞后但可追溯（有日期、编号、提交 SHA），因此当二者冲突时应以仓库为准，并把差异作为「时点 + 口径」登记而非替作者"改正"。
- **可迁移条件**：项目开源、文档入库、有路线图或验收记录等状态件。
- **反例/边界**：闭源产品无一手件可查，此时只能标「仅博文单源」；也不能反过来假定 README 永远更"真"——它同样可能未及时更新，故结论须写成「截至核验时点的官方口径」并设 `stale_after`。

## 洞察 4：成效数字的错误大多不是造假，而是三轴口径缺失

- **观察**：1.7k star（F-006，发文时点）vs 2024（F-063，核验时点）；6 小时（F-039）vs 18 工作日（F-050/F-078）；10-27 称「国产开源模型」（F-037）vs 权重 11-04 才公开（F-081）；「有点贵」（F-061）vs 第三方「便宜约 80%」（F-084）。
- **机制（洞察/推断）**：数字失真集中在**时间轴**（取值时点）、**主体轴**（谁统计/谁体验）、**定义轴**（净运行时长 vs 全职档期、承诺开源 vs 权重开放、绝对价格 vs 相对价格）三处。去掉任一轴的限定词，读者就会把两个不可比数字读成因果或倍数。
- **可迁移条件**：任何跨时点、跨主体的二手内容 → 可信知识库转化；落到操作上即「勘误四张清单」（日期/版本、成效溯源、口径对照、引文逐字）。
- **反例/边界**：不带时点的定性描述不适用；也不得因发现口径差异就推断作者造假——官方验收记录反而印证了「自修 bug」「186 测试」「图文合一 PDF」等多数技术叙述（F-079/F-080）。
