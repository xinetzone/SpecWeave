## P1 选核验事实

| F编号 | 声明内容 | 博文口径 | 核验等级 |

| F-010 | 日常并行 2-3 个产品项目，每个项目多 worktree 多任务 | "我日常通常会有 2-3 个产品项目并行来做，然后每个产品项目中，又会开多个目录/worktree 来做多个任务" | 作者实践描述，无需独立核验 |
| F-011 | code review 时并行启动 3 个 sub-agent 各负责一个角度 | "在 code review 时，并行启动 3 个 sub agent，每个 agent 针对一个特定角度来进行 review" | 作者实践描述 |
| F-012 | MR 范围膨胀问题：500 行改动经多轮迭代膨胀至 2000+ 行 | "一开始仅仅是 500 行不到的代码改动，随着问题的提出、修复，多轮迭代之后，处理的 scope 越来越大，膨胀到 2000 多行" | 作者实践观察，无需独立核验 |
| F-013 | 单个代码文件不超过 500 行的 lint 规则 | "最简单的比如，单个代码文件不要超过 500 行" | 作者实践设定，软约束 |
| F-014 | 每个任务控制在 500 行改动以内 | "每个任务的大小，还是像之前一样，控制在 500 行改动以内" | 作者实践设定 |
| F-015 | 使用 Codex + gpt-5.5，自动压缩功能非常强大 | "一定要用 Codex + gpt-5.5，自动压缩非常强大，几乎可以当成无限 session 来使用" | 作者主观评价 |
