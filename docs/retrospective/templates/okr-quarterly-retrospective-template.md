# OKR 季度复盘模板

> **适用周期**：季度（Q1–Q4）；填写时机为**下一周期第一周**。
> **复盘对象**：个人 / 团队。
> **内容级别提醒**：本模板为通用方法论，可入库 `docs/`；但填入的真实 O / KR / 结果数据属**私域内容**，承载文档建议落在 `playground/` 并在 frontmatter 标注 `type: private`，避免个人或内部数据进入公开文档中心。

## 0. 六步总览（模板骨架）

本模板把 OKR 复盘的标准四段（数据分析 → 归因 → 经验沉淀 → 改进落地）与七概念链对齐：**R=数据分析，I=归因，E=经验沉淀，V=自评偏差攻击，A=行动拆分，C=归档提交**。

| 步骤 | 七概念 | 核心动作 | 产出物 | 质量门 |
|:---:|:---:|------|------|:---:|
| 1 | R 复盘 | 采集客观评分与执行事实 | 事实清单（≥20 条，无因果词） | G1 |
| 2 | I 洞察 | 高分/低分归因、提炼四元组 | 3 条洞察（陈述/证据/反常识/行动） | G2 |
| 3 | E 萃取 | 提炼可迁移经验模式 | 1–2 个模式（触发/步骤/反模式/迁移） | G3 |
| 4 | V 对抗审查 | 攻击自评偏差（可选，个人复盘建议执行） | 偏差攻击记录 + 修正 | V 门 |
| 5 | A 原子化 | 下季度行动项拆分 | 行动项（单一职责、可独立验证） | G4 |
| 6 | C 原子提交 | 归档、索引更新、原子提交 | 归档记录 + 提交哈希 | — |

> **最小闭环不可裁剪**：R→I→C（事实→洞察→行动）。V 阶段在 `depth=quick` 时可跳过，但个人自评场景强烈建议保留——自评最易受确认偏误与自我美化影响。

### 1.4 OKR 评分标准（引用知识包）

| 分数 | 说明 |
|:---:|------|
| 0 | 完全没有进展 |
| 0.3 | 进展很小，远未达到目标 |
| 0.5 | 完成了一半左右 |
| 0.7 | 接近目标，略有差距（**理想状态**） |
| 1.0 | 完全达成目标 |

> **解读基线**：0.6–0.7 表示不错的表现（OKR 要求激进，未完全达成仍推动进步）；**0.4 分以下不代表失败**，其价值在于暴露问题与优先级。分析重点是"为什么"而非分数本身。

#### 进阶口径一：三维加权评分（可选）

> 当单纯"完成度"无法反映真实价值时（典型如"完成率虚高、实则目标设定过保守"），改用三维加权评分。

| 维度 | 权重 | 说明 |
|------|:---:|------|
| 完成度 | 50% | 实际完成情况 |
| 挑战性 | 30% | 目标的挑战程度 |
| 影响度 | 20% | 对团队/业务的影响 |

综合评分 = 完成度 × 0.5 + 挑战性 × 0.3 + 影响度 × 0.2

#### 进阶口径二：等级制（简化）

| 等级 | 分数 | 说明 |
|:---:|:---:|------|
| S | 0.9–1.0 | 超出预期，表现卓越 |
| A | 0.7–0.8 | 符合预期，表现优秀 |
| B | 0.5–0.6 | 部分完成，表现一般 |
| C | 0.3–0.4 | 进展较小，需要改进 |
| D | 0–0.2 | 未完成，需重新审视 |

### G1 质量门检查

- [ ] 事实数量 ≥ 20 条
- [ ] 无"因为/所以/导致/失误"等因果或判断词
- [ ] 每条事实可追溯来源（数字、记录、链接）
- [ ] 关键数据（目标值/实际值/日期）完整无遗漏

> **不合格处理**：返回重写，剥离全部判断与推断。

### G3 质量门检查

- [ ] 触发场景同时写明"适用于"与"不适用于"边界
- [ ] 核心做法 3–7 个具体步骤，可直接执行
- [ ] 反模式 ≥3 个，且均来自本次真实教训

> **不合格处理**：返回提升抽象层级，或按"模式成熟度"如实降级标注。

## 步骤 4 · V 阶段：对抗审查（可选，个人复盘强烈建议）

> 个人自评最大风险是**确认偏误与自我美化**。用四视角攻击已产出的洞察与模式：

| 视角 | 攻击问题 |
|------|------|
| 🔴 魔鬼代言人 | 高分是真本事还是运气/目标过低？低分归因是否甩锅外部？证据是否只挑支持性事实（幸存者偏差）？ |
| 🟢 新人视角 | 下季度换一个人，按此模式能否复用？前置条件交代清楚了吗？第一步该做什么明确吗？ |
| 🟠 老板视角 | 投入产出比如何？这些行动项真能改变 Q4 结果吗？不做会怎样（机会成本）？ |
| 🔵 未来视角 | 一年后回看，今天的结论还成立吗？是否是过渡形态？二阶效应是什么？ |

**OKR 常见误区速查（攻击素材，逐条自问是否踩中）**

| 组别 | 误区 | 错误示例 → 正确示例 |
|------|------|------|
| 目标设定 | 目标模糊化 | "提升用户体验" → "提升移动端用户支付体验" |
| 目标设定 | 目标任务化 | "完成 3 篇推文" → "打造爆款内容体系" |
| 目标设定 | 目标过多 | 10 个以上 → 3–5 个 |
| 目标设定 | 目标太保守 | 完成率常年 100% → 60%–70% 为优 |
| KR 设定 | KR 活动化 | "每周发 3 篇" → "线索量增长 40%" |
| KR 设定 | KR 不可量化 | "提升满意度" → "满意度 80 → 90 分" |
| KR 设定 | KR 数量过多 | 8 个以上 → 3–5 个 |
| KR 设定 | KR 与 O 无关 | O 谈体验、KR 谈招聘 → KR 直接支撑 O |
| 执行 | 与绩效强绑 | 分数直接定奖金 → 解耦，分数仅作参考 |
| 执行 | 忽视对齐 | 目标脱节成"部门墙" → 定期对齐会议 |
| 执行 | 缺乏复盘 | 定完目标就不管 → 建立周/月/季度复盘机制 |
| 执行 | 目标一成不变 | 季度中从不调整 → 随实际情况动态调整 |

> **绩效解耦提醒**：OKR 分数低 ≠ 绩效差（OKR 之外的工作可能超出预期）；OKR 分数高 ≠ 绩效好（若源于目标难度过低）。个人复盘时既不要因低分自我否定，也要警惕"高完成率"背后的保守设定。

### V 门检查

- [ ] 四视角全部覆盖
- [ ] 审查意见 ≥5 条，且均为具体攻击点
- [ ] 至少采纳 2 条意见并修正原洞察/模式
- [ ] 未出现"完成得很好"类表演式结论
