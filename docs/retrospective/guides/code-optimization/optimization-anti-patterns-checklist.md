# 🚫 代码优化反模式 Checklist（可打印版）

> **使用方法**：打印出来贴在显示器旁，每次做优化前过一遍
> **更新日期**：2026-07-31

---

## ⚠️ 7大致命反模式（不要这么做！）

|  | 反模式 | 危险信号 | 正确做法 |
|--|--------|---------|---------|
| ☐ | **不建基线直接优化** | "感觉这个比较慢，改一下试试" | ✅ 先跑benchmark记数字，保留原有代码路径 |
| ☐ | **一次性改所有调用点** | PR里改了10+文件，说"都改好了" | ✅ 每个PR≤3个文件，逐步迁移 |
| ☐ | **没有回退开关** | 优化代码直接替换旧代码，没有if包裹 | ✅ 编译期+运行期双开关，加完立即演练 |
| ☐ | **隐式修改原有API语义** | 悄悄在non-const方法里加COW/锁逻辑 | ✅ 新增显式方法，旧方法语义不变 |
| ☐ | **只写文档不写脚本** | 环境问题只写在README/Troubleshooting里 | ✅ 构建前预检脚本，主动检测+明确修复建议 |
| ☐ | **过度设计重复造轮子** | 自定义内存池/引用计数/锁机制 | ✅ 先看框架/STL已有机制，能复用就复用 |
| ☐ | **不做回退演练** | 开关写好了但从没试过关闭 | ✅ 加完开关立即测试关闭路径，验证回退有效 |

## ✅ 优化前检查（开始写代码前过一遍）

|  | 检查项 |
|--|--------|
| ☐ | 我有profile数据证明这是瓶颈吗？ |
| ☐ | 优化目标能量化吗？（从___ms降到___ms） |
| ☐ | 原有代码路径保留了吗？ |
| ☐ | 编译期开关设计好了吗？ |
| ☐ | 运行期开关设计好了吗？ |
| ☐ | Phase 1场景有数学证明等价吗？ |

## ✅ 提交前检查（PR/MR前过一遍）

|  | 检查项 |
|--|--------|
| ☐ | 单元测试覆盖正常路径了吗？ |
| ☐ | 单元测试覆盖边界case了吗？（空输入/巨型输入/并发） |
| ☐ | 测试代码是实现代码的2-3倍吗？ |
| ☐ | 关闭编译期开关，测试通过吗？（回退演练） |
| ☐ | 设置运行期环境变量禁用，测试通过吗？ |
| ☐ | PERF日志显示确实变快了吗？ |
| ☐ | PR改动文件≤3个吗？ |
| ☐ | 没有过度设计吗？（框架已有机制优先复用） |
| ☐ | API变更都是显式的吗？（没有悄悄改语义） |
| ☐ | Windows PATH长度检测加了吗？（Windows项目） |

## 🔑 5个核心洞察（记住这些少走弯路）

1. **复用框架机制**：零拷贝不需要自定义内存池，框架的智能指针已经是引用计数的
2. **const正确性是零成本的**：C++ const/non-const重载区分读写，不需要运行时标记
3. **显式优于隐式**：新增`mutable_data()`比修改原有`data()`更安全
4. **脚本>文档**：环境问题写预检脚本，不要只写在wiki里
5. **Windows PATH 32KB限制**：Windows项目预检必须加PATH长度检测

## 📏 优化策略选择速查

| 场景 | 推荐策略 |
|------|---------|
| 改内存所有权/共享/并发/FFI | 🟢 分层渐进优化（必须双开关） |
| 某个函数占80%耗时且逻辑独立 | 🟡 瓶颈优先（benchmark对比） |
| 线上紧急性能问题 | 🔵 保守补丁（先止血，事后重构） |
| 技术栈整体升级（Python2→3） | 🔴 一次性重写（⚠️必须有灰度+回退） |
| 不确定要不要优化 | ⏸️ 先做Phase 0基线测量 |
