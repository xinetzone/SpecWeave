# 版本差异判别（Version-Discrepancy Arbitration）

## 触发场景

同一实体（书/人/机构/版本）在多个文件中出现**不同署名、年份或卷数**，特别是：

- 含版本源流、译本清单、勘误史的书目类知识包
- 一致性审查（如统一译名/统一年份）与"保留历史差异"发生冲突时
- 调研代理并行采信了不同信源，汇合后发现同实体多值

**不适用**：单文件仅一处引用、且无权威信源可查时——应直接标【待核验】，不强行裁决。

## 核心步骤

### 步骤1：收集全部出现值与上下文

1. 全库检索该实体的所有写法/取值，记录每处出现的文件与语境
2. 区分"署名差异/年份差异/卷数差异"等差异类型
3. **产出**：多值清单（值 × 出现位置 × 语境）

### 步骤2：权威信源核验

1. 按权威度排序选取核验源：作者官方页 > 馆藏目录（如北大图书馆页）> 出版社登记 > 权威数据库
2. 禁用论坛帖、二手书城页面等低可信源作为裁决依据
3. **产出**：核验记录（核验源 URL + 各版本实际取值）

### 步骤3：判别分支

```
核验结果如何？
├─ 确属真实版本差异（各版本取值本来就不同）→ 步骤3a：分版表述
└─ 属转录/用字歧义（同一版本被写错/写异）→ 步骤3b：全库统一
```

### 步骤3a：分版表述

1. 按版本逐一列出取值（如《房内考》1990 版署「郭小惠」、2007 版署「郭晓惠」）
2. 每个版本值均给出来源锚点
3. 在事实登记（facts）中注明"两版用字本不同，非转录错误"

### 步骤3b：全库统一

1. 确定唯一权威写法
2. 全库替换，复查各旧变体零残留
3. 在事实登记（facts）中记录裁决依据（哪个信源、为何采信）

### 步骤4：裁定依据回写

1. 无论分版还是统一，均将裁定依据写入 facts 供追溯
2. 无权威信源可查的多值实体标注【待核验】，纳入增量核验清单
3. **产出**：每个多值实体都有"分版 or 统一 + 依据"的明确记录

## 反模式

| 反模式 | 后果 | 正确做法 |
|--------|------|---------|
| 默认"统一成最常见写法" | 抹掉真实版本差异，引入错误 | 先权威核验再判别，版本真实差异必须分版 |
| 默认"保留所有说法"不设权威裁决 | 库内同实体互相矛盾，读者无所适从 | 核验后分版或统一，均有明确依据 |
| 核验来源不权威（论坛/二手书城页面） | 用低可信源裁决高可信分歧 | 按权威度排序选取核验源 |

## 检验标准

- 每个多值实体都有"分版 or 统一 + 依据"的明确记录
- 同实体在各文件不再互相矛盾（分版场景下矛盾已转化为结构化版本对照）
- 裁定依据可在 facts 中追溯到核验源 URL

## 迁移验证

- ✅ 性学经典 OKF 知识包：《房内考》"郭小惠 vs 郭晓惠"经李零北京大学官方个人页核验为两版本署名本不同，采用分版表述修复（F-ANCIENT-027）
- 🔄 可迁移到：软件版本矩阵、跨库命名对齐、多语言译名统一等场景
