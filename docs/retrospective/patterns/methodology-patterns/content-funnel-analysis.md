# 内容漏斗分析模式（Content Funnel Analysis）

## 触发场景

- 当需要对一篇技术文章/行业报告/微信公众号文章进行**从浅到深**的递进式分析时，使用这个模式
- 适用于：技术文章深度分析、行业报告解读、竞品分析、学术论文分析、产品文档学习
- 不适用于：纯摘要任务（只需L1-L2即可）、短文本分析（<500字，五层漏斗过重）、实时新闻点评（时效性优先于深度）

## 核心做法

将分析过程分为五个递进层级，每层有明确的输入、输出和深度标准：

| 层级 | 名称 | 输入 | 输出 | 深度标准 |
|:---:|------|------|------|---------|
| L1 | 原始内容 | 网页原文 | 完整内容提取 | 无信息遗漏 |
| L2 | 结构化提取 | L1 原始内容 | 按章节/模块分类的要点 | 每个模块 3-5 个核心要点 |
| L3 | 核心要点 | L2 结构化内容 | 一句话概括+关键数据 | 精准概括，不丢失关键信息 |
| L4 | 技术深度分析 | L3 核心要点 | 技术创新点+设计理念分析 | 分析有原文依据，技术术语准确 |
| L5 | 行业洞察 | L4 技术分析 | 趋势判断+方法论启示+认知模型 | 体现独立思考，超越字面内容 |

**执行要点**：

1. **逐层递进，不可跳跃**：必须先完成L1才能进入L2，以此类推。跳跃层级会导致上层分析缺乏依据。
2. **每层有独立产出物**：L1产出完整原文、L2产出结构化表格、L3产出核心要点清单、L4产出技术分析报告、L5产出洞察报告。各层产出物可独立审查。
3. **L4必须在L3基础上进行**：技术深度分析必须以核心要点为基础，而非直接跳到原文细节——避免"只见树木不见森林"。
4. **L5必须超越原文**：行业洞察层需体现分析者的独立思考，不能停留在原文内容的复述。如果L5的产出仅是对L4的换种说法，说明洞察深度不足。
5. **每一层都需标注原文依据**：L4和L5的每个论断都应标注来自原文的哪个段落或数据，确保可追溯性。

## 为什么需要五层漏斗

**层层递进保证分析深度**：单层分析容易陷入"要么太浅（仅做摘要）要么太散（直接跳到细节）"的困境。五层漏斗通过强制分层，确保每一层的分析在适当的深度上进行——L1-L3保证"理解准确"，L4-L5保证"洞察深刻"。

**防止"跳过理解直接判断"**：最常见的分析失败模式是——读了两段就开始下判断。五层漏斗通过L1-L3的强制沉淀，确保分析者在做出判断（L4-L5）之前已经充分理解了内容。

**每层可独立审查**：分层结构使得每层产出物可以独立审查。如果L4的技术分析有误，不需要重新审查L1-L3；如果L5的洞察不够深刻，只需要回到L4补充分析基础。

## 反模式（不要这么做）

- ❌ **跳跃分析**：从L1直接跳到L4或L5，缺乏L2-L3的结构化理解——导致分析浅薄、缺乏依据
- ❌ **层级混淆**：将L4的分析内容混入L3的要点总结中——破坏层次边界，读者无法区分"原文内容"与"分析者观点"
- ❌ **L5空泛**：行业洞察层仅有泛泛的趋势判断（如"AI将改变世界"），缺乏具体的技术趋势、方法论启示和可复用认知模型——失去洞察价值
- ❌ **L2过度拆分**：每个模块拆出10+个要点，失去"核心要点"聚焦意义——应控制在3-5个
- ❌ **L1信息遗漏**：原始内容提取不完整，遗漏关键数据或章节——导致后续所有层级分析建立在残缺信息之上

## 检验标准

做完之后怎么知道做对了？

- **标准1（层级完整性）**：五层均有独立产出物，可逐层追溯
- **标准2（递进深度）**：L5的产出明显深于L4，L4明显深于L3——不是简单的换种说法
- **标准3（原文可追溯）**：L4和L5的每个关键论断都标注了原文依据（段落/数据/引用）
- **标准4（L5超越原文）**：行业洞察层包含至少1个原文未明确提及的独立判断
- **标准5（L2聚焦度）**：每个模块的核心要点不超过5个，且不与原文标题简单重复

## 迁移示例

这个模式还能用在什么其他场景？

- **场景1（竞品分析）**：L1=竞品官网/文档 → L2=功能与定位结构化 → L3=核心差异化要点 → L4=技术架构与设计理念分析 → L5=竞争策略与市场机会洞察
- **场景2（学术论文分析）**：L1=论文全文 → L2=章节结构与要点 → L3=研究方法与核心结论 → L4=实验设计与理论贡献分析 → L5=研究意义与未来方向洞察
- **场景3（行业报告解读）**：L1=报告全文 → L2=报告结构与数据分布 → L3=核心数据与趋势概括 → L4=数据背后的逻辑分析 → L5=行业趋势判断与投资建议
- **场景4（产品文档学习）**：L1=产品文档 → L2=功能模块与架构梳理 → L3=核心设计理念概括 → L4=技术实现与设计决策分析 → L5=产品哲学与行业定位洞察
