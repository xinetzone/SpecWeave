# 截图成本裁剪法（Screenshot-Step Cost Trimming）

## 模式类型

任务设计优化（执行类）。作用于**任务编写阶段**，产出为分段任务书与步数/费用台账；不负责单步执行可靠性，也不做模型路由。

## 模式概述

比较模型贵不贵时，最自然的做法是看「每百万 token 单价」：单价低就是便宜。这条路在以**截图为主要输入**的图形界面 Agent 上系统性失效——这类 Agent 每一步都要把整屏图像发给模型判断，费用与失败率**由步数决定**，而步数由任务书写法决定；同一模型、同一目标，写得含糊的任务书会多走十几步，比换一个更便宜的模型带来的差异更大。

本模式的核心转向是：

> **把成本当作任务设计的因变量：先估算步数，再把长任务切成「侦察 → 选定 → 决策」三段分别验收，把条件写成可判定的数字，把停点尽可能前移，并记录每轮步数与费用形成自己的基线。**

支撑证据来自一个手机 Agent 课程知识包（[上游知识包](../../../../../projects/awesome-okf-xs/doc/bundles/jishu/ai/ecosystems/trae/trae-agent-camp-01/index.md)）：

1. 手机操作时的截图会发给配置的模型做判断（F-068）——每一步都产生一次图像输入；
2. 课程给出的费用口径是「淘宝这类十几二十步的长任务大约几毛钱到一块钱，每一步都要发一张截图」（F-064，讲师口径，无账单佐证）；
3. 任务设计被要求写明条件与停点（F-054），官方示例把「停在商品页」写死在任务书里（F-055）——停点前移直接减少详情页之后的步数。

> 上游知识包明确标注：把「每步发截图」与「长任务更贵」合成成本模型属于**本包推断**，课程未把它们写成因果关系。因此本模式的因果主张按「可检验假设」处理，检验标准要求用自己的步数台账来证实或推翻。

## 触发场景

**适用于**：

- 以**屏幕图像**为主要输入的 Agent（手机自动化、浏览器自动化、桌面 GUI 操作）；
- 长任务包含多次搜索、筛选、翻页、详情页进入；
- 需要在多轮执行中持续降本（同一类任务会反复跑）；
- 出现了「费用高但说不清高在哪」的困惑。

**不适用于**：

- 纯文本 API 调用或纯文本 Agent——成本主要由 token 长度决定，应走上下文压缩与模型路由；
- 有结构化接口可直接取数的场景——应改用接口，而不是优化截图路径；
- 单步即可完成的任务——步数无可裁剪空间；
- 需要全量比较才能得出结论的任务（见反模式 1）——此类任务应先重写目标，而不是裁剪步数。

## 核心做法（5 步）

### 步骤 1：估算步数——把任务拆成可计数的动作

按「一次搜索 = 一步、一次筛选 = 一步、进一次详情页 = 一步、一次表单填写 = 一步」的口径，先给出步数量级估计。

- **主手段**：按动作类型逐项累加；**替代手段**：无历史数据时，用同类任务的经验步数区间（如 5–10 步 / 10–20 步）。
- 估算的目的不是精确预测，而是**识别哪一段占步数最多**。
- 此步产出：步数估算表（动作 → 步数 → 累计）。

### 步骤 2：切成「侦察 → 选定 → 决策」三段，分别验收

把长任务拆成三段，每段有独立的完成标志，而不是「一路做到下单」：

| 段 | 目标 | 完成标志 | 典型步数占比 |
|---|---|---|---|
| 侦察 | 摸清候选范围与筛选条件 | 拿到候选清单（名称/关键属性/价格） | 高（多页浏览） |
| 选定 | 在候选中确定目标 | 一个明确目标 + 依据 | 低 |
| 决策 | 执行不可逆或有副作用的动作 | 停点或人工确认 | 低但代价高 |

- 分段的价值：把「探索成本」与「不可逆成本」分开，任一段失败只需重跑该段。
- 此步产出：三段任务书（可分别下发、分别验收）。

### 步骤 3：把条件写成可判定的数字，减少来回比较

预算、规格、数量、时间一律写成数字区间或枚举，避免「性价比高」「便宜点」这类需要多轮比较才能收敛的描述。

- 条件越含混，Agent 越倾向于多翻几页、多进几个详情页来「找感觉」，步数随之上升。
- 此步产出：可判定条件清单（与 [四要素任务书法](four-element-task-brief.md) 的条件项一致）。

### 步骤 4：把停点前移——能停在列表页就不进详情页

按「列表页能判定的不进详情页、详情页能判定的不进结算页」的原则，把停点设在**能满足验收的最早位置**。

- 停点前移同时降本与降险：少走一步既省一张截图，也少一次触碰不可逆动作的机会。
- 此步产出：文字化停点（如「停在候选项列表，回报前三条的名称与价格」）。

### 步骤 5：记录每轮步数与费用，形成基线

每次执行后登记：任务类型、步数、失败重试次数、费用、验收结果。第二次执行同类任务时与基线比较。

- **主手段**：从平台用量/账单读数；**替代手段**：无账单时用步数作为代理指标（费用 = 步数 × 单步成本）。
- 只看单次费用会低估重试成本——失败重试的累计费用必须一并记录。
- 此步产出：步数/费用台账。

> **不可越过的约束**：裁剪的对象是「与验收无关的步数」，不是验收标准本身。任何以减少步数为由放宽验收（少比一家候选、少核一项回报、跳过必要确认）的做法，属于**降低目标**而非降低成本——步数下降但验收项减少时，不得记为优化成功。

## 反模式

1. **用「找最便宜的」这类需要全量比较的表述**：把收敛责任推给 Agent，它会翻遍候选页，步数无上界。
2. **一个任务里同时做搜索、比价、下单**：三段混为一个不可分割的整体，中途失败要全部重来，重试成本翻倍。
3. **只看单次费用，不看失败重试的累计成本**：把「一次成功很便宜」误当成「这类任务很便宜」。
4. **用换更便宜的模型代替减少步数**：单价下降但步数不变，且弱模型更容易多试错，反而增加总步数与失败率。
5. **没有基线**：无法判断第二版任务书是否真的更省，优化停留在感觉层面。
6. **把停点设在最深处**：认为「都跑到这一步了干脆做完」，把成本与不可逆风险同时推到最高。

## 检验标准

1. **步数可复现**：同一目标第二次执行时步数下降（或明确说明为何无法下降），且结果仍可验收。
2. **台账可核**：有任务类型—步数—重试次数—费用的记录，能回答「贵在哪一段」。
3. **条件可判定**：任务书中无形容词式条件，Agent 无需多轮比较即可收敛。
4. **停点最早**：停点位置满足验收且不再深入，不可逆动作位于停点之后。
5. **假设被检验**：模式主张的「步数驱动成本」在本环境被台账证实或推翻，推翻后不再套用。

## 迁移示例

- **RAG 检索**：减少无效检索轮次比换更大模型更能降本；步骤 1 的「一次检索 = 一步」与步骤 4 的「先看摘要不取全文」同构。
- **批量爬虫/翻页采集**：把「采样侦察 → 确定翻页上界 → 只抓目标页」三段化，避免全站遍历。
- **自动化测试**：按「定位 → 复现 → 断言」分段，失败时只重跑失败段，而不是整套重跑。
- **已知边界（不可外推）**：纯文本调用、有结构化接口、单步任务，以及必须全量比较才能回答的问题（此时应改写目标而非裁剪步数）。
