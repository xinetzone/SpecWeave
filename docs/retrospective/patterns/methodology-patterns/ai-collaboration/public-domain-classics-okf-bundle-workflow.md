# 公版经典原文→OKF知识包生成工作流

## 模式类型

方法论模式 / AI协作 / 知识沉淀

## 成熟度

L1 已验证（1 次验证：2026-08-30~31 中西化学经典 7 束 120 文档，`projects/awesome-okf-xs/doc/bundles/science/chemistry/`，V 阶段 54 条事实回源核验通过）

## 模式概述

为已进入公有领域的经典著作（古代典籍、1900 年前西方著作等）生产"原文选读 + 现代解读"式 OKF v0.2 知识包时，采用 seven-concepts 场景 4（知识沉淀）R→I→E→V→C 链路：公版信源实测登记与零推测事实采集（R）→ 四元组洞察（I）→ 每束 17 文件统一结构批量生成（E）→ fresh context 逐束事实回源对抗审查（V）→ 按线索原子提交（C）。核心价值是保证**引文可回溯、今译自撰无版权风险、信源 100% 实测、成就与局限并陈**，并沉淀可跨学科复用的生产模式。

## 1. 触发条件

同时满足以下条件时适用本模式：

- 目标内容为**已进入公有领域的经典著作**（作者逝世超 70 年/出版超 130 年，或古代典籍），需要"原文选读 + 现代解读"式教程；
- 本地无现成文献资料，素材须来自公开网络；
- 目标知识库为 OKF v0.2 格式（含 toctree 门禁、frontmatter 规范）；
- 单学科首批 3-8 部经典，每部一个独立 bundle。

不适用：版权仍在保护期的著作（改为综述模式，禁止原文引用）；本地已有完整文献资料（信源策略改为本地库+网络补充）。

## 2. 核心步骤（R→I→E→V→C 五阶段）

### R：事实采集（G1 门）

1. **信源优先级**（实测可达者优先级递减）：
   - 西方经典：Project Gutenberg（全文转录）→ Internet Archive（原版扫描，注意 API 可能超时，书目页兜底）→ en/fr.wikisource.org（可能超时）
   - 中国典籍：ctext.org（全文+分章，注意反爬限流）→ zh.wikisource.org（可能超时）→ 古诗文网/quanxue 等在线全文站
   - 权威解读：学术机构页面（大学/学会/博物馆）→ 同行评议论文/权威百科条目（后者仅作线索，关键事实必须交叉验证）
2. **URL 实测纪律**：每个拟登记 URL 必须 WebFetch 实测可达（内容与主题相符）才可写入 references/；超时/不可达的列入"未能登记的资源"节如实说明，绝不冒称信源。
3. **facts.md**：≥25 条编号事实（F-001 起），纯客观陈述，分类成表；头部引用块注明采集时间/范围/说明。

**G1 检查清单**：
- [ ] 事实条数 ≥25，编号连续
- [ ] 因果推断词扫描 0 命中（因为/导致/所以/因而/从而/使得/促成/源于/由于）
- [ ] 每条事实可对应 references 登记信源；人名/年代/数据/引文出处无凭空虚构

### I：洞察（G2 门）

- insights.md：≥3 条四元组洞察（陈述/证据[引 F-xxx]/反常识/行动）+ 知识地图（树状代码块）+ 学习路径；
- 经典类束的必含洞察类型：①"该元典的真正价值是什么"（破除直觉误读）；②"如何使用浩繁的注本/译本"；③中西对照类洞察（若为对照组织）。

**G2 检查清单**：
- [ ] 每条洞察四元组齐备，证据引用真实 F 编号
- [ ] 至少 1 条反常识洞察（读者直觉误读的纠正）

### E：批量生成（G3 本模式沉淀）

每束统一 17 文件结构（对齐 boshu-reading 范式）：

```
<bundle>/
  index.md            # type: OKF；快速导航/快速开始(两类读者路径)/Bundle定位/学习路径/隐藏toctree
  log.md / facts.md / insights.md   # 无 frontmatter
  concepts/           # index(无frontmatter) + 00-why-read + 01-语境 + 02-03-核心内容 + 04-key-passages + 05-现代科学视角
  examples/           # index + 01-段落精读实操(六步法) + 02-reading-route
  references/         # index + original-sources + modern-scholarship（均 type: Reference）
```

**内容纪律**：
- 原文短引：西方著作每段 ≤40 词、中国典籍每段 ≤80 字，逐段标注出处（著作/篇章/节）；
- 今译全部自撰并标注"今译"，禁止照抄现代版权译本/注本（版权译注仅可登记书目线索）；
- 概念文档 ≥80 行，frontmatter 含 type/title/description/tags/generated/status/stale_after/sources（双引两个 references）；
- 关键事实处脚注 `[^n]` 归因；
- "现代科学视角"文档（concepts/05）必须成就与局限并陈，不吹捧不贬斥；
- 涉及科学内容（化学反应式等）必须准确，不得臆造；
- 毒物/危险操作内容附安全警示。

### V：独立对抗审查

- fresh context 子代理逐束抽查 ≥5 条关键事实回源核验（网络重查人名/年代/数据/引文）；
- 检查版权合规、frontmatter、链接规范、立场平衡；输出 pass/fail/blocked 结构化报告。

### C：原子提交（G4 门）

- 按线索拆分提交（如：骨架+西方束 / 中国束 / 总索引），显式路径 add（禁止 `git add .`）；
- **共享工作树注意**：多个会话并行开发同一仓库时，先 `git status` 区分文件归属，绝不提交他人会话的文件；提交信息用 UTF-8 临时文件法（`git commit -F`）避免 Windows GBK 乱码；提交后 `git cat-file -p HEAD` 验证编码。

**G4 检查清单**：
- [ ] 每次提交单一职责、显式文件清单
- [ ] 提交后重扫描工作区，确认无本任务残留

## 3. 反模式（血泪教训）

| 反模式 | 后果 | 预防 |
|--------|------|------|
| 编造引文/人名/年代 | V 阶段必被抓；学术事故 | 只写实测信源可回溯的内容，拿不准就不写 |
| 照抄现代版权译本 | 侵权风险 | 今译自撰+标注；版权注本只登记书目 |
| 登记 URL 不实测 | 死链信源，溯源失效 | WebFetch 逐个实测后才登记；不可达的如实说明 |
| 漠视 toctree 门禁 | CI 拦截（含 bundle 根 index 检测、目录清单一致性） | 每束 17 文件结构完整后跑 check-toctrees |
| file:/// 或盘符路径入库 | 环境绑定断链 | 链接全部相对路径；提交前全量扫描 |
| 单一信源立论 | 偏颇/被单一来源误导 | 关键事实多源交叉；单一线索须标注"转述"性质 |
| 无依据拔高/贬斥历史成就 | 立场失衡（如把炼丹术吹成"科学先驱"或斥为"迷信"） | 成就与局限并陈；争议结论标注"有争议/尚有争议" |
| 忽视并行会话 | git add . 混入他人半成品 | 显式路径 add；status 区分归属 |
| IDE 工具对新路径超时 | 反复失败浪费时间 | 直接改用 PowerShell UTF-8 无 BOM 写入并回读核验 |
| PowerShell 批量替换函数嵌套数组参数 | 参数展平退化为"首字符→次字符"全局单字符替换，批量损坏文件 | 批量文本修复用 Python 脚本逐项 Replace 并报告命中数；损坏文件用 git restore 恢复后重修 |

## 失败案例

| 案例 | 事故经过 | 失败根因 | 修复 |
|------|---------|---------|------|
| PowerShell 批量替换损坏文档 | 用嵌套数组参数调 PowerShell 批量替换函数，参数被展平退化为"首字符→次字符"全局单字符替换，多个刚生成的文档被批量损坏 | 误信 PowerShell 函数对数组参数的传递语义（嵌套数组在函数间展开），未先做单文件试跑 | 批量文本修复改用 Python 脚本逐项 Replace 并报告命中数；已损坏文件 `git restore` 后重修 |
| 子代理回报丢失 | 并行 10 个子代理生成束内容，3/10 的完成回报丢失，无法从对话记录确认交付 | 把会话回报当作事实源；子代理输出经上下文传递不可靠 | 先核查磁盘落盘状态再决定重做范围——**磁盘状态是唯一事实** |
| 信源登记未实测 | 直接登记搜索结果 URL 到 references/，后续核验发现超时/不可达，死链信源使溯源失效 | 跳过"每个 URL 必须 WebFetch 实测"纪律，采信搜索摘要 | 不可达 URL 移入"未能登记的资源"节如实说明，绝不冒称信源 |

## 反目标用户/场景

以下场景**不适用**本模式，强行套用会产生反效果：

1. **版权仍在保护期的著作**：禁止原文短引，应改用综述模式（只登记书目线索+自撰解读），否则构成侵权风险；
2. **本地已有完整文献资料**：信源策略应改为本地库优先+网络补充，公版网站实测流程是多余成本；
3. **只要摘要不读原文的读者**：17 文件结构（原文选读+段落精读+今译）是重资产投入，轻量需求用单文件综述更划算；
4. **非公版的现代注译需求**：本模式今译必须自撰，无法满足"直接引用权威现代译本"的需求场景。

## 早期预警信号

出现以下任一早期预警信号时，应暂停推进、回到信源核验：

| 预警信号 | 含义 | 处置 |
|------|------|------|
| 引文在登记信源中找不到原句 | 可能已虚构 | 立即删除或改写为转述并标注 |
| 同一事实只有单一信源且无法交叉验证 | 立论不稳 | 标注"转述"性质或补第二信源 |
| 子代理连续 2 个束的回报与磁盘不一致 | 交付失控 | 暂停派发，改为磁盘状态驱动的验收 |
| toctree 门禁连续报同一目录不可达 | 结构断裂 | 停止新增内容，先修 17 文件结构完整性 |
| 今译写作时"顺手"复述了某现代译本的表述 | 版权污染 | 回读对照版权译本，改写至自撰 |

## 适用边界

- **规模前提**：单学科首批 3-8 部经典、每束 17 文件的批量结构有规模效应；单部经典的轻量需求性价比低；
- **学科前提**：跨学科迁移示例（物理/生物/数学）尚未全部实测，迁移时须重新走 R 阶段信源实测，不能直接照搬信源清单；
- **团队前提**：依赖"磁盘状态是唯一事实"的验收纪律，无落盘验收机制的团队需先补该门禁。

## 4. 跨学科迁移示例

**物理经典**（已在本仓库实践：science/physics）：
- 信源：Gutenberg（牛顿《原理》Motte 译本、法拉第《蜡烛的化学史》）+ IA（麦克斯韦/朗道扫描本）；中国典籍（《墨经》《考工记》《梦溪笔谈》）用 ctext/维基文库；
- concepts/05 现代视角对照：经典力学 vs 相对论修正、经验物理记载 vs 定量理论。

**生物经典**（可复用）：
- 信源：Gutenberg（达尔文《物种起源》第一版）+ BHL（生物多样性遗产图书馆，含博物学画版扫描）；
- 关键差异：博物学著作图版版权需逐一确认（多数已公版）；"现代视角"需注意进化生物学综合理论的后续修正。

**数学经典**（可复用）：
- 信源：Gutenberg/维基文库 + archive.org（欧拉、高斯原版扫描）；中国算经（《九章算术》《周髀算经》）用 ctext；
- 关键差异：数学符号史（原文符号与现代记法差异大），今译需保留原符号并另附现代记法对照。

## 5. 规模与效率参考

- 7 束 120 文件实测：并行子代理每代理一束（含网络调研+生成+自验）是最优并行度；R 与 E 可合并为单代理执行（信源在手即写，减少上下文交接损耗）；
- 子代理回报可能丢失（本任务 3/10 丢失），**磁盘状态是唯一事实**——回报丢失后先核查落盘再决定重做范围；
- 事实清单先行落盘（R 阶段独立提交产物）可让 E 阶段重做时免于重复调研（tiangong-kaiwu 案例实测有效）。
