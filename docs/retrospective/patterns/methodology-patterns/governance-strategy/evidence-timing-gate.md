# 证据时序门（Evidence Timing Gate）

## 模式类型

跨领域迁移型方法论模式——把"发布 / 提交 / 上线 / 投稿这类一旦发生便无法回撤的对外动作"的时序、资格与证据判定经验，迁移到任何"存在公开动作、外部审核依赖与硬时间窗口"的通用任务场景。

## 成熟度

- **等级**：L1-draft（机器可校验字段 `maturity: "L1"` + 库内语义字段 `maturity_level: "L1-draft"`）
- **验证次数**：validation_count = 1（仅表示完成一次方法抽取；来源为规则结构与时序演算，**未经**真实审核周期、获奖、收益或跨域实际交付验证）
- **复用次数**：reuse_count = 0
- **升级条件**：在第二个**非同谱系**案例（资助申请、论文预印本、软件公开发布等）中完整应用，并留下窗口计算、依赖失败处置与第三人复核记录 → L1.5；再需一次包含"不可逆动作已真实发生之后"的复盘回填 → L2-validated

> **为什么把等级拆成两个字段**：`maturity` 承担机器可校验的等级阶梯（L1/L2/L3/L4），`maturity_level` 承载库内细粒度语义（L1-draft = 假设性、单案例、待验证）。两者并存，使等级统计不被"草案态"污染，同时不丢失"尚未经受真实不可逆动作检验"这一关键信息。

## 模式概述

对"公开即发表"类动作，最自然的做法是把"内容准备好"等同于"可以公开"：稿子写完就贴、代码写完就推、材料齐了就投。此类动作的系统性失效在于——**公开是一种状态跃迁，而不是一次文件编辑**：一旦内容进入可被第三方检索的范围，就产生了无法通过后续编辑消除的历史条件（首发判定、相似性记录、授权状态）。绝大多数失控不是"内容不够好"，而是"内容对，但公开的时机、资格或证据还差一项"。

证据时序门把每个**不可逆公开动作**前的判定改写为一个**三条件合取门**：在动作发生之前，**同时**核验①证据就绪、②适用资格、③时间条件；任何一项为未知，即保留暂停状态或至少一条退路，而不是把未知折算成一个乐观估计后照常推进。

**为什么是合取（AND）而非加权**：三条件各自独立地拥有"一票否决"的能力——证据不足使成果无法被判定成立，资格不符使动作从起点无效，时间不符使动作错过窗口。任何一项无法用其他项的盈余补偿（资格不能靠证据多补，时间不能靠资格好换），因此不能用加权分数把"两项很好、一项未知"平均成"可以推进"；合取的产物是"未知必须显式保留"，而非"总分够高即可放行"。

本模式由一次"三入口参赛与写作指南"知识包沉淀萃取：其 M-002 给出六步动作，I-002 给出该门必须存在的原因——先发表的历史不因**等待**、**换词**或**删除重发**而消失（F-062/F-063：站外先发与实质相似简单改写均非首发；F-066/F-079：站内相同内容删后重发仍在非首发情景内），且窗口按**实际小时**而非日期计算（F-061/F-064）。案例细节与完整规则地图保留在[上游知识包](../../../../../projects/awesome-okf-xs/doc/bundles/sheke/industry/contest-writing-guide/index.md)，本条只取去场景化的通用动作。

## 适用场景

**适用于**：

- 任务包含**不可逆的公开动作**（对外发布、提交、上线、申报），动作一旦完成不能通过编辑回退
- 动作成立与否取决于**外部资格**（工具链、授权、身份、合同），而非仅取决于自方产出质量
- 存在**硬时间窗口**或审核依赖，且窗口的判定需要精确到时刻与时区
- 公开动作可能产生**对后续路径的不可消除影响**（首发判定、相似性记录、授权状态）

**不适用于**：

- **可无损回滚的内部动作**（草稿保存、内部评审、私有分支提交）：随时可撤回，加门只会增加成本 → 直接用普通编辑流程
- **纯内部草稿**（信息公开范围被严格控制、不存在对外发布可能）：无不可逆公开动作可判定 → 无需本门
- **结果完全可控、无外部资格与时间窗**的纯产能任务（无门可设）→ 用常规优先级排程
- 需要给出**法律意见**或替对方接受协议的场合：本模式只约束"未知如何被保留"，不代为判定条款效力 → 转相应专业流程

## 问题背景

**公开表达有独立的时间成本（沉淀自上游洞察 I-002）。** 内容准备、公开可检索、平台声明是**三种不同状态**，它们并不随"我心里觉得写完了"一起达成：

1. **内容准备**只说明材料就绪，不说明它可以被发表；
2. **公开可检索**一旦发生，就在可被他人核对的范围里留下了痕迹；
3. **平台声明**（是否声明为首发、是否声明为原创）则是对上面两个状态的一种断言——断言错了，成本不由本平台独自承担。

三态分离带来的后果是：**先公开可能产生另一路径无法消除的历史条件**。相近内容无论隔多久、无论换多少措辞、无论事后是否删除重发，都可能被识别为"此前已公开"，从而使后续路径上的"首发/原创"类资格失效（F-062/F-063、F-066/F-079）。

直觉在这里给出的判断是错的：人常想"**我自己的稿，换个平台或等几天就能重新当首发**"。但已取得的规则记录的是**原先发表的事实与相似性**，等待不会删除历史，换词不足以抹掉实质相似，删除也不自动恢复（F-066/F-079）。同时，窗口本身按**实际经过的小时**而非日历日期计算——把"跨了几天"折算成"够不够"会直接算错（F-061/F-064；本包实施代理对该示例的时序算术见 C-006：示例区间实为 71 小时而非 72 小时，边界是否恰好达标不予确认）。

因此，对一个不可逆公开动作，**"内容准备好了"既不是"可以公开"的充分条件，也不是必要条件**——它只是三个并列条件中的一个。把它误当作全部，就是这个门要被建起来的原因。（本段为通用机理表述，具体平台规则与案例数字见上游知识包。）

## 核心做法与操作流程（6 步）

### 步骤 1：为每条条件建立登记台账（来源 / 版本 / 时点 / 已读范围 / 未知项）

把参与判定的每一份依据单独登记，字段至少五项：**来源**（谁出的、原始出处）、**版本**（哪一版）、**时点**（何时读到）、**已读范围**（读的是全文还是片段）、**未知项**（没读到的部分是什么）。
- **主手段**：用一表一行登记，未知项单独成列而非留空。
- **替代手段**：无表格工具时，每条依据写成"来源—版本—时点—范围—未知"的一行文本，未知项必须显式写出"未读/未确认"字样。
- **判据**：任一条目若存在"未读范围"，该范围必须出现在未知项列；登记完成后台账中没有空白的"未知项"列（空白的含义只能是"已确认无未知"，需另行标注）。

### 步骤 2：分三线并列列出节点（资格线 / 交付物线 / 发布线），标明自控与外部依赖

把任务拆成三条并行线：**资格线**（取得动作所需的身份、授权、权限、工具资格）、**交付物线**（准备真正要交付或公开的内容与材料）、**发布线**（执行公开动作本身）。每条线上的节点标注"可自控"或"依赖外部"。
- **主手段**：三线并列成表，逐节点标注归属方。
- **替代手段**：无主动清单时，对每个节点追问"这件事的结果取决于我无法影响的第三方节奏吗"——是则归外依，否则归自控。
- **判据**：每条线上的外部依赖节点都被显式标出；不存在"把外部依赖塞进交付物线、假装它只是最后一步"的合并写法。

### 步骤 3：用实际时刻与明确时区计算窗口；缺钟点或时区时拒绝输出精确最晚时间

窗口一律以**起止时刻**为单位换算，不使用"提前几天""跨没跨日期"这类日历直觉。
- **主手段**：取到"起算时刻 + 截止时刻 + 时区"三元组后，按小时差算剩余窗口。
- **替代手段**：若无精确截止时刻（只有日期）或时区未明，**不接受该缺口为确定值**——此时只输出"窗口是否可能满足"的区间判断与"待确认项"，拒绝给出一句确定的"最晚几点前必须动手"。
- **判据**：产出的每一句时间结论都能追到一个明确的起止时刻与时区；存在未确认的钟点/时区时，结论中不出现单一确定的最晚时刻。（案例中"跨过日期即满足"与"按实际小时算"给出相反结论，见 F-061/F-064 与 C-006。）

### 步骤 4：逐项核对凭证与对应版本，不以预计结果充作完成证据

把"我做过""我申请过""我提交过"的每一项换成**可被第三方观察的凭证**，并核对凭证对应的版本是否就是被判定版本。
- **主手段**：逐项列出"待证事项 → 实际凭证 → 凭证对应版本 → 是否匹配"。
- **替代手段**：无法取得某凭证时，如实记为缺口，不以下游的"预计结果"或"口碑信息"替代（如以"该功能应当可用"替代"实际取得的权限"）。
- **判据**：台账中没有以"应当/预计/据说"开头的凭证项；每项凭证都能指到它证明的那个版本。

### 步骤 5：动作发生前同时检查时间、适用资格、许可与材料；任一冲突即缩范围、改独立内容或停止该分支

这是门的本体——**合取检查**，四类项同时过，不接受"其他都好，先推进"。
- **主手段**：动作前一次性过"时间 / 资格 / 许可 / 材料"四项，任一为未知或冲突即触发分支动作。
- **替代手段**：分支动作有三档——**缩范围**（减小动作覆盖的对象）、**改独立内容**（另作一份不依赖冲突条件的内容）、**停止该分支**（本次不执行，保留成果）。三档按"未知能否在窗口内消除"选择。
- **判据**：动作执行记录中能找到当次四项检查的结论；任一为未知时，能找到对应的分支动作，而非沉默推进。

### 步骤 6：保存当轮检查范围与真实结果；来源或版本变动后只回核受影响项，不抹掉既有失败

把"这次检查覆盖了什么、结论是什么、没覆盖什么"作为记录保留下来，而不是用一句话"已完成"代替。
- **主手段**：每次检查产出一条记录，含"检查对象 / 覆盖范围 / 未见事项 / 结论（含失败）"。
- **替代手段**：无版本库时，以带日期与对象名的独立记录文件保存，逐次追加不覆盖。
- **判据**：来源版本更新后，只重核受影响条目；既有失败记录被追加修正说明，而非被删除或改写成成功。

## 反模式

| 反模式 | 为什么失效 | 替代动作 |
|---|---|---|
| 「提前两天肯定够 / 跨过三天就是 72 小时」 | 外部审核没有 SLA，日历日期差不是小时差；把"跨了几天"折算为"够不够"会得到与按实际时刻计算相反的结论（F-061/F-064，C-006 演示了 71 小时被当成"够 72"的情形） | 记录外部依赖、用明确起止时刻与时区算窗口，并为"未确认钟点/时区"保留失败分支而非给出确定最晚时刻 |
| 「字符串比对一致，就宣称整个平台流程已核验」 | 一次比较只覆盖它实际比较的字段与对象；表单、服务协议、实际入口可能同时在变，不在该比较的覆盖面内 | 把结论限定到"被检查的对象与字段"，未覆盖项显式登记为未知，不升级为"全面合规" |
| 「用公开 Wiki / 公开仓库存待发布的实际正文，稍后删掉」 | 公开即形成可检索的发表痕迹，删除不自动恢复；公开历史与相似内容可能仍影响后续路径的首发/原创判定（F-066/F-079；公开表达边界仍为缺口，见 G-023） | 实际正文留在受控私有区，公开面只放指南、结构与问题清单；发布记录与内容分离保存 |
| 「权限申请后 24 小时视为必开通」 | 原文表述是"可尝试"而非承诺，时限只描述可尝试的时点，不构成开通保证 | 取得实际权限后再推进依赖它的节点；未取得前保留缺口与备选分支，不把申请动作当作已取得 |

## 失败案例

以下为上游知识包已登记的**规则性失败态**（"跳过门、先发了再说"在各去向规则中对应的处罚落点），均取自对应方原文已登记事实：

| 失败情形 | 规则落点 | 与本模式的对应关系 |
|---|---|---|
| 相近内容先在站外发布，再发目标平台 | 相似文章先在站外发布，即使隔很久再发，也不是该规则的首发（F-062） | 违反步骤 5：动作发生前未做时间条件核验，把"很久以后"当成"历史已消失" |
| 自己站外文章简单改写后投 | 简单改写而实质相似，不符合首发（F-063） | 反模式"换词即可复位"的规则实证：改写不改变已公开的事实 |
| 站内相同/实质相似内容删后重发 | 站内相同或实质相似内容、删后重发仍在非首发情景内（F-066） | 违反步骤 5 与步骤 6：删除不恢复首发状态，检查范围与真实结果未留存 |
| 按日历"跨了三天"估算 72 小时窗口 | 窗口按小时理解；官方示例 3 月 5 日 15:00 至 3 月 8 日 14:00 仍违规（F-064；本包算术 C-006 计为 71 小时） | 违反步骤 3：以日历直觉替代"起止时刻 + 时区"换算 |
| 自动同步同发其他平台 | 自动同步同发其他平台属首发违规示例（F-065） | 外部依赖未按步骤 2 单列为"发布线外依节点"，其节奏未被纳入窗口核算 |
| 先发后删、并以申诉翻案 | 恶意删除站外 72 小时内内容、伪造证据申诉，可取消首发功能（F-079） | 违反步骤 6：以"抹掉既有失败"替代"追加修正说明" |
| 以低质内容反复冲量 | 非原创非首发每篇扣 5 信用分及对应首发补贴，30 天最多扣 50（F-076）；频繁低成本内容可冻结首发功能 14 天、累计 2 次永久关闭（F-077） | 把门当成可绕过的形式，忽略每次放行都在累积不可逆代价 |

失败案例的共性是：**失效不发生在"内容不够好"层面，而发生在"门被绕过"层面**——每一条都可归因到六步中的某一步未执行（未登记依据、未分线、未按时刻算窗、未核凭、未合取检查、未留存检查范围），没有一条指向内容质量本身。

## 反目标用户/场景

本门**不适用**于以下人群与场景；对它们设门，只会增加成本而不减少风险：

| 反目标用户/场景 | 为何不适用 | 应改用 |
|---|---|---|
| 可无损回滚的内部动作（草稿保存、内部评审、私有分支提交） | 动作随时可撤回，不存在"不可逆公开"，门无判定对象 | 普通编辑或评审流程 |
| 结果完全可控、无外部资格与时间窗的纯产能任务 | 无外部依赖与硬窗口，合取门退化为空判 | 常规优先级排程 |
| 需要法律意见或要求判定条款效力者 | 本门只约束"未知如何被保留"，**不适合**代为判定条款效力 | 转合同/法律专业流程 |
| 把本门当作审核耗时预测器者 | 本门不预测审核耗时、不把任何固定缓冲当 SLA；该诉求对本门**不适用** | 只记录外部依赖节点，不承诺完成时点 |
| 想借本门把未知折算成乐观工期者 | 本门的作用恰是**阻止**"未知 → 默认够用"的跃迁，与"如期推进"的诉求方向相反，**不适合** | 未知保留为未知，另设退路分支 |

## 早期预警信号

出现以下**预警信号**之一，应立即暂停该分支的推进、回到步骤 1 的台账核对，而不是"先发了再补"：

1. **用"提前几天""跨没跨日期"来估算窗口**——而非起止时刻 + 时区。
2. **说不出外部依赖节点的最晚完成时点，却已在排自己的截止**——外部依赖被当成自控节点。
3. **把"我申请过了"当成"已取得"**——以申请动作替代实际凭证。
4. **用一次字符串比对的结果宣称"全流程已核验"**——单次比较被提升为整链路结论。
5. **打算先把实际正文放到公开仓库或公开 Wiki，之后再删**——忽略公开即形成可检索痕迹。
6. **对某条依据说不清"读的是全文还是片段"**——步骤 1 的"已读范围"字段缺项。
7. **出现"反正截止还有几天，先发了再补"的念头**——把未知折算为乐观工期，恰是本门要拦截的动作。

**预警信号**累计出现两项及以上时判定为高危：不得执行任何不可逆公开动作，须先补齐台账、三线分解与窗口核算。

## 检验标准

模式被正确执行后，应满足以下**对准决策结果**（而非流程是否走完）的标准与可审计产物：

1. **每个不可逆公开动作都有三条件依据**：在动作执行记录中，能同时找到该项的时间依据、资格依据与证据状态三项，且三者均能追到步骤 1 的台账条目。
2. **窗口计算可由第三人复算**：任一窗口结论都能由第三人用记录中的起止时刻与时区独立算出同一结果；不存在只有结论、没有输入的"最晚时间"。
3. **未知没有被转换成确定工期或许可**：台账中每个未知项在结论里仍以未知形式出现；不出现"未确认 → 默认够用/默认开通/默认合规"的跃迁。
4. **"一次检查成功所支持的对象与未覆盖范围"写在同一记录中**：检查记录同时说明它比对了什么、以及它**没有**覆盖什么；单份一致性比对不得被引用为全流程已核验。
5. **既有失败在版本更新后仍可追溯**：来源或版本变动后，回核只覆盖受影响条目，既往失败记录被保留并附修正说明，而非被抹掉。

## 迁移示例

- **学术预印本与配套开源发布（同构推演，未实测）**：把"预印本挂出"与"仓库公开"视为不可逆公开动作，公开前合取核①预印本政策与数据许可（资格）、②正文与数据的具体版本与凭证（证据）、③会议/期刊投稿窗口的时点口径（时间）；冲突时缩范围（先公开数据、缓公开正文）或改独立内容。**同构推演，未实测**。
- **已知边界（不可外推）**：① 本模式不预测审核耗时，不把任何固定缓冲当 SLA；② 不替代合同/法律审查，"是否许可"须由相应条款判定；③ 门只在存在**不可逆公开动作**时成立——可无损回滚的内部动作与外推此门属误用；④ 上游案例的具体平台窗口（如按小时的首发计时）不构成本模式的通用常数，迁移时一律重核目标域规则。

## 适用边界与前提条件

**成立前提（缺一即不成立或降级）**：

1. **存在不可逆的公开动作**（对外发布、提交、上线、申报）：本门的判定对象即此动作本身。
2. **动作成立与否取决于外部资格**（工具链、授权、身份、合同），而非仅取决于自方产出质量。
3. **存在硬时间窗口或审核依赖**，且窗口判定需精确到时刻与时区。
4. **公开动作会产生对后续路径的不可消除影响**（首发判定、相似性记录、授权状态）。
5. **能取得起止时刻与时区**：取不到时，本门降级为"区间判断"，只输出"窗口是否可能满足"与待确认项。

**边界（本门不做的事）**：

- 不预测审核耗时，不把任何固定缓冲当 SLA；
- 不替代合同 / 法律审查——"是否许可"须由相应条款判定；
- 不把上游案例的平台窗口（如按小时的首发计时）当作通用常数；迁移时一律重核目标域规则；
- 只约束"未知如何被保留"，**不保证**动作一定成功；按记录保留未知而结果未如预期，责任不在执行方。

**例外处理**：可无损回滚的内部动作、纯内部草稿与外推本门的场合均属误用——此时应退回普通编辑流程或常规优先级排程，而不是给它们"补一个门"。
