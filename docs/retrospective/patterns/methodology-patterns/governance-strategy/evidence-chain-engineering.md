# 证据链工程化（Evidence Chain Engineering）

## 模式类型

跨领域迁移型方法论模式——把合规审计领域"过程必须可举证"的要求，迁移到任何"需要向第三方证明自己是怎么做的"通用工作场景。

## 成熟度

- **等级**：L1-draft（机器字段 `maturity: "L1"` + 语义字段 `maturity_level: "L1-draft"`）
- **验证次数**：validation_count = 1（仅表示完成一次方法抽取；案例为计划态，结果未获验证）
- **复用次数**：reuse_count = 0
- **升级条件**：第二个非同谱系案例完整应用 → L1.5；本团队一次真实任务的赛后复盘证据回填 → L2-validated

> **为什么把等级拆成两个字段**：`maturity` 承担机器可校验的等级阶梯（L1/L2/L3/L4），`maturity_level` 承载库内细粒度语义（L1-draft = 假设性、单案例、待验证）。两者并存，使等级统计不被"草案态"污染，同时不丢失"结论尚未验证"这一关键信息。

## 模式概述

当一项任务的合规性由**过程**而非结果证明时（"全程使用某工具完成""过程真实""未搬运他人成果"），执行者的口头声明不构成证据，只有**在过程中被顺手生产出来的证据资产**才构成证据。证据链工程化把这类过程约束翻译成一组可观察、可存档、可复原的证据动作，并把证据生产**嵌入到工作流本身**——每做一步就顺手产出一步的证据，而不是等到交付前补拍。

该模式的核心判断是：**证据的边际成本在产生的那一刻最低**。同一张截图，流程中随手截是零额外成本，事后补拍要么不可复现、要么需要重演一遍流程——而重演本身就是造假风险。版本化命名与检查点清单则把散落的证据串成**可审计轨迹**，使审核者无需访谈即可还原完整过程。

本模式由一次工具受限型合规执行包的七概念知识沉淀萃取（49 条事实 / 4 条洞察 / 8 条 V 意见）。案例细节属私域内容，不在本库复述。

## 适用场景

**适用于**：

- 任务含**过程性合规约束**：要求全程使用指定工具/方法、证明原创过程、证明未套壳未搬运等
- 评分或审核包含**过程维度**，且该维度只能通过真实过程痕迹被观察
- 需要在事后（公示期、审计、复核）向第三方证明"我是怎么做的"
- 产出物本身高度可复制（同类作品已大量存在），差异化只能来自过程可信度

**不适用于**：

- 无过程约束的普通创作（追求可复现即可，证据链是过度工程）
- 结果本身即证据的交付物（如财务数字、实验测量值）
- 无法在过程中留下痕迹的环节（线下口头协商、外部机构内部流程）
- 只面向最终消费者的产品（无审核方，留痕无人查阅）

## 问题背景

过程性合规的判定标准通常在**事后**才被明确，而执行者直到被要求"证明"时才发现：

1. **声明代替证据**：用"我确实全程用了"作为唯一凭证，审核者无法独立核实
2. **证据生产被推迟**：把截图、版本、记录留到发布前集中补，无法覆盖真实过程中的关键节点
3. **证据无版本序**：多轮迭代后只剩最终产物，中间的取舍与修复过程不可见
4. **证据无检查点**：清单存在但靠记忆逐条打勾，临期才发现关键项从未产出
5. **证据被过早销毁**：为省空间删除中间版本，公示期开始后无法回溯

反常识点在于：当结果的差异化空间被压缩（同形态作品大量存在）时，**过程真实性反而成为更稀缺、更难被模仿的壁垒**——因为它无法靠临场呈现获得，只能靠过程沉淀获得。

## 核心做法与操作流程（5 步）

### 第 1 步：把合规条款翻译为可观察的证据类型

逐条读取任务约束，为每条约束指派**唯一对应的证据形态**（截图 / 版本文件 / 原始对话记录 / 日志条目 / 外部链接凭证）。翻译标准是：**第三方仅凭这份证据，不访谈作者也能判定该条款是否被满足**。无法映射到具体证据形态的条款，说明它要么不可判定、要么实际无人核验——应显式标注，而不是含糊放过。

### 第 2 步：为每类证据设定生成时机（当场生成，不事后补）

把证据生成动作**挂到工作流节点上**，而不是挂到"交付前"：某一步工作刚完成，其对应证据即刻产出。判定标准是"证据与动作在同一时刻产生"。凡是无法在动作发生当下取得的证据（如"整体创新性"这类总体判断），不列入证据链，转为文字论证。

### 第 3 步：用版本化命名建立审计轨迹

所有中间产物按**可排序、可回溯、无覆盖**的方式命名（版本号 + 日期 + 内容标识），保留而非覆盖。命名规则需要同时满足：能看出时间顺序、能定位到具体内容、不会因同名覆盖丢失历史。审计轨迹的价值来自**序列本身**——只有最终版本时，过程是不可见的。

### 第 4 步：把检查点清单逐条打勾并绑定证据位置

清单不是待办事项，而是**证据索引表**：每一行声明"哪条约束 → 需要哪份证据 → 证据文件在哪 → 何时产出"。逐条打勾时确认的是"证据已落位"，不是"我大概做了"。清单与证据目录一一对应，缺一即视为该项未完成。

### 第 5 步：把证据保留期延长到公示/审计期结束

中间版本、原始对话、过程记录在**审核窗口关闭之前不得删除**（含"看起来冗余"的中间版本）。保留期由外部审核周期决定，不由个人存储焦虑决定。存储成本可通过压缩与分目录控制，但保留期限不可自行缩短。

## 反模式与反例警示（5 个）

1. **声明代替证据**：以"我全程使用了某工具"的自述作为合规凭证——审核方无法独立核实，等价于未提供证据（反常识：合规常被执行成自我声明，而非可核验事实）
2. **事后集中补证**：把留证推迟到交付前统一补拍——补拍无法覆盖真实过程节点，且若需重演流程，重演即是新的造假风险
3. **只留最终产物**：交付后清理中间版本与过程记录——过程不可复原，证据链只剩结论没有路径
4. **清单靠记忆打勾**：有清单但不对应具体证据位置——临期才发现关键项从未产出，验证成本全部堆在截止日前
5. **证据缺失被当作"没问题"**：因某类证据难获取而跳过该项并默认通过——把"无证据"与"已满足"混为一谈，是审计中最常见的失分方式

## 失败案例

### 失败案例 1：证据集中补拍，审核时无法复核

- **场景**：任务要求全程使用指定工具并证明原创过程，执行者前几轮正常工作但不留痕，直到交付前一天才开始集中补拍"证明材料"。
- **结果**：补拍材料与真实过程无法对应，审核方按既定标准给出不通过结论；若补拍需要重演部分流程，重演痕迹与原始产出时间线自相矛盾，反而坐实存疑。
- **失败根因**：把证据生产当成"交付前的一道工序"，而不是"工作流的副产品"——证据的边际成本在产生的那一刻最低，事后补拍要么不可复现、要么需要重演，而重演本身就是新的造假风险。
- **正确做法**：在拆解每一步工作时就绑定对应的证据动作（截图 / 版本文件 / 原始记录），随做随存；无法在动作当刻取得的证据（如整体原创性判断）不列入证据链，改为文字论证。

### 失败案例 2：检查点清单存在，但证据登记表始终为空

- **场景**：执行计划设置了逐项检查点清单，登记表格也已建好，但直到截止前一天，登记表仍是空的——每一项都没有指向具体的证据位置。
- **结果**：清单被默认为"已通过"，复核时才发现关键项从未产出，验证成本全部堆在截止日前，最终来不及补齐。
- **失败根因**：把"无证据"与"已满足"混为一谈。清单只声明了"要做什么"，没有声明"拿什么证明做了"，于是任何一项缺失都无法被察觉。
- **正确做法**：把清单从待办事项改写为**证据索引表**——每一行绑定"约束条款 → 所需证据形态 → 证据文件位置 → 产出时刻"，缺证据即判定该项未完成。

### 失败案例 3：为补齐证据而编造过程

- **场景**：某项证据在真实过程中确实难以取得（例如某个环节本身不留痕），执行者选择按"应该是什么样"补写一份材料。
- **结果**：材料触发更高层级的红线判定（编造过程比缺证据更严重），该项证据作废，整份材料的可信度一并被否定。
- **失败根因**：把"证据缺失"当作"没问题"处理，而不是当作"未满足"处理——两种失败中，前者主动制造了更难挽回的失败。
- **正确做法**：在第 1 步翻译约束时就显式标注"该项无法映射到具体证据形态"，把它从证据链移出并转为文字论证，而不是临期补造。

## 反目标用户/场景

| 反目标对象 | 特征 | 为何不适用 | 替代路线 |
|-----------|------|-----------|---------|
| 无第三方审核方的个人创作者 | 产出只面向自己或普通读者，无人查验过程 | 证据生产无人查阅，成为纯开销；留存痕迹反而额外制造"被要求举证"的压力 | 只保留版本存档（成本极低、收益确定），跳过证据链与检查点 |
| 结果本身即证据的交付方 | 如财务数据、实验测量值、可复算的产物 | 结果可被第三方独立复算，过程证据不增加可核验性 | 建立"结果可复算"的说明与复算指引，把举证责任放在结果侧 |
| 过程完全不可留痕的环节 | 线下口头协商、外部机构内部流程 | 无法在动作当刻产出证据，事后补拍只能靠演绎 | 把该条款从证据链移出，转为文字论证并显式标注"不可举证" |
| 已有成熟留痕体系的组织 | 组织已有审批、留痕与审计系统 | 双轨并行产出两套互相矛盾的证据，反而推高审计成本 | 直接接入既有系统，把本模式降级为"仅补系统未覆盖的环节" |
| 追求极速的一次性探索 | 目标是快速验证可行性，而非通过审核 | 证据生产的单步附加成本高于该步本身，挤占真实工作 | 用最小留痕（版本号 + 一句话结论）替代完整证据链 |

## 早期预警信号

**读法**：以下任一预警信号出现，即视为证据链已失效，应暂停推进并回到第 1 步重新翻译约束。

| 信号编号 | 早期预警信号 | 含义 | 建议行动 |
|---------|------------|------|---------|
| W-01 | 开始用"我全程使用了某工具"这类自述代替留存证据 | 已滑向声明代替证据 | 立即回退到第 1 步，为每条约束指派证据形态 |
| W-02 | 心里冒出"这步做完回头补张图就行" | 证据生产已被推迟到交付前 | 把该步的证据动作挂到该步本身，改为当场产出 |
| W-03 | 检查点表格存在但长期没有勾选记录 | 清单已退化为形式清单 | 把清单改写为证据索引表，每行绑定证据位置 |
| W-04 | 为省空间删除"看起来冗余"的中间版本 | 保留期被个人存储焦虑提前截断 | 恢复保留策略，至少覆盖整个审核/公示窗口 |
| W-05 | 同一证据类型出现多份且无法判断哪份对应真实过程 | 补拍或重演已经发生 | 保留时序可判定的一份，其余标注重拍来源 |
| W-06 | 命名出现覆盖式写入（同名文件被直接改写） | 审计轨迹已断裂 | 立刻改用版本号命名，并从回收处找回历史版本 |

## 实施检查清单（检验标准）

- [ ] 每条过程性约束都能指认唯一对应的证据形态
- [ ] 每类证据都在其对应动作发生的当刻产出，无一项依赖事后补拍
- [ ] 中间产物的命名可排序、可定位、不覆盖，历史版本可完整回溯
- [ ] 检查点清单每一行都绑定了具体证据位置，缺证据即判定未完成
- [ ] 审核方在**不访谈作者**的前提下，能依据证据材料还原完整过程
- [ ] 审核方据材料给出通过/不通过的明确结论，且该结论可由第三方按同一材料独立复核（**结果性判据**）
- [ ] 证据保留期覆盖整个审核/公示窗口，窗口内无删除动作
- [ ] "无证据"与"已满足"在清单中被显式区分，不默认合并

## 跨场景迁移示例（正例视角，均为同构推演、未实测）

- **企业合规审计留痕**：把"变更须经审批"翻译为审批单编号 + 变更前后快照，保留期对齐审计周期，检查点清单绑定到变更流水号——审计方无需询问经办人即可还原变更历史（同构推演，未实测）
- **科研实验日志**：把"实验可复现"翻译为原始数据文件 + 每次处理的参数文件 + 运行环境快照，按处理轮次版本化命名，检查点清单对应实验记录表（同构推演，未实测）
- **软件开发可追溯性**：把"谁在何时改了什么"翻译为版本提交 + 作者标识 + 差异记录，与本模式的版本化命名与不可覆盖原则同构（同构推演，未实测）

| [溯源驱动信任](../../architecture-patterns/provenance-driven-trust.md) | 系统层面的不可篡改审计轨迹与制品完整性 | 本模式面向**人工执行的过程约束**（人 + 工具 + 文档）；溯源面向机器系统的日志可信性。层级互补：治理规则 vs 系统机制 |
| [合规驱动规则建设五步法](compliance-driven-rule-building.md) | 从一次合规事件沉淀为**可复用规则** | 本模式是一次任务的证据生产实践；后者是把合规教训固化成规则资产的机制，产出物层级不同 |
| [发布资格不变量与发布路径对账](release-eligibility-invariant-gate.md) | 把发布条件写成**可判定不变量**并挂到触发路径 | 两者都追求"可判定"，但本模式产出证据材料，后者产出放行门禁与坐标台账 |
| [权重对位备赛法](../product-growth/weight-aligned-preparation.md) | 把评分表当公开契约，按权重与边际得分率配置工时与材料 | 本模式管**过程证据的生产与存档**，该模式管**材料与工时投向**；两者在"过程可审计 → 权重可兑现"链路上串联，非重复 |

## 适用边界与前提条件

**前提条件**（任一不满足，本模式不成立）：

1. 存在可识别的第三方审核方，且其判定确实依赖过程痕迹
2. 至少一部分关键动作可在动作当刻留下可存档的痕迹
3. 审核窗口的长度可预估（用于确定证据保留期）
4. 单步证据生产的额外成本明显低于该步骤本身的价值
5. 执行者接受"证据缺失即视为未满足"这一判定纪律

**适用边界**：

- ✅ 适用于：合规评审、赛事与申报、审计留痕、实验可复现性、内部变更追溯
- ❌ 不适用于：无审核方、结果本身即证据、过程不可留痕、既有留痕体系已覆盖、极速一次性探索
- ⚠️ 本模式只保证**过程可被还原**，不保证**实质结论正确**——留证完整而内容违规，责任仍在执行方

## 失效条件与演进

- **失效场景**：任务无第三方审核方、无过程性约束、或过程完全不可留痕（线下/外部机构内部）时，本模式退化为无效开销
- **成本边界**：证据生产必须轻量（单步额外耗时与注意力成本应低于该步本身），否则会挤占真实工作——检查点若需要额外 30 分钟以上才能核对，应重新设计证据形态
- **成熟度演进**：L1-draft → L1.5 需第二个**非同谱系**案例（如审计留痕或实验日志）完整应用；→ L2-validated 另需本团队一次真实任务的赛后复盘证据回填
- **环境漂移**：若通用平台普遍提供"过程自动留痕 + 一键导出"，人工留证的边际价值下降——但自动留痕通常与平台绑定（不可导出、随账号注销消失、审核窗口后失效），跨窗口可携带的证据仍需自行归档
- **前提消失后的退化形态**：若审核方只看最终结果、过程痕迹不再被检查，本模式会退化为"事后补拍截图"的形式主义——证据齐全却与真实过程脱钩。此时应直接停用该模式，而不是继续加码留证
- **技术更替后的复查触发器**：当工具链普遍提供"过程自动留痕 + 可导出归档"时，须复查本模式是否仍有独立增量；若自动留痕可跨账号、跨窗口导出且第三方可验证，本模式应降级为"仅补自动留痕覆盖不到的环节"
- **责任边界**：本模式只约束证据生产的纪律与可审计性，**不担保审核结论本身的实质正确性**——留证完整而实质内容不合规，责任仍在执行方；反之，证据缺失时"已满足"的主张不可采信
