# 三对象分账法（Three-Object Ledger）

## 模式类型

跨领域迁移型方法论模式——把"一次主题交付其实包含多个**独立交付客体**"这一判断，从多入口内容交付场景迁移到任何"同一主题要向不同受众分别交付不同产物"的通用工作场景。

## 成熟度

- **等级**：L1-draft（机器字段 `maturity: "L1"` + 语义字段 `maturity_level: "L1-draft"`）
- **验证次数**：validation_count = 1（仅在单案例知识包上完成一次方法抽取，未经实际投稿、获奖或独立迁移验证）
- **复用次数**：reuse_count = 0
- **升级条件**：第二个**非同谱系**案例完整应用并复盘 → L2；跨域迁移示例（科研论文配套 Demo）仅为同构推演、尚未实测，不计入验证。

> **为什么把等级拆成两个字段**：`maturity` 承担机器可校验的等级阶梯（L1/L2/L3/L4），`maturity_level` 承载库内细粒度语义（L1-draft = 假设性、单案例、待验证）。两者并存，使等级统计不被"草案态"污染，同时不丢失"结论尚未验证"这一关键信息。

## 模式概述

直觉会把一次主题交付当成"**一份稿**"（或"一份代码"），于是三处投递只改标题。但同一主题下的交付物其实是三类**独立交付客体**：产出物（可体验、可使用的作品）、文章（面向读者的独立论证）、传播材料（用于扩散的宣传素材）。三者各自绑定不同的产生工具、不同的同一性判定、不同的发表时序与授权条件，改标题不改变其中任何一项。

三类客体必须分开登记，因为约束它们的**三个条件互相独立**：① 工具绑定——产物的创作工具是否满足去向的资格要求；② 作品同一性——不同去向是否把同一产物视为同一件作品；③ 发表先发——何处何时首次公开，是否已消耗首发或独占条件。三者不可互相补偿：工具合资格，不表示跨去向不构成重复投稿（F-022）；许可非独占，也不表示其他去向接受该作品；先发状态一旦形成，等待或删重发都不能自动复位。

案例中，去向把"用什么工具做"直接写进资格条件——要求全程使用指定工具、一件作品只对应一个工具与一个赛道（F-012/F-014），并要求提供真实创作对话（F-035/F-042）；同时对一稿多投、轻微修改重复与跨赛道投稿设有取消资格的情形（F-022）。这些条件分属工具、同一性与时序三本账，任一本不满足都不能由另一本的好转抵消。证据均登记于[上游知识包](../../../../../projects/awesome-okf-xs/doc/bundles/sheke/industry/contest-writing-guide/index.md)。

本模式由一次多入口内容交付的七概念知识沉淀萃取（83 条事实 / 3 条洞察 / 2 项候选方法）。**隐藏前提**是：存在两个及以上去向，且各去向的约束文本可读、可逐条对齐。**降级路径**是：当去向唯一，或规则不可读时，本模式降级为"单客体缺口清单"——只列未知与缺口，不产出任何"可以做"的许可结论。

## 适用场景

**适用于**：

- 同一主题需要向两个及以上去向交付，且去向对"工具链、作品同一性、发表时序或授权"至少一项设有约束
- 交付物可自然分化为"产出物 / 面向读者的文字 / 面向传播的材料"三类
- 公开或提交动作不可简单撤销（先发、独占、公示、资格审核等）
- 规则文本可读但分散在多方，需要逐客体对齐而非整体拍板

**不适用于**：

- 只有一个去向且无工具与授权约束 → 按普通交付流程走，分账属过度工程
- 需要出具法律意见或代他人接受协议 → 应改用"逐条回证 + 取得完整协议"的做法，本模式不代答法律问题
- 指望用一张表就证明允许跨投 → 应改用逐客体、逐去向的分别论证，缺口保留为缺口
- 尚无任何真实来源、资格或可用工具链 → 只能列缺口清单，不得据推测填成许可

## 问题背景

当去向把"用什么工具做"写进资格条件时，**创作过程本身即资格证据**，而不只是成品的展示。资格核的是"怎么做的"，不是"做得好不好"；因此功能质量再高，也不能证明工具资格。这与"提交一份能跑的成品即证明能力"的直觉正好相反。

反常识点在于：直觉会把"**同一产物能在多处运行/使用**"当成"多处都可用"。功能可用是能力事实，工具资格是资格条件，两者不同轴；当去向已明确限定工具与时序时，"能跑"无法替代"合规"。案例中，去向上限定了怎样创作与怎样投递（F-012/F-014、F-035/F-042），说明资格锚定在过程上，而过程无法由成品的措辞补足。

由此推出两条后果：其一，**事后改写声明无法补救工具资格**——若创作时未按目标工具留下过程证据，事后调整用途或类别措辞只会留下与真实过程不一致的痕迹；其二，**同一份产出物不应被默认当作可跨去向复用的路径**，跨去向复用必须回到工具、同一性、时序三本账逐一核对，而不是靠改标题。这条机理同时构成本模式最重要的反模式来源。

## 核心做法与操作流程（6 步）

### 第 1 步：拆出独立交付客体并登记同一性关系

- **主手段**：列出全部产出物、文字稿与传播材料，逐项标注"它是什么、面向谁"，明确哪些是同一产出物的不同表述、哪些是真正不同的客体。
- **替代手段（无工具/无去向文档时）**：用一张手写三栏纸（客体 / 载体形式 / 同一性关系）逐项登记即可，不必上系统。
- **判据**：任一客体都能被指认"它是独立客体，还是另一客体的副本"；无法判断时不合并登记。

### 第 2 步：为产出物客体登记真实工具链与原创性证据

- **主手段**：记录该客体由什么工具、以何过程产生，保留能指向该过程的过程材料；同时登记目标去向对工具链的要求。
- **替代手段（无 API/无平台文档时）**：以"我能指向的过程材料有哪些"作为代理判据，把拿不到的部分显式标为未知。
- **判据**：能回答"它由什么工具产生、有何过程证据"；仅凭功能可用不构成工具资格。

### 第 3 步：为文章客体登记独立读者问题、论证与发表历史

- **主手段**：为每篇文字记录它独立回答的读者问题与论证链条，并记录真实的发表历史（是否已公开、何时、何处）。
- **替代手段（无发布系统记录时）**：在私有写作区保留实际正文与发表时间线，公开包只保留指南与结构，不落待投正文。
- **判据**：能回答"这篇文章独立回答什么问题、是否已公开、何时何处"；未发表正文不进入公开区。

### 第 4 步：为传播材料客体登记第三方权利与用途

- **主手段**：逐项登记传播材料涉及的商标、界面、引用与他人素材的授权来源，以及拟投放的平台与用途。
- **替代手段（无授权台账时）**：按素材逐项列出"来源 → 许可主体 → 许可范围 → 拟用目的"，缺项保留缺项。
- **判据**：能回答"这份材料里有哪些非自有权利、权限从哪来、用于何处"；不同权利与授权前提不得合并成一类。

### 第 5 步：逐客体判定已确认条件、缺口、冲突与保守分支

- **主手段**：对每个客体逐条写出"已确认条件 / 待确认缺口 / 与其他客体的冲突 / 保守退路"，缺口单独成列，不写成许可。
- **替代手段（无正式台账时）**：用"已确认 / 未知"两栏分列，未知即未知。
- **判据**：任何"可以做"的结论都能指向已取得的条款；只有缺口时结论只能写"待确认"。

### 第 6 步：改动或公开前回核关联客体并留痕

- **主手段**：任一客体即将改动或公开时，回核与之关联的其他客体状态（同一性、时序、授权是否因此变化），并保存真实版本与发表记录。
- **替代手段（无版本系统时）**：以带日期的文件副本保留历史版本，不覆盖。
- **判据**：改动后每个关联客体的状态仍可追溯到具体版本与时刻；不可逆公开动作前已完成回核。

## 反模式（≥4 条）

| 反模式 | 为什么失效 | 替代动作 |
|---|---|---|
| 一份代码或一份稿件只改标题，三处投 | 工具绑定、作品同一性与发表先发是三个互相独立的条件，改标题不改变其中任何一个 | 分别核对产出物工具链、文章论证与发表状态、传播材料授权三本账 |
| 用一份非独占许可证明所有外部用途合法 | 非独占许可不确认其他去向的资格要求、他人知识产权的限制或其他协议的约束 | 按许可主体、许可范围与拟用目的分别登记，逐一判断 |
| 以库规模或去向知名度选择方案 | 总量与知名度不证明任务可被真实体验，也不证明过程可被举证 | 选一个能跑且有真实过程证据的客体，再判断去向是否可走 |
| 事后改写用途或类别声明以补救工具资格（来自问题背景的机理） | 资格核的是创作过程，成品的质量与措辞补不出未按目标工具留下的过程证据 | 创作前就按真实工具链进行；冲突时另做合规的新作品，不事后伪造过程 |
| 把第三方商业素材、引用界面与纯自有代码混成一类 | 不同权利与授权前提会被省略，登记随之失真 | 逐素材登记来源与用途，按权利类型分列 |

## 失败案例

以下为上游知识包已登记的**规则性失败态**（"未分账"在各去向规则中对应的处罚落点），均取自对应方原文已登记事实，非事后追认的个案叙述：

| 失败情形 | 规则落点 | 与本模式的对应关系 |
|---|---|---|
| 同一作品投多个去向 | 同作品一稿多投、轻微修改重复投稿或跨赛道投稿，可取消相关作品评奖资格（F-022） | 客体未分账，去向按"同一作品重复投递"计——这正是"把三类客体当成一份产物"的最直接代价 |
| 一件作品绑定不止一个工具或赛道 | 每件作品仅可用一个赛道指定工具完成、仅报名一个专属赛道（F-014；工具要求见 F-012） | 违反第 2 步：资格核的是创作过程，成品质量补不出工具资格 |
| 未登记第三方权利就投放传播材料 | 虚假、同作品重复、不正当、侵权违规等可取消资格、追回奖励（F-059） | 违反第 4 步：传播材料客体未登记其非自有权利与授权来源 |
| 含主办方 IP 而未经授权跨平台转发/商用/二创 | 在含主办方 IP 前提下，擅自转发、出版、商用或二创，可取消资格及追责（F-057/F-058） | 第 4 步与第 6 步的合并失效：用途与授权未逐项登记、改动前未回核 |
| 公开后删除以图复位 | 公示期结束前删除活动内容，属可取消全部资格情形（F-023） | 违反第 6 步：已发生的公开动作不因删除而复位，回核与留痕才是唯一可控项 |
| 频繁低成本重复投递 | 频繁低成本内容可冻结首发功能 14 天，累计 2 次可永久关闭（F-077） | 把"多投即多机会"当成策略，忽略同一性账上的累计代价 |

失败案例的共性是：**失效不发生在"作品质量"层面，而发生在"客体未分账"层面**——上述处罚全部指向"不同客体、不同权利、不同时序被混成一份产物"的登记缺失，无一条指向产出物本身不可用。

## 反目标用户/场景

本模式**不适用**于以下人群与场景；对它们套用分账登记，不是"更严谨"，而是**过度工程或制造伪许可**：

| 反目标用户/场景 | 为何不适用 | 应改用 |
|---|---|---|
| 单一去向交付者（只有一个出口且无工具与授权约束） | 不存在需要分账的第二个客体，登记成本全无收益 | 直接走普通交付流程 |
| 需要法律意见或代他人接受协议者 | 本模式只做登记与缺口标注，**不适合**用来判定条款效力或代答法律问题 | 转法律专业流程；取得完整协议后逐条回证 |
| 想用一张表换"可以跨投"结论者 | 分账的产物是"逐客体、逐去向的分别论证"，不是一张放行条；该诉求对本模式**不适用** | 逐客体列出已确认条款与缺口，缺口保留为缺口 |
| 规则文本不可读者（只给片段、无可用入口） | 无对齐全的对象，产出只能是缺口清单，得不出任何许可结论 | 停在本模式的降级路径：只列未知与缺口 |
| 要把平台专有常数当通用常识者（如把某平台 72 小时窗口当普适时限） | 平台专有规则**不适合**外推，本模式只规定"分账登记"这一动作本身 | 迁移时一律重核目标域规则 |

## 早期预警信号

出现以下**预警信号**之一，说明分账尚未完成，应立即暂停跨去向推进、回到规则与工具链研究，而不是先投出去再看结果：

1. **脑海里出现"同一份稿子 / 代码只改标题就能投多处"**——最常见的起点，对应"把三类客体当成一份产物"。
2. **无法回答"这份产出物由什么工具产生、有何过程证据"**——工具资格不可举证，等于资格未确认。
3. **只读到其中一个去向的规则，其余去向"应该差不多"**——缺口被直觉补成许可。
4. **说出"我们的许可是非独占的，所以到处都能用"**——用许可性质替代逐去向资格核对。
5. **出现"先公开一下，之后删掉再发"的念头**——忽略公开不可回撤、删除不恢复资格。
6. **传播材料里含他人商标、界面或素材，但没有任何授权台账**——第三方权利未登记。
7. **改动一个客体时说不清其他关联客体（同一性 / 时序 / 授权）会怎样变化**——缺少第 6 步的回核。

**预警信号**累计出现两项及以上时判定为高危：此时不得跨去向投递，须先补齐分账登记与缺口清单。

## 检验标准

1. **五问齐备（结果性判据）**：每个交付客体都能回答"是什么、由什么工具产生、权限从哪来、在哪何时公开、还缺什么"。
2. **事实与意见分栏**：每条陈述可归类为"已确认事实"或"判断/建议"，两者不混写。
3. **跨发决定可追溯（结果性判据）**：任何跨发/跨去向决定都能指向已取得的条款，或明确标注为待确认分支，不存在"看起来没问题"的默认通过。
4. **第三人可发现缺项**：第三方仅凭登记内容即可指出缺项，无需访谈作者。
5. **缺口即缺口**：缺口被写成缺口，不被表述为许可；"已满足"与"无证据"被显式区分。

## 迁移示例

- **科研论文配套 Demo（跨域，同构推演，未实测）**：把论文正文、代码仓与宣传材料视为三个独立交付客体，分别登记许可（论文版权 / 代码许可 / 素材与数据授权）与公开历史（预印本、仓库提交、海报与社媒）；再核目标会议的预印本政策与数据许可。对应关系：第 1 步拆客体、第 2 步核代码仓的工具链与原创性证据、第 3 步核论文正文的发表历史（预印本先发）、第 4 步核宣传材料的图片与数据许可、第 5 步逐项判缺口、第 6 步投稿前回核关联客体。**同构推演，未实测**。
- **已知边界（不可外推）**：不得把某平台 72 小时窗口等平台专有规则外推为通用时限；也不得把任一平台的资格判定口径、相似性阈值或入口身份照搬到其他场景。本模式只规定"分账登记"这一动作，本身不产出任何具体去向的许可结论。

## 与现有模式的关系

| 相关模式 | 关系 | 说明 |
|---|---|---|
| [单一权威声明对齐](single-authority-declaration-alignment.md) | 相邻易混 | 对方管"同一事实被多载体重复声明时的权威源收敛"；本模式管"同一主题下**不同交付客体**的分账登记"。前者是同一事实的副本，后者是不同的客体，非重复。 |
| [合规契约化](../compliance-contracting.md) | 层级互补 | 对方管"约束怎么写"（态度式约束 → 可度量契约）；本模式管"对象怎么分"（交付物 → 多个客体各自登记）。约束层 vs 对象层。 |
| [权重对位备赛法](../product-growth/weight-aligned-preparation.md) | 对位轴不同 | 对方按**评分维度与权重**组织证据物与工时；本模式按**交付客体**分账，不对准评分。 |
| [证据链工程化](evidence-chain-engineering.md) | 流水线互补 | 对方管证据的**生产过程**（条款 → 可观察证据动作，嵌入工作流当场生产）；本模式管证据的**归属分账**（哪个客体、哪类权利、哪个时序状态）。 |

## 适用边界与前提条件

**成立前提（缺一即降级或停用）**：

- **前提 1｜至少两个去向**：只有一个出口时本模式退化为过度工程。
- **前提 2｜各去向约束文本可读、可逐条对齐**：规则不可读时只能产出缺口清单，不得据推测填成许可。
- **前提 3｜交付物可自然分化为"产出物 / 面向读者的文字 / 面向传播的材料"三类**：无法分化时按普通交付流程处理。
- **前提 4｜存在不可简单撤销的公开或提交动作**（先发、独占、公示、资格审核）：不存在时本模式无对象可管。
- **前提 5｜作者保有对客体状态的可见性**（能知道某客体是否已公开、何时、何处）：丧失可见性时登记将失真。

**边界（本模式不做的事）**：

- 不判定任何**具体去向**的许可结论——只做登记与缺口标注；
- 不替代法律审查，也不代他人接受协议；
- 不把任一平台的资格口径、相似性阈值或时限常数外推为通用常量（见"迁移示例"的已知边界）；
- 不提升证据本身的质量——证据来源不可靠时，分账登记也救不回结论。

**例外处理**：去向唯一，或规则不可读时，本模式降级为"单客体缺口清单"——只列未知与缺口，不产出任何"可以做"的许可结论。
