# 边界成对交付（Paired Negative-Boundary Delivery）

## 模式类型

方法论模式（知识生产 / 内容层）。作用于**单源或 `flagged` 材料被转成知识包、报告或教程时的产出决策**，回答「每新增一项产出，必须同时交付什么」。

> **为什么单独成条**：既有模式把「不覆盖声明」放在**结论口径**（`verification-scope-bounding` 的四项限定）或**验证范围**（`hermetic-isolated-verification` 的两者都不覆盖）里。本模式把它放在**产出项的配对关系**里——声明不是一段补充文字，而是与每一项产出绑定的、带机械判据的交付物。区分判据见 §7。

## 触发场景

**适用于**：

- 单一信源、无法交叉验证的材料（课程复盘、访谈、厂商公告、单次实测）转知识包 / 报告。
- 材料带 `flagged` / `stale_after` / 明确的时效或平台边界。
- 产出层新增章节、推导路径、算例、可操作清单，或把源文主张改写成教程结论。
- 材料含营销话术、效果承诺、法律或平台规则主张，需要显式剥离。

**不适用于**：

- 多源可交叉验证、结论有独立出处的材料（此时声明应写成证据等级，而非成对禁用条款）。
- 纯格式转换、无内容判断的搬运。
- 已有 L3 全流程模式覆盖的博文→bundle 标准转化：本模式只作该流程内「产出决策」环节的窄补充，不替代全流程骨架。
- 声明已经由 CI 强制校验且判据与产出项一一绑定的项目（本模式已内化，重复套用属过度工程）。

## 反目标用户/场景分析

| 类别 | 反目标对象 | 不适用原因 | 切换到什么 |
|---|---|---|---|
| A | 多源可交叉验证材料的研究者 | 结论有独立出处，边界应由证据等级表达；套用成对禁用条款会把可验证结论无端降级 | 证据分级 + 引用台账 |
| B | 纯格式转换、无内容判断的搬运执行者 | 没有产出决策，配对表与判据全是净成本 | 格式一致性清单 |
| C | 已用 CI 把「产出项 ↔ 声明 ↔ 判据」强制绑定的团队 | 本模式已内化，重复套用属过度工程 | 直接维护 CI 规则，不再写模式文档 |
| D | 强时效草稿、一次性纪要 | 成对登记成本高于读者收益，且边界会随下一版失效 | 只写一行「单源 / 未核」提示 |

> **范式切换信号**：出现 A~D 任一类时，不要「简单说不适就结束」——按上表最后一列换用对应范式，并在交付物里写明切换理由。

## 适用边界与前提条件

- 前提 1：材料确为单源或 `flagged`，且本次存在**新增产出项**；仅修订错别字不触发。
- 前提 2：项目能运行一次机械判据（脚本 / grep / CI job）；无法运行判据的环境里，本模式只剩 prose 承诺，应降级为「显式缺口清单」。
- 前提 3：产出项可枚举；产出项是连续生成、无法事先列全时，改为按批次收口后补登记。
- 前提 4：声明的词表由项目约定给出，本模式不内置固定词表。

## 问题与机制

单源材料的读者无法从正文判断「这条结论能外推到别处吗」。若交付物只列产出项，缺失的边界会以「沉默」的形式被读成「默认适用」：视频号条款被读成通用法律口径、讲师演示被读成可照做流程、单次数据被读成因果规律。

**机制**：把每条「不覆盖」从 prose 承诺升级为**与产出项成对登记的结构化条目**，再为每条目配一条可执行判据。产出项是「给了什么」，声明是「不给什么」，判据是「怎么证明没给」——三者缺一，边界就退回人工记忆。

## 核心步骤（5 步）

1. **枚举产出项**：列出本次全部新增内容单元（教程篇、章节、算例、结论档位、判断清单），写成表格第一列。不枚举就无法配对。
2. **逐项写不覆盖声明**：每个产出项配一行，含三项——不覆盖什么、适用到哪个平台 / 时段 / 证据等级、证伪条件（什么情况下这条声明作废）。
3. **声明翻成机械判据**：每行配一条可执行检查，例如品牌词与课时号全文扫描、`route` 字段存在性检查、F 台账边界行计数、跨文档关键计数比对、相对链接逐条点开。判据必须能在落盘后一次运行内给出布尔结果。
4. **落盘即跑，红项修产出**：判据报红时改产出内容，不放宽判据、不把红项改标为「例外」。本模式与「结构承诺配机械判据」在这里接壤，后者已有 L2/L1 覆盖，本模式只要求**判据与成对表逐行对应**。
5. **登记与缺口外置**：在 frontmatter / 来源清单登记「产出项 ↔ 声明 ↔ 判据」对应关系；官方源未取得、平台后台未核验、实证缺失等情形显式列入缺口清单，不补写推测内容。

### 成对登记表模板

| 产出项 | 不覆盖声明 | 适用边界 | 证伪条件 | 机械判据 |
|---|---|---|---|---|
| 教程第 N 篇 | 不复述课程运营细节 | 仅方法论层 | 源文出现可公开复述的结构说明 | 课时号 / 品牌词全文扫描 = 0 |
| 官方条款引用 | 不裁定源文未指明的平台 | 仅条款发布平台 | 源文明确平台且条款覆盖之 | 台账边界行存在且编号在范围内 |
| 可操作清单 | 不作效果承诺 | 仅判据，不保证结果 | 有独立实证数据 | 营销话术词扫描 = 0 |

## 反模式（5 条，均来自实测教训）

| # | 反模式 | 实际后果 | 正确做法 |
|---|---|---|---|
| 1 | 只写「教程层去品牌化」不配扫描 | 本轮 `concepts/04` 把课时编号与加课安排写进教程层，首轮 8 条对抗审查全部采纳仍未覆盖，回归机械扫描才抓到 | 每条 prose 承诺配一条 grep / 脚本判据，落盘即跑 |
| 2 | 用官方条款给未指明平台的源文背书 | 视频号《原创声明功能使用条款》被误读为通用法律边界 | 显式写适用边界（本轮 F-040），把「不裁定什么」写进事实台账 |
| 3 | 检索不到法条就凭印象补一句 | 著作权法官方全文两次检索未取得，若无缺口登记就容易被补写成「依法如何」 | 列未闭合缺口，不引用任何未回源条文 |
| 4 | 可复现性两问皆否仍建 `examples/` | 用「有示例」暗示源文存在可照做流程 | 把「不建该目录」当负向产出登记，并写明两问判据 |
| 5 | 声明只写正文、不写 frontmatter | 跨端 / 跨文档口径漂移，`route` 档位与措辞不一致 | 档位、声明、缺口写进 frontmatter 与来源清单，正文只引用不重述 |

## 失败案例

**失败案例 1：prose 承诺未配判据，回归阶段才暴露**（本轮真实记录）。

`content-creation-three-rules` 在来源清单写有「教程层不出现课程名与课时编号」的承诺，V 门四视角 8 条攻击全部采纳，仍没有一条覆盖「课时编号是否出现在教程层」。落盘后运行品牌词与课时号机械扫描，`concepts/04-claims-and-boundaries.md` 命中：该篇把「次日 15:00 加餐直播、21 天进阶课程」复述进教程层，与来源清单的结构承诺自相矛盾。

- **失败根因**：承诺写在正文、判据没有与成对表逐行绑定，验收退化为人工审读。
- **处置**：改写该表格行为抽象描述，复扫至 0 命中；判据保留，不放宽为例外。
- **教训**：V 门的意见条数与采纳率不度量结构覆盖度；「声明 ↔ 判据」的对应关系才是可验收对象。

**失败案例 2：官方条款被外推到未指明的平台**（本轮已防御，故记为反事实失败侧）。

源文只说「抄封面抄标题」，未指明平台；若把回源得到的《微信视频号原创声明功能使用条款》直接写成通用法律判据，就会用官方口径给另一场景背书。本轮以 F-040 显式登记「视频号条款不裁定源文未指明的平台」，并把著作权法官方全文未取得列为未闭合缺口，不引用任何法条原文。

## 检验标准

- 成对表行数 = 产出项数；每行四列（声明 / 边界 / 证伪 / 判据）无空缺。
- 全部机械判据一次运行 0 红；红项均有对应产出改动记录。
- 缺口清单非空，或有「本次无未闭合缺口」的显式判定并附检索命令。
- 跨文档关键计数（事实条数 / 冲突项数 / 缺口项数 / 审查意见数）机械比对一致。
- 源文品牌、人名、课时号在产出层的扫描命中数为 0（若项目约定允许出现，须在成对表登记为显式例外并说明依据）。

## 早期预警信号

出现下列任一信号时暂停推进，回到「产出项是否可枚举 / 判据是否可运行」的前置判断，而不是继续补文档：

| 预警信号 | 可观察现象 | 暂停后动作 |
|---|---|---|
| 预警信号 1：声明写不出适用边界 | 成对表里「适用到哪个平台 / 时段」列反复留空 | 回到源文，确认平台与时点是否根本未指明；若是，改列缺口 |
| 预警信号 2：判据无法给出布尔结果 | 某条声明只能写「人工复核」，没有脚本或 grep 表达式 | 判定为 prose 承诺，降级为缺口清单或补写脚本 |
| 预警信号 3：红项被反复标为例外 | 同一判据连续多轮报红，处置都是「本次例外」 | 停止放宽，检查是否判据与产出项错配，或产出本身越界 |
| 预警信号 4：产出项持续增加但表不增长 | 教程篇数 / 章节数增加，成对表行数不变 | 回到步骤 1 重新枚举，禁止只在末尾补一句总括声明 |
| 预警信号 5：官方源被当成通用依据 | 引用了平台条款，源文却未指明平台 | 补适用边界行，或撤下该引用 |
| 预警信号 6：缺口清单长期为空 | 连续多次交付都写「无未闭合缺口」却无检索命令留痕 | 要求附检索命令与命中数，无留痕即视为未检查 |
| 预警信号 7：出现反目标用户/场景 A~D | 材料多源可交叉验证，或 CI 已强制绑定判据 | 停止套用本模式，按「反目标用户/场景分析」表最后一列切换范式 |

> 7 个信号均来自本轮与上轮实测的可观察现象，非同构推演；「何时不该用」优先于「怎么用」。

## 跨领域迁移示例

**软件发布说明**：每新增一个 API / 能力项，同步写一条「不兼容变更、不覆盖的平台或版本、已知限制」声明，并配一条 CI 检查扫描 changelog 与 deprecation 表；缺声明或声明未关联到能力项时，发布门拦截。此处产出项是 API，声明是「不覆盖什么」，判据是 CI 扫描——与本模式在知识包上的结构同构。该示例为同构推演，未实测。

## 三维去重裁决（入库前置）

按 `pattern-dedup-three-axis-ruling` 的四检索面留痕：文件名 Glob 命中 40 个候选；内容 Grep 覆盖「不覆盖 / 负向声明 / flagged / 单源 / 机械判据」；逐文档读 frontmatter 与主张；复盘报告内嵌模式核对到 `pattern-sedimentation-dedup-ruling-20261106.md` 的「另案处理」标记。

| 对比对象 | 作用对象 | 核心动作 | 层级 | 裁定 |
|---|---|---|---|---|
| `verification-scope-bounding` | 结论口径 | 写清「谁检查 / 查什么 / 截至何时 / 仍不覆盖什么」 | 结论层 | 不重复：不要求与产出项成对，也不要求机械判据 |
| `hermetic-isolated-verification` | 验证范围 | 划清两个验证面都不覆盖的部分 | 验证层 | 不重复：对象是验证活动，不是内容产出 |
| `blog-article-to-okf-bundle`（L3） | 博文→bundle 全流程 | 单源声明、`stale_after`、`status: flagged` | 全流程骨架 | 部分覆盖：本模式是其「产出决策」环节的窄补充 |
| `source-code-to-okf-wiki-workflow` | 源码→wiki | 「负向声明也是产出」 | 工作流 | 近邻：命题相近但对象限定在源码转 wiki，未做逐项配对与判据 |

**可证伪区分判据**：`verification-scope-bounding` 只要求每条结论写「仍不覆盖什么」；本模式额外要求「每新增一项产出，都有一条对应的声明 + 一条机械判据 + 一次落盘即跑」。在「只做结论口径限定、不做成对登记」的项目里，前者判合格、本模式判不合格——两者给出不同验收结果。写不出这条判据即默认判重复（本次已写出，故按策略 D 新建窄补充模式）。

**同轮被撤销的申报**：「基线先测 / 既有红与增量红分离」与「结构承诺配机械判据」两个候选，经三维比对与 `concepts/nav-co-registration`、`single-authority-declaration-alignment`、`pattern-dedup-three-axis-ruling` 等既有条目全同或近邻，按策略 C 回写，不新建。

## 案例与验证记录

- **案例 A（本轮）**：2026-11-05 公众号付费课程班主任课后复盘 → `content-creation-three-rules`（14 篇 / 40 条事实 / 719 束）。成对项包括 `route: chaptered-summary` ↔ 不逐字转录、去品牌化 ↔ 品牌词扫描、F-040 ↔ 平台适用边界、著作权法缺口 ↔ 不引用法条、不建 `examples/` ↔ 可复现性两问。V 门 6 条攻击采纳 5 + 部分 1；回归机械扫描抓到 1 处漂移并修产出。
- **案例 B（并行会话，同仓同谱系）**：`flagged` 单源访谈知识包的参数化路径扩展，要求每条推导配禁用条款与证伪条件；该命题被上一轮去重裁决挂起为「另案处理」。两案例同仓、同方法论、相邻日期，**不计为独立复用验证**。
- **升级条件**：第二个非同谱系案例（例如软件发布说明或数据报表口径）完整应用并复盘 → L1.5；另需一次独立第三方复核 → L2-validated。

## 不覆盖声明（本模式自身遵守）

- 本模式不替代 `verification-scope-bounding` 的结论口径四项限定，也不替代 `blog-article-to-okf-bundle` 的全流程骨架。
- 本模式不提供「声明写什么内容」的领域知识，只规定声明与产出项的**配对结构**与判据要求。
- 本模式不覆盖多源可交叉验证材料的证据分级方法。
- 检验标准中的扫描项为示例；具体词表须按项目约定配置，不内置固定词表。
