# 合规契约化（Compliance Contracting）

> 把合规红线从"态度"翻译成"可度量标准 + 显式声明"的审查契约，审查者照契约逐项打勾即可判定，无需理解合规背景。

## 一句话定义

产出物定稿前，把一切"要合规"的模糊要求翻译为数字/正则/清单可判定的契约条款，并以"标准 + 溯源 + 边界"三段式显式写入产出物；契约与产出同步演进，审查按契约打勾而非凭感觉。

## 触发场景

**适用于**：
- 有明确合规红线的产出物：版权引用、数据脱敏、许可证、隐私信息；以及需要区分"作者主张 vs 客观事实"的自助/灵性/健康类材料
- 产出物须经他人/下一阶段审查（V 审查、合规审校、客户验收）
- 合规约束曾因"模糊执行"出过问题（过度谨慎损失信息或失守红线）

**不适用于**：
- 无合规要求的内部草稿或一次性临时产物
- 红线本身尚在谈判中、无法定数的阶段（此时契约条款只能是"待定"，不得伪造确定性）

## 核心步骤（4 步）

1. **红线翻译**：把态度式约束（"尽量少引用""注意脱敏"）翻译成可度量标准——单条 ≤N 字、条数上限、合计字数、正则模式（`\d{11}`）、清单枚举。翻译不了的表述（"适量""合理"）视为未完成翻译，继续下钻直至可判定。**计数口径必须随标准一并定义**：是否计标点、占位符句式模板/通用口令/专有名称如何排除，须在契约中点名，否则同一句子在不同审查者手里得出不同计数。
2. **契约显式化**：以"标准（可度量）+ 溯源（可核验）+ 边界（使用说明）"三段式写入产出物索引页，声明在正文完成、实证统计后回填定稿（版权类落地模板见 [citation-redline-declaration-template](../../../../.agents/templates/citation-redline-declaration-template.md)）。
3. **契约同步**：产出物每次改写/增补，新增内容先过契约标准再入稿；发现不符时先收敛事实（改内容、去冗余引用），禁止放宽标准迁就现状；契约标准的任何变更必须留痕并能回答"为什么现在的标准和以前不同"。
4. **契约打勾**：审查者不按笼统感觉审，按契约逐项打勾；核验动作对接模式 [声明对账](../documentation-patterns/declaration-reconciliation.md)（实证对账是契约的执法机制）。

配套资产：复现检查清单 `.agents/checklists/compliance-contracting-reproduction-checklist.md`、复现报告模板 `.agents/templates/compliance-contracting-reproduction-report-template.md`、引用红线声明模板 `.agents/templates/citation-redline-declaration-template.md`。

## 检验标准（怎么知道做对了）

- 每条红线能回答"怎么判定越线"（数字、正则或清单，三者至少其一）；计数类条款附口径定义与排除项清单
- 审查者无需理解合规背景，照契约逐项打勾即可通过或指出具体违约项
- 契约修改可追溯（标准变更留了痕，能回答"为什么现在的标准和以前不同"）
- 涉及主观功效/玄学主张的材料，"作者主张"与客观事实在正文中分层可辨，健康/财务类边界声明在位

## 反模式（均来自实际教训）

1. **态度式合规**：以"尽量少引用"的模糊自我约束替代标准，结果两极摆动——要么过度谨慎损失信息，要么失守红线（反常识点：合规常被执行为态度而非契约）。
2. **先写声明后产出**：索引骨架阶段先把契约数字写进声明，正文未写完，契约沦为愿望（与 [声明对账](../documentation-patterns/declaration-reconciliation.md)反模式 1 同源）。
3. **契约不随产出演进**：改写引入新引用、新数据，契约条款滞留原状，审查者按过时契约打勾仍漏检；另一种变体是发现不符后反向放宽契约，把契约改成愿望。
4. **标准不可测**：契约条款使用"合理使用""适量引用"等不可判定词，审查者无法打勾，契约名存实亡。
5. **计数口径缺失**：标准写了"≤30 字、共 19 条"却没定义标点是否计入、模板句式/通用词/专名算不算——操作口令密集的练习册体裁会让口径分歧直接放大为合规争议（案例 2 实测）。
6. **主张与事实混写**：把作者的因果承诺、科学类比、健康功效转述成客观事实，构成版权之外的第二条红线；自助/灵性类材料尤其高发（案例 2 实测）。

## 跨场景迁移示例

- **数据交付**：契约"不含手机号"→ 翻译为正则 `\d{11}` 全表扫描可判定；溯源条款注明扫描范围与工具。
- **API 兼容性承诺**：契约"破坏性变更须主版本号递增"→ 版本 diff 对照变更清单可判定。
- **性能指标报告**：契约"p99 延迟 < 200ms"→ 压测报告数据可直接判定，无需解释"性能良好"。
- **自助/健康类出版物**：契约设两条轴——引用轴（条数/字数/页码口径）+ 主张轴（作者主张显式标注、保留"配合正规医疗"限定、财务练习加注非理财建议）。

## 与其他模式的关系

- **声明对账**：一对互补模式。本模式管契约**设计**（生产侧），声明对账管契约**核验**（审查侧）；契约是本模式产物，对账是执法机制。
- **摘要替代转录**：其步骤 5"合规声明契约化"即本模式在扫描版版权材料场景的落地实例。

## 验证记录

### 案例 1（2026-09-11，萃取源案例）

- 对象：扫描版财商寓言《管道的故事》转教程任务链；态度式"少引用"翻译为"单条 ≤30 汉字 + 逐条书页页码"三段式契约，V 审查实证对账拦截改写引入的冗余引用
- 详见 [pipeline-parable v1 复盘](../../../../playground/pipeline-parable/retrospective/retrospective-2026-09-11-pipeline-parable-v1.md)

### 案例 2（2026-09-11，独立复现——练习册体裁 + 双契约轴）

- 对象：《魔力》28 天练习手册教程（session `sc-20260911-the-magic`）
- 结果：四步骤完整复现——契约（19 条/合计 219 字/最长 26 字/14 个 PDF 页码清单）在正文完成后固化、S5 实测回填；显式定义计数口径（不含标点；4 处占位符句式模板、通用口令"谢谢"、练习名专名点名排除）；新增第二契约轴"事实—主张分层"（吸引力法则等标注"作者主张"，保留医疗与理财边界）；契约标准零变更，9 处字数不符全部先收敛事实
- 证据：[复现报告](../../../../playground/the-magic/retrospective/reproduction-report-compliance-contracting.md)、[S5 对账台账](../../../../playground/the-magic/retrospective/s5-reconciliation-ledger.md)
- 结论：跨体裁独立复现成功，计数口径与主张分层两条迁移经验补入核心步骤与反模式，升 L2

## 成熟度说明

L2（双案例验证）：萃取自扫描版书籍转教程的版权引用场景，并在操作咒语密集的练习册体裁（《魔力》）中独立复现成功；案例 2 同时验证了模式对"事实—主张分层"新红线类型的可扩展性。
