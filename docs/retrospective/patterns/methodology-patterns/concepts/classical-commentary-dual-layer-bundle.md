# 古典文本-现代阐释双层Bundle构建模式

## 触发条件

当出现以下任一或多个场景时，应采用本模式：

1. **同一主题双层结构**：存在一份古典文献原文（如《了凡四训》）及其现代阐释（如智然《了凡生意经》），需要分别构建两个独立OKF Bundle。
2. **三层文本分层需求**：需要区分古典层（原文）、经典层（被引用的古籍）、阐释层（现代解读），并在Bundle中明确标注每层的归属。
3. **跨Bundle交叉引用**：两个Bundle之间存在事实引用关系，需要通过F编号体系建立可追溯的交叉索引。
4. **信源隔离**：原文层和阐释层使用不同信源（古籍底本 vs 音频课程），需要在各自的references目录独立登记信源。
5. **分组内导航**：两个Bundle需要纳入同一分组（如 `guoxue/liaofan/`），并在分组索引中统一展示。

## 核心步骤

### 阶段R：事实采集（两Bundle并行独立）

**目标**：分别对古典层和阐释层进行零推测事实采集，建立独立的事实清单。

**操作步骤**：

1. **确定F编号起点**：
   - 先完成古典层Bundle的事实采集（编号F-001起）
   - 统计古典层事实总数N
   - 阐释层Bundle事实从F-(N+1)起编号，避免冲突
   - 例如：古典层F-001~F-031（共31条）→ 阐释层从F-051起（跳过F-032~F-050预留扩展空间）

2. **古典层Bundle事实采集**：
   - 识别所有原文段落（篇/章/节）
   - 每条事实需包含：段落定位、原文引用、信源ID
   - 补充版本信息（成书时间、作者生平、序跋信息）
   - 补充文本统计（总字数、各篇估算字数）

3. **阐释层Bundle事实采集**：
   - 识别课程/书籍结构（讲次/章节）
   - 每条事实需包含：讲次定位、核心观点、对应原文段落
   - 明确标注"智然老师阐释"而非原文内容
   - 区分原文事实（引用古典层F编号）与阐释事实（新编F编号）

**质量门**：
- 古典层与阐释层事实清单完全独立，编号不重叠
- 每条阐释事实标注是否引用了古典层F编号
- 信源ID在各自Bundle的references/sources.md中独立登记

### 阶段E：批量生成（两Bundle独立执行）

**目标**：按映射方案并行生成两个Bundle的目录结构和文档。

**操作步骤**：

1. **目录结构**：
   ```
   guoxue/liaofan/
   ├── yuan-liaofan-sijun/          # 古典层Bundle
   │   ├── index.md                  # OKF类型Bundle导航
   │   ├── facts.md                  # F-001~F-031
   │   ├── concepts/                 # 原文概念文档
   │   └── references/               # 古典层信源登记
   └── liaofan-shengyi-jing/        # 阐释层Bundle
       ├── index.md                  # OKF类型Bundle导航
       ├── facts.md                  # F-051~F-070
       ├── concepts/                 # 阐释层概念文档
       └── references/               # 阐释层信源登记
   ```

2. **分组索引更新**：
   - 在 `guoxue/index.md` 中添加两Bundle的导航行
   - 在 `bundles/index.md` 中更新统计数字

3. **交叉引用规则**：
   - 阐释层概念文档引用古典层事实时使用 `[F-xxx]` 格式
   - 阐释层概念文档中的"对应原文"说明应指向古典层概念文档
   - 古典层概念文档不反向引用阐释层F编号（单向引用）

**质量门**：
- 两个Bundle的目录结构完整（index/facts/concepts/references）
- 两个Bundle的frontmatter字段格式一致
- 交叉引用编号均已在facts.md中定义

### 阶段V：独立验证

**目标**：对两个Bundle分别进行完整验证，并检查交叉引用一致性。

**验证维度**：
1. **编号独立性**：Grep确认古典层F编号范围与阐释层F编号范围无交集
2. **交叉引用有效性**：阐释层概念文档中所有 `[F-xxx]` 引用均指向对应Bundle的facts.md
3. **信源独立性**：两个Bundle的references/sources.md各自完整，无遗漏信源
4. **分组导航完整性**：guoxue/index.md包含两Bundle的toctree条目

## 反模式

1. **F编号重叠**
   - 错误做法：古典层和阐释层共用F-001起编号，导致不同事实被赋予相同编号
   - 后果：交叉引用歧义，读者无法判断[F-014]是指原文事实还是阐释事实
   - 正确做法：先完成古典层全部事实采集，再按F-(N+1)起为阐释层独立编号

2. **阐释混入原文**
   - 错误做法：在古典层Bundle的概念文档中混入现代阐释内容，未明确标注"智然老师阐释"
   - 后果：读者无法区分原文与现代解读，古典层Bundle失去"原文忠实呈现"的用途
   - 正确做法：古典层Bundle仅包含原文事实和原文概念；阐释层Bundle才包含现代观点

3. **信源ID重复使用**
   - 错误做法：两个Bundle共用同一个信源ID（如都用`source-cfolu-liaofan`）
   - 后果：难以区分同一URL在不同Bundle中的用途差异（原文底本 vs 阐释参考）
   - 正确做法：每个Bundle在自己的references/sources.md中独立登记信源，即使URL相同也分别登记

4. **子目录index.md添加frontmatter**
   - 错误做法：在`concepts/index.md`等子目录索引页添加type/title等frontmatter字段
   - 后果：子目录index是纯导航页，frontmatter会被误识别为独立文档条目，导致Sphinx构建警告
   - 正确做法：子目录index.md不包含任何frontmatter，直接从H1标题开始书写导航内容

5. **忽略旧编号残留**
   - 错误做法：重编号后未验证旧编号在两个Bundle中均已清零
   - 后果：旧编号F-032~F-050在概念文档中仍作为交叉引用存在，与新facts.md定义冲突
   - 正确做法：重编号后使用Grep在整个Bundle目录搜索旧编号范围，确认返回"无匹配"后再标记完成

6. **facts.md补充顺序错误**
   - 错误做法：先生成概念文档再补充facts.md，导致概念文档引用未定义的事实编号
   - 后果：交叉引用指向不存在的事实，验证阶段发现大量未定义引用
   - 正确做法：先完成facts.md全量事实采集（包括补充缺失章节），再生成概念文档

## 迁移验证

本节说明另一个人（或另一个团队）如何按照本模式独立完成一次古典-阐释双层Bundle构建任务。

1. **读取本模式和OKF规范**：完整阅读OKF v0.2 Bundle结构规范和本模式，理解双层Bundle的目录约定和F编号隔离原则。
2. **确定编号起点**：若已有同类古典Bundle存在，查询其facts.md最大F编号，确定本任务阐释层的起始编号（建议跳过若干编号预留扩展空间）。
3. **R阶段并行采集**：分别对古典层和阐释层进行事实采集，古典层用F-001起，阐释层用预设起始编号起。
4. **E阶段独立生成**：两个Bundle独立生成目录结构和文档，交叉引用仅在阐释层指向古典层（单向）。
5. **V阶段交叉验证**：重点验证F编号无重叠、交叉引用均有效、分组索引已更新。

## 适用范围与边界

**适用于**：
- 古典文献（明清善书、儒家经典、佛道典籍等）及其现代阐释的OKF Bundle构建
- 存在"原文+解读"双层结构的任何主题知识包

**不适用于**：
- 仅有原文无现代阐释的单层Bundle（使用`batch-docs-to-okf-bundle-conversion`模式）
- 同一原文的多版本对照Bundle（如敦煌本vs宗宝本，使用版本对照模式）
- 纯现代著述无古典底本的知识包（使用常规OKF Bundle构建模式）

## 案例

本次案例：`guoxue/liaofan/` 下两个Bundle的构建。
- 古典层：`yuan-liaofan-sijun/`（F-001~F-031，共31条事实）

- 关键修复：编号冲突发现后重新编号阐释层（F-032~F-050 → F-051~F-070），并验证旧编号清零
