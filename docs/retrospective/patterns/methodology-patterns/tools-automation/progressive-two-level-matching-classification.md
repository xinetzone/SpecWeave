# 先强后弱两级匹配分类

## 模式概述

当面对**大批量文本/文件**需要按类别分拣、且无法一次性准确全部分完时，放弃"一次性写全规则"的默认做法，改用"高置信度先行、低置信度遗留后用更丰富特征回捞"的递进策略：第一轮只做高置信度精确匹配立即归入目标类别，统计遗留项；第二轮针对遗留项做特征放大（正则模式、领域词典、作者库、N-gram 高频词）后再回捞。

**核心洞察**：规则库是迭代收敛的产物，而非一次性设计完备的产物。第一轮强关键词覆盖 68.6%，剩余 667 本恰恰需要第二轮用更高维特征才能再分 42%——一次性设计全部规则属于过度工程，边际收益在低置信区间急剧递减。

## 问题场景

一次性穷尽规则做分类/分拣时常见的失败模式：

1. **一次想写全规则**：第一轮就试图穷尽所有关键词与正则，规则库庞大且互相冲突，仍只能缓解首轮覆盖，低置信区间反复调参收效甚微
2. **直接拿原始文本匹配**：格式噪声（书名号、`[精品]`标签、版次后缀、扩展名）同时造成关键词误判与漏判，匹配准确率与召回率双降
3. **匹配规则越宽泛覆盖越全**：宽泛正则/单字符短词带来大量跨域误分类，在无人工复核的批量场景下，误判成本远高于漏判成本

## 解决方案

### 核心做法（9 步）

1. **全量枚举基线**：先导出完整文件名/文本清单，记录总数作为守恒校验基线
2. **清洗与匹配解耦**：编写独立 `clean` 函数统一剥离格式噪声（扩展名、标签、冗余后缀），匹配逻辑只消费清洗后的文本，禁止内联清洗
3. **第一轮强关键词精确匹配**：只放高置信度精确关键词（含领域词典、作者库），命中即归入目标类别，同时记录命中的关键词与匹配类型
4. **统计遗留项**：未命中项全部留在"其他"暂存区，列出清单，计算首轮分类率
5. **高频词分析发现遗漏**：对遗留项做 N-gram（bigram/trigram）高频词统计，识别未被规则覆盖的分类信号
6. **第二轮丰富特征回捞**：据高频词结果补充正则模式、作者库、短语规则，对遗留项二次匹配，返回匹配类型（strong/regex/none）便于审计
7. **执行与守恒校验**：先 dry-run 预览移动结果，执行后统计各目录计数，总和必须等于基线总数
8. **抽查验证准确率**：对每个类别（尤其高占比类别）随机抽样核对无跨域误判
9. **边界收窄**：两栖关键词消歧、正则加排除词、短词加词边界、精确关键词与正则分表管理

### 匹配类型与置信度分层

| 层级 | 匹配类型 | 置信度 | 内容 |
|------|---------|--------|------|
| 第一轮 | strong（精确关键词） | 高 | 精确关键词 + 领域词典 + 作者库 |
| 第二轮 | regex（正则模式） | 中 | 短语模式 + 排除词 |
| 暂存 | none | 未分 | 留在"其他"，供审计/人工处理 |

## 适用场景

- ✅ 大量文本/文件需按类别分拣，且无法一次性准确全部分完
- ✅ 分类对象携带格式噪声（标签、后缀、书名号等）
- ✅ 允许存在"未分类/其他"暂存区，容忍部分难例遗留
- ✅ 追求高准确率（宁可漏判，不可错判）而非高召回
- ❌ 需要 100% 全覆盖、无法容忍任何遗留项
- ❌ 分类规则本身已稳定且简单（单轮即可分完）
- ❌ 需要语义理解（同义词/上下文）才能正确分类的难例

## 反模式

### ❌ 反模式1：一次想写全规则

第一轮就穷尽所有关键词与正则，导致规则库庞大且互相冲突。应"先强后弱"分层，首轮只做高置信精确匹配。

### ❌ 反模式2：正则通配符混入精确关键词列表

在精确关键词列表里混入 `打造.*团队` 这类通配符，既引发语法歧义又破坏"精确匹配"的高置信度假设。应分离为独立正则规则。

### ❌ 反模式3：过宽的单字符/短词匹配

用单字符（如 `C`）做匹配导致大规模误分类。短词必须进正则并加词边界 `\b`。

### ❌ 反模式4：两栖关键词不去歧

同一关键词命中多个类别时不消歧，导致同一对象被多个规则争抢、错分。发现两栖关键词必须先消歧再入规则。

### ❌ 反模式5：过宽正则无排除词

`思维.*模型` 这类宽正则误吸跨域内容。正则必须附排除词列表。

### ❌ 反模式6：执行后不做守恒校验

移动文件后不统计各目录总和与基线对照，可能出现静默丢失或重复却无感知。

## 检验标准

做完之后怎么知道做对了？

- 分类率首轮 ≥ 60%，两轮后 ≥ 80%
- 执行后各目录计数总和 = 基线总数（文件守恒）
- 随机抽样 ≥ 30 本核对无跨域误判
- dry-run 预览结果与实际执行结果一致
- 每个匹配结果可追溯到命中的关键词与匹配类型（strong/regex/none）

## 迁移示例

这个模式还能用在什么其他场景？

```python
# 通用两级匹配分类骨架（伪代码）
def classify(text):
    t = clean(text)                      # 步骤2：清洗解耦
    for kw, cat in STRONG_KW.items():    # 步骤3：精确关键词
        if kw in t:
            return cat, kw, 'strong'
    for cat, pattern in REGEX_RULES:     # 步骤6：正则模式
        if pattern.search(t):
            return cat, pattern.pattern, 'regex'
    return '其他', None, 'none'          # 步骤4：遗留

# 非 EPUB 场景迁移：只需替换 clean() 的噪声词典与 STRONG_KW/REGEX_RULES
# 可复用于：邮件自动分箱、客服工单分类、评论情感分类、日志告警分类、电商商品归类
```

## 实际案例

### 案例1：EPUB 电子书分类（2026-08-19）

**背景**：2121 个 EPUB 电子书文件散放，需按 19 个类别归类。

**使用"先强后弱"策略**：
1. 首轮强关键词精确匹配 → 分类 1454 本（68.6%）
2. 遗留 667 本集中在"其他"目录
3. `clean_title` 清洗 + 正则 + 作者库 + N-gram 高频词回捞 → 再分 280 本
4. 两轮后分类率提升至 81.8%（1734/2121），目录计数总和与基线一致
5. 剩余 387 本难例（短书名/跨域书）留待元数据或语义分类

**反模式印证**：过程中踩了正则语法错误、单字符过度宽泛、两栖关键词冲突、过宽正则误匹配、通配符混入强关键词等 6 类坑，全部归入本模式反模式。

## 边界与选型

**什么时候不应该用这个模式？**
- 分类对象数量小（<50），人工分拣更快
- 规则简单且稳定，单轮即可分完
- 无法容忍任何遗留"其他"项，要求 100% 覆盖

**什么时候必须用？**
- 大批量（成百上千）文本/文件分类
- 分类率首轮卡在 60%-70% 区间，继续加规则边际收益递减
- 格式噪声严重，直接匹配准确率不达标
