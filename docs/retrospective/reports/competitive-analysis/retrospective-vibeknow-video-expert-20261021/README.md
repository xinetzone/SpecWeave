# VibeKnow 视频专家全面调研报告：产品能力、Agent 原生 CLI、商业化定价与合规风险

> **方法论**：七概念编排 **R（事实）→ I（洞察）→ E（萃取）→ V（对抗审查）→ C（原子提交）**。R 阶段采集可验证公开事实 **106 条**（PRO-01~25 产品功能、TEC-01~31 技术与 CLI、COM-01~25 商业化与竞品、RP-01~25 主体口碑与风险，见附录 A~D）；I 阶段形成 4 条四元组洞察；E 阶段沉淀 [Agent 原生 CLI 扣费-授权-续跑三元契约](../../../patterns/methodology-patterns/tools-automation/agent-cli-charge-authority-resume.md)；V 阶段 4 视角 10 条意见全部处置（采纳 9、部分采纳 1）；C 阶段单次原子提交交付。
> **评估范围**：产品功能矩阵与可编辑性、官方开源 CLI 的 Agent 原生工程契约、双站点商业化定价与单位经济、运营主体与合规/司法风险、公开证据强度。
> **非评估范围**：付费账号实测成片质量、真实积分消耗与服务稳定性压测、服务端实现逆向、竞品性能横评。
> **证据分级**：官方/监管司法来源 > 权威媒体 > 第三方目录与评测 > 厂商自述；凡仅厂商/官方自述数据，全文标注「厂商口径」；第三方评分与目录收录仅作**旁证**，不与官宣等权对冲。
> **时点声明**：全部事实采集于 **2026-10-21**。VibeKnow 英文站自述 2026-04 公开上线（COM-19），CLI 最近一次 push 为 2026-09-09（RP-13），本报告结论的**有效期窗口约 90 天**，过时须按第十二章清单复核。

## 一、执行摘要（结论先行）

**结论**：VibeKnow 是中文「文档 → 知识讲解视频」赛道中**工程契约最完整、证据链最薄弱**的一类产品。它的产品内核不是"生成模型"而是**「可编辑的流水线 + 批量产能 + 可分享的交付形态」**（PRO-11~PRO-14/PRO-24）；它的技术内核是**一套面向 Agent 的 CLI 契约**——两阶段 Device Flow、语义化退出码、SSE 四阶段进度流、Agent Skills 规范、MIT 许可零依赖 Go 二进制（TEC-01~TEC-31）；它的商业内核是**积分三态 + 双站点双计价**（COM-01~COM-08/COM-24）。但支撑其规模叙事的证据几乎全部为**厂商单源自述**：50,000+ creators、4.5/5 独立评测均分、7+ 目录收录三条对外口径均无独立复核（COM-19/E-8/E-9/G-6），而独立第三方记录中**没有一条 G2/Capterra/TrustRadius 评测**（RP-21），中文社区一手用户内容几乎为零（G-1/G-2）。六维加权自评 **65/100**。

**推荐场景**

- **中文长文档批量转讲解视频**（教材、图书配套、课程、出版物）——可编辑脚本 + 单帧换背景/换图 + 批量并发 + 系列视频自动编号构成完整生产链路（PRO-12/PRO-13/PRO-24/PRO-06）。
- **课件 / PPT 逐页还原**——`replica` 模式逐页还原，母版与配色保留，CLI 与 Web 双通道（PRO-06/TEC-07/TEC-16）。
- **Agent 编排下的批量内容生产**——CLI 契约是同类产品中罕见的完整度：SSE 四阶段进度、语义化退出码、`--async` 异步契约、TTY 自动切换 JSON、Agent Skills 兼容 55+ 运行时（TEC-05~TEC-06/TEC-11~TEC-13/TEC-29）。**前置条件**：须先核验 RP-15 的 3 条 open issue 是否已闭环。
- **对 Agent 原生 CLI 契约做技术借鉴**——本报告 E 阶段萃模式即以该产品为主要案例源。

**不推荐 / 需谨慎的场景**

- **需要 4K 导出、自有品牌 Logo/字体、团队协作审核流的团队**：官方口径与第三方评测互斥（PRO-23/E-6/G-8），digitalizelife 明确记 "no AI avatars or talking heads, no custom branding options, no team collaboration or review workflow"（RP-19），官网团队版入口实际为「敬请期待」（PRO-24）。
- **需要企业批量 API / SLA / 发票流程的采购**：FAQ 声明提供 API（PRO-25/COM-14），但「还没开放批量 API」（PRO-24）、团队版路径 404（E-5）、团队版价格与坐席数未公开（COM-14）。
- **涉个人声音/形象克隆且对外公开发布**：声音克隆可用（PRO-18/PRO-19），但需同时满足 AIGC 标识义务（RP-24）与声音权益司法口径（RP-25：上海首例二审维持原判、赔 5 万、**举证责任转移至平台**）。
- **把厂商成本口径当 ROI 依据**：「3 分钟 ≈16 元 vs 外包 ¥5,000 起」（COM-10/RP-22）为**厂商自述对照**，未经实测，不可进采购模型（见 Q-1）。

**核心行动建议**：把 VibeKnow 当作**「中文知识内容批量视频化」的工程化样本**看待，能力面可用、证据面不可用——选型决策必须以**自测**（Q-1/Q-5/Q-7）而非官方页面为准；引用任何体量数字前执行 [社区指标三查法](../../../patterns/methodology-patterns/governance-strategy/community-metric-triple-check.md)（口径/时点/独立性）。

## 三、评估方法

按六个可打分维度组织评估；每个维度依据均挂事实编号，打分为评估者主观判断（1–5），权重公开可替换重算，**非基准测试、非市场份额统计**。

| 维度 | 权重 | 打分锚点 |
|---|---:|---|
| 产品能力完整度与可编辑性 | 20% | 输入覆盖面、模式矩阵、脚本/画面/字幕可编辑粒度、批量与系列能力 |
| Agent 原生工程化 | 20% | CLI 契约完备度（认证/退出码/进度流/输出模式）、许可与依赖、Skill 生态、缺陷闭环 |
| 定价可预测性与单位经济 | 15% | 档位与权益透明度、积分规则、附加成本、跨站一致性、退款与抵扣 |
| 主体稳定性与合规风险 | 20% | 主体可核性、融资与团队、司法与监管约束、协议一致性 |
| 证据强度与口碑可核性 | 15% | 独立信源占比、一手用户内容、第三方评测独立性、客观使用数据 |
| 生态与集成开放度 | 10% | API/批量能力、团队与企业能力、第三方集成与可扩展性 |

### 4.1 分组概览（明细与来源 URL 见附录）

- **A 发布形态与工程基线（TEC-01~04）**：Go + v1.25、MIT、npm v0.9.2 / 18 版本 / 0 依赖；中英双 README；「one command, zero editing skills」定位。
- **B Agent Skills（TEC-05~06）**：`skills/` 目录按 agentskills.io 规范提供 vibeknow-core / vibeknow-create / vibeknow-doc；`npx skills add vibeknow/cli` 自动探测本地 agent 并 symlink；声明兼容 55+ 运行时。
- **C 认证与凭证（TEC-07~10）**：两阶段 Device Flow（`--no-wait` 输出 JSON → 人类浏览器批准 → `--device-code` 续轮询），交互按**每个 token 一次**计；凭证优先级 `VIBEKNOW_TOKEN` > OS keychain；4 个环境变量；`auth status --output json` 含 `pending_authorization` 态。
- **D 流水线与退出码（TEC-11~15）**：SSE 四阶段 outline→tts→render→publish + NDJSON 机器可读形态；**exit 6 = `wait_budget_expired`（语义为「继续等待」）**、exit 7 = 渲染失败；`--async` 秒级返回且「打印 task_id 即代表 run 已启动」；默认停在 preview 输出 `share_url`，export 需数分钟并额外消耗积分。
- **E 模式与引擎（TEC-16~19）**：replica / image / handdraw；`--script-lock` 逐字朗读可叠加任意模式；`--engine agent`(v2) / `--engine pipeline`(v3 默认)。
- **F 数字人/字幕/知识库（TEC-20~24）**：`avatar-retry` 标注免费、`edit --script-only` 更省积分；字幕以**预设**（白字黑底 / 白字黑边）组合表达可读性；`kb prune` 默认 dry-run，需 `--yes` 才实删。
- **G Profile 与安全（TEC-25~29）**：多环境 profile + per-service 端点覆盖 + 信任级别 + 生产标记；`doctor` 诊断；五项安全设计（keychain、ANSI 清理、日志脱敏、非生产端点信任边界、per-service 独立鉴权）；`api call` 原始逃生通道；非 TTY 自动切 JSON。
- **H 预设包与扣费防护（TEC-30~31）**：preset 为 YAML 默认值集（mode/aspect/theme/voice/language/bgm/avatar 位置），命令行显式参数优先；**preset 不得携带 `--export` / `--yes` / `--confirm`**，目的是「打开他人 preset 永远不会批准一笔扣费」。
- **I 输入与规格（PRO-01~05）**：50M/文档字数分档/按格式分派解析策略（PDF 判扫描版自动 OCR、Word 按段落分镜、PPT 优先备注讲稿、链接抓正文忽略广告）。
- **J 模式与引擎（PRO-06~10）**：7 个 Web 模式与 4 个 CLI 模式；两套引擎；16:9 / 9:16 双画幅；官网自动完成环节（脚本拆解/分镜/画面/配音/BGM/精剪）与 CLI SSE 四阶段的对应关系。
- **K 交付与可编辑（PRO-11~14）**：Preview/Export 两阶段；脚本面板编辑后「重新生成」次数无限制；单帧换背景/换图片与字幕样式编辑器；`avatar-retry` 不额外扣费、`edit --scene N` 不可撤销。
- **L 数字人与声音（PRO-15~19）**：数字人 ID 体系与位置尺寸；档位专属数字人 1/3/5 位；克隆流程「选风格 → 生成 demo → 待激活 → 激活后可用」，`/preview/digital-avatar` 标注「即将上线」；声音克隆 30 秒样本、857/686 积分、90 天有效。
- **M 模板与资产（PRO-20~23）**：100+ 模板；创作资产模块（数字人/系列封面/风格/声音/Logo/连接器）；水印为会员功能；**分辨率口径冲突**（1080p–4K vs 最高 1080p）。
- **N 批量团队与 API（PRO-24~25）**：并行 1/5/50/不限；团队版「敬请期待」；「还没开放批量 API」；FAQ 声明提供 API + `sales@vibeknow.com`；设置内「API 密钥」标签页与团队密钥归属；`vibeknow api call` 原始调用。
- **O 中文站定价（COM-01~11）**：三档价（连续订阅/月付）、月积分与周赠、并行档位、数字人位数、克隆积分规则、加油包四档、**积分三态**定义、发票与客服档位、注册送 400 积分不绑卡、「≈16 元/条 vs 外包 ¥5,000 起」厂商口径。
- **P 场景与案例（COM-12~14）**：官方 FAQ 场景清单与「批量生产为核心能力之一」；出版社/博主/教师三则用户自述案例；团队版入口存在但价格未读到。
- **Q 英文站（COM-15~20）**：Free $0 / Plus $29 / Pro $79 / Max $199；credits 1,128+100/日、4,000+150/日、10,000+300/日；产出条数 2–3/8–10/45–55/140+；官方「vs 外包 vs 自制」对照表；四条厂商自述体量口径。
- **R 第三方目录（COM-21~25）**：12 家目录收录与定位/评分；竞品对照（HeyGen $29 / Synthesia $29 / Pictory $23 / 剪映免费）；推广合作测评自述；双站计价体系差异；运营主体与石榴 AI 同主体。
- **S 主体与融资（RP-01~05）**：工商登记全要素；36氪 2024-10-30 首发（沈仁奎为原得到/罗辑思维 CTO）；天使轮 1000 万；招聘页客户名单（人教社/高教社/清华/浙大/中传/阿里/金山/知乎/得到/当当）；同主体备案的 shiliu.cool / figlen.com。

## 五、洞察（I 阶段·四元组）

### 洞察 1：可编辑性与批量产能是差异化，生成质量是行业共性红海

- **陈述**：VibeKnow 的可核优势集中在**「改」的粒度与**「并行」的规模**两处——脚本面板可改字/删段/调序/加段/改语气并同步重生成画面与配音且次数无限制，单帧可换背景/换图片，字幕样式可逐段控制显隐并存为模版，数字人位置尺寸可拖拽并一次性应用到全部页；并发档位为 1/5/50/不限，支持系列视频自动编号与项目空间连续出片。与之对照，全部第三方负面评价集中于**生成质量本身**（"机械的、刻板的"、"分不清重点和非重点"、"声线过于 AI"、"画面有时不够精准"、"配音在专业术语、数字、人名上偶尔出错"），而全部第三方正面评价集中于**省事、便宜、可批量**。即：生成质量是这条赛道所有玩家的共同红海，可编辑性与批量产能是 VibeKnow 相对突出的落点。
- **证据**：PRO-12/PRO-13/PRO-24/PRO-06/PRO-15（可编辑性与批量）；RP-16/RP-17/RP-19（生成质量负面）；RP-18/RP-22/COM-23（省事便宜正面）；PRO-04（制作 3–8 分钟、镜头 10–30 个）。
- **反常识**：一条广受好评的产品，负面口碑全部落在"AI 味"上——而"AI 味"是**全行业不可差异化项**。把可编辑性当卖点、把首条出片质量当卖点，恰好是选型时最容易被误导的两个位置。
- **行动**：评估同类产品时把**首条出片质量**降级为"合格线"（低于线直接淘汰即可），把**「改一稿的成本」**（改一句旁白要重跑多少、能否只重跑配音、画面能否单帧替换）提为第一权重评估项；本产品具体落到 Q-1/Q-5/Q-7 三项实测。

### 洞察 2：收费点被刻意放在"不可逆"动作上，扣费防护写进了配置文件契约

- **陈述**：VibeKnow 的流水线默认停在 **preview** 阶段并输出可直接在浏览器播放的 `share_url`，导出 MP4 是**另行触发、需数分钟、额外消耗积分**的独立动作；生成阶段的计费由积分三态（活动积分可能过期/订阅积分仅当期有效/购买积分长期有效）承载；重试侧把**失败数字人页的 `avatar-retry` 标注为免费**、`edit --script-only` 标注为更省积分；安全侧把「preset 不得携带 `--export`/`--yes`/`--confirm`」写成 CLI 契约的硬约束，理由写明是"打开他人 preset 永远不会批准一笔扣费"。即：它把**「可逆且可分享」与「不可逆且计费」拆成两级**，并对后一级设置了跨信任边界的防护。
- **证据**：TEC-15（默认 preview / export 额外计费）、PRO-11（两阶段交付）、COM-08（积分三态）、TEC-21（avatar-retry 免费）、TEC-24（--script-only 更省）、TEC-30/TEC-31（preset 默认值语义与三条禁带开关）、TEC-23（kb prune 默认 dry-run）。
- **反常识**：主流 SaaS 的免费分享是**获客钩子**，把不可逆的"下载"留作收费点；VibeKnow 反过来把"生成"与"导出"解耦，让分享页成为**默认终点**。同时，`--export` 被禁入 preset 这一条，把"配置文件"从"快捷方式"重新定义为"**不可信输入**"——这在 CLI 设计里并不常见。
- **行动**：把「可逆/不可逆动作分级 + 配置文件不可携带授权型开关」作为任何 Agent 可调用 SaaS CLI 的设计准则（已萃取为模式 `agent-cli-charge-authority-resume`）；评估时优先核验"重试是否计费""导出是否二次计费""共享配置能否越权触发付费"三项。

### 洞察 3：面向 Agent 的 CLI 把"可续跑中间态"提升为一等退出码语义

- **陈述**：官方 CLI 在多处显式为 Agent 场景做契约设计——认证采用**两阶段 Device Flow**（`--no-wait` 先吐 JSON，人工在浏览器批准后 `--device-code` 续轮询，README 声明交互次数为**每个 token 一次**而非每个命令一次）；`video wait --for 90s` 在等待预算耗尽时以 **exit 6 + 理由 `wait_budget_expired`** 返回，语义为「继续等待」，与 exit 7（渲染失败）区分；`--async` 在后端确认 run 已 live 后秒级返回，README 声明「**打印出 task_id 即代表 run 确已启动**」；输出格式在非 TTY 环境自动切 JSON 并可显式覆盖；SSE 进度流同时提供人读进度条与机器可读 NDJSON 两形态；`skills/` 按 agentskills.io 开放规范提供三个技能并支持 `npx skills add` 自动 symlink 至 55+ 运行时。
- **证据**：TEC-07/TEC-10（Device Flow 与 pending_authorization）、TEC-12（exit 6/7）、TEC-13（--async 契约）、TEC-11（SSE + NDJSON）、TEC-29（TTY 自动切换）、TEC-05/TEC-06（Agent Skills 与 55+ 运行时）、TEC-27（安全设计五项）、TEC-25/TEC-26（profile 与 doctor）、TEC-28（api call 逃生通道）。
- **反常识**：主流 CLI 退出码约定是「0 成功 / 非 0 失败」，非零即终止。VibeKnow 用**非零退出码表达"可恢复中间态"**——把"我没等够，不是失败"编码成退出码而不是日志文本；这是把 Unix 约定从"结果码"扩展为"状态码"。另一处反常识在于，认证交互按**令牌**而非按**命令**计费（每个 token 一次），等于承认 agent 会连续发多条命令，人类交互不能按命令数线性放大。
- **行动**：把"终态失败"与"可续跑中间态"在 CLI 里显式分开，是任何把长任务交给 agent 执行的产品的基线要求；本产品侧的落地风险是 RP-15 记录的 3 条 open issue（其中 #10 直接质疑 async 与 wait 的可用性、且称 wait 在无事件时**静默退出 0**），须在采用前核验（Q-6）。

### 洞察 4：对外体量叙事全部落在厂商单源，客观使用数据却指向另一个量级

- **陈述**：英文站对外的体量叙事由四条自述构成——「50,000+ creators」「Apr 2026 public launch」「4.5/5 average across independent reviewers」「7+ independent AI tool directories featured」，其中"4.5/5 均分"未点名任何评测站点（可核独立评分为 AIxploria 4.5/5 与 digitalizelife 3.5/5，两者不同），"7+ 目录"实际可点开验证的为 4 个（另有 AIHub、9200、watcha 等中文站收录共 12 家）。第三方目录 aitoolsatlas 明确记录"截至 2026-05 无 G2 / Capterra / TrustRadius 等任何第三方评测、无公开用户数、收入与融资披露"。中文社区一手用户内容几乎为零（G-1/G-2）。而**客观可测**的工程侧数据是：GitHub 仓库 stars 9 / forks 0 / 3 条 open issue 且三条同账号同日创建、最后 push 2026-09-09；npm 累计下载 3562 次，峰值 2026-08-27 的 468 次。
- **证据**：COM-19/E-8/E-9/G-6/RP-21/G-1/G-2（自述与旁证）；RP-13/RP-14/RP-15（客观工程数据）。
- **反常识**："多来源"在这里不成立——12 个目录收录里多数是互相转载同一段简介，评论账号形态为 persona-XXX 且 Q&A 文案与官网 FAQ 逐字重合（G-9），URL 有 12 个，**独立信源仍接近 1 个**。反方向的误读也要避免：npm 下载量与 GitHub stars 只覆盖**CLI 渠道**，不能用来否定 Web 产品的用户体量——两个口径范围不同，不可互推。
- **行动**：把"厂商自述体量"与"客观使用数据"分列为两条独立证据轨，**不做合并、不做对冲、不做换算**；对体量类结论一律降级为"未经独立核验"；采购或对外材料引用前先执行三查法（口径/时点/独立性）。本报告 65 分中「证据强度与口碑可核性」仅给 2/5，即源于此。

**与既有模式的边界**：已有 [CLI 即 API 设计](../../../patterns/code-patterns/cli-as-api-design.md) 覆盖「多格式输出 ⊕ 结构化错误 ⊕ 退出码约定 ⊕ 会话持久化」四要素；本模式**不重复**该四要素，只在其上增加**「扣费-授权分离」**维度（哪些动作计费、哪些授权不可被配置文件携带），并把「可续跑中间态」从一般退出码约定提升为**独立一等语义**。

**三元契约（6 步）**：①**分级动作**（可逆可分享 / 可逆计费 / 不可逆计费三级，收费点只落在不可逆级）→ ②**分离授权**（授权型开关禁入可共享配置文件，配置文件仅提供默认值）→ ③**分离人类交互**（人类交互按令牌/会话计，不按命令数计；两阶段授权协议）→ ④**编码可续跑**（为"未等够"这类中间态分配专属非零退出码，与终态失败区分）→ ⑤**声明启动语义**（异步返回时明确"打印 X 即代表已启动"的可验证锚点）→ ⑥**豁免重试与降级动作**（失败重试、仅重配音等局部动作不重复计费，且默认 dry-run）。

**反模式（6 个）**：把付费动作写进可共享配置；用同一个非零码表达"失败"与"还没好"；人类授权按命令数重复索取；异步返回不留可验证启动锚点；失败重试全额计费；破坏性操作默认执行不需 `--yes`。

**检验标准**：六问——①（Q1 扣费可达性）任何一个会产生费用或不可逆副作用的命令，能否在**不开命令行显式开关**的情况下被触发？②（Q2 退出码可区分性）非零退出码是否能被下游无歧义区分「终态失败」与「可续跑中间态」？③（Q3 交互次数）一个人类 token 最多需要几次交互、是否与命令数解耦？④（Q4 重试计费）失败重试与局部重做是否计费、破坏性操作是否有 dry-run 兜底？⑤（Q5 授权来源）授权型开关是否只可能来自命令行、可共享配置文件能否携带它们？⑥（Q6 启动锚点）异步命令的返回体是否含可回查标识且文档给出可证伪断言？

**跨场景迁移**：Agent 可调用的支付/云资源 CLI（`aws`/`terraform`/`kubectl`）；SaaS 平台的公开 MCP 工具集；代码托管平台的 CI 触发与部署流水线。

> **G3 检验**：模式文档含触发条件与 4 类不适用边界 ✅｜6 步可执行核心做法 ✅｜6 个反模式（≥3）✅｜有六问检验标准（Q1~Q6）✅｜3 个跨域迁移示例（≥1）✅｜单案例显式标注 L1-draft、validation_count=1 ✅｜与既有 `cli-as-api-design` 显式划界 ✅。

## 七、六维详细评估

### 7.1 产品能力完整度与可编辑性（4/5）

**优势**：从输入到交付的链路无断点——输入侧按格式分派解析策略（PDF 判扫描版自动 OCR、Word 按段落自动分镜、PPT 优先备注讲稿、链接抓正文忽略广告评论导航），规格侧给出文档字数→成片时长与镜头数的分档参考，交付侧提供 Preview/Export 两阶段与浏览器可播放分享页（PRO-04/PRO-03/PRO-11/TEC-15）。可编辑粒度是本产品最扎实的部分：脚本（改字/删段/调序/加段/改语气/重生次数不限/多音字 1–4 声）、画面（单帧换背景/换图片、批量应用到多帧、替换后元素自动适配）、字幕（逐段显隐 + 位置/动画/字号/字色/底色/描边 + 存为模版）、数字人（位置尺寸可拖拽、一次调好全页应用）四个层面均有官方教程对应（PRO-12/PRO-13/PRO-15）。批量与系列能力（并行 1/5/50/不限、系列项目自动编号、整系列分享、「一讲做完再开始下一讲，积分逐讲扣」）直接命中出版社与教育机构的产能诉求（PRO-24/COM-12）。

**缺口**：负面口碑集中在首条出片质量而非可编辑性——"分不清重点和非重点"、"画面有时不够精准"、"声线过于 AI"（RP-16/RP-17），即**改得动但第一版不够好**，两者需叠加才能成立；7 个 Web 模式与 4 个 CLI 模式存在**能力错位**（CLI 无「图解视频」「原文讲解」等价模式，数字人不可与 handdraw/agent 引擎同用）（PRO-06/TEC-07/TEC-20）。

### 7.2 Agent 原生工程化（4/5）

**优势**：同类产品中罕见的契约完备度——认证以两阶段 Device Flow 面向 agent 编排设计且交互按 token 计（TEC-07）；`auth status --output json` 暴露 `pending_authorization` 态供宿主判断该等还是该催（TEC-10）；SSE 进度流同时提供人读与 NDJSON 两形态（TEC-11）；退出码区分终态失败（7）与可续跑中间态（6）（TEC-12）；`--async` 给出"打印 task_id 即代表已启动"的可验证锚点（TEC-13）；输出按 TTY 自动切换 JSON（TEC-29）；Agent Skills 目录按 agentskills.io 开放规范组织、`npx skills add` 自动 symlink 至 55+ 运行时（TEC-05/TEC-06）；MIT 许可、0 依赖、Go 单二进制（TEC-01/TEC-02）；`doctor`/`profile`/多 service 独立鉴权/日志脱敏/ANSI 清理构成完整的诊断与安全面（TEC-25~TEC-27）；`api call` 保留原始逃生通道（TEC-28）。

**缺口**：**缺陷闭环缺失是主要扣分项**——3 条 open issue 全部创建于 2026-06-10、至 2026-10-21 仍 open，且提交者账号同为 xntj-ai；#10 直接质疑 `create --async` 的任务"永远不会开始生成"与 `video wait` 静默退出 0，#12 记录数字 voice ID 致 TTS 40401 在管线中段才失败（RP-15）。**宣称与实测存在观测缺口**：官方文档的 exit 6 语义化设计（TEC-12）与 #10 记录的"静默退出 0"在行为层面并不一致，须实测核验（Q-6）。同时 npm 累计下载 3562 次、GitHub stars 9（RP-13/RP-14），说明该工程化资产**尚未获得实际使用验证**。

### 7.3 定价可预测性与单位经济（3/5）

**优势**：积分三态定义清晰（活动积分可能过期、订阅积分仅当期有效不累积、购买积分长期有效），加油包四档阶梯明确（1,000/¥99 ~ 10,750/¥999），并发档位与档位挂钩（1/5/50/不限），注册不绑卡且送 400 积分，订阅赠送与年付折扣的官方宣传口径可读（COM-01~COM-11）。两站同档位月积分额度一致（1,128/4,000/10,000），说明**积分是统一的底层单位**、货币只是前台表现（COM-24）。

**缺口**：**跨站与跨来源共 9 项口径冲突**（C-1~C-9），其中每日赠送积分在英文站自身两页就不一致（C-1），分辨率上限与 BGM 归属互斥（C-2/C-3），模板数 100+ vs 40-plus（C-4），注册赠送 400 vs 500（C-5）；年付绝对价两站均未能从官方页面读出，只能依赖第三方转述（E-1/E-2）；团队版价格、坐席数、发票流程在可访问页面全部缺失（E-5/COM-14）；退款与积分抵扣顺序在 FAQ 中为未渲染的折叠项（E-12），而 ToS 4.2 条明确"费用不退不换、不为未使用的订阅/功能/产出提供退款或额度补偿"（RP-09）——即**文本上不存在退款通道**。厂商成本口径「3 分钟 ≈16 元 vs 外包 ¥5,000 起」（COM-10/RP-22）无任何实测支撑，不可进采购模型（Q-1）。

### 7.4 主体稳定性与合规风险（3/5）

**优势**：主体可核且叙事完整——北京向量方程科技有限公司（统一社会信用代码 91110106MADEQEYY83，成立 2024-03-14，注册资本 321.4286 万，法定代表人沈仁奎），36氪 2024-10-30 首发报道其创始人为原得到/罗辑思维 CTO，产品「石榴数字人」2024-06 商业化，2024-08-26 完成 1000 万天使轮（真成投资领投）（RP-01~RP-03）；同主体另有石榴 AI 与同备案的 shiliu.cool / figlen.com（COM-25/RP-05）；招聘页客户名单覆盖人教社、高教社、清华、浙大、中传、阿里、金山、知乎、得到、当当（RP-04）；隐私政策明确不用个人信息训练模型、备份删除窗口 up to 15 days（RP-07）。

**缺口**：**协议主体与经营主体不一致且未获证实**——ToS/隐私政策署 "Minerva Noctua"、适用特拉华州法律、英文仲裁，文中无「北京向量方程」字样，而中文版用户协议与隐私政策在 /privacy、/agreement、/legal/terms、/terms 路径全部 404（RP-06/G-5）；国内 ICP 备案主体为京ICP备2024060545号-15，与英文协议署名的对应关系未获证实。**声音与肖像权风险已具备司法口径**——最高法 2026-09-07 意见第四条支持未经同意模仿音色生成可识别合成人声的权利主张，上海首例生成式 AI 声音侵权案二审维持原判、判赔 5 万、明确"权利人完成初步举证后**举证责任转移至平台**"（RP-25）；而本产品提供声音克隆（30 秒样本、857/686 积分）与数字人克隆功能（PRO-17~PRO-19）。**AIGC 标识义务已生效**——《人工智能生成合成内容标识办法》2025-09-01 施行，要求视频起始画面显著提示标识、生成内容添加隐式标识、用户发布时主动声明（RP-24）。**竞争性条款约束用户**——ToS 第 9 条禁止使用服务/输出/底层系统开发竞品 AI 产品（需事先书面同意）（RP-08）。

**优势**：可核的独立旁证存在且方向一致——12 家第三方目录收录，评分分布在 3.5（digitalizelife）、4.5（AIxploria、olymphill）、8.5（watcha，中国站评分制）区间；中文第三方评测给出可操作的成本对比（此前用 Nano Banana/Seedance 单条 200–300 元，本产品一分钟十几元）（COM-23/RP-18）；fly63 与 36氪 两篇给出四条与三条具体可定位的负面（RP-16/RP-17）；客观工程数据完整可复算（18 tag、6 Release、npm 逐日下载曲线）（RP-13/RP-14）。

**优势**：开放度在"开发者侧"明显高于"企业侧"——MIT 许可、0 依赖、npm 分发、Agent Skills 开放规范、55+ 运行时兼容、`api call` 原始逃生通道、per-service 端点覆盖与独立鉴权、`api` 设置页支持团队密钥与启停状态管理（TEC-01/TEC-06/TEC-25/TEC-28/PRO-25）。

## 十一、最小可验证切片与采购清单

### 11.1 最小试用路径（半天内可完成，不触发付费）

1. 注册中文站账号 → 领取 400 注册积分（不绑卡，COM-11）。
2. 用一篇 800–5000 字的中文文档走「文档转视频」→ 观察 3–8 分钟制作过程与 10–30 个镜头（PRO-04）。
3. 免费档并行度为 1、输出带水印（COM-04/PRO-22）——先把**带水印预览**用于内部评审。
4. 在脚本面板改一句旁白 → 点「重新生成」→ 观察是否同步重生成画面与配音、是否重复扣积分（PRO-12）。
5. 满意后再评估是否升级 plus 档（连续订阅 ¥79/月）并导出无水印 MP4（COM-01/PRO-22/PRO-11）。

> 该路径专为验证洞察 1 的核心命题：**「改一稿的成本」是否真的低**。若改一稿需重跑全流程并重复扣费，则本产品的核心卖点不成立。

### 11.2 CLI 最小可用序列（开发者通道）

```bash
# 1. 安装（npx 分发，MIT，0 依赖）
npx vibeknow-cli@latest auth status --output json

# 2. 两阶段授权：先取设备码（人类交互按 token 计，非按命令计）
npx vibeknow-cli@latest auth login --no-wait        # 输出 device_code / user_code / verification_uri
#    人类在浏览器批准后：
npx vibeknow-cli@latest auth login --device-code <device_code>

# 3. 生成并拿分享页（默认停在 preview，导出为独立的不可逆计费动作）
npx vibeknow-cli@latest create --from report.pdf --mode default --aspect 16:9

# 4. 观察进度（人读进度条 / 机器可读 NDJSON）
npx vibeknow-cli@latest video wait --for 90s --output json
#    退出码 6 = wait_budget_expired（语义：继续等待）｜退出码 7 = 渲染失败

# 5. 异步长任务（打印 task_id 即代表 run 已启动）
npx vibeknow-cli@latest create --from long.md --async
```

> 上述序列的每一步都可能因 RP-15 记录的三条 open issue 而受阻（#10 async 任务不开始 + wait 静默退出 0、#11 复用文档缺 knowledge_id 被拒、#12 数字 voice ID 致 TTS 40401），采用前请先核验 Q-6。
