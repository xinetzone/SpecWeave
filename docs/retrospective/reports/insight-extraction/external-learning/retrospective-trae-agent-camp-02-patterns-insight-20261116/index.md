## 二、六条洞察

### I-1 改造成本由「选层」决定，而不是由执行效率决定

**现象**：同样一条需求，落在记忆层是即时生效，落在技能层需一次校验推送，落在程序层需重新构建安装、且可能触发数据风险（F-063、F-081）。

**根因**：三层是三种不同的「生效机制」，不是三种难度。选层的瞬间就锁定了此后每一次修改的成本档位；执行得再快，也改变不了这一档。

**影响**：选错层的人会在后续每次调整中重复支付构建与安装成本；而且程序层的卸载重装会清掉记忆与技能，形成「越改越不敢改」。

**行动**：改造前先写一行「落点声明」——**落在哪层、多久生效、怎么回滚**；三者任一说不清，就不动手。

### I-2 可靠性来自三件设施，不来自模型能力

**现象**：课程的自检、验收与排障都不约而同地指向同一组东西：可观察的检查点（F-037）、可回退的改前版本（F-086）、可拦截的确认闸门（F-078）。

**根因**：模型能力决定「能不能做对一次」，设施决定「做错时能否被发现、被回退、被拦住」。前者是概率，后者是结构。

**影响**：只押注模型能力的人，会把每次失败都解释为「模型不行」，从而错过唯一能工程化改进的三处位置。

**行动**：任何自动化任务上线前先列「三件设施」——检查点、回退点、闸门；缺一件就标为实验态，不承诺可用。

### I-3 配置化能力的收益在三层交界处跳变，不在层内渐变

**现象**：课程给出的三条改造路径中，记忆与技能之间是平滑过渡，技能到程序之间出现一次能力跃变：只有程序层能实现「没有确认就存不进手机」这类强制闸门（F-075、F-078）。

**根因**：记忆与技能都是**可被解释和绕过的声明**，程序层是**不可绕过的执行**。跃变来自约束性质的变化，而非工作量的变化。

**影响**：把「需要强制约束」的需求留在技能层，会得到「写了但没拦住」的假安全；把普通偏好推进到程序层，则会付出不必要的构建与数据风险。

**行动**：用一句话判层——「这条要求是希望它记得（记忆）、会做（技能），还是**做不到也不能做**（程序）」。

### I-4 多 Agent 的前提不是「任务够大」，而是「单段可验收」

**现象**：课程在讲多 Agent 之前先强调「先单后多」，并把切分规则写成四条（单一产出、人工确认处切、触发时间不同分开、同产出合并），交接单必须含「怎么验收」（F-086、F-093、F-096）。

**根因**：并行提高的是吞吐，不是可验收性。若单段无法独立验收，拆得越多，共担产出越多，失败时越无法归因。

**影响**：按人头拆分的团队，会在交付时才发现同一份产出有两个版本，返工成本随人数上升。

**行动**：切段前先为每段写「怎么验收」；写不出来就先不切，回去把单段做到可验收。

### I-5 闸门的有效性只能用反证证明，不能用声明证明

**现象**：模式 P6 的检验标准不是「是否写了两层确认」，而是「故意绕过规则层时，能力层是否仍能阻止」（F-078 与技能层确认 F-054、F-060 并存）。

**根因**：规则层是可被上下文截断、被指令改写、被压力说服的软约束；能力层是执行路径上的硬约束。声明只证明意图，反证才证明存在。

**影响**：只写规则的团队会得到「文档上很安全、事故时全线穿透」的结果，且每次都要靠人来兜底。

**行动**：每个不可逆动作配一条反证用例（移除确认后应失败）；未通过的动作按「无闸门」处理，不按「已声明」处理。

### I-6 同构率揭示方法论厚度：六模式中两个与既有模式同构

**现象**：本次入库去重裁定显示，P1 三层改造面与底座先行最小定制法核心动作同构，P3 试改验循环与编辑-验证分离同构；真增量为四篇（F 编号支撑见各模式文档「沉淀与校验记录」）。

**根因**：课程的方法论厚度集中在「配置化 AI 系统的改造」这一处（选层、固化、闸门、拆分），其余部分与通用任务管理重叠。

**影响**：若不做去重、逐条入库，会在模式库里制造两套权威，读者无法判断该引用哪一篇。

**行动**：同类课程或方法论材料，先做「同构率预估」——真增量低于四成才逐条入库，否则优先走「并入既有篇 + 补一节」的路径。
