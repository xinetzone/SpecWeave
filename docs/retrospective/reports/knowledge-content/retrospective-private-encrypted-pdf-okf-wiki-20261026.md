# 里程碑复盘：加密私域 PDF 转 OKF Wiki 交付

> 复盘对象：一次「加密私域课程讲义 → OKF v0.2 知识包」的完整交付。复盘目标不是评价产出好坏，而是回答一个问题：**这次交付中哪些做法可以固化成下一次同类任务的默认动作，哪些只是运气好**。
>
> 脱敏声明：本报告不复述源材料的具体论断与数据，不记录访问凭据，不提供指向私域目录的可点击跳转。所有数字均为本次实测或交付记录，取证命令见附录。

## 摘要

一次 4 页加密培训讲义转知识包的交付，产出 20 个 Markdown 文件（交付当场 121,363 字节，返工修正后以固化脚本复测 123,430 字节）、45 条编号事实、102 条本地引用、4 条洞察、4 条可迁移模式。交付过程记录 5 类返工（断链 2 处、繁体字 1 处、frontmatter 路径 2 处、事实计数失真 1 次、引用计数失真 1 次）。

最重要的发现不是"有返工"，而是**两类计数声明的失真原因不同**：事实计数是"数漏了"，可通过机械计数根治；引用计数是"口径未定义"，换一种归一化策略即可从 11 条变 14 条——这类声明在写入文档的瞬间就与实测脱钩，除非把口径写成可执行断言。

结论：本类任务的核心风险不在内容质量，而在**可审计性**。已被萃取为独立 Skill `private-encrypted-pdf-to-okf-wiki`，与既有的扫描版技能构成姊妹分支。

## I 阶段：四元组洞察

> G2 校验：每条洞察含陈述、证据、反常识、下次行动四元组。

### 洞察 1：计数类声明是口径函数，不是客观量

- **陈述**：同一批产物，"引号内逐字比对且 ≥8 字"口径得 11 条唯一引用，"归一化去标点后 ≥8 字"口径得 14 条，幅度差 27%。而"最长 23 字"实际是全文公共子串长度，与"最长单条引用长度 22 字"是两个不同指标，在交付文档中被合并表述为一项。
- **证据**：R7、R8、R9
- **反常识**：直觉认为"我数过了"就等于准确。实际上写作时数的对象是记忆中的引用，不是文件里的引用；且自然语言计数本身没有唯一答案，标点是否计入、重复是否去重、是否归一化，每一个选择都改变结果。
- **下次行动**：声明中的每个数字必须能追溯到一次具体脚本输出。先跑脚本、再写声明，并在声明旁写明归一化函数与阈值；不同指标（引用长度 / 公共子串长度）不得合并为一句话。

### 洞察 2：断链的根因是心智模型中的目录层级与磁盘层级错位

- **陈述**：2 处断链与 2 处 frontmatter 路径错误，形态一致——`../` 多一级或少一级。写作时以"文件位于 bundle 根"计算路径，而文件实际位于子目录。
- **证据**：R12、R14
- **反常识**：通常归因为"手滑"或"粗心"。实际是相对路径的层级基准来自记忆而非文件系统，且同一错误在正文链接与 frontmatter `source` 两个位置重复出现，说明这不是偶发失误，而是缺少一个"以实际位置为准"的校验动作。
- **下次行动**：把"写链接"与"跑链接检查"绑定为同一动作，不留给收尾阶段；新增跨层引用后立即对该目录执行 `check-links.py`，而不是等全部写完后统一检查。

### 洞察 3：高风险内容的价值与风险可以分离交付

- **陈述**：源材料含"无需偿还"类绝对化表述与具体渠道数量宣称。交付时未作删减处理，而是按法律性质将渠道分家族归类，并对每一类标注"是否需要偿还本金"与"法律边界"，另设刑法相关条款红线提示。结果是渠道地图的信息价值保留，照做风险被显式阻断。
- **证据**：R1（材料性质）、R3（concepts 分层中包含审计与红线内容）、R19（源文件未外流）
- **反常识**：合规处理常被理解为"删掉危险内容"。实际删减会同时丢掉可用的结构信息；分类 + 标注既保留了信息，又让风险变成可审计的字段，读者能自己判断边界在哪里。
- **下次行动**：遇到"承诺型 / 绝对化 / 法律敏感"主张，先做法律性质分类与边界标注，再决定保留形态；把"要不要删"的问题转化为"用什么字段标注"的问题。

### 洞察 4：私域分流保护了合规，代价是资产的可发现性

- **陈述**：按内容敏感度预检，本次全部产出落 `playground/`，跳过 `.trae/specs/`。对应地，产出未进入 `docs/` 索引。后续同类任务中，智能体按路由表检索时不会命中该目录。
- **证据**：R18、R17
- **反常识**：直觉认为"文件写好了就在那里，随时能复用"。实际上未被索引的资产在跨会话场景中等同于不存在——下一次遇到同类任务，智能体会重新发明流程，这正是本次需要萃取 Skill 的直接动因。
- **下次行动**：私域交付完成后，同步产出一篇脱敏方法论报告入 `docs/`，把"可复用的方法"与"不可外流的材料"分仓存放：材料留在私域，方法进入公开索引。

## E 阶段：可迁移模式

> G3 校验：每条模式含触发场景、核心步骤、反模式、迁移验证。

### P-1 口径先行计数（Measure-Before-Declare）

| 要素 | 内容 |
|------|------|
| 触发场景 | 产出物需要在文档中声明任何计数（条数、字数、文件数、最长片段） |
| 核心步骤 | ① 先写一次性取证脚本并对真实文件跑出数字；② 把归一化函数与阈值写进脚本；③ 用脚本输出回填声明；④ 在声明旁注明口径 |
| 反模式 | 先写"本包共 N 条引用"再去找引用；用"大约""最长不超过"等模糊量词替代实测；把两个不同指标合并成一句话 |
| 迁移验证 | 本次：初稿 11/23 与实测 14/22 不一致，改用脚本口径后声明可复现。可迁移至任何带计数声明的知识包、报告、清单 |

### P-2 链接即写即验（Write-Check Coupling）

| 要素 | 内容 |
|------|------|
| 触发场景 | 在多层目录中写相对路径引用（正文链接、frontmatter 路径字段） |
| 核心步骤 | ① 写完一个文件立即对该目录跑 `check-links.py`；② 发现层级错误按文件实际位置重算，不按记忆重算；③ 收尾时全量复跑一次 |
| 反模式 | 全部写完后统一检查（错误集中爆发，定位成本翻倍）；仅凭编辑器预览判断链接有效 |
| 迁移验证 | 本次 4 处路径错误（2 链接 + 2 frontmatter）在同一批次修复。可迁移至任何 Markdown 文档集 |

### P-3 高危主张的分类替代删减（Classify-Not-Delete）

| 要素 | 内容 |
|------|------|
| 触发场景 | 源材料含绝对化承诺、法律敏感操作、不可核验功效表述 |
| 核心步骤 | ① 抽取主张并按性质分类（可核验事实 / 经验值 / 不可核验 / 法律红线）；② 对红线类标注边界依据而非删除；③ 单独设审计页承载红线清单；④ 正文保留边界声明与"不构成建议"限定 |
| 反模式 | 整段删除导致信息结构断裂；保留原文但加一句"仅供参考"（免责声明不能替代边界标注） |
| 迁移验证 | 本次产出 4 类主张分层与 5 条高风险主张拆解。可迁移至金融、医疗、法律等受监管主题的知识整理 |

### P-4 方法外流、材料内留（Method-Out-Material-In）

| 要素 | 内容 |
|------|------|
| 触发场景 | 私域材料的加工过程产生了可复用的方法论，但材料本身不可外流 |
| 核心步骤 | ① 材料与中间产物留在私域目录，用后删除中间产物；② 方法论提炼为脱敏报告入 `docs/`；③ 稳定流程再固化为 Skill |
| 反模式 | 整包（材料 + 方法）一起放进私域，导致方法不可复用；或为可复用而把材料一并公开 |
| 迁移验证 | 本次：20 文件留私域，本篇脱敏报告入 `docs/`，Skill 入 `.agents/skills/`。可迁移至内部培训、会议纪要、客户资料的处理 |
