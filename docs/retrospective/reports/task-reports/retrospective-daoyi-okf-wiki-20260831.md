## 5. 问题解决

### P1. 并发竞态：首次提交「no changes added」（已解决）
- **现象**：daoyi 首次 commit 退出码 1，暂存区被清空、daoyi 重新显示 untracked。
- **根因**：并行会话期间提交了 `cd18b05e`（伤寒/难经/外经）并重置暂存区。
- **修复**：核实 24 文件完好在磁盘且未入 HEAD 后，将 `git add` + 暂存清单越界守卫（非目标路径即中止）+ `git commit -F` 合并为单条 PowerShell 命令，成功得 `3a880237`。

### P2. 编辑回写竞态：jupyter 69 被回退为 67（已解决）
- **现象**：13 处编辑完成后校验发现 document 节表格和少 2，grep 证实 jupyter 行在磁盘上仍是 67。
- **根因**：并行会话回写 index.md 同一区域，覆盖了该处编辑（其余 12 处存留）。
- **修复**：重新应用该行，并将「最终校验+add+守卫+commit」压缩为单命令执行；提交后以 `git show HEAD:<file>` blob 级核验全部关键行。

### P3. 盘点计数三连错（已解决）
- PowerShell `$arr += ,@(...)` 数组元素被拆开导致 322KB 输出爆炸 → 改哈希表；
- `@($bundles[$d]) + 1` 首元素计数翻倍 → 改 `[int]` 累加；
- **锚点组陷阱**：15 个组目录本身即束（concepts/examples 直挂组目录，如 katex、cpython、rust 三组、containers 十一组），初盘误得 354 束 → 确立「锚点组=1 束 + 束子目录 index.md 计数」规则，终得 **317 束/54 组**。

### P4. 总索引整体滞后（已解决）
- index.md 声明 301/40，HEAD 实际 317/54：缺 anthropic 组、containers/rust 组数错误、ai/build/document/think 束数漂移。按 README-merge-notes 的警告「不要机械 +1」，先全量盘点再统一对账。

### P5. 前序会话环境超时（已解决，归档）

## 9. 经验方法（可复用模式）

1. **HEAD 盘点三分法**：`git ls-tree HEAD` 已提交事实 ↔ 工作区未跟踪 WIP ↔ 工作区已修改，三类严格分离，计数只认真实 HEAD。
2. **锚点组计数口径**：组目录直接含 concepts/examples/references 时该组本身即 1 束（锚点组）；束数 = 锚点组 + 束子目录 index.md 数。盘点脚本须先识别锚点组。
3. **三角计数自洽校验**：frontmatter 计数 = 各节标题束/组和 = 表格束数列和（WIP 前向引用行单独挂账），三者不等即中止提交。
4. **并发提交单命令守卫模式**：`git add <path>` → 立即校验 `git diff --cached --name-only` 纯目标清单（不纯则 reset 退出）→ `git commit -F`，全在一条命令内，压缩竞态窗口。
5. **blob 级验证优于工作区验证**：提交后 `git show HEAD:<file>` 抽查关键行，免疫并行回写。
6. **人文经典知识包质量范式**：事实七前缀编号 + 信源分级链（识典＞维基文库＞ctext＞道藏阁）+ 争议两说并陈 + 禁用站显式警示 + 非医疗声明逐页覆盖 + 「待考」标注 17 处。
7. **全量对账优于机械 +1**：共享索引滞后时先盘点全域再一次性对齐，避免把计数漂移债务转嫁给下一个会话。
