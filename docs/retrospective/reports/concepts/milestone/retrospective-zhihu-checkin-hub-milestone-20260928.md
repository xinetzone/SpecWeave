## 三、核心洞察（I 阶段，四元组）

### 洞察 I-1：mock 100% 覆盖与真实可用之间，隔着一整个「输入信任模型」；测试替身会复刻实现者的错误心智模型

- **陈述**：当集成点跨越「自动化框架 → 第三方受控编辑器」边界时，mock 测试的成功率不提供任何真实可用性信息，因为 mock 回读默认了实现者假设的成功语义（DOM 变了=成功），而真实系统的成功语义在另一层（DraftJS 模型/字数计数）。
- **证据**：F-008/F-009（审查时 publisher 100% 覆盖、143 测试全绿）→ F-012（真实页「只看到标题没有内容」）；F-013（模型层字数读数才是真信号）；F-017（懒挂载竞态同样未被 mock 覆盖）；F-006（真实证据出现后代码才改）。
- **反常识**：高覆盖率不仅没拦住故障，还制造了「已验证」的确定性错觉——测试桩模拟的不是真实系统行为，而是实现者**当时以为的**真实系统行为；桩与错误假设同源，构成自证预言。100% 覆盖的 publisher 在真实首跑时三个关键动作（标题框、正文、想法入口）全部出过问题。
- **行动**：①对受控编辑器类集成点，规格阶段把三件事写成独立 AC：受信输入通道、**模型层信号**回读（字数计数/框架 API，而非 DOM 文本）、真实页面冒烟；②mock 回读必须包含「DOM 已变但模型未接收」的失败形态用例；③覆盖率汇报对「跨边界模块」单列出 mock-only 标记，禁止与真实执行证据合并表述。

### 洞察 I-2：自动化的确定性边界终止于 OS 焦点与第三方页面状态机；「最后一步人来做」会把异步页面行为引入确认协议

- **陈述**：人在环路（HITL）切分点之后，应用与页面之间不存在同步通道；「发布成功」的机器可判定信号必须按每种内容类型分别设计并在真实环境验证，统一的「读 URL」方案只在部分类型成立。
- **证据**：F-015（OS 前后台决定 CDP 点击是否产生真实焦点，bringToFront 不等价）；F-018/F-019（pin 发布原地刷新 feed、弹窗自动消失，URL 信号缺席，首次 confirm 409）；F-022（自动反查器又撞上列表懒渲染/后台节流，两次真实实测 None）；对照文章类型有稳定 edit URL（F-016），信号获取成本完全不同。
- **反常识**：本里程碑最难自动化的不是「填进去」（CDP 可工程化），而是「知道成没成」——人点击之后那几秒页面异步行为（跳转/原地刷新/弹窗/懒加载/标签页节流）构成一个没有任何文档承诺的状态机。这个差异在 mock 里不可见，只有一次真实端到端才暴露，且暴露一次只够覆盖一种内容类型。
- **行动**：①HITL 确认协议为每种目标类型单独定义成功信号获取策略（URL 锚定 / 弹窗文本 / 列表反查 / 最长等待时限），写入规格；②反查策略必须包含懒渲染处置（滚动步进、前后台要求、轮询预算）与「找不到即阻断」，且**必须在真实环境验证可达后才能关闭对应 AC**——F-022 的反查器当前不得视为完成（见行动项 A-3）；③向导文案在 pin 类型提示用户「发布后请勿切换/关闭标签页」。

### 洞察 I-3：红线工程的真正保障是「结构性不能」，不是提示与约定；审查应按能力缺口而非代码错误找问题

- **陈述**：本应用四条红线在真实使用中保持完好，依靠的是三类结构性约束（能力剥夺、流程闸门、信号自证）；独立审查发现的 4 个 P1 全部是「结构未合拢、靠调用顺序保证」的位置，而非逻辑写错。
- **证据**：F-030 + 静态 AST 守护（publisher 源码不存在 `client.click(`，能力被物理删除）；F-007 中 P1-1（锁正确但 serve 未接线）、P1-2（门状态有但 fill slug 未绑定）、P1-3（回读有校验但只查 /question/ 子串）；F-026（cdp 失败单向降级、degraded 零存证）；F-019（confirm 只认真正则锚定 URL + pin 反查要求正文前缀匹配）。
- **反常识**：页面上那些「最终发布由你点击」的显著文案贡献的是合规告知，零安全增量；真正起作用的是代码**不具备**越界能力。反过来，「调用方会先过门再填充」「启动时记得加锁」这类依赖时序的正确用法，在审查时应一律按缺陷处理——无论当前调用路径是否真的遵守。
- **行动**：①红线验收用「能力清单测试」表达：AST 扫描证明不具备某能力、跨会话状态测试证明不能绕过、信号正则证明不能伪造；②审查清单新增一类检查项：「该安全属性是否依赖调用顺序/调用方自觉」，命中即升 P1；③降级路径与正常路径对称测试（零半成品写入），作为 HITL 应用的标配审计项。

**G2 自检**：3 条洞察维度独立（测试认识论 / HITL 协议设计 / 安全保障结构）；每条含陈述+证据（引用 F 编号）+反常识+行动；无正确的废话。**G2 通过。**

## 五、模式萃取（E 阶段）

### 模式候选：受信填充链（trusted-input-degradation-chain）· **成熟度 L1（单案例待验证）**

```yaml
id: trusted-input-degradation-chain-l1
name: 受信填充链
maturity: L1  # 单案例：知乎文章+pin 各 1 次真实样本；回答类型未验证
source_case: zhihu-checkin-hub 2026-09-28
external_dependency: webbridge v1.11.6 chrome.debugger 通道 / Microsoft Edge 155
failure_signal: cdp 方法不可用→已自动回退 execCommand/fill 旧路径；编辑器改版→字数计数选择器漂移
```

**适用于**：自动化向第三方 Web 的 JS 模型驱动富文本编辑器（DraftJS/ProseMirror/Slate 类 contenteditable）写入长文本；自动填充与人工提交并存、最终提交动作必须由人完成。

**不适用于**：原生 textarea/input（value setter 即可靠，本应用标题框即此类）；自有可控页面（直接调 API）；纯展示数据抓取。

**核心步骤（7 步）**：

1. **输入信任模型前置探针**：最小实验区分 textarea 与受控编辑器——DOM 赋值/execCommand 后令其失焦，文本回滚即判定必须走受信事件；不探针直接上 fill 是本模式最大的坑。
2. **受信通道+焦点回读**：CDP `Input.insertText`/dispatchKeyEvent；`Page.bringToFront` 后受信鼠标点击编辑器坐标，并回读 activeElement 的 contenteditable；失败重试 3 轮仍失败**立即降级**（bringToFront ≠ OS 前台焦点，必要时提示用户切窗口）。
3. **受信清空、只用干净草稿**：Ctrl+A/Delete 走受信键盘事件；早期合成注入污染过的草稿模型/DOM 永久脱节，直接弃用、开新草稿，不要尝试修复。
4. **分段分块发送**：按 `\n` 分段，每块 ≤20 字（**单样本经验值**，出现截断就调小），块间约 120ms（同经验值），段间受信 Enter。
5. **模型层回读**：以编辑器字数计数/模型长度为准（阈值 expected-2）；DOM textContent 一致不算成功。
6. **失败单向降级**：打开目标页 + 正文写剪贴板 + 中文指引；禁止合成事件兜底；degraded 状态零存证、零勾选、零状态推进。
7. **成功信号分类型设计**：URL 正则锚定优先；原地刷新类型用「正文前缀反查 → 命中详情页 → 二次读 URL」，反查含懒渲染处置（滚动步进+轮询预算+标签页前后台要求），找不到**维持阻断**，不得放宽匹配。

**反模式（6 个，全部来自本次真实教训）**：

- AP-1 **合成注入当成功**：execCommand/DOM 赋值 + DOM 静态回读，失焦被模型回滚（用户看到「只看到标题没有内容」）。
- AP-2 **污染草稿硬清**：在模型/DOM 脱节的旧草稿上反复 Ctrl+A/Delete；正解是弃用开新稿。
- AP-3 **整块大文本 insertText**：62 字单块字数读数短少；必须分块+间隔+回读。
- AP-4 **假设后台标签页有焦点**：只 bringToFront 不回读 activeElement 就填充。
- AP-5 **拿首页 URL 当裁决**：pin 原地刷新，直接判 409 是一个方向的错，放宽正则误确认是另一个方向的错；正解是带正文前缀的反查+详情页二次确认。
- AP-6 **桩测试自证**：FakeBridge 对页面 JS 逻辑直接应答，JS 本身写错测试全绿；新模式的最终证据只能是真实页面冒烟，且探针脚本应固化留存。

**检验标准**：编辑器字数计数与发送长度一致；失焦/切换窗口后文本保留；发布产物可在平台个人页检索到；全程无自动点击最终提交动作；失败路径零半成品写入。

**跨场景迁移示例（未验证）**：微信公众号后台草稿填充（同类富文本编辑器，接入前必须先做步骤 1 探针）；RPA 向第三方 OA 富文本审批单填长文本。获得任一第二平台真实样本前不升 L2。

**新平台接入前置实验清单（V-7 采纳）**：①textarea 还是受控编辑器？②失焦回滚吗？③CDP 通道可用吗？④字数/模型回读信号在哪个元素？⑤发布成功后 URL 变不变？⑥列表页懒加载与前后台行为？——六问无答案不写生产代码。

**G3 自检**：模式名 5 字；适用/不适用边界明确；7 步可执行；反模式 6 个均有事实出处；有检验标准；有跨场景示例（标注未验证）；多案例要求以 L1 显式标注（单案例待验证）；frontmatter 字段完整。**G3 通过（L1）。**
