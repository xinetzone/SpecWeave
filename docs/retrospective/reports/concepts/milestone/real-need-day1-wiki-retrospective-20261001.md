## 三、洞察环节（I · 4 条四元组，G2 通过）

### I-1 不落映射表

- **陈述**：「不落映射表」决策把脱敏从「可回查」变为「单向」，映射表本身才是最大泄露面
- **证据**：F-11（映射表文件数=0）、F-20（组合残余风险以登记方式被接受）
- **反常识**：通常认为脱敏越彻底越需要对照表备查；本任务相反——对照表一旦泄露，全部脱敏前功尽弃
- **行动**：后续私域任务将「映射表存废」列为脱敏方案独立决策点，默认不落表

### I-2 登记不修是合规闭环

- **陈述**：「登记不修」是低危审查问题的合规闭环方式——显式登记+书面论证+复核确认可替代修复
- **证据**：F-17（首轮仅 P2/P3）、F-20（P3-3 登记不修）、F-22（复核后 PASS 维持）
- **反常识**：惯性认知是「审查发现问题必须修完才能 PASS」；低危项强行修复可能引入新风险，显式登记反而更可审计
- **行动**：制定「登记不修」三要素清单（低危定级+不修论证+复核确认），提交治理规范评审

### I-3 私域同目录治理

- **陈述**：私域任务中 Spec 三件套与内容产物同目录落盘，治理证据与产物同步隔离、同步可查，审计完整性优于拆分存放
- **证据**：F-08（20+3 同目录）、F-25（隔离验证通过）、F-05（裁剪决策可追溯）
- **反常识**：常规约定把 Spec 放 `.trae/specs/` 公共区；私域任务跳过公共区后证据链反而完整自洽
- **行动**：私域任务默认结构模板化——产物目录内自带 spec/tasks/review/log 四件套

### I-4 生成期脱敏前置

- **陈述**：首轮 0 P0/0 P1 与「生成期脱敏」在时间上重合——脱敏作为写作约束前置，而非事后扫描补丁
- **证据**：F-09/F-10（名单+代号化在生成期应用）、F-17（首轮零高危）
- **反常识**：事后扫描替换看似省事；前置脱敏后审查首轮即零高危，返工集中在 P2/P3 表述层
- **行动**：脱敏词名单前置为私域任务 Task 1 写作约束清单模板项
