## 三、洞察（I · 第一性原理，四元组）

> 格式：`[条件C] → [机制M] → [行动A] → [结果B]`（可证伪、附迁移场景）

### 洞察 1 — 规模化的可持续性依赖「自举规范」而非「人力意志」

- **条件**：项目跨越 100 天、3990 次提交、超十万级文件规模后仍保持 docs/feat/fix 结构稳定。
- **机制**：AGENTS.md 启动协议 + 内容敏感度预检 + 三层路由构成的自举规范，把"该怎么做"从人脑转移到可审计文件。
- **行动**：继续强化规范自举（规则↔知识库↔命令链一致），新增规范时同步顶层引用/导航/存量迁移。
- **结果**：规模越大，规范边际收益越高，质量可预测（该洞察迁移至任意长时程 monorepo 治理）。

### 洞察 2 — 门禁的质量由其「反例发现能力」而非「覆盖率」决定
- **条件**：gate 报警数 421→0、误报 400+、断链遗留 504 等实测矛盾并存。
- **机制**：仅追求"通过率/警告清零"会把门禁调成低灵敏度，真实缺陷（如 P1 静默降级）仍漏网；门禁价值=能否构造并拦截反例。
- **行动**：每次门禁改版先注入 1-2 个已知缺陷回归，验收其"能拦、不漏、不误报"。
- **结果**：门禁可信度从"状态展示"升级为"质量保证"（迁移至 CI 与代码评审）。

### 洞察 3 — 私域/公共文档的分离决定文档资产的长期可用性
- **条件**：`.agents/docs/` 废止、docs/ 与 playground/ 边界确立。
- **机制**：公开/私域按内容敏感度分流，公开内容入 docs/、私域入 playground/，避免敏感信息泄漏与文档债务混淆。
- **行动**：继续执行内容敏感度预检分流，落盘前三查（目标目录/同类位置/磁盘原文）。
- **结果**：docs/ 成为唯一可对外消费、可导航、可审计的中心（迁移至所有工作区）。
