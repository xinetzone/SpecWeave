# 做完 500 个 AI 知识包，我最想分享的是 5 条反常识

> 我是这个仓库的开发者。上一篇我拆了"带质检的流水线"怎么造；这篇不聊工艺，聊做完之后我更确信的五件事——每一件都和直觉相反。

如果你关注 AI 内容生产，最近应该见过两种声音：一种说 AI 生成的内容"不敢引用"，一种说"AI 已经能批量生产知识"。我大概是少数能把这两种声音同时验证的人——因为 [awesome-okf](https://github.com/awesome-flexloop/awesome-okf)（500 个 OKF 知识包）是我用 17 天、284 次提交做出来的，而它同时被我自己的项目立为"最高可信度知识库"。

复盘完这 284 次提交，我留下五条反常识。它们不是操作手册，是我对"知识生产"这件事看法的改变。

## 一、先造尺子，而且让尺子先量它自己

**反常识：第一件"产品"不该是你想做的内容，而是规范本身。**

大多数内容项目的第一周在写正文；我的第一周，用 OKF 格式写了"解释 OKF 规范"的知识包——让格式定义格式，让尺子先量自己（dogfooding）。

它的威力不在那 34 篇文档，而在后面：当规范知识包通过"自己审自己"后，**500 个知识包共用同一把尺子**，生产者不再需要为每篇文档重新发明"什么算合格"。

你不需要做 OKF，但你需要做一次"自举"：在量产任何内容前，先写一篇定义"内容该长什么样"的样板，并让它通过校验。这一步省下的不是时间，是后面所有内容的"格式税"。

## 二、可信度是流程的属性，不是作者的属性

**反常识：一份内容"能不能信"，取决于它出厂时走了哪条流水线，而不是谁签的字。**

我们习惯用"作者是谁"判断可信度——但 AI 时代这个信号失效了：AI 没有履历可以抵押。我选择把"可信"从人品问题改成工程问题：每条内容出厂前，必须经过编码门禁、目录门禁、计数对账门禁，每条事实带 F 编号、指向可查的信源（规范母体见 [GoogleCloudPlatform/knowledge-catalog](https://github.com/GoogleCloudPlatform/knowledge-catalog)）。

于是出现了一个奇妙的结果：**这份"AI 批量生产"的库，比我手写的很多文档更可信**——因为它的每句话都能被 30 秒内验证，而我的手写文档不能。

## 三、先易后难：用低风险内容练兵，才敢碰高风险经典

**反常识：内容的"高风险区"应该最后做，即使它最吸引人。**

翻 git 历史会看到一个秩序：8 月中旬先做源码教程（Sphinx、CPython 这类技术束），8 月下旬才做《论语》《黄帝内经》这类经典。这看起来只是内容安排的巧合，复盘时我发现这是整件事能成的关键——**它是按"错误成本"排序的**：

- 技术教程写错一个 API 参数：读者跑一次就发现，修复成本低；
- 古籍解读错一句话：可能误导十年，且读者不一定能发现。

所以正确顺序是：**先在低风险区把"AI 生产 + 门禁校验"的流程跑通、攒够信任，再把同一套流程用于高风险内容。** 如果我第一周就冲《黄帝内经》，大概率翻车——因为流程还没被低风险内容打磨过。

## 四、目录是可以推倒重来的——只要你付得起"换目录的自由"

**反常识：重构本身不是成本；"无法安全地重构"才是成本。**

17 天里这个库的目录被我重排了四次：6 个来源组 → 10 个技术域 → 8 个学科域 → 如今的 9 域 57 组。在传统项目里，一次目录迁移就要改几百个链接、吵几周；在这里，重排=改链接+跑一遍门禁，一天完成。

为什么？因为每个文件格式高度统一、门禁自动兜底，迁移的"物理成本"趋近于零。**当分类可以追着认知跑时，早期分类错误就不是终身判决。**

把这条用在个人知识管理上也成立：你的笔记系统不敢搬家，往往不是因为搬家难，而是因为你没有"自动校验链接"的机制。先装安全网，再谈整理。

## 五、凡是"我们有多大"这种数字，都别让人类数

**反常识：规模数字是最容易过期的派生数据，手工维护等于制造假新闻。**

最有意思的证据来自我自己：当我今天告诉你"这个库有 500 个知识包"时，**这个库自己的 README 上写的还是"24 个"**，我更大项目文档里写的还是"248 个"。为什么？因为人类手工同步派生数字，必然落后于内容增长。

解法只有一个：**数字由脚本生成，不由人登记**。这个库的总索引 frontmatter（9 域 / 57 组 / 500 束）是门禁从目录树里"数"出来的——它每次提交都被机器对账，人根本插不上手。

下次再看到任何"我们收录了 X 万条"的官方声明，先问一句：这个数字是脚本数出来的，还是人写上去的？

## 结尾：五条反常识，其实是一条

把这五条放回一起看，它们指向同一件事：

**AI 时代，把"质量责任"从人脑搬进流程，是唯一可扩展的路线。** 先让规范自举（一），把可信做成流程属性（二），用低风险内容练兵（三），给重构装安全网（四），把度量交给机器（五）——每一步都在做同一件事：让"可信"不再依赖某个人的水平与运气。

但别误会，这不意味着人退场了。恰恰相反：**流程负责"看起来对"以上的部分，人负责"对"本身**——对抗审查、语义判断、信源独立性裁决，仍是整条流水线最贵、最不可压缩的环节。

500 个知识包不是重点。重点是：当内容的"可信"可以由流程背书时，我们才第一次有条件大规模使用 AI 生产知识——而不是被它生产。
