# 02 生产管线与选型：工序五段·双范式选型法

> 模式成熟度：L1（跨 ≥2 个生态方案验证形态一致；迁移至播客/资讯领域为设计推演，未见落地实证）
>
> 时点声明：本页 skill 清单、口径与实测"本机可用"标记均为 2026-10-20 时点快照；开源生态与平台规格随上游演进，引用以当期为准。

## 0. 术语速查（正文首次出现，统一在此定义）

| 术语 | 含义 |
|---|---|
| **storyboard.json** | 流水线各 skill 之间传递的结构化分镜文件（合同字段如 `hook/scene/duration/screen_text/sources`），详见 §5 |
| **5-beat（五拍）** | 短视频分镜的五节拍结构（钩子→展开→递进→高潮→收束一类节奏骨架），用于钩子与镜头分配 [F-024] |
| **T2V / I2V** | 文生视频（text-to-video）/ 图生视频（image-to-video），生成式成片的两种入口 [F-007] |
| **Ken Burns** | 对静态图施加缓推/缓移的动效处理，让静图"动起来像视频"，程序排版线的镜头兜底手段 [F-021、F-024] |
| **ASS** | Advanced SubStation Alpha 字幕格式，可定义字体、位置、逐词同步与花字样式 [F-024] |
| **LUFS** | 响度单位（loudness units full scale），短视频平台主流目标响度 ≈ -14 LUFS [F-024] |
| **质量门** | 阻断式校验点：未通过即停止交付（fail-loud），区别于"事后汇报型"检查 |

## 1. 适用于 / 不适用于

**适用于**：任何"让 Agent 帮我做短视频，帮我选/搭 skill 流水线"类任务；个人量产（口播/知识/带货）与企业批量生产均适用。

**不适用于**：①只要一条随手拍素材（手机直拍直传，无需 skill）；②互动 H5 玩法类的抖音互动空间交付（那是 douyin-interact-creation 的自有约束体系 [F-011]）；③追求逐帧 keyframe 手工精修的电影级制作（作者自报本方法可覆盖约 80% 常规剪辑 [F-026 自报口径，未经第三方验证]，其余属人工领域）。

## 2. 五段工序模型

调研样本中的头部流水线（本机 + 开源 8 仓库）多数能映射到同一组工序 [F-019、F-020、F-022~F-026]：

```mermaid
flowchart LR
    S1["① 策划<br/>选题/钩子/脚本/分镜"] --> S2["② 素材<br/>静图/实拍/生成/抠像"]
    S2 --> S3["③ 音频<br/>TTS配音/ASR校对/BGM"]
    S3 --> S4["④ 合成<br/>渲染/字幕/转场/响度"]
    S4 --> S5["⑤ 发布质检<br/>平台规格/封面/合规门"]
```

| 工序 | Agent 负责（创意判断） | 脚本/CLI 负责（机械执行） | 质量门标配 |
|---|---|---|---|
| ①策划 | 选题、受众、钩子类型、分镜结构（如 5-beat） | 转写竞品作对标输入 | 事实先行：论断未核实不进脚本 [F-022] |
| ②素材 | 画面方向、风格锚点、一致性约束词 | 文生图/图生图调用、Ken Burns 直出 | 用户目检预览门（生成画面禁汉字）[F-010] |
| ③音频 | 口播稿改写、音色推荐 | edge-tts/Kokoro/local-tts 逐句合成、ASR 校对时长 | 响度标准化（≈-14 LUFS 两遍）[F-024] |
| ④合成 | 转场/花字/节奏决策 | ffmpeg/Remotion/HTML 渲染、ASS 字幕、BGM 闪避 | 字形检测（emoji/汉字）[F-021] |
| ⑤质检发布 | 发布文案策略、AB 标题 | 平台导出（9:16 安全区）、封面挑帧 | 平台规格+广告法自检 [F-024] |

## 3. 双范式判定（核心决策）

**范式 A：生成式成片。** 适用：品牌感强、前期高投入低产量、每秒画面价值高（产品/节日情感/虚构剧情）。约束：秒级计费、需要 API Key（ARK 等）[F-007]、生成分镜/脚本/成片全链有一致性约束词表 [F-020、F-023]；AI 画面禁出现可辨文字 [F-010]。

**范式 B：程序排版成片。** 适用：解说、知识、资讯、带货主图、批量复刻——内容核心是"信息+节奏"而非画面奇观。特征：零 Key、本地 ffmpeg/Ken Burns/Pillow/HTML 渲染兜底 [F-021、F-024、F-025]，每个镜头有固定预算（时长与信息密度），生成模型退化为可选项。

**判定规则**：先用 B 成片 dry-run 出 15s 预览稿（Ken Burns/黑底卡帧），观众或用户确认后再评估是否需 A 补关键镜头。错用 A 范式的三个误区：①烧钱抂数量——画面奇观不等于信息有效；②一致性失控——每镜重抽都会漂移主体/商品外观；③修改迭代贵——改一句口播，生成式要逐镜重新出片，程序排版改字幕即交付。

**成本估算三步法**（经验法，非官方定价；本包不收录具体价格数字，以厂商当期官网为准）：

1. **数镜头**：按分镜把 A 范式镜头数 n 与每镜秒数列出来（例如 3 镜 × 5s）；
2. **查单价**：厂商当期官网"每秒/每次生成"定价 × 镜头秒数 × n；
3. **乘返工系数**：首版过目检门后通常仍会因一致性漂移/崩字重生成（经验上 1~3 次），预算按 2~3 倍留上限。

**范式与量产不硬绑定**：douyin-video-forge 面向 Cron 每日量产却走 A（可灵 3.0 + Seedance 双版脚本）[F-020]——量产选型时先算清逐镜一致性锁定成本再决定，别把"省钱=B范式"当成教条，也别把"质量=A范式"当成借口。

## 4. skill 映射矩阵（每段 1~2 个候选）

| 工序 | 优先候选（带质量门） | 备选 | 本机可用 |
|---|---|---|---|
| ①策划 | hook-3s-script（9 型钩子）、viral-remake（爆款五拍拆解） | LLM 自由发挥 | ✅（LLM 自带能力） |
| ②素材 | selling-point-storyboard / Seedream 分镜静图 | Pexels/Pixabay 实拍素材 [F-022] | ✅ byted-seedream / image-gen |
| ③音频 | ai-voiceover-edge-tts / hyperframes-media tts | local-tts（Intel AIPC 离线）、TTS 大厂 API | ✅（宿主层 local-tts 离线可用） |
| ④合成 | ffmpeg-auto-assemble / hyperframes render / short-video-maker(Remotion) | 表演级可选 Seedance I2V | ✅ hyperframes+mediakit |
| ⑤发布质检 | platform-spec-export / cover-title-AB | 手工导出 | ✅ |

> 时点快照声明：上表"✅"为 2026-10-20 本机调研时点实测；读者环境可能不同，以"本机实际注册的 skill"为准（含宿主注入层 [F-018]）。

选型时对每个候选过"三问门禁"（见 [index.md 洞察 3](../index.md)）：①有没有交付前的阻断检查点？②失败 fail-loud 还是无声降级？③发布权限是否绑定具体产物？

## 5. 中间契约：storyboard.json

多 skill 协作的通用做法是用一个结构化分镜文件串接所有工序 [F-019、F-022、F-024]：策划 skill 写入 `hook/scene/duration/screen_text/sources`，音频 skill 按句合成并回填 `tts_duration`，合成 skill 消费全部字段渲染，导出 skill 按 platform goal 产出。**契约的价值**：单点 skill 可替换（换 TTS 引擎/换渲染器不动上游）——这是"簇形态"的工程表达（见洞察 1 与其单体系反例）。

## 6. 发布前合规门（2025-09-01 起的法定义务）

依据《人工智能生成合成内容标识办法》（国信办通字〔2025〕2号，2025-03-07 印发、2025-09-01 施行）及配套强制性国标 GB 45438-2025 [F-031、S20]：

- **显式标识**：视频须在起始画面和播放周边的适当位置添加用户可明显感知的显著提示标识（下载/导出时文件中须保留满足要求的显式标识）；
- **隐式标识**：生成合成内容的文件元数据中应含生成合成属性信息（服务提供者名称/编码、内容编号等）；
- **用户义务**：使用平台发布生成合成内容时，**用户应主动声明**并使用平台提供的标识功能；抖音等平台已上线 AI 内容声明入口；
- **红线**：任何组织和个人不得恶意删除、篡改、伪造、隐匿标识，也不得为他人恶意删改提供工具或服务。

操作化清单（叠加到 ⑤ 段导出前）：

1. 范式 A 成片（生成式画面）：合成时保留/叠加起始画面提示帧，元数据不被清洗；
2. 范式 B 成片但素材含 AI 生成图/视频：同样需要标识；
3. 具体样式参数（提示标识的高度/位置/时长等）以 GB 45438-2025 当期文本与平台规范复核——本页只记录义务存在与时点。

## 7. 反模式

1. **单点全能幻想**：找"一个最强的短视频 skill"一步到位——调研样本内多数头部方案按工序拆簇协作（单体反例的内部也分层）。
2. **默认接视频模型**：量产内容全走 T2V/I2V——成本、一致性、返工全线恶化（但见 §3 边界反例：量产≠必须 B，先算成本）。
3. **模型自评代替目检**：让模型自己说"效果很好"就交付——一切交付走人眼门禁，模型自评属"表演式审查"。

## 8. 检验标准

方案合格当且仅当：每个工序有 ≥1 候选 skill 且标注阻断门；存在 storyboard.json 契约；成片交付前多数场景可 0 成本本地 dry-run 预览；交付包内含可审计 sources；并且已过 §6 合规门。

## 9. 新人第一步：最小可跑通组合

1. **先读 [03 概念页的"线 1"（口播/知识讲解线）](03-recipes.md)**——它是本模式的最小完整实例，不需要任何 API Key；
2. **首装最小组合**：Node.js + ffmpeg + edge-tts（免 Key）——即可跑通"钩子口播稿 → 逐句配音 → ASS 字幕 → ffmpeg 合成 9:16"；
3. **加一条排版带**：`npx hyperframes init --example <name>` 起步（HTML/GSAP 动效线，见 [F-012、F-013]）；
4. **需要生成式画面时**再申请 API Key 接 Seedance/Seedream（先过 §3 成本三步法），生成画面中禁出现可辨文字 [F-010]。

## 10. 迁移说明

同五段模型可推演迁移至：图文排版流水线（素材段换水印/字幕段换格式）、播客制作（③ 音频为主工序、④ 合成退化为拼接）、数字人直播课件（② 素材段换数字人资产）。三个领域形态一致性经对抗审查确认成立；**注意**：样本为设计推演，未见落地实证报告——定级保持在 L1，待任一领域实际迁移案例后升级 L2。
