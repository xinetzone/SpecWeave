# Medium 产品形态与设计理念

## 设计总纲

Medium 的产品设计围绕一个目标：**让深度阅读成为可观察、可激励的行为** [S02][S03]。体现为三层：

1. **写作层**：极简编辑器降低创作摩擦，让内容本身成为主角；
2. **发现层**：Tag 体系按主题而非作者组织内容，让高质量内容上升到头部；
3. **反馈层**：Claps、高亮、阅读完成度等信号，把"深度"变成可量化的信号并接入收入分配。

## 编辑器与写作体验

| 功能 | 事实 | 信源 |
|------|------|------|
| 编辑器形态 | WYSIWYG / 类 Markdown 简洁界面，取消传统博客工具栏 | [S01][S02] |
| 技术底座 | 早期基于 TinyMCE，主站 Node.js | [S01] |
| 移动编辑 | 2015-03 起 iOS 可编辑发布，2015-06 起 Android 应用 | [S02] |
| 发布 API | 2015-03 升级，支持 WordPress 插件、Ulysses、IFTTT 等第三方工具交叉发布 | [S02] |
| 排版 | 首字放大、多字体标题格式，移动端可读性优先 | [S02] |
| 协作 | 注释（2013 起）：作者可邀请同事协作，发表后署名提及 | [S02] |

## 互动与反馈机制

### Claps（2017-08 取代 Recommend）

- 读者可对一篇文章鼓掌最多 50 次，表达支持强度 [S01][S02]；
- 早期按 Claps 分配作者收入，后调整为"会员阅读时长为主" [S01][S03]；
- 设计动机（原工程师 Katie Zhu）："二元点赞只告诉你多少人认为好，不告诉你有多好" [S02]。

### 高亮（Highlight）

- 2013 年推出，2015-03 起全体读者可高亮任意段落——把"读到哪里有价值"变成公共信号 [S02]。

### Tag 体系

- 文章按主题（tag）分类而非按作者分类，与 Blogger 等传统博客不同 [S01]；
- 作者"给类别添加文章"而非"给文章添加类别"——内容优先于作者身份 [S02]。

## 内容组织：Publications（出版物）

- Publications 是共享空间，有独立主页，像报纸/杂志一样承载编辑职责 [S01]；
- 可设编辑、草稿、独立品牌；2015 年起开放出版物参与赞助项目 [S02]；
- 2018-05 取消出版物自建付费墙能力（后恢复受限形式） [S02]。

## 阅读与分析指标

| 指标 | 说明 | 信源 |
|------|------|------|
| Views | 页面浏览（PV） | [S02] |
| Reads | 阅读完成度——区分"有人打开"与"有人读完" | [S02] |
| Recommends | 推荐数（2017-08 前） | [S02] |
| Total Time Reading | 平台级总阅读时长（2015-03 约 150 万小时/月） | [S01][S02] |
| Member Reading Time | Partner Program 分成的核心依据 | [S03] |

Medium 2013 年的分析理念："目标是凸显内容质量而非受欢迎程度，提供普通网络分析无法提供的反馈" [S02]。

## 会员体验

- $5/月 或 $50/年：解锁会员专属内容、音频朗读（text-to-speech）、增强书签 [S01][S03]；
- "你读的越多，作者赚得越多"——平台把阅读时长直接映射为对作者的支持 [S03]。

## 设计理念的行业影响

- Medium 的杂志级排版与"阅读时间"指标影响了整个在线出版行业：众多出版商与营销人员从依赖 PV 转向"注意力指标" [S02]；
- 被媒体评价为"重新点燃了长篇内容在线发布的兴趣"，并驳斥了"移动端无法做内容编辑"的误解 [S02]。

## 本概念要点

1. 编辑器、Tag、Claps、高亮、阅读指标构成闭环：创作→发现→深度反馈→激励。
2. 平台刻意弱化"作者身份"（署名导向、按主题组织），强调"内容质量"。
3. Claps 从"推荐"演进为"收入信号"，是商业模式与产品机制耦合的典型。
