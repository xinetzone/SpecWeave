# 07 监控、备份与韧性：发现要快，恢复要有底

> 本文是分层加固的最后一层：用日志与入侵检测保证"发生了什么能被知道"，用备份体系保证"即使被破坏也能恢复"。

## 7.1 日志与集中留存

- 系统认证日志位置：Debian/Ubuntu 为 `/var/log/auth.log`，RHEL 系为 `/var/log/secure`；也可用 `journalctl -u ssh` 查看；
- 关键审计对象：SSH 登录与失败、sudo 提权、用户与密钥变更、防火墙动作；
- 日志应远程同步到集中日志服务（日志平台、另一台专用日志机或对象存储归档），防止攻击者在本机抹除痕迹；
- 配置合理的日志轮转（logrotate），避免磁盘占满。

## 7.2 入侵检测与定期审计

```bash
# 文件完整性监控：安装并初始化基线
sudo apt install aide
sudo aideinit
sudo cp /var/lib/aide/aide.db.new /var/lib/aide/aide.db

# 定期比对（建议加入月度计划）
sudo aide --check

# 安全体检（建议每季度一次，按报告逐项整改）
sudo apt install lynis
sudo lynis audit system
```

- 需要更细粒度审计时可部署 `auditd`，监控关键文件与提权行为；
- 更高要求环境可部署 HIDS（如 Wazuh）；
- 外部变更感知：定期复核云控制台中安全组、IAM 账户、API 密钥清单。

## 7.3 备份体系（3-2-1）

备份 3-2-1 原则：至少 3 份副本、2 种存储介质、其中 1 份异地存放。

实施要点：

1. 数据库使用逻辑或物理备份并定时调度，备份前校验一致性；
2. 备份文件**加密**后异地保存（如跨区对象存储）；
3. 备份目标使用**独立凭据**——与服务器登录账号分离，避免服务器被攻破后备份被连带删除；
4. 对象存储开启版本控制与 MFA 删除保护；
5. 备份范围除数据外，还应包括配置文件、自动化部署脚本，并记录恢复所需的软件版本。

## 7.4 恢复演练（不可省略）

只备份不验证，在需要时可能发现备份不可用。建议：

- 每季度执行一次真实恢复演练：从备份在隔离环境重建服务，验证数据完整性与业务可用；
- 留存演练记录（时间、备份点、耗时、发现的问题）；
- 编写并维护一页纸的恢复操作手册，明确负责人与联系人。

## 7.5 长期运维节奏

| 节奏 | 事项 |
|---|---|
| 每月 | 确认安全更新与备份任务执行成功；抽查登录日志与封禁记录；核对新增端口/服务 |
| 每季度 | Lynis 体检；AIDE 基线比对；恢复演练；账户与密钥清理；安全组与 IAM 复核 |
| 事件驱动 | 人员离职当日收权；新业务上线先走暴露面评审；重大漏洞公告后 24 小时内排查 |
| 持续 | 将加固清单固化进初始化镜像、Cloud-Init 或 Ansible 配置，保证新实例默认达标 |

## 7.6 验收标准

- 关键日志可在集中平台查询，删除本机日志后远程仍有留存；
- AIDE 基线已建立并能完成一次比对；
- 至少一份加密备份位于异地且使用独立凭据；
- 完成一次恢复演练并有记录。
