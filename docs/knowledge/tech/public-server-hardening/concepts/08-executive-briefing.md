# 08 非技术人员执行摘要：管理者需要知道什么

> 本篇面向不从事技术工作的负责人与管理者，用通俗语言说明加固工作的内容、顺序、红线与验收方式。

## 8.1 一句话结论

加固不会让服务器绝对安全，但能挡住绝大多数自动化攻击。这类似于给临街店铺装门锁、监控和报警器——不是因为一定遭窃，而是无人防护的店铺会被优先光顾。核心工作通常一至两个工作日可完成，长期维护则需要固定节奏。

## 8.2 这些措施在做什么（通俗对照）

| 技术措施 | 通俗理解 |
|---|---|
| 关闭不必要的端口和服务 | 封死不用的门窗，只留正门 |
| 防火墙 | 门口保安，默认任何人不得入内，逐人审批 |
| SSH 密钥登录、禁用密码 | 用门禁卡替代口头暗号，无法反复试密码 |
| fail2ban | 连续几次敲门试探者，保安自动拉黑 |
| 安全更新（打补丁） | 房屋出现隐患及时维修 |
| CDN / 隐藏真实地址 | 只公布前台接待地址，真实办公楼位置保密 |
| 日志与监控 | 安装监控摄像头，事后能查清谁来过 |
| 备份 | 重要文件复制一份锁进异地保险柜 |

## 8.3 需要安排的六件事

1. **当天**：清点并关闭非必要通道；远程管理改用密钥；部署自动拉黑；
2. **一周内**：安装全部安全更新并开启自动更新；启用网站加密访问（HTTPS）；
3. **两周内**：接入 CDN 或防护服务，隐藏真实地址并获得抗攻击能力；
4. **持续**：落实最小权限，任何人只拥有本职所需权限；
5. **同步**：建立自动备份，加密、异地、独立账号，并定期实际恢复一次；
6. **长期**：按月确认更新与备份，按季度做一次安全体检。

若无专职技术人员，应将工作书面委托给运维服务商，并要求提供检查结果与验证记录，而非仅口头确认"已处理"。

## 8.4 操作红线（注意事项）

1. 修改远程登录设置时保留一个已登录窗口，另开新窗口验证后再结束，防止所有人无法登录；
2. 云服务器有"两道门"：云控制台安全组与服务器内防火墙都要配置；
3. 不在网上随意复制命令执行，不使用来历不明的"一键加固脚本"；
4. 修改登录端口不是真正的防护，不能替代换锁和安保；
5. CDN 必须配合"只接受 CDN 来访"设置；真实地址曾泄露的应申请更换 IP；
6. 备份凭据必须与服务器分离，并开启防删除保护；
7. 一切默认口令（服务器、数据库、面板、设备）交付后立即更换；
8. 加固期间逐项变更、逐项验证，便于定位故障；
9. 涉及个人信息或经营数据的系统，还需确认相关法律法规的合规要求。

## 8.5 如何确认工作做到位（验收证明）

管理者无需理解技术细节，可要求提供以下证明：

- 外部扫描结果显示对外开放的只有网站入口，没有多余端口；
- 使用密码远程登录会被拒绝，只能通过指定密钥进入；
- 防火墙、自动拉黑、自动更新的运行状态截图或记录；
- 网站显示安全连接标识，访问旧地址自动跳转；
- 一次真实备份恢复演练的时间记录与结果确认。

## 8.6 长期意识

安全加固是类似消防设施的持续维护：补丁持续更新、日志定期复查、备份定期演练、人员离职及时收权。建议指定一名负责人，按月确认、按季度检查，防止上线时的加固状态随时间重新门户大开。
