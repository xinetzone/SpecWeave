# 06 成本、折旧与度量：harness 的第二条曲线

> 读完本文你会知道：为什么 2026 年主流 harness 都在主动"变薄"、变薄省下的到底是什么、凭什么敢变薄，以及你手上的 harness 什么时候该删东西、什么时候绝对不能删。

## 6.1 折旧定律：harness 是"关于模型不能做什么"的假设集合

Anthropic 2026-04 的工程文章给出一个去厂商化的定义：agent harness 是"围绕模型的软件脚手架——循环、工具、上下文管理与护栏，把原始智能变成可工作的 agent"；而 harness 设计本身就是"决定脚手架里该放什么，以及随着模型变强可以拿掉什么"（F-049）。

这句话把 harness 从"功能集合"重新定义成**假设集合**：每一个部件都在编码一个"模型当前做不到"的判断。提示词里的分步指令假设模型不会自己拆解；格式约束假设模型不会自然输出合规结构；规划模板假设模型会丢步骤；示例假设模型需要一个模仿样板。模型能力每跃迁一次，这类假设就有一部分过期，部件从"能力补偿"变成"死重"——它继续消耗 token、稀释注意力，还可能和新模型自己学会的行为打架（F-052）。

但"都会折旧"是错的。按失效方式，部件要分三类：

| 类型 | 例 | 它在补偿什么 | 折旧特征 |
|---|---|---|---|
| **能力补偿型** | 分步提示词、few-shot 示例、格式约束、规划模板、纠错重试循环 | 模型的推理/格式/规划缺陷 | **快速折旧**：随模型代际失效，且失效后会扣分（F-046/F-051/F-052） |
| **治理型** | 权限、审批、沙箱、审计日志、预算闸 | 人的风险敞口，不随模型变强而消失 | **不折旧，反向增强**：模型越自主，越需要边界（F-037/F-039） |
| **界面型** | bash、文本编辑器、文件读写等基础工具的动作粒度 | 模型训练分布里的既有习惯 | **半衰期长**：模型在这些接口上被训练过，换掉等于放弃训练红利（F-049） |

这条分类是本文的核心判据，也是本知识包 v1.1 最重要的一条修正：**该删的是补偿，不该删的是治理**。把"变薄"当成普适口号，会得出"砍掉审批"这种灾难性结论。

## 6.2 三条实证：2026 年确实在发生"主动减配"

### 证据一：Deep Agents v0.7 把基础输入砍掉 65%

2026-07-24 发布的 Deep Agents v0.7 做了三件事（F-046）：

1. **删掉内置 system prompt**（通用指引与工具使用说明那一段）；
2. **工具描述削减 43%**；
3. **把 `TodoListMiddleware` 从默认栈里移除**——作者的原话是评测显示"规划提示词 + `write_todos` 工具没有显著提升表现"，需要时一行代码 `middleware=[TodoListMiddleware()]` 加回来。

三项合计使默认 agent 单轮的**基础输入 token 从约 6k 降到约 2k（-65%）**，而作者声称评测奖励持平（F-047）。

值得注意的是验证方式：他们用三类评测（自主任务 / 多轮对话 / 长上下文）× 四模型（`gpt-5.6-luna`、`gemini-3.6-flash`、`claude-sonnet-4-6`、`claude-opus-4-8`）与 v0.6.12 做对照，并**如实声明"每个模型的奖励置信区间都跨零"**（F-047）——也就是说，能确证的是 token 下降，不是效果提升。这种"只主张数据能支撑的部分"的写法，本身就是可复用的示范。

### 证据二：Claude Code 的系统提示被砍掉八成以上

Anthropic 对 Opus 5 / Fable 5 一代模型把 Claude Code 的 system prompt 削减超过 80%，编码评测无可测下降（F-051，**该数字由 LangChain v0.7 文章转述，本包未回到 Anthropic 一手报告逐项核验**）。同一篇 Anthropic 文章记录了一个更锋利的例子：他们曾为 Sonnet 4.5 的"上下文焦虑"（临近上下文上限就草草收尾）加了 context reset 机制；到 Opus 4.5，这个行为自己消失了，那套 reset 就成了纯死重（F-052）。

### 证据三：mini-swe-agent v2 仍是一百来行

mini-swe-agent 现为 v2（PyPI 2.4.6，2026-07-23），README 宣称 SWE-bench Verified 超过 74%，核心 agent 类仍是约 100 行，且被 Meta、NVIDIA、IBM、Nebius、Anyscale、Princeton、Stanford 等机构使用（F-054）。SWE-agent 官方文档现在的表述是"建议改用 mini-swe-agent，它已取代 SWE-agent"（F-056）。

> **口径警告**：以上三条证据全部来自厂商或项目方自述。可机械验证的是**token 与代码行数**这类结构指标；"效果不降""超过 74%"属于自报结果，且评测设计方与产品方是同一批人。引用时请保留这一层限定。

## 6.3 上下文经济学：成本首先是"布局问题"，不是"框架厚薄问题"

Messages API 是无状态的——模型看不到上一轮，harness 每一轮都必须把所有历史动作、工具描述与指令重新打包送进去（F-050）。这决定了一条容易忽视的会计事实：**agent 的边际成本 ≈ 每步输入 token × 步数 × 单价**，而输入 token 的单价不是常数。

Anthropic 的计价中，**命中缓存前缀的输入 token 只按基础输入 token 的 10% 计费**（F-050）。于是同一模型、同一任务，在 Claude API 的计价下，两个 harness 的成本可以差近一个数量级——差别不在"框架重不重"，而在**前缀是否稳定**。同一篇文章给的五条前缀纪律可以直接当工程规范用（F-050）：

| 原则 | 做法 | 违反的代价 |
|---|---|---|
| 静态在前、动态在后 | 系统提示、工具定义放最前，易变内容放后 | 每次变动都让整段前缀失效 |
| 用 messages 传递更新 | 加 `<system-reminder>` 追加消息，而不是改系统提示 | 改一次前缀 = 全量重算 |
| 会话中不要换模型 | 缓存是模型专属的，换模型即清零；要便宜模型就用子 agent | 中途降级反而更贵 |
| 谨慎管理工具集 | 工具定义位于缓存前缀内，增删一个就失效；动态发现用 tool search 追加 | 每加一个工具都在重置缓存 |
| 维护缓存断点 | 多轮场景把断点移到最新消息，或用自动缓存 | 缓存永远追不上对话 |

由此可以定义三个一等成本指标（比"框架代码行数"更能预测账单）：

1. **base input tokens**——默认装配自带的固定开销（v0.7 把它从 6k 压到 2k，F-046）；
2. **每任务输入 token**——步数 × 每步上下文，直接决定账单；
3. **缓存命中率**——命中部分按 1/10 计价，命中率每掉 10 个百分点，输入成本近乎翻倍。

> **口径警告**：10% 是 Anthropic Claude API 的缓存折扣（F-050），其他厂商的缓存计价与失效规则不同，不可直接外推。跨厂商比较成本时，必须按各自价目表重算。

这条视角也修正了 [04 编码 agent 赛道](04-coding-agent-track.md) 对 F-032 的一种常见误读：mini-swe-agent 每任务 0.37 美元对 SWE-agent 2.50 美元的差距，一部分来自 scaffold 厚度，另一部分来自**上下文形态**——线性消息历史天然产生稳定后缀，前缀（系统提示 + 工具集）固定不变，因此缓存命中率高；而频繁变化工具集或重复注入状态的 harness，会把同样的模型用贵好几倍。

## 6.4 减法的前提是度量：没有 eval 的团队只能冻结在旧假设上

折旧定律要求持续删减，但删减是高风险的：删错了，评测分数会掉，而你可能两周后才发现。v0.7 的每一次删减都配了对照实验（F-047）；Pydantic 有 Pydantic Evals，Strands 把 evals 做成独立产品线（F-021/F-024）——这些不是"上线前的验收工具"，而是**演进的许可证**。

一个够用的最小评测集可以直接沿用 v0.7 的三分类：

| 类别 | 测什么 | 对应部件 |
|---|---|---|
| 自主任务 | 端到端完成（编码、数据分析） | 规划、子 agent、shell |
| 多轮对话 | 与模拟用户来回澄清 | 记忆、上下文压缩、HITL |
| 长上下文 | 长文档检索与推理 | 压缩策略、文件系统、断点 |

没有这个基线，团队只有两条路：一是不断加部件（因为不敢删），二是锁版本冻结（因为不敢升）。两者都在把折旧成本延后支付，而不是消除。

## 6.5 折旧审查表：给你的 harness 做一次季度体检

对每个**已启用**的部件填一行（不是对清单上的九件都填，只填真在跑的）：

| 部件 | 类型 | 它假设模型做不到什么 | 上次验证日期 | 失效条件 | 复查动作 |
|---|---|---|---|---|---|
| 例：分步规划提示词 | 补偿 | 模型不会自己拆解长任务 | 2026-07（v0.7 评测） | 新模型自主任务得分 ≥ 基线 | 关掉跑对照，掉了再加回 |
| 例：工具调用重试循环 | 补偿 | 模型输出格式不稳 | — | 解析失败率 < 1% | 改为单次重试或删 |
| 例：危险动作审批 | 治理 | 人不接受不可逆副作用 | 持续 | 不失效 | 不许删，只能调细粒度 |

四个复查问题（照抄就能用）：

1. 这个部件补偿的是**模型的缺陷**，还是**人的风险**？后者不许删。
2. 如果今天从零写这个 harness，我还会加它吗？
3. 它最近一次被证明有用是什么时候、用什么测的？
4. 删掉它之后，哪个指标会掉？如果答不出，说明你没法安全地删——先补 eval。

## 6.6 边界：折旧定律不适用的地方

- **弱模型场景**：v0.7 明确保留 todo 机制的三类场景之一是"能力较弱的模型，需要更多脚手架才不丢步骤"（F-046）。补偿型部件对弱模型仍然有效。
- **治理型部件反向增强**：模型越自主，审批、审计、沙箱的价值越高（F-037/F-039）。把折旧定律套到治理层，是拿事故换 token。
- **界面型部件动得慢**：bash 与文本编辑器之所以成为事实标准，是因为模型在这些接口上被大规模训练过；替换它们要付出重新适应的成本（F-049）。
- **高价值长任务**：检查点、恢复、tracing 的成本是固定的，但一次失败重跑的成本可能远高于它——这类部件按失败成本判断，不按 token 判断（见 [05 模式](05-selection-pattern.md) 步骤①）。

一句话收束：**折旧定律不是"越薄越好"的许可证，而是"定期重估"的纪律**。它管的只是能力补偿型部件。

## 6.7 与本知识包其他结论的关系

- **I-1（杠杆从 scaffold 移向 model + environment）是折旧定律的一个静态截面**。I-1 说"薄栈在基准上只差 2 个百分点"；本文补上机制：差距会随模型代际进一步收窄，因为补偿型部件正在被模型吸收。
- **I-2（竞争转向治理）在折旧框架下有了必然性**：能力补偿型部件折旧快 → 靠它做不出差异化 → 厂商只能把差异化押在治理原语与交付形态上（后者见 [03 框架目录](03-framework-catalog.md) 的托管档）。
- **I-3（生命体征检查）应扩一项**：除了发版频率与维护状态，还要看"这个项目有没有 eval 能力"——没有 eval 的项目，其默认装配只会越堆越厚。
- **02 的九大部件要按本文的三分类重新读**：哪些是补偿（可删）、哪些是治理（只增）、哪些是界面（少动），见 [02 §2.1](02-harness-anatomy.md) 的限定说明。
