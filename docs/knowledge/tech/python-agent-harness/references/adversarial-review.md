### 视角一：魔鬼代言人（质疑事实与推断强度）

**O1｜TTFA/LOC 实测是单一第三方博客，且任务定义不明**

F-003/F-004 的全部量化对比（7–26 分钟、18–84 行、34%、45.9K、$18M）来自 growthengineer.ai 一篇文章。"同一任务"的具体内容、评测者对各框架的熟悉程度、硬件与网络条件均未在引用处交代；该站本身有厂商导流性质。初稿在 I-1 与概念页 05 中把 7 对 26 分钟的差距叙述得过硬，读者可能把它当成可重复的实验结论。

45.9K（CrewAI，2026-03）、58.9K（AutoGen，2026-06）、76K+（OpenHands，2026-06）、44K（Aider，未注时点）、12.7K（Strands，未注时点）五个数字的采集时点与信源类型不同；初稿总表若不加约束，极易被读成"热度排行榜"。
**裁定：采纳。**

**O3｜"harness"可能只是厂商造词，调研却把它当成品类实体**

"harness"作为产品品类名主要由 LangChain 在 Deep Agents 营销中推广（F-002），MAF/Strands/Pydantic 的同名产品层也可能是跟风命名。把九项能力说成"事实标准"存在循环论证风险：厂商互相抄命名，不等于用户侧形成了标准。
**裁定：采纳（补术语辨析，不推翻结构）。**

**O6｜SWE-bench 分数跨模型跨采样不可比，95.8 与 65% 同表出现即误导**

mini-swe-agent 的 65%（Sonnet 4）、SWE-agent 的 67%（SL#68 口径）、OpenHands 的 95.8（claude-fable-5，2026-06-09）三者模型、采样次数、框架版本、成本口径全不同；F-034 的 60.6%/66.4% 自身就演示了单次与 5 次采样的差距。初稿 04 概念页需要显式口径警告，否则读者必排座次。
**裁定：采纳。**

## C.5 第二轮：四视角与意见清单（v1.1 增量内容）

### 视角一：魔鬼代言人（质疑 v1.1 的推断强度）

**O8｜折旧定律的三条证据全部来自 harness 卖方，且"效果不降"是自报**

F-046/F-047（LangChain）、F-051/F-052/F-053（Anthropic）都是厂商官方博客，两家都在卖 harness。厂商说"我们把默认装配砍了、效果没降"，对自己有利——它同时暗示"我们的 harness 更精炼"。而"效果不降"依赖自建评测集与置信区间，外部无法复现。初稿把 token 数字与效果结论并排陈述，读者容易把两者当作同等强度的证据。
**裁定：采纳。** 全篇拆分为"可机械验证"（token 数、代码行数、工具描述削减比例）与"自报"（奖励持平、基准分数），并在局限声明中新增第⑥条。

**O9｜"harness 在变薄"被写成普适规律，但同期治理部件是在增强的**

初稿的折旧定律若被理解为"所有部件都该删"，会与本文档自己的 I-2（竞争转向治理）矛盾，更危险的是可能被读成"审批、沙箱也可以简化"。事实上 2026 年同期：Claude Agent SDK 强化 permissions/hooks，MAF 增加 Provider 层，Copilot harness 把认证与审批列为四个构件之一（F-018/F-012/F-058）。减配发生在**提示词与规划类部件**，不发生在治理类部件。
**裁定：采纳（本轮最重要的一条修正）。** 引入三分类——能力补偿型（折旧）、治理型（反向增强）、界面型（半衰期长），把折旧定律的适用域限定在第一类，并在 06 §6.1 与 I-5 的行动项中明确写出"该删的是补偿，不该删的是治理"。

**O10｜"缓存 token 按 10% 计费"是 Claude API 的价目，不能当行业通例**

F-050 明确出自 Claude API 计价说明。初稿在 I-6 与 06 §6.3 用"输入成本可差近一个数量级"的表述，容易被外推到任意厂商。
**裁定：采纳。** I-6、06 §6.3、03 相关段落全部加"在 Claude API 计价中"的限定，并在 A.6 登记为无效路径。

**O11｜mini-swe-agent 的 ">74%" 与"击败 Claude Code"存在循环论证风险**

"击败 Claude Code"来自项目方 README；而 DeepSWE 基准把 mini 固定为唯一 harness（F-057）——在该榜上，"mini 优于某产品"不是被测结论，而是设计前提。
**裁定：采纳。** 04 §4.2 标注"项目方自述"，§4.3 新增"先看榜单是否固定 harness"的读法，并说明固定 harness 的榜单不能反推 harness 优劣。

### 视角二：新人（能否找到新内容的入口）

**O12｜新增 06 页与既有五页的关系不清楚**

06 讨论的是"成本与折旧"，但 02（部件）、03（目录）、05（模式）都会引用它，读者不知道应该在什么时机读，容易把 06 当作附录跳过。
**裁定：采纳。** index 快速导航新增一行（"搞清 2026 年 harness 为什么在主动变薄"）；05 页脚改为指向 06；02 §2.1 与 §2.4 增加内链；06 结尾回链 02/03/05。

### 视角三：决策者（成本与风险）

**O13｜托管 harness 的 vCPU 单价极易被误用为 TCO 依据**

0.0994 美元/vCPU·小时看着可算，但它是预览期价格、2026-12-01 才生效、随区域与协议变化，且不含模型推理（F-059）。若决策者直接乘上工期，会得到严重偏离的数字。
**裁定：采纳。** 03 §3.6 加显式口径警告与"三形态不可用同一张 TCO 表对比"的说明；index 局限声明新增第⑧条。

### 视角四：未来维护者（时效与一致性）

**O14｜v1.1 的版本号同样是快照，且已出现取数面冲突**

同一次复核中，Claude Agent SDK 的 PyPI 页面显示 0.2.152（2026-09-03），而 v1.0 记录到 0.2.161；说明项目页、JSON 接口、changelog 三处的"最新"可能不一致。若只写"最新版"，三个月后无人能判断当时到底看到的是什么。
**裁定：采纳。** 信源台账 A.5 新增第 6 条：版本号必须与"取数页面"同时记录，禁止只写"最新版"；03 §3.1 标注每个复核单元格的取数时点。
