## C.1 四视角与意见清单

### 视角一：魔鬼代言人（质疑事实与推断强度）

**O1｜"336M 镜像"误导磁盘规划**
初稿在选型表写"WSL 基础镜像（约 336M）"，读者会以为占用 336M 磁盘。实际 336M 是 gzip 压缩态下载体积（来源是本仓实测 S26，非官方文档明文），导入解压后 VHD 约 1.1G 量级；且该数字随版本变动。教程把一个"时点实测值"呈现为"官方规格"，属于事实来源混级。
**裁定：采纳。**

**O2｜公开默认凭据无安全提示**
概念页 03 直接给出预置账号密码 `openkylin/openkylin` 与 xrdp 3390 端口，却没有任何安全警告。读者若照做并把端口暴露/长期不改密码，弱口令风险真实存在；教程对"本机体验场景"与"可联网场景"未做边界切割。
**裁定：采纳。**

**O3｜I-3 把"文档存在"论证得过强**
"SDK 手册是证据""比发布会特性更硬"方向正确，但"四层齐备才按平台级能力采信"暗示有文档=能力可用。教程并未实机安装 AI SDK、未调通任一接口、未验证模型当前可下载，文档规模只证明"被设计并文档化"。
**裁定：采纳（加证据边界，不推翻洞察）。**

**O4｜🆕 标记的统计口径会被误读**
full-catalog 的 🆕 仅依据 commits API 默认返回的最近 12 条提交，读者可能理解为"其余文件 2026 年均无更新"，而我们并未对 237 篇做全历史 git log。
**裁定：采纳。**

### 视角二：新人（能否照着完成决策与操作）

**O5｜选型表没有"想要桌面的 Windows 用户"的直接答案**
初版选型表 WSL 行只写基础镜像，"想体验完整 UKUI 桌面"行直接跳到虚拟机；Desktop WSL 镜像（最省事的图形路径）埋在正文第 3 步，新人按表决策时会错过。
**裁定：采纳。**

**O6｜跨文件锚点链接成批错误（机械审计发现）**
对全部文件做链接审计（grep `index.md#` 并逐一核对目标锚点是否存在），发现 7 处问题：02/03/05 中 6 处"姊妹调研"链接被写成 `../index.md#<锚点>`——相对路径指向的是**本教程自己的 index**（锚点如 `#1-2-b-组版本时间线`、`#1-4-d-组ai-能力演进` 在本教程均不存在），实际目标是 `../../openkylin/index.md`；另有 1 处自指 I-3 锚点含全角空格，docsify/GitHub 锚点生成不可靠。属确定性断链。
**裁定：采纳。**

### 视角三：决策者/老板（成本、风险、结论边界）

**O7｜教程可能被误读为"openKylin 可上生产"的背书**
本教程是文档导读，但概念页 02 的版本选型表、05 的 AI 能力清单组合起来，容易被决策者当成选型结论；教程没有任何独立的稳定性/性能/兼容性验证。
**裁定：登记为局限（不改正文结构）。** 理由：教程定位与边界已在摘要与各节声明，02 的选型表回答的是"轨道怎么选"而非"该不该用"；但应显式增加一条局限，声明不承担生产适用性背书、采用前需 POC。
