# 02 治理与生态形状：同构捐赠，两种下游

> 读完本文你会知道：两个社区的治理结构与捐赠路径如何对照、规模数字各自是什么口径、为什么形成"25 家 OSV 多点下游"与"单一商业下游加适配汇聚"两种生态形状，以及引用这些数字时必须遵守的纪律。

## 2.1 治理结构对照

| 维度 | openEuler | openKylin |
|---|---|---|
| 发起方 | 华为（EulerOS 开源，O-001/O-002） | 麒麟软件联合 13 家单位（K-001） |
| 基金会捐赠 | 2021-11-09 华为捐赠全量代码、品牌商标、社区基础设施（O-005） | 2024-09-25 麒麟软件捐赠，官方表述"我国首例央企开源捐赠"（K-002） |
| 顶层治理 | openEuler 委员会：常务委员会、顾问专家委员会、技术委员会、品牌委员会、用户委员会；项目群办公室加执行总监（O-006） | 理事会、秘书处、技术委员会、咨询委员会、生态委员会（本地包 F-037） |
| 技术治理单元 | SIG 加 Maintainer/Committer/贡献者三级角色（O-006） | SIG 加 Owner/Maintainer/Contributor 三级角色，权责限于各自 SIG（本地包 F-032） |
| 代码托管 | AtomGit/GitCode（src-openeuler 组织）、release-management 仓库；双域名并存（O-033） | Gitee openkylin 组织，配套 CLA、UKBS 编译、UKIF 镜像、UKCI 平台（本地包 F-009） |
| 芯片企业位势 | Intel、Arm、AMD 均为捐赠人；2025 年新增海光、AMD、浪潮云、神州数码（O-008） | 国产 CPU/GPU 厂商以适配与 SIG 方式汇聚（本地包 F-023） |
| 学术机制 | 联合 18 所高校成立学术与教育委员会（O-009） | 高校站与 55 个海内外用户组（本地包 F-055） |

同构点：两者都是"企业发起 → 运营成熟后捐赠开放原子基金会 → 委员会加 SIG 治理"的路径，与既有模式[根社区—商业发行版双轮](../../../../retrospective/patterns/methodology-patterns/product-growth/root-community-commercial-distro-flywheel.md)描述的结构一致。差异点在发起方的产业位置（见 2.3）。

### 口径使用纪律（四条）

1. **注册用户 ≠ 装机量 ≠ 出货套数 ≠ 市场份额**：openEuler 官网"社区用户约 1000 万"是注册口径，不得写成"1000 万装机"；装机序列（60 万→610 万→1600 万→2000 万）各有发布场合。
2. **厂商大会口径与第三方机构口径分开标**：2000 万套与"份额第一"为 2026-09-18 华为全联接大会口径（O-013）；57.3% 为沙利文加头豹白皮书经媒体转引，本调研未取得白皮书原文（O-012）；36.8% 标注 IDC 与 2023 年时点（O-011）。
3. **动态页面数据给区间不给点值**：官网首页两次抓取数值不同（O-007），引用时写"约 2.9 万贡献者、112 个 SIG（2026-09-30 官网实时页）"。
4. **跨社区不比大小**：SIG 112 与 158、贡献者 2.9 万与 2.4 万的统计门槛（是否要求 CLA、是否计入机器人/企业账号）无对齐文档，只能各自纵向看趋势。

## 2.3 两种生态形状的形成逻辑（洞察 I-2 的证据展开）

| 项 | openEuler 形状 | openKylin 形状 |
|---|---|---|
| 发起方禀赋 | 华为：云、鲲鹏、运营商/金融大客户、内核与虚拟化工程团队 | 麒麟软件（CEC）：党政桌面渠道、整机厂商关系、桌面环境 UKUI 积累 |
| 下游结构 | 首日即 4 家 OSV（O-003），官网现列 25 家（O-007）；多家竞争厂商同台（普华、统信、麒麟等） | 麒麟桌面商业版为书面明示的最大下游（K-012），另有 AgentOS/Claw Box OS 等社区衍生镜像（K-011） |
| 生态汇聚物 | 服务器栈项目群（StratoVirt/iSula/SysCare/Kmesh 等，O-027/O-028）、超节点与 NPU 特性（O-019） | 国产 CPU/GPU 与外设适配（本地包 F-023）、桌面软件/智能体上架（本地包 F-050）、RISC-V 统一镜像（K-010） |
| 变现与认证承接 | 各 OSV 自行承担合同、SLA 与测评；银河麒麟高级服务器 V11 SP1 通过安全可靠测评 II 级（本地包 F-061 为麒麟公司侧证据） | 麒麟桌面商业版承担认证与售后；测评主体同样是商业版而非社区版 |

中立基金会治理在两边都承担同一个功能：以商标与治理中立性吸引发起方的竞争方与上下游厂商进入（openEuler 侧 Intel/Arm/AMD 同为捐赠人即典型例证，O-008）。但中立化不改变生态形状——捐赠后两者各自仍沿发起方禀赋最强的区间生长。评估社区时应直接核查"非发起方企业主导的 SIG 与特性名单"，而非引用总量数字（本地包 V-05 对 openKylin 侧有同样的数据缺口登记）。

## 2.4 工程治理的可观察信号

- **安全响应透明度**：openEuler Release/QA/CICD SIG 每周发 update 邮件，含 CVE 清单与缺陷清单，多分支并行（O-022）；这是生产侧用户可以直接订阅的风险信号源。
- **开发者大会节奏**：ODD 2026 为年度线下技术大会，450 余人、109 个 SIG、八大方向（O-030），方向表可视为社区技术路线的年度公开样本。
- **供应链基础设施**：openKylin 侧有 OKBS/UKBS 编译平台、factory/UKIF 构建平台与 CLA 三分类的完整操作手册（本地包 F-027/F-031）；openEuler 侧以 src-openeuler 组织、release-management 仓库与周度公示运转（O-033/O-022）。两边均具备第三方复现构建的制度入口。
