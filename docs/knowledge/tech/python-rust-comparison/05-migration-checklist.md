# Python 迁移到 Rust 简易检查清单

> 本清单源自《Python 与 Rust 技术对比》Wiki（决策矩阵 [04-decision-migration.md](04-decision-migration.md)、代码示例 [03-ecosystem-scenarios.md](03-ecosystem-scenarios.md)）。**原则：不要一步到位整体重写**，推荐「识别热点 → 单点验证 → 渐进替换 → 全面固化」。每条可勾选，建议按序执行。

## A. 迁移决策（先确认「该不该迁」）

- [ ] 明确迁移目标：是性能、资源、内存安全，还是交付确定性？（不要「为了 Rust 而 Rust」）
- [ ] 用决策矩阵（04 章）自评权重与评分，确认 Rust 在本项目的优势维度确实占优。
- [ ] 确认迁移对象是**热点/核心**模块，而非整个业务层；业务编排层通常保留 Python。
- [ ] 确认团队具备或愿意投入 Rust 能力（学习曲线陡峭，需数周至数月）。
- [ ] 核算「迁移 ≠ 免费」：重写成本、测试回归、招聘供给、双栈维护都要纳入。

## B. 识别热点（迁什么）

- [ ] 用 profiling（cProfile / py-spy / perf）定位 CPU 密集、延迟关键、内存敏感的核心路径。
- [ ] 筛选「边界清晰、可独立封装、可测试」的模块作为首批候选。
- [ ] 优先候选：协议解析、数值计算、加密、高并发核心链路、CLI、基础设施组件。
- [ ] 暂不迁移：胶水层、数据/AI 编排、快速迭代的业务逻辑（Python 更合适）。

## C. 单点验证（PoC）

- [ ] 用 Rust 重写 1–2 个热点模块，做**同环境、同输入**的正确性与性能对比。
- [ ] 确定集成方式：
  - [ ] FFI 扩展（PyO3 + maturin）——计算密集/内存热点，Python 侧无感知。
  - [ ] 独立服务（gRPC/HTTP/消息队列）——需要独立部署与扩缩容的并发热点。
  - [ ] 子进程调用 Rust CLI——低频、可批处理。
- [ ] 实测收益（吞吐/延迟/内存/冷启动），确认值得投入后再扩大范围。
- [ ] 验证 Rust 版本与工具链（Rust 1.97.1、Cargo、目标平台交叉编译）可用。

## D. 逐模块迁移（渐进替换）

- [ ] 按「先低风险、后高风险」顺序替换，保持接口兼容，逐模块灰度。
- [ ] 每个模块替换后立即跑完整回归，避免一次性大范围改动。
- [ ] 写 Rust 时牢记范式差异：所有权/借用/生命周期替代 GC；`Result/Option` 替代异常；`?` 替代 `raise`。
- [ ] 注意 Python 动态类型 → Rust 静态类型：为接口定义明确的类型契约。
- [ ] 注意并发差异：Rust 无 GIL，多线程并行更自由，但需处理 `Send`/`Sync` 与 `unsafe` 边界。

## E. 测试与回归（迁移不改行为）

- [ ] 接口级回归：定义稳定契约（类型、出入参、错误码），替换前后跑同一组用例。
- [ ] 等价性测试：准备「黄金样本」，验证 Rust 输出与 Python 原实现完全一致（含边界、异常输入）。
- [ ] 性能回归基准：`criterion`（Rust）+ `pytest-benchmark`（Python），CI 固定硬件与版本防退化。
- [ ] 静态保障：启用 `cargo test`、`clippy`、`rustfmt`，纳入 CI。
- [ ] 保留回滚预案：旧实现作为 feature flag 或版本分支，问题可快速回退。

## F. 团队与工程化

- [ ] 分层培训：全组 Rust 入门（所有权/借用/生命周期、Rustlings），核心成员 tokio/PyO3/性能工程进阶。
- [ ] 初期结对与严格代码评审，沉淀团队 Rust 惯用法与规范。
- [ ] 建立内部示例库、混合架构脚手架与最佳实践文档，降低人员流动知识流失。
- [ ] 统一工具链：Cargo 管依赖与构建（可复现），约束 Python 侧工具链一致。

## G. 灰度与上线

- [ ] 按流量灰度（1% → 10% → 50% → 100%），监控错误率、延迟、内存与业务指标。
- [ ] 按模块灰度：先低风险后高风险，每步独立验证。
- [ ] 统一可观测性：Python 与 Rust 模块在同一日志/指标/追踪体系下可比对。
- [ ] 准备分钟级回退：feature flag + 版本回滚，异常即切回旧实现。

## H. 收尾固化

- [ ] 沉淀混合架构规范、构建与发布流程、测试与监控口径。
- [ ] 长期维护 Rust 模块的文档、依赖锁定（Cargo.lock）与人员能力建设。
- [ ] 定期复盘迁移收益，决定是否扩大或收敛 Rust 引入范围。
