## 3. 比较方法与统一口径

### 3.1 比较范围
- 比较对象：Python、Rust。
- 比较层次：语言机制、工程能力、应用落地、组织与迁移。
- 比较目标：回答「何时优先选 Python，何时优先选 Rust，何时采用混合架构」。

### 3.2 统一分析模板
以下模板适用于每一个技术维度章节：

```markdown
#### 维度名称
1. Python 视角
2. Rust 视角
3. 核心差异
4. 适用场景
5. 结论与取舍
6. 证据与来源
7. 风险与边界
```

### 3.3 证据口径
- 事实类型：官方文档、稳定版本特性、公开基准、企业案例、社区生态数据。
- 量化数据：必须标注测试环境、硬件条件、运行时版本、库版本、样本规模、指标单位。
- 定性结论：必须对应可追溯依据，避免无来源的绝对化表述。
- 横向比较：尽量在相同任务模型、相似实现方式、相近依赖版本下进行。
- 适用边界：必须注明结论依赖的前提，不将局部结果泛化为全局结论。

### 3.4 评分口径
- 评分方式：1 到 5 分，5 分代表更优。
- 权重方式：按团队目标分配权重，总和为 100。
- 结论方式：维度得分乘以权重后汇总，结合风险备注给出建议。

### 3.5 统一术语
| 术语 | 统一定义 |
| --- | --- |
| 开发效率 | 从需求实现到上线交付的综合效率，含编码、调试、测试与迭代成本 |
| 运行性能 | 吞吐、延迟、CPU 使用率、内存占用等运行时表现 |
| 并发模型 | 线程、协程、异步任务、消息传递等并发组织方式 |
| 内存安全 | 越界、悬垂指针、数据竞争等问题的预防能力 |
| 工具链成熟度 | 包管理、构建、格式化、静态检查、测试、调试等工具完整性 |
| 生态成熟度 | 第三方库、社区活跃度、维护稳定性、行业采用度 |
| 学习曲线 | 团队掌握语言与工程实践所需的时间与认知成本 |
| 迁移成本 | 代码重写、系统改造、测试回归、组织培训等综合代价 |
| 混合架构 | Python 与 Rust 通过 FFI、扩展模块或服务边界协同运行的架构 |
| 证据等级 | 对结论支撑强度的分层，分为官方资料、可复现实验、案例引用、专家判断 |

## 4. 核心结论摘要
- **Python** 的综合优势集中在开发效率、生态广度、人才供给与业务试错速度，适合业务层、数据层、自动化层和 AI 应用编排层。
- **Rust** 的综合优势集中在运行性能、资源效率、内存安全、并发正确性与交付确定性，适合高性能服务、系统工具、基础设施组件和安全敏感模块。
- 对多数中大型组织，最佳实践通常不是整体替换，而是采用 **Python + Rust 混合架构**：Python 负责业务编排、接口整合与实验验证，Rust 负责性能热点、协议解析、并发核心链路和高风险执行路径。
- 语言选型应同时核算学习成本、招聘供给、迁移代价、测试治理、发布复杂度与长期维护模式，而非只看运行时指标。
