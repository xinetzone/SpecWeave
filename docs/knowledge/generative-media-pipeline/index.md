# 生成式媒体生产管线：从静帧到成片的六条工程做法

> 一句话摘要：**生成式媒体生产真正的难点不是"生成"，而是"接缝"**——锚点图与视频段之间的接缝、素材与目标时长之间的接缝、规格文档与实际产物之间的接缝。本文给出六条把接缝变成工程接口的做法，每条都可复跑、可机械验收。

---

## 这份教程解决什么问题

"用 AI 做一条视频"这件事，散落在十几篇教程里的都是**生成侧**技巧：写什么提示词、选什么模型、分辨率设多少。但真正卡住产出的，通常是生成侧之外的四类问题：

| 卡点 | 表现 | 本文对应做法 |
|---|---|---|
| 锚点不匹配 | 图生视频出来的画面与剧本的视觉系统对不上，改图还是改提示词都行不通 | 做法 1 · 首帧保真 |
| 平台强制标记 | 生成平台在画面角落烧入标识，违反"画面无可读文字"的交付红线 | 做法 2 · 水印去除 |
| 编码器缺失 | 本机没有目标编码器，或依赖的库在当前 Python 版本下损坏 | 做法 3 · 编码兜底 |
| 时长缺口 | 素材总时长不够目标时长，缺口要么被掩盖要么被硬填 | 做法 6 · 组装即代码（缺口显式化） |
| 字幕渲染 | 中文字幕卡在"看起来不对"但说不清哪里不对 | 做法 4 · 字体选型 |
| 平台限流 | 生成接口排队失败、并发被限，子代理整段挂起 | 做法 5 · 限流降级 |

另有一条贯穿性条款：**规格同步**——文档与产物分叉不会自己暴露（第 7 节）。

**读法建议**：第一次做按 1→6 顺序读；已经踩过坑的直接跳到对应小节；做复盘的直接看第 8 节（证据纪律与成本）。

## 核心概念速查

| 术语 | 定义 |
|---|---|
| **锚点帧（anchor frame）** | 图生视频链路中作为首帧输入、并承载全部视觉系统约束的静态图 |
| **段落表（segment plan）** | 把成片时间轴表达为「类型 + 源 + 帧数」序列的数据结构，是组装的唯一输入 |
| **有设计的空（designed gap）** | 目标时长与素材总时长之差中，被显式赋予用途与运动参数的段落 |
| **机械对读（mechanical diff）** | 用脚本把规格文档与实际产物逐字段比对，输出差异计数；差异数 = 0 才允许标记收口 |
| **质检分层（QA tiering）** | 按对象分别声明质检强度：静态图全检 / 视频段抽帧 / 成片节拍级，不混用结论 |

## 六条做法速览

| # | 做法 | 一句话 | 触发条件 |
|---|---|---|---|
| 1 | [首帧保真](concepts/01-anchor-frame-fidelity.md) | 静帧正确即视频正确的场景下，先定稿锚点再下发视频指令 | 产出含"静态图 → 动态视频"环节 |
| 2 | [水印去除](concepts/02-watermark-and-codec.md) | 平台烧入的标识用固定区域 + 确定性 inpaint 抹掉，输出副本 | 生成平台强制烧入可见标记 |
| 3 | [编码兜底](concepts/02-watermark-and-codec.md) | 编码器逐个探测 + 外部 ffmpeg 管道回退，目标格式不妥协 | 目标编码器不可用 |
| 4 | [字体选型](concepts/03-text-rendering-and-fallback.md) | 中文字幕字体以渲染比选用图固化，不凭经验指定 | 需要中文/特殊符号渲染 |
| 5 | [限流降级](concepts/03-text-rendering-and-fallback.md) | 平台 429 排队失败时主理人直派 + 自建管线替代 | 生成接口排队/并发受限 |
| 6 | [组装即代码](concepts/04-assembly-as-code.md) | 时间轴写成段落表，assert 自校验，规格与产物机械对读 | 成片由多段落拼装 |

## 一句话收束

**生成侧的能力决定成片的天花板，接缝处的工程决定成片的地板。** 大多数"AI 视频做不好"的体感，来自地板没铺平——不是模型不够好。
