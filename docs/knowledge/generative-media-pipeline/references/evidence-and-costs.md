# 参考：证据与成本基线

## 1. 本知识包的来源与验证等级

| 项 | 说明 |
|---|---|
| **来源** | 一次真实的多模态媒体生产批次的复盘产物，经七概念方法论（R→I→E→V→A→C，standard 深度）萃取 |
| **原始事实量** | 50 条客观事实 + 6 项证据缺口 |
| **原始洞察** | 3 条四元组洞察 |
| **萃取模式** | 2 个可迁移模式（锚点前置 / 缺口显式化），经 4 视角对抗审查（12 条意见，全部处理） |
| **验证等级** | **candidate（单案例已验证，未跨案例验证）** |
| **去私域化处理** | 剥离全部项目名、作品名、角色名、剧本内容、平台水印原文、具体坐标数值；保留方法结构、参数区间、判定标准与流程要素 |
| **可复用部分** | 六条做法、26 条检验标准、14 条反模式、证据纪律条款、成本基线的**结构** |
| **不可复用部分** | 具体矩形坐标、具体字体名、具体文件路径、具体帧率与时长数值（这些属于单批次参数，读者须按自己的素材重新测定） |

**关于 validation_status = candidate 的含义**：本文的每条做法都在一次真实批次里跑通了，但**只跑通过一次**。用它指导第二个项目时，检验标准的阈值需要重新标定，尤其是第 4 节里那些带具体数值的项。

## 2. 去标识化的量化观测

以下数值用于让读者判断"这类批次的量级"，不含任何项目标识：

| 观测项 | 数值 |
|---|---|
| 文字卡片 | 12 张，PNG 1920×1080 |
| 情绪板 | 3 张，同分辨率 |
| 锚点关键帧 | 4 张，同分辨率 |
| 视频段 | 8 段（6 段 × 5.04s + 2 段 × 10.04s），均 1920×1080 / 24fps |
| 素材总时长 | 50.32s |
| 成片 | 90.00s / 2160 帧 / 1920×1080 / 24fps / H.264 / 约 42.3 MB / 无音轨 |
| **时长缺口** | **39.68s**（占成片 44.1%） |
| 有信息空段（黑场 + 台词） | 5 段 / 504 帧 / 占 23.3% |
| 无信息空段（静帧延展拍） | 3 段 / 360 帧 / 占 16.7% |
| 批次时间跨度 | 约 129 分钟 |
| 去水印后体积变化 | 降至原版约 50.5% |

**这些数值的意义不在于"标准值"**，而在于**比例关系的量级**：缺口占 44%、有信息空段占 23%——这个量级下，缺口处理方式的选择直接决定成片观感。它说明"先算缺口"不是一句形式主义的提醒。

## 3. 成本基线

### 3.1 返工事件类型

一次完整批次里发生的返工与绕路（已剥离项目内容）：

| 类型 | 事件 | 代价性质 |
|---|---|---|
| 视觉系统冲突 | 4 张锚点图与目标视觉系统冲突 → 全部重制 | 4 次生成调用 + 1 轮人工复核 |
| 平台强制标记 | 8 段视频全部带平台标识 → 全部 inpaint 重编码 | 8 段重编码；双份存储 |
| 帧数配平错误 | 卡片段落帧数写错 → 累加总长不符 | 被 assert 拦截，1 轮返工 |
| 编码器缺失 | 目标编码器不可用 → 改走外部 ffmpeg 管道 | 1 次管线改造 |
| 依赖库损坏 | 图像库在当前 Python 版本下无法导入 → 强制重装 | 1 次重装 |
| 解释器错配 | 目标模块不在默认解释器里 → 换解释器 | 1 次切换 |
| 平台限流 | 两个生成子代理因排队限制终止 → 主理人直派 + 自建管线替代 | 一半素材改由主理人产出 |
| 指令未执行 | 子代理完成原任务后未处理插播指令 → 重发完整规格 | 1 次重发 |

### 3.2 成本对账原则

> **未做成本登记的模式采纳是无本之木。**

记录一次模式采纳时，除了收益，必须同时记录：
- 返工事件数与类型；
- 额外生成调用数与算力时长；
- 人工复核工时；
- 存储增量。

下一次评估时，先取上一次的代价基线，再判断收益是否超过代价。**没有基线的"值得采用"只是印象。**

## 4. 证据纪律：五条条款

这五条来自本批次最重要的一次自我修正，也是本知识包最容易被忽略但最有价值的部分。

### 条款 1 · 区分"我检查过"与"它被验证过"

质检由执行者自己做时，结论的正确性不因"我亲自看了"而提升。**自述不是验证。**

- 表述规范：写"已按 4 项清单逐张检查（执行者自述）"，不写"经独立验证通过"。
- 归档一份自述**不能**把它升级为独立验证。

### 条款 2 · 时间先后以文件 mtime 为代理指标，且须声明口径

mtime 可被复制、移动、重写改变，**不等于指令下发时刻**。缺平台侧生成记录时，时间先后结论只能作弱判定，且必须在文中声明这个口径。

### 条款 3 · 缺记录 ≠ 未发生

"日志里没有回改记录"不能推出"没有回改"。这类判定应标为**不可判定**，不计入通过项。

### 条款 4 · 存在性判定不等于有效性判定

- 存在性：「表里有这一行」「代码里有这个 assert」——容易形式化满足。
- 有效性：「差异数 = 0」「缺字数为 0」——真正要的东西。

检验标准应尽量给有效性判据；给不出有效性的，至少要在旁边标注它只是存在性。

### 条款 5 · 质检结论必须标注强度与覆盖率

抽帧通过 ≠ 全量通过。每一份质检报告都应写明：本轮做了哪一层、覆盖率多少、哪些位置没有被覆盖。

**这五条款的共性**：都在阻止一个具体的偷懒——把"我做了某个动作"当成"某个结论成立"。

## 5. 检验标准速查（26 条）

### 首帧保真（6 条）

| 编号 | 标准 | 类型 |
|---|---|---|
| C1 | 锚点通过质检的时刻早于依赖段下发时刻 | 有效性（mtime 口径，弱） |
| C2 | 每张锚点图有可逐条核对的定点检查项 | 存在性（执行情况为自述） |
| C3 | 锚点图分辨率与成片一致 | 有效性 |
| C4 | 依赖段未因画面问题回改 | **通常不可判定** |
| C5 | 锚点在时间轴上有独立段落类型与时长 | 有效性 |
| C6 | 质检强度按对象分层声明 | 存在性 |

### 水印与编码（7 条）

| 编号 | 标准 | 类型 |
|---|---|---|
| W1 | 处理后标识区域无可读文字残留 | 有效性 |
| W2 | 修补区域无可见涂抹痕迹 | 有效性 |
| W3 | 原片保留且可回放 | 有效性 |
| W4 | 输出帧数与输入一致 | 有效性 |
| W5 | 矩形定义与分辨率解耦 | 有效性 |
| E1 | 输出流 codec 等于目标格式 | 有效性 |
| E2 | 实际使用的编码器已记入日志 | 存在性 |
| E3–E7 | `isOpened()` 被检查 / 退出码被检查 / stdin 关闭 / 依赖清单归档 | 存在性 |

### 文字与降级（8 条）

| 编号 | 标准 | 类型 |
|---|---|---|
| T1 | 字体选型有渲染比选用图留证 | 存在性 |
| T2 | 全部字符集做了字形覆盖检查 | 有效性（缺字数 = 0） |
| T3 | 字号按画面高度比例定义 | 有效性 |
| T4 | 字幕定位扣除了 bbox 偏移 | 存在性 |
| T5 | 429 预案卡存在且含触发条件 | 存在性 |
| T6 | 降级切换事件已记入日志 | 存在性 |
| T7 | 直派产物被单独标记 | 存在性 |
| T8 | 每条质检结论标注强度与覆盖率 | 存在性 |

### 组装即代码（8 条）

| 编号 | 标准 | 类型 |
|---|---|---|
| C1 | 缺口在文档中显式出现且可复算 | 有效性 |
| C2 | 每类空段有最小规格参数 | 存在性 |
| C3 | 空段在时间轴上为独立类型 | 有效性 |
| C4 | 段落表长度自校验存在 | 存在性 |
| C5 | 规格与产物做过机械对读，差异入报告 | 有效性 |
| C6 | 交付核对表含"知识同步性"行 | 存在性 |
| C7 | 无信息空段占比可统计且有上限 | 有效性 |
| C8 | 规格与产物的差异数 = 0 | 有效性 |

**统计**：26 条中，有效性判定 14 条、存在性判定 12 条；本批次未满足 3 条（全部集中在"规格与产物同步"这一族），另有 1 条判定为不可判定。

## 6. 未满足项的影响评估范式

复盘报告里写"未满足项"时，必须同时回答：**它影响什么、不影响什么**。

以"未做规格—产物机械对读"为例：

| 分类 | 内容 |
|---|---|
| 影响 | 可维护性与下次复用成本——下一个读规格的人会被过期信息误导 |
| 不影响 | 已交付产物的规格正确性——成片本身的参数是经探测验证的 |

不写这一栏，读者会以为批次有实质缺陷；写清楚，读者能判断这个缺陷的性质。

## 7. 复用本知识包时的检查清单

把它用到自己的项目前，先确认这四件事：

1. **你的任务满足"静帧正确即视频正确"吗？** 不满足则做法 1 退化为参考，不设前置门。
2. **你的视觉系统能翻译成定点检查项吗？** 不能则做法 1 的质检清单会流于形式。
3. **你愿意先做单一手写源吗？** 不愿意则做法 6 的后半段（机械对读）会一直缺位，分叉会持续累积。
4. **你记录了上次采纳的代价吗？** 没记录则你无法判断这六条做法是否真的划算。
