# 01 首帧保真

## 1. 核心命题

在「静态图 → 动态视频」的链路里，**视频模型的生成能力不构成瓶颈，锚点图的合规性构成上限**。

理由很直接：图生视频是以首帧为锚做展开的。首帧里存在的缺陷（色调错、光源方向矛盾、人物外形漂移、画面里有一行字），会被模型的随机性放大成整段视频的缺陷；而首帧正确时，视频段的返工需求接近于零。

推论：**顺序比工具重要**。直觉顺序是"先把视频跑出来，再补关键帧"——视频调用慢、可并行、看起来像主工序。正确顺序是先锁死锚点。

```
✗ 先发视频指令 → 后补关键帧      返工发生在已付出生成成本之后
✓ 先定稿锚点图 → 冻结 → 再下发     返工发生在生成成本之前
```

## 2. 把视觉系统翻译成可判定的锚点规格

"画面要冷、要压抑、有年代感"这类描述无法验收。锚点规格必须落到**可逐张核对的定点项**。

做法：把视觉系统拆成四个维度，每个维度给出 1–2 个具体的画面元素作为检查锚点。

| 维度 | 规格化的问法 | 示例锚点项 |
|---|---|---|
| 光源 | 光从哪来？硬还是软？色温多少？ | 单一硬光源从画面右侧入射；走廊顶灯为冷白频闪 |
| 色调 | 高调还是低调？对比度？ | 暖橙 2700K 主调，阴影侧带荧光冷青补光 |
| 投影 | 有什么可见的物理投影特征？ | 栅栏状条形投影横切墙面 |
| 洁净度 | 画面里有没有不该有的东西？ | 无可读文字、无平台标识、无人脸畸形 |

要点是**每张锚点图都要过同一张清单**。清单是固定的，检查项是逐张的。

### 2.1 质检必须由执行者独立做

不采信生成侧的自我描述（"已完成，符合规范"）。做法是打开图，逐条对照清单。

这条不是可选做法——它是本模式成立的必要条件。生成侧与验收侧分离，是唯一能发现"看起来对但其实不对"的方式。

## 3. 冻结规则

锚点图通过质检后：

1. **分辨率与成片一致**。尺寸差会在后期引入缩放与插值，把构图控制权交回给不可控环节。1920×1080 是常用目标。
2. **登记为只读**，文件名带用途与时段语义（如 `-night` / `candlelight` / `boiler-fire`），便于反查"这张是哪一段的锚点"。
3. **下游指令只引用文件名，不重述画面内容**。一旦在指令里重述"画面应该是冷青色、有栅栏投影"，下游模型就会对同一画面做二次解释，产生与锚点不同的版本——锚点定稿的意义被稀释。
4. **一次定稿，双处使用**：锚点图既作图生视频的输入，又作静帧延展拍的画面来源（见 [04 组装即代码](04-assembly-as-code.md)），摊薄定稿成本。

## 4. 质检分层：不要把不同强度的结论混用

这是本节最容易被忽略、也最容易出事的地方。质检强度按对象分层，各层结论**不得互相冒充**。

| 层 | 对象 | 强度 | 覆盖 |
|---|---|---|---|
| **L1** | 锚点静态图 | **全检**——逐张查看，每张过完整清单 | 全部锚点图 |
| **L2** | 视频段 | **抽帧**——取 20% / 50% / 80% 三个位置 | 全部视频段 |
| **L3** | 成片 | **节拍级**——按结构节点抽帧做接触印相 | 每个节拍一处 |

**反模式**：把 L2/L3 的抽帧结论表述为"成片已全面检查"。抽帧通过与全量通过之间有真实差距——字幕淡入的起始帧、段落交界处的接缝、延展拍与视频段的过渡帧，恰恰都是抽帧最容易漏掉的位置。

**最低限度的补强**：成片质检除了节拍点，还要覆盖**每一个淡入/淡出区间**至少一帧。本教程的实践里，这是 L3 最薄的一环。

## 5. 可执行卡点

"锚点先定稿"如果只写成一句原则，在进度压力下会被跳过。要把它变成一个**有状态的卡点**：

```
锚点图未在质检清单上逐项签字  →  视频指令不发出
```

签字的形式可以是清单文件里的一项勾选，也可以是日志里的一条带时间戳的记录。关键是**可核查**：事后能回答"这张锚点图是什么时候、按哪几条、谁签的"。

把卡点登记在流程的门位上（如批次日志的 GATE_CHECK 事件），并让越权下发成为一个可被检出的事件。

## 6. 适用边界（重要）

「锚点质量决定视频上限」是**有条件成立**的。

**锚点承载什么**：视觉系统（色调、光源、构图、对比度）与合规（无文字、无标识、人物外形一致）。
**锚点不承载什么**：运动、节奏、表演、时长、运镜设计。

因此：

- ✅ **适用**："静帧正确即视频正确"的任务——风格化短片、情绪片、产品概念片、氛围镜头。判据是：这一段视频在视觉上除了动起来，别的什么都不该变。
- ❌ **不适用**：需要表演动作、速度感、形变、粒子物理的任务——舞蹈、动作片、爆炸、液体。判据是：这一段视频在视觉上除了动起来，还必须有静帧无法表达的东西。

在不适用的场景里，锚点退化为**参考之一**，不应作为前置门去卡视频指令。

## 7. 三类反模式

| # | 反模式 | 为什么错 |
|---|---|---|
| R-1 | 先发视频指令、后补锚点图 | 视频段继承有缺陷的首帧，模型随机性把缺陷放大，返工发生在已付出成本之后 |
| R-2 | 采信生成侧的自我描述作为质检结论 | 生成侧与验收侧不分离，"看起来对"永远发现不了 |
| R-3 | 用情绪板或参考剧照直接充当锚点 | 情绪板往往属于视觉系统的**另一侧**（如"明亮记忆"对"黑暗当下"），混用破坏全片一致性 |
| R-4 | 在视频指令里复述锚点画面内容 | 下游模型对同一画面二次解释，产生与锚点不同的版本 |
| R-5 | 把锚点当万能参考，要求视频复现静帧姿态 | 锚点不承载运动信息；把静帧的具体性当约束会让视频僵硬，或反之忽略视觉系统约束 |
| R-6 | 把抽帧质检当成片全量审看 | 不同强度的结论混用为同一句"已质检" |

## 8. 检验标准

| 编号 | 标准 | 判定类型 | 说明 |
|---|---|---|---|
| C1 | 锚点图通过质检的时刻早于任何依赖它的视频段下发时刻 | 有效性 | ⚠️ 只能用文件 mtime 做代理指标。mtime 可被复制、移动、重写改变，**不等于指令下发时刻**；缺平台侧记录时该判定作弱结论 |
| C2 | 每张锚点图有可逐条核对的定点检查项 | 存在性 | ⚠️ 清单存在不等于清单被执行——复核若由执行者自述完成，只能算过程记录，不算独立验证 |
| C3 | 锚点图分辨率与成片一致 | 有效性 | 像素相等 |
| C4 | 依赖视频段在锚点定稿后未因画面问题回改 | **通常不可判定** | 除非有生成记录或明确的回改登记，否则"没记录"≠"没发生"，不计入通过项 |
| C5 | 锚点图在时间轴上拥有独立段落类型与时长 | 有效性 | 见 [04 组装即代码](04-assembly-as-code.md) |
| C6 | 质检强度按对象分层声明，不混用 | 存在性 | 分层表随交付物归档 |
