# 03 文字渲染与限流降级

## 1. 字幕字体：把"看起来不对"变成可判定的选型

中文字幕渲染最耗时间的环节，不是不会渲染，而是**看不出为什么不对**。

"看起来不对"通常来自四个可分解的原因：

| 症状 | 真实原因 | 可判定的检查 |
|---|---|---|
| 某个字缺了 / 变成了方框 | 字体缺该字形 | 逐字符字形覆盖检查 |
| 整体太"粗"、太"重" | 字体是黑体类无衬线 | 找衬线/细线字体 |
| 标点挤在字里或空一大块 | 标点宽度处理不当 | 检查全角引号、破折号、省略号 |
| 字幕显得压迫画面 | 字号 / 位置不对 | 字号 = 画面高度的一个固定比例 |

**核心建议：不要凭经验指定字体，用一张渲染比选用图把它固化下来。**

### 1.1 渲染比选用图的做法

在一张图上把候选字体按同字号排成若干行，每行放同一段**测试串**，测试串必须包含：

- 常用汉字（尤其是笔画密的字）
- 希腊字母（如果片中有公式/符号）
- 全角引号 `「」`、单引号 `‘’`
- 破折号 `——`、省略号 `……`
- 数字与半角标点

出图后横向对比，一眼能看出：哪行字形完整、哪行最纤细、哪行标点最规矩。

```python
from PIL import Image, ImageDraw, ImageFont

def render_specimen(path, fonts, sample, size=44):
    line_h = size + 18
    img = Image.new("RGB", (1920, line_h * len(fonts) + 40), "black")
    d = ImageDraw.Draw(img)
    for i, (name, fpath) in enumerate(fonts):
        f = ImageFont.truetype(fpath, size)
        d.text((20, 20 + i * line_h), f"{name}  {sample}", font=f, fill="white")
    img.save(path)
```

### 1.2 选型倾向（经验起点，仍须以比选用图确认）

| 倾向 | 说明 |
|---|---|
| 纤细衬线 | 衬线体在暗底上笔画边缘更锐利，比黑体更"轻"，不抢画面 |
| 中文标点全角处理正常 | `「」` `——` `……` 的间距要看起来对 |
| 特殊符号字形齐全 | 希腊字母、上下标、箭头等要在同一字体里有形 |

### 1.3 字幕排版参数

- **字号**：按画面高度的**固定比例**取（本教程实践取 4%），不按绝对像素——这样换分辨率时比例自动保持。
- **位置**：锚点用「基线锚点」而非「顶部锚点」，因为不同字体的 ascender/descender 高度不同，只按顶部定位会导致不同字幕行视觉基线不齐。做法：先用 `textbbox` 量出真实 bbox，再按基线反推绘制 y。
- **留白**：字幕不要贴画面底边。留出下三分之一的安全区。

```python
probe = ImageDraw.Draw(Image.new("L", (10, 10)))
bbox = probe.textbbox((0, 0), text, font=font)
tw, th = bbox[2] - bbox[0], bbox[3] - bbox[1]
x = (W - tw) // 2 - bbox[0]      # 减 bbox[0]：抵消字体的左边距
y = SUB_BOTTOM - th - bbox[1]    # 减 bbox[1]：抵消顶部偏移，按基线反推
```

`bbox[0]` / `bbox[1]` 这两个偏移**必须减掉**，否则每行字幕的视觉位置都会有肉眼可见的抖动。

### 1.4 字形覆盖的机械化检查

不要靠肉眼确认"字都在"。用字体对象直接查：

```python
from fontTools.ttLib import TTFont

def missing_glyphs(font_path, chars):
    f = TTFont(font_path)
    cmap = set()
    for t in f["cmap"].tables:
        cmap |= set(t.cmap.keys())
    return [c for c in chars if ord(c) not in cmap]
```

把成片实际用到的全部字符集跑一遍，缺字直接暴露。这条检查应进流水线，成为**阻断式**门（见第 3 节）。

## 2. 限流降级：平台 429 的处置

### 2.1 症状

- 生成接口排队，任务停在 waiting 状态，长时间无进展；
- 并行分派的子代理中，个别任务整段挂起（有的能跑完前 4 段再阻塞）；
- 任务在"已完成原任务后没有继续处理插播指令"处静默停止；
- 平台侧返回 429（Too Many Requests）或队列超时。

**关键判断**：这类失败**不是**能力问题，是并发与配额问题。重试同一路径通常无效。

### 2.2 降级路径一：主理人直派

子代理挂起时，由主理人直接调用生成工具补齐剩余素材。

**要点**：
1. **规格必须完整重述**。子代理中断后，主理人手里的上下文可能不完整——把该段的完整视听规格重新写一遍，不要用"接着刚才那个"这类指代。
2. **逐项回报**。直派后让每个产物单独报告（尺寸、时长、有无可读文字），而不是打包一句"已完成"。
3. **记录切换点**。哪几段来自子代理、哪几段来自主理人直派，要写进批次日志——这直接影响后续的质检强度判断（直派产物没有经过子代理的自检）。

### 2.3 降级路径二：自建管线替代

当某个执行环节（尤其是"剪辑/组装"）的子代理不可用时，主理人可以直接写脚本完成该环节。

本教程的实践里，视频-editor 环节就是这样降级的：由主理人自建 OpenCV + ffmpeg 管线完成时间轴组装、去水印与抽帧质检（详见 [02](02-watermark-and-codec.md) 与 [04](04-assembly-as-code.md)）。

**为什么这条路可行**：剪辑/组装的本质是**确定性的时间轴操作**——把若干已知参数的视频段、卡片、字幕按时间码拼起来。这正是脚本的强项，而不是模型的强项。让模型做这件事，是把确定性问题交给不确定的执行者。

**判断原则**：
> 环节越接近"确定性变换"，越应该由脚本承担；越接近"创作判断"，越应该由模型承担。

组装、去水印、编码、抽帧质检——全部是前者。

### 2.4 预案卡要素

限流是会复发的。把降级路径写成一张**预案卡**放在工作目录，触发时直接照做：

| 要素 | 内容 |
|---|---|
| 触发条件 | 明确到可判定的信号（例：任务在 waiting 状态超过 N 分钟无进展） |
| 切换决策 | 什么情况下继续等、什么情况下切主理人直派 |
| 直派指令模板 | 完整规格的字段清单（避免"接着刚才"式指代） |
| 替代管线启用步骤 | 脚本路径、依赖、验证命令 |
| 产物标记规则 | 直派产物需单独标记，质检强度相应调整 |
| 日志登记位点 | 切换事件写进哪个事件类型 |

## 3. 质量门：阻断式 vs 记录式

流水线上有三种检查，混用会出事：

| 类型 | 失败时 | 用在哪 |
|---|---|---|
| **阻断式（blocking）** | 停下，不允许下游继续 | 字形缺失、段落数与目标帧数不符、编码器全部不可用 |
| **返工式（rework）** | 退回上一环节重做 | 锚点图不满足视觉系统、抽帧发现水印残留 |
| **记录式（record-only）** | 记进报告，继续往下 | 抽帧未见异常但覆盖率不足、成片未做全量逐帧审看 |

**反模式**：把记录式的检查当成阻断式的用——比如"抽帧没看出问题"就当"成片没问题"签收。正确做法是在报告里**明确写出本轮质检的强度与覆盖率**，让读报告的人知道结论的边界在哪。

## 4. 检验标准

| 编号 | 标准 | 判定 |
|---|---|---|
| T1 | 字体选型有渲染比选用图留证 | 存在该图 |
| T2 | 成片用到的全部字符集做了字形覆盖检查 | 检查输出无缺字 |
| T3 | 字幕字号按画面高度比例定义 | 源码中为比例或注明比例 |
| T4 | 字幕定位扣除了 bbox 偏移 | 代码中含 `bbox[0]` / `bbox[1]` 修正 |
| T5 | 429 预案卡存在且含触发条件 | 文件存在且字段齐全 |
| T6 | 降级切换事件已记入批次日志 | 日志中存在该事件 |
| T7 | 直派产物被单独标记 | 有标记字段或独立目录 |
| T8 | 每条质检结论标注了强度与覆盖率 | 报告中显式声明 |
