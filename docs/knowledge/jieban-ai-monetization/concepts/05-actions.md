# 05 · 原子行动项：本周做什么，90 天核对什么

> 回到 [知识包首页](../index.md)
>
> 行动项按执行主体分三类：**成员侧**（你自己做）、**管理员侧**（群运营动作，AI 无法代劳）、**资产侧**（文档/仓库动作）。每项单一职责、可独立验证（G4）。

## 本周 Hello World（5 分钟理解，当晚可完成）

如果你是「愈多」成员，且 P1（技能空白）成立——不要收藏本知识包，直接做：

1. 今晚选一件**今天本来就要做的小事**（写封邮件、整理一段文字、做个家庭开支表、给备婚清单排期都行）；
2. 用任意 AI 工具完成它，记下工具名、三步操作、花了多少分钟、卡在哪；
3. 在「愈多」群按[案例模板](04-case-reflow-covenant.md#第三条案例模板回流声誉域的唯一合法格式)发一条记录，**全篇是失败也合格**；
4. 不发朋友圈、不研究变现、不比较工具。完成 P1 即解锁后续路径。

## A3 的子项目纪律（重要）

daoapps.github.io 是 git 子模块，**不在本仓直接修改**。正确路径：

1. 在 `projects/daoapps.github.io/` 内开分支，按其 [AGENTS.md](../../../../projects/daoapps.github.io/AGENTS.md) 路由修改 `doc/jieban/` 内容；
2. 先跑契约测试 `python -m pytest tests -q`，再跑 `python -m sphinx -b html -W doc _build/html`；
3. 提 PR，子项目仓库内评审合并，由 GitHub Actions 发布；
4. 一期页面仍不设任何表单（源码 `<form>` 有测试断言），案例提交通道维持「微信端交管理员」。

## 90 天核对表（A8）

| 指标 | 数据来源 | 达标线 | 不达标时的回查动作 |
|---|---|---|---|
| 案例登记数与失败字段非空率 | 案例集编号记录 | ≥10 份且非空率 100% | 回查步骤 3：入口动作是否真的 ≤5 分钟、模板是否太重 |
| 群内导流违规事件数 | 处置记录 | 0 起（或全部 24h 内闭环） | 回查步骤 2：四类特征是否覆盖新话术，补特征枚举 |
| 交换域可核验到账 | 成员个人 monetize tracker/records（local，不公开金额） | ≥1 名成员有到账记录 | 不作失败判定——收入是副产品；只复核路径是否被正确告知 |
| 新成员来源可溯率 | A4 本地记录 | ≥50% 能说出来源 | 回查声誉域案例的可发现性（A3 是否完成、案例是否可读） |

## 明确不做清单（防实体化反模式）

- ❌ 不在群内收会员费、不开付费训练营、不做「结伴甄选好课」；
- ❌ 不做小程序/商城/分销系统，不建收益排行榜；
- ❌ 不给成员定收入目标、不晒收入截图、不承诺任何收益区间；
- ❌ 不在一期网站加表单或收集任何个人信息；
- ❌ 不把本知识包的模式立刻收入方法论模式库——先在包内 L1 试运行，90 天达标后再议独立化。

## 执行顺序建议

```text
第 1 周：管理员发布 A2/A5/A6（一次群公告即可覆盖）；成员做 Hello World
第 2-4 周：成员产出 A1 首批案例；管理员启动 A4 来源记录
第 2 月：提交 A3 子项目 PR；组织首次 A7 跨频道联动
第 3 月末：A8 核对 → 决定公约升 v1.0、模式升 L2 或回炉
```
