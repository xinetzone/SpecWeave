# 01 · 第一性原理：假设剥离、公理与三域重构

> 回到 [知识包首页](../index.md) ｜ 下一概念页：[02 三元组诊断](02-real-problem-need-goal.md)

## 1. 问题界定

- **原始命题**：如何利用结伴（四频道社群+网站）实现 AI 变现，让更多人活好每一天。
- **约束**：公约第四条（群内零收费导流，F-018）、邀请制零表单（F-022）、「不当流量池」（F-017）、不做收益承诺（F-015）。
- **症状与根因的区分**：「赚不到钱」是成员个人层面的症状；本包要解的根因层问题是「信任关系与商业交换在同一空间内不兼容，而二者都是成员需要的」。

## 2. 假设剥离：5 条隐含假设的裁决

| # | 隐含假设 | 裁决 | 依据 |
|---|---|---|---|
| H1 | AI 变现 = 在群里卖 AI 课/项目 | ❌ 否决 | 与第四条互斥，成立即触发永踢（F-015/F-018） |
| H2 | 变现主体是社群运营者，用流量做变现 | ❌ 否决 | 「把这里当家，不当流量池」（F-017）；零表单无漏斗（F-022） |
| H3 | 「让更多人活好」= 规模化获客增长 | ❌ 否决 | 邀请制是刻意的限速器；对的人密度优先于人数（F-007/F-021） |
| H4 | 「活好每一天」是可交付、可验收的结果 | ❌ 否决 | 站点自述「不追结果，先把日子过好」（见 F-026）；它是现在时态状态，时态检验拦截（见 [02](02-real-problem-need-goal.md)） |
| H5 | 微信群和网站是产品本身 | 🔄 重构 | 二者是关系基础设施——「客厅」（F-004/F-005），产品是域之间的连接协议 |

## 3. 公理（拆解到不可再分的要素）

| # | 公理 | 性质 |
|---|---|---|
| A1 | 普通人有四组关系需求：与自己、与伴侣、与家庭、与时代；四频道是这一判断的经验证据（F-008/F-027） | 事实归纳 |
| A2 | AI 降低了「个人技能 → 作品/内容/服务」的转换成本，这是「业」频道成立的技术前提 | 事实归纳（F-013/F-014） |
| A3 | 熟人信任不可购买、不可加速，只在真实生活互动中累积；恒与的慢介绍机制是其制度表达（F-011） | 结构推导 |
| A4 | 经验分享的边际成本趋零，且分享动作本身使分享者的理解增值——「分享出去的经验，比藏起来的更值钱」（愈多页原话，F-013 组） | 事实归纳 |
| A5 | 市场变现需要「可被陌生人评估的价值凭证」：作品、公开案例、账号资产；群内好评不是市场凭证 | 结构推导 |
| A6 | 商业交换一旦回流进信任关系内部，信任对全体成员同时贬值且不可逆——第四条是对此的防御（F-018/F-020） | 结构推导 |

> 注：A1/A2/A4 锚定文档事实；A3/A5/A6 为本 session 的结构推导，未经独立实证，按「机制假设」使用，90 天用可观测代理项检验（见 [05](05-actions.md)）。

## 4. 自下而上重构：三域飞轮

从公理推导：

1. A1+A2 → 成员的成长发生在信任互动与真实任务中（信任域内）。
2. A5 → 变现必须发生在陌生人可评估价值的市场（交换域），凭证在群外生成。
3. A6 → 货币流动必须与信任关系物理隔离，且隔离规则要可机械执行（不能靠判读人心）。
4. A4 → 经验回流声誉域对作者和读者都增值，但回流物必须过滤掉一切可转化为营销信号的字段（收益金额、购买入口、承诺性措辞）。
5. A3 → 新成员的进入靠案例呈现的「同类人」气质吸引，而非投放；邀请制保持信任累积速度可控。

```{mermaid}
flowchart LR
    D1["信任域 微信群<br/>流通: 经验 反馈 陪伴<br/>货币零流经"] -->|"能力增长"| D2["交换域 群外市场<br/>平台接单 雇主 客户<br/>主体: 成员个人"]
    D2 -->|"脱敏案例 含失败"| D3["声誉域 结伴网站<br/>只沉淀证据 不接广告"]
    D3 -->|"案例吸引同频者"| D1
```

飞轮转动的介质是**证据与能力**，不是钱与流量。货币只出现在交换域内部。

## 5. 与「三之位」的同构关系

本方案不在群与市场之间增加第三个产品（商城/训练营/小程序都是「把第三项当实体」的反模式），而是找到使二者构成整体的**关系位**：连接协议（谁给谁、给什么、什么格式）。这与 L2 模式「三之位」（不增实体、只设计连接）同构——参见模式库 [three-as-relation-position](../../../retrospective/patterns/methodology-patterns/governance-strategy/three-as-relation-position.md) 与 OKF 知识包 [dao-san-triads](../../../../projects/awesome-okf-xs/doc/bundles/guoxue/laozi/dao-san-triads/index.md)。

> 纪律声明：此处为**结构类比**，不声称结伴站点的设计者依据《老子》或该模式建站；缘起文档未提及此类设计框架（F-025 亦明确不伪造典出）。
