# 结伴 × AI 变现行动知识包

> 一句话摘要：**群内零交易、站外去赚钱、回站只讲案例。** 结伴（微信群）是信任域，货币永远不在这里流经；成员个人在群外市场完成变现；只有脱敏的、含失败字段的、不带收益数字的案例允许回流沉淀。飞轮转动的燃料不是成功经验，而是真实记录——成功案例引流量，失败案例建信任。

## 2. I 阶段：核心洞察（四元组）

> G2 已通过：4 条洞察各含 **陈述 / 证据（编号）/ 反常识 / 行动**，四个维度（风险结构、时态机制、冷启动燃料、资产盘点）互不重叠。三元组诊断全文见 [02 三元组诊断](concepts/02-real-problem-need-goal.md)。

### I-1　最大风险是「在群内赚到钱」：第四条是信任资产保全条款

- **陈述**：群内一旦出现货币交换，熟人信任即被重估为「营销场景」，且该贬值对所有成员同时发生、不可逆。公约第四条（F-018/F-019）与「永踢并公示」处置（F-020）防御的不是道德瑕疵，而是社群唯一资产（信任）的挤兑。
- **证据**：F-015、F-017、F-018、F-019、F-020。
- **反常识**：直觉把第四条读作「价值观洁癖」；结构分析显示它是性价比最高的资产保全机制——一次成功的群内成交对卖家收益有限，却向全体成员释放「这里可以卖东西」的信号，治理成本随后指数上升。
- **行动**：变现动作全部移出信任域；用机械识别清单（外链/二维码/私聊引流/收益承诺）替代管理员对「意图」的主观判读，见 [04 案例回流公约](concepts/04-case-reflow-covenant.md)。

### I-2　「活好每一天」是变现的前置机制，且是现在时态

- **陈述**：F-026 与 F-028 记录的是同一结构——把注意力从结果（那件具体的事）移到当下状态（把日子过好），预期外的结果在过程中出现。「活好每一天」不是可在未来交付的 KPI，而是一组每天可执行的现在时态动作；它同时是信任域的入场筛选（同频者识别）与个人产出质量的来源。
- **证据**：F-026、F-028、F-010、F-027。
- **反常识**：直觉认为「先变现、再过好生活」或把「让更多人活好」当成增长目标去运营；时态检验指出，把现在时态的状态当未来结果追求，动作会立即变形（感恩记录变成打卡表演、AI 学习变成副业焦虑），恰好复现「越盯越难」。
- **行动**：所有频道的入口动作设计为「今天一件小事」级（≤5 分钟、允许失败）；运营指标不设人数与收入目标，改用案例登记密度与违规事件数。

### I-3　飞轮冷启动燃料是真实记录与失败报告，不是成功经验

- **陈述**：新成员没有成功经验可分享（短路规则：技能清单全无验证项时，先做出一件东西），但拥有无限供给的真实使用记录与失败报告。F-013 的「真案例」与 F-016 的颗粒度要求对失败同样适用；成功案例的功能是吸引同频者，失败案例的功能是建立与验证信任。
- **证据**：F-013、F-016、F-017（不评判条款）、F-010（「过得不太顺的时候来，可能更有用」）。
- **反常识**：直觉认为社群案例库应展示「做成了」；在反营销语境下，只展示成功的案例库在结构上与割韭菜 landing page 无法区分，反而触发防御。失败字段必填使案例不可被营销化（Goodhart 防御：当案例成为拉新工具，成员会优化案例外观）。
- **行动**：案例模板设失败/卡点为必填字段、禁止收益金额字段；新成员首动作=「今天用 AI 解决一件真实小事，发工具+步骤+卡点」。

### I-4　不需要新产品，缺的是三个已存在域之间的连接协议

- **陈述**：交换域（市场）的执行基础设施已存在于 monetize 容器（F-029~F-036：六件套、五公理、知乎 18 行动项、到账唯一事实源）；声誉域（网站）已存在（F-001/F-005）；信任域（四微信群）已存在。缺口是域间协议：什么可以从信任域流向声誉域、以什么格式、谁来判定。这是「三之位」——不增加实体，只设计连接。
- **证据**：F-029、F-031、F-032、F-004、F-005。
- **反常识**：直觉的变现方案是「做课/做训练营/做小程序商城」；这类方案与 F-014/F-015 正面冲突，且重复建设已有资产。最小方案是一份连接协议文档。
- **行动**：执行 [04 案例回流公约](concepts/04-case-reflow-covenant.md)；个人变现执行外置到 monetize 工作台；网站侧仅做案例结构承接（走 daoapps 子项目 PR 流程，不增表单）。

## 3. E 阶段：可迁移模式摘要

### 模式：三域飞轮（Three-Domain Flywheel，L1）

**一句话**：高信任社群面对成员商业化诉求时，把系统拆为信任域（群，零货币流经）、交换域（群外市场，个人变现）、声誉域（站点，只沉淀含失败字段、无收益数字的脱敏案例），只设计域间连接协议，不新建商业实体。

| 要素 | 摘要 |
|---|---|
| 七步 | 划域定流通物 → 货币只在交换域+机械识别导流 → 每域入口动作 ≤5 分钟 → 案例失败字段必填且禁收益数字 → 个人执行外置独立工作台（local 隔离） → 只写连接协议不建新平台 → 邀请制限速 |
| 五反模式 | 群内卖课（信任提款）／只沉淀成功案例（软文化）／拿变现当社群目标（时态错配）／逼新手贡献经验（应改为贡献记录）／新建商城或小程序（三域实体性合并） |
| 检验三问 | 货币是否零流经信任域？案例是否含失败字段且无收益数字？连接是否已写成「谁给谁/给什么/什么格式」？ |
| 成熟度 | **L1**：单社群方法论推导，36 条一手文档事实支撑；无运营实证。升级 L2 条件：90 天内案例登记 ≥10 份且失败字段非空率 100%、零起群内导流事件、≥1 名成员在交换域产生可核验到账记录 |

全文（适用/不适用边界、步骤详解、跨域迁移）见 [03 三域飞轮模式](concepts/03-three-domain-flywheel.md)。
