# 书籍转 Web 教程的原创重写与适当引用编写规范

> **一句话结论**：侵权风险由"公开发布"与"搬运深度"决定，与格式是否变成 Markdown、是否盈利无关。把全书机械转换后公开是高风险行为；以自己的独立表达讲解知识、仅对少量内容规范引用、不替代原书，才是《著作权法》第 24 条第（二）项支撑的"适当引用"路线。

**适用场景**：以正式出版、仍受版权保护的书籍（PDF/EPUB 等）为学习对象，撰写并公开发布技术/知识类 Web 教程。

**不适用场景**：① 个人本地转换、不传播（适用第 24 条第（一）项个人学习，规则可放宽）；② 公有领域作品或 CC 等开放许可书籍（按许可条款执行，参见 [§2](#2-合规路线的选择)）；③ 已获得权利人书面授权的合作教程（按授权合同执行）。

> 相关工具链：格式转换的技术方案见 [EPUB 转 Markdown 转换方案系统性调研报告](../operations/epub-to-markdown-conversion-research.md)。**注意：转换工具只解决格式问题，不解决版权问题。**

## 1. 法律基础速查

### 1.1 三个行为分别对应三项专有权利

| # | 行为 | 对应权利（《著作权法》第 10 条） | 行为定性 |
|---|------|------|------|
| ① | 将 PDF 解析、转换为 Markdown | 复制权 | 格式转换不改变复制行为本质 |
| ② | 调整结构、改写表述、重组内容 | 改编权（演绎权） | 基于原作的独创性改写构成改编 |
| ③ | 发布到 Web 供不特定公众访问 | 信息网络传播权 | 无论是否收费，"公之于众"即落入控制范围 |

**侵权判定公式**：未经许可行使著作权人的专有权利，**且**不存在法定免责事由（合理使用 / 法定许可）。

### 1.2 四个常见错误前提

- ❌ "我不赚钱就不算侵权"——商业目的只影响赔偿轻重，不影响侵权成立。
- ❌ "我标注了作者和来源"——署名是合理使用的**必要非充分条件**，全文照搬再署名仍是侵权。
- ❌ "知识/方法不受版权保护，所以书里讲的技术我都能写"——知识点、原理、公式（思想）不受保护，但具体的文字表述、代码、图示、案例编排、结构序列（表达）受保护。
- ❌ "PDF 能免费下载，转换它就没问题"——盗版复制件不产生合法使用权；破解 DRM/加密另违反《著作权法》第 49–50 条关于技术保护措施的规定。

### 1.3 两条免责通道

- **第 24 条第（一）项个人学习**：仅限个人、私下使用**合法取得**的作品；一旦公开传播，通道关闭。
- **第 24 条第（二）项适当引用**：为介绍、评论作品或说明问题而引用已发表作品，须同时满足**比例适当、注明作者姓名与作品名称、不影响原作正常使用、不实质替代原作市场**（第 24 条总则已确立三步检验法）。这是唯一支撑公开发布的合理使用路径。

### 1.4 风险谱系

| 情形 | 风险 | 说明 |
|---|---|---|
| 本地转换、个人学习，不传播，来源合法且未破 DRM | 🟢 低 | 第 24 条第（一）项 |
| 公有领域作品（注意译本/插图/注释的独立版权） | 🟢 低 | 原作版权消灭，新版本层权利需单独排查 |
| CC 等开放许可书籍，严格遵守许可条款 | 🟢 低 | 合同许可路径，违约条款仍需遵守 |
| 自己原创重写讲解，少量引用原文并规范署名，不替代原作 | 🟡 中低 | 第 24 条第（二）项，边界靠必要性与替代性判断 |
| 大比例搬运/结构照搬，仅格式转换和少量改写后公开发布 | 🟠 高 | 复制权+改编权+信息网络传播权三重命中 |
| 全书转 Markdown 公开（尤其商用、附下载、替代原书） | 🔴 极高 | 可能触发惩罚性赔偿（第 54 条，故意且情节严重可按损失 1–5 倍），法定赔偿上限 500 万元；销售盗版还可能涉刑 |

## 2. 合规路线的选择

按优先级三选一：

1. **开放许可路线**：选择 CC 许可或公有领域书籍，严格遵守其条款（BY 署名、SA 相同方式共享、NC 非商业等）。引入 SA 类素材前确认整篇教程的许可兼容性，SA 具有传染性。
2. **授权路线**：联系作者或出版社，取得**复制 + 改编 + 信息网络传播**的书面授权。成本远低于一次侵权纠纷。
3. **原创重写 + 适当引用路线**：本文档主体，适用于无法取得授权、但确有公开讲解价值的场景。

> 页脚的"如有侵权请联系删除"**不产生免责效力**，只能作为通知—删除响应机制，不能替代逐条规范引用。

## 3. 文件级规范

### 3.1 每篇教程必须含溯源 frontmatter

````markdown
---
title: "闭包原理详解：从作用域链到内存管理"
type: tutorial
sources:
  - id: src-1
    title: "《JavaScript高级程序设计（第4版）》"
    author: "Matt Frisbie 著，李松峰 译"
    publisher: "人民邮电出版社，2020"
    isbn: "978-7-115-540"
    usage: "quotation"           # reference=仅参考观点 | quotation=含直接引用
    license: "all-rights-reserved"
created: 2026-09-11
originality: "本文为作者独立撰写的讲解，未复制原书章节结构；直接引用处均已标注 [src-1]"
---
````

要点：

- `sources` 是确权台账而非免责装饰；仅参考过观点的书也登记为 `usage: reference`，便于自查讲解是否不知不觉复刻了原书脉络。
- **观点来源与引文出处分开管理**：转述观点登记"观点来源"；直接引用必须标注实际抄录的**具体版本**——译本有独立版权，引用译本须标译者与译本页码，不能只标原著。

### 3.2 站点级必备页面

- **参考资料与版权声明页**：集中列出来源文献、许可协议链接、引用原则。
- **投诉联系入口**：供权利人主张权利（主动设计通知—删除机制）。
- 篇末"参考与出处"小节集中放脚注全文，与站点级版权页分工：前者逐处精确，后者总目管理。

## 4. 内容级五条硬规则

### 规则 1：结构必须自建，禁止镜像原书目录

- 按**学习者的问题路径**组织（如"报错 → 原理 → 最小实验 → 常见误区"）。
- 不得复刻原书的章节顺序、小节划分、案例编排序列——文字全部重写但结构高度雷同，仍可能构成改编层面的实质性相似。
- 开写前先自拟提纲，再与原书目录比对：若三级标题序列能一一对应，推倒重来。

### 规则 2：表达必须独立，禁止同义词替换式洗稿

- **"合书默写"而非"边看边改"**：先合上原书写出讲解，再打开核对事实与术语。
- 允许共用的只有：通用术语、事实、公式、API 名称（思想与事实层）。
- 检验问句：*"把我的段落与原书段落并排，除术语外是否还有连续的句式或论证节奏雷同？"* 有，则重写。
- AI 辅助写作同样适用：AI 生成内容必须经过结构独立性与实质性相似自查，**使用 AI 不构成"原创"的抗辩理由**。

### 规则 3：直接引用显性化、碎片化、最小化

- 任何原文词句进入本文，必须用块引用或引号包裹并紧跟出处标注，**禁止原文与自己的文字无缝混排**。
- 工程经验阈值（**非法律红线，仅为便于执行的内控标准**）：单处直接引用不超过约 150 个汉字或代码 10 行以内；每 1 份直接引用至少配 3 份以上自有讲解、实验或评论；整篇直接引用总量占明显少数，且不得位于教程最核心、最有价值的位置。
- 引用必须服务于自己的讲解目的（引出、评论、对比、佐证），引用后紧跟自己的分析，禁止用引用拼接充当正文主体。
- 唯一刚性的法律判准始终是：**引用必要性、比例适当性、不可替代性**。

### 规则 4：素材分层处理

| 素材 | 处理规则 |
|---|---|
| 文字 | 原创为默认；原文走引用格式；转述他人观点也标注观点来源 |
| 代码 | 自行实现并配自己的注释；原书代码**整段照抄不适用"适当引用"抗辩**，确需引用时限最小片段并标注出处与许可 |
| 图片/截图 | 一律自绘、自拍或使用明确开放许可（CC BY / MIT 等）的素材并署名；**禁止扫描原书插图** |
| 表格 | 数据来自原书须标注来源，表格用自己的列设计重新组织；整表照抄视同复制 |
| 数据/事实 | 事实本身不受保护，建议标注来源以建立可信度 |

### 规则 5：市场替代性自检（发布前一票否决）

逐篇回答：*"读者只看本篇，是否就不必购买/阅读原书对应章节？"* 若偏向"是"，说明引用过量或讲解沦为原作替代品，必须删减引用、加深自有内容。

## 5. 引用格式示例

### 5.1 行内短引用（引文嵌在自己的句子中）

````markdown
事件循环并非 ECMAScript 标准的一部分，而是宿主环境（浏览器、Node.js）
提供的调度机制。正如《深入理解ES6》在讨论 Promise 时强调的：
"作业队列是微任务的执行队列"[^src-1-p253]；这意味着
then 回调总是在当前同步代码结束后、下一个宏任务之前执行。

[^src-1-p253]: Nicholas C. Zakas：《深入理解ES6》，刘振涛译，
    电子工业出版社2017年版，第253页。引号内为原文表述，引用仅用于说明术语定义。
````

脚注定位**页码优先**；电子书无页码时标注位置号/章节号。诉讼中"见第 7 章"难以核对，不足以支撑精确举证。

### 5.2 块引用 + 引用后的原创评论（标准范式）

`````markdown
### 为什么闭包能"记住"变量？

初学闭包最常见的误解，是以为闭包复制了变量当时的值。原书对此有一个
精炼的界定：

> 闭包是指有权访问另一个函数作用域中变量的函数。
> —— 《JavaScript高级程序设计（第4版）》[src-1, 第7章]

需要特别注意的是，这个定义里"有权访问"指的是**对变量本身的活引用**，
而非值的快照。下面用一个最小实验说明这一区别：

```javascript
// 本文原创示例，非原书代码
for (let i = 0; i < 3; i++) {
  setTimeout(() => console.log(i), 0);  // 输出 0 1 2
}
```

将示例中的 let 换成 var，输出会变成 3 3 3——原因正是 var 声明
被提升到循环外层，三个回调共享同一个变量……（下略，全部为自撰讲解）
`````

三件套：**引用块独立成段 → 紧跟出处 → 引用后立刻展开自己的实验与分析**。

### 5.3 观点转述（不复制文字，只借用思想，仍须归功）

````markdown
关于原型链的查找过程，本文采用"委托模型"来讲解：对象自身找不到属性时，
会沿内部链接 [[Prototype]] 向上一级对象请求，直至 null。这一理解框架
受到《你不知道的JavaScript（上卷）》"委托优于继承"观点的启发
[^src-2-ch6]，但下文的类比与示例均为本文自行设计。
````

### 5.6 禁止写法对照

| ❌ 高危写法 | ✅ 合规写法 |
|---|---|
| 大段原文直接转写为 Markdown，无引用标记 | 原文一律块引用+出处，且压到最小必要量 |
| 逐段同义词改写，保留原书全部例句顺序 | 合书默写自撰讲解，自建示例，仅核对事实 |
| 扫描原书架构图上传 | 用绘图工具自绘并注明"自绘" |
| 复制整段源码后加"来源见参考资料" | 自行实现代码；最小引用片段逐处标注与许可 |
| 文末统一列参考书，正文不标引用位置 | 引用处就地标注 + 脚注页码 + 文末完整书目 |
| 提供"原书 Markdown 版"下载链接 | 不提供任何可替代原书的完整内容 |
| 教程章节与原书目录一一对应 | 按问题路径自建结构，开写前比对目录 |

## 6. 发布前自查清单

**文件级**

- [ ] frontmatter 的 `sources` 已登记全部参考与引用来源，观点来源/引文出处区分清楚
- [ ] 引用译本时标注了译者与译本页码
- [ ] 站点有版权声明页与投诉联系方式

**内容级**

- [ ] 提纲与原书目录无三级以上序列雷同
- [ ] 全文为"合书默写"产出，无连续句式或论证节奏雷同
- [ ] 每处原文引用均有引用标记、就地出处、引用后的自有分析
- [ ] 直接引用总量占少数，无单处超长引用，引用配比不低于 1:3
- [ ] 代码全部自行实现或为最小片段+许可标注
- [ ] 无原书扫描图；表格为自行设计；未引入许可冲突的 SA 素材
- [ ] AI 辅助生成内容已通过结构独立性与实质性相似自查

**发布级**

- [ ] 市场替代性测试通过（本篇不能替代阅读原书）
- [ ] 无 PDF / 全书 Markdown 等下载物
- [ ] CI 机械检查通过（见 [§7](#7-团队协作的机械检查)）

## 7. 团队协作的机械检查

多人写作时，自觉不可靠，将以下检查纳入 CI：

1. **未标注块引用扫描**：检测未紧跟脚注/出处标记的 `>` 块引用与过长块引用。
2. **引用占比统计**：统计单篇引用文字占比，超阈值转人工复核（阈值由团队自定，仅作筛查信号，不作法律结论）。
3. **孤立脚注/悬空引用检查**：改版后脚注定义与引用标记必须一一对应，防止迭代中引用片段删改后出处残留。
4. **文件名与链接检查**：遵循仓库的文件名规范与相对路径链接检查（如 `check-filename-convention.py`、`check-links.py`）。

> 机械检查只解决"留痕完整"，不解决"是否合理使用"——最终判准仍是第 24 条的必要性、比例与替代性，由作者与评审人负责。

## 8. 反模式清单（来自对抗审查的真实教训）

| # | 反模式 | 后果 | 正确做法 |
|---|---|---|---|
| 1 | 把 150 字/10 行阈值当法律红线机械执行 | 产生虚假安全感，整体仍可能侵权 | 阈值只是内控信号，法律只认必要性与替代性 |
| 2 | 同义词替换式洗稿 | 接触+实质性相似仍可构成改编侵权 | 合书默写，自建结构与示例 |
| 3 | 镜像原书目录，只换文字 | 结构序列的实质性相似 | 按学习者问题路径重组 |
| 4 | 脚注只标章节不标页码、译本不标译者 | 举证时无法核对，译本版权被遗漏 | 页码优先，区分版本 |
| 5 | 扫描原书图、整段复制代码 | 图片与代码几乎无"适当引用"抗辩空间 | 自绘/开放许可素材，代码自行实现 |
| 6 | 用"免责声明"替代规范引用 | 声明无免责效力 | 逐条留痕 + 投诉响应机制 |
| 7 | 教程迭代后不核对脚注 | 孤立脚注、悬空引用破坏证据链 | 改版重跑 CI 检查 |
| 8 | 认为"用 AI 转写一遍"即原创 | AI 洗稿正被司法以实质性相似认定 | AI 产出同样过自查 |
| 9 | 公开提供全书 Markdown/PDF 下载 | 直接命中复制权与信息网络传播权，风险最高 | 永不提供可替代原书的完整内容 |

## 9. 跨场景迁移

本规范的"独立表达 + 显性引用 + 可审计留痕"三原则同样适用于：
